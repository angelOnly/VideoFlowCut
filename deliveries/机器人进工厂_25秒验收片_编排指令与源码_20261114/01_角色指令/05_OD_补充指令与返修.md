## 一、首版制作中补充的受管作品合同

这不是创意返修，而是第一次发布阶段作品时补齐输入。实际补充内容如下：

补充本次 VideoFlowCut 受管源码与阶段交件的实际技术合同，属于开工输入补全，不是审阅反馈；请保留现有创意、素材身份、源段、时序和工作内容，在本 Run 继续。
1. 完整合同：../03_动效源码/00_源码与使用说明.md；作者清单版本 videoflowcut.authored-motion-manifest.v1。阶段工具的输入清单顶层仅有 work、readyRanges、changedRanges（sourceFile、sourceSha256、authorSubmissionId 由 stage 自动填）；changedRanges 每项为 {startFrame,endFrame,reason}，readyRanges 每项为 {startFrame,endFrame}。work 包含 name、compositing、width、height、fps、durationInFrames、creativeBrief、props、imageBindings、videoBindings、fontBindings。
2. videoBindings 每槽为 {assetId,sourceStartMs,sourceEndMs,startFrame,endFrame}，源毫秒与作品根帧均为半开范围、按 25 fps 原速对应；重复回看使用不同槽并按交接清单真实绑定。已给出对应 Asset ID 和源时间。源码使用带稳定 id 的 <img data-vfc-video-slot="槽名">，不要填写 src；平台按根时钟注入视频帧。不可直接使用 <video>、音频元素、外链脚本、外链样式或播放壳；完整单页 HTML，CSS 和普通 JS 内联，平台提供 GSAP。
3. 根合成 data-composition-id、data-start=0、data-width=1920、data-height=1080、data-duration=25.48；主时间线暂停并注册 window.__timelines。字体需 fontBindings 对应已登记 ID，当前可用 noto-sans-sc-regular 400 和 noto-sans-sc-bold 700，CSS 使用平台注入的 --vfc-font-槽名。配音和普通字幕继续外层合成。
4. 在你实际完成并确定范围后，继续使用 od motion-work stage --source <项目内HTML> --manifest <项目内作者清单> 发布；遇到实际校验或素材问题请保留原错误，不要以工作文件存在冒充冻结交件。

随后 OD 使用了含连字符的槽名，收到字段校验拒绝。主任务再次补充的实际说明是：

补充本次刚出现的作者清单字段校验依据：videoBindings 与 fontBindings 的槽名必须匹配 ^[a-z][A-Za-z0-9_]{0,39}$，例如 abb_candidate，不能含连字符；对应 HTML 的 data-vfc-video-slot 名称保持一致。素材 Asset ID 本身无需更改。其余设计及阶段范围保持原样。

OD 的实际反馈是：保持现有编排，改用受管视频槽和登记字体；槽名改用下划线，素材 Asset ID、源段和创意时序不变。首版先冻结 [0,160)，再在同一发布 Run 冻结完整 [0,637)。对应的[完整首版源码](../03_动效源码/01_完整首版/motion-source/robot-factory/index.html)、[首版清单](../03_动效源码/01_完整首版/manifest.json)和[冻结回执](../03_动效源码/01_完整首版/receipt.json)均保留。

这一真实制作当时依赖以上两次补充；后续代码已自动提供相关合同，但本次不能把“手动补充后成功”写成“新版自动送件已在真实制作中从头验收”。
