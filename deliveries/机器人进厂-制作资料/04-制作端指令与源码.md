# 制作端指令与动效源码

本片由 VideoFlowCut 组织，Local Codex 使用同一个受管作品制作，最终视频是五份冻结源码的分段合成。主任务先冻结导演、创意、视觉稿及实料，后提交整片。完成情况以该版真实回件为准。

## 实际委托的角色

- **主导演和文案**：采用用户给出的全文，组织六个连续段落，核对独立概率条件、实际工厂素材的含义、画幅、字幕及声音，协调视觉作者并决定整片采用。详见 [主导演编排](01-主导演编排.md)。
- **创意作者和素材探查**：不读取历史项目、历史任务或旧项目案例。根据本片稿与新取得的外部原始材料，核查后空翻和 Digit 事实，用“同一工件”贯通位置变化，提出逐场入口、动作与出口。详见 [创意编排](02-创意编排.md)。
- **视觉作者和运动机制**：保持 16:9、中文旁白与无出镜讲述者，观看真实材料，安排全片构图、节奏与跨场接力；用实料试摆验证后，完成六场逐拍制作稿。详见 [视觉编排](03-视觉编排.md)。
- **Local Codex 画面制作**：根据导演已采用的固定稿、素材绑定与实测时钟生成 HyperFrames 源码，按作品根时钟发布并接回固定版本。代码实现及发布记录见下表。事实性材料不得被拼装成虚构的同一事件，假设中的掉落、滑脱和工位状态以明确的原创图形演示。

这些是受管 HyperFrames 源码，视频素材使用槽位注入，字幕和声音在外层时间线合成。HTML 单独打开无法自动装配视频槽，也不包含外层字幕与声音。为便于直接审看，包内另有[最终成片](成片/机器人进厂.mp4)和各[已渲染片段索引](检查资料/阶段回件及文件映射.json)。

## 回件与修订

首版的 H1 片段超出当时冻结的可采用源范围，第一版发布被拒绝。反馈后 H1 首场限制在源 2.4–7.8 秒，空出的根帧由原创过渡接住。首批已采用的回件留有三个缺口，随后沿同一作品分别完成自动恢复、Figure 通道和换岗电量维护三段。

视觉作者在工作台发现“10万+”比对应旁白晚出现。最后一次续修把数字移到项目 F3270，F3506 退场，保持托起、右移、滚道承托和广角的源片正常速度。最终固定片段的关键帧再次核对位置与遮挡。

部分资料的原始文件名与素材 ID 没有可读含义；[素材清单](06-素材与来源.md)将其映射到本包文件。
