# 四站参考怎样写成可执行的 Skill

这是一份流程教学，说明如何把参考观察转为设计与 Remotion 源码。先给出本轮真实观看的 Jitter 案例，再用**虚构教学演示**说明 A–D 的取舍。A–D 没有对应已观看的线上 URL，不能复制为实际观察记录。站点入口来自项目的 `packages/motion-work/src/catalog.ts`，只证明系统列有这些入口。

## Skill 应当约束判断，而不是指定每次四站拼一遍

四站是候选池，不是四项必选风格。先有当前内容的观众任务，再决定寻找何种机制。`browse_motion_sources` 返回 Onda、Jitter、RemotionLab、Mixkit 的当前入口；先选可能相关的公开预览，使用 `inspect_motion_reference` 查看页面及 preview 索引，再对实际选中的索引连续采样。只有采样能支持的判断才记入观察。标题、缩略图、单帧或没有变化的采样不能证明运动；登录、验证和付费限制不能绕过。

可写入生产 Skill 的专业指令是：

> 先把内容写成一项可被看见的关系或变化，再寻找能表达它的参考。观察它的稳定构图、对象身份、运动顺序、阅读停留和退出连接，说明每个动作帮助观众理解了什么。只保留适合本片的关系，重新设计中文分行、比例、画幅与声画时序。源码格式不决定参考价值；有许可时复用相应源码，否则按已观察机制独立实现。无法观察或没有相关候选时记录缺口，不填写虚构证据，也不要求用户替代理承担每次选型。

## 一次真实选型：漂亮，但只是部分匹配

2026-09-07，从 Jitter 社交媒体模板目录进入 [The Track: Product Reveal](https://jitter.video/template/the-track-product-reveal/)，在未登录的公开页面实际播放第一个 Canvas 预览并连续截图。页面标注 7 秒、4:5。观察到白底符号和细线跑道、红底球鞋与前景大字、符号放大转场、白底小号品牌落版等连续状态；没有原片时间码，不将截图时刻换算为精确动画帧，也没有审阅声音或取得源工程。

这次任务若是“产品由一件变多件，再引出数量”，候选只能判为**部分匹配**。能借鉴的是共同空间轮廓、产品与前景文字的主次、从高信息密度收束到简单结尾；本轮没有看到对象增殖，不能因为画面漂亮就登记为已验证的增殖机制。球鞋照片、品牌、红色广告场景与固定七秒时长都不应照搬到数字人讲解。

可以把这个判断写成下面的检索记录；它是创作记录示范，不是 MCP 新字段：

```yaml
candidate: https://jitter.video/template/the-track-product-reveal/
observed: 公开 Canvas 预览连续截图
match: partial
confirmed: [共同空间轮廓, 主体与文字层次, 尺度转场, 低密度落版]
unconfirmed: [对象增殖, 精确缓动, 声音节奏]
retain: [主体可追踪, 重点接管, 结尾收束]
replace: [品牌素材, 球鞋广告文案, 红色外壳, 固定时长]
decision: 只作构图与节奏的辅助参考
```

自己的实现再由内容决定：读 [产品增殖案例 Skill](../../motion-case-product-multiply/SKILL.md)，让首件与复制件共享身份线索和坐标，数量完成后停留，再收回重点。这个增殖结构来自本项目的案例设计，不冒称是原模板的动作。由此示范的 Skill 编写原则是：同时写清**实际观察、未确认部分、采用理由、舍弃理由和本片改写**，不能只说“参考这个很好看的模板”。

## 教学 Brief：扩容后，资源如何分配

假设旁白要解释：“共享通道原本是瓶颈；容量增加后，还需要决定不同需求各占多少。”任务是看懂同一系统的容量与分配变化，适合一个持续约 14 秒的全屏解释 Scene。教学数值为容量 48→120、出口分配 30%/50%/20%，均是示意；不是网络测速、真实业务数据或科学仿真。对应源码为 [通道分配案例 Skill](../../motion-case-capacity-stream/SKILL.md)。

进入检索时，把问题交给每个候选，而不是预先给网站分配必须采用的零件：

| 系统入口 | 这次寻找的问题 | 虚构候选观察 | 本次设计决定 |
|---|---|---|---|
| [Onda](https://remotion.onda.video/components) | 共同通道怎样持续存在并显出状态变化？ | 假设候选 A 保留路径与节点，只改变瓶颈宽度和通过节奏，变化后停稳。 | 若真实采样支持，借鉴“固定拓扑、局部改变”的关系；路径布局与数值按本片重画。 |
| [Jitter](https://jitter.video/templates/all/) | 结论如何出现，同时保留观众阅读图形的时间？ | 假设候选 B 的短标题沿同一基线轻微揭示，停稳后不继续弹跳。 | 若真实采样支持，只借鉴结论揭示与停留；不把每个出口标签做成独立大标题。 |
| [RemotionLab](https://remotionlab.com/showcase) | 中文条件与主结论能否共存，字号和留白怎样取舍？ | 假设候选 C 用两级中文排印，但附带逐字旋转。 | 排印关系可供比较；逐字旋转不帮助理解容量，舍弃。长中文仍需在本片实际尺寸验证。 |
| [Mixkit](https://mixkit.co/free-after-effects-templates/) | 是否存在有意义的章节切换或人物返回方式？ | 假设候选 D 用大幅擦除切换完全不同的章节。 | 当前仍在解释同一通道，擦除会毁掉共同坐标，拒绝；无需为了“用过四站”加入转场。 |

这张表是检索与判断示例，不表示这些网站实际上提供了 A–D。实际任务应保存真实选中 URL、返回的 preview 索引、采样覆盖与看见的差异；无法看清的部分保持未知。当前提交对象只有一个 `reference.url`：选最能支撑主要机制且确已观察的合法页面，其他真实辅助参考可在观察说明中标明各自用途，不虚构额外 Schema 字段。

## 从观察到 Design Map

这份教学设计保留三入口、共享通道和三出口的身份与坐标。开场让观众建立方向，随后只强调窄颈；扩容改变共享部分的宽度，分配变化在既有出口上发生，最后让流动减弱或停止，读清结论。容量变化与分配变化分开成为两个主动作，背景、标题、节点不同时争抢注意。

视觉结构先在停稳帧成立：浅底上的路径承担关系，色彩对应输入或输出身份，数字附单位与示意标记，主结论有最大可用的中文字级，其余标签退为辅助。狭窄通道与扩宽后的差异必须可感知；线宽是否代表精确比例要明确，不能让示意图暗示已经验证的线性测速。全屏解释使用完整画布，底端结论若与字幕竞争，先重排或调整字幕角色，不等到成片才靠缩字解决。

在本例中，源代码应使用稳定的 SVG 路径与对象身份，用局部 `useCurrentFrame()` 控制窄颈、包的位置和分配状态；同一对象进入下一语义拍时延续其坐标和状态。通道案例中的 `assets/fixture.json` 保存当前演示内容、画布和审阅帧。可复用的是“共同对象 + 局部状态变化”，不是 48、120、30/50/20 或固定 14 秒。正式旁白时长不同，就重定状态区间并重审。

若改为票据解释，则改读 [票据展开案例 Skill](../../motion-case-ticket-rules/SKILL.md)：同一张票的纸面展开，三项条款依次被强调，票根保留到实际优惠结论。它与通道案例共享对象延续的原则，却不共享容器、动线或材质。把四站原则变成 Skill 的价值正在于这种选择能力。

## 代码开发的可复现演示

在已授权的源码开发任务中，可在项目根目录执行 `npm run motion:cases`，生成四例 MP4 与审阅图；`npm run motion:cases -- capacity-stream` 只生成这一例，追加 `--stills` 仅做快速审帧。若开发环境无法启动 HTTP 预览服务，可执行 `npm run motion:cases -- --offline`，使用本地 Remotion Player 逐帧生成预览。两种模式的输出均位于 `previews/motion-cases/`。这是项目案例的开发复现命令，不是正式剪辑工作流，不访问或修改正式项目，不应被剪辑代理用来绕过 MCP。具体实现和验证结果以当前脚本、源码与实际输出为准。

开发预览先确认排印和停稳构图，再连续观看进入、瓶颈强调、扩宽、分配及末端停留。审阅帧定位溢出、重叠与状态边界；MP4 才能发现迟疑、突然跳位、主动作相互打断和停留不足。没有音轨的演示只能验证视觉时序，不能冒充旁白、字幕、SFX 的合成审片。

## 在当前产品中投产

实际剪辑先读当前 MCP Schema，并继续按 `remotion-production` 的受管作品流程执行。这里的名字和字段依据当前源码说明职责，不是对任一运行时版本的保证：`inspect_motion_reference` 使用 `source_url`，在工具实际返回预览索引后才填写 `preview_index`；观察说明中的 layout、motion、rhythm、adaptation、evidence 必须来自本次真实观察与设计判断。

`submit_motion_work` 接收目标 Revision、幂等键与 `work`。作品包含默认导出的 TSX、Props、画布/fps/时长、真实合法的 `reference.url`、五类 observation 与 rights。图片通过当前支持的 `imageBindings` 注入，不内嵌任意外链；源码依赖与 API 以当前校验器为准。不把本地 fixture 整包当作 submission，不向 Schema 添加 `original=true`、`localCaseId`、Mask 支持或新的参考来源。

提交生成 Job 后用 `track_job` 等待、`read_motion_work` 读回固定版本和 Asset，再用 `inspect_asset` 及连续动态预览审阅。参考对照的结论写入 `review_motion_work`：实际通过才写 passed，偏离写 failed，证据不足写 inconclusive。随后按受管作品合同创建或更新 ManagedMotion Cue；读回对象与 Impact，复查进入前、完整运动、稳定停留、退出及下一画面。源码或内部时序变化要新生成版本，并将局部动作帧交回声音专项，不沿用失效声音绑定。

若替换既有 Explainer 主视觉，按主 Skill 先检查底层 Program 的启用状态；新作品叠入并不自动停用旧画面。若回到数字人，复查脸部、字幕、手势与人物返回，不能用没有 Mask 的叠层伪装后景穿插。正式完成仍需主工作流收拢当前 Revision 的连续声画审片和成片 QA。

当前四站外链是平台硬约束。本地案例即使完全原创、编译成功、MP4 漂亮，也不能自行变成免参考的合法提交。若找不到真正相关且可查看的参考，就明确说明当前步骤尚未满足提交条件；解除强制外链、增加本地原创的证据与权利合同应作为后续平台改造单独设计和验证，本轮不实现。
