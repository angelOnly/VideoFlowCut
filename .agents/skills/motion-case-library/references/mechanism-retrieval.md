# 机制检索与组合

## 从画面问题得到可比较的候选

接收当前文案、实际素材和创意与视觉已经选中的场面。先想清楚这一段需要观众看见什么变化，再查找适合的运动方式。

运动尚未确定时，描述内容中有哪些对象，它们之间有什么关系，画面需要怎样发展。已有方向时，进一步写清谁先动、谁同时变化、哪些内容继续留在画面里，以及最后形成什么画面。

查询优先表达运动和画面组织。具体题材名称按需要补充语境，媒介、素材来源、画风和制作方式默认保持开放。用户明确条件，以及素材连续播放、主体保持可辨或重点文字读清等实际条件，写进对应查询。需要特定力度或节奏时，描述动作幅度、速度变化和停顿。

每次围绕一个完整主要过程展开。不同过程分别查找，再结合本片内容安排先后与连接。候选中的构图和运动可以改变初步方案。

已经选中的创意视频包含适用动作时，直接读取对应机制和必要上下文。已有候选、正文和观察结果继续参与比较。

素材、文字、背景、美术和运动一起判断。具体复现沿[创意参考与素材落地](../../creative-reference-to-sequence/SKILL.md)完成。

## 完整新制作的需求覆盖

完整新制或主要视觉重做时，视觉作者围绕以下适用角度主动检索并深化设计；正式采用按[完整参考观察与机制核读](#完整参考观察与机制核读)完成观察：

- 观察与运镜：观众从哪里看向哪里，取得什么新内容，什么参照保持。
- 场内发展与场间连接：主体怎样改变，结果留下什么，下一关注怎样接入。
- 花字演出：准确短语与哪个对象共同表达，字组怎样形成、读清和交接。
- 局部协作：主动作时相关文字、背景、标记和辅助对象如何保持、跟随、让位或接管。

完整新制或主要视觉重做时，围绕这四类作用主动探索并比较适用的不同方法；同一参考可以支持多类，不规定每镜数量。根据实际内容将所需作用组合进整片，候选同质时扩展查询。已有有效观察直接复用；确无合适机制时记录真实尝试并原创，制作中可补查。遵守用户指定的参考范围；局部参数任务沿用当前方案，不重搜全库。

需求与采用决定写回同一当前稿，不建立新的查询模板、组合数据库或 MCP 字段。

完整人物混合解释调用与视觉解说相同的通用机制能力。
同时考虑主要内容发展和人物参与关系，不只检索人物窗口、头像或局部花字。
查询表达活动视频、容器、字组、材料、持续参照与接管关系，不按原片是否有人物硬过滤。
初步构图可以被合适参考改变，不能先锁死人物布局再只搜附加效果。
采用后在原稿写明真实对象映射、保留与改造的动作、能力条件、其余主要过程和接点。
已有一个机制能承担多项作用就直接采用；不足则补查或原创，不凑查询次数和编号数量。
读取 diagnostics，区分精确定位、浏览、语义结果及任务状态；正式采用核读实际过程，准确记录观察边界。

候选的 `case_context` 派生自父案例目录，提供视频类型、材料、场景、材料要求和迁移成本；这是原案例事实，不证明本片具备相同能力，也不作为人物片硬过滤。

## 五种查找方式

**描述变化。** 使用 `query`，或用 `stages` 批量提交本次真实需要的若干动作需求。每组保持与完整稿的关系，返回顺序不代表最终演出顺序。查询内容由当前稿生成，不存放固定题材的可执行查询范本。

**依据当前状态寻找。** 已知入口、出口和保持关系可辅助召回。内容身份保持与几何位置不变分开；未由用户或实际表达锁定的构图只作偏好。自动推导的粗标签用于排序和提示，不当成普遍硬排除。显式硬条件只来自当前确实需要遵守的条件，字段以实时 Schema 为准。

**找相似演法。** 用 `similar_to` 比较同一作用的不同方法，核对谁运动、谁保留、怎样取得主读及所需空间。题材与配色相同不是主要依据。

**找前后接续。** 用 `before`、`after` 寻找候选，并读实际起止关系和缺口。公共标签只提供比较线索；没有公共标签不等于不能经由遮挡、观察变化或本片连接接上。所需连接由当前作者具体设计。

**精确定位与恢复。** 已知编号用 `ids`，已有网页清单用 `selection`。保留原编号、来源指纹、采用项和资料入口；精确定位不应被普通语义筛选覆盖。分页按真实返回继续，不把首批候选称为完整库。各定位模式是否可混用，以当前正式工具 Schema 为准。

## 混合召回与整段重选

使用当前发布的 `search_motion_mechanisms` 查询，读取实际候选、诊断信息和语义任务状态。自然语言语义查询使用当前项目。

首次语义查询返回原任务时，通过 `track_job` 跟进 `job_id`。任务完成后使用 `readback.tool` 和 `readback.arguments` 读取候选页，再按 `next_offset` 继续，核对实际检索方式和 `semantic_used`。候选尚未返回时继续其他独立工作，不能把任务提交当作已完成检索。

首轮已经发现且仍适用的候选，与后续结果共同比较。主任务代为执行或接回结果时，将完整候选交给原视觉作者继续读取、观看和选择。已有候选支持其他工作继续时，仍需接回已发出的有效语义结果，完成相应比较。

对入围项使用 `read_motion_mechanism` 取得完整正文和媒体，传入真实编号与来源指纹。观看时同时判断运动、美术和本片材料能否支持。

候选缺少需要的过程时，继续改写变化描述，查找相似做法或前后连接。任务失败或结果未知时，沿现有恢复方法处理原任务。明确使用已有候选继续时，如实记录实际检索方式与未取得的结果。普通查询没有合适结果时，继续调整检索策略。

## 完整参考观察与机制核读

完整新制或主要视觉重做时，视觉作者须主动检索并实际观察、比较多个适用候选，覆盖整片发展、连续镜头与相关运动机制；同任务已有有效观察可以复用。分别观察两层：选定的整片参考需完整观察建立、发展、关注转移与结束；适用的机制候选需核看完整动作过程及必要前后连接，再决定映射或取舍。用户提供参考时优先使用，并遵守用户对参考范围的限制。不得用一段机制切片代替整片结构观察，也不要求把全部候选或整个案例库通看；确无适用参考时记录实际查找与观察缺口，再依据内容原创，不能未经学习直接跳过。

整片可以连续观察，也可以按顺序分段覆盖全片，保留相邻范围重叠，完成后检查全片顺序与接点。记录可定位的观察转移、场内发展、场间接管、花字、相关层协作、美术延续与安静范围，不推测原作者提示词、代码或精确曲线。

入围机制有 `card.clip` 时，依据 `boundary_note` 检查建立、主变化、中途、落稳和接管是否完整。切片路径相对项目的 `references/motion-cases/skillry/`；缺少起止或前后关系时，通过 `video_path` 补看原片。没有切片的条目直接按真实原片范围核读。`start_ms`、`end_ms` 仅定位参考，不规定本片时长。

需要辅助理解时，使用当前已发布的 `analyze_motion_reference`，按真实编号、来源指纹及 `range.startMs`、`range.endMs` 提交，通过 `track_job` 跟进原任务。当前每次不超过15秒；范围更长时按实际限制分段并保留接点上下文，不能把调用上限当作动作结束。工具能力变化以实时合同为准。

打开播放器、取得视频路径、读取分镜、抽帧或模型分析，均不能直接记作作者已原速连续观看。实际观察方法、覆盖范围和仍未知内容分开说明。可用方式能补足时继续；确实无法观察时保留具体缺口，继续候选设计、预览和其他独立工作，但不得把完整观察写为已完成，也不因未知无限盲改。参考正文用于筛选，不能代替本节正式采用前的观察责任。

选定具体连续范围后，把其中共同形成效果的构图、文字、素材、背景、镜头和运动一起用于本片编排。补充分析注明来源和实际覆盖范围，采用决定以真实资料和当前作品为依据。参考文件、准确范围、本片用法及待确认内容写回同一份当前稿。

## 在同一场面稿中适配对象

打开参考和本片实际素材，确定参考中的主要画面、重点文字和图形，在本片中分别使用什么内容。

沿参考的发展顺序，写出本片怎样开始、各项内容怎样共同变化、形成什么结果，以及怎样接到下一段。保留形成所选效果的构图变化、动作顺序、对象配合、运动幅度、速度起伏和关键停顿。禁止将选中的完整过程缩减成动作名称或统一的入场、退场。

当前画幅、中文字数和素材条件带来的调整，由创意与视觉共同确定。具体位置、比例、取景、路径、曲线和内部时序交制作作者结合原视频完成。

参考中的背景、边界和附属层承担遮挡、承载、显露或连接时，在本片中完成对应作用。采用视频和本片编排一起进入制作简报。

## 设计接点，让对象连续发展

先看前一段结束时留下什么画面，再看下一段从什么画面开始。确定哪些素材、文字、方向、空间或声音继续存在，以及新内容怎样进入。

根据参考与当前内容选择直接切换、交叠或连续动作。写清前段怎样结束、后段怎样开始，以及两者之间需要补充什么过程。

同一对象继续出现时，检查位置、大小、姿态、前后层次和源时间怎样接上。新旧内容同时出现时，安排清楚谁取得注意，谁继续提供参照。

调整参考中的形体、背景或附属层时，同时完成它们承担的遮挡、显露、承载和连接。需要补充连接方法时继续检索，并将有效决定写回同一份当前稿。

同一连续范围使用统一的场面编排和作品时钟。技术上需要拆分时，按[素材坐标与时间](../../opendesign-video-production/references/material-space-and-time.md)处理源时间与作品范围。

## 执行边界与维护

正式剪辑使用上述只读 MCP，先核对实时 Schema。工具缺失时报告当前版本缺少入口，保留参考待查；不借 shell 或浏览器脚本绕过正式项目权限。明确允许本地只读资料脚本的开发/维护任务，可从仓库根调用 `node references/motion-cases/skillry/tools/mechanisms.mjs --request` 传同一查询 JSON，或用 `--ids` 定位、`--offset/--limit` 浏览。`--build`、分类修改与索引修复仅属于已授权的库维护任务。

索引过期、未知编号、路径越界或正文缺失会明确失败。视频、切片和分镜的可用状态逐项返回，读取可用资料并按实际缺口继续查找。无匹配先拆运动阶段、改写关系、减少软筛选、按类别浏览或查相似项，保留真实结果。确实缺少主要动作机制时，交清已找到部分、缺口与尝试过的替代，由导演与作者选择调整或补充实现。运动顺但美术差回构图与排印，整片平回内容、材料与顺序。普通无结果不自动报障，实际工具故障沿项目诊断合同处理。目录与维护见库 README.md；网页承担预览和比较。
