# 四个连续动效案例的设计与改写

四例均以 720×1280、30 fps、420 帧（14 秒）作为开发样例。每份 `.tsx` 是默认导出的 Remotion 组件，同名 `.fixture.json` 保存演示 Props、画布、语义拍和建议审阅帧。源码是实现，MP4 是其可观看结果；下文说明为什么这样组织。数值、票据、无品牌产品与容量关系均是教学示意，不是外部事实、真实凭证或产品证据。

已渲染的配套视频随 Skill 一起提供：[票据展开](../assets/videos/ticket-rules.mp4)、[产品增殖](../assets/videos/product-multiply.mp4)、[时钟换算](../assets/videos/clock-shift.mp4)、[通道分配](../assets/videos/capacity-stream.mp4)。每次只看选中案例；这些 MP4 是无声审阅代理，数字人例的预览底色不代表源组件不透明。无法播放时明确记录观察限制，不把源码推断写成已看过动态。

## ticket-rules：纸张展开，条件积累

观众要先看见“优惠”，再意识到费用、门槛与退改会改变判断。稳定对象是一张票，票头建立身份，条款属于同一纸面，票根从保留凭证变成结论。它适合内容确实具有“表面承诺—适用条件”的结构；不适合用票据外观包装没有票据关系的任意三条知识。

开场票据落位后先读票面。翻角与纵向展开把视线带进条款，随后费用、门槛、退改依次获得强调；前面已知的条款保持原位。结尾票根转为“符合门槛时，扣除服务费后实际省多少”，轻微分离仍保留与票身的来源关系。当前开发时序是 0–66 帧建立、67–124 帧展开、125–332 帧逐项阅读、333–419 帧汇总；实际项目应跟随真实语音和阅读需求重新定时。

暖白纸、暗色字、有限的酸绿强调形成印刷层级。票面裁口、虚线、编号与条码让形状具有对象含义；它们应退居辅助，不能盖过中文条件。动作幅度来自翻纸与展开，不要求整张卡不停飞入飞出；最后需要真正停稳。数字有币种，门槛与退改分开，不把“优惠 − 服务费”误写成所有情况下的最终价。

改写时先替换 `title`、`ticketName`、`discount`、`serviceFee`、`minimumSpend`、`cancelHours` 与 `accent`，核对事实及长文字布局，再决定是否仍需要三项条款。本版主标题与票据名按不超过约 14 个中文字、金额为整数的样例排版；更长内容应重新分行和布置。当前 `earned` 计算只表达这个教学模型，费用超过优惠时显示“还需付”；其他规则应修改模型与源码，不能只换标题。正式法规、合同或真实票据的证明任务仍应绑定已审阅的真实素材。

失败对照：把每项条件换成新场景会丢失“同一优惠受到多个条件约束”的积累；让全部条款同时高亮会消除阅读顺序；只保留巨大的优惠数字会遮蔽条件；提前删除票身再展示结果会让计算失去出处。若同屏人物或底部字幕与票面争空间，应重排或让此段全屏接管，不把整票缩成不可读的小窗。

## product-multiply：从一件到规模，再回到行动

本例让数量被看见：先认识一件无品牌示意平板，再看同类展开，随后建立 10×7 的 70 件阵列，最后将注意回收到首件和行动提示。稳定对象是最初那件产品及其视觉身份；阵列是数量关系，不是 70 个彼此无关的动画。它适合赠品规模、库存、组合或作品数量的表达，不适合证明某一具体机型的设计和功能。

几个阶段使用同一对象的大小与位置变化承接，避免以数字“70”替代数量证据，也避免让全部小件长期散射。展开时先建立少量可辨认的对象，规模阶段用规整阵列让数目可核对，结尾给行动保留稳定阅读。当前构图尝试把产品与信息放在画面下部，为上方人物预留空间；这是案例假设，不是已经通过某个真实数字人画面的安全区验收。

产品轮廓、边框、屏幕高光与统一透视帮助观众在缩小时仍识别“同一种东西”。大到小的过渡须保持首件可追踪，阵列的间距比额外发光更影响清楚程度；主数字、单位和 CTA 分出层级。底部与字幕天然可能竞争，正式使用时同时审查脸部、手势、字幕与产品路径，必要时调整人物画面或改成全屏。

改写时先判断要表达的是精确数量、类别还是细节。当前 Props 为 `productName`、`quantity`、`actionLabel`、`accent`、`transparent`，数量范围是 3–70，行动短句按约 9 个中文字以内排版。数量改变就同步核对阵列、标签与节奏；超出范围需要重新设计分组，不能继续显示 70 个对象却换成其他数字。默认及 fixture 均为 `transparent=true`，上方 600 px 保持透明，但这份留白仍需在真实人物画面复核；`transparent=false` 只用于需要独立底色的展示。用于实际产品宣传时，示意 SVG 不能冒充产品：既要通过当前 `imageBindings` 绑定真实已就绪图片，也要同步将绘制代码改为 `Img` 消费对应的 `props.assets` Slot，重审裁切、尺寸与权利；只增加 Binding 不会替换自绘平板。教学任务也可明确保留示意图。

失败对照：随机复制到满屏只传递热闹，无法核对数量；多件从互不相关的位置突然出现会断开首件到规模的关系；产品和 CTA 一起退场会没有行动阅读时间；把整个画布做成不透明底板再声称“人物同屏安全”是错误集成。没有真实人物素材或 Mask 的开发预览不证明任何人物前后穿插成立。

## clock-shift：先改变刻度，再解释相对关系

观众要区分钟表读数与太阳参照，并理解“钟表向前拨一小时后，仍按相同钟点行动”的相对变化。稳定对象是一只时钟，以及下方持续存在的日照参照。教学把读数 08:00→09:00 作为清楚的一小时变化；具体地点的制度、日出时间与政策结果需要另外核实，不能由这段示意推出。

开场让人读懂钟面。指针向前拨动时，日照参照本身不凭空移动，只改变对应钟点的解释；随后通勤标记用同一空间展示与日照的相对位置。先完成“时钟改了”，再解释“相同钟点的出门相对早晨发生了什么”，避免两种坐标同时变化而失去基准。结尾保留钟、参照与结论，让观众复核刚建立的关系。

奶油底、暖橙色和有厚度的钟壳让时钟成为可识别的主对象。刻度是共同坐标，指针和关键刻度承担注意重点，阴影与装饰退后。中文标题、图形标签和结论使用不同级别，留白使两种参照可区分。拨针是本段主要动作；不需要钟壳、标题和日照带始终循环晃动。

改写时使用当前 Props 调整标题、说明、日出/出门标签与结论，再检查文案是否仍符合源码中的方向与一小时关系。改变时间跨度、钟面数值或日照位置需要同步改计算及图形，不能只换 `sunriseLabel`。横屏重新安排钟与日照带，叠字幕则重新分配底端空间；不把竖版直接缩小到人物旁边。

失败对照：只让钟针转动却没有稳定日照参照，会让观众把“改读数”理解成“太阳运动变了”；把拨针和通勤移动同时做完，会让原因与结果难分；整段快速连续转圈会让一小时变成不确定时长；在结论前切掉共同参照，会失去复核机会。过渡到真人时，先让结论停稳，再交回人物表达。

## capacity-stream：通道持续，容量与分配分开变化

观众要在同一结构里看见瓶颈、扩容和出口分配。稳定对象是三入口、共享窄颈、三出口与它们的连线，流动包用来解释方向和通过状态。教学容量 48→120 与分配 30%/50%/20% 只描述这个示意系统，不代表真实网络速率、排队模型或某个产品性能。

开场观察已有流动，窄颈得到局部强调；随后扩宽共享通道，保留入口和出口位置；最后在相同出口上改变分配重点，再停留阅读。容量与分配是两个不同问题，依次展示能让观众知道哪项变化产生了哪种可见后果。背景、节点与总标题不必为每个阶段重新进入。

浅灰蓝底与清楚的路径形成技术解释的秩序。通道宽度、包的密度或移动速度应选择有明确含义的编码，不同时全部增强来制造“更快”。当前使用 30 条等权流线，最终按 9/15/6 分配以对应 30%/50%/20%；若改动图形编码，数值、百分比和颜色的对应仍需一致。最后流动逐渐减速并冻结，留出结论阅读窗口，不能让流动包持续抢夺结论。整体仍是简化模型，不据此声称真实系统性能已被验证。

改写时先确定对象代表人、订单、数据还是产能，并替换标题、入口/出口标签和结论。单位、容量与分配比例若不在现有 Props 内，就应有意识地修改源码及 fixture，一并检查总量和分配和为 100% 的关系。实际数据要补来源，复杂网络不要强行压进三入三出的拓扑。人物同屏通常没有足够空间阅读整个系统，可以由全屏 Scene 接管，再用出口结果承接下一拍。

失败对照：每次换新线路会让观众重新寻找拓扑；不断发射粒子但没有瓶颈与结果，只有装饰；把所有箭头同步变粗会无法判断扩的是哪一段；百分比改变却没有共同出口基准，会混淆容量与占比。连续审片要特别看包在路径分叉和状态边界是否跳位、停顿是否足够，以及结论出现时是否仍有竞争动作。

## 从案例回到当前视频

改写前先说清本片保留什么对象、在同一 Scene 中改变什么状态，以及何时真正改变观众任务。共用对象可以跨多句旁白，静止也可以持续多个语义拍；换 Scene 应由观看任务改变触发。案例之间共享的是判断方法，不要求同一色板、同一弹簧或同一转场。

先审静态构图的中文层级、留白、语义与数量，再在正常速度下连续看运动节奏、停稳阅读和前后交接。开发时可用 `npm run motion:cases` 复现，详见 [四站示范中的开发边界](four-source-worked-example.md#代码开发的可复现演示)。MP4 默认是无声视觉演示；它不能证明与正式人物、旁白、字幕或声音已合成通过。最终仍由 `remotion-production` 按实时工具合同生成受管版本、绑定 Cue、处理 Impact，并回交主要工作流做当前 Revision 的连续审片与成片 QA。
