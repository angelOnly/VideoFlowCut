# OpenDesign 制作、深化与返修

OpenDesign 是视觉作者的实现与深化作者。视觉作者持续负责整幅画面的主要创意、实际预排、制作交接和视觉返修。

正式制作前，视觉作者必须完成：
- 当前有效视觉稿。
- 真实素材和采用参考的实际观察。
- 主要构图、素材关系、文字、背景和运动决定。
- 当前作品中的同源预排。
- 需要保留的视觉关系和允许 OD 深化的范围。

主任务按现有项目和资源合同提交制作。OpenDesign 在同一作品和现有 Run 中深化美术、构图细节、排印、运动、时序和源码。

制作作者发现素材限制、技术冲突或设计缺口时反馈视觉作者。不得自行静默改变主要视觉主体、素材主次、参考核心或整场发展。

作品阶段交付后，原视觉作者继续检查实际预览并提出返修。继续沿现有 Run、Frozen Version、MotionWork、Project Revision 和正式采用链路处理，不创建平行工程。

## 发送前准备实际可读输入

正式提交前，先核对视觉作者是否已经交回同源预排、当前视觉稿和明确的深化边界。若只有文字简报而没有主要视觉预排，不得将该范围标记为完整视觉设计已就绪；将缺口交回原视觉作者。

同源预排使用现有 MotionWork 和正式作品机制，不新建独立练习项目。已有作品沿同一项目和 Run 续作。

核对你实际能调用 OpenDesign MCP，沿用本机成功的视频技能与模型配置。
主任务可通过 `read_runtime_release` 的 `openDesign` 状态核对配套版本；
`not_running` 表示尚未启动，先建立画面工具连接；`release_mismatch` 先完成服务切换。
读取本机工具 Schema；skill/skills 只填写 list_skills 返回的 OD 已注册 ID，
不能把 VFC 的镜头 Skill 名称或路径当作 OD 技能参数。

先确认本作品的 OD 项目：新作品先用 create_project 取得 project ID，
返修复用现有项目与源码，再准备并传送以下资料。

视频不使用固定用途、时长或画幅的选择卡。用户明确的要求直接传入；
未指定画幅时由视觉作者依据作品选择，不能写成用户已选择。已生成
旁白时以实际 SpeechTiming 安排完整作品，未生成时先按完整内容构思，
真实时长返回后校准；不设 60 秒上限或将项目默认值当作用户要求。

将共同确定的制作简报、时间安排、准确文案、实际配音、采用参考和本片素材放到制作项目可读取的位置。

采用整片编排时提供完整原片，采用局部过程时提供该范围及必要上下文。创意卡、机制正文、视频和分镜随参考一起交付。

在完整请求中逐项点名文件与用途。文本通过当前文件接口交付，大文件沿实际文件交接能力传送，并保留与 VideoFlowCut 资产的对应。

逐项交付供学习与已采用的创意、美术、动效参考及本片真实素材；已选整片交完整原片，机制交正文、视频、分镜及必要上下文。按真实读取结果保留相对目录与链接，不能按编号猜文件或复制整库。共用文件只交付一次，清单保留各用途。记录项目与输入 Revision、参考 ID 和库来源指纹、原路径或 Asset ID、OD 实际路径、文件 SHA-256、MIME、大小、视频时长与帧率、源范围和用途。库指纹不代替实际文件哈希。核验文件读取与视频解码；无法核实时如实记录，不能把路径存在、静帧或写入成功称为 OD 观看了视频。

主任务使用 `prepare_motion_handoff`，传当前 `base_revision_id`、`brief_path`、`timing_plan_path`、`selected_scene_ids`、实际素材、创意与机制参考和 `scenes`。每个场面给 `sceneId、status、visualRoles、process、preserve、adapt`；采用参考放入 `references`，逐项提供 `kind`（`creative` 或 `motion`）、`id、sourceSha256、startMs、endMs、purpose`。其他按场面使用的声音、美术等资料在顶层 `references` 中声明，并以场面的 `resourceIds` 引用。素材角色使用真实 Asset ID 和素材文件本地范围。工具读取当前项目，返回清单路径、哈希、文件及逐场面缺口。

已有预排时，场面的可选 `visualPlan` 填写 `status: previewed`、`primaryRoles`，以 `preview: {workId, startFrame, endFrame}` 引用当前项目中已发布的 MotionWork 根帧范围。必要时通过 `referenceMappings` 记录已采用参考、目标视觉角色及处理方式；图形主导时设置 `graphicLed` 并在 `graphicReasons` 说明承担的内容及原因。工具交付同版固定源码与绑定并核对哈希；若作品来自 OD 阶段交件，预排引用同时保留真实项目、Run 和冻结版本。`draft` 或 `pending` 返回未完成诊断。没有视觉计划字段的旧交付仍可准备，但资料就绪不表示预排已完成，视觉作者仍须实际交回预排。字段只定位决定，不代替观看或完整视觉稿。

按返回的 `files` 通过制作端文件接口交付本次需要的文件。导演确认后主任务使用 `record_creative_decision.delivery_ref` 保存 `manifest_path、manifest_sha256、scene_ids` 和导演 delegation，再通过 `manage_visual_treatment` 写入 `adopted_decision_ref` 与本范围采用素材。制作启动传对应 `production_run_id` 和 `visual_treatment_ids`，连接器核对制作端真实文件、当前素材与采用稿后发送完整请求。准备后如果目标场面、相关内容或声音时序变化，重新准备并确认受影响场面；其他场面的变化不妨碍继续。未就绪场面继续探索；其他已选且就绪的场面可以单独准备和制作。

完整请求由视觉负责人编写。请求点名本片制作简报、时间资料和实际文件，要求制作作者先读取完整简报，打开采用的参考视频，查看指定范围的连续变化及必要前后画面，再查看本片对应素材。

实际观看的范围和方式照实记录。只读卡片、分镜或部分抽帧时，记录尚未看清的动作和节奏，并继续补看对应过程。文件可读、作者实际观看与作品实现分别按真实情况说明。

明确本次预排已成立的整场美术、素材组织、文字作用、主要运动和节奏。参考中的完整过程与本片用法由简报说明，制作作者在既定主要构图与运动关系内深化局部取景、排版实现、镜头路径、曲线和内部时序。

将本次适用的美术、排印、物件、动作、层次、运镜和接续要求写入完整请求，点名对应资料与用途。制作依据使用当前有效决定及必要依赖，参考中的题材事实和旧时间按本片准确内容与实际时钟重新确定。

视觉作者的同源预排使用本片实际素材和准确文字，呈现主要内容及选中的完整变化。构图、美术与运动在同一作品中共同深化。

资料无法读取时返回具体文件。素材无法支持某项表现时，指出缺少的动作、画面或持续时间，交原视觉作者处理。指令与参考表现存在影响制作的冲突，或需要改变主要编排时，由创意与视觉共同更新简报。

读[项目源码规范](references/hyperframes-contract.md)及 read_motion_capabilities，
附本轮已经发布的输出约定。规范尚未发布时，可在 OD 制作观察，但不声称已接回 VFC。
明确交回项目中可读取的完整源码入口及作者清单，不假定默认 artifact 就是 HTML 源文件。已发布冻结能力时由作者明确交件、固定源码与清单，主任务按同一冻结身份接回；能力缺失不得声称已经冻结。

## 素材驱动参考迁移的执行要求

本节适用于完整新制、主要视觉重做和需要重新迁移创意参考的场面。

### 1. 先读取完整制作简报

制作作者必须读取 opendesign-shot-brief 形成的完整制作简报。

同时打开简报点名的参考原片和本片真实素材。

不能仅凭简报摘要、创意卡编号、关键帧或素材名称开始制作。

### 2. 理解参考与本片素材的对应关系

对照参考原片检查：

- 主要素材如何组合。
- 主体和辅助画面如何安排。
- 文字如何参与构图。
- 背景和空间怎样变化。
- 镜头如何改变观看位置。
- 动作如何接力和共同发生。
- 完整画面怎样形成结果。

同时检查本片素材能否承担简报规定的视觉角色。

不能擅自将真实素材替换为原创图形或其他无关内容。

### 3. 深化已成立的整场视觉设计

以视觉作者的同源预排和当前视觉稿为依据，深化完整场面的：

- 素材取景、比例与位置。
- 主体和辅助素材的空间组织。
- 中文排版与文字动作。
- 背景、前后层次和视觉中心。
- 镜头运动及主要动作。
- 素材之间的接力、叠放和切换。
- 连续动作的节奏、停顿与接点。

不得将完整场面缩减成单个动作、静态展示或普通标题动画。

### 4. 自主深化，但不改变主要创意

制作作者自主决定具体技术实现和内部时序。

如果发现原简报无法实现，必须返回具体问题和可替代方式。

不得静默取消素材、缩短主要表现或改变场面含义。

### 5. 及时交回代表性连续范围

第一版具有代表性的连续范围完成后，使用现有阶段交付能力返回同版作品。

导演、创意和视觉作者可以在其他场面继续准备期间检查该范围。

发现问题后，根据实际问题类型返回对应作者。

主要编排问题由创意与视觉共同修订；素材不足交素材作者；实现遗漏由同一制作作者修订。

### 6. 返修必须保留原委托身份

使用当前已发布的 Run、作品版本和冻结范围提交反馈。

同一 Run 尚在执行时，沿现有反馈机制继续。

原 Run 已结束时，使用现有 continue_from_run_id 续接原作品。

不能为了局部修订重新创建一套互不关联的作品。

### 7. 实际结果检查

作品返回后，原创意与视觉作者对照参考检查完整场面。

导演检查整片发展和前后连接。

不能只检查源码是否存在、文件是否成功生成或 Job 是否 succeeded。

必须区分工程完成、设计兑现和实际观看结果。

## 调用与续接

主任务用 `start_motion_authoring` 完整提交视觉负责人交回的制作请求，补齐当前 Project／Revision、已确定的目标、OD 项目和稳定幂等键。用 `wait_motion_authoring` 按返回的 sequence 续等，超时只是暂无新进展。连接器保存原 Run 与冻结事件游标，阶段交件后按已发布可用范围登记并采用，返回 workId、Revision、Cue、范围和 editorUrl；冲突保留作品并读回具体原因。停止或中断后沿原 Job 与 Run 恢复，不新建作者。当前范围未交件、未完全可用或最终状态 incomplete 时不能报告完成。

每次接回可用阶段作品，主任务立即把回执中的 `editorUrl`、Revision、Cue 和范围交回原视觉负责人，安排其在工作台播放实际合成。阶段观察、问题和返修结果关联本次 ProductionRun，制作反馈沿对应作者 Run 和冻结版本提交。原视觉负责人接回观察后，主任务继续组织已成立范围及其他无依赖工作。

以 `authoring.status` 判断制作范围是否完成，外层 Job 状态记录任务执行。阶段被拒时读取回执中的版本、字段、原因与反馈状态；原作者发布修正版后沿同一委托继续接回。反馈投递结果未知时读取原记录，保留已采用范围。

完整新制或主要视觉重做时，首个具有代表性且可连续检查的范围形成后，就由同一 Local Codex 作者在本 Run 内明确完成该范围，使用
`od motion-work stage --source <项目内HTML> --manifest <项目内作者清单>` 发布阶段冻结版，
回传得到的 `frozen_version` 与实际可检查范围，再继续修改工作件。该命令由作者当前 Run
授权，外层不能凭文件变化假装作者交件。以实时能力为准；没有阶段入口时只能等正式 Run
结束后按完整交件冻结，不能宣称边写边看已实现。阶段预览用于尽早发现风格、时序和素材绑定问题，不新建重复 Run，也不设置逐镜审批或等待全部结果的门槛；已有条件的其他工作继续。

核对实际运行采用的 Skill、任务路由、加载规则和产物。
默认由 OD 交源码、VFC 工作台直接显示固定源码；通过 OD 正式路由选择 HyperFrames 源码交付，
motion-design 仅提供适用的美术与动效方法，不再额外创建 MP4、播放器或声音。
独立视频任务仍沿其自己的视频交付规则。必须从实际 Run 核对所选路线和交付身份。
HyperFrames 源码交付 profile 不等于已注册 Skill ID；存在配置文件不证明路由激活。
记录实际采用路线和交付结果；仅一句“不渲染”不能证明生效，
不修改 OD 私有工作副本伪装永久配置。明确按本片美术与连续演出制作，
不采用与本任务冲突的固定切镜、统一幻灯片或无关结尾结构。
使用 OD 内部适用的制作指南深化实现；实际是否遵循，以作品和源码为准。
不因等待制作而由外层作者绕过 OD 另写一份替代成品。

## 观察与返修

### 接回能够实际查看的作品

首个具有代表性的连续范围完成后，沿已发布的阶段交件能力提交。主任务取得同版作品，将实际版本、范围和声音情况交回原导演、视觉与创意作者。

创意与视觉带着采用参考查看本片对应范围，检查具体素材组织、构图、文字、背景和运动。导演沿粗剪与返修方法判断材料组织、观看发展和前后关系，并组织需要的补材或重新编排。

查看范围应包含所选表现的完整变化及必要接点。实际观察方式、覆盖范围和待确认内容随反馈记录。

创意作者判断选中这一段的吸引力、发现和发展是否做出来。视觉作者检查素材组织、构图、文字、背景、镜头、运动和节奏是否实现。

### 把问题写成能够修改作品的反馈

反馈写清本片哪一段实际出现了什么画面，参考中对应过程怎样表现，什么表现遗漏或变弱，本次需要达到什么结果，以及已经成立、需要保持的内容。明确这次需要重新安排哪些素材、构图、文字或动作。

素材使用不足时，重新安排素材的出现、换位、切换和接力。画面长时间没有发展时，重做这一范围的连续变化。文字失去构图作用时，重新安排它与素材、背景的共同动作。节奏偏弱时，调整行程、用时、动作交叠、发力和停顿。

所选场面需要重新组织时，由创意与视觉共同改写该段编排，再交原制作作者完成。涉及事实、正文和跨段关系的变化交导演协调。

### 将反馈送回同一制作委托

使用实际阶段回执中的作品版本和发布 Run 定位反馈。`steer_run` 的 `run_id` 使用观察版本的发布 Run，`frozen_version` 与该版本配对，影响范围使用作品根帧。由服务定位同一委托当前接收反馈的 Run。

记录反馈 ID、实际范围、具体问题、需要完成的修改和用户锁定项。反馈接收状态、作者处理情况和新版复查结果分别记录。

接收结果未知或轮次不匹配时先读取原委托与反馈记录，按原身份对账。任务已经结束后，视觉作者交回原作品版本、源码、修订范围和保持项；主任务读取当前 Revision 和目标 Cue，以新幂等键调用 `start_motion_authoring`，在 `opendesign_request.continue_from_run_id` 中填写原作品发布 Run，选择 `replace_cue` 或 `replace_range`。需要沿用原作者配置时，传入已核实的 `agent/model/serviceTier`。新 Job 接回修订作品。

同一次修订跨多个 Cue 时，简报交清所有范围并制作一次新作品。先采用明确的首个目标，核对新作品 `readyRanges` 后，主任务用 `manage_effect_cues(action=adopt_work)` 将同一 `work_id` 依次采用到其余授权目标。每次读取当前 Revision，接回全部采用结果后复看完整连接。

### 修改后查看实际新版本

制作作者沿同一作品交回修订版本，主任务接回并采用到授权范围。原视觉及创意负责人使用新版工作台入口查看修改范围和前后连接，按各自职责确认反馈是否落实。已有问题通过“在本版复查”定位，实际观察后保存结果并关闭已解决的问题。

参考效果仍有遗漏时继续修改。反馈中的问题已经在实际画面中解决并复查后，再结束这项返修。主要编排发生变化时，共同更新原简报，使制作依据与实际作品一致。

使用连续画面判断运动与节奏，使用实际声音判断声画配合。暂停画面和抽取画面用于检查对应时刻的构图、文字与素材。实际观察方式、覆盖范围和仍待确认的内容照实记录。

## 交回原项目

一件作品交回固定 HyperFrames HTML/CSS/GSAP 源码，连接器在授权范围内登记 MotionWork 并采用；先在工作台观察同版源码，文件按实际用途由 VFC 生成。
已有 OD 视频只在来源、源码、Props、实际绑定与源区间、字体、画幅、帧率、帧数和输出用途
均有可验证的同版身份时采用；无播放器、重复字幕或声音。登记路径按实时 Schema 核对，
派生媒体必须关联真实 workId、根范围和字节身份，不把普通导入视频宣称为已验证作品缓存。
按已发布规范整理依赖、真实图片/视频/字体对应、作品职责、实际时长与帧率、
