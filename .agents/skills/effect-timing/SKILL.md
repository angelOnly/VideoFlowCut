# 动效时机、语义落点与媒体事件

## 为什么 startFrame 不等于时机

一个视觉对象从开始出现到观众真正理解，往往经历预进入、运动、稳定和阅读。SFX 的文件起点、可听起音、主要攻击峰值和尾音是不同位置。因此“把效果放在关键词那一帧”没有说清楚：是开始进入、完成落地，还是保持到句子结束？

`effect-timing` 把编辑意图与物理范围连接起来。它不根据固定间隔堆动画，而是判断视觉和声音事件如何服务语义、动作和观众预期。

## 四种语义关系

### anticipate

在关键词或结果前开始建立对象，让观众做好准备。例如人物即将说“70 台平板”，产品轮廓可稍早出现，数字在落音时稳定。预进入不能早到泄露信息。

### land_on

主要动作或 Settled Frame 在数字、结论、对比、对象名称或动作结果落音时完成。用于让视觉和语言共同形成一句“句号”。

### react_after

在笑点、失败、反应或结果之后触发。ComicReaction、短 CameraPunch 或音效通常不应在包袱前泄露。

### hold_through

对象在完整解释、证据阅读、CTA 或操作期间保持。关键词说完不代表观众已读完或理解完。

当前 EffectCue 的 semanticAnchor 已支持 speech_segment、narrative_beat、scene、absolute 与这四种 relation。没有 targetId 或真实 Timing 时，不应写成伪精确。

## 动作阶段

一份作品可包含多个语义事件与多次阅读停留。逐个命名真正需要强调的动作，给出局部帧、落点依据与时间精度；不把完整作品套一次统一入场。

每个重要 Cue 至少考虑：进入前、Enter、主要落点、Settled、Hold、Release、Exit。简单效果可以压缩阶段，但必须有稳定状态和清楚结束。若动画在整个范围持续漂浮，没有信息完成时刻，观众很难知道何时读取。

## 不同内容的时机

### 数字

先建立容器或上下文，再让数值在落音时稳定，单位和比较基线同时可见。不要只在数字出现时做快速计数后立即消失。

### 对比

当论证包含延迟披露或反转，先建立 A，在“但是、相比之下、另一种”处引入 B，两者同屏后再显示差异或结论。若观众先需要完整比较框架，可以同时建立双方，再依次聚焦；是否先后揭示取决于观众已知与语义结构，不按模板固定。

### 因果与流程

原因先存在，关系词开始路径，结果在对应语言或动作处完成。路径动画需要让观众跟上，不应为了速度一次跑完整条。

### 列表

每项随对应语句加入，最终形成整体。若一开始全部显示，后续旁白只是在朗读已经知道的内容。

### 证据

先让观众知道来源和页面，再聚焦区域，最后高亮关键句。高亮先出现会让观众不知道它来自哪里；页面只闪一秒则没有证据价值。

### 笑点

包袱前保持清楚，落点后短反应，随后给观众释放。声音和视觉反应都提前会毁掉笑点。

### CTA

行动动词出现时进入，在完整行动语句、按钮或操作期间保持。CTA 不应抢在用户知道为什么行动之前出现。

## 时间精度和降级

`segment_exact` 只保证 SpeechSegment 的起止，原声 `sentence_exact` 只保证已有句段范围。它们适合段首、段尾、Scene 切换、段间停顿和完整短语效果，不等于句内词级落点。优先利用已有可验证边界；必要时在支持调整的 Cue 上依据连续声画复核物理位置，并记录它是人工式感知校正，不是 ASR 词时间。不要仅为强调重建已确认的语音或强拆原声字幕；稳定字幕的编辑边界继续由 captions 约束。

`chunk_coarse` 只用于素材定位和低频变化；没有时间信息时不做正式同步。未来真实 `word_exact` 也不能机械让每个词跳动，语义重音、阅读和运动仍然优先。

## 阅读时间

观众需要识别对象、阅读文字、比较关系、理解结论，再回到人物或下一 Scene。复杂页面、图表和 UI 需要的时间远大于一个关键词。若 Scene 不够长，先减少信息或拆步骤，不通过缩小字体和加快动画解决。

## 与人物动作和声音的冲突

同一范围检查人物手势、Caption 换卡、CameraPunch、另一个 Effect、Cutaway、音乐强拍和 SFX。多个独立焦点重叠时，应延后、减弱、拆开或删除次要事件；文字落定与短音效如果共同标记同一语义事件，可以同步形成复合重音。不能把协同峰值机械判成竞争。

SFX 可绑定预进入、对象落定、数字完成、关系建立或笑点后的反应。先区分要同步的是可听起音还是主要攻击；渐强掠过可以先起音、后在落点完成，短攻击提示可以直接确认事件。检测和波形只提供候选，需结合实际声画判断；缺少证据时不声称精确。

### 将感知落点转换为音频范围

统一使用项目帧率，把所选源片段开头定义为零点。设可听起音相对偏移为 O，主要攻击相对偏移为 P，希望攻击对齐的视觉帧为 V，则音频 Item 起点为 V−P，可听起音事件帧为 V−P+O。当前 `manage_audio` 的 `onset_offset_frames` 填 O，`event_frame` 填可听起音事件帧；不能把攻击峰值偏移误称起音偏移。对于没有明显渐强的短音效，O 与 P 可能接近，但仍需实际确认。

这只是定位方法，不是自动检测能力。预进入、主要攻击与尾音的数值来自所选文件与源范围，不能用示例数值或统一零偏移。若计算越过 Timeline/Scene 的可用范围，选择更短攻击的候选或重新设计事件，不截掉必要起势后声称同步完成。

## Event Anchor 与物理 Item 的区别

同一范围事件可选起势或落定的单次声音：不填写 endLocalFrame，localFrame 使用实际起点或终点（作品末尾按最后一帧）；需要完整持续声时才同时绑定起止范围。不要因为视觉动作持续三秒就强制所有音效也持续三秒。

受管作品有 eventMap 时，声音绑定提供 eventId 与 workVersion，并按 eventMap.fps 换算到项目帧率；startFrame/endFrame 是作品局部坐标。先选动作开始、落定或维持中的听觉锚点，再设置相对视觉偏移。持续声音显式填写时长或已复核的循环，不用一个短声音的起点冒充整段声音结构。作品平移可以跟随，内部版本或节奏改变需重读事件并复核。

“Ding 应在结论被听见时发生”是 Event Anchor。SFX Item 可能要更早开始，因为文件前导；动画也可能要更早进入，让稳定帧在结论落音。把所有 Item startFrame设为语义帧会导致观众实际感知错位。

当前 `manage_audio` 已持久化 media_event、onsetOffset 与可选 effect_event。后者以 Cue ID、动作名称、局部帧及听觉相对视觉偏移绑定一次具体动作，平台固定当前作品和内部时序签名。不要只在 note 写“结论落定”，实际却对齐到另一个动作。Cue 纯平移可同步移动音效；换作品、改内部运动或时长后停止旧声音并要求重新确认，不按比例推算新落点。这不提供自动词级或自动感知定位，校正仍需连续声画证据。

## 节奏的期待、动作和释放

好的时机往往包含期待—发生—停住—释放。产品在人物说到前略微预示，数字落音完成，保持阅读，再退出；笑点则相反，包袱前不预示，之后快速反应。严肃证据应慢建立和长停留，不能套促销运动。

## 动画时长的相对性

同样 12 帧在 24fps 与 60fps 感受不同，也随对象尺寸和距离变化。应使用项目 fps 和视觉距离判断。大对象跨屏需要更长，微标签可以短；快速不等于没有 Settled Frame。

## 首尾安全

Cue 不应在 Scene 开始第一帧就处于半动画状态，除非从上一 Scene有连续关系；也不应在 Scene 结束后仍有视觉残留。短 Scene 无法容纳完整运动时，简化效果或延长 Scene。

## Browser 微调后的记录

人工式帧级调整需要保存目标 Revision、原精度、调整原因和检查范围。主线重新编译后，该 Override应 review，而不是自动当作仍正确。

## 当前写入和验证

普通 Registry Cue 可修改 Motion；ManagedMotion 内部时序由源码/Props 固定，需重新生成版本。整体平移只改变 Cue 时间，内部重定时必须重新交付事件帧、读回 stale AudioCue 并复核。

使用 `manage_effect_cues` 写入 start/end、semantic_anchor、motion 和 quality_rules。当前 MotionLayoutCompiler 已消费 `spatial_anchor`、进入/稳定/退出预设与 `style_pack_id`；不同组件的实际曲线、素材布局和人物关系仍必须以 Preview 验证。写后读取 Impact，渲染目标范围，检查进入、中间、Settled、退出和前后完整语句。

## 案例：结论大字

人物说：“所以真正稀缺的不是钱，是你能支配的时间。”错误做法是在“真正稀缺”开始就让所有文字同时爆出。更合理：保持人物建立前半句，转折“不是钱”时短暂显示被划去的钱；“是你能支配的时间”落音时让“时间”稳定为主视觉，并保持一小段阅读。若人物表情是关键，也可只用轻排印而不全屏。

## 交接合同

连续作品交接还带入口/出口约束、真实可用范围与局部事件；素材、时序或作品版本变化后相关 Cue/声音需要复核。验证必须对应当前版本实际合成。

输入是 SpeechTiming、Scene、语义/动作事件、人物状态、Caption 和其它声音。输出是 Cue 时序、落点、稳定/阅读时间、精度和需要 Preview 微调的标记。它会影响 Preview、SFX 和字幕注意力。验证是完整动作阶段与连续播放。结果交回 `remotion-production` 或主工作流。
