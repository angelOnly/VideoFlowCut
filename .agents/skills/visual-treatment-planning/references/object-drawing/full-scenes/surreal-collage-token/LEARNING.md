# 从完整场面学习：一句话怎样变成可操作的单元

本案例首先是完整观看过程，其次才是物件画法。请先播放 [原生无声全片](完整场面_无声.mp4)，再看 [同阶段对照](comparison.html)。原生版本保留作者 Canvas，受管版本只迁移 8.10–14.00 秒完整段落，均未获得新的效果认可。

## 全片怎样发展

| 原作时间 | 观众正在认识什么 | 场面与后续关系 | 原源码入口 |
|---|---|---|---|
| 0–2.18 秒 | 从海报进入实际输入行为 | 米灰纸底、太阳、青条和方格纸拍上；聊天卡片带阴影盖住海报，镜头转向输入框 | drawCover、pasteTex、drawCard、camAt |
| 2.18–4.33 秒 | 用户输入的一句话 | 文字按原 timeline 出现；发送后从输入框跳到对话区，变成具有厚度与撕边的纸条 | TYPED、SENDMSG、stripShape、cardToWorld |
| 4.33–7.73 秒 | 这类输入叫提示词 | 墨圈和手写箭头指向同一纸条；旁侧提示词叠层让出空间给 Prompt 标题，物件身份不变 | drawDeck、drawPromptArrow、drawPromptTitle |
| 7.73–8.94 秒 | AI 接收输入 | 左侧海报被撕走，侧面石雕从底部升起；纸条沿弧线从卡片飞到头顶，而不是切成另一张无关示意图 | drawTear、headDy、stripPose、W2D / D2W |
| 8.94–11.81 秒 | 一句话如何被分成单元 | 镜头钻进开口；纸条保持、剪刀入场空剪后连剪七刀；切口出现后碎片错开，八片顺次翻成骨牌并落到石阶 | toDive、drawInterior、drawStrip、drawScissors、domino |
| 11.81–13.79 秒 | 八块就是 Token | 骨牌已经落定，仍保留原词及成都红、旅行蓝；括号先给数量，轻跳给逐个辨认，Token 字样最后落下 | domState、drawDiveNotes、slam、shakeAt |
| 13.79–18.99 秒 | 模型在大量数据中寻找关系 | 大纸条遮满屏幕后切回全景；头顶喷出信息纸条，放大镜搜索，红蓝胶带让成都和旅行再次被认出 | drawSweep、drawSlips、slipPose、drawDataNotes |
| 18.99–21.17 秒 | 得出旅行需求 | 太阳先抬起再砸下，纸条被震开；先前的红蓝骨牌离开头部落到地面，结论出现在腾出的太阳区域 | sunAt、drawPair、pairPose、drawConclusion |

上表依据原源码、时间线及已提取画面整理；本轮未完成正常速度连续观看，不把源码推断记为观看通过。

这条线的关键是身份持续：聊天中的句子、被剪的纸条、骨牌上的词、数据中被标记的词、结尾并置的两张骨牌相互对应。仅借走剪刀或“弹一下”的曲线，就失去了这段解释。

## 美术为什么成立

- **纸不是白底噪点**：PAPER 先做不同尺度的明暗网格，再加纤维；GRAIN 是固定种子的透明黑白颗粒，叠在纸条、骨牌等各自的局部表面。撕边由 tornRect 的边缘与端部不同幅度形成。阴影相对纸条偏移，飞起时阴影更远、更淡。
- **材料有分工**：SUN / TEAL / GRAPH 由 makePiece 和独立图案生成；暖黄太阳承接重点，青条提供方向，方格纸承接拼贴层次。它们轻漂且使用不同视差，不是所有元素统一漂浮。
- **石雕是容器**：headPath 的额头、鼻、嘴、下颌与颈部形成侧面识别。HEADTEX 有大范围受光、140 个柔斑、5200 颗细粒、下颌暗部和后脑暗部；开口边缘单独着色。drawInterior 在椭圆内画暗腔及石阶，骨牌有真实落点，避免悬在无深度的色块上。
- **剪刀的材料与结构**：scissors 的两半绕同一支点旋转，金属横向渐变、灰色连接柄、朱橙手柄、轴钉与后面的纸牌分层；标签摆动逐渐衰减。此处保留原作者的图形化表演，不把它声称为经过机械工程验证的剪刀。
- **骨牌有体积**：domino 用左侧面与顶面表达厚度，侧面压暗、顶面提亮、正面垂直受光并叠颗粒。词在上、点在下；红蓝身份贯穿全片。落地影接近石阶，落地短促压扁与横向展宽提供重量。
- **文字各司其职**：纸条文字就是受操作的内容，骨牌文字保留内容身份；批注指出动作和数量，Token 大字完成命名；底部字幕是原作解释，不替代物件行为。字体缺失会改变字形与宽度，原生本机结果本身也不同于作者 macOS 静帧。

## 首个迁移段：关键中途与因果

对照视频采用同一根时钟：受管第 f 帧对应原生 `8.1 + f / 30` 秒。结束于下一场纸条遮挡接点，不能把它当作后半片也已迁移。

| 原作时刻 | 必须检查的中途 | 原函数 → 受管函数 |
|---|---|---|
| 8.10–8.82 | 同一纸条从聊天区飞向头顶；弧线顶点、缩放与转角连续，飞行不是匀速直线 | stripPose / drawStrip → Strip |
| 8.94–9.60 | 镜头推进时头顶开口仍是同一位置，纸条和开口没有彼此滑脱；背景视差分层 | camAt / toDive → cameraAt / Camera / Dive |
| 9.64–10.06 | 剪刀从右上进入、略超调后站稳；纸牌跟随并逐渐止摆 | drawScissors / scissors → scissorsState / Scissors |
| 10.09–10.31 | 先空剪一次建立工具身份，不提前切断纸条 | drawScissors → scissorsState |
| 10.40、10.47、10.54、10.61、10.68、10.75、10.82 | 七个切口的刀位、闪光和裁片错开共用事件时间；刀向下一处的横移约 0.035 秒，不做慢吞吞的整体平滑 | CUTS / BOUND / cutOff → scissorsState / pieceState / Strip |
| 10.92–11.69 | 八片以 0.05 秒间隔启动；先轻抬再加速下落，翻到侧面时收窄，后半面才成为骨牌；最后一片不能早于第一片落地 | domFall / domLand / drawStrip → pieceState / Strip / Domino |
| 11.34–11.83 | 各片落地后 0.14 秒内压缩回弹，接触阴影与底边同在石阶；碎片和骨牌不能重复显示 | domState / drawHead → Motion 中落地分支 / Domino |
| 12.06 起 | 逐个轻跳仍按原八片顺序，数量括号与“最小的语言碎片”建立理解 | domState / drawDiveNotes → Notes / Motion |
| 13.34–13.74 | Token 在 0.13 秒内砸下，字、笔刷、画面短震配合；页眉和字幕保持屏幕坐标 | slam / drawDiveNotes / shakeAt → Notes / Motion |
| 13.67–14.00 | 斜纸条逐层盖满，成为下一镜头切回全景的遮挡依据 | drawSweep → Sweep |

原作不是所有动作都快：纸条飞行和钻入镜头建立空间，连剪极短，翻落有错峰，落定后给辨认时间。必须同时保留这些快慢差，而非给所有属性套同一缓动。

## 怎样迁移到不同内容

1. 先写清“输入对象是什么、哪项操作改变了它、输出单位有什么身份、这些单位接下来做什么”。例如把一条订单拆为多个加工工序：长条保留订单内容，切开的单位须与真实工序对应；后续要排序或装配，不能继续照抄旅行推断。
2. 先在同一份受管源码中改内容和结构，再决定比喻是否仍成立。句子长度变化要重算实际字宽、切割边界与裁片中心；单元数量变化要重排落点和七刀时序，不能只改纸条文字却保持八块。这一版是固定八单元参考，尚未实现任意内容自动排版。
3. 保留动作关系而不是死抄物体：需要“分离”可借切分；需要“分类”可能用托盘或不同轨道；需要“合成”则不能借剪刀。工具、接触点、受作用对象和输出去向必须同时改变。
4. 从材料与受力决定外观：纸可以撕边和翻面，金属要有边缘与反射，石头以块面和暗部支撑重量。允许静态纹理烘焙，但核心物件保持独立几何、枢轴和事件，不能用整段原视频充当可编辑成品。
5. 内容相同才保留红蓝身份，内容改变就重新定义色彩语义。先看小画面下输入、工具和结果谁最重要，再定对比、尺度和留白；不要把原页眉、原品牌、旅行用语照搬进新作品。
6. 先验证飞入、接触、侧面翻转、落地与镜头接点这些危险中途，再以正常速度播放同一源码出的完整段落。静帧漂亮、帧数正确、跳帧一致只说明部分问题，不能自动进入推荐。

## 本版可编辑范围与代价

`managed/source.tsx` 在现有受管 React / SVG 环境运行。纸条裁切、剪刀双刃和枢轴、骨牌面与厚度、石阶、字幕及镜头是可编辑实现；纸底、石材、色纸、笔刷和颗粒来自原源码生成的静态材料。入场聊天卡片与页眉为静态参考贴片，其内部人物呼吸未迁移，若迁移此前聊天段需继续拆成可编辑对象。

本版已补回 Token 橙色字母、AI 标签撕边、背景纸屑和光影视差；阶段对照仍发现手写揭示方式、剪刀手柄暗边、AI 标签入场和段首撕纸残片等差异。不能因为主动作已实现而隐藏这些差异。最终观察以 `managed/reviews.json` 对当前预览哈希的记录为准。
