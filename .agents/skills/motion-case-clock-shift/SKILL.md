# 时钟拨快：同一束晨光，两套时间刻度

[观看独立动效](assets/clock-shift.mp4) · [完整源码](assets/motion.tsx) · [演示参数与语义拍](assets/fixture.json)

本 Skill 解释这一个已经完成的动效：为什么选择时钟与日照带，怎样把一句结论生成可追踪的对象变化，以及如何把方法迁移到其他内容。视频是 720×1280、30 fps、420 帧的 14 秒无声案例；它提供独立效果，不代表已经与某段真实数字人、旁白或字幕合成验收。

## 观众究竟要理解什么

观看目标是区分两个容易混在一起的变化：同一物理时刻的钟表读数可以由 08:00 改为 09:00；太阳的位置没有因此改变。如果之后仍按钟表的 09:00 出门，出门相对原来的日照参照就提前一小时。结论成立依赖“统一拨快一小时，出门仍定在 09:00”这个案例前提。

画面先解释读数，再解释行动，不能把拨钟过程理解成现实中已经流逝了一小时。标题“把时钟，拨快一小时”、钟面“同一物理时刻”、固定的太阳和页脚前提一起限定这一阅读方式。教学数值不提供任何地点的日出事实，也不能单独证明某种时间制度的政策效果。

这个内容关系的重点是“改变约定而保留外部参照”。只有时针旋转，观众可能理解为时间经过；只有两张时间表，观众又需要自己重建变化。因此主物体负责让改动可见，日照带负责让没改的部分可见，通勤标记最后把抽象差别落实到行动。

## 为什么是这只钟和这条日照带

时钟的十二个数字、六十格刻度、长短针和数字读数提供相互校验。一小时可以同时被看成“时针前进一格”“分针完整一圈”和“08:00→09:00”，三者讲同一件事。钟壳和钟面属于同一个 SVG 组，拨针时不会换成另一只钟。

倾斜约 15°、压扁的纵向比例、铜色外圈和叠放的侧壁让钟有厚度，帮助它先被识别为物体。外圈、瓷面和影子只建立体积；承担概念的是针与刻度，所以钟壳只在入场时微调，后续不持续晃动。

下方不是第二个装饰场景，而是共同的空间坐标。太阳固定在 x=147，通勤起点固定在 x=405，刻度间距为 86 px。拨钟时每个位置的小时文字整体加一；随后通勤移动到 x=319，恰好向左一格。这样观众能用同一条带核对“读数向前，行为相对更早”。

钟面展示“同一刻如何改读”，通勤标记展示“未来仍遵守同一约定时刻会怎样”。两者是先后解释的两个观看任务，不是声称整个画面中所有对象都在模拟同一段真实经过的时间。

## 配色、排印与比例的理由

奶油纸底 `#F4F0E5` 配深青墨色 `#243C3A`，让数字和中文在低刺激的背景上成立。暖橙 `#C9653B` 用于 +1 小时、指针中心、拨钟提示和结论短线，把规则变化串成一个强调系统；它不是给所有对象上同样的高亮。

钟面用乳白到暖灰的径向渐变，铜圈用深浅带表现受光，模糊影子位于钟下。浅椭圆辅助线与细页眉线降低实物的悬空感，但对比度低于刻度与文字；移除它们不应改变概念解释。

画布左右各留 48 px，标题放在 y=149、字号 45，副标题字号 23。钟体半径约 252，占据上中部；日照带为 624×204，放在 y=864。大钟先获得注意，较窄的日照带随后承接比较，底部 34 号结论字在动作完成后承担收束。

钟面小时数字 34 号，数字窗 31 号等宽字体，避免分钟变动造成字宽抖动；日照带小时 17 号、日出与出门标签 20 号，形成“读数—关系—说明”的层级。长文案不能依靠继续缩字号解决，因为小字会先破坏竖屏中的比较任务。

## 从结论到成片的生成顺序

先写出观众最终应说出的结论：“改的是读数，太阳不动；仍按 09:00 出门就相对更早。”再画四个静态关键状态：08:00 的钟与原位标记、09:00 的钟与原位太阳、通勤左移后的同一日照带、保留全部参照的结论帧。静态状态若已经互相矛盾，先改模型，不用动画掩盖。

第二步确定对象身份和保持项：同一钟壳、同一钟面、同一太阳、同一条日照带、同一个通勤图标。允许变化的是指针角度、读数、刻度文字和通勤横坐标；太阳、地形和刻度位置保持不动。将“太阳不变”落实为坐标不依赖 `shift`，比只写一句旁白更可靠。

第三步定义状态与依赖：`arrival` 只控制钟的落位；`shift` 同时驱动两根针、数字窗及小时刻度；`commute` 等拨钟完成后再驱动图标；`ending` 只负责结论接替解释句。一个语义改动共用一个进度变量，避免针、数字和刻度分别计时而互相脱节。

第四步用 `useCurrentFrame()` 写纯帧函数。`ease(t)=t²(3−2t)` 先将输入限制在 0–1，再让两端速度归零；`blend(a,b,t)` 负责标量插值，`polar(angle,radius)` 把角度转为针端坐标。随机访问任何帧都能得到同样状态，不依赖播放历史。

最后细化美术：在身份、坐标和关键帧稳定后增加铜圈、瓷面、指针投影、地形层次和注释线，并复核它们是否抢走比较关系。先确保一格对应一小时，再调铜圈颜色；这就是本例的生成次序，而不是先找一个漂亮钟再硬塞文案。

## 实际帧段怎样保持连续

| 语义拍 | 当前帧段与函数 | 观看任务和保留项 |
|---|---|---|
| 建立 | 0–67；`arrival=ease(frame/48)` | 钟在前 48 帧完成微小落位，此后保持钟、太阳与原通勤位置供辨认。 |
| 换刻度 | 68–225；`shift=ease((frame−68)/130)` | 到 198 帧完成拨快，随后停留；日照带和太阳始终保留。 |
| 比行动 | 226–323；`commute=ease((frame−226)/86)` | 到 312 帧通勤从 x=405 到 x=319，原位虚线与空心点留下比较证据。 |
| 得结论 | 324–419；`ending=ease((frame−324)/30)` | 到 354 帧完成文字交接，余下 66 帧保持钟、日照带与新通勤位置。 |

入场不是大幅飞入：钟中心 y 从 528 到 508，横向缩放从 0.94 到 0.98，纵向从 0.81 到 0.845；旋转固定为 −15°。这样先建立体积，随后把主要运动预算留给拨针。

`hour=8+shift` 令时针转过 30°，分针角度为 `shift×360°`。数字窗以 `floor(shift×60)` 显示分钟，并在 `shift>0.998` 时收束为 09:00；它是离散读数，几何指针则平滑转动。不能把数字逐位变化误写成所有视觉属性都连续插值。

日照带在同一组刻度位置上交叉淡化 05–12 与 06–13 两套文字；变化的是标签透明度，太阳坐标从未参与插值。通勤移动之后，旧 08:00→09:00 提示降低到原透明度的 25%，把注意交给日照带，同时保留因果来源。

通勤以相同缓动左移 86 px，虚线从原位置指向新位置，透明度最高 0.5；不是把图标删掉再在左侧生成一个。324 帧开始旧解释句退出，新结论进入，钟、太阳、道路和通勤均不退出，因此结尾仍能检查结论。

## 已处理的误读与改写时的边界

本例针对“拨针就等于太阳也动了”的误读，把时刻读数与日照几何彻底分开，并写明“日照带保持原位”。针对“出门早晚方向看不出来”，它保留旧通勤位置，以左移一整格表达相对提前；方向、格距与固定出门时刻共同构成证据。

另一个常见问题是原因与后果同时变完。当前 198 帧结束拨钟，226 帧才开始移动通勤，先给观众看清新刻度的时间，再解释行为。结论也等通勤停稳后进入，避免标题、指针、图标在同一时刻竞争。

当前刻度文字在换算中途交叉淡化，两套数字会短暂叠显；理解精确读数应依靠起止停稳帧。若新的教学任务要求逐帧读清刻度，可重新设计数字滚动或标签交接，但应保持固定位置，不能顺手移动太阳来消除叠字。

审阅参数给出帧 0、60、132、198、260、330、419，分别覆盖建立、运动、换算完成、通勤中途和结论。静帧用于核对位置和层级，正常速度播放才用于判断拨动方向、停留与前后连续；不能把源码推断或抽帧等同于已观看完整动态。

## 迁移机制与反例

可迁移的是“一个外部基准保持不变，约定坐标先改，再比较行动”的解释方法。例如改用相同事件在两种时间标记中的读法，应重新定义两套刻度、固定事件和读数对应；使用单位换算时，则要选择具有同一测量对象的尺、容器或仪表，并重建数值关系。

现有 Props 只有 `title`、`subtitle`、`sunriseLabel`、`departureLabel` 和 `conclusion`。把标题改为“拨慢两小时”不会让程序倒转：时间起点、跨度、角度、数字窗、刻度、86 px 位移和结论文案仍写在源码中。此类改写需要同步修改模型与 fixture，再检查全部关键状态。

反例是讲季节变化时沿用“太阳位置不变”，或者讲真实等待时只换数字不让物理时间流逝；内容关系已改变，原不变量会误导。另一个反例是每一拍切成不同的钟或不同的道路，观众将无法判断变化来自规则还是换了场景。

## 数字人或解说怎样接入

本例源组件有完整不透明底色，且钟与日照带占用主要画幅，适合解说时由全屏 Scene 接管。数字人可以在段前提出“钟拨快后为什么反而更早出门”，段后承接停稳结论；若要求持续同屏，需要依据实际脸部、手势与字幕范围重新排版。

旁白按“同一时刻—读数加一—太阳不变—仍按九点出门—相对更早”依次推进。“读数加一”覆盖拨针段，“仍按九点”在换算停稳后引出通勤移动；最终判断在图标停稳时落下。14 秒只是案例节奏，真实语速改变后应重定帧段并保留阅读时间。

此 MP4 无声，不能据此声称已经完成旁白、音乐或音效验证。若使用拨针声或落点声，应服务于关键事件，不让连续滴答声把“改读数”误导成“真实时间过去”；有声版本还需检查声音与正式字幕共同存在时的注意层级。

## 交接合同

输入是当前内容要说明的读数与现实参照关系、明确的固定条件、预期结论，以及需要适配的画幅、旁白和人物关系。案例学习可以直接读本 Skill 与配套视频；不要求用户每次提供新的参考，也不在这里启动正式 Project 的整片流程。

输出是选用或放弃本例机制的理由、保持对象与变化状态、关键帧和时序改写、Props 与必要代码改动范围，以及实际获得的静帧或连续播放验证证据。说明验证的是案例本身还是已合成版本；无法播放、缺少真实旁白或人物画面时如实保留这一限制。

改变跨度、方向、刻度、通勤约定或布局会使相关数值对应、动作时序、阅读与遮挡验证失效，需要复核。正式生产结果交回 [remotion-production](../remotion-production/SKILL.md) 处理受管组件、项目对象与受影响预览，再由调用方主工作流回收；本 Skill 不假定任何未经读取的 MCP 能力已经可用。

案例选择与横向比较返回 [动效案例总 Skill](../motion-case-library/SKILL.md)。学习完成的标准是能解释“保留什么、改变什么、为何这样分拍”，并指出新内容是否仍满足同一个因果关系，而不是记住铜色时钟外观。
