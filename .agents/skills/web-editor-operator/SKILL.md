# Web 工作台操作与视觉证据

## 工作台字体库只读预览

通过左侧“字体”入口或 `get_editor_url(panel="fonts",font_preview=...)` 进入推荐区，使用实际文案、统一字号和深浅背景观察并比较候选。短示例只用于快速浏览，不能替代实际文案和视频中的排版复核。加载失败不以系统字体伪装；原件仍可能缺生僻字或符号，须用实际文案观察。完整字体名可通过悬停查看，复制只提供候选标识；浏览和复制不创建 Job、Asset 或视频 Revision，也不自动采用字体。字体采用与替代沿[字体可用性方法](../opendesign-video-production/references/submission-and-recovery.md#字体可用性与替代)，主任务续接原视觉作者修订，导演负责风格方向与跨段协调。推荐链接及页面字样仅为候选观察，不能冒称当前视频已经改用该字体；普通字幕轨字体编辑未新增。

## 观察职责与统一提交

主任务安排本次观察和修改范围，当前负责人使用工作台完成对应操作。专业判断由原导演、视觉、创意、声音或审片负责人按职责作出，实际操作者保存自己完成的观察和修改结果。

工作台已有控件支持的字幕、声音、片段位置和普通效果调整，由明确委派的操作者直接保存。保存后读回 Revision 和实际修改结果，再播放受影响范围复查。作品内部画面与动画交原作者同源修订，其他正式操作沿共同交接约定提交。

## Web Operator 的角色

工作台操作者负责定位正确版本、播放真实合成、执行获委派的控件调整，并交回实际观察及持久化结果。是否改变主要表达、构图、声音或跨段关系，由对应专业负责人决定。操作与专业创作由同一负责人承担时，按该负责人已获委派的范围执行。

## 定位之前先确认事实

调用 `get_editor_url` 或 `focus_editor_object` 前，先通过 `project-basics` 确认 Project、Revision、Scene/Item/EffectCue ID。打开页面后至少用两个信号确认定位：URL 参数与 Inspector ID、Timeline 高亮、Scene 卡片、Preview 选框或当前帧。不能因为页面看起来像目标场景就开始编辑。

固定版本用于观察和记录问题。需要编辑时使用“查看最新版”或“退出固定版本审阅”，重新核对对象及当前值，再通过已有控件提交。保存成功后暂停播放，读回结果版并继续复查。版本冲突按现有项目写入与恢复规则处理，保留目标、修改意图和问题记录供重新核对。

## 如何看一个效果

检查入口、多个关系变化、结论和出口，随后观看完整连续动作与前后语句；打开浏览器或抽帧只能证明对应观察，不能证明已听过或看完整段。

单张稳定帧只能回答构图，不能回答运动。对 EffectCue 至少检查四个时刻：进入前的原画面、运动中的中间状态、信息完整的 Settled Frame、退出和下一事件的交接。随后播放“前一句—完整效果—后一句”，确认画面不是局部正确、连续观看却突兀。

Settled Frame 应单独成立。观众应该能迅速识别第一重点，文字可以读完，人物的脸、嘴、手和字幕安全，证据没有被裁掉，画面在运动停止后仍然有构图。若效果只有不停漂浮时才显得“丰富”，通常是稳定画面本身没有设计好。

## 如何做微调

把初稿的大约秒级范围与实际预览中的动作、阅读、旁白和前后画面一起核对，按 [初始节奏与预览修订](../effect-timing/SKILL.md#初始节奏与预览修订) 局部前移、后移或延长；记录改前改后时间及依据，落帧时按当前 fps 换算。已讲清就收尾或交接，保留主体、美术和接续意图以及锁定声音/总长，避免统一倍速。

普通 Cue 参数调整与受管作品内部修改分开：ManagedMotion 内部排版/节奏需回 opendesign-video-production 提交新版本，不能用网页临时 CSS 或无效 Inspector 参数冒充持久修改。

调整顺序从高到低是：事实和内容、主体与证据、字幕和平台安全区、第一注意目标、阅读时间、空间平衡、运动、颜色和材质。不要先改 Glow、阴影和圆角来掩盖对象位置错误。

微调应尽量落在当前数据模型能持久化的属性，例如 EffectCue 的 SpatialAnchor、Props、Motion、StylePack 或 Inspector 中注册的布局参数。如果 Web 只能通过临时 CSS 获得结果，说明能力尚未进入项目模型；此时记录缺口，不声称修改完成。

## A/B/不使用比较

仅对高影响分歧比较有实质差异的候选；不要求每个小效果渲染三个版本。比较相同语义与预算下的完整过程，不能凭单张静帧判定运动优劣。

尚未确定的高影响选择或当前预览失败时，比较有实质差异的相关方案；可以包含当前、轻处理或不使用，不固定数量。比较哪一个更快被理解、哪一个更保护人物、哪一个更符合整片视觉语言、哪一个注意力成本更低。主工作流可能发现最好的结果是不使用该效果；这不是失败，而是最小充分处理。

## 证据记录

固定源码作品和已有媒体均使用工作台范围播放或循环播放。先核对 Project、Revision、对象和半开帧范围，等待实际显示帧及资源就绪，再观察对应过程。声画检查同时确认实际播放的声音。

在“审阅与返修”中保存实际观察者、方式、范围和观察内容。制作任务使用本次 ProductionRun，制作作者 Run 作为作品来源和反馈身份传递。发现问题时填写现象、影响、严重程度和对应对象。

已有控件支持的问题在工作台调整，内部源码问题通过现有工作单交回原作者。工作单由主任务接手并安排负责人。新版采用后，使用“在本版复查”定位结果版范围，实际播放后保存复查结果。

日常检查使用直接播放。需要可传递文件、离线审阅或渲染差异诊断时，按具体用途调用 `render_preview_range`。`inspect_composed_frames` 用于需要精确定位的静态问题，记录实际检查帧及所得结论。

## 常见场景

### 字幕上移

先确认是 Caption 对象还是整个 Scene 的构图问题。上移后检查嘴、手势、产品、平台 UI 和下一张 Caption 的位置。只检查当前一句可能遗漏后续近景遮挡。

### 产品前景变大

不能只看产品是否显眼。还要检查人物是不是正在做重要手势、产品是否遮嘴、字幕是否被挤压、进入路径是否穿过脸，以及本次要求的画幅是否可接受；需要多个版本时分别检查。

### 证据卡片

先核对真实来源与页面坐标；呈现时根据已建立的上下文决定是否重新给全貌。证据需要足够时间阅读；如果为了保持人物可见把页面缩得无法辨认，应切全屏，而不是继续缩小。

## ChatCut 式工作区的联动检查

选择 Transcript/SpeechSegment 后，Playhead、Scene、Caption 和 Timeline 应定位到同一范围；选择 Timeline Item 后，Preview 选框、Inspector 和 Scene 高亮；选择 Preview 对象后反向找到 Cue/Item。Browser Operator 应验证这些联动，而不仅是按钮能点击。

## Timeline Canvas 的可访问性

若 Timeline 使用 Canvas，页面仍需通过 DOM/辅助语义层暴露 Track、Item ID、起止帧、选中和状态，供自动化定位。需要调整位置时使用已发布的持久化控件，保存后读取 Inspector 数值和新 Revision，再播放受影响范围及接点。

## Job 和状态观察

queued、running、failed、stale、conflict 和 blocking 应在 UI 可见。Browser Operator 可以等待状态，但不能将页面 Spinner 消失当 Job succeeded；仍需通过 API/MCP读回。

## Revision 比较

视觉 A/B 应明确 Revision，不在同一页面临时改 CSS截图。切换 Revision 时所有面板和 Selection 应一次切换，避免 Preview来自旧版、Inspector来自新版。

## 失败恢复

页面控件不存在可能是当前版本未实现、对象类型不支持、权限/连接问题或定位错。先确认 DOM和 Revision，不重复随机点击。需要代码能力时返回开发缺口，不用浏览器脚本直接修改后端状态。

## 交接合同

进入时应有：目标 Project/Revision、对象 ID、预期观察问题、需要比较的方案。输出是：持久化的新 Revision（若有修改）、真实 Preview/Frame 证据、发现的问题和是否需要退回某个专业 Skill。Web Operator 不自行给出“成片通过”结论。

## 停止条件

对象定位不一致、页面 Revision 过期、目标属性无法持久化、Preview 不是目标 Revision、素材未就绪或问题需要改变上游 Story/Scene 时停止。此时把任务退回 `project-basics` 或对应主工作流。

## 源素材审阅操作合同

源素材审阅发生在现有 Assets / Inspector 工作区。先选中目标 Asset，确认 Asset ID 和源时间坐标；使用 overview 查看素材结构，使用 range 循环播放候选范围，只有精确动作、微表情、停顿、口型或切口会改变决定时才进入 dense。

对比两个 Take、两个机位或两个 B-roll 候选时，保持相同的上下文长度和播放条件，分别记录完整性、动作/表演、声音、构图、余量和当前视频功能。采用选择通过工作台持久化控件或已发布 MCP 提交，经应用层保存并生成新 Revision 后，返回时间线检查实际合成结果。

写入后必须返回 Timeline 或真实 Composition Preview，播放修改前后和受影响完整范围。不能把源素材窗口中单独成立的镜头，直接当作已经在成片中成立。

## 浏览器审阅跨回合交接

宿主浏览器的实时文档和能力表优先。临时标签在回合结束会关闭；后续还需使用时，在本回合对实际标签调用宿主支持的 `markHandoff()`，每个继续使用的回合重新保留。交接浏览器身份、标签ID、来源URL、素材ID、源范围、实际最后观察位置和保留结果，不交接旧页面对象作为恢复凭据。下一回合重新绑定实际标签并核对来源、播放位置；标签已消失时按当前合同取得新标签，不操作失效对象。

`iab` 的 `visible` 参数不能套用于 Chrome；Chrome使用实时文档要求的 `sessionName`。能力不支持、标签失效和浏览器入口不可用分别记录，不猜测宿主API。主线程可连接不能证明子代理可连接；恢复验证须在原代理完成真实跨回合调用。入口仍不可用则停止其直接浏览器步骤，保存完整错误并由主任务用正式只读能力回传有效证据；连续代理缺失保持待审，截图不能冒充连续观看。
