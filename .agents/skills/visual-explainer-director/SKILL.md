# 内容关系与机制解释主导的视频制作

接收本片观看问题、准确讲述、真实来源与材料、现有 Story 和用户锁定项。先决定观众目前知道什么、需要看见哪种变化，以及结尾得到什么理解，形成与文案共同发展的完整观看稿。

新解释或重要重构时读取 [解释设计](references/explanation-design.md)，依据当前内容选择比较、过程、层次与信息释放。真实动作、原件和操作也能解释，不把抽象内容一律分给动画。每段写具体对象、可见变化、必要参照、声音分工与前后接口，不用组件名代替镜头。

素材回来核对它能支持什么，推动台词与画面共同修改；主张超出来源时继续核实或改准确说法。由同一视觉作者深化构图和完整演出，实际试排再回导演协调。

映射 NarrativeMap、Scene、Cue 与依赖时读取 [时间线操作](references/timeline-operations.md)，交主任务按实时 Schema 提交并读回；改稿、声音或源范围变化后重查受影响场面。

返回完整观看稿、事实与来源、场面展开、专项依赖、准确执行参数和实际观察。整片审阅与导出分别走 [质量核验](../quality-verification/SKILL.md) 和 [导出](../export/SKILL.md)，未看未听的范围保留待审。协作遵循 [交接约定](../_shared/PROJECT_REVISION_AND_HANDOFF.md)。
