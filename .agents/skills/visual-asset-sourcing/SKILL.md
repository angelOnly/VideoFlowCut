# 视觉素材需求、搜索、候选与本地化

## 来源研究与素材取得

接到前期探索任务时，先读取导演方向、文案作者的具体疑问和已知材料。分别辨认需要核实的事实与需要看见的过程，选择当前实际可用的入口：项目原片用已有观察和片段搜索；公开原文通过宿主浏览器使用 Google 搜索并打开原站阅读；图库镜头用无需 Key 的 Provider 或 Pexels 网站搜索；选定来源按支持的方式取得。研究与选材由同一负责人关联起来，不把搜索结果标题直接写成解说结论。

查询写出对象、动作或关系，以及有必要的记录形式。例如“产品名＋主题切换＋完整录屏”比单独搜索“电脑”更接近本段任务。先看返回内容缺少什么，再决定改动词、补功能名、换来源、查看同源前后范围或继续下一页。关键词命中、候选得分与下载成功都不能证明材料已完成表达任务。

探索阶段通过现有 manage_asset_requirements 建立具体需求，不必虚构 Scene 或固定时长。需求创建、下载、分析提交与正式采用由主任务执行；本专项负责完整参数和实际选材判断。搜索和读取使用本次实际可用的宿主浏览器与 MCP；浏览器可查找、阅读、复制真实文字和获取可公开下载的文件，正式入库仍由主任务通过已发布 MCP 获取或导入。缺少能力时报告具体缺口，不用 shell 或浏览器脚本绕过项目写入。

候选足以影响讲述时，尽早将实际发现交回文案作者和导演：发生了什么、支持哪句话、需要改哪项判断、有哪些可发展的画面、还有什么未确认。不必等所有镜头下载完才反馈。导演采用方向后，再补连续源范围、裁切、原声和接点。

首次按观察过程寻找材料，或当前结果只有相关插图时，完整读取 [从问题到可剪材料](references/research-and-footage-example.md)，学习查询怎样依据候选改变；不按示例固定执行搜索次数。

具体探索示例见 [研究与画面](references/research-and-footage-example.md)。当前由宿主浏览器搜索、阅读并摘录真实原文，保留来源 URL、阅读范围和时间；通过 `acquire_source_material` 正式取得选定公开网页快照、直接图片或 PDF。`kind=web_snapshot` 使用固定 1440 像素视口，不传 `pages` 或 `pageWidth`；这两个字段只用于 PDF，`pageWidth` 是页面图片最长边像素。网页快照由服务重新获取，不等于浏览器当前页面选区；无法公开获取时交回具体缺口。Google 和 Pexels 网页访问不需要搜索 API Key，也不是 MCP 自动搜索 Provider。图库用 `nextCursor` 继续，变更查询、服务或媒体类型时重新开始。

## 执行角色与代理交接

本 Skill 的创意工作在专项子代理中执行，负责素材搜索策略、候选比较、生成提示词、采用理由与完整获取参数。主任务通过 [production-coordinator](../production-coordinator/SKILL.md) 真实分派；同一授权子代理可按需读取相关 Skills 并直接创作，不递归分派。涉及整片主线或跨段风格的决定交导演子代理。

执行前读取 [代理角色与交接](../_shared/PROJECT_REVISION_AND_HANDOFF.md#代理角色与交接)：输入带 Project、输入 Revision、对象、事实证据、硬约束和前后接口；返回完整产物与参数、选择理由、影响/失效范围和证据请求。下文的项目写入、生成提交及审阅保存由主任务统一执行，子代理不直接写正式项目。收到实际对象和真实 Preview 后由原子代理审阅修订，不能以摘要、工具成功或等待证据代替完成；输入变化先重新确认，不能只换版本重发。

## 从表达探索到分镜补齐

本 Skill 接受两种任务。前期探索从导演的初步表达方向、开场声画、可能的发展和关键未知出发，寻找实际存在的处境、行为、过程、细节、反应、环境、声音及资料，让导演知道哪些表达有材料支持、哪些新发现值得采用。此时不要求最终剧本、分镜 ID、固定秒数或已存在的 Scene；探索问题通过已有代理交接说明，正式保存需求时遵守当前对象合同，不编造占位 ID 或新 Schema 字段。

定向补材接收导演已经明确的镜头任务、前后声画、必须看见的对象与变化、连续源长度、构图和声音要求。找到候选后比较实际片段能否完成这些要求，并反馈更合适的材料或不能完成的部分。两种方式不要求固定先后轮数；已有材料足够便继续制作，需要补哪一项才搜索哪一项。

先区分事实研究与画面探索。事实研究确认主张、背景和真实过程；画面探索发现怎样让观众看到行动、理解关系或感受气氛。同一来源可以兼有两种用途，但外观相似不能证明旁白中的事实，下载结果也不自动表示已被采用。

素材专项负责发现、观察、比较、推荐及完整获取参数；整片故事、剧本和跨段分镜仍由导演决定。找到更有表现力的过程时，交回实际范围及改变表达的建议，由导演采用后再进入制作。具体全屏、PiP、裁切、持续时间、原声与返回由 Cutaway 或对应 Scene 专项在该决定下细化，不能因为搜索相关就自动放置。

现有 AssetRequest 的主体、动作、构图、时长等要求用于正式需求和定向任务；探索阶段只确定已知且影响当前判断的条件，未知明确保留。导演尚未作出的美术和节奏决定不由素材专项为填满字段而补写。

## 先定义观众任务，而不是关键词

AssetRequest 应说明这段画面要做什么。例如“表现自由”几乎无法执行；“在人物解释时间长期被工作占据后，给观众一个现实生活的安静恢复，画面是下班后独自行走并抬头，竖屏上方有天空留白，4～6 秒，不要旅游广告感”才是可搜索需求。

素材需求分别说明段落预计持续多久，以及需要多少连续源视频。`min_duration_ms` 只约束视频或音频的最短连续源长度，图片不应用此条件；省略保持原值，传 `null` 清空，不能用 `0` 清空。修改需求后重新搜索并复核候选，不沿用旧搜索结果。约五秒动作可以参与约十秒段落，余下由讲述、状态辨认、明确回看、图形或其他镜头继续表达；不能因此声明存在十秒连续动作。确实需要十秒连续发展时，继续寻找、生成或修改分镜，不隐式循环或冻结。

初稿秒数与用户硬约束、源文件实测长度分别保留。先写进入、观看与接出，取得材料后核对真实动作余量和声音，完整预览后局部修订。明确锁定的声音与总长保持，可修改讲述由导演结合画面修订，不为原估计补空等。方法见[秒级初始节奏与预览修订](../_shared/EDITORIAL_FOUNDATIONS.md#秒级初始节奏与预览修订)。

需求至少包含：解释、证明、具体化、地点建立、情绪呼吸、跳切遮盖、笑点或 CTA 中的主要用途；主体和真实动作；环境、年代和情绪；画幅、景别、运动、主体方向和留白；可用时长；受保护内容；排除水印、错误品牌、摆拍感和错误人物；来源和许可；搜索失败时允许 Remotion、MiniMax 还是保持原画面。

抽象机制通常优先 Remotion，因为可编辑、可解释且不需要用泛化 Stock 强行象征。真实生活经验、地点和动作更适合项目素材或可授权 Stock。法规、论文、投诉和产品规则必须走真实证据来源，不能降级成 AI 生成。

## 当前能力与计划能力

独立音效的功能与音色选择由 `audio-finishing` 负责，不套视觉构图标准。它复用 AssetRequest → Candidate → 本地 Asset 的获取合同：media_kind=audio、audio_brief、sfx/bgm 角色，无需画幅。`browse_sound_sources` 返回来源与访问边界，Mixkit 的公开分类已接入现有 Provider；候选不自动进入 Timeline，其它站点仍遵守原站合法获取与许可。不要为了声音需求调用生成画面的 fallback。

可选参考研究用于理解运动机制，不是原创二维对象的前置模板搜索。灵感、作品绑定图片、真实证据与实拍分别记录用途；只有实际使用的素材进入获取链。无原始文件时不能把预览当素材。

在线动效不是 Stock 下载任务。Onda、Jitter、RemotionLab、Mixkit 由 `browse_motion_sources` 提供入口，`inspect_motion_reference` 支持公开页面与动态采样。把选中链接和观察依据交给 `remotion-production`；无源码或 AE 格式不妨碍独立实现。只有确实要使用第三方图片、视频或音频时才进入本 Skill 的授权和素材获取流程，不把参考预览登记成正式素材。

当前获取链包括 `manage_asset_requirements`、`search_media_candidates`、`inspect_media_candidate`、`acquire_media_asset` 和 `read_asset_provenance`。需求创建、修改与关闭使用创作 Revision；搜索意图、候选、来源和过滤结果保存于独立搜索会话，搜索本身不改变创作 Revision，也不下载或采用素材。

首次搜索先调用 `list_asset_providers`，直接使用返回的准确 `id`，核对 `enabled`、`mediaTypes`、`queryMode` 和缺失配置。品牌名不能代替服务标识，例如 Commons 的 id 是 `wikimedia-commons`。已注册不代表网络、下载器或许可已经验证；当前自动搜索来源只保留无需 Key 的服务；无需 Key 不代表网络一定可达。公开材料获取使用运行环境已有的 HTTP(S) 代理和 NO_PROXY，每次跳转仍核验公网地址，并保留浏览器实际来源请求头。网页子资源失败可以保存当前截图；主任务读取 Job.result.capture 的 complete、warnings 与 reviewStatus，交回原文案或证据专项逐项核验正文、限定条件和缺失资源。reviewStatus=pending 表示待核验，complete 只表示请求是否有已知缺口，均不代表证据可用。统计等非 GET 请求不会发送，作为缺口记录；主页面失败、登录/验证码、安全限制和预算超限仍拒绝。某页失败不等于全部来源不可用，也不能把失败页面标记为已读取。需要连续实拍时给 `search_media_candidates` 显式传 `media_type="video"`，图片用 `image`；关键词里的 video 不保证媒体类型。

返回候选后先看 `diagnostics.complete` 和 `diagnostics.warnings`。部分详情失败时已有候选仍可检查，但未读取部分保留缺口，不能写成没有合适素材或全部检索完成。主任务只在错误明确携带 `sideEffects="none"`、`safeToRetry=true` 和具体恢复依据时，按目录纠正参数或等待 `retryAfterMs` 后再搜索一次；同因再次失败按 Repair Ticket 报障。下载、生成和写入的未知结果不适用该例外，不能由专项改代理、密钥或执行 shell。

视觉 Provider 保留无需 Key 的 Wikimedia Commons，以及选定单个视频页面的 YouTube 获取合同；Pexels 通过浏览器搜索、查看和下载，经现有 MCP 获取或导入，不提供需要 Key 的 API；实际可用性仍以当前 Runtime、正式工具返回和实时 Schema 为准，不把源码实现当成当前会话已发布能力。Creative Library、其他站点和通用网页证据获取不能只因出现在方案中就被视为已接入。网页调研、来源核实和将媒体正式取得为 Project Asset 是不同步骤；需要当前会话未提供的获取能力时按平台合同反馈。

查询后先查看候选来源、许可、媒体类型、时长、构图与过滤理由，再决定获取。Worker 验证下载文件的 MIME、文件头、哈希和媒体流后登记 Asset，预览 URL 和 Candidate ID 不能直接进入 Scene、作品绑定或 Timeline。

MiniMax 已有独立的 `submit_video_generation`，支持文生、图生、首尾帧与多参考四种模式的提交合同，不经过 Stock Candidate 获取接口。使用已确认的 `workflow_id`，提交当前镜头提示词、生成源长度、画幅与必要的已就绪输入 Asset；Worker 实际调用前读取 Bridge Schema。枚举存在不等于当前工作流支持任意时长、分辨率或全部参考组合，不硬编码未验证的工作流和参数。

生成提示词写本镜主体与环境、动作怎样发展、取景与运镜、构图留白、进入和结束状态、连续性及需避免的内容错误。生成是首版分镜可主动选择的方式，适合示意、氛围或允许虚构的画面；事实内容可以由原创示意解释，但生成结果不能替代真实证据或冒充拍到的事件。`duration_seconds` 是待生成镜头的源长度，不自动等于整段叙事时长。

提交后通过 `track_job` 跟踪结果；只有 Worker 下载验证完成并读回真实 Asset，才进入正式内容复核。生成素材的权利默认 unknown，不自动放入 Timeline；技术 ready 或需求 fulfilled 只表示文件已交付，不表示镜头表达、许可与采用已经通过。失败或状态不确定时先读取现状和诊断，遵循幂等与报障合同，不换键猜测重试。生成依赖当前项目版本，执行期间按 Revision 合同协调写入，不能无条件并发改项目。

本地化或生成完成后，通过 `inspect_asset` 及媒体观察核对原文件实际动作、画质、声音和可用范围；模型摘要不替代必要实际观看。用 `adopt_media_fragment` 保存当前用途、范围、观察与原声策略，具体放置后用 `bind_media_adoption` 关联使用对象。候选、文件、内容合适和正式采用分别判断。

浏览器用于发现候选、阅读图片和文字所在页面、核实来源与查看可用预览，保存来源链接和实际观察。网页上的图像、视频预览与项目正式素材是不同状态；使用原图或页面证据时保留相应区域与上下文，经已发布的获取或导入路径进入项目，不能把浏览器缓存地址直接填入作品。

YouTube 的已实现路径由平台执行 yt-dlp。专项先在浏览器调研中选出单个 HTTPS 视频页面并说明拟用范围，主任务以现有 `search_media_candidates` 提交 `provider="youtube"`、`query=选定页面URL` 与真实需求 ID；这里的 query 是单视频链接，不是关键词搜索。读取候选后，按真实许可依据为 `acquire_media_asset` 提交 `usage_rights: {purposes, basis}`；purposes 数组按实际范围包含 draft、delivery 或二者，basis 记录对应依据。用途依据不会把来源 unknown 改写为 cleared，也不会放行技术过滤或人工拒绝。实际调用前读取实时 Schema，接口缺失时报告具体缺口，不让剪辑代理临时执行 shell。

下载取得选定视频的整条单文件，最高 1080p；同一视频只有分离音视频流时，由 yt-dlp 原生无重编码合并成完整 MP4，不下载播放列表、不按拟用范围截取，也不拼接多个视频。最终文件受 maxAssetBytes 限制，临时原流与合并文件合计受两倍缓存预算限制；获取后才根据实际原文件复核和选择源范围。下载器缺失、访问失败、超限、超时、合并失败或输出无效都会报错，主任务沿 Job、幂等与 Repair Ticket 合同处理，不能临时换工具绕过。只有下载验证并受管登记后，才把 Asset 与元信息交回原专项；获取、内容复核、用途条件和具体采用各自保留结果。

## 查询计划

先将导演的问题写成能在画面或声音里辨认的内容：谁在什么环境做什么，正在出现何种变化，需要哪些细节、结果、反应或现场声。审美和体验需求也要落实为可观察的光影、空间、材质、动作或声音特征，不能只把抽象情绪当作唯一关键词。

再选择可能包含该内容的来源。真实操作、产品过程更适合演示、实测和录屏；生活行为与反应更可能在实际记录、Vlog 或访谈中；空间与氛围可找现场拍摄；规则、数据和原始表述应回原始页面。需要可重新编排的过程时优先寻找关键动作未被原片剪断的范围，不机械排斥已剪辑材料。

从主体名称、动作、环境、拍摄形式和必要构图组合少量查询，按来源语言尝试准确的中英文表达。先保留必须满足的条件，允许景别、色调等未锁定条件有候选差异；不一开始把尚未决定的参数全部设成硬过滤。完整旁白不作为唯一检索句。

根据结果改查询：只有主题氛围而缺行为，就换动作和来源；缺结果或反应，就看前后片段、同系列或同作者相关记录；具体对象不符就细化名称。记录实际找到什么、为什么改搜法，而不以搜索次数表示完成。找到足以判断关键方向的材料即交导演，其余按明确分镜继续补齐。

## 候选发现、连续观看与比较

搜索标题、标签、热度、缩略图和技术数据用于发现候选，来源、访问、画幅等条件用于排除明显不适用内容；它们不能代替观看。先了解原视频上下文和可能的采用范围，再观看该范围及必要前后内容。已有转写、联系表或模型分析可帮助定位，但未观察的动态、声音与心理状态保留未知。

比较候选实际提供了什么：是否能看到所需过程或状态变化，是否保留值得看的细节、表情、动作、空间或声音；其气质、尺度和节奏是否适合本片。温馨、欣赏、观察和陪伴可以依赖细微变化与视听愉悦，不强求每镜都有冲突、信息增量或明显反转。

同时判断可剪性：动作有没有被原片提前切断，有无进入与退出余量，原字幕、水印、黑边或配乐是否遮住重点，目标画幅裁切后主体和运动路径是否成立，原声是否可按本片需要保留。对切口敏感的短范围补密集复核；不要把整条十分钟视频的长度当作已经找到所需五秒完整动作。

把候选放回导演的问题比较，交出推荐、备选与拒绝理由。漂亮但只在主题上相关、与事实不符或不能完成当前表达的素材不直接采用；新发现的内容更适合时说明依据，交导演决定。权利与来源事实按现有规则记录，未知不自动升级为允许正式使用。

## 来源和权利

候选记录真实来源页面、作者、可知许可与署名条件、取得时间和使用范围；未知明确保留。YouTube 单页候选和整文件下载按上述实现合同及现场实时 Schema 执行；浏览器用于搜索、阅读图片文字与核实页面证据，实际用途依据保存到 usage_rights，不冒充来源许可已清楚。技术上可以下载不等于内容已经适合当前分镜，也不自动改变素材的来源或用途状态。网页证据保留原始上下文与目标区域，区分原文、项目高亮与原创示意；下载、受管导入、内容复核和具体采用各保留实际结果。

## Acquire 与本地化

被接受的 Candidate 必须先下载到临时目录，验证 HTTP、MIME、文件头、大小、哈希和 ffprobe，再移到项目受管目录并注册 Asset。HTML 错误页不能因扩展名 mp4 被接受。Timeline 和 Remotion 只能引用本地 Asset ID，不长期依赖 Provider URL。

## 根据实际缺口选择继续搜索、生成与原创

每次把未解决项说明到内容层：没有找到所需行为，现有范围缺少结果或反应，画幅裁切破坏主体，原声被覆盖，素材事实不符，或者取得方式不可用。分别修改动作词与来源、查看同源前后范围、寻找互补镜头或提出新的表现建议；不只重复搜索主题或加“高清、电影感”。

已有素材、网络获取、MiniMax 生成与原创动效按镜头用途主动组合，不排固定降级顺序。事实无依据先核实；表达关系可改为明确示意、图形或允许虚构的生成镜头；已拍过程不能由生成画面冒充。若必须改变关键画面、故事顺序或主声音，带可行方案及影响交导演判断。

已经找到足以试排关键段落的材料，就交导演查看和粗剪，留下普通补材需求；不等所有备选搜尽。若连续结果只重复同类弱相关内容，应说明这一轮尝试及无效原因，返回具体缺口，而不是无限下载。搜索停止不等于内容问题解决，未完成项继续可见。

来源不可访问、下载或 Runtime 失败由主任务沿现有报障路径处理；专业选择不合适回原专项，跨段表达冲突回导演。未知写入结果先对账，不重放获取或导入，不把工具失败换成“已经做出安静区”。

## 组合候选，而不只选择孤立镜头

比较一个候选怎样与其他材料共同完成表达。按需要寻找环境、行动、细节、结果、反应、空间联系或声音的互补，不要求每段固定配齐一套景别。可以来自同一长视频的不同范围，也可以来自不同来源；同源方便寻找连续关系，但不是必选条件。

说明建议顺序与衔接依据，例如对象或动作持续、由环境进入细节、以结果回应过程、让声音延续空间。检查组合后是否只是重复同一作用，人物、地点、方向、时间与声音是否会制造错误事实。不同来源可以类比、并列或有意跳跃，但不能伪装成同一事件。

交回少量可试排的组合及必要替代，指出为什么共同观看优于只选一个镜头，以及仍缺什么。导演确定采用方向，Cutaway、视觉与声音专项细化实际切口和用法；素材专项不自行写最终时间线或另编整片。

## 交接合同

素材已经放入 Timeline 或图片插槽后，以 `bind_media_adoption` 把采用依据关联到这个具体对象；需要静音的选择实际控制原声播放。未裁切整图不能沿用局部观察的许可范围，先生成并复核实际派生素材。同一 Asset 的其他用法不会自动继承此采用结论。质量系统检查具体使用版本，改范围或上下文后重新确认。

公共素材理解经 `analyze_media` 对原文件或在线预览按源毫秒/图片区域提交异步分析；`read_media_observations` 分页读取处理窗口、各模态实际事实和未知范围，`search_media_fragments` 按画面、声音、语言、文本分别检索。MiniCPM 经外部 HTTP 理解实际输入，Qwen 只编码文字；模型漏掉某模态时不宣称覆盖完整。采用前复核原文件，`adopt_media_fragment` 保存当前需求版本、观察、连续范围或页面区域、用途和原声策略。需要纠错时保留原始观察并标记受影响用途待审。分析/查询不产生创作 Revision，正式采用与放置由主工作流决定。

输入是导演的初步表达探索任务，或已有分镜的定向素材需求，连同已有 Project/Revision、事实与硬约束；不存在的对象明确说明。输出围绕具体表达问题组织，交付来源与可访问材料、实际观察过的源范围、发生的动作和声音、推荐用途与组合、备选和拒绝原因、裁切及原声限制、进入退出余量和未解决项。范围尚不能精确确认时注明精度，不编造时间戳；已取得原文件后再给可执行的准确范围。

明确区分观察事实与使用建议。“人物停下操作并看屏幕”是观察，“适合作为这里的停顿”是建议，不能无依据地推断人物当时情绪。清楚标记仅页面、在线预览、已取得原文件、已核对范围和已正式采用的状态；链接、候选和生成 Job 成功都不能替代实际内容复核。

主任务回传真实文件或可访问证据与完整回复，导演查看后给出采用、改写或继续寻找的决定。对应决定、素材源范围及限制交 Cutaway、Scene 或视觉专项继续，不只留下文件名。正式使用仍遵守已有采用与绑定合同；换范围、声音、画幅或上下文时由相关负责人重新确认，不直接沿用旧用途结论。

素材进入声画粗剪后，原专项按回传媒体复核选段和建议。材料本身缺内容时继续找；内容合适但接续、裁切或声音不成立时交使用方修订；发现原故事不适合这组材料时回导演。素材下载完成不是本次表达已经完成。

## 候选本地化后的真实内容复核

Provider 返回的标题、标签、缩略图和技术元数据只能帮助发现候选。候选通过硬过滤并由 `acquire_media_asset` 本地化为 Project Asset 后，还要查看真实画面与可用范围，才能交给 Cutaway 或 Explainer 工作流。

先用 `inspect_asset overview` 确认主体、动作、地点、画幅、镜头运动、字幕/品牌、水印和整体结构；再用 `range` 查看可能采用的连续范围，判断真实动作、构图、方向、留白、可用时长和进入/退出余量。只有短暂动作、主体越界或精确切口会改变选择时，才使用 `dense`。

搜索结果需要向主工作流交付三类信息：候选实际支持当前 AssetRequest 的证据；候选与需求不匹配或被拒绝的原因；被接受 Asset 的可用源范围、构图限制和来源信息。最终是否全屏、PiP、持续多久、保留哪一层声音以及何时返回主画面，仍由 `cutaway-planning` 或对应 Scene 主工作流决定。
