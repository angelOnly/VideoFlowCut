# 字幕、语义分卡与屏幕文字

## 字幕首先是信息层

字幕的第一职责是让观众可靠获得语言内容，其次才是节奏和风格。动态文字不能修复残句、错读或不清楚的主线；如果屏幕已经用图表、证据或 UI 解释同一信息，字幕应简化和退让，而不是复制第三遍。

本 Skill 在最终 Script、可播放语音和 Timing 稳定后开始。主声音变化会使 Caption 失效；不要在 Gate A 之前精修所有换行和强调。

## 文本事实来源

字幕来自最终观众会听到的 Script/Speech，而不是原始 ASR、旧文稿或模型改写。数字、专名、否定、条件和单位必须与实际声音一致。若用户要求字幕做摘要或标题，应明确它不是逐字字幕，并避免改变事实。

## Caption Card 是阅读单位

观众不是按标点自动阅读。每张 Card 应是一个能在短时间理解的完整短语，保护主谓、否定与对象、数字与单位、专名、因果和转折。过长 Card 让阅读追不上，过短 Card 造成频繁闪动和机器感。

例如“不是钱不重要，而是我把生活推到了以后”不应拆成“不是钱不重要 / 而是 / 我把生活 / 推到了以后”，因为“而是”单独出现没有意义。可以按视觉和语气拆成“不是钱不重要 / 是我把生活推到了以后”，但必须保持完整对比。

## 换行

换行应保护语义和视觉重心。避免数字与单位、姓与名、否定词与对象、介词与核心名词分开。两行字幕不必字数完全相同，但视觉重量要平衡。中文标点通常不单独留在下一行。

在人物近景中，字幕位置应避开嘴、手和重要道具；UI/证据 Scene 中应避开操作和原文。9:16 和 16:9 需要不同宽度和行数，不是简单缩放。

## 稳定字幕与动态字幕

人物、MG 和 B-roll已经有高动态时，字幕保持稳定短句。Kinetic Caption 只在画面简单、时间精度可靠、文字本身承担主要节奏时使用，而且应限制在少量关键词和重复视觉语法。全程逐字弹跳会与人物口型、手势和视觉对象竞争。

当前只有 `segment_exact` 时，可以按 SpeechSegment 或稳定 Card 显示；不能按字符平均做逐字高亮。若必须强调句中短语，优先调整 SpeechSegment 或通过真实 Preview 人工微调，并标明来源。

## 强调

强调不是把所有“重要词”变色。它应帮助发现结构：数字、对比、否定、行动、关键词或结论。一次 Card 通常只有一个主要强调；同一风格中颜色、字重、尺寸和运动应有稳定语义。强调不能提前泄露笑点、转折和结论。

## 字幕与其它画面的分工

- 人物坦白：字幕稳定、低运动，给表情和停顿空间；
- 促销数字：字幕可简化，主数字由 MG 承担；
- UI 教程：字幕移到不遮界面的区域，内容只保留必要说明；
- Evidence：字幕避免压原文，必要时短暂隐藏或放到独立区域；
- Vlog：环境和动作不需要每件事都文字解释。

## 字体、层级和可访问性

字体选择应优先可读、字形完整和渲染稳定。中文缺字、字体回退、过细字重、低对比和复杂背景会在 Render Worker 出错。字幕不是品牌海报，过度装饰会损害速度。主字幕、强调、说话人和补充说明需要有限层级。

## 阅读速度与时长

不能只用字符数公式，但可以作为风险提示。判断观众是否能在自然播放中读完，尤其在复杂画面、陌生专名和数字时。若读不完，优先简化 Card、延长时长或减少同步视觉，不通过缩小字体解决。

## 说话人和访谈

多人内容需要真实 Speaker 证据。当前无 Diarization 时，不凭 ASR猜姓名。可以通过画面、用户说明或明确标签建立说话人；不确定时使用中性字幕，不错误归属。

## 标题、注释和字幕

章节标题、证据来源、UI 标签和对白字幕是不同文字角色。不要全部使用同一位置和动画。标题可以在 Scene Entry，来源靠近证据，字幕随声音，注释指向对象。

## 安全区验证

至少检查近景、手持物、最大文字、最长行、竖/横画幅和平台 UI。一个代表性帧通过不代表整片，人物和 Cutaway变化会改变背景与碰撞。

## 修改范围

仅改文字错字通常不改变主线时长；改分卡和 Timing 会影响 Preview；改 Style 可能影响全片布局；主声音变化使 Caption stale。Impact 应与修改类型一致。

## 当前工具与能力

当前 MCP 可 `read_captions` 与 `edit_captions`。后者只能对当前、与 Script 一致的 SpeechAsset 所生成的稳定 Card 做原子修改：屏幕文案（最多两行）、有限字号/颜色/安全区、一个连续强调短语，或恢复语音原文；它不接受时间范围，也不会改 Script、SpeechSegment 和声音。若主线原文或时序变化，旧 Card 会被明确 stale 或重建，不能静默沿用。`occurrence` 从 0 开始，仍没有逐词时间或逐词动画能力。

任何修改后要读回 Caption、Revision、Impact，渲染真实 Preview。只看文本 JSON 不能发现遮挡、行宽、画幅和阅读时间问题。

## 验证

完整播放检查：文字是否与声音一致；Card 是否有足够阅读时间；换行是否自然；强调是否帮助而不是干扰；近景、产品、证据和 UI 是否被遮；静音时观众能否理解必要内容；有声时字幕是否重复主视觉。

## 交接合同

输入是最终可播放语音、Script、Timing、画幅、人物/Scene 和 Style。输出是 Caption Card、布局、强调和精度声明。它会影响 Preview 和 Quality。验证是阅读速度、语义分卡、遮挡、同步和整片疲劳。完成后返回主要工作流。
