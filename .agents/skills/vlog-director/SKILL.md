# Vlog、实拍事件与现场感完整工作流

<!-- material-scene-v3:vlog-director:begin -->
## 主题型日常片：由实际空间与行为决定表现

用户只给日常/空间主题时，先以可得真实材料和源声发展角度，而不是因为动效案例可用便改为规则科普。使用 [素材到场面方法](../_shared/MATERIAL_TO_SCENE.md) 选择真实的视线、行为、局部或环境变化；初稿可以先行，采用时回到实际可辨内容。

图形服务当前观察：引导到书架的一段、标出通道或帮助读到真实标识；不默认在实拍下方另摆独立小物体。两馆、不同时间和不同来源明确区分，可以形成编辑上的对照，不能伪装为同一现场连续跟拍。

无动效但源动作与声音已经有吸引力时保留镜头；需要解释才使用适配的图形。整体→局部→继续真实镜头的源时刻与对象归属在交接里写清，现场观察结束后再切到有理由的新场景。源材料不支持原稿时与文案一起改稿，导演不要求用户补专业素材。

## 执行角色与代理交接

本主要视频工作流运行在导演子代理中，由 [production-coordinator](../production-coordinator/SKILL.md) 分派，并经 [production-director](../production-director/SKILL.md) 选定。导演负责整片创意判断、主线、阶段安排和跨段协调；“主工作流”不表示主任务在主线程创作。

到具体阶段才提出专项范围与依赖，由主任务真实分派专项子代理；不递归分派，也不把加载 Skill 当作调用。导演提供已确定的完整方案或专项任务，接收实际项目对象、Revision、Impact、证据和未知后判断 Gate。正式项目写入、异步生成与渲染、审计保存都由主任务统一执行，导演不直接提交。遵循 [代理角色与交接](../_shared/PROJECT_REVISION_AND_HANDOFF.md#代理角色与交接)，实际 Preview 经主任务回传原负责人修订，输入变化重新确认受影响决定，最终专业审片交审片子代理。

## 根据需求构思观看主线，以真实事件决定采用

总导演结合用户想呈现的经历、已知事件与已有拍摄，提出从开头到结尾的观看主线：建立什么处境，跟随哪些行动、观察或体验，各段怎样发展，最后如何完成这次经历。尚未确认的行动、结果和反应保留为待核候选，不能为了完整结构直接写成已发生的事实。

主线初稿指导选片、补材和分镜，真实审阅决定能够采用的内容与必要改写。普通日常可以依靠观察深入、细节、空间与情绪展开，不必预设冲突或理想结局。地图、资料、补充画面、明确示意和动效可以帮助讲清经历；漂亮镜头与音乐不能代替真实事件。

初步主线用于提出探索问题，不要求实拍必须符合预设剧情。素材专项可以找出原先未注意的行动、细节、环境声与反应，导演据此重排观看顺序或改写初稿。不同人物、地点或日期的素材即使剪接顺畅，也不能冒充同一真实事件；用于类比或补充说明时保留其用途。

`vlog-director` 负责完整链路：建立素材证据和事件地图，选择 Shot，保护动作、空间、视线、时间和情绪连续，安排长镜头与 Montage，调用字幕、声音、B-roll 和必要 Remotion，最后完成整片审查。当前镜头分析、事件聚类和自动 Vlog Timeline 尚未完整实现时，本 Skill 可以生成可执行计划和使用当前基础 Scene/Timeline 能力，但不能声称自动剪辑已完成。

## 适用范围

适合旅行、日常、活动、制作过程、宠物、运动、幕后、体验记录和以现场事件为主的访谈纪录。若人物坐在镜头前持续讲述，核心仍是语言和人物关系，交给 Presenter；若旁白和图形建立机制，交给 Explainer。

Vlog 可以有旁白、字幕和 MG，但这些是辅助。若移除实拍事件后视频仍完全成立，可能它其实是口播或解释片，而不是 Vlog。

## Gate A：先理解素材

### 建立素材地图

不要一上来把所有 Clip 按文件名或拍摄顺序放入 Timeline。先识别地点、人物、动作、对象、声音、质量、镜头功能、时间和可能的事件。对关键范围保存 Source Range 和 Evidence；低质量、重复、误拍、严重失焦和无意义摇晃应标记，但不要仅凭画质删除可能重要的反应或事实。

### Event Map

一个事件通常包含：当前状态、目标或问题、尝试/行动、变化/障碍、结果、人物或环境反应。普通生活没有明显冲突也可以组织为观察、发现、变化和余韵，不必人为制造戏剧。

例如猫咪从窗边听到声音、回头、走向门口、停下观察，是一个微型事件。只把最可爱的三个特写按音乐拼起来会得到素材集合；保留声音触发、回头、移动和停下，观众能跟随行为。

### Shot 功能

每个选中镜头应承担至少一个功能：建立空间、推进动作、展示细节、表现反应、连接时间/地点、提供氛围或形成节奏。相邻镜头功能完全相同且没有变化时，应删减或重新选择。

### Shot Selects

选择不是按“画面最好看”排序，而是看事件需要。一个略微抖动但包含关键反应的镜头可能比稳定空镜重要。记录选中和拒绝理由，保护动作前后余量、现场声和可用转场。

## 连续性

### 动作连续

切点应考虑动作准备、主相位和结果。相同动作从两个角度切换时，避免重复动作或突然跳过关键相位。高速运动的切点需要真实帧证据，不能按粗转写或固定拍点猜。

### 空间和方向

人物从左向右移动后，下一个镜头若突然反向，观众可能以为折返。轴线、视线、入口/出口和地标帮助定位。可以有意打破，但要用建立镜头、反应或声音重新定位。

### 时间连续

不同天气、光线、服装和物体状态混在一起会制造假同时性。若是蒙太奇，可以通过章节、音乐或旁白明确概括；若叙述具体事件，必须保护真实顺序。

### 情绪连续

反应镜头属于事件，不是装饰。行动结果后若没有反应，情绪无法落地；借用另一时刻的表情可能制造假反应。人物情绪、现场声和镜头长度应共同表达价值变化。

## 长镜头、Montage 和节奏

动作、空间、表演或环境本身有发展时，保留较长镜头可以让观众进入现场。Montage 适合压缩重复过程、表现积累、时间流逝或多角度能量，但每个镜头仍应提供新信息或感觉。

音乐拍点可以帮助组织，但不自动决定切点。优先切在动作、视线、构图、声音和事件变化上，再看是否与音乐形成关系。每拍一切会让真实体验被音乐吞没；完全无音乐变化又可能缺结构。

## 自然声和听觉视点

Vlog 的现场感很大程度来自环境声、脚步、门、风、水、动物、观众反应和空间混响。不要用一条 BGM 覆盖全部。可以在建立新地点时让环境声先进入，在关键动作处保留真实声音，在 Montage 中适度抬高音乐，再在反应和结尾恢复现场。

声音桥可以跨镜头保持事件连续。若画面先切到下一地点但声音仍在旧地点，要有明确意图；不要因为音轨操作方便造成错误空间。

## 补镜和外部素材

按整片主线与分镜检查缺口。缺事件事实、必要过程和人物反应，需同一经历的可靠依据；缺地点建立、背景、空间关系、体验或节奏画面，则可以补充表达材料。网络素材和生成镜头不能冒充用户亲拍、同一现场或当时真实反应。

先查项目素材，再向 `visual-asset-sourcing` 提出具体需求；必要时通过已发布能力取得外部资料、生成明确示意或制作动效。说明服务哪段、要展示什么、需要的连续源范围与接续条件。候选审阅后由总导演决定采用、继续补充或修改分镜；关键事件无依据时调整讲述，不拼造经历。

分镜未定时先找会改变观看方向的过程与细节，分镜明确后再找对应镜头；实际材料足够便不重复搜索。选择同一来源的连续范围或成组片段，有助于取得动作、结果和反应，但不把来源相同当作必选条件；最终仍看真实内容及其组合效果。

`cutaway-planning` 负责额外素材怎样进入和返回。漂亮空镜不能代替人物行动和反应。

## 字幕和 Remotion

新增动画先按 [秒级初始节奏与预览修订](../_shared/EDITORIAL_FOUNDATIONS.md#秒级初始节奏与预览修订) 给出大约的秒级范围与动作衔接，完成首版后连同实拍事件、字幕和现场声连续观看再调整。原素材时间是实际证据；缩短图形不能自动裁短完整动作、原声或用户锁定总长。

对话和旁白需要字幕时调用 `captions`，但自然环境和动作不必被文字解释。标题、路线、地点、时间、简单地图和章节可使用 Remotion；复杂卡片、持续动态字幕和大量效果通常会破坏 Vlog 的现场感。包装应服从事件。

## 当前能力边界

当前 MCP 已实现 `submit_vlog_analysis`、`read_vlog_plan`、`manage_vlog_events`、`manage_vlog_shot_selects`、`compile_vlog_montage` 和 `manage_vlog_music_beats`。它们能把已完成媒体分析的素材转换为技术 Shot Boundary、由导演确认的 Event Map/Shot Select，以及 Background 与 Ambient 轨上的 Montage；写入后应读回计划、Revision、Impact 和 Preview。

这不是自动事件理解或自动选片：Shot Boundary 只提供源范围、变化分数和音轨事实；Event、Select、源声保留和 Montage 顺序仍由主工作流根据真实审阅决定。上述 MCP 合同已经有确定性测试，但真实素材中的事件理解、复杂节奏、现场声连续和完整审美仍须通过 `inspect_asset`、连续 Preview 与五轮审片验证。无法以当前素材兑现判断时，输出清楚的 Event/Shot Plan 和能力缺口，不把计划写成成片。

## 详细素材审阅流程

### 第一轮：技术和重复

查看时长、画幅、帧率、音轨、失焦、严重抖动、重复和损坏。技术差不等于无用，关键事实/反应可以保留；漂亮重复镜头也可能删除。

### 第二轮：按时间恢复事件

先按真实拍摄顺序建立地点、人物、对象和动作。不要在第一遍为了故事随意重排。标记人物何时知道什么、物体状态怎样变化、环境声和天气是否连续。

### 第三轮：事件与 Shot 功能

为每个候选写事件角色和镜头功能。建立镜头不是因为“广角”，而是给空间；细节不是因为“特写”，而是展示动作或对象；反应不是表情素材库，而是对当前结果的真实回应。

### 第四轮：Selects 与 Stringout

依据当前主线初稿建立较宽松的 Selects/Stringout，保留动作与声音余量，用真实镜头检验观看顺序、事件完整性和段落作用。发现缺口后，区分补看原素材、补充说明画面，还是初稿预设了无法证明的过程，由总导演补全或改写。随后压缩重复、细化镜头与节奏，不到 Stringout 完成才第一次考虑整片怎样讲；不直接选最短范围而丢失前因、结果和反应。

粗排实际镜头与原声，检查每次切换是否保留必要的前因、结果、空间或情绪。单条素材都合适而组合后重复或断裂时，先调整选段和组合；若观看过程本身没有发展，由导演修订主线，不交素材专项无限补空镜。

## 当前项目对象如何承载 Vlog 计划

当前 Revision 已有 Shot Analysis、VlogEvent、VlogShotSelect、VlogMusicBeat、VlogMontageScene、TimelineItem 和 ProductionRun。`submit_vlog_analysis` 先形成技术边界证据；主工作流使用 `manage_vlog_events` 和 `manage_vlog_shot_selects` 明确事件与选择；`compile_vlog_montage` 才把已确认 Select 写入 Timeline。应明确哪些是源证据、哪些已进入 Timeline，并在每次写入后读回；不要让临时文本成为第二份 Timeline，也不要把技术边界误写成导演事件。

## 实拍内容的重排伦理

Vlog 可以压缩时间、并置相似行动和使用概括蒙太奇，但不能让观众误以为两个事件同时发生、某个反应针对不存在的对象、或用户在实际没有到过的地点。外部 Stock 和生成画面必须标记为补充/示意，不能伪装为用户拍摄。

## 与主要专项的交接

- narration-writing：仅在需要新增或获准改写解说时使用，负责相应旁白与声画配合；实拍事件、真实对话和原声继续决定本片观看顺序，不为调用写作 Skill 强行增加旁白。

- `asset-import`：完整媒体和来源；
- `semantic-continuity`：真实对话/旁白的完整语义；
- `visual-asset-sourcing`：确有必要的建立镜头或补充，不替事件；
- `cutaway-planning`：补镜怎样进入和返回；
- `audio-finishing`：现场声、音乐、声音桥；
- `captions`：必要对话和坐标；
- `remotion-production`：地点、路线、时间、简单图形，不接管主线。

主工作流完成每次交接后重新看事件链，而不是让各工种独立优化造成整体失真。

## Vlog 的完整观看检查

从头到尾问：人物/对象的目标何时建立；行动是否推进；变化是否可感知；反应是否有时间；重复镜头是否消耗；观众是否在空间上迷失；音乐是否把不同事件强行统一；结尾是结果、余韵还是突然停止。

## Gate B：构建与审查

主线先由真实 Shot 和现场声成立，再加入必要字幕、音乐、标题和补镜。检查每个 Scene 是否有事件功能，动作和方向是否连续，环境声是否自然，音乐是否压过现场，MG 是否克制。局部 Preview 不能代替完整事件播放。

## Gate C：交付

只听声音检查空间和事件，静音看画面检查动作、方向和重复，完整声画检查情绪与节奏，首次观众检查是否知道人物在做什么、为什么关心和最后发生了什么。正式 Delivery 仍遵循 `quality-verification` 与 `export`。

## 三个典型案例

### 猫咪日常

不要只选可爱特写。先建立窗边、声音出现、猫回头、靠近门口、停下观察和最终反应。若没有明显结果，可以在停下观察处收束，保留环境声和呼吸。小标题只用于时间或地点，不要给每个动作加拟声字。

### 游泳

动作准备、入水、划水、转身、到达和呼吸形成连续。高速段可以使用 Montage，但入水和转身的关键相位不能被音乐拍点截断。水声和呼吸应在重要位置被听见，慢动作只能用于真实动作细节，不可任意减速造成时间错觉。

### 访谈式纪录

人物回答仍需要 `semantic-continuity` 保护完整观点；环境、手部、听众反应和地点可以丰富，但反应必须真实对应。B-roll不应覆盖最重要的表情和犹豫。

## 交接合同

本主工作流接收素材、镜头证据、Event Map、Shot Selects、现场声、字幕和必要包装，并负责整片收口。完成条件是事件和情绪来自真实素材、镜头功能清楚、连续性成立、环境声被保留、包装克制、辅助审阅与未审范围如实记录、能力缺口明确、交付绑定目标 Revision。

## 从技术 Shot Boundary 到导演 Event

`submit_vlog_analysis` 提供镜头变化边界、源范围、变化分数和音轨事实；它不说明镜头里发生了什么，也不决定故事价值。得到 Shot Boundary 后，先用 `inspect_asset overview` 建立素材地图；对可能构成事件的范围使用 `range` 查看连续动作和声音；对快速动作、反应、镜头运动起止和精确切点使用最小 `dense` 窗口。完成这些审阅后，才创建 VlogEvent 和 VlogShotSelect。

Event Map 中的目标、行动、变化、结果和反应必须能够回到真实 Shot 与源范围。Shot Select 要说明镜头功能、选择理由、动作余量、现场声策略以及它与前后镜头的因果、反应、相似、对立、递进或空间关系。scene score、文件顺序、清晰度和时长只用于技术筛选，不能自动进入 Montage。

不同素材使用不同事件判断。猫咪视频可能由声音触发、回头、移动、停下和反应构成事件；游泳视频需要保护准备、入水、划水、转身、到达和呼吸；旅行素材还要维护地点、方向、时间和环境声。主工作流应先让事件成立，再决定音乐、字幕和少量 Remotion，不能用卡点替代动作和反应。
