# SIM → 页面 → 撕纸 → 实拍：24 秒连续案例

[观看选定视频](assets/preview.mp4) · [固定版本源码](assets/motion.tsx) · [画布、素材与合成参数](assets/fixture.json)

这是用户选定的最早一条 24 秒案例，768×1344、24 fps、576 个视频帧。它不是一份 TSX 单独输出的全部画面：Remotion 负责 SIM、演示页面、撕纸和前景包装，外层视频轨负责后段的基站与手机实拍。容器中的音轨不能证明完成了声音设计；本例没有旁白与音效设计。

## 先决定观众怎样发现问题

本段的认知路线是“看起来相似的对象，为什么受到不同处理→到规则里找解释→回到真实使用环境”。因此不把三句话分别做成三张标题卡，而是让注意力跟随同一组对象，选中一件，再把观看尺度从物体推到页面，最后打开纸面，把视线交给现实素材。

SIM 只作机制隐喻：五张卡的 A–E 与“优先处理”不是实际套餐等级。页面正文明确标注“演示页面 / 非运营商原文”；示意表达调度差异，不把优先级说成凭空增加带宽。改写新题材时先确认是否仍有“群体—选中—规则—现实”的关系，再换对象和内容，不能只替换 SIM 上的文字。

## 美术与连续身份怎么建立

深墨底 `#151716` 与黄绿强调色 `#bcff42` 形成高反差；银灰卡体和金色芯片先负责“这是物体”，选中标签、正文高亮与撕开后的结论再共用强调色。绿色的职责是串联注意，并非所有新视频都要采用黑绿风格。

`Chip` 用 SVG 画接触面；`Sim` 以八层带裁角的平面、逐层 translateZ 和方向一致的阴影近似厚度。父级透视承载整体观察角度，子级保持五张卡的坐标和身份。选中的始终是 index=4：上抬、变大、标签高亮都来自同一个 select 进度，未选卡降低对比，避免观众以为镜头换了一组产品。这是 CSS 2.5D，不是真三维模型或物理光照。

页面沿用同一个 `Page` 组件。先作为手机中的内容进入，随后淡去边框、推近正文，最后把同一页裁为上下两部分。纸内文字与高亮不会在撕开时重新随机排版，所以观众能确认打开的是刚才阅读的那一页。

## 代码怎样把状态连起来

`useCurrentFrame()` 是唯一时间来源。`ease` 为两端收速的三次缓动，`out` 用较快建立、逐渐停稳的曲线；`mix` 把进度映射为位置、尺度和透明度。选择、放大、换景并非每帧都同时动，主动作按照阅读任务依次交棒。

| 局部帧（24 fps） | 源码与动作 | 为什么接得上 |
|---|---|---|
| 10–66 | 各卡 spread 按 index 错开 4 帧 | 从一个堆叠体展开，落点有差异但属于同一空间。 |
| 72–105、108–148 | 标签建立，select/focus 选中并靠近 | 先认识群体，再看差异；不是所有对象同时最大化。 |
| 163–225 | take 放大选中卡；stageAway 166–205；phoneIn 187–225 | 旧场尚未完全退出，手机已经进入，重叠承担接力。 |
| 227–298 | push 推近至 274；highlight 278–298 | 镜头先把正文送到可读尺度，底色再指出具体句子。 |
| 326–364 | rip 326–354；结论 340–364 | 纸面尚在分开，结论已从裂口建立，不等纸退出后另开标题页。 |
| 385–430 | open 撕开至 426；结论退出 396–414；实拍说明 413–430 | 开口、旧字退出、新素材说明形成连续接力。 |
| 468–514 | 黄绿斜擦 468–497；最终文字 494–514 | 覆盖切镜点，下一段文字在擦除尚未结束时起势。 |

`ridge` 用 81 个固定点、三组不同频率的正弦扰动生成纸边；它不随时间重新随机采样。上下遮罩共享这条边，一边反向遍历，避免撕裂两侧轮廓不吻合。gap=`rip×185 + open×850`，先开一个能露出结论的缝，再大幅打开交出画面。

## 本例修过什么，怎样避免再次“卡顿”

[早期源码](assets/before-motion.tsx) 与选定版的实际差异包含：页面横坐标从 112→−10 改为固定 64，减少推近时的横向偏移；撕裂边从粗齿改为固定多尺度细边；rip=0 时只渲染一张完整页面，开始撕裂后才使用两个裁切层，避免未撕开就出现接缝。这些属于构图与遮罩修订，不应冒称帧率修复。

连续感主要来自上述动作交叠，以及页面和纸面保持身份。阅读段 298–326 的短停留有明确用途，不能为了让检测器不报静止而让全文持续晃动。若复用后觉得停顿，先看停留是否仍在提供阅读，前一动作何时结束、后一动作何时启动，再改区间；不要把整段统一倍速。

本例包含 CSS 3D。它在当时生成过合成视频，但这不保证换浏览器、字体或运行版本仍逐像素确定。重新生成若出现同帧不一致，应检查合成层与投影，必要时改为显式 SVG 投影；不能关闭一致性检查。完整分类和实际修订证据见[停顿与顺滑经验](../motion-case-library/references/timing-continuity.md)。

## 实拍接管和改写边界

包内 [基站素材](assets/tower.mp4) 与 [手机素材](assets/phone.mp4) 是原来已下载的素材副本，不是动效生成的视频。保存的 Cutaway 配置是在 24 fps 时间线上让基站占 384–480、手机占 480–576，均使用源起点后的 96 帧、cover、源声音静音。该配置来自保存的 R13 合成记录，最终选定预览为 R16/v2，不能把这份精简摘要宣称为完整 R16 项目快照。

Remotion 背景随 open 退为透明；底层必须已存在对应素材，否则开口将露出空底。正式使用由现有合成链绑定素材，不能把带底的预览 MP4 当作透明包装覆盖人物。素材授权记录保留原来的 unknown，案例选择不等于重新确认素材交付权利。

本例几何和时序按画布写定，props.title 并未用于实际文案。换稿、换比例或换时间长度需要修改页面内容、坐标、状态区间及外层素材入点；只改 props 不会自动重排。若配音效，撕开、主要落点与擦除可提供候选事件，但要根据真实旁白和可见动作确定 attack/onset，不能直接每段头部放一声。
