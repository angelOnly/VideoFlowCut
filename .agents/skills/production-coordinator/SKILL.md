# 视频生产协调

先用 [项目基础](../project-basics/SKILL.md) 定位当前 Project、Revision、目标对象与未结束 Job；尚无项目就如实交接，不编造标识。主任务负责沟通、事实、真实分派、确定性提交、技术核对与交付。

## 按任务继续

剪辑中的专业决定由 Codex 的导演与专项作者自主完成，包括选材、剪点、节奏、声音采用、试听、审片和返修；不要求用户试听片段、挑选候选或逐项确认后才能继续。用户已要求全权处理时，将该要求随任务交接传递。检查能力不足按[共享交接](../_shared/PROJECT_REVISION_AND_HANDOFF.md#技术检查、辅助审阅与人工定稿)保留具体未知并继续可执行工作，不转交用户补做检查；只有现有授权无法覆盖的任务范围变化或不可推断的必要信息才向用户询问。

完整视频分派导演前，必须先读取 [视频类型路由](references/video-type-routing.md)，综合本次用户要求、完整稿及需求补充、当前项目和明确有效的已有采用决定；关键类型、说话人、原声或改稿权限仍不明时，由主任务向用户询问最小必要问题，未确认前不创建依赖该选择的正式生产任务。类型明确后才分派主导演，并在每次 `spawn_agent`、`followup_task`、接替和结果续接中传递主类型、人物／声音来源、编辑权限、当前范围及真实 Revision。下游不得自行改片型。

完整视频用宿主 `spawn_agent` 启动持续负责的导演，让其读取 [production-director](../production-director/SKILL.md) 并沿已采用类型进入相应主视频流程。局部创意直接交相应专项，完整参数的机械修改可直接执行。准备派发、续接或接替时读取 [任务路由](references/task-routing.md)，按依赖和当前名额安排；Skill 数量不等于代理数量。

`visual_explainer` 与 `presenter_motion` 的完整解释沿[主题入口](../_shared/TOPIC_TO_FILM.md)并行共创；完整新制或主要视觉重做接入[创意统筹](../creative-sequence-design/SKILL.md)和[视觉入口](../visual-treatment-planning/SKILL.md)。职责、同一当前稿、范围接回和返修沿[唯一交接约定](../_shared/PROJECT_REVISION_AND_HANDOFF.md)，不为每项规则再创建代理。

实际写入、生成、渲染、审计、字体选择或恢复时读取 [项目写入](references/project-writes.md) 对应章节，核对实时 Schema，按唯一顺序提交并读回版本、影响与结果。主任务只补真实 ID 和无歧义参数，不补创意。结果未知先对账原 Job，不能换幂等键重放。

## 完整视频的持续协作、OD 对接与返修

完整解释视频和主要视觉重构，由一个持续主导演和一个持续视觉作者负责整片；主任务负责真实分派、项目操作、正式提交、反馈投递和结果接回。

### 一、首轮并行分派

主任务建立完整 ProductionRun，读取当前 Project、Revision、用户要求、当前稿和已有材料，分派一个持续负责的主导演。

主导演确定初步方向后，主任务按职责分派：
- 文案作者：必须接入现有 `narration-writing`，负责事实研究、观点结构、初稿或现有文案诊断与授权范围内的持续改稿。用户提供完整/锁定文案时仍完成适配检查，但不得擅自重写。
- 素材作者：真实素材搜索、核实和观察。
- 创意作者：creative-case-library、creative-sequence-design。
- 视觉作者：visual-treatment-planning、creative-reference-to-sequence、motion-case-library。

文案作者、素材作者、创意作者和视觉作者从首轮并行工作。文案作者与主导演、素材、创意和视觉作者按问题直接双向协作；创意作者与视觉作者直接协作；素材作者与视觉作者直接协作。视觉作者从首轮开始观察真实素材和视觉参考，不等待其他作者全部结束。

Skill 数量不等于代理数量。并发受限时允许相邻职责由同一作者兼任，但必须分别完成对应专业工作，并保留真实结果和交接关系。不得因角色兼任而省略创意研究或视觉研究。

### 二、当前成果接回与交叉传递

每个作者返回当前成果或新发现后，主任务接回实际文件、决策 ID、来源、版本和未完成项，并交给需要使用的原负责人：

- 素材作者的实际素材、Asset ID、源范围和观察结果交给视觉、创意和主导演。
- 创意作者的正式研究决策、原片和采用范围交给视觉和主导演。
- 视觉作者的素材观察、视觉构思和素材缺口交给主导演、素材作者和创意作者。
- 文案变化交主导演及受影响的素材、创意和视觉作者；文案作者负责合并并交回当前完整正文。

不得只记录任务已启动、Agent 已返回或 Skill 已加载。必须接回实际结果；不得由主任务代替专业作者解释研究或完成视觉设计。

### 三、持续共同编排

主导演持续负责整片主线、事实、观看方向和跨场关系。

创意作者负责完整参考研究、创意深化和迁移判断。

视觉作者负责真实素材观察、整片视觉创作、美术、构图、排印、镜头、运动和连续作品。

创意作者与视觉作者直接双向沟通，不通过主导演逐条转述。素材作者与视觉作者直接沟通素材作用和补搜缺口。主导演持续接收各作者的新发现并协调调整。

初次创作、OD 制作期间的补充工作和返修都使用这套并行分派、结果接回和交叉传递机制，不另设返修路由。不同工作可以多轮往返，不要求严格串行。一个场面需要补搜时，只续接相应素材或创意任务；其他不依赖该缺口的工作继续。

### 四、正式制作准备

视觉作者完成当前目标范围的视觉方案和同源预排，主导演检查内容、事实、真实素材主次、整片方向和场间关系。

主任务接回：
- 主导演对当前方向的判断。
- 原视觉作者的整片视觉稿和同源预排。
- 当前完整 MotionWork、根时间轴和目标范围。
- 准确文案、声音、素材和参考。
- 正式制作简报、文件和深化边界。

主任务先调用现有 `prepare_motion_handoff` 核对资料；主导演正式 adoption 时引用当前视觉设计和交付清单，再通过现有制作准入检查。未满足当前目标范围依赖时不得正式提交 OD；不依赖缺口的其他场面可以继续。

### 五、OD 制作、当前作品接回与同一协作循环

视觉作者是 OD 的主要专业对接人，负责解释完整视觉方案、同源预排、素材映射、主要构图、镜头、运动和深化边界。

主任务先将已进入当前项目的预排范围和工作台入口交回原视觉作者，由原视觉作者在工作台查看实际合成；可由已有控件完成的调整直接保存，并在结果版原位复查。

主任务负责正式提交 OD 请求、记录原制作委托，并接回同版作品及其 `editorUrl`、Revision、Work、Run、Frozen Version 和根帧范围。阶段交付后继续将同版工作台入口和实际范围交给原视觉作者，检查作品、修订并在新版本复查。

OD 每次返回当前作品后，主任务将作品交回原作者团队，重新进入本章第三节的同一协作机制。初次创作、OD 制作期间的补充工作和后续返修使用相同的作者角色、职责边界、结果接回和问题回流规则：

- 视觉作者检查真实素材、素材主次、构图、美术、排版、镜头、运动和整片视觉连续性；判断视觉方案本身是否成立，并作为 OD 主要专业对接人整理具体反馈、提出修改要求和复核结果。
- 创意作者对照原始参考检查创意迁移；发现偏差时，将原片对应过程、当前作品差异和应保留的核心关系交给视觉作者，与视觉作者共同确定修改。
- 素材作者按视觉作者和主导演提出的具体缺口，继续搜索、核实和补充素材。
- 文案作者按主导演协调的范围修订内容、事实和讲述。
- 主导演持续检查整片内容、事实、主线和场间关系，协调优先级、跨场影响和重大导演决策。
- 主任务负责正式反馈投递、Job/Run/Revision/Frozen Version 对账和结果接回。
- OD 根据视觉作者确认的制作反馈，沿原委托和同一 MotionWork 修复实现问题，并返回新的可检查版本。

如果问题来自视觉方案本身，视觉作者先与相关作者共同调整方案和同源预排；主导演检查是否影响整片方向。只有视觉方案发生实质变化时，主任务先准备受影响范围的制作交付，主导演再判断是否更新 adoption 并关联新清单。

如果视觉方案本身成立，只是 OD 没有准确实现，视觉作者直接提出实现反馈，主任务投递给原 OD 委托，OD 沿原作品返修，视觉作者复核。此类实现返修不重复走完整创意研究和导演 adoption。

### 六、同一协作循环中的问题责任与最终交付

按问题归属处理，不增加独立审批节点：

- 内容、事实、用户锁定项、主线和场间关系：主导演负责判断与协调。
- 创意参考理解、创意迁移和风格还原：创意作者负责分析，视觉作者共同确定本片处理方式。
- 真实素材组织、构图、美术、排印、镜头、运动和整片视觉连续性：视觉作者负责提出修改要求并验收。
- 素材搜索、取得和来源核实：素材作者负责。
- 源码、绑定、时钟、渲染和已采用方案的实现偏差：原 OD 制作作者负责修复。
- 正式反馈投递、Job/Run/Revision/Frozen Version 对账和结果接回：主任务负责。

主导演持续掌握所有问题和返修，协调优先级、跨场影响和是否需要重新采用；但不代替视觉作者与 OD 逐项讨论字体、构图、镜头和运动参数。

完整作品的声音、字幕、合成和声画质量按现有链路检查。主导演结合所有作者的实际复核结果，完成唯一的最终交付判断。最终检查未通过时，问题回到本章同一协作机制，不创建独立返修流程。

## 交回结果

返回当前稿、实际对象与版本、已完成范围、确定缺失、观察未知、原作者续接结果及真实可用文件。技术条件允许时可继续生成预览或导出；已确定的设计缺失、实现遗漏和必需表现未兑现仍由主任务续接原负责人处理，不能以“已导出”结束制作。感知能力不足只保留对应观察未知，其他已授权工作继续，不伪造通过，也不无限盲改。技术输出、创作完成与用户认可分别报告。角色接替、版本和事实传递遵循[唯一交接约定](../_shared/PROJECT_REVISION_AND_HANDOFF.md)。

`presenter_motion` 完整解释首轮同步落实人物导演、材料探索与整场视觉责任；人物源返回后继续接回材料、作品、绑定及合成。`vlog` 由事件导演按真实原片决定是否补材和增加视觉工作。收口范围依据本次用户要求确定，整片使用 project，内容范围使用 beats，局部对象修改使用 objects，明确的时间区间使用 frames（结束帧不包含在内）。独立工作台审阅自动以实际观察区间建立 review_only 任务。交付前按任务路由中的“按本次范围收口”读取实际制作状态、处理缺项、调用完成接口并读回结果。

当前范围采用 OpenDesign 时，主任务按[任务路由](references/task-routing.md#视觉派发与接回的完成口径)续接原视觉负责人。创意作者交回参考场面后，将完整采用意见、参考视频、文案和实际素材交给视觉作者，与创意作者共同完成本片编排。

接回视觉负责人写好的制作简报、实际资料路径和完整请求，补齐正式项目参数并提交。实际作品和修订版本继续接回原视觉与创意作者，对照参考检查和返修。
