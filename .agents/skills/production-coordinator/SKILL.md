# 视频生产协调与创意子代理分派

## 主任务控制字体候选与用户选择

理想字体未收录属于选择问题，不提交修复工单。主任务查询`read_motion_capabilities`并交给正在负责这段文字视觉的原作者，由原作者推荐最多3款已登记字体，返回准确ID、实际预览文案、用途和每款理由；导演只给整片风格与文字用途，推荐不由导演和作者重复共同选择，也不另开字体代理。主任务不补创意或自行挑选替代。

主任务通过`get_editor_url(project_id, panel="fonts", font_preview={text, expected_font?, purpose?, candidates:[{font_id,reason}]})`提供推荐预览链接。用户在工作台看实际字样，点击复制选择后在聊天确认；界面操作不写项目，复制不表示已采用。未回复不自动采用首选或把等待报成故障，只暂缓依赖字体的相关画面，继续无依赖工作。用户选择后主任务`followup_task`续接原作者，交回选择、当前Revision与依赖差异，让原作者修订排版和动作，再按完整产物排序提交；只有跨段风格冲突交导演协调。

若`submit_motion_work`明确返回`code=MOTION_FONT_UNKNOWN`、`stage=validation`、`sideEffects=none`、`safeToRetry=true`、`recovery=select_registered_font`，进入上述选择流程，不报工单，不重放原输入；用户确认后修订为已登记ID再提交。这是提交前未创建Job的窄分支，不适用于运行失败、网络超时或结果未知。已登记原件损坏、加载失败仍报平台故障。实际采用与原计划的差异保存在现有creativeBrief和创意决策记录，最终按预期字体去重提示替代与可选扩充，用户自己决定是否扩充。

## 只有主题时：组织完整创作和材料交接

按 [主题到成片](../_shared/TOPIC_TO_FILM.md) 组织持续负责的导演和现有专项。缺少用户稿件、素材、参考或固定时长不是停工条件；普通创作选择在团队内完成，正式项目写入、任务追踪和版本对账仍由主任务集中执行。

涉及实际材料的关键场面，交给原作者的是原件可达入口、实际源范围、观察记录以及导演完整采用稿，使用 [素材到场面方法](../_shared/MATERIAL_TO_SCENE.md)。确认稿中写了源内具体对象与结合方式；只有“放手机素材再做动画”的摘要，回原导演或作者补设计，协调者不自行发明位置、细节或剧情。

定向媒体问题通过现有`analyze_media`的`depth=review`和`input.context`提交；index/discovery仅保存用途说明，不能误当该问题已送模型。读取真实覆盖、方法与未知，再交原负责人。坐标估计不能用模型输出包装成自动跟踪。

素材适配采用后，按实时Schema更新需求、采用范围、Scene/VisualTreatment和作品绑定；图片清空不适用的连续视频时长条件，保留真实事实限制。作品返回并放置后，用`bind_media_adoption`关联准确的`motionImageSlot`或`motionVideoSlot`；外层`slot=motion`不能代替内部来源关联。读回相关版本，不按整条素材推定所有用途已审。

首个预览就检查作者和审片者能否取得同一实际媒体。关键混合场面的复核范围包含材料进入前、交接中途、发展后与下一画面；范围预览的文件毫秒与整片帧用返回composition映射。分别记录工程、设计、观看与声音状态。普通素材未命中继续适配；实际工具故障沿原Repair Ticket处理，不绕过MCP或要求用户重传已在项目中的材料。

## 主任务的职责

原素材审阅部分失败时，主任务读取 `inspect_asset.diagnostics` 控制流程，不把单张空图片扩大成全片停工。`diagnostics.recovery=inspect_available_evidence` 将有效证据、失败时间点和连续代理状态交回原素材作者；作者决定继续查看局部、换范围或换候选，主任务排序调用。`diagnostics.recovery=select_another_candidate` 暂不采用当前候选，继续正常搜索/下载另一候选，不删除旧记录、不重放旧下载；原因未知不能说原视频已损坏。只有 `diagnostics.recovery=report_platform_failure` 报修受影响步骤，其他无依赖工作继续。range/dense 没有可用连续代理仍待审，截图不能替代连续观看；本工具只写审阅缓存，不改变 Asset 状态、采用、Revision 或 Job。

先读取 [project-basics](../project-basics/SKILL.md) 定位 Project、当前 Revision、对象、素材、未完成 Job 和实时 MCP Schema。主任务收集用户约束与反馈，准备事实、调度、提交、检查引用与资源状态、交付和报障。只要仍需决定“怎样表达才合适”，包括观众承诺、故事、风格、选材、文稿、构图、运动、听感和专业审片，就交子代理；不能把这些决定藏在任务说明、参数装配或最终验收里自行完成。

完整视频启动一个持续负责的导演子代理，由它读取 [production-director](../production-director/SKILL.md) 并只选择一个主要视频工作流。这里的“主工作流”是导演的专业职责，“主任务”是协调者，两者不是同一个执行位置。导演返回范围内的创意结论、下一项专项工作和依赖，主任务据此分派；跨段风格、声音与视觉冲突仍回到导演。

尚无项目时，先把用户输入与“尚无 Project/Revision”的事实交导演形成路由和建项建议；主任务按明确参数创建项目并读回真实版本，再交导演确认正式创意产物的输入。采用与来源审计前绑定实际 Project 和输入 Revision，不为满足交接字段编造 ID 或版本。

局部创意直接分派对应专项，例如 [captions](../captions/SKILL.md)、[audio-finishing](../audio-finishing/SKILL.md)、[cutaway-planning](../cutaway-planning/SKILL.md) 或 [remotion-production](../remotion-production/SKILL.md)，不重跑整片。用户说“把指定字幕上移 20 像素”可以直接执行；“字幕放哪里更舒服”则由专项判断。指定文件导入、客观转写和媒体参数读取可在主任务完成；最终素材采用、删留和表演选择属于创意。

只派发当前已到达的阶段，按完整工作范围选负责人；同一代理可以承担相关专项，不要求每行单独启动代理。

## 真实分派与续接

读取 [代理角色与交接合同](../_shared/PROJECT_REVISION_AND_HANDOFF.md#代理角色与交接)，使用当前宿主的 `spawn_agent` 启动子代理，用 `followup_task` 把证据或修订任务交回原负责人。这些是宿主协作工具，不是 VideoFlowCut MCP；不得用 Agent 工作单、读取 Skill 或手写报告冒充调用，也不为专项创建侧边栏任务。只在可独立推进的范围内并行，不按 Skill 数量拆代理。

首次分派提供稳定分派标识、职责 director/specialist/reviewer、已有 Project 和输入 Revision、对象与源范围、用户硬约束、相关事实和前后接口；宿主返回后再关联真实代理标识，不提前编造 agent ID。专项子代理得到完整范围后直接创作，可在同一个代理中按需读取构图、时机或案例资料，不再递归派发。需要其他专项时返回明确工作请求，由主任务调度。

子代理返回完整产物与执行参数、选择理由、输入版本、影响范围，以及需要的素材或 Preview。摘要和“做一个高级动画”不够提交；缺少创意细节时返回原代理补全。素材请求或待审阅只表示对应事项未完成；不把待审阅扩大为整片制作停工或不能导出。

主题起步、委托原创解说或允许实质优化草稿时，导演先明确创作范围与初步方向，由主任务分派 narration-writing。文案专项返回完整朗读正文、逐段声画初稿和研究/素材请求；导演接收全文及实际材料后决定采用、修订与整片分镜。文稿和画面中的需要查清的问题允许先探索，不要求最终分镜或精确时长已经确定。

素材返回与预览反馈同时交原文案作者和相关导演，涉及讲述的修改由原作者更新完整稿。主任务传全文及当前负责段落的完整上下文，不压缩成标题或效果名。正式朗读正文经导演采用和语义核对后，由主任务沿 apply_authored_script 写入；真实原话剪辑保持现有 semantic-continuity 路径。

按完整范围派发，不按 Skill 数量拆代理；相关视觉和动效工作可由同一专项完成。返回产物缺少创意内容时，续接原负责人补齐；主任务只补真实 ID、版本和无歧义装配，不自行写新画面、删动作或换模板。

相关专项收到同一份完整场面，包含实际发展、载体、文字与讲述分工和允许修订范围。协作回复保留原设计上下文，不能分别转成“加字幕”“加动效”“加音效”的孤立清单；主要表达变化由导演采用，主任务只转录完整决定和确定性参数。

### 完整场面的深化、协调与实现

同一场面的美术、运动和受管源码默认由同一授权视觉作者连续负责，可按需
读取多个相关 Skills。给作者实际素材、完整声画稿和前后接点，不缩成效果名。
代表段的实际作品与合成回同一作者修订；导演协调主要表达和跨段关系。
不为读取案例、制作关键帧或调用另一个 Skill 自动增加一位代理。

完整视觉动效段先由同一专项作者连续完成视觉与运动设计，按需读取相关 Skills。首次派发要求：根据导演完整分镜及前后画面，主动补足段内发现、主体美术、关键构图、连续动作、文字与声音；先交完整设计和必要关键画面。已看出不成立的构思先改进，必须通过运动判断的关系提出限定范围试作请求。导演未指定坐标或曲线不是退回静态说明的理由。

收到完整深化稿后，正常续接原导演，把全文、关键画面、版本与前后接口交它统筹。导演返回吸收深化结果的完整分镜、具体续接要求与未解决项；主任务将统一采用稿及差异回原作者继续设计、试作或正式实现。主要表达变化提前反馈是额外规则，不能替代每份完整深化稿的常规导演协调；局部参数不逐项送审。已能判断不成立的设计不以“采用”收口，动态未知不预先宣布通过。

完整分镜、深化稿和协调稿保留在真实宿主消息中，采用决定及产物引用写入现有 CreativeDecision，固定作品保存完整指令与源码。审计和结构化段落信息不是通用文稿存储；恢复尚未提交作品的长篇设计仍需原任务全文，缺失回原负责人补全，不靠更换 Revision 或摘要续作。

### 素材探索、定向补齐与导演回传

导演提出关键材料探索或具体镜头补齐任务时，主任务把完整问题、初步方向或当前分镜、已有事实、用户约束与依赖交给素材专项，使用当前宿主真实分派或续接原负责人。先按现有名额和接替规则操作，不按阶段或候选数量新建重复代理；专项不递归分派。

探索没有最终 Beat、Scene、精确时长时如实说明，不能因此拒绝创作或编造对象。尚无 Project/Revision 时先传用户输入与真实建项状态，按现有流程创建后再回传正式版本。专业探索说明可通过已有交接文本表达，不增加假定的任务枚举或绕过正式需求校验。

候选返回后，主任务检查引用、媒体可用状态、范围、参数和未完成项，将实际材料及完整观察交回原导演。缺证据时补齐原文件、连续范围或声音输入；主任务的观感与摘要不替代接收者实际查看。导演返回明确采用、修订分镜或继续搜索的决定，才调度依赖这个选择的专项制作，不根据候选得分自行选片。

正式下载、导入、生成、采用、放置和审计保存由主任务按实时合同排序，包括完成时会改写项目的异步 Job。主任务读回实际结果、Revision 和影响，再交原负责人确认依赖；收到外部变化先回传差异，不仅更改 base Revision 重发旧创意。未知提交先对账，能力或工具阻断沿独立 Repair Ticket 处理。

采用后回传 Cutaway、视觉、动效和声音所需的真实源范围、构图与原声限制及前后接口；实际合成回原负责人修订，跨段问题回导演，最终专业审阅交审片子代理。探索资料或尚未完成的辅助观看只标注影响范围，不扩大成整片停工，也不默认让用户逐阶段批准。

### 名额不足时续接与接替

分派或恢复前先用宿主 `list_agents` 读取实际代理列表，并核对本轮提供的名额上限是否包含主任务。列表中的 `completed` 只表示该轮结束，不证明线程已关闭或名额已释放；`interrupt_agent` 也只用于中断，不用它清理名额。宿主未提供关闭工具时，不能编造关闭调用、修改全局上限或假设退出一轮就会腾出位置。

原负责人仍在列表且空闲时，用 `followup_task` 续接同一个代理；正在工作时交给该负责人并等待相关依赖，不再创建重复负责人。原负责人不在列表时先判断恢复是否需要名额：有空位才尝试恢复，成功与否以实际调用为准。列表未满仍被拒绝时，保留调用前后列表、上限说明和原始错误，不能自行认定计数正确或存在泄漏。

名额已满而原负责人无法恢复时，优先让现有、职责合适且当前任务已结束的代理接替；所有合适代理都在忙时，只等待这一项依赖，继续其他已授权工作。不要在满额后立即另开新的同职责代理。跨专业范围或创意分歧交导演决定接替范围；主任务负责传递已经确定的职责与完整事实，不补做创意。

接替先沿[负责人接替与结果接收](../_shared/PROJECT_REVISION_AND_HANDOFF.md#负责人接替与结果接收)交清用户约束、原产物、真实提交和新预览。接任者明确确认输入版本、接手范围和缺失内容后，才成为该范围当前负责人。主任务按当前分派、负责人和版本接收结果；旧负责人迟到的回复保留为历史材料，不直接提交。恢复失败时报告独立 Repair Ticket；只有状态变化或接替方案成立后重新判断下一步，不反复调用同一失败续接，更不重放项目写入。

### 工具可见范围与事实交接

首次分派和续接后的子代理都先检查本轮实际工具表：能发现哪些必要只读工具，参数是否为当前 Schema，以及一次必要只读调用是否真正成功。仅在工具实际可调用时执行；主任务提供的 Schema 用于理解和组装方案，不会给子代理增加工具权限。`read_runtime_release` 可用于核验连接，但同版不能替代实际业务工具可见性或所需材料的读取。

主任务首次分派就按[事实交接与能力核验](../_shared/PROJECT_REVISION_AND_HANDOFF.md#事实交接与能力核验)准备本范围必要事实。子代理缺 MCP 工具时，停止该代理的直接调用并如实回报；主任务沿独立工单记录工具缺口后，用自己可用的正式只读 MCP 补齐事实并回传，专业判断仍由原代理或已确认接任者完成。这条路径恢复的是事实交接，不表示子代理直接 MCP 访问已修好。主任务也无法读取时，只保留该项缺失和阻断，不能用 shell、HTTP 或浏览器脚本绕过。

子代理返回具体材料请求，注明 Project、所需版本、对象与范围、缺少的字段或观察材料；主任务重新读取后补齐。实际版本有变化时连同 Impact 和差异回传，由负责人确认，不能把旧事实包改个 Revision 数字继续使用。需要观看的预览、帧或音频必须由接收者实际打开；路径存在或主任务的观感不能替代观察。缺材料保留未完成范围，缺连续感知保留相应辅助审阅状态，均不扩大为无关制作停工。

## 项目写入与预览回传

主任务是正式项目唯一写入者：按实时 Schema 提交子代理完整方案、生成与渲染任务、审计和质量记录。正文专业 Skills 中的“写入”“调用”“修订”描述工作要求，项目命令由主任务执行。子代理可读取可用事实和真实证据，但不直接修改正式 Project、提交生成 Job 或保存审计。

提交前核对当前 Revision、目标对象与依赖，主任务只补真实 ID、工具返回的新对象 ID 和无歧义的字段装配。按导演或专项给出的完整参数排序提交现有项目对象、声音和受管作品，粗剪也遵守同一合同。会在完成时回写项目的异步 Job 等终态后读回对象、Revision 和 Impact，再安排依赖写入；不以顺序发出 API 代替后台依赖排序。出现外部变化时，读回差异和失效范围，交原子代理重新确认受影响产物，不能直接换 `base_revision_id` 重发。

取得实际 Timeline/Preview 或作品后，将版本、素材绑定、事件、真实媒体、临时内容范围和已知缺口回传原负责人。粗剪由导演看完整观看过程，作品由专项看实现及专业细节，跨段影响回导演。路径存在与主任务观感转述不能代替负责人打开媒体；无感知证据如实保留对应未审，不独立构成制作和导出阻断。

一个完整动效段的闭环是：导演分镜 → 专项完整深化 → 原导演协调并返回统一稿 → 原作者继续设计、必要试作或正式实现 → 主任务提交完整说明、源码、Props、绑定与事件帧 → 跟踪读回 → 原作者核对实际作品并修订 → 主任务按完整参数放置并取得真实合成 → 原专项与原导演观察 → 按范围交[审片子代理](../quality-verification/SKILL.md)复核。作品生成、独立作品通过、真实合成通过和整片交付是不同结论。媒体必须由接收者实际打开，缺对应证据保留待审。

粗剪、代表段与阶段合成都正常回原导演，取得可沿用设计、需改段落、下一项具体制作范围与整片剩余依赖，再继续制作。用户要完整视频时，一个样片不结束整片任务。素材或工具故障只停受影响步骤，其他无依赖工作继续；正式参数已确定的机械修改仍走短路径，不强制重跑整片创作。

## 技术核验与审计

主任务核对引用、版本、范围、资源就绪、Job 结果、证据覆盖及文件规格；专业判断由导演、专项与审片子代理负责。未获得连续画面或真实音频的相应结论保留 inconclusive，不把文件存在、播放器启动或静帧当成完整观看。

专业审片先按本轮要求取得实际媒体观察，再对照计划；主任务转录审片原结论，不代替其艺术判断。遗漏动作、构图或声音局部问题回原专项；设计主线、主要画面或跨段关系不成立回导演；事实与技术问题分别补核与报障。

回派包含原问题、实际证据、当前版本与影响范围，负责人返回具体修订及完整参数。主任务核对依赖后提交，再把新版本媒体续接回去。新素材、声音或时序有变化时由原负责人确认差异，不能只换 base Revision 重发旧创意。

记录已经观察和仍未观察的范围，不把 AI 未审或未关闭审美意见变成导出禁令。技术和用途按当前合同检查，最终用户批准属于具体 Artifact。工具故障或未知写入走独立 Repair Ticket，缺创意产物回负责人，不由主任务修改平台或补做创作。

使用 [MCP 执行合同](../_shared/MCP_EXECUTION_CONTRACT.md#创意委派来源审计) 中实际发布的 `record_creative_decision` 保存委派来源，复用现有对象与证据引用；保存审计不创建视频 Revision。代理标识由真实宿主调用返回，不能编造。自报 delegation 用于追溯，不认证真实调用；执行验收同时保留宿主分派、产物返回和预览续接记录。

## 失败处理

缺产物回原代理补全；创意失败回专项，跨段冲突回导演；缺证据返回具体范围与所需观察方式。代理退出或不可续接时，先检查名额并优先复用现有合适负责人；有空位才启动新的同职责子代理，并完成上述接替确认，不能改由主任务创作。

宿主没有子代理能力时阻断相关创意步骤。工具缺失、MCP 错误、Runtime 故障或结果未知时停止该步，按 [剪辑阻断与平台修复交接](../_shared/PROJECT_REVISION_AND_HANDOFF.md#剪辑阻断与平台修复交接) 由主任务记录 `report_editing_blocker`；未知写入先对账，不重放。无法报告时明确保留阻断事实，不伪造 Ticket。剪辑角色不得改平台源码、配置、插件缓存或正式项目外文件来绕过。

素材搜索只允许一项窄例外：正式错误同时返回 `sideEffects="none"`、`safeToRetry=true` 和恢复依据，才可按 `list_asset_providers` 纠正参数，或等待 `retryAfterMs` 后再搜索一次。同因再次失败即报障；该规则不适用于下载、生成、项目写入和未知结果。已有部分候选交原专项检查，并保留 `diagnostics` 中的未完成项，不把局部搜索失败扩大为所有来源都无素材。

## 交接合同

本次范围完成时应能从实际记录追溯：哪个子代理基于哪个 Revision 完成了什么产物；主任务实际提交了什么对象和新版本；哪些范围失效并已复核；哪个审阅者看了什么实际证据；还有哪些未完成、能力缺口或用户待决事项。局部任务按局部范围退出；完整成片的专业收口回导演，技术检查后由主任务执行 [export](../export/SKILL.md)。用户批准仍绑定具体 Artifact，子代理审阅和工具成功均不能代替它。
