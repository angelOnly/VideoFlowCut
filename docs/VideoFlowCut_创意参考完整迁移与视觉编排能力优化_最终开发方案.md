# 1. 目标与范围

## 1.1 最终创作目标

**真实素材是视频的主体，旁白负责讲述内容，创意和视觉负责让这些真实素材形成有美感、有构图、有层次、有连续运动、有节奏的完整视觉作品。**

旁白说的是内容，画面不需要逐句翻译旁白，也不应把解释旁白作为创意和视觉工作的重心。

画面需要做到：

1.  让真实素材成为值得观看的主体。
2.  让不同真实素材之间形成有设计的视觉关系。
3.  让主体、空间、构图、花字、背景和镜头发生有设计的变化。
4.  让一幅画面自然发展成下一幅画面，而不是机械切换。
5.  让视觉表现有强弱、有变化、有停留、有高潮。
6.  让整部视频具有统一的美术语言，同时不同场面具有各自的视觉表现。

真实素材优先级：

1.  先研究真实素材本身的动作、构图、场景和可用源范围。
2.  再研究多条真实素材怎样通过接管、并列、叠放、交叉、累积和连续运动形成完整演出。
3.  创意参考改变真实素材的组织方式、整幅构图和画面发展。
4.  动效机制实现和强化这些画面关系。
5.  不允许原创图形承担独立的主要内容表达。

## 1.2 禁止原创图形承担独立解释表达

完整解说视频不得使用原创图解、原创流程图、原创数据演示、原创抽象物件或原创动画场景，替代真实素材承担旁白所讲述的主要内容。

不得以"真实素材无法表达"为由，自动转向原创图形表达。素材表现不足时，应继续完成素材搜索、源范围研究、取景、裁切、多素材组织、创意参考迁移和动效机制应用。

允许使用参考中已有的画框、色面、遮挡、花字、线条、空间、镜头和运动方法，但这些设计必须服务于真实素材的组织和表现，不得独立组成一套替代实拍的解释世界。

禁止以下做法：

-   先制作一套原创解释动画，再把实拍作为背景、角落插图或短暂点缀。
-   因内容涉及数据、概率、流程、机制或不可见过程，就默认用原创图形演示。
-   以"素材承担不了表达"为由绕过素材检索、素材组合和参考迁移。
-   用原创物件、原创流程图或抽象动画代替本应持续观看的真实素材。

如果当前素材组织效果不成立，必须回到素材、创意或视觉环节解决，不得用原创图形作为退路。

## 1.3 用户输入与默认行为

用户只需提供文案、画幅等基本制作要求。用户不需要提供：

-   创意参考卡号。
-   动效机制卡号。
-   预写照排指令。
-   每场的构图和镜头安排。
-   对视觉表现的额外提醒。

系统必须自主完成整片视觉研究、参考检索、候选比较、完整参考选择、创意迁移、视觉编排、OD
制作和审核。

## 1.4 本次不做的事情

-   不新增 Agent、导演角色或审核角色。
-   不新增独立创意数据库、视觉状态系统或预览系统。
-   不重建创意库、动效机制库、素材库或播放器。
-   不新增与本目标无关的 MCP 工具。
-   不恢复创意卡中预写的完整照排正文，不让下游机械换料。
-   不改变用户提供完整文案时的既有文案权限边界。
-   不改变正式首版必须使用真实旁白的要求。
-   不改变 OD 第一版直接制作动态作品的模式。
-   不做无关 UI、渲染器、播放器、基础设施和目录重构。
-   不增加固定素材占比、镜头数量、动画数量或参考卡数量作为质量替代指标。

# 2. 当前问题与根因

本方案基于此前对当前 `main` 技能、派工链路、R40、0.1.92、01
单场照排和近期机器人交付的核对。实施时仍须重新读取当前 `main`
的实际文件，不能把本节当作代码现状的永久快照。

## 2.1 创意研究有三层，但没有形成真正的整片创作任务

当前 `creative-sequence-design` 已经包含：

-   整体视觉组织。
-   完整场面创意。
-   局部运动机制。

当前 `creative-case-library` 也已经包含：

-   根据观看体验形成查询。
-   研究对象关系。
-   翻译成镜头表达。
-   跨题材检索。
-   原速观看候选原片。
-   全片美术查询。

所以问题不是没有三层研究，也不是再加一段"三层研究"的文字就能解决。

根因是：

1.  三层目前主要是知识分类，没有形成强制的先后依赖和正式交付成果。
2.  `creative-case-library`
    虽然提到全片研究，实际查询入口仍容易从单场代表素材、单句旁白和局部观看问题开始。
3.  创意作者可以先找到局部机制，再把局部结果拼成整片，缺少阻止局部结果冒充完整创意的硬性规则。
4.  `research_coverage` 的 `covered`
    状态只是研究记录，不能证明整片视觉组织、完整场面和运动关系已经形成可执行方案。
5.  所有参考研究完成后，没有强制要求创意作者重新检查和组织整片素材，参考容易只修正局部，不改变全片画面组织。
6.  普通新片的实际派工仍出现"选用成熟整段才进入完整迁移专项"的条件分流，导致完整迁移被当成可选路线。

## 2.2 完整迁移已有方法，但容易只保留内容含义和动作关系

当前 `full-reference-transfer.md` 已经有：

-   原片原速观看。
-   逐拍定位。
-   初始状态、运动对象、保持对象和接手对象。
-   干净原帧及标注。
-   本片素材对应。
-   同状态对位。
-   连续过程对照。
-   视觉补偿说明。

但现有方法更容易证明对象关系和素材对应正确，没有足够强地约束原片完整视觉表现必须迁移。

容易丢失的内容包括：

-   整幅构图和主体分量。
-   空间、背景、前后层级和遮挡。
-   美术、色彩、材质和明暗差异。
-   花字的字形、字号、字重、倾斜、承托和运动。
-   多层同时存在、旧层保持和新层接管。
-   连续运动的关键中途。
-   视觉高潮、结果停留和出口。

因此，换料时可能保留原片的内容含义、工作点或动作方向，却把原片的画面表现降级成实拍播放、简单运镜和普通文字渐显。

## 2.3 视觉作者有复摆职责，但没有承担完整视觉表现的不可转移责任

当前视觉作者已经有：

-   观看创意原片。
-   查看本片素材。
-   复摆。
-   整片视觉导演稿。
-   美术、构图和运动设计。
-   OD 制作请求。
-   首版回件复核。

问题不是缺少这些步骤，而是缺少一条不可被替代的责任：

**视觉作者必须对创意参考的完整视觉表现如何落实到本片承担最终视觉实现责任。**

当前流程容易把"原片时刻找到了、素材映射正确、复摆图存在、导演稿写了"当成完成依据。它们只能证明研究和交接发生过，不能证明原片的视觉表现真正迁移到了本片。

## 2.4 主导演有内容主线职责，但整片视觉导演基准不够具体

当前 `production-director/SKILL.md`
已经有整片主线、场面任务、真实素材参与、参考采用和视觉稿确认等要求。

缺口不是完全没有视觉职责，而是导演工作仍容易围绕内容讲述和素材证据组织，没有形成一份可供创意、视觉作者共同使用的整片视觉导演基准。

导演需要先实际观看真实素材，确定整片视觉方向、素材主体、场间关系和需要研究的完整视觉问题；但不提前替创意作者决定具体参考和构图。

## 2.5 研究、实现、OD 和审核没有使用同一组视觉决定

现有
`CreativeDecision`、`ProductionUnitHandoff`、`visualPlan.referenceMappings`、OD
制作请求和 `reference_reviews` 已有基本关联能力。

但实际交接仍可能只传递参考编号、原片范围和总体意图，关键视觉特征没有贯穿所有阶段。

结果是：

-   创意研究记录了原片关系。
-   创意稿写了本片迁移。
-   视觉作者复摆时可能删减表现。
-   OD 请求可能只剩概括性指令。
-   审核无法依据同一组锁定特征准确判断是否简化。

必须让同一项视觉决定从研究、迁移、视觉实现、OD
制作到成片审核始终可追溯。

# 3. 创作模式调整——最终决定

## 3.1 彻底删除 original

**最终决定：original 模式从类型、Schema、程序分支、MCP 契约、UI、Skills 和测试中彻底删除；不保留、不兼容、不迁移。**

**`original` 创作模式彻底删除，不保留、不兼容、不迁移。**

删除范围包括：

1.  TypeScript 类型、枚举及联合类型中的 `original` 模式值。
2.  Zod Schema 和相关数据校验中的 `original` 模式值。
3.  `ProductionUnitHandoff` 中对应的正式模式分支。
4.  MCP 输入输出契约中作为创作模式使用的 `original` 值。
5.  所有根据创作模式 `original` 进行的程序分支。
6.  UI 中的 `original` 模式选项、标签、说明和选择逻辑。
7.  默认值、状态转换、正式制作准入和回执处理中的 `original` 分支。
8.  Skills、派工提示词、交接文档、模板和测试中的 `original`
    创作模式定义。
9.  所有允许通过 `original` 代替完整创意参考迁移的判定。

不保留 deprecated 枚举，不增加 fallback，不将旧 `original` 自动转换为
`full_reference`，不增加历史兼容分支。

不主动删除历史交付文件和历史项目资料，但不保证旧 `original`
模式任务能够在新版中恢复、继续执行或通过新 Schema
校验。不得为此增加兼容代码或数据迁移。

注意：只删除作为创作模式的 `original`，不得误删代码中其他含义的
original，例如原片、原始素材等普通业务字段。

## 3.2 full_reference：普通完整新片唯一主创意模式

普通完整解说新片的主要视觉单元必须采用 `full_reference`。

这里的自主是指：

-   创意作者自主检索。
-   创意作者自主观看和比较候选。
-   创意作者自主选择参考。
-   创意作者自主组合多个参考。
-   创意作者根据本片真实素材重新设计完整演出。

不是脱离参考库进行原创视觉表达。

完整迁移不是照搬整支参考视频，而是完整迁移所选原片范围内决定视觉效果的建立、发展、关键变化、结果和出口。

一个完整参考可以覆盖多个连续场面，多个参考也可以共同组织整片视觉，不要求每场必须使用一张不同的卡。

参考来自创意库还是动效机制库，不决定它是否属于完整参考。判断依据是它是否提供了完整视觉过程：

-   创意参考通常承担整幅构图、画面组织和完整视觉发展。
-   动效机制参考如果本身提供完整视觉演出过程，也可以承担完整参考迁移。
-   动效机制如果只解决一个局部运动，则只能作为辅助机制。

## 3.3 local_mechanism：只能辅助完整创意，或用于独立专项

普通完整新片中，`local_mechanism` 不再作为与 `full_reference`
平级的单元完成模式。

它只能用于：

1.  完整参考已经确定，但某个具体运动关系仍需研究。
2.  主体接管、素材交叉、对象保持、遮挡或连续运动的实现需要补充。
3.  视觉作者发现已成立的画面设计缺少具体运动方法。

普通完整新片中，局部机制应作为同一完整创意单元的辅助研究，记录到现有
`motion_research` 和
`visualPlan.referenceMappings`，不得将该单元的主模式改成
`local_mechanism`。

独立动效机制专项任务仍允许使用
`local_mechanism`，但不得借此完成普通完整新片的主创意准入。

实施前必须核对当前模式字段分别属于 ProductionRun、ProductionUnitHandoff
还是专项任务。优先使用现有任务类型区分普通完整新片和独立机制专项；只有现有结构确实无法区分时，才做最小必要调整，不得借机重构任务系统。

## 3.4 普通新片唯一正式流程

`整片视觉研究 → 完整参考检索 → 参考选择与组合 → 完整视觉迁移 → 局部机制补充 → 视觉作者整片编排 → OD 制作`

局部机制只能补充完整创意，不得替代主参考。

普通完整新片每个正式主要视觉单元必须有完整参考覆盖。一个参考可以覆盖多个连续单元，多个参考也可以共同覆盖一个完整单元。不得要求每场一张卡，也不得以一个局部机制映射冒充完整覆盖。

## 3.5 参考案例必须吸收的已验证经验

本次不把案例中的具体画面硬编码进新项目，而是将案例中已经验证的方法转化为
Skills 的研究和验收要求。

### 3.5.1 R40：整片问题驱动的多层参考研究

R40 的检索从整篇内容和视觉问题出发，而不是先决定局部动画。

当时的查询包括：

1.  同一动作或物件反复出现，数量逐渐累积，原本让人放心的结果逐步发生变化。
2.  一个步骤的异常让后续工作相继等待。
3.  重复固定工作与可以更换场景的灵活工作如何形成对比。
4.  同一对象快速重复形成阵列，一个位置变化后其余对象依次受影响。

最终参考承担不同设计职责：

-   `016-c01`：多来源活动画面、画框、文字带、线条和整幅视觉组织。
-   `026-m07`：圆阵、方阵、扫描、散开、重新聚合，形成完整视觉发展。
-   `032-m09`：同一活动实拍越框、全屏、收回、扫描并交给后续处理。

R40
的核心不是参考数量，而是参考承担不同层次的设计职责，并由视觉作者统一成同一部作品。

R40 的 R32
首版仍出现固定左右分栏、近全屏文字流程图等问题。导演通过实际画面检查，要求实拍、点阵、数字和背景共同参与变化。该返修证明：参考、素材、映射和源码齐全，不等于画面已经兑现。

### 3.5.2 0.1.92：局部机制可以组织成持续视觉世界

0.1.92《AI
的油门与刹车》证明，即使参考库提供的是局部运动机制，只要视觉作者拥有完整画面设计责任，也可以将机制组织进同一持续视觉空间。

已记录的做法包括：

-   按多个观看问题检索机制。
-   以八个阶段组织同一持续空间。

4. 对照调整前后的画面，判断观众实际失去了什么。
5. 如果删除后造成主体辨认、空间层次、素材关系、连续接管、视觉差异、节奏重音或结果收束的损失，则将该特征标记为必须保留。
6. 如果删除后没有造成可辨认的视觉损失，该特征不必作为核心迁移要求，可以根据本片需要调整。

每项必须保留的特征记录：
- 原片时刻。
- 原片视觉特征。
- 该特征产生的实际视觉作用。
- 删除或简化后的具体损失。
- 本片对应素材和目标范围。
- 本片保留方式或等效补偿方式。

不得只写“该效果很重要”“不能简化”。必须指出删除后具体失去了什么视觉效果。

不得将原片的装饰性细节全部当作不可修改的要求。必须保住的是决定视觉效果的关键特征，而不是机械复制所有元素。

最终确认的必须保留特征进入本片完整迁移稿，供视觉作者复摆、OD 制作和成片审核共同使用。

## 原片视觉表现保留与等效重建

完整迁移以原片实际视觉表现为基准。

不能只记录内容含义、对象关系和动作顺序。

必须检查原片的完整画面组织：

1. 主体在画面中的视觉分量。
2. 整幅构图和空间关系。
3. 画面前后层级和遮挡。
4. 美术、色彩、明暗和材质。
5. 字形、字号、字重、断行、倾角和承托。
6. 多素材共存和连续变化。
7. 运动速度、力度、停留和收势。
8. 视觉高潮、结果和出口。

## 素材替换的视觉补偿

原片主体与本片素材不同，不代表可以删除原片的关键视觉表现。

必须明确：
- 哪些原片表现可以直接保留。
- 哪些需要替换具体素材。
- 哪些需要重新构图或运动设计。
- 哪些视觉特征无法直接复制。
- 本片通过什么方式补偿其视觉作用。

补偿必须在本片真实素材上实际试摆，不能只写文字理由。

不得以内容含义相同、工作点相似或方向一致代替视觉表现保留。

## 同状态与连续过程双重对照

同状态对照：

将原片关键状态与本片对应状态放在同一画幅比较。

先缩小看第一眼落点、主体分量、视觉重心和空白形状，再恢复正常尺寸检查取景、字形、前后层级、材质和遮挡。

连续过程对照：

连续播放原片采用段和本片完整演出。

检查建立、保持、响应、共存、接管、关键中途、落点和出口。

不能只对照首尾帧。

必须检查中途是否发生简化，特别是：
- 多层同时运动被拆成独立动画。
- 旧层过早退出。
- 真实素材被切成普通插图。
- 整幅视觉变化被简化为文字渐显。
- 花字被统一成同款普通标签。
- 画面高潮和最终收束被删除。

## 完成条件

只有原片决定效果的视觉特征在本片得到保留，或有经过实际画面验证的补偿，才能确认完整迁移成立。

静态对位正确不代表连续过程正确。

素材映射正确不代表视觉表现正确。

完整迁移稿必须由原创意作者确认；视觉作者完成双重对照后，才能进入正式制作稿。
```

## 正式接件的双重对照

## 七项视觉表现标准

1. 主体表现：真实素材中的主体、动作或细节具有明确的观看主位，实际取景能够展示其形态、动作和关键细节。

```

# 7. 验收标准

验收必须以实际作者执行结果和实际画面为依据，不能以技能文本存在、工具调用成功、状态登记成功或代码生成成功代替。

## 7.1 第一轮：01 单场盲复测

输入： - 原片 `001-c01`。 - 原始九份真实素材。 - 原始旁白。 -
原画幅和目标时长。

不给旧创意稿和旧视觉导演稿。

验收： - 创意作者能独立选择完整参考。 -
能识别原片决定效果的完整视觉变化。 - 能完成真实素材之间的连续接力。 -
能保留不同视觉状态的构图、美术和花字表现。 -
能完成窗口累积、旧窗保持和最终回收。 -
视觉作者完成同状态和连续过程双重对照。 - OD
请求没有把主要视觉设计权交回制作端。

## 7.2 第二轮：02 两场连续创作

输入： - 完整文案。 - 真实素材。 - 画幅。 - 不提供参考编号和预写照排。

验收： - 从整片视觉研究开始，不从单句局部查询开始。 -
能自主形成整片和主要场面的参考研究。 -
多个参考承担不同层次的视觉职责。 -
创意参考确实改变本片素材的组织和画面发展。 -
两场之间形成真实视觉接续。 - 视觉作者统一两场的构图、美术和节奏。 -
不出现原创图形独立解释内容。

## 7.3 第三轮：完整六场成片

验收： - 完整声画首版使用真实旁白。 -
所有正式主要视觉单元有有效创意研究和完整迁移。 -
正式采用的每个参考都能在成片找到对应表现。 -
真实素材承担主要视觉内容。 -
多素材组织、接管、连续运动和花字设计成立。 - 场间视觉关系成立。 -
不存在无目的空镜、静音等待旁白。 - 所有正式参考和机制均完成实际复核。 -
审核能准确指出原片与本片的视觉差异。 -
返修能够沿同一研究决定追溯和确认。

## 7.4 程序契约测试

  测试场景                          预期结果
  --------------------------------- ----------------------------------
  普通完整新片提交 `original`       Schema 或准入拒绝，不做转换
  普通完整新片使用空创意参考        不允许正式采用
  只有 local_mechanism              不允许代替完整主参考
  只有 researched 状态              不允许代替有效研究证据
  full_reference 没有覆盖目标单元   不允许正式制作
  参考与目标帧范围不对应            返回具体缺口
  VisualPlan 丢失研究决定引用       不允许冻结或采用
  OD 请求删除锁定视觉特征           必须回提视觉作者确认
  审核没有逐参考实际观察            不得判定参考审核完成
  独立动效机制任务                  继续允许 local_mechanism
  原片、原始素材等普通字段          不受删除创作模式 original 的影响

## 最终完成标准

`original` 创作模式已从类型、Schema、程序分支、MCP 契约、UI、Skills
和测试中彻底删除。

不得以研究完成、素材绑定、代码生成或审核记录齐全代替实际画面效果。
