# 验证

当请求结果可见时，同时使用结构证据和视觉证据：

1. 根据情况使用 `read_project`、`preview_timeline`、`inspect_item`、`browse_assets` 或 `inspect_asset` 重新读取受影响范围。使用最新响应中的 ID、Track、时间和就绪状态。
2. 通过当前 manifest 暴露的视觉工具检查合成后的时间线帧。成功渲染或变更元数据并不等于视觉证明，必须实际检查返回的像素。

当原始路径可用时，使用本地源字节理解原始素材。原始文件在本地不可用时，使用 `inspect_asset`。源素材帧有助于选择片段，但不能证明时间线合成结果；对裁切、叠层、字幕、特效、裁剪、转场和 MG 动画，应使用合成时间线帧。

如果返回的是签名帧 URL，而宿主无法直接检查它们，应把完整且经过 shell 引号保护的 URL 下载到临时目录，再检查这些文件。不要仅凭 URL 报告视觉成功。

如果视觉证明被上传/就绪状态或渲染器状态阻塞，应明确报告阻塞原因，并在适当时让用户检查实时编辑器。绝不能把验证失败转化为不受支持的工具回退或虚假的完成声明。
