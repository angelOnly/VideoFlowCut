# 已知错误

把当前 MCP 工具 schema 和返回的结构化错误视为权威依据。当当前 manifest 不同时，不要使用记忆中的旧 payload 重试。

## 变更被拒绝

- 发生同轨重叠时，不要强行写入，也不要静默删除冲突 Item。判断内容是顺序内容还是叠层内容；适当时选择可用 Track，或询问应保留哪个 Item。
- 发生锁定 Track 或过期 ID 错误时，刷新受影响的时间线范围，只使用当前 ID 和状态重试。
- 发生校验错误时，只修改被拒绝的字段或事务结构；保留无关项目状态。

## 导入与媒体

- 托管插件表面使用 `asset-import` 适配器和 `import_media`；当后端专用的 `push_asset` 或 `download_media` 不存在时，不要用它们替代。
- 如果媒体转换失败，在辅助脚本提供结构化重试时使用该重试。否则说明源文件不受支持，并要求用户提供兼容替代文件；不要重复相同的失败编辑器导入路径。
- 只有在执行依赖字节的操作前才等待上传完成。当 Asset ID 已知时，即使字节仍在上传，也可以用于元数据和时间线放置。

## 生成与 MG 动画

- 只使用当前宿主上可见的生成工具。Codex 和 Claude Code 插件使用 `create_motion_graphic_from_code` 直接编写 MG 动画；内置 ChatCut Agent 可能暴露 `submit_motion_graphic`。
- 保留原始供应商或内容策略失败。不要在相同请求上反复消耗额度，也不要静默切换模型。

## 验证与导出

- 变更成功不等于视觉证明；必须看到结果时加载 `verification`。
- 渲染任务使用 `track_export`。如果云端渲染无法读取某个 Asset，只能在用户允许时通过 `asset-import` 解决远程就绪问题，否则报告限制。

遇到身份验证或项目访问错误时，先确认准确的 Project ID，并确认编辑器与插件使用同一个 ChatCut 账号，然后再尝试代码或基础设施调试。
