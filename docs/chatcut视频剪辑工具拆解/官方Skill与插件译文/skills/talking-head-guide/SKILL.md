# 语音主导型视频剪辑（口播、访谈、播客）

## 本 Skill 涵盖什么

**必需输入**：已经登记或导入 Project 的现有语音主导型源素材——例如单人 talking-head / 口播、双人或多人 interview / 访谈、视频播客、讲座、教程或课程。对于基于文字稿的 A-roll 编辑，先按照 `asset-import` 操作，然后在文字稿就绪后立即开始。如果用户想在没有源画面的情况下开始（例如从头生成新的 talking-head），本 Skill 不适用。

### 缺少源媒体时

- **Claude Code：** 用户可以在对话中提供源文件，也可以直接上传到已打开的 ChatCut 编辑器中。当对话附件或本地路径仍需导入 ChatCut 时，使用 `asset-import`。对于编辑器上传的文件，直接从已登记的 Project Asset 继续，不要再次导入。
- **Codex：** 让用户把源文件附加或拖入对话，然后按照 `asset-import` 操作。不要使用编辑器的 Browser 上传路径，也不要把用户引导到该路径：它目前可能导致 Codex Browser 运行时崩溃。

如果此工作流通过 Codex/连接器宿主运行，并且任务为用户创建、设定或打开 ChatCut Project，则在开始非平凡编辑前满足任何返回的 `browserHandoff.required=true`、`Codex internal Browser handoff` 或等价的实时 Project 交接；如果最终交付前可见编辑器已经不再对应当前 Project，则再次完成交接。

以下是可以独立应用于语音主导型视频的处理。选择符合用户需求的处理——并非每次都需要全部使用。

- **A-roll editing**（中文称 **语音剪辑** / 含 **去口癖、停顿、重复**）——基于文字稿的语音编辑。常见操作包括清理、提取精彩片段、重组、开场 Hook，以及为对齐后的目标所需的其他处理。
- **Motion graphics overlay**（英文展示给用户时写全称 **Motion Graphics**，不要缩成 "MG"；中文产品术语固定为 **MG 动画**——不要叫"动效""字幕条""动态字幕"等其它说法）——用屏幕上的 MG 动画强化关键信息、结构化内容和话题转场
- **B-roll**（行业术语——任何语言中都保留为 "B-roll"，不要翻译）——遮盖跳切，或把正在讲述的内容可视化
- **Background music**（中文 **背景音乐**）——建立情绪并平滑细小空隙
- **Captions**（中文 **字幕**）——用于无障碍访问的屏幕文字
- **AI Voice Isolation**（中文 **AI 人声隔离**）——使用 DeepFilterNet3 清理或分离人声，画面保持不变。参见 `voice-isolation` Skill。

> 用户语言为中文时，在 widget options / choices options / 对话文案里**严格使用上面括号里的产品术语**——别自己再翻译一遍，会跟产品其它地方对不上。

## 什么因素决定剪辑

除了选择处理方式之外，talking-head 剪辑还受到几个彼此正交的变量影响。当用户的要求模糊时，以下是最值得优先澄清的内容：

- **Target**——平台（YouTube / TikTok / Shorts / ...）、目标时长、宽高比
- **Which treatments to apply**——上面的处理是可选项；不要假设全部都要应用
- **Pacing / tone**——紧凑 / 有活力 / 正式 / 随意；如有说明，还包括品牌或声音偏好。（MG 视觉风格应遵循活动 Motion Graphics Skill/工作流。）

当这些变量中有多个缺失时，加载 `widget-forms` 后使用一个表单询问。不要提出 Markdown 编号问题，然后只针对同一轮收集中的某一部分追加 `<choices/>`。

## 执行顺序

当已经与用户对齐多个处理时，它们彼此依赖，必须按照依赖顺序最终确定。本节**只在完成对齐之后相关**——它不说明新请求应从什么开始。

语音时序（由 A-roll 编辑确定）锚定所有下游内容——MG 放置、B-roll 跳切遮盖、音乐时长和字幕同步都以最终语音 Timeline 为参照。

因此：在提交任何视觉、音频或文字层之前，先最终确定 A-roll 编辑。不要针对编辑前的语音制作字幕，不要按编辑前的时长裁切音乐，不要把 MG 放在之后还会变化的时序上。

剪辑结构最终确定后，作为最后一个音频步骤运行一次 `smooth_audio`——它会在每个硬音频切口处加入微型交叉淡化，并淡化暴露的边缘，避免编辑产生爆音。应在 `apply_script`/`clean_script` 重组之后运行（重新流排会移除转场）；它是幂等的，因此 Timeline 再次发生变化后可重新运行。

**每完成一个主要步骤后，都必须先与用户确认结果，再开始下一步**，除非用户明确要求不中断地端到端执行。应用多个处理时的关键检查点：A-roll 编辑最终确定语音时序后；MG 生成前（确认风格和方向，并且在不明显时确认它是叠在视频上，还是占据整个画面）；MG 生成后；B-roll、音乐和字幕同样如此。**不要把多个检查点捆绑在一条回复中——分别确认每一步。** 上游错误会迫使所有下游工作返工（例如把 MG 放在清理前的时序上，会在 Timeline 移动后浪费生成积分）。

## A-roll 编辑

### 场景

在 talking-head 工作流中，第一步通常是 A-roll 编辑：编辑原始语音画面。

A-roll 编辑最终会应用到 Timeline，并改变观众实际听到和看到的内容。不过，编辑决策通常应从文字稿开始，因为核心问题是：观众应听到哪些语音内容，以及哪些内容应被移除、压缩或重新排序？

### 常见 A-roll 任务

A-roll 编辑不只是清理。先判断用户要求的语音内容任务是什么，再选择编辑策略和工具。

常见任务：

- **Cleanup**——移除错误、重复尝试、口头习惯、填充词和无意义停顿，使语音更清晰、更自然。
- **Highlight extraction**——从较长素材中提取最有价值、最有观点、最有情绪或最符合主题的时刻。
- **Restructure**——重新排列语音内容，例如把结论提前、按主题分组，或把分散的内容组合成更清晰的结构。
- **Hook / short version**——从源素材中选取强有力的主张、结果、冲突或问题作为开场，或把长内容压缩成较短版本。
- **Target-script / script alignment**——按照用户提供的目标文稿、目标段落或期望内容匹配、保留并重新排列语音内容。

Cleanup 是最常见的任务，也是最容易因错误边界决策而失败的任务。下文会详细说明。其他任务的规则较短，但仍遵循共同的 A-roll 原则：语义完整、边界清楚、听感自然。

### 共同的 A-roll 原则

这些原则适用于所有 A-roll 任务，而不只适用于 Cleanup。

- **先确定任务，再选择工具。** 不要让工具可用性改变编辑策略。
- **按完整语义单元编辑。** 只要可能，就移动/删除/保留完整句子、完整想法、完整回答或完整步骤。不要只因为几个词匹配，就剪掉半句话。
- **当任务明确指定保留什么时，将范围裁到该边界。** 这是上一条规则的反向规则，适用于任何明确指定要保留哪些内容的任务——恢复特定句子、匹配目标文稿、提取指定精彩片段、构建某个版本：准确保留所请求的范围。将保留范围裁到从请求词语开始、在请求词语结束，并丢弃它所在源 `[sN]` Segment 中不属于目标文稿的头部/尾部；为了保留一句指定语句而保留整个 Segment，会过度保留并拖入用户未要求的语音。这只适用于任务明确指定保留什么的情况——绝不适用于开放式 Cleanup；开放式 Cleanup 中应保留完整单元（见上文）。
- **不要跨不同重录拼接未完成片段。** 不要把不同尝试中的不完整部分组合成一句人为拼接的话。这并不意味着早期尝试一定可以丢弃：如果一个完整且有用的引入、铺垫、对比、类别、评价或上下文没有在后续重复，并且可以自然连接到后续完整重录，则应保留。
- **保留连接组织。** 当删除列表标签、转折词、主语、动词或相邻源词会使保留的想法不合语法、突兀或误导时，它们就不是填充内容。裁掉最小范围，同时保持句子可说、可听。
- **保持自然听感。** 结果仍应具有自然措辞和呼吸空间。不要为了“干净”而让句子听起来像被强行粘在一起。
- **边界不确定时采取保守策略。** 如果不确定某个切口是否会损害含义、逻辑或听感，就保留它，或只做更小的切口。
- **复杂修改先确认。** 对于复杂重组、激进缩短、结构变化或生成式 Hook，编辑前先与用户确认目标时长、结构方向和必须保留的内容。
- **解释内容，不解释索引。** **绝不能**使用 `[sN]`、`[cN]`、`[gap]`、词索引、Clip ID 或 Segment ID 等内部地址向用户解释编辑。用户看不到这些地址，也不会理解。应使用实际说出的内容、短引文，或通俗语言描述编辑。
- **绝不要用屏幕方位称呼面板。** 邀请用户审阅或微调结果时，称它为 "the Transcript panel"（中文「文字稿面板」）——绝不要称左侧 / 右侧 / 侧边 / left / right / side。布局可以重新排列，该面板不固定在任何角落。

### Cleanup 目标与决策

#### 什么是好的 Cleanup

好的 Cleanup 不意味着尽可能缩短视频，也不意味着把说话者重写成另一份文稿。

好的 Cleanup 意味着：

- 逻辑保持连贯
- 表达变得更清楚
- 音频听起来自然
- 明显错误、重复尝试、无意义卡顿和填充词被移除
- 说话者的意图、语气和自然节奏得到保留

糟糕的 Cleanup 通常有两种失败方式：

- 清理不足：明显错误、重复、长停顿或填充词仍然存在。
- 过度清理：句子被截断、语义缺失、节奏过硬，或结果听起来像拼接而成。

默认原则：在不改变含义的情况下移除缺陷；让语音更顺畅，而不是更生硬；优先使用小范围局部切口，不要删除整句或整个 Segment；如果不确定某个切口是否会伤害含义，就保留它。

#### 如何判断常见 Cleanup 情况

以下是常见 Cleanup 类别及其编辑决策方法。

##### 无意义填充词

填充词分为两类。

第一类是明确无意义的犹豫音。通常可以安全移除：

- `um`
- `uh`
- `er`
- `ah`
- `呃`
- `额`

当它们不承载特殊含义时，优先使用 `clean_script` 批量清理。

第二类取决于上下文，不能仅凭词表删除：

- `so`
- `like`
- `然后`
- `就是`
- `嗯`
- `啊`
- `那个`
- `那`
- `对`
- `所以`
- `但是`

判断方法：

- 如果该词只是犹豫或填充，移除它。
- 如果它承载顺序、延续、转折、原因、指代、回应、强调或自然语气，保留它。
- 如果移除后周围词语听起来像硬切，保留该词，或只压缩停顿。
- 如果不确定，保留它。

示例：

- `um, I think this solves the main problem` -> 移除 `um`。
- `It works like a checklist` -> 保留 `like`；它表达比较。
- `The upload failed, so we retried it` -> 保留 `so`；它承载因果关系。
- `right after the call, send the recap` -> 保留 `right`；它修饰时间。
- `然后我们再看第二点` -> 保留 `然后`；它标记顺序。

##### 重录与重复尝试

重录是指说话者因为说错、卡住、忘词或重新开始，而再次尝试表达同一个预期想法。清理重录不等于“删除重复文字”。目标是保留该预期想法的一个完整、自然且逻辑连贯的版本。

使用以下决策路径：

1. 判断它是否真的是重录。
   只有当多个尝试都在表达同一个预期想法时，才把它视为重录。如果重复是有意强调、修辞节拍、结构标记，或者第二次表达增加了新信息或新语气，则不要把它当作普通重录。
2. 定义要保留的完整版本。
   完整版本可能不止包含主要内容句。它可能还需要引入、连接词、章节标记、话题铺垫、对比、限定语、主语、宾语或结论。当保留内容依赖这些部分时，它们不是填充内容。
3. 只剪掉失败或已被覆盖的部分。
   只移除错误、悬空、放弃，或已经被保留版本完全覆盖的词语。切口从重复或失败的想法开始，而不是自动从更早的转场、铺垫或连续语音开始。如果更早语音包含保留版本没有重复的有用上下文，就保留它。
4. 选择最佳完整尝试。
   如果多个尝试都完整，通常优先选择后一个，因为它往往更接近说话者期望的 Take。但不要机械地总选最后一个。如果后一个尝试缺少必要上下文、结构、主语、宾语或结论，就保留更完整的版本，或保留前一个尝试中缺失的引入。

只有当另一个等价引入仍然与保留内容自然相连时，重复引入才是冗余。如果删除所有副本会让结果失去结构或听起来突兀，就保留一个自然副本，只移除额外的重新开始。不要把不同尝试中的未完成片段拼成一句人为句子。

以下示例是模式，而不是封闭列表：

- 保留句子内部的局部错误起始：
  `There, there's no After Effects, no Premiere, no DaVinci Resolve learning.`
  保留完整句子，但移除被放弃的重新开始：
  `There's no After Effects, no Premiere, no DaVinci Resolve learning.`
  不要只因为完整句子的其他部分有用，就保留多余的第一个词。
- 重复的结构引入：
  `And secondly, ... and secondly, we're introducing a brand new UI.`
  移除额外重新开始，但保留一个与保留内容相连的自然引入：
  `And secondly, we're introducing a brand new UI.`
  不要删掉所有结构标记，只留下：
  `We're introducing a brand new UI.`
- 失败结尾之前的有用铺垫：
  `Then the next one is different from comedy. It is popular on Disney Plus. It is called...`
  后续重录：
  `It is a popular Disney Plus show called Love Story.`
  保留后续重录没有重复的有用铺垫，并从失败点开始剪切：
  `Then the next one is different from comedy. It is a popular Disney Plus show called Love Story.`

##### 错误起始和未完成片段

对此类别使用 `false starts / unfinished fragments`。`False start` 是更自然的剪辑/转录术语，指说话者开始一个短语后重新开始或放弃；`unfinished fragment` 则明确表示悬空的半句话。

只有当一个片段明确没有形成有用信息时，才移除它。

可以安全移除：

- 说话者放弃了该想法，后面出现了完整版本。
- 该 Segment 只是悬空短语，例如 "this is actually..."，而且没有完成。
- 它明显是一次失败尝试遗留的开头。

不要移除：

- 不够完美但包含有用信息的句子。
- 为后续内容提供所需主语、宾语或上下文的引入。
- 提供铺垫、对比、结论、情绪或语气的内容。

如果句子或 Segment 中只有一部分错误，不要删除其周围的有用内容。只移除坏词、短语或停顿；如果局部切口无法听起来自然，就保留该 Segment。

##### 停顿与呼吸

停顿清理默认应压缩，而不是归零。语音视频需要自然呼吸空间。

默认规则：

- 明显超过 0.8–1 秒的长停顿：通常压缩到约 0.3 秒。
- 句子之间：保留约 0.3–0.5 秒，让听众能听出自然措辞。
- 话题变化、对比或强调周围：需要时保留稍长停顿；不要让表达过于匆忙。
- 一个句子内部的短呼吸：如果是正常呼吸，不要移除。
- 一个句子内部明显的长停顿：压缩它，但不要紧到相邻词听起来粘在一起。
- 重录前的长停顿：如果周围失败尝试被移除，就连同该停顿一起移除。
- 如果用户提供明确阈值，遵循该阈值。例如，如果用户说“只处理超过 0.8 秒的停顿，并至少保留 0.3 秒”，就不要处理 0.8 秒以下的自然停顿。

### 其他 A-roll 任务指导

只加载用户所选分支的参考文件。不要预加载未要求处理的参考文件；默认 Cleanup 不需要参考文件。

对于 Cleanup 之外的 A-roll 编辑场景——包括提取精彩片段、重组、Hook / 短版本、目标文稿 / 文稿对齐，或构建版本、精彩片段和摘录——在规划或编辑该 A-roll 分支前，完整阅读 `.claude/skills/talking-head-guide/references/other-a-roll-editing-scenarios.md`。

### A-roll / 基于文字稿的编辑工作流

对任何由文字稿含义驱动的 A-roll 任务使用此流程。

1. 从定位开始。调用 `read_script`，然后阅读一次 `timeline.md`，了解用户目标、内容结构，以及是否存在固定填充词或长停顿。如果将运行 `clean_script`，不要根据清理前这次读取构建完整语义编辑。
2. 对于 Cleanup 任务，如果存在固定填充词或长停顿，先运行机械清理 Pass，再做语义编辑。不要用这一步处理依赖上下文的填充词、重录、重复句子，或任何需要理解含义的内容。
3. 在 `clean_script` 之后，进行语义编辑前始终阅读刷新后的干净 `timeline.md`。以这个刷新文件为事实来源；之前读取的文字可能已经过期。然后用语义判断进行编辑：选择最佳重录、清理错误起始、移除重复或失败尝试、保留有用铺垫和上下文、在需要时重新排序内容，并保持语音自然。对于很长的文字稿，如果可以提高判断准确性，就一次处理一个清晰章节。
4. 使用 `apply_script` 应用语义编辑。
5. 阅读重新生成的干净结果，检查观众实际会听到什么：逻辑断裂、上下文缺失、过度删除、遗漏清理、顺序错误，或停顿过紧/过长。只修复明确问题。

`[sN]` 行是 ASR Segment，不是语义单元。一个完整句子、想法、重录或转场可能跨越多个 `[sN]` 行，而一个 `[sN]` 行也可能只包含半句话。决定删除或保留什么之前，在脑中跨相邻行重建完整语句或想法。

## MG 叠层

### 目标

叠加到 A-roll 上的 MG 动画用于强化说话者正在传达的内容——加深观众对关键点的印象，并帮助他们理解仅靠口头表达难以落地的内容。先完成 A-roll 编辑；MG 时序以编辑后的 Timeline 为基础。

本节只补充 talking-head 场景的时序、画面构图、主体/字幕保护和审阅约束。关于视觉风格对齐、MG 创建或编写、实现约束、可编辑属性、Asset 尺寸和验证，应使用当前 ChatCut 环境中可用的活动 Motion Graphics Skill/工作流。

### MG 工作流

对于 talking-head MG 工作，把视频视为一个完整剪辑，而不是彼此孤立的 Graphic。

选择 talking-head Motion Graphics 时，包括只做规划或交接分析的请求，先激活当前表面上可用的 Motion Graphics Skill：当生成器 Skill 可用时，调用 `Skill` 并传入 `skill: "motion-graphic-gen"`；在有意不提供该 Skill 的 Codex 中，则调用 `Skill` 并传入 `skill: "create-motion-graphics"`。然后在规划、生成、放置或审阅 MG 前，完整阅读 `.claude/skills/talking-head-guide/references/motion-graphics.md`。本 talking-head 指南提供场景专用编辑上下文，但不替代活动 Motion Graphics Skill。
