### 目标

丰富视觉层，并遮盖 A-roll 编辑留下的跳切。

### B-roll 适用的位置

- **遮盖跳切**——当 A-roll 编辑留下用户希望隐藏的可见跳切时
- **将具体指代可视化**——当说话者提到适合展示的物体或场景时

B-roll 依赖合适的画面，也会增加制作工作量——把它视为可选增强，而不是默认处理。只有用户选择使用，或存在明确需要解决的视觉问题时才应用。

### 来源

画面可以来自三个地方：Project Library 中已有的片段；通过 `search_stock_media` 搜索 Stock，随后把选中的结果下载到 Sandbox，并通过 `asset-import` + `push_asset` 导入；或通过 `video-gen` Skill 进行 AI 生成（Seedance 2.0，仅限 ChatCut Pro）。根据用户需求选择；如果不明确，提前与用户对齐。

### 如何放置

不要在最开始或最后 3 秒切走。对于密集跳切（间隔小于 3 秒），使用一个较长的 Cutaway 同时遮盖多个跳切。默认不要与 MG 重叠。

先决定 B-roll 模式：

- **全屏 Cutaway** 会在该时刻替代 talking head。当用户要求全屏显示 B-roll、遮盖跳切，或 B-roll 需要占满整个画面才可读时使用。
- **PiP / 小窗叠层** 保持 talking head 可见。当用户要求叠层/PiP、现有剪辑风格明确使用小窗 B-roll、用户说 talking head 可以继续可见，或 B-roll 只是快速辅助视觉时使用。

如果用户只说“添加 B-roll”，而现有剪辑没有暗示模式，只问一次：“这些 B-roll 应当是全屏 Cutaway，还是带小圆角的 PiP 小窗叠层？”

对于 **PiP / 小窗叠层**：

1. 先检查目标 Timeline 帧。在实际镜头中比较候选目标矩形。排除会遮挡 A-roll 人物脸部/头部、嘴部、重要手势、字幕、现有叠层、产品/Logo 或其他可见主体的区域。在安全候选中，选择能够以有用且可读的尺寸展示 B-roll 的矩形；在保持构图平衡的同时，优先选择最大的空白或低信息区域。
2. 检查 B-roll 源帧。识别主要主体/动作、受保护信息和可以安全损失的区域。任何可读文字/UI、姓名/标题、Logo、品牌条、产品边缘、卡片、海报或文档边界默认都受保护，除非用户明确同意损失该项具体信息。
3. 在选定的目标矩形内，以有用尺寸放置叠层。保持 B-roll 的受保护信息可见/可读，并且不遮挡 A-roll 的受保护内容。当其他候选位置有更多可用空白时，不要默认放在固定角落或 Lower Third 位置。
4. 除非要求的风格是方正/锐利，否则默认把媒体 Item 的原生 `borderRadius` 设为 24–36。不要只为了普通圆角 PiP 添加 Mask/Effect；只有特殊形状或无法使用原生 `borderRadius` 的 Item 类型才使用 Effect。
5. 报告成功之前，对受影响的帧截图。如果唯一不遮挡内容的 PiP 小到无法理解，则改用全屏 Cutaway、选择不同的源时刻/Asset，或让用户选择取舍。

对于 **全屏 Cutaway**：

1. 选择 Fit 前，比较源宽高比和画布宽高比；不要未经检查就默认 Cover。对于相近的宽高比，例如竖屏源放入竖屏画布，或横屏放入横屏且差异小于约 30%，先使用占满画布的 `fit:"cover"`，让 B-roll 完整承担该视觉节拍。
2. 对于差异明显的宽高比，例如横屏媒体放入竖屏画布，或竖屏媒体放入横屏画布，不要直接使用 Cover 放置。如果尚未看过源内容，选择 Fit 前用 `inspect_asset` 检查有代表性的源时刻；当受保护区域不明显时，使用 `visual-analysis` Skill。
3. 判断受保护信息是否分布在 Cover 会裁掉的区域。任何可读文字/UI、姓名/标题、Logo、品牌条、产品边缘、卡片、海报、文档边界，或位于画面两侧的主体，默认都受保护。
4. 检查之后，只有受保护信息能够在裁切后保留时，才可以使用 Cover 或安全裁剪，例如主体单一、居中且边缘信息量低。对于没有必须保留的特定文字或主体的低信息上下文媒体，例如风景、人群镜头或其他情绪/环境画面，即使宽高比差异明显也可以使用 Cover。
5. 如果会丢失受保护信息，例如边缘附近的文字/Logo、两侧都有主体，或赛程表、比赛海报等横向信息布局，则前景使用 `fit:"contain"`，并添加有意设计的全屏背景，例如与剪辑匹配的不透明 MG 背景/Matte，或模糊/放大的重复层/背景层。如果 Cover 尝试只裁掉了一个紧凑主体/动作，而且可以在不隐藏其他受保护信息的情况下恢复，则尝试更安全的 Reframe/Crop，把源保护框完整移入画布，并更靠近期望的视觉中心。
6. 对每个源 Asset 分别应用 Fit 策略，不要把它作为批量默认值。即使用户要求 Cutaway，也不要在未逐个检查源宽高比和受保护内容时，批量使用 `fit:"cover"` 放置多张图片或多个片段。
7. 对最终画面截图，并与检查过的源帧比较。验证前景仍保留源素材中的受保护信息，而不只是验证最终画布已被填满。

编辑后，使用 `inspect_item({itemId:"..."})` 重新读取每个准确修改过的 Item；如果同一 Track 上修改了多个 Item，则使用 `preview_timeline({views:["timeline"],tracks:["V1"]})`。Asset 出现在 Library 中并不能证明它已位于 Timeline 上。如果结果涉及 Crop、Fit、Scale、叠层放置或全屏构图取舍，则在报告成功前，用 `preview_timeline({views:["viewer"],viewerFrames:[...]})` 或视觉分析验证受影响帧，然后修复失败的源/目标保护，或说明无法避免的取舍。如果目标 Item 没有变化，不要报告成功。
