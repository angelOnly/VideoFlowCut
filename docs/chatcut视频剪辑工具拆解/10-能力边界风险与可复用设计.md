# 10｜ChatCut 能力证据、链路闭环与待验证边界

> 本篇只讨论 **ChatCut 外部产品**：本轮看到了什么、哪一段链路已经在受控样本中走通、哪一段只有工具或 Skill 合同、哪一段仍无法验证。它不评价任何其他视频系统，也不把“未来值得研究的机制”写成 ChatCut 已有或缺失的功能。

## 先分清两件不同的事

读这套拆解时，最容易混淆的是下面两张“状态表”。它们回答的不是同一个问题。

| 要问的事 | 正确问题 | 例子 |
| --- | --- | --- |
| **证据等级** | 这句话依据什么？ | “Duck 在本轮导出的 MP3 中确实使音乐下沉”是已实测；“TTS 要先生成 Asset 再摆放”是 Skill / 工具合同。 |
| **链路闭环程度** | 一条用户动作是否从输入走到读回、可见/可听验证？ | “删完整语义 → V1 重编译 → 字幕读回 → 合成帧”已在样本中闭环；“Web 手动上传 → Codex 接手”因当前授权失败没有闭环。 |

所以“未验证”不等于 ChatCut 没有；“一个机制闭环”也不等于所有素材、所有版本和所有创作质量都已保证。

## 1. 四种证据等级：先说现状，不急着下产品判断

| 标记 | 在本调研中的含义 | 可以写什么 | 不能写什么 |
| --- | --- | --- | --- |
| **[已实测]** | 本轮真的调用过当前 MCP，写入后又读回；涉及画面或声音时还查看合成帧、浏览器或导出样本。 | “此样本中，V1 的同轨 ripple 只移动后续 V1 Item。” | “所有 ChatCut 项目都一定如此。” |
| **[工具 / Skill 合同明确]** | 当前运行时 Schema 或官方 Skill 明确写出了输入、前置条件、流程或限制。 | “`submit_voice` 只生成音频 Asset，不自动放入 Timeline。” | “当前账号已经完整跑通 TTS 成片。” |
| **[合理推断]** | 为解释多个外部现象所必需的最小职责边界。 | “语义选择与帧级写入应由不同职责承担。” | 私有数据库、模型、队列、锁或算法的具体实现。 |
| **[未验证]** | 当前样本、入口、权限或测试范围不足。 | “未观察到统一的语义影响报告。” | “ChatCut 一定没有影响报告或自动导演。” |

这四类标签是全文统一的语言。若一句话同时有两个依据，应并列写出，例如“[已实测] + [Skill 合同明确]”。

## 2. 什么叫“在本轮已闭环”

这里的“闭环”不是“产品从此没有问题”，而是一个很严格的最低标准：

~~~text
有明确输入和初始状态
→ 发起一次受控操作
→ 读到后端保存的结果
→ 对可见/可听结果做相应验证
→ 写清该结果不能外推到哪里
~~~

例如只看到 `success: true`，不算闭环；只看到一张时间线截图，也不算闭环。对不同能力，最后一环不同：结构编辑看 Item/Script/Caption 读回，视觉编辑看合成帧，声音关系看最终导出或试听样本。

## 3. 已在样本中形成闭环的 ChatCut 机制

下表中的“闭环”都带有明确样本和边界；它们是本套文档可以稳定依赖的核心事实。

| 机制 | 已走通的链路 | 这真正证明什么 | 不能扩大成什么 |
| --- | --- | --- | --- |
| **Asset 与 Timeline Item 分离** | 导入/已有 Asset → 形成多个 Timeline Item → 副本 Timeline 改动后读回原线 | 源素材与“在某个版本中使用一次”的对象是分开的；主线可重排而非改坏原片。 | 所有 Asset 删除、跨项目复用、权限继承都已验证。 |
| **口播 Script 语义剪辑** | `read_script` → 删除/重排完整语义 → `apply_script` → V1 Item、源范围、字幕读回 → 合成帧 | Agent 可以只表达“观众还要听什么”，后端会将选择编译为新的主线源范围、Item 与帧位。 | ChatCut 会自动找到最佳观点、自动遮住所有跳切，或已重锚所有包装。 |
| **陈旧 Script 拒绝** | 读取 Script → 另行修改同一 Timeline → 提交旧 Script → 被拒绝 → 重新读取后恢复 | 该样本的 Script 写入有新旧状态保护，不会静默覆盖后来主线。 | 已验证多用户并发合并、完整版本历史或一键恢复。 |
| **批量 Item 写入保护** | 同一批中混入合法更新与非法同轨重叠 → 整批失败 → 读回未发现合法部分半提交 | 这次 `edit_item` 批次具有原子失败边界。 | 所有工具、所有网络异常下都有同样事务语义。 |
| **物理删帧与同轨 ripple** | V1 切开/删 1 帧，分别不开与开启 `ripple` → Timeline、字幕、合成帧读回 | 默认删除会留下同轨空洞；显式 ripple 会重排同一轨后续 Item，帧计算不是 Codex 手算。 | V2、A1、音乐、MG、B-roll 会一起自动移动。 |
| **字幕投影与 Card/Token 分离** | 主线改变 → `read_captions` / refresh → Card、Token、合成帧 | 字幕能以最终可播放语音的成片帧为基础重新映射；文字、词级时间和视觉样式不是一回事。 | 每个切口都语言自然，或字幕一定替人修正 ASR/口型问题。 |
| **声音事件与物理 Item 起点分离** | Ding 的编辑事件、资源 onset、音频 Item 范围读回；Whoosh 的 Item 与导出能量对照 | “观众听到的那一刻”不必等于音频文件第 0 帧或 Item 起点。 | 系统已经自动判断每个镜头该选何种音效。 |
| **Anchor / Follower Duck 渲染生效** | 同一 Timeline 导出 Duck 开/关/仅 BGM 音频 → 人声窗口波形对照 | 本轮样本中，人声段的音乐下沉约 6.6 dB，与 `duckDepthDb` 读回一致，说明轨道角色关系进入最终云端渲染。 | 每首音乐、每种人声都自然，或生成音乐已经完成。 |
| **两类 `builtin:zoom` 绑定不同** | 片段绑定 Zoom 与轨道范围 Zoom 经插入、Script 删除、删帧后读回 | 片段绑定效果可随目标 Item 继续关联；轨道范围效果记住绝对时间，可能停在旧帧位。 | 所有 MG、转场、LUT、B-roll 或第三方效果都遵循相同继承规则。 |
| **无声素材的正常终态** | 无声视频处理后返回 `no_audio` | `no_audio` 是“没有可转写的人声”的成功状态，不应当作上传或处理失败。 | 无声画面已经被自动理解成故事，或会自动生成旁白/字幕。 |

这些机制的详细坐标和 MCP 返回在[第 08 篇](./08-实测记录浏览器验证与字段样例.md)，对象关系在第 03—06 篇。

## 4. 已有合同或局部证据，但还没有完整走通的链路

这一节不是“ChatCut 缺少什么”的清单，而是防止文档把半条链路写成整条能力。

| 能力链 | 当前最强证据 | 还缺哪一环 | 当前应怎样表述 |
| --- | --- | --- | --- |
| **Web 手动上传 → Codex 接手同一项目** | [工具 / Skill 合同明确] Web 上传会进入 Project Asset；Codex 可用 `projectId`、`target_project`、`browse_assets` 接手。 | 2026-08-31 当前会话 `list_projects` 返回 `Auth required`；命令行登录报告成功后，同一已运行会话仍未恢复读取。 | 项目状态应可作为交点；本轮尚未在新的可用授权会话中测通真实接手。 |
| **新本地文件的 Codex 导入** | [Skill 合同明确] `import_media create_session → upload-media.mjs → Asset → 等待处理状态`。 | 本轮当前授权无法重新跑导入；历史导入不能替代这个会话的可用性。 | 外部导入有指定适配路径；不要将浏览器手传和 Codex 导入写成同一上传协议。 |
| **新素材转写从启动到完成** | [已实测] 已完成 Asset 上的幂等状态；[工具 / Skill 合同明确] 触发、进度、`no_audio`、失败重试。 | 尚未在当前受控新素材上跑完“启动 → 完成 → Script 可读”。 | 转写有明确状态门，但完整新任务时延、异常与恢复仍待再测。 |
| **TTS / 旁白与画面同步** | [工具 / Skill 合同明确] `submit_voice` 创建音频 Asset；官方同步图要求记录视觉锚点、实际时长、摆放范围与 stale 状态。 | 尚未生成音频、读取真实时长、摆放、改画面后重核。 | ChatCut 已公开这条工作合同；本轮不能称它已实测闭环。 |
| **生成背景音乐** | [工具 / Skill 合同明确] `submit_music` 创建异步音乐 Asset，之后仍需时间线摆放、循环、淡入淡出和 Duck。 | 未提交生成任务，也未验证生成资源的许可与最终音乐结构。 | Duck 已实测；音乐生成和“自动卡点”未实测。 |
| **自定义声音 / 声音克隆** | [工具 / Skill 合同明确] 有授权、试听、创建、应用、额度与安全门。 | 无本轮获得明确授权的克隆样本，未进入生成与摆放。 | 这是有严格授权门的能力，不能因项目里存在人声就推定可用。 |
| **Hosted MG 动画创建** | [工具合同明确] 暴露 `create_motion_graphic_from_code`；[已实测] 已有 MG Asset 的 Timeline 摆放与独立轨行为。 | 未在 Hosted 路径实际创建 JSX、检查属性继承、再渲染。 | “创建 MG Asset”和“把一个 MG Item 摆到 V2”是两步，后者已测、前者未测。 |
| **多机位同步** | [Skill 合同明确] 详述同步母版、证据、节目版与 `multicam_sync`。 | 当前 58 个外部 MCP 中没有该同名入口，且本轮多机位测试已暂停。 | Skill 明确描述产品方法；当前 Hosted MCP 入口未验证，不能写成一键可用或产品不存在。 |
| **Web 原生自动导演** | [官方 UI / Skill 合同明确] Web 有 AI Panel、Agent、@ 引用和口播编辑工作面。 | 没有外部 MCP 用来启动/读取 Web Agent 的任务、计划或推理；也没有受控端到端导演实验。 | Web 原生 Agent 是可见产品入口，其内部导演链路未公开。 |
| **Vlog / 影视高光自动规划** | [已实测] 无声素材可用；[合理推断] 通用 Timeline 能承载场景/情绪结构。 | 没有“自动选场景、解释情绪弧、生成可读规划”的专用受控结果。 | 第 02 篇讲的是编辑规划方法，不是 ChatCut 已证实的一键模式。 |
| **资源下载与外部复用** | [已实测] 一个项目源媒体可创建 source 下载目标；一次公开搜索可返回候选。 | 未验证内置库/生成资源下载，也没有逐项核对平台外授权。 | “能放上 ChatCut Timeline”不等于“可批量下载或自由复用”。 |

## 5. 对“不会自动跟”的正确理解

这不是简单的“功能缺失”，而是 ChatCut 已经表现出的对象边界：

~~~text
同一轨后续 Item：明确启用 ripple 时，后端知道怎样移动
Script 主线与字幕：有源语音关系，能重新编译 / 投影
片段绑定 Zoom：有目标 Item 关系，可随片段延续
V2、Ding、绝对时间 Zoom、音乐、MG：本轮大多保存自己独立的时间或对象关系
~~~

因此，主线改动后需要问的不是“为什么没有全部自动平移”，而是：

1. 它原先记住的是**语义理由、目标 Item，还是绝对帧**？
2. 这次改动后，它是否仍在**物理正确**的位置？
3. 即使物理位置合法，它是否仍在**编辑正确**的位置？

**[未验证]** 当前 Hosted MCP 是否有统一的“影响报告”，能一次列出哪些对象已更新、哪些留在旧帧、哪些因语义理由失效。不能把这种报告写成 ChatCut 已有；也不能因没有观察到它，就断言 ChatCut 全产品没有任何内部协调。

为了继续研究这一点，任何结构改动实验都应保留下面这张影响账本：

| 对象 | 读什么 | 要判断什么 |
| --- | --- | --- |
| 主线 Item | 源范围、成片范围、轨道、时长 | 后端是否正确重编译或同轨重排。 |
| 字幕 | Card、Token、文本、修订状态 | 时间是否连续，切口是否仍自然。 |
| 片段绑定效果 | 目标 Item、局部效果范围 | 是否仍附在被保留的画面上。 |
| 绝对时间覆盖 | V2、音效、范围效果的起止帧 | 是否留在旧事件附近而失去理由。 |
| 音乐 | 范围、淡入淡出、Anchor/Follower、片尾 | 时长和段落关系是否仍合理。 |
| 旁白 | 视觉锚点、真实时长、放置范围 | 画面重计时后是否必须标记 stale。 |

这张表是**研究与审片框架**，不是在声称 ChatCut 已对所有对象自动生成它。

## 6. 后续深拆的优先级：补证据，不补猜测

在当前调研范围内，下一轮最有价值的不是增加更多工具名，而是补齐下列边界：

1. **恢复当前 Hosted MCP 授权后，完成 Web 上传 → Codex 接手实验。**
   要验证的是访问身份、`projectId`、目标 Timeline、Asset 就绪状态和可见编辑器是否真的形成同一条协作链，而不是只验证浏览器能打开。

2. **完成一条画面驱动旁白实验。**
   选择已经稳定的无声/录屏画面，建立同步图，生成一个明确音色的短旁白，记录真实时长并摆放；随后改变一个视觉段，验证哪些同步行变 stale、怎样重新对齐。

3. **补“复杂包装遇到语义删除”的隔离实验。**
   在同一主线旁放 B-roll、MG、Ding、音乐、片段绑定效果和绝对范围效果；删一个完整语义后分别读回。目标不是要求全部自动移动，而是把每种锚定关系讲清楚。

4. **补无声 Vlog 与影视高光的“证据—规划”测试。**
   重点看 Agent 能从当前读取面拿到什么可回源证据、什么只能人工查看、计划能否解释每段为什么出现；不要把“可手工排 Timeline”误说成“系统自动懂故事”。

5. **多机位维持暂停。**
   只有当前运行时真正暴露同步入口或产品范围重新需要时，才使用陈清泉 A/B/C 素材做同步母版、偏移证据和节目版切镜实验。

## 7. 最终结论

本轮最坚实的 ChatCut 事实，不是“它有 58 个工具”，而是它已经显示出一套可解释的编辑分层：

~~~text
语义选择（Script）
→ 确定性主线写入（Item、源范围、帧）
→ 字幕投影与独立包装
→ 项目读回、合成帧、浏览器或导出验证
~~~

其中，语义剪辑、同轨 ripple、字幕映射、批量保护、声音事件对齐、Duck 渲染和 Zoom 绑定差异已经拥有受控证据。TTS 同步、生成资源、Hosted MG 创建、多机位、Web/Codex 真正接手、非语音自动规划和资源许可仍有不同程度的入口或证据缺口。

这正是本篇要保留的边界：**已经测到的机制可以深入解释；尚未测到的机制只能提出下一轮问题，不能用想象把它补成事实。**
