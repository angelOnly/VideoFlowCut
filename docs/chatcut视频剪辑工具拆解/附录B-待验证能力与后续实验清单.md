# 附录 B｜已完成实验、待验证能力与后续实验清单

## 为什么还要做下一轮实验

本轮已经证明 ChatCut 的项目模型、口播/字幕基本结构、音效锚点、同轨 ripple 和浏览器可见状态；2026-08-26 又补完了“多轨基线中的插入 30 帧、Script 删除完整语义、删 1 帧有/无 ripple、片段绑定与绝对时间 Zoom”的受控证据。随后又补了自动导演入口审计、Duck / Whoosh 的最终云端 MP3、陈旧 Script 拒绝、批量原子失败和 Timeline 副本隔离。

但不能用这一批口播线推导所有视频类型。特别是 Vlog、影视高光、TTS 旁白闭环、复杂包装重锚和资源下载/许可仍缺少受控证据；多机位已按当前产品范围暂停，不再作为本轮待补实验。

### 恢复实验前的第零步：先恢复访问身份

**[已实测，当前会话边界]** 2026-08-31 的 `list_projects` 返回 `Auth required`；随后命令行登录显示成功，但同一已运行 MCP 会话仍返回 `Auth required`。所以下一轮任何“导入、Web 手传接手、TTS、音乐生成、结构写入”实验都不应直接从素材操作开始，而应先验证以下三件事：

1. 在一个重新建立的 Codex 会话中，当前连接器已真正获得 ChatCut 项目访问授权；
2. `list_projects` 能读到该账号可访问的项目；
3. 对用户提供的 editor URL，`projectId`、目标 Timeline 和素材库读回确实一致。

这一步若失败，结论只能是“当前会话身份绑定未完成”。它既不否定历史实验，也不能被写成“ChatCut 不支持这条能力链”。

## 本轮已经完成的 P0 实验

完整操作、关键字段和结论以[第 08 篇](./08-实测记录浏览器验证与字段样例.md)为准；本附录不再把已完成事项伪装成“待验证”。

| 已完成实验 | 已经证明什么 | 仍没有证明什么 |
| --- | --- | --- |
| 自动导演入口审计 | 当前 Hosted MCP / 初始 Web 工作区没有可提交、可读回的导演执行入口。 | ChatCut 产品在其它入口、权限、版本或 Desktop 工作面是否有内置导演。 |
| Duck 与 Whoosh 的最终云端 MP3 | 人声段的 BGM 下沉约 6.6 dB，符合 `duckDepthDb`；Whoosh 物理 Item 起点与主要声音能量起点不同。 | 每种声音都自然好听、音乐生成质量或全混音审美。 |

## 统一实验模板

每一个后续实验都按同一模板记录：

~~~
1. 测试目标：要证明或证伪什么？
2. 素材条件：时长、是否有语音、是否授权、机位数、预期内容。
3. 初始状态：项目、Timeline、轨道、字幕和资源的读回。
4. 操作：准确的 MCP 调用或浏览器操作。
5. MCP 反馈：关键字段、状态、错误或异步任务 ID。
6. 读回：项目/Timeline/Item/Caption 的前后对比。
7. 画面/声音证据：合成帧、浏览器播放或导出试听。
8. 结论：已证明、未证明、失败原因和下一步。
~~~

不要只写“工具成功”，也不要只截一张时间线图。

## 每个待测实验背后究竟在验证哪一条架构假设

待验证不等于“随便再多试几个按钮”。每个实验都应先说清：如果通过，我们能把哪一条产品机制从“合理推断”升级到“已实测”；如果失败，究竟是工具入口、素材条件、设计假设还是执行质量出了问题。

| 待测主题 | 想证实的架构假设 | 初始状态与关键操作 | 通过时必须读到的状态变化 | 失败时应怎样解释，而不是硬凑结论 |
| --- | --- | --- | --- | --- |
| 无声 Vlog 场景规划 | 系统是否暴露可查询的视觉/场景证据，而非只返回 no_audio | 多场景无声素材；先读 Asset，再请求局部帧/任何相关入口 | 能回源到场景范围、事实和未知；导演计划可说明每段为什么入选 | 若只有局部帧，没有自动场景索引，应写“Agent 人工按需理解”，不是“产品自动识别失败” |
| 旁白 Vlog / TTS | 生成旁白后能否成为普通可编辑音频，并在画面变动时重新同步 | 固定画面主线、明确文案和选定音色；生成、等待、摆放、改一处画面 | 得到真实时长、音频 Asset、Timeline Item；同步图能标明受影响段 | 若 TTS 工具未暴露、音色未授权或任务未终态，应记录入口/授权缺口，不假装生成成功 |
| 影视高光 | 是否存在可解释的事件/情绪证据入口，或只能由 Agent 人工规划 | 授权片段，预设“钩子—升级—爆点—余韵”评价表 | 每个选段有源时间、前因后果和情绪作用；成片可理解 | 若仅能手动看片，不应写为自动情绪分析能力 |
| 主线删句后的复杂包装 | 下游对象是否有明确锚定关系，还是只停在旧绝对帧 | V1 + 字幕 + Ding + B-roll + MG + 音乐 + 转场；删一个完整语义 | 每个对象被分类为自动更新、原位保留或待复核；画面/声音可验证 | 没有自动移动不是产品失败；重点是系统能否诚实报告影响 |
| 插入 / 替换镜头 | Item 替换是否原子，效果/音频/字幕哪些继承 | 建立带覆盖层和片段效果的基线，原位替换一个源范围 | 旧/新 Item、源范围、效果继承、字幕来源和回滚结果均可读回 | 若无完整继承，不应默认为 bug；应区分合同是否声明支持 |
| 多机位同步 | 是否有可用工具将多路素材建立为可复核共同时间尺 | 陈清泉 A/B/C；等待当前入口实际暴露后再测 | 同步偏移、置信度、母版与节目版可分开读回 | 当前范围已暂停、入口未暴露时，只保留方案，不宣称自动同步不可用 |
| 资源下载 / 许可 | “可用在项目”能否安全提升为“可下载、可外部复用” | 对每类资源单独查下载入口与许可页 | 下载身份、文件、来源和使用限制能形成清单 | 许可冲突/不明时停止；不是通过技术抓取绕过 |

### 所有结构改动实验都要有同一份“影响账本”

未来做“删一句、插一段、替换镜头、延长几帧”时，实验记录必须列出这些对象的前后状态：

| 对象类别 | 记录什么 | 为什么 |
| --- | --- | --- |
| 主线 Item | 源范围、成片范围、轨道、总时长 | 判断后端是否正确编译/移动主骨架 |
| 字幕 | Card、Token、文本、修订状态 | 判断投影是否连续且语义没有残留 |
| 片段绑定效果 | 目标 Item 与效果范围 | 判断它是否仍附在目标片段上 |
| 绝对时间效果 / 覆盖层 | 原范围与新范围 | 判断它是否停在旧时刻，需要不要重锚 |
| 音效 | 事件意图、Item 起点、onset/主要能量 | 判断“放在时间线上”是否真的对准听觉事件 |
| 背景音乐 | 音乐范围、淡入淡出、Anchor/Follower、片尾 | 判断结构变动是否造成音乐逻辑断裂 |
| 人工审片结果 | 哪一帧/哪一秒看到或听到的问题 | 避免用结构成功代替成片质量 |

这样，下一轮实验不只是扩大表格，而是能持续补齐“对象如何锚定、何时失效、谁负责恢复”的产品模型。

## A. 不同视频类型的受控实验

| 类型 | 建议素材 | 要验证什么 | 成功标准 |
| --- | --- | --- | --- |
| 单人口播 | 有重拍、口癖、长停顿的授权素材 | Script 是否能保留完整观点并重新落帧 | Script 前后可听内容正确；字幕刷新后无明显错位。 |
| 双人访谈 | 陈清泉 A/B/C 原片 | 同步母版、节目版、镜头切换策略 | 若无 multicam_sync，明确记录工具缺口；不能把人工同步写成自动化。 |
| 无声 Vlog | 有明确场景变化的授权旅行/生活素材 | 是否有可用视觉理解/规划入口 | 输出应有可解释的场景证据；没有则记录为 Agent 人工规划。 |
| 旁白 Vlog | 旁白 + 多场景素材 | 主线是否应由旁白驱动，画面如何覆盖 | 旁白稳定后，画面事件与叙述对应。 |
| 教程/录屏 | 可公开的软件演示或用户授权录屏 | 关键操作与字幕/Callout 是否能对齐 | 每个操作步骤在画面中可看见，文字不遮挡关键控件。 |
| 事件高光 | 授权的体育/游戏/活动素材 | 是否能围绕前因—高潮—后果安排 | 高潮可理解，不只是一串碎片。 |
| 音乐 Montage | 已授权音乐和多个视觉片段 | 音乐节拍与镜头落点如何维护 | 明确哪些是人工 Timeline 对齐，哪些不是生成模型承诺。 |
| 画面驱动旁白 | 授权录屏、产品演示或图文解释片 | 画面重计时后旁白是否仍对应当前视觉状态 | 每段旁白都有可见锚点、真实时长和读回后的摆放范围。 |
| 销售/广告 | 用户授权产品素材 | 证明、CTA、文字停留的编排 | 不是只做炫酷蒙太奇；关键主张可读可证。 |
| 图文/数据 | 历史图、数据卡或用户授权素材 | 读屏停留与字幕/MG 动画冲突 | 每屏有清楚阅读层级，没有过快闪读。 |

素材优先顺序：用户提供并授权的素材 → ChatCut 内置/公开许可素材 → 明确许可的公开样本。不要用抖音、小红书或影视平台随意下载的内容充当长期测试库。

## B. 主时间轴改动与下游联动矩阵

下表把“已经看见的事实”和“下一轮仍要验证的项”分开写，避免把 Skill 中的推荐流程误写成实测功能。

| 操作 | 当前实测结果 | 可得结论 | 仍待验证 |
| --- | --- | --- | --- |
| 删除 1 帧，不 ripple | V1 留下真实 gap `[180,181)`；V2 画中画和 A1 Ding 仍在原帧；云端第 180 帧主画面黑。 | 默认删除不等于缩短整条片，只是移除同轨一小段。 | 背景音乐、MG、转场在同一点的结果。 |
| 删除 1 帧，`ripple:true` | V1 后半段从 181 左移到 180，片长 390→389 帧；V2/A1/V3 不动；第 180 帧画面连续。 | ripple 只推动同轨后续 Item。 | 音乐、MG、转场是否仍服务正确语义。 |
| 上述两种删帧的字幕 | 不 ripple 时 180 帧没有 Card；ripple 时 Token 被连续投影，但出现 1 帧重复“我”。 | 字幕会跟最终可播放媒体重新落时，不会判断切口是否自然。 | 更复杂词边界、口型和人工 Token 重计时。 |
| Script 删除一个完整语义 | V1 由后端重编译，Item ID / 起点变化；对应 Card 消失；刷新返回 canonical、`changedCards: 0`。 | Agent 选内容，ChatCut 计算主线的 Item、源区间、帧位。 | 删除首句、尾句、跨两个来源的更复杂语义段。 |
| 在 V1 中间插入 30 帧，`ripple:true` | 后续 V1 右移 30 帧、片长 360→390；V2/A1/V3 均不动。 | 主轨插入不会全轨道自动平移。 | 不 ripple 的同轨冲突/拒绝；音乐、MG、转场。 |
| 片段绑定 Zoom 遇到切分 / Script 重编译 | 新 V1 Item ID 出现后，`inspect_item` 仍显示附着的 `builtin:zoom`；物理切分时效果留在含其范围的后半段。 | 本次片段绑定 Zoom 能随目标片段保留，不等于所有效果都能。 | MG、转场、LUT、B-roll、第三方效果。 |
| 轨道范围 Zoom 遇到主线增删 | V3 Zoom 始终为 `[170,210)`，不随 V1 插入、Script 删除或 ripple 删帧移动。 | 时间范围效果是绝对成片坐标，需要 Agent 重锚。 | 其它轨道范围效果和转场。 |
| 修改 Caption Card 文本 | 当前工具合同明确应只改观众可见文案。 | 不应改变语音或主视频。 | 用真实 Card 做可回滚编辑、合成帧确认。 |
| 重计时字幕 Token | 当前工具合同要求正序、无重叠且在 Card 内。 | 这是展示层定时，不是重剪语音。 | 人工改词级时间后的完整实操。 |

已经完成的基线含 V1、V2、A1、V3 和字幕，足以证明最核心的“同轨 / 独立轨 / 两类效果 / 字幕派生”的区别；仍需另建带背景音乐、MG、B-roll 和转场的隔离 Timeline，不能因为对象名称相近就套用 Zoom 的结论。

## C. 多机位专项验证

> **当前范围暂停。** 以下方案保留为将来产品重新需要多机位时的受控实验设计，不再列为本轮 P0，也不能据此推定当前 Hosted MCP 已有可调用同步执行入口。

1. 从陈清泉 A/B/C 原片中找到有重叠对话的连续段；
2. 通过转写重叠、音频相关或当前运行时支持的工具建立同步证据；
3. 建立单独的同步母版 Timeline，不改动节目版；
4. 记录每个机位的时间偏移、置信度、连续性检查和音频来源；
5. 建立第二条节目版 Timeline，只从母版相同墙钟时间提取镜头；
6. 在多个说话点检查嘴型、主说话人、反应镜头是否仍真实。
7. 母版建立后不在其上做内容删改；任何节目剪切在独立 Timeline 完成，并保留母版偏移作为读回证据。

若运行时没有 multicam_sync，实验结论应是“当前 MCP 没有暴露该执行能力”，不是“自动同步失败后就用手算结果替代并继续声称自动”。

## D. 背景音乐和音效专项验证

| 测试 | 目标 |
| --- | --- |
| Anchor/Follower | **已完成机制验证**：最终云端 MP3 中人声段的 BGM 下沉约 6.6 dB；未来只需在新音乐、人声或混音目标下补听感样本。 |
| 音乐过长 | 裁切和淡出是否在真实片尾结束。 |
| 音乐过短 | 交替音轨循环时是否有可听见断裂。 |
| Ding/Whoosh 锚点 | **已完成基础验证**：Item 物理范围与主要声音能量起点可不同；未来可增加不同资源的 onset / 峰值样本。 |
| 结构重排后 | 音效、音乐、MG 动画是否还强调正确内容。 |
| smooth_audio | 硬切口是否得到微交叉淡化，是否出现额外问题。 |
| 画面重计时后的旁白 | 改变画面位置或时长后，旧旁白是否被标为待重核；重新摆放后是否仍在正确视觉锚点出现。 |

## E. 下载与许可专项验证

在用户明确授权执行下载之前，只做以下只读审计：

1. 分页枚举内置音效库的名称、分类、ID 和可见使用说明；
2. 分别确认项目上传音频、生成音频、内置库音效、MG 动画和转场的下载入口；
3. 读取每种资源的许可/使用条件；
4. 确认是否允许离开 ChatCut、是否允许商业使用、是否需要署名；
5. 仅对明确允许的资源，创建下载清单和用户指定目录的下载计划。

不要把“能够在项目 Timeline 中使用”推导为“能够批量下载、永久保存和任意再分发”。

## F. 终止条件

以下情况应停止当前实验并记录，不要强行得出正面结论：

- 素材未处理完成或云端不可读；
- 当前 MCP 不存在所需工具；
- 需要付费生成而用户没有明确确认；
- 资源许可不明；
- 合成帧、浏览器状态或结构读回彼此矛盾；
- 多机位同步置信度低或出现嘴型漂移。

诚实地保留“待验证”比补一个猜测出来的产品能力更有价值。
