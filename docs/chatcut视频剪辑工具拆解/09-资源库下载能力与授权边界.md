# 09｜资源库、下载能力与授权边界

> 证据范围：本篇区分 2026-08-27 的实际读取/调用结果与当前 MCP Schema 的工具合同。它不是法律意见；任何脱离 ChatCut 的复用、商用或批量归档，都必须以资源实际许可和平台条款为准。

## 先回答“能不能把所有音效和背景音乐下载下来”

**目前不能直接承诺“全部下载”。** 原因不是技术上一定做不到，而是当前可观察能力和许可边界尚未满足三个必要条件：

1. 需要确认每个资源是否有允许下载的入口；
2. 需要确认下载后是否允许脱离 ChatCut、用于其它项目或商业使用；
3. 需要确认它是内置库资产、生成资产、公开素材还是用户上传资产，它们的权利来源不同。

因此，本轮没有批量下载，也没有绕过页面、抓取隐藏链接或归档受限资源。

## ChatCut 里至少有四种“资源”

| 类别 | 从哪里来 | 在哪里用 | 能否默认外部下载 |
| --- | --- | --- | --- |
| 用户/项目源素材 | 用户导入或上传 | 项目素材库与 Timeline | 本轮一个 source 视频样本可创建下载目标；是否实际下载、以及权利范围仍须另查。 |
| 内置编辑资源 | browse_library 的音效、MG 动画、效果、转场等 | 通过库使用指引放到项目 Timeline | 不能默认推定可独立下载或离开 ChatCut 复用。 |
| 生成资源 | submit_music、submit_sound、TTS、视频生成等 | 若任务完成，可成为项目 Asset | 这是工具合同；本轮未调用付费生成，许可仍要按服务和实际资源确认。 |
| 外部公开素材 | search_stock_media 搜索后的明确来源 | 先选择、下载、导入项目 | 需要逐个核对来源许可证。 |

## 已验证的库概览（2026-08-27 动态快照）

本轮 browse_library 返回的分类为：MG 动画 211、音效 35、Zoom 4、效果 11、转场 13、LUT 2；音频效果当前为 0。

注意两个容易误解的点：

- 这个“音效”分类是 **ChatCut 内置资源库**，不是抖音、小红书或任意网页；
- 该概览没有“背景音乐”分类。背景音乐的来源更多是生成、外部公开素材搜索或用户自有音乐，而不是可以想当然地从音效库全量抓取。

## 当前 MCP 的下载边界

`request_asset_download` 的工具合同说明：它为**项目素材库中的源媒体 Asset**生成一个面向用户的下载目标，当前 Schema 只暴露 `source` 变体。

本轮对访谈项目的 `C1297.mp4` 实际调用 `request_asset_download({ variant: "source" })`，返回 `success: true`、`video/mp4`、文件名、文件大小和面向用户的临时下载目标。下载目标已脱敏且本轮没有实际下载文件。

这意味着：

| 情况 | 当前能说明什么 |
| --- | --- |
| 用户上传到项目的音频/视频 | `C1297.mp4` 已实测可创建下载目标；其它格式/其它项目仍未逐项验证。 |
| 已生成完成并成为项目源媒体的音频 | 从工具合同看可能符合项目 Asset 下载的形态，但本轮没有实际生成或下载验证。 |
| MG 动画、效果、转场 | 工具合同把它们与普通 source 媒体区分；是否能通过对应导出能力取得可复用文件，本轮未验证。 |
| ChatCut 内置音效库的全部条目 | 没有已验证的“批量导出库中所有源文件”合同。 |

本轮在 Timeline 中使用的 Clean Ding 已成为项目可用的音频 Asset，但这不自动证明它有权被下载后作为个人通用素材库再分发或用于其它软件。

## 深度拆解：一个资源要经过六个状态，才能从“看见”变成“可安全复用”

“在资源库里搜到了一个声音”“把它放进了 Timeline”“下载到了本地”是三件不同的事。要让资源能力不变成版权和交付黑洞，需要把它的生命周期拆开：

~~~mermaid
flowchart LR
    A[发现
库搜索 / 外部检索] --> B[身份与用途确认
资源类型、时长、来源]
    B --> C[权利判断
项目内使用 / 下载 / 外部复用]
    C --> D[进入项目
成为可引用 Asset]
    D --> E[作为一次 Item
摆到 Timeline]
    E --> F[渲染/导出
成为这条成片的一部分]
    C --> G[若明确允许
创建下载目标并归档]
~~~

| 阶段 | 技术上意味着什么 | 权利上仍要确认什么 | 不能误写成什么 |
| --- | --- | --- | --- |
| 发现 | 返回一个库条目或外部搜索候选 | 来源、许可、署名、商用与地域条款 | “已经拥有该素材” |
| 身份确认 | 有资源 ID、名称、分类、时长、可能的使用指引 | 它是内置、生成、用户上传还是外部公开 | “所有音效属于同一套可下载库” |
| 进入项目 | 成为项目可使用的 Asset，或通过库动作可放到项目中 | 项目内可用是否等于可脱离平台使用 | “已经有永久外部授权” |
| 摆入 Timeline | 这一次出现有轨道、时间、混音和效果关系 | 它服务当前成片的使用是否仍符合条款 | “这个文件已经被导出保存” |
| 导出成片 | 声音/图像进入用户可观看的交付版本 | 成片的发布用途是否受资源许可限制 | “源文件可以被单独再分发” |
| 下载/归档 | 取得一个用户下载目标或本地文件 | 是否可下载、可保存多久、可否在其它项目复用 | “只要下载成功就可以任意使用” |

这就是为什么“资源可用于 ChatCut 时间线”和“资源可批量下载到你的通用素材库”之间不能画等号。

### 四种资源的权利问题根本不同

| 资源来源 | 谁通常提供技术入口 | 最先应问的问题 | 本轮已经确认的边界 |
| --- | --- | --- | --- |
| 用户上传 / 项目源素材 | 用户导入、项目 Asset、source 下载目标 | 用户是否有权在当前 ChatCut 项目和导出成片使用 | 一个项目 source 视频可创建下载目标；不代表所有文件和用途 |
| ChatCut 内置资源 | ChatCut Library 的浏览与使用指引 | 是否只限 ChatCut 内使用，是否有独立下载/再分发权 | 可浏览分类；没有批量导出合同证据 |
| 生成资源 | 音乐、声音、TTS、视频生成任务 | 生成服务的输出许可、商用和导出权是什么 | 当前主要是工具合同；本轮没有生成/下载闭环 |
| 外部公开资源 | 外部检索、来源页、下载与导入 | 许可证正文是否一致、是否需署名、是否允许改编/商用 | 一次搜索结果的字段曾互相矛盾，必须回来源核验 |

资源系统要同时保存两套事实：

~~~text
编辑事实：这个声音 / 图片在第几帧、哪个轨道、以什么音量出现
权利事实：它从哪里来、允许怎样用、许可页面和确认时间是什么
~~~

前者解决“能不能剪”；后者解决“能不能交付和复用”。本轮只对前者的少量项目内行为和后者的少量搜索/下载目标做了验证，不能从中推导完整版权许可链。

### 调研 ChatCut 资源生命周期时，哪些事实必须分开记录

这一节不是对其他产品的设计建议，而是本调研为了不把“搜索到”误写成“可以下载/复用”而采用的**证据记录框架**。对于每一个 ChatCut 或外部候选，至少要把下面几类事实分开：

| 需要记录的事实 | 它在 ChatCut 研究中回答什么 | 为什么不能省略 |
| --- | --- | --- |
| 来源和原始页面 / 项目来源 | 它是用户上传、ChatCut 内置、生成，还是外部搜索结果。 | 同名音效可能来自完全不同的权利链。 |
| 资源身份、类型、时长和当前 Asset 状态 | 当前项目能否引用它，是否已成为可读的项目 Asset。 | “库条目”“生成任务”“项目 Asset”不是同一个状态。 |
| 项目内使用许可与脱离平台复用许可 | 能否用于当前 Timeline，是否能下载后在别处使用。 | 能放入成片不等于能再分发或建立通用本地库。 |
| 署名、地域、期限和平台限制 | 导出、发布或再次使用时还受什么约束。 | 搜索结果的简短许可证字段甚至可能与来源页文字冲突。 |
| Timeline 使用位置 | 该资源在当前版本的哪条轨、哪一帧、以何种形式出现。 | 这是“剪辑事实”，与许可事实并列，不能互相替代。 |
| 下载动作与下载目标 | MCP 是否仅生成短期目标，是否真的完成下载。 | 一条临时 URL 不是长期授权证据，也不应写进文档。 |

用这张记录框架重新看本轮结果：`Clean Ding` 已能在 Timeline 中作为声音对象使用；`C1297.mp4` 已能生成 `source` 下载目标；外部音乐搜索返回了候选和矛盾的许可证文字。三者都没有证明“可以把 ChatCut 资源全部下载并自由复用”。

## 背景音乐的特殊性

### 生成背景音乐（工具合同，未实测）

`submit_music` 的工具 Schema / Skill 说明可提交背景音乐生成任务；按合同，任务完成后会得到项目音频 Asset，之后仍需用时间线操作做放置、裁切、循环、淡入淡出和 duck。

本轮没有调用该付费/生成入口，因此没有证明实际生成是否成功、生成音乐的完整听感、放置结果、duck 效果或外部复用许可。

它不是：

- 一个可浏览的“全部背景音乐库”；
- 对既有歌曲的编辑、清理、混音或分轨能力；
- 自动保证精确 Beat 对齐；
- 自动保证可以在 ChatCut 外无限制使用的许可承诺。

### 外部公开素材（一次只读搜索已实测）

`search_stock_media` 可以搜索公开素材平台的 B-roll、图片、声音和音乐。本轮用 `kind: "music"` 与 `gentle piano background` 做只读查询：Pexels、Pixabay、Unsplash 返回 0，Freesound 返回 1 条，并带来源页、作者、下载候选和许可证字段。

该返回的结构化许可证字段是 `CC BY 4.0`，描述文字却自称 `CC BY-SA 4.0`。这正说明搜索结果不能当作许可核验：仍必须打开来源页、以许可正文为准。该候选本轮没有下载或导入。

不要以“网上能播放”为依据，将抖音、小红书、影视平台或个人账号的视频/音乐下载后作为素材库。它既无法保证授权，也不适合作为可审计的产品调研样本。

## 如果以后要下载，推荐的审计流程

先建立清单，再下载，不要一上来做批量文件操作：

~~~mermaid
flowchart LR
    A[枚举候选资源] --> B[记录类型、来源、ID、时长]
    B --> C[检查下载入口和许可]
    C --> D{允许脱离 ChatCut 复用？}
    D -->|是| E[下载到用户指定目录]
    D -->|否/不清楚| F[只记录，不下载]
    E --> G[生成资源清单与校验记录]
~~~

建议的资源清单字段：

| 字段 | 作用 |
| --- | --- |
| 本地文件名和哈希 | 识别重复与文件完整性。 |
| ChatCut/外部资源 ID | 可以回溯来源。 |
| 分类和时长 | 后续检索和剪辑使用。 |
| 来源、下载日期、许可链接 | 证明资源从哪里来。 |
| 是否可商用、是否需署名、是否限 ChatCut 内 | 避免后续误用。 |
| 试听标签 | 如 Ding、Whoosh、轻快、低沉、转场、环境等。 |

## 调研资料与下载目标的保存边界

- 本轮不会把下载后的大体积音频、视频或库资源存入文档目录；
- 如用户后续确认某资源可下载，应保存到用户明确指定的外部素材目录，而不是把临时资源混进调研文件；
- 文档只保存必要的来源、资源身份、许可结论与非敏感清单，不保存私有签名下载链接；
- 即使资源确实可下载，也要保留“仅个人、仅当前 ChatCut 项目、需署名或有发布限制”等实际条件。

## 结论

本轮**已实测**：内置资源库概览、一个项目 source 视频创建下载目标、一次公开音乐素材搜索；另在项目内真实导出的云端 MP3 中验证了 Anchor / Follower Duck 会让人声段的背景音乐下降约 6.6 dB。当前 MCP **工具合同明确**：可以提交音乐生成任务，完成后再把音频摆到时间线。  

本轮**尚未实测**：实际生成音乐、完整成片的审美听感、内置/生成资源下载、批量下载，以及任何资源脱离 ChatCut 的复用许可。Duck 的最终渲染机制已验证，不等于每种音乐下的听感已经验收。因此，“将所有库资源完整下载并在其它项目自由复用”不是当前已验证能力，也不应在未核对许可前执行。正确做法是先审计，再对明确允许的资源逐项下载和登记。
