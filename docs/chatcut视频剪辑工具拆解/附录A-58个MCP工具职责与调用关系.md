# 附录 A｜58 个 MCP 工具职责与调用关系

> 证据范围：本附录按 2026-08-27 当前运行时暴露的 58 个 `mcp__chatcut__*` 工具整理。它是当前版本的能力地图，不是永久 API 文档；精确参数和字段以当次工具 Schema 为准。

> 当前会话边界：2026-08-31 再次调用 `list_projects` 返回 `Auth required`。随后命令行登录虽报告成功，同一已运行会话仍返回 `Auth required`。因此“58 个工具曾在 manifest 中可见”“账户完成登录”“当前会话有权限对某个项目执行工具”是三件事；以下矩阵描述工具面与合同，不把当前会话刷新失败写成产品能力缺失。

## 怎样读这张矩阵

不要把工具看成 58 个孤立按钮。每一行都用三件事描述它：

- **一句人话**：这个工具替编辑流程解决什么问题；
- **通常在什么时候调用**：它的上游条件；
- **后面会接什么**：它的典型下游，而不是强制顺序。

工具分为读取、写入、异步提交和交付四类。读取工具通常可安全地用于定位事实；写入和生成工具则应先完成内容/风格对齐，并在写入后读回验证。

除非某行明确写有“已实测”，本表的“一句人话”和调用顺序只是在解释当前 Schema / Skill 所描述的职责，**不等于本轮已经端到端执行成功**。完整实验事实只以第 08 篇为准；本表不把“当前接入面没有入口”写成“ChatCut 产品没有能力”，也不把工具合同转写成已经跑通的用户可见结果。

## 工具的深层关系：每次调用都在交接一种项目状态

MCP 工具不是把自然语言直接变成一条成片。绝大多数调用都遵循同一个合同：

~~~text
先读到当前对象和版本
→ 用它的身份、范围、修订条件提交一个明确动作
→ 得到新的对象身份、任务身份或写入回执
→ 再读回受影响对象 / 看可见结果
~~~

| 工具组 | 主要读取什么 | 主要写入或创建什么 | 下游拿到什么 | 必须怎样验证 |
| --- | --- | --- | --- | --- |
| 项目与 Timeline | 项目、活动线、版本、Marker | 项目容器、Timeline 分支、活动线 | 正确的 project / timeline 身份 | 再读项目与目标 Timeline |
| 素材与证据 | Asset、处理状态、源时间帧、转写 | 导入会话、素材组织、素材级编辑 | 可用 Asset 或候选证据窗口 | 确认处理/转写/云端可读终态 |
| Script / 转写 | 当前可听内容、源锚点、转写错误 | 语义主线或源转写修正 | 新 Script / 主线编译结果 | 重读 Script、Item 与字幕 |
| Timeline / Track / Item | 轨道、Item、范围、效果 | 片段、音频、画面、效果、轨道角色 | 新的帧范围、Item 状态或失败原因 | 读回范围与合成帧 |
| 字幕 | Card、Token、样式、布局、修订版本 | Caption 程序和 Card 局部修改 | 新修订的字幕状态 | 读 Card 并看可见帧 |
| 资源与生成 | 库候选、字体、模板、头像 | 生成任务、可用 Asset、设计资源 | Job 或新 Asset 身份 | 跟踪终态，再摆入 Timeline |
| 导出与下载 | 导出任务、资源身份 | 交付任务或临时下载目标 | Export / 下载的可追踪身份 | 查询终态、检查文件/许可 |

这里的“身份”可理解为 Project、Asset、Timeline、Track、Item、Caption 修订或异步 Job 一类的引用。精确字段名以实时 Schema 为准；重要的是不要把一个阶段的引用错误地当成另一个阶段已经完成的证明。

### 五条最常用的状态交接链

| 用户真正想做的事 | 正确工具链 | 中间必须出现的状态 | 最容易跳过的验证 |
| --- | --- | --- | --- |
| 把口播压成短版 | 项目定位 → 转写就绪 → read_script → 预览 / apply_script → read_script / Timeline → 字幕刷新 | 当前 Script 快照和新的主线版本 | 结构重排后独立声音/视觉包装是否失准 |
| 在某句上加 B-roll / MG / Zoom | 找到最终句子的 Timeline 范围 → 看目标合成帧 → 找/建 Asset → edit_item → preview_timeline | 目标轨、可用 Asset、精确起止范围 | 是否挡脸、挡字幕，是否仍服务该句 |
| 给一处强调加音效 | 明确编辑事件 → browse_library / 用户资源 → 检查 onset → edit_item / edit_track → 试听 | 事件时刻与音频物理起点的换算 | Item 起点不等于观众听到主要声音的时刻 |
| 给无声画面加旁白 | 先定画面—旁白同步图 → 确认音色和授权 → 生成音频 Asset → track_progress → Timeline 摆放 → 字幕/复核 | 真实音频时长、画面锚点、音频 Asset | 当前本轮未实测此完整路径，不能用工具名宣称已支持 |
| 导出可交付版本 | 主线与包装验证 → 用户明确导出 → submit_export → track_export | 导出 Job 与格式/用途 | 导出终态不等于资源许可和听感已验收 |

### 每条写工具都要问的四个问题

1. **我正在改哪个权威对象？** 例如一个目标 Timeline、一个 Card，还是一个源 Asset。  
2. **这次写入的前置快照还新鲜吗？** 陈旧 Script 已实测会被拒绝；其它对象也不应盲写。  
3. **写入后谁应该自动变、谁可能不动？** 主线、字幕、独立包装和异步任务的联动各不相同。  
4. **怎样证明观众实际看到/听到的是对的？** 结构读回、合成帧、浏览器播放和最终导出解决的问题不同。  

这四个问题比记住 58 个名字更接近真实的工具使用方法。

| 工具 | 一句人话 | 通常在什么时候调用 | 典型下游与边界 |
| --- | --- | --- | --- |

## 工具不应怎样串联

下面几种错误连接最常见：

| 错误做法 | 为什么不对 | 正确关系 |
| --- | --- | --- |
| 用 split_item 反复删口播每个词 | Agent 必须维护大量会变化的帧。 | 用 Script 完成语义结构，再由 apply_script 落帧。 |
| 用 edit_item 管字幕 | 字幕不是普通 Timeline Item。 | 读 Card，再用 edit_captions 修改。 |
| 先生成音乐/大批 MG 动画，再确认访谈内容 | 上游结构一改，下游位置全部可能失效。 | 先完成主线，再做包装和声音。 |
| 把 browse_library 当作外部下载库 | 它是编辑资源发现入口，许可和下载能力另有边界。 | 先查资源，再按第 09 篇做审计。 |
| 只依据 Skill 调用不存在的工具 | Skill 和运行时 MCP 可能有版本差异。 | 每次以当前 Schema 为准，缺工具就诚实标记缺口。 |
| 工具返回成功就说视频正确 | 结构成功不等于合成画面、字幕或听感正确。 | 读回结构，并查看浏览器/合成帧。 |

## 最小调用关系图

~~~mermaid
flowchart TD
    P[项目定位] --> A[素材与证据读取]
    A --> S{语音内容是否决定主线？}
    S -->|是| SC[read_script → clean_script → apply_script]
    S -->|否| TL[节目段落计划 → edit_item / edit_track]
    SC --> PK[字幕、声音、视觉包装]
    TL --> PK
    PK --> V[preview_timeline / inspect_item / read_captions]
    V --> B[浏览器或合成帧验证]
    B --> E[用户审片或导出]
~~~

这张图比“按工具编号逐个调用”更接近真实剪辑链路。
