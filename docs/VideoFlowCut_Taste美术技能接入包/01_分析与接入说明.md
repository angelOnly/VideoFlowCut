# VideoFlowCut：视频美术技能与项目接入

## 先看结论

**本包提供完整的视频美术方法与技能文件，可直接读取和接入。**

本文件同时交付分析思路与具体文件：美术怎样统筹配色、构图、文字与字幕，素材为什么不应被预设横窗，机制怎样围绕内容协同，以及已经写好的技能怎样接入当前项目。

最终工作关系是：**导演确定内容与观看发展，素材作者取得有表现力的内容，美术作者把内容组织成具体画面，动效作者把机制组合成同一场连续演出，实现端准确兑现，预览再回到这些设计决定。**

包内 `payload/` 已提供完整的美术入口与专业方法，附录逐字显示这些实际文件，不是待填充提纲。尚未修改用户仓库、插件、正式视频或字幕协议，也没有把本包接入后再验证新成片。实际效果需在接入后验证。

# 第一部分：从内容建立美术判断

## 一、先建立设计判断，再选择具体手段

### 1. 先理解任务，再使用一种方法

先判断任务、观众、已有资产和视觉意图，再确定设计方向：这段正在讲什么，观众应先看见什么，实际材料已经有哪些视觉条件，画面怎样推进，而不是先问这是“科技风还是高级风”。

“有电影感”要继续解释到摄影距离、主体尺度、光线、明暗、色彩关系、材质和运动。它不是一个自动决定黑底、金属、颗粒和宽银幕的标签。

### 2. 给出可以观察的设计，而不只给出标准

“保持高级”“字体要有层次”“动画要丝滑”没有给作者一个具体选择。有效方法应让作者作出决定：主体占据哪个区域；必读文字跟哪个对象；背景为什么保留；哪一处亮暗变化引导注意；新内容建立时旧内容怎样让位。

这些决定要直接体现在当前画面。格式完整或写出一套色号，不代表已经完成美术。

### 3. 将失败变成定位明确的修改

通过观察、诊断进行定向修改，不设“先换字体”的固定优先级。页面结构压住内容时，应先重新构图；如果换了字体但页眉、页码、横窗和票据仍占同样位置，核心问题没有改变。

### 4. 不把项目差异强制转换成随机变化

形式差异、运动强度、信息密度应分别判断，不需要新增三个必填分数，也不按题材自动映射固定数值。多个机制合作不等于信息拥挤；慢速镜头也可以复杂且有层次。每次换一套颜色并不能证明设计来自内容。

# 第二部分：美术怎样真正主导配色、布局、字幕与质感

## 二、美术的职责要从“选颜色”变成“交付整幅画面的设计”

用户指出配色、标题、字幕应在美术阶段一起做好，这个方向成立。需要避免的分工是：导演先把布局写死，美术只刷颜色，字幕另按默认模板覆盖，动效再给每个框加进出场。

保留现有技术路径 `visual-treatment-planning`，中文职责明确为“美术指导：构图、配色、排印、材质与字幕呈现”。不新增一个只交色号的代理。

| 负责人 | 应决定什么 | 不应越过的工作 |
|---|---|---|
| 导演／文案 | 讲述、内容发展、哪些文字有表达作用、镜头间关系 | 不预设所有镜头同一页眉、文字坐标、素材窗口 |
| 美术指导 | 实际主体、构图、色彩明暗、材质、画内文字与字幕的呈现关系 | 不篡改事实、金额、来源文字或已锁定叙事来迁就版面 |
| 字幕作者 | 准确转写、分卡、时序与实际排版落实 | 不独立覆盖美术已决定的字色、阴影或位置逻辑 |
| 动效作者 | 将材料和美术组织成机制协作的连续过程 | 不从原案例继承额外卡壳、图标、配色或页码 |
| 实现与主任务 | 将设计映射到真实接口、提交并读回结果 | 不用技术默认值悄悄替代尚未完成的设计 |

同一授权作者可以承担美术与动效，不按这张职责表机械增加人数。

## 三、从实际画面出发的完整美术工作方法

### 第一步：先确定观众面对什么，不从文字页面开始

接收实际素材、选段、准确台词和相邻镜头。看清原片的主体、运动、光线、空间与声音，决定这里是观看环境、靠近物体、比较关系、读资料还是面对一句主读。不同内容可以有不同观看方式，但不是为了凑形式种类而变化。

R75需要改掉的不是“左对齐”这个动作本身，而是每一场都先建立一张带标题的说明页。人物、客舱、票据或费用关系都应有机会成为整个画面的主角，不必先服从上方标题和下方横窗。

### 第二步：在未增加页眉与装饰时，让主体、必要文字先成立

先把当前真正需要的主体和准确文字放入实际输出画幅。决定观察距离、可见面积、共同参照和留白。然后再判断是否需要额外标签，而不是先建容器、栏目名和编号，再找地方放内容。

标题是随表达进入和退出的视觉对象，不是每镜的页眉。制作场次、机制编号、文件名和页面顺序留在生产记录里。R75现有栏目名和页码已被用户否定，本片不再以“保持统一风格”为由继续保留。其他任务确有观众导航用途时，仍可由导演和美术明确设计，不建立通用位置禁令。

### 第三步：先建立明暗和面积关系，再决定具体色号

先观察整幅缩略画面：第一眼看到什么，主体是否与背景分开，必读文字是否过弱或过强，是否到处都是同等重量的小块。必要时用灰度辅助检查，不把灰度当唯一审美标准。

色彩由实际材料、叙事情绪和角色关系共同产生。某一颜色可以在多场保持同一含义，但背景明度、材质和色彩面积可以随环境与观看变化。不能把“统一语言”翻译成“全片背景同一个十六进制值”。

落实在本片中的应当是关系：大面积如何安静、哪个局部更亮、何处保留材质色、如何用冷暖分出空间。不要只记录五个色块，也不继承“只能一个强调色”“所有饱和度必须低于某值”“禁止冷暖共存”等网页处方。

### 第四步：在整幅构图里一起决定字形、字幕和质感

主读、对象标签和普通字幕可以有不同尺度、字重与出现范围。准确文字先进入画面，再选择实际可用字款与换行。中文不能机械套用英文字体名单、字符数或紧缩行距。

字幕的字色、字重、阴影、描边、底板和位置一起判断。深色字并不天然错误，白字也不自动清晰；关键是它与当前背景怎样分离，以及是否与主体争抢面积。字幕时序与准确转写仍由字幕作者落实。

材质来自具体的轮廓、受光、薄厚、边缘和接触关系，不把“加颗粒”“加模糊”“双层卡壳”作为高级感的自动步骤。平面表达可以不模拟物理；需要体积时，就让实际几何和光影一致，而不是每个对象都叠同一个CSS黑影。

### 第五步：看相邻画面的发展，而不只看一张漂亮图

把本片已经实际设计的相邻状态放在一起：环境进入、主要关系成立、新重点接管、结尾完成。核对变化来自内容，还是只换了标题；字形和颜色逻辑是否连贯；素材有没有一直被压在相同小框里。

重要方向尚未确定或已被用户否定时，针对问题尝试不同主体尺度、观察位置或材质语言。已经成立的部分直接深化。这里没有每片几张图、每场几套方案的固定要求。

### 第六步：用实际实现修订，而不把概念图当成片证明

先形成可观察的设计，再实现并比对，不停留在口头方案。 可以使用当前代码预排、素材合成或明确标注用途的设计图。关键是基于本片真实材料和准确文字产生实际画面，并注明输出方式；不以概念图中的假字、虚构素材或复杂几何证明受管实现已经做到。

预览失败时定位原因：构图压缩了主体就重分面积，阴影脏就改分离方法，素材不合适就换范围或补素材，设计稿成立但代码变回标题页就修实现。不能统一加阴影、增加弹簧或延长时长。

## 四、防止美术被公共模板、字幕默认和交接重新覆盖

**美术责任统一，不代表只写一个Skill就能盖过已有硬编码。** 需要使后续实现服从该决定。

### 1. 共用视觉语言，不共用无条件的页面结构

共用代码可以保存实际字体绑定、颜色职责、材质工具、数学函数和确实重复的内容组件。根容器只提供渲染承载；当前场面的背景、文字与素材分别由该场设计决定。

将 R75 所示“场景分支之外自动画栏目名与页码”的代码移出默认路径。不要再让所有主标题通过同一个默认位置出现。复用文字样式不等于复用文字的屏幕位置；复用票据对象不等于它在每个镜头里都正面、居中、同样大。

这不是禁止公共组件或像素坐标，而是取消未由内容产生的自动可见元素。原用户确认的锁定品牌元素仍按本片实际要求处理。

### 2. 字幕外观的决定权在美术，执行能力必须真实支持

前轮核对的渲染代码存在固定 `textShadow: "0 3px 14px #000"`。若当前运行版本仍这样实现，美术作者写“无阴影”也不会自动生效。

因此需在实际协议允许的范围让阴影可控；尚无能力则同步修改字幕格式、编辑与读回、预览与导出端。新设计的显式选择优先；旧作品的兼容行为另行处理。不在Skill里发明一个字段，随后假称已经能控制。

### 3. 采用状态不是永久锁定

“曾经采用暖白纸票风格”只说明先前一次决定。用户明确否定它以后，需要作实质设计，不应要求所有作者继续保持。只改一个已明确参数时保持局部；整幅设计被否定时，就允许重做构图与美术，但不借机改写事实和用户已锁定内容。

# 第三部分：素材不再背负默认版式，机制真正协同

## 五、取消“必须横窗”等上游版式限制，但保留材料事实

原材料可能是横屏，这是文件事实；“在竖屏里必须保留横向窗口”是一次使用决定。两者不能混写成素材永久属性。

| 上游应该提供的事实 | 由导演与美术决定的用法 |
|---|---|
| 源片尺寸、时长、实际可用范围 | 全屏、横窗、并置、局部或跨镜剪接 |
| 主体在哪里、动作怎样发展 | 观察距离、素材面积、文字位置 |
| 某一区域裁掉后会丢掉什么内容 | 保留该范围、换另一源段、用相邻镜头交代，或重选材料 |
| 已知遮挡、声音及跟踪能力 | 是否使用源上标注、局部复制或独立解释层 |

导演需要“看见客舱空间或座位关系”，就写这个内容目标。下游实际看片后可重新取景，也可寻找更适合的范围；不预先要求一律contain，也不反过来规定必须cover全屏。

在工程中还要检查：旧素材需求、采用条件和当前交接是否仍保存了横窗要求。若只是前一次作者的布局决定，新稿替换其当前用法；历史记录仍保留。不能把旧布局混同事实条件继续向下游传，也不应为了换构图删除真实原件和观察。

来源、题材、媒介不预设固定路线；视频意图需要进入真实视频发现与获取。规则页齐了不关闭尚未完成的生活场景需求；某候选失败也不等于放弃该段观看任务。物理尺寸、实际可见内容及用户明确锁定项仍如实处理，这些不是限制创意的默认版式。

## 六、机制组合要按关系组织，而不是给每页分配一个效果

### 1. 组合的单位是一场连续表达

导演决定这段的内容与转折；美术建立入口、主读和接管的具体画面；动效作者从机制库选择能支持这些变化的关系。库里条目不等于可直接粘贴的成片组件，本片的路径、幅度、曲线、构图与源时间仍要实际实现。

复杂不是“更多物体同时动”，而是不同变化共同完成一次观察。一个主体可以继续运动，局部细节被揭示，文字开始读清，旧参照同时退让；它们可以有先后与交叠，不要求逐项演完后再开始下一项。

### 2. 四种关系需要按内容组合

| 组合关系 | 实际要决定什么 |
|---|---|
| 顺序发展 | 前一步建立了什么，下一步为什么由这里开始 |
| 并行协作 | 主过程继续时，哪层揭示、哪层说明；共同服务哪个注意目标 |
| 嵌套变化 | 外层对象或摄影窗口运动时，内层源片、标注与文字怎样随归属变化 |
| 交叠接管 | 旧重点还没退出时，新重点在哪里建立、什么时候取得主读 |

清楚切镜同样可以完成连接，不要求任何两个镜头都变形相连。

### 3. 把“共同完成什么”写进组合稿

不能只列机制A、B、C。应该说明：哪一个是本场主行为，哪些用于支撑；谁持续存在，哪个变化触发后一个；新重点在哪里可读；旧重点如何让出面积、对比或声音。

以R75的费用条为当前任务讨论对象，可以先设计：费用条从账单内部取得可读前景，账单保留为整体参照；移动过程中只呈现识别所需文字，读清区域建立后再给具体说明；结尾核对沿已形成的关系继续，而不是清空再新建一张总结卡。实际机制ID从当前库检索，不凭这段讨论虚构。它不是新增通用业务范文。

你认可的历史直播稿也有同类关系：手机尚在下沉时，头像、板面、文字和图像已经开始建立；不是四个动作串行退完再进。这里只借它解释协作，不重新要求导演前期加载该案例，也不继承其字体、配色和坐标。

### 4. 实现必须能保存共同状态

同一场面的共同对象优先在同一实现中安排，或在技术拆件时明确传递状态。父层负责整体观察与运动，子层负责局部揭示；两条机制不能同时把同一个位置属性重置。

同源视频继续自己的时间，不因为外框移动、变成局部窗或跨机制而从头播放。不同来源进入时保持真实起点与身份。声音可以提示接管或帮助动作落定，不要求每个元素一声提示。

这不是要新增复杂动画引擎或图数据库。组合关系写在现有演出正文，源码沿当前受管实现完成；只有某个真实缺口反复出现，才决定是否抽成可复用能力。

### 5. “高级”要在关键中途和整个过程里成立

静帧可以检查构图与色彩，但不能证明组合连贯。应看新旧并存时的投影面积、遮挡和主次，再看正常速度下是否能跟住观看。外提若只挪动几像素、比较若只有两张同义卡，即使登记了机制ID，也没有完成预期表达。

不设置每场最少几个机制、不要求全部源片做动画，也不把所有层都运动称为丰富。真正要保留的是机制中的完整动作关系，并使它在本片有可感知的作用。

## 美术指导：构图、配色、排印、材质与字幕

你负责本片整幅画面的视觉质量，不只是提供色号或给已有卡片换皮。输入是导演当前声画稿、实际素材与选段、准确文字、相邻画面、已有设计和用户明确要求。输出写回同一份场面稿，并附本次真实制作的设计画面和实现所需选择。

### 正常工作

先用一句话判断本段的视觉任务：主角是什么，观众怎样看它，材料提供什么条件，本段需要什么情绪与变化。不要先把“高级”解释成某套颜色、巨大标题或固定页面。

将实际素材、准确中文与普通字幕放在同一画幅里设计。先确定主角面积、观察距离、共同参照和阅读次序，再决定颜色、字形、边缘与材质。材料可以成为主画面；标题是否出现及其位置由本段决定，根容器不自动添加栏目名、页码和说明板。

制作本片可观察的设计结果，再继续实现。可用当前代码预排、真实素材合成，或明确标注用途的设计图；记录实际使用的方法。生图用于表达设计意图时，不重绘事实原件、编造数字或冒称已经由受管源码实现。设计与实现应能逐项对应。

统一的是本片的颜色职责、字形语气、材质和空间逻辑，不是所有镜头同底色、同标题位置。字幕的字色、字重、位置与分离效果和主画面一起确定；字幕作者继续负责准确分卡和时序，执行端落实外观。只承诺实际接口能支持的效果。

初步构图阶段不主动读取内置案例或机制库来替内容选形式。进入动画制作后，由当前作者沿[演出设计](../motion-brief-writing/SKILL.md)使用机制库，把已成立的对象、空间与阅读组织成顺序、并行、嵌套或交叠的变化。机制需要调整局部字位或面积时继续完善，不为保留某个机制的外壳重写本片美术。

## 视频美术方法

本页说明视频美术的需求理解、设计判断、视觉具体化和定向修订方法，涵盖中文排印、材料共场、体积、遮挡和实际返修。

新场面沿下面的设计过程工作；已有作品只进入当前问题。当前稿、实际材料、已确认结果与用户要求始终是依据。案例资料和运行合同在具体问题出现时读取，不要求每次预读全部资料。

### 设计判断：先有这条片子的视觉理由

读完整句群和前后画面，确定观众面对的是人物、环境、实际动作、材料细节、对象关系，还是文字本身。理解需要关系或变化，感受需要表演、空间和声音，定位需要身份与背景；这些可以共同出现，不必登记成一组分类。

在当前稿里写一条明确的视觉判断：本段以什么为主角、从哪里观察、材料有什么值得保留、画面怎样发展。涉及已有设计时，区分用户要求保留的部分与前一次作者自行采用的部分。用户否定旧风格，就允许重做构图，不把旧默认当成品牌要求。

设计方向要继续落到可见选择。不能只写“电影感、杂志感、高级科技”：这些词不决定是否用黑底、宋体、金属、颗粒、柔光或巨型标题。依据当前素材和内容选择，不按题材套颜色，也不为了避免重复而随机换一套风格。

形式差异、运动力度和信息密度分别判断。多层运动可以服务同一焦点，安静镜头也可以有细腻结构；不新增三个必填分数，不把可信赖的内容自动设计成保守说明页。

普通专业选择在任务内完成。方向已有依据就推进；确有高影响分歧或预览失败时，再比较能改变主体、观察距离、关系或情绪的不同方案，不为数量重复试色。

### 构图：让主体成立，再安排文字与辅助层

#### 从材料中找画面的结构

打开实际文件与准备使用的范围，识别主体轮廓、位置、视线、动作方向、亮暗、边缘、背景与可裁空间。使用已有有效观察，不把缩略图当成实际动作；缺关键材料时写具体寻找方向，不预设素材拥有可分离人物、开口或特定运动。

确定观众离主角多近、需要辨认哪些部分、哪些关系必须共存。物体的开口、部件、刻度和边缘既形成身份，也决定后续能够怎样展开。摄影、插画和模型按实际内容使用；组件能保留设计才复用，缺的是本片部件就在当前作品中完成，不先扩大平台组件库。

先摆主角与准确文字，暂不添加栏目、页码、细标签和装饰容器。查看缩小到实际观看尺寸后的第一注意：主要内容是否被标题压小，最亮的区域是否是无关底板，画面有没有在等文字宣布变化。根据原因重分面积，而不是统一扩大所有字。

实拍可以直接承担整幅场景，图形也可以凭对象关系成为主角。左对齐、居中、非对称、全幅和并置都是可选手段，不把某一种布局强制套给整片。不同场面因观看内容改变构图，不按场次机械轮换模板。

#### 横屏是素材事实，横窗是使用选择

来源的尺寸、源范围、实际可见内容和声音如实保留。全屏、横窗、局部、并置、跨镜剪接以及 cover/contain 是本次使用决定，由导演与美术依据内容选择。旧素材记录里的临时构图建议不自动成为永久约束。

需要保留空间关系时，说明哪一关系重要，再考虑取景、同源不同范围或相邻镜头共同交代。不能不看裁切损失就强制铺满，也不因源是横屏就永远缩在横条里。材料变化影响主角、字位和接点时，一起更新当前稿。

具体取材沿[取材与材料反馈](../../production-director/references/asset-briefing.md)。请求说明当前缺哪项行为、细节或范围，不让机制、来源网站、原件形式和预设容器反过来限制所有候选。

#### 文字和资料与主体共场

普通字幕承接当前语言，主读负责此刻的强调，标签说明所属对象，来源提供必要身份与条件。写清准确内容、归属、阅读位置和出现范围；这些文字有实际作用才出现，不默认每场配齐一套。

没有作用的常驻标题应让位。场次、文件名、机制编号等制作信息留在记录中，只有用户要求或明确的观看用途才进入成片。字幕换卡、段落编号与技术作品切换不要求画面清空重建。

主读进入前景时，材料仍保留理解身份与动作所需的部分。字幕挡住关键内容就调整字幅、布局、取景或时机，不能总靠缩小视频解决。材料本身的过程已经有价值时可以直接使用，不要求每段都形变。

证据已在前文建立，本段可以直接观察有效局部；身份未知时提供必要背景。原图文字、表格数据和条件按实际来源保留，强调层与原件区分。不得为了画面完整重绘一份虚构的官方表、金额或成功提示。图表比例、单位和比较基线来自本片真实数据。

### 配色：先组织明暗与面积，再确认色彩

#### 让配色成为当前画面，而不是一张色卡

从实际材料中挑出值得延续的色彩与明暗关系，结合当前表达选择基底、主体和强调。素材原有色彩不必全保留为图形颜色；可以保留某个联系并降低干扰，但不能在未处理原片时宣称已经完成调色。

先看主角和背景是否分开、主要文字是否清楚、是否存在许多同等亮度的小块。必要时灰度辅助检查面积与层级，再回到彩色确认冷暖和情绪。颜色、尺寸、位置和边缘一起影响注意，不能只提高饱和度。

选出方向后，把具体颜色放入当前素材、真实文字和字幕中试排。检查相邻表面是否融在一起，小面积强调是否变成多处抢眼装饰，截图本身的白底是否与环境冲突。可以改主体面积、局部背景、阅读区域或颜色关系，不必给每份原件另套一张大卡。

#### 统一颜色的用途，不统一每一块背景

同一关系跨镜保持可追踪，字形与材质语气可以持续；背景明度和颜色面积可随实际环境、主角和观看变化。不能把全片一致等同于每场相同底色。材料由亮变暗时，应相应检查字幕和标注，而不是让它们盲目沿用上一镜的字色。

不预设米白、深蓝橙色、黑金或任何其他色板。也不把“最多一个强调色”“不许冷暖共存”“饱和度低于某个数”作为视频通用规则。颜色数量和力度服从表达；要比较多个对象时，用共同基线和清楚归属维持理解。

用户明确喜欢的颜色可用，用户否定的方案要实际重做。替换色号后若仍是原来的标题页和小窗，不能把它称为完成美术重构。

### 中文排印与字幕：在同一幅画面中设计

#### 用真实字形而不是字体名称判断

用本片主读、最长条件、数字与代表性字幕查看实际可用字款，比较墨迹轮廓、笔画、字宽、断行、行距与观看尺度。字体盒尺寸只辅助测量，不替代真实渲染。主读可以有性格，字幕要稳定可读，标签体现对象归属，不要求三者同等大或亮。

字太细先核对字体回退、真实字重、可用面积；字太宽先调整布局、选用适当字款或准确断行。不要横向挤字、用厚影补错误字款，或以一个 CSS 字重数值冒充不存在的字体文件。英文排印推荐不直接替代中文字款判断。

实际字体绑定和加载按[组件合同](../../remotion-production/references/remotion-component-contract.md)处理；用户指定但缺失时再进入[字体与提交操作](../../remotion-production/references/submission-and-recovery.md)。普通设计先使用当前可用字款，不把扩字体库变成前置任务。

#### 字幕外观归美术统筹，准确时间归字幕作者

把当前真实字幕放入设计，包括字色、字重、尺度、位置和与背景分离的方式。深色字并不天然错误，白字也不天然清楚；判断其与实际画面的边缘、亮暗和运动是否相容。

字幕模糊时先核对字体与阴影；阴影、描边和底板是不同手段，不默认全部叠加。浅色稳定背景可以测试无阴影，复杂动态背景可使用适当分离；最终选择来自实际结果，不设统一的字幕背景带或固定字体颜色。

字幕作者沿已采用外观处理准确转写、分卡、时序与必要排版，不能又套另一套全局默认。美术不为塞入版面删掉事实条件；确需改变语言或分卡时与相应作者在同一稿中协调。

实际平台支持什么就落实什么。设计为“无阴影”而渲染仍有黑影，属于实现或能力问题，不能说成设计已兑现；也不能在稿中写一个不存在的字段假装解决。沿当前字幕操作返回具体差异，主任务处理真实接入。

### 材质与空间：细节属于对象，而不是通用滤镜

选择平面表达时，用轮廓、比例、排印、色块和对齐成立，不强加三维、玻璃和金属。选择物体表达时，先确定几何、薄厚、透视、光向与承载面，再处理高光和影子。不要靠颗粒、模糊或多重卡壳自动制造质感。

曲面高光随形体变化，薄片的边缘和内层不要被渐变画成鼓起的厚块。文字、图案、边缘和阴影属于同一物体，随姿态与透视一起变化。主体移动时不能把接触影留在原位置；粗描边也不能替代真实厚度。

接触影随对象与承载面的距离调整：靠近时收紧，远离时扩散，同时核对接触点和投影方向。影子的色相、浓度和模糊放回环境判断，不把一个固定黑影复制给所有素材和文字。

表面文字随姿态和曲面离开可见范围；可靠附着无法实现时，调整形体、观察角度或表示方式，交回实际影响，不让文字永远正对镜头却声称已附着。

尺度、遮挡与清晰度建立前中后关系。焦点转移改变相应深度，不用整图模糊冒充景深；远处可减少细节但保留对象身份。运动模糊服务快速变化，阅读和展示阶段仍应可辨。

视频、附着标注与裁切共用正确坐标；固定点只适用于源内相对稳定的目标。全屏转窗口、同源局部、跟踪或持续播放涉及的映射，读取[素材坐标与时间](../../remotion-production/references/material-space-and-time.md)，不在这里重复公式或假称已跟踪。

### 从美术画面交到连续机制组合

美术不是只设计入口和终点。按当前难点做出必要状态：第一次认出主角、关系读清、新旧共存的关键中途、交给下一镜的出口。不固定每场张数；每张解决一个实际选择。

使用本片素材和准确文字制作这些画面。代码预排、图像合成和方向性设计图分别注明；生成的理想图不能代替真实中文、事实原件及连续视频的实际实现。主要变化只有动态中才看得懂时，再做对应短预览，不能用“这里加动画”的静态占位宣称已经验证。

前期从内容与材料形成美术，不主动用机制库选故事或配色。进入动画制作后，当前作者按[演出设计](../../motion-brief-writing/SKILL.md)和[机制检索](../../motion-case-library/SKILL.md)读取需要的条目，映射到本片对象与源范围，不预读全部机制。

围绕一个完整场面的主行为，说明哪些变化顺序发展、哪些并行支持、哪些发生在共同对象内部、哪些在旧重点离开前接管。原机制中的额外横条、卡壳和小标签没有本片用途就不用。机制在这里帮助实际对象发展，不是拿几段原片首尾拼接。

接点要能回答：谁持续存在，新重点怎样取得可读面积，旧参照怎样退让，下一镜接住什么。外层变化和内层揭示应有明确归属，避免多个机制重置同一属性。同源视频按源时钟继续，窗口运动或更换机制不重新播放素材。

比较时保留必要尺度和基线，发现时给重要变化足够辨认空间。普通局部构图随机制适配完善；改变主要对象、事实或跨段讲法才回导演。实际配音和源声参与时机，详细节奏沿[时机方法](../../effect-timing/SKILL.md)，不照搬参考片固定时长。

结尾从前文已经建立的关系继续，令最后一次观察与结句一起完成。导演负责是否回答开场，文案负责准确收束，美术负责最后实际看见什么；不要因“到结尾了”自动开启总结卡、栏目外壳或全部对象轮流退出。

### 预览与返修

先用实际观看尺寸看整幅，再看关键中途和前后连续片段。区分设计本身不成立、实现偏离设计和运行端没有相应能力；也区分构图已检查与动态、声音尚未检查。

| 看到的问题 | 先修改哪一层 |
|---|---|
| 主体被标题和说明压小 | 撤去无作用的常驻文字，重新分配主角、必要条件与实际素材的面积 |
| 色彩脏、表面粘在一起 | 调整明暗分离、强调面积和边缘，再回彩色确认；不同时叠更多影、光和纹理 |
| 中文显得细、糊或拥挤 | 核对真实字款与回退、字幅、字重、行距和字幕分离方式 |
| 每场只换字而画面一样 | 改观察位置、材料用法与内容关系，不只换另一套色号 |
| 两端好看、中途挤成一团 | 改接管时刻的面积、遮挡、显露和主次，不把整段统一放慢 |
| 机制动作只有轻微挪动 | 核对目标行为是否真正发生；调整空间、行程、层次和接管，而非只加缓动 |
| 材料内容不支持当前画面 | 回当前源范围或补材；不要让布局或动画伪造不存在的过程 |
| 设计图正确、渲染回到页面模板 | 修共用可见外壳和默认值，保留已有设计，不反过来改设计迎合默认 |

实际任务只使用相关判断，不要求逐项填表。已确定且成立的部分保留，记录观察到的原因、具体修改和复看位置，让下一步可以直接继续。

只检查本次交付画幅。平台界面遮挡和裁切条件与本镜为人物、动作、阅读安排的空间分开；不永久空出一条字幕带。确需多画幅时分别调整主体、路径、字幅和负空间，不能把整幅机械缩小；单画幅没有另做一版不算降级。

交回当前场面稿中的实际画面、准确文字、材料与范围、字体、颜色用途、字幕呈现、必要参数及前后接点；注明已观察和待核内容。正式项目操作沿[共享交接](../../_shared/PROJECT_REVISION_AND_HANDOFF.md)和[场面操作](../../scene-planning/references/scene-operations.md)。方法落实为同一份产物，不再让接收者另填一套设计标签或重新猜全部意图。
