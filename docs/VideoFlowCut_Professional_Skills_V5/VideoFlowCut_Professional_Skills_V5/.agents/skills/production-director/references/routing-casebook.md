# 完整视频主工作流路由案例库

这份案例库用于处理“看起来同时像口播、解释片和 Vlog”的边界。路由的核心不是素材类型，而是谁决定主时间轴的顺序、长度和价值变化。

## 案例一：人物讲一本书，偶尔出现动画和空镜

素材是一位人物完整口播，内容从个人困惑进入书中观点，再回到自己的生活。虽然中间需要全屏解释“以后不断后退”的机制、书封面和城市/海边 B-roll，但人物的声音、表情和观点顺序决定整片。主工作流选择 `presenter-motion-director`。

Explainer 只在机制 Scene 范围参与，负责关系图；`visual-asset-sourcing` 找现实 B-roll，`cutaway-planning` 决定如何进入和返回；最终仍由 Presenter 工作流检查人物信任、安静区和主声音。

错误路由是因为有很多动画就选择 Explainer。这样会让人物变成旁白附件，个人反思的停顿和表情被卡片覆盖。

## 案例二：旁白解释某平台商业模式，人物只在开头露面

视频开场人物提出“为什么这个平台看起来免费却能赚钱”，随后整片使用流程、数据、官方页面、用户路径和现实 B-roll。主时间轴由问题—机制—证据—结论决定，不由人物连续表演决定。因此选择 `visual-explainer-director`。

人物开场是 PresenterScene，但不改变主工作流。若误选 Presenter，Agent 可能围绕人物不断加前后景小卡片，把需要完整阅读的图表和证据压缩在脸旁。

## 案例三：旅行 Vlog 有大量后期旁白

旁白解释旅程和感受，但真正顺序来自抵达、寻找路线、下雨、改变计划、最终到达和人物反应。镜头与环境声决定事件，旁白只是连接。因此选择 `vlog-director`，在有旁白的段落调用 `semantic-continuity` 和 `captions`。

错误路由是因为旁白很多就选 Presenter，结果会先按文字组织，再硬找镜头匹配每句话，真实行动和空间被打乱。

## 案例四：访谈加大量证据图表

主持人提问、受访者回答和追问形成主线，证据图表在具体回答中出现。问题—回答关系决定顺序，人物反应和完整观点需要保护，因此选择 Presenter 主工作流；局部证据由 `evidence-visualization` 和 Explainer Scene 参与。

若证据和论证完全重构为旁白，人物只作为引语来源，才可能改为 Explainer 主工作流。

## 案例五：产品发布视频

若主持人贯穿，以人物演示和 CTA 为中心，选择 Presenter；若视频主要是产品 UI、结构、比较和功能场景，人物只开场，选择 Explainer；若跟随真实使用过程、失败和结果，选择 Vlog。不能只根据“产品”一个名词路由。

## 案例六：用户只说“帮我把 20 秒那条字幕上移”

这是局部任务，不进入 production-director。使用 `project-basics → captions → web-editor-operator/quality-verification`。主工作流不会因为局部修复被重新执行。

## 案例七：用户说“这条片整体太平了”

这是整片反馈，先回 production-director 和当前主要工作流。不要直接进入 effect-timing。需要诊断是主线没有问题、信息重复、AttentionCurve 平、声音没有结构、Scene 过晚还是确实缺视觉变化。

## 路由判定问题

在不确定时依次问：

1. 去掉所有包装，什么仍然决定观众看到的顺序？
2. 观众主要通过人物关系、认知模型还是事件行动获得价值？
3. 最重要的修订会发生在 Script、Scene Grammar 还是 Shot Selects？
4. 哪个主工作流最有资格判断整片完成？
5. 第二类表达是否只在部分 Scene 需要？

答案指向唯一主要工作流。多个主工作流可以合作，但不能同时拥有整片最终决定权。
