# VideoFlowCut：技能精简与视觉演出落地优化方案

日期：2026-10-15

状态：技能源、调用路由及关联测试已实施，仓库内插件技能副本已同步。检查结果与实际验证边界见[实施与验证记录](development/技能精简与视觉演出落地_实施与验证_20261015.md)。未安装部署或重制正式视频。下文保留原方案的分析和拟修改描述，实际变更以实施记录为准。

本文重点是技能本身的优化：保留专业知识，重写不明确的入口和触发条件，补齐参考到演出、演出到实现以及实际返修的方法。第 4 节列出具体文件和修改位置，并给出关键段落准备采用的写法；第 5 节规定各阶段读取范围；第 10—11 节说明实施与验证。

本文承接本次视频质量复盘和用户已认可的优化方向，具体说明：哪些问题已有证据，重复内容怎样合并，技能在什么情况下读取，以及视觉作者怎样借助参考，把设计意图落实为连续画面。实施源仍为 `.agents/skills/`；本文是开发方案，不进入制作角色的默认读取链，也不在 `docs/` 建立另一套活动技能。

## 1. 目标与边界

优化后的正常工作应是：

> 理解准确内容与材料 → 通过参考形成演法 → 在本片对象上设计完整过程 → 用同一源码做连续粗排 → 观察实际效果 → 修设计或修实现 → 扩展到整片并复核接点。

具体目标：

1. 完整保留服务创意、效果与实现判断的知识；同一工作流程不反复展开，其他入口按需要引用。关键决策点必要的短提示可以保留。
2. 新设计读到必要的核心方法；局部修改直接进入对应分支，不因技能可发现就读取全部正文。
3. 参考从构思阶段参与，美术与动效共享观察，采用的关键动作实际进入作品。
4. 视觉作者持续负责美术、演出、源码和返修；导演负责内容、整片发展与主要采用，不承担逐对象运动编程。
5. 审片同时判断设计有没有兑现、实际观看是否成立，不用文字可读和技术成功替代美术、动效评价。

本方案不新建动效源码全集、参考管理平台、独立设计数据库、固定评分门禁或新的代理角色。现有通用组件可以继续使用，但组件能力不能成为降低已采用设计的理由。

不以压缩字数、减少文件数或删除比例作为成功目标。优化应让作者读对当前需要的方法，并将其中的创作知识用到实际作品；已经完整且有效的专业正文可以不改。

## 2. 问题分析：已经确认什么，尚不能确认什么

### 2.1 作品对照中的实际差异

本次较弱作品为约 328 秒的 AI 新闻片，较满意对照为用户提供的第三条机票视频，约 53 秒。以下沿用前轮对当前稿、源码、审阅记录和参考资料的审计；不将其扩大为本轮重新完整观看、听审了全部视频。

| 观察 | 能支持的结论 | 不能据此推断 |
|---|---|---|
| AI 新闻片有较完整的美术与演出文字，但实现主要依靠少数通用显字、线段和遮罩方法 | 意图到实现之间发生了可定位的过程损失 | 模型主观上故意省事 |
| `068-m07` 的独立信号传播和到点反馈，被压成线段伸长与端点显示 | 引用编号保留了，关键动作关系没有完整保留 | 动效库本身没有可用内容 |
| `043-m10` 的分组遮挡升出、附属行接力，以及 `002-m17` 的多对象接管与内部发展，没有完整兑现 | 采用参考不能只记录名称；必须追踪借用的具体过程 | 所有局部借鉴都必须逐像素复刻原片 |
| 已记录返修集中在裁切、姓名归属、文字重叠和可读性 | 局部修正确有价值，但没有关闭其他已缺失的演出问题 | 导演技能从来没有美术、动效要求 |
| 第三条视频同样使用通用组件，但有座椅参照、票据错峰、原件让位、列表接管等共同变化 | 组件负责绘制，场面逻辑负责对象如何共同发展；两者可以兼容 | 减少组件复用就一定能提高效果 |
| 第三条视频在真实配音到达后重排局部动作 | 语音需要改变启动、阅读和接管关系 | 只按段长比例缩放就完成了声画校准 |

第三条是本次用户指定的效果对照，不据此把该作品或其全部美术、声音宣称为正式入库标准。现有约 30 秒的整场协作教学样例与第三条约 53 秒的视频也不是同一作品，二者验证边界分别保留。

### 2.2 参考少，主要是需求没有继续展开

已查方法和接口使用说明没有“整片最多三条参考”的限制。查询的 `limit` 控制单次返回量，分页、补查、相似检索与前后接续检索另按实际返回执行。

三条参考不等于只有三次动画；同一机制可以在不同对象与关系中合理复用。但本片存在多种尚未完成的观看任务，最终核读的三条局部机制及其后续自主设计，没有充分解决这些任务。问题应追到具体范围：哪里缺主体发展，哪里缺观察变化，哪里缺文字协作，哪里缺连接。不能用“已经搜到几个编号”作为停止条件，也不能反过来规定每分钟必须使用多少条参考。

### 2.3 上下文负担是风险，尚不能作为单一根因

前轮日志审计中，两位视觉作者使用相同模型与推理配置，公开记录的输入规模都很大，较满意作品的峰值还更高。失败作品的初次简化也早于自动压缩。因此，不能把此次结果直接归因于“上下文长”或“自动摘要”。这些记录也不等于技能正文的独立 token 消耗。

更具体的阅读差异是：第三条视频的视觉作者写源码前有读取 `performance-design.md` 的记录；AI 新闻片没有找到对应读取记录。单次对照不能证明漏读一个文件就是全部原因，但足以说明：读取了大量外围资料，仍可能遗漏关键方法。

当前入口之间也存在多次转接：视觉入口、演出入口、机制入口、实现入口都重复讲整场职责、参考适配、同源粗排和交接。核心演出方法虽可达，仍需要执行者正确跟进。`motion-brief-writing` 当前配置为不隐式调用；这不阻止显式读取，也不应单独被定性为 Bug。优化应让视觉入口直接带入它需要的方法，而非寄希望于宿主偶然自动选中另一项技能。

### 2.4 旧精简方案有用，但需要继续落实到工作路径

已有两份方案提供了正确基础：

- [Skills 去冗余的分析与实施](VideoFlowCut_Skills去冗余_分析与实施.md)：一个决定、一套方法；合并独有条件，去掉重复流程。
- [技能文件组织与按需加载](VideoFlowCut_Skills文件组织与按需加载_思路与实施说明.md)：区分工作入口、专业方法、技术操作和案例；明确读取触发。

已有实施记录显示，目录迁移和部分正文合并已经发生。不能把旧文档的历史体积、目录数量或待办当作当前状态重新实施。此次针对当前版本继续解决三个缺口：核心演出方法未稳定进入实际工作，参考到实现的具体关系容易丢失，返修未持续追回这种损失。

## 3. 保留的效果要求与责任分工

### 3.1 精简不降低已经确认的标准

完整新制或主要视觉重做的视觉解说片，继续执行现有六项要求：场内连续变化、场间动态连接、有目的运镜、重点花字、局部动效协作、统一美术语言。定义只在 `visual-treatment-planning/references/art-direction.md` 维护。

同时保留主要动作的准备与蓄力、发力与冲击、通过、惯性和收势；保留适用范围内的全元素动态参与、完整场间交接及无硬切要求。阅读可以稳定，元素可以随共同父层参与，不把要求误解为全片不停移动或每个字都做同款弹跳。

六项不等于六个镜头，不要求每段各做一遍。既有用户锁定范围、其他视频类型和机械局部任务按原适用边界处理。普通字幕保持独立链路与统一规范，主画面作者负责画内标题、数值和标签。

### 3.2 谁负责什么

| 负责人 | 主要决定与产物 | 不再重复承担 |
|---|---|---|
| 主任务／协调者 | 用户沟通、实际分派、输入差异、正式提交、版本与结果恢复 | 为补齐参数而自行缩写或替换主要创意 |
| 导演 | 准确内容、整片顺序、主要材料采用、跨段含义、声画节奏与主要采用 | 替视觉作者逐项选机制、写路径、算曲线 |
| 持续视觉作者 | 参考观察、美术、对象映射、完整演出、同源源码、视觉返修 | 把美术、动效、实现视为三个互不负责的交接阶段 |
| 文案、素材、声音、字幕作者 | 各自专业产物，以及受真实变更影响的修订 | 重复读取其他角色的整套流程或重复检索同一视觉参考 |
| 审片负责人 | 观察实际作品，定位偏差与根因，复核修订结果 | 重新替作者设计整片，或只检查格式和无遮挡 |

局部构图、运动与代码修订由原视觉作者继续；主要事实、内容和跨段含义改变回导演。沿用已有真实分派方式，不新增一位“动效监督”或“设计转译代理”。

## 4. 去重方案：完整保留专业知识，精简重复流程

### 4.0 内容怎样分类处理

| 内容类型 | 默认处理 | 允许改动的条件 |
|---|---|---|
| 服务创意与效果的专业知识 | 原位完整保留，包括判断依据、动作关系、条件、例子与返修方法 | 只在确实妨碍正常工作时调整组织，完整承接独有内容；不为压缩长度改写 |
| 实现效果不可缺少的技术语义 | 完整保留，如坐标、时钟、父层、挂载、任意帧重建和声音起音 | 可以调整读取入口，不压成“查 Schema”或一句原则 |
| 多处完整复述的相同流程 | 核对等价后合并一份，其他处保留入口和必要局部提示 | 独有条件先合入，再删除等价副本；当前任务仍能直接找到完整方法 |
| 入口、职责与阶段路由 | 按当前任务重写触发条件、读取范围和返回位置 | 不能因此让新设计跳过核心演出方法，也不扩大机械修改范围 |
| 关键决定旁的简短提醒 | 判断有无防止误用的作用，有作用就保留 | 不因为出现过同义词就删除，例如源时间独立、用户锁定项和字幕独立层 |
| 尚不能确定是否重复的段落 | 先保留，列为待核对项 | 不用“可能冗余”作为删除依据 |

一个知识点是否保留，要核对它教会作者在什么情况下、为何这样选、具体怎样做、出现什么问题怎样改。保留标题、关键词或一个跳转链接，不等于保留了这些知识。

### 4.1 内容归属

| 决定或方法 | 唯一完整方法的归属 | 其他位置怎样处理 |
|---|---|---|
| 整片讲什么、为什么这样展开 | `production-director` 的主线与粗剪方法 | 视觉、Scene 方法继承准确内容与前后关系 |
| 视觉作者怎样开始和切换工作 | `visual-treatment-planning/SKILL.md` | 其他入口说明本阶段输入、动作和返回；保留独立使用时必要的责任提示 |
| 六项效果标准、美术判断 | `visual-treatment-planning/references/art-direction.md` | 导演、实现和审片链接对应标准，不复制定义 |
| 怎样找、读、选择真实参考 | `motion-case-library` 及其检索参考 | 演出方法提出当前问题并接回结果，不重写查询操作 |
| 怎样把参考变成完整演出 | `motion-brief-writing/references/performance-design.md` | 串联各专业方法；美术、检索和实现中独有的具体知识继续留在原处，只合并经核对重复的流程叙述 |
| 新语音、事件及阅读时机的校准 | `effect-timing` | 演出方法保留初步时间安排，精确校准进入此处 |
| 绑定、素材坐标、源时间、任意帧求值 | `remotion-production` 的对应技术参考 | 不压成一句“查询 Schema”，也不搬入每份创作方法 |
| 连续设计映射到平台 Scene 等对象 | `scene-planning` | 继承已采用的观看过程；保留 Scene 边界、内部状态和持续对象的专业解释 |
| 当前稿和角色之间怎样交接 | `_shared/SCENE_DESIGN_HANDOFF.md` 与 `_shared/PROJECT_REVISION_AND_HANDOFF.md` | 分别保留内容交接、身份版本与恢复，专业方法不反复抄写 |
| 实际观察与创意返修 | `quality-verification/references/professional-review.md` | 导演组织返修，作者按技术或设计原因处理，标准不另起一套 |

六项标准与演出方法可以互相引用，但不形成“必须全文来回重读”的循环。标准回答做到什么程度，演出方法回答如何形成和实现过程，二者用途不同。

“主位置”用于明确完整流程和标准的维护责任，不要求把其他文件中有关联的专业正文全部搬走。读取范围可以先收窄，知识正文可以保持完整；有实际收益再迁移，避免只为目录整齐制造大面积改写。

### 4.3 去重时的具体做法

以一个决定为单位查找所有控制它的段落，先保留独有的触发条件、判断理由、动作、例子和失败处理，再合并确实等价的流程。不能以标题相近、同用“交接”一词或篇幅较长作判断，也不能只在末尾加一句“按需灵活执行”而保留前面的相反要求。

例如“原设计成立，只改一个字”：视觉入口直接进入当前源码，演出入口、协调路由、主导演和实现方法不得再把它引回整片参考、完整稿重写和全量美术比较。所有实际调用位置一起修正，才算分支成立。

去重不删除裁切公式、源点映射、源时钟、命名事件与起音等重要行为语义。字段全集由实时 Schema 提供，字段为什么这样使用仍由对应技术参考解释。

| 原设计成立，只改文字、颜色、偏移 | 当前稿、源码、实际影响范围；相关实现章节 | 修改及受影响画面成立 | 新片构思、整片检索和重新分类 |
| 首次安排时机，新配音到达，正文或时长改变 | 当前演出与真实差异；演出方法第 4 节与 `effect-timing` 相关部分 | 启动、可辨、阅读、回应和接点对应当前可靠时钟；不足精度保持待校准 | 全部美术重选和无关素材再搜索 |
| 素材缩窗、标注漂移、跨段重播 | 素材坐标与时间、动态视频合同对应章节 | 坐标、源时钟、接续得到修正 | 重新编写故事或搜索新机制 |
| 需要人物遮挡、Mask 或多画幅 | `depth-composition`、人物编排和实际相关合同 | 此专项条件和实际表现成立 | 非当前类型的所有人物、Vlog 流程 |
| 需要精确证据、数据或 UI 演示 | 证据呈现及当前来源；相应真实材料操作 | 主张、条件与可见呈现对应 | 不相关的历史案例与修复背景 |
| 作品有图形缺失、动得弱或中途混乱 | 先看实际范围，再读演出／美术对应返修部分 | 找到设计缺口或实现遗漏，并回传具体修订 | 不带问题重读整套技能 |

完整新制作仍按现有方法观察选定整片的观看发展，正式采用机制前核读完整变化与必要接点。“按需”减少的是无关参考和重复读取，不把选中参考缩成只看首尾几帧。已有有效观察、资料未变时复用；缺失的连续观察如实标明并继续补足。

### 5.3 主任务、导演和审片的读取条件

| 角色与触发 | 读取范围 |
|---|---|
| 主任务准备项目操作 | 项目基础和协调入口；实际写入时进入对应操作与实时 Schema |
| 主任务派发或续接 | 任务路由、当前产物和真实差异；给作者必要核心链接，不替作者全文加载所有专业方法 |
| 导演首次组织整片 | 主线方法与已采用类型路线；取材、文案、视觉并行反馈按现有初始依赖进入 |
| 导演接回实际粗排 | 粗剪返修及当前设计；出现美术或动效问题时进入专业审片对应部分 |
| 专业审片开始 | 质量入口、专业观察核心、当前类型与实际问题；解释片读取适用六项标准 |
| 只检查文件或准备导出 | 技术交付、实际 Revision 和导出合同；不能据此填写未执行的创意审阅结论 |
| 出现具体错误 | 当前错误及正式恢复方法；没有错误时不把修复历史当制作前置 |

五种专业观察方式继续按问题和实际感知能力选择，不增加固定五轮导出门禁。已确认的设计缺失继续制作，未观察到的动态与声音保留未知，两者分开报告。

### 5.4 防止按需读取再次失效

- 链接锚点只是定位，不会自动保证工具只返回该章节。执行者按实际需要读取章节；不能把一次全文输出称为局部加载。
- 不因阶段切换重复读资料未变的完整参考。保存采用项与未解决问题，继续当前工作。
- 上下文压缩或接任后，先读当前稿、源码范围、参考位置和剩余问题；如果必要方法已不在有效上下文，再补读相关核心，不能把“以前读过”当永久有效。
- 主任务交完整相关内容和可恢复引用，不附上所有历史工具输出。`creativeBrief` 的长度限制只影响提交摘要，不能截断完整演出依据。
- 仓库源与安装插件同时可发现，不等于两份正文已经加载。实施后按实际会话核对来源与版本，同一内容不重复读取，不手改已安装缓存掩盖版本差异。

## 6. 从设计意图到动效：视觉作者的具体工作方法

### 6.1 先拿到可以开始创作的内容

导演交准确句群、观众需要理解的变化、前后关系、真实材料、锁定项和已有声音。可以只明确“从受控范围到外部影响”，尚未决定怎么动。缺少事实和内容含义时回导演；只是缺演法时，视觉作者直接开始参考探索。

此时不提前固定标题栏、资料窗或每句一页。材料已有强表现力的实际过程继续使用，参考用于组织它与其他对象的关系。

### 6.2 让参考帮助产生方案

先用内容关系寻找观看方式，比较候选是否能帮助本片展开，而非只找相同题材或配色。机制查询保留真实内容依据，同时描述可迁移关系：什么改变、什么保留、如何先后或同时发生、结束后留下什么。

入围后同时观察运动与美术：主体比例、字组、承托、明暗、材质、观察位置、运动准备、到达反馈及前后连接。选定参考可以改变初始构图，不把静态页面当不可改前提。

不强制固定候选数。已经有成立方向就深化；没有解决主要发展，或同类候选只提供入场效果时，改变查询关系、扩大范围或重选整段演法。实际工具参数、分页和语义结果以实时 Schema 与返回诊断为准。

### 6.3 确定借用的关键关系

对采用参考，作者先用简短正文说清：它为什么成立，本片借哪段动作，换成哪些真实对象，哪些关系要保留，哪些不采用，前后怎样接。这段直接写在当前演出旁边。

“必须保留”指采用后构成该演法的关键过程，例如独立主体传播、抵达才反馈、旧对象退让后新对象取得空间。对象名称、材质、画幅、具体行程和节奏可以适配。需要改变关键关系也可以，但应说明本片的新演法及实际收益，不能仍把弱化版本称为完整复现。

### 6.4 把多个参考组织为一个场面

由本段主变化组织相关层，其他机制补足观察、花字、局部响应和接点。顺序、并行、嵌套、交叠都可使用，取决于对象和注意关系。

组合时先处理真实状态：前一步留下的对象在哪里、占多大面积、处于什么速度和源时刻；后一步从这个状态开始做什么。两个机制都操作同一对象时，明确共同父层、局部层及同一属性的控制顺序，不让各自重新从空场起步。

没有解决的主变化或接点继续定向检索、试排或调整设计，不以“其余自行设计”交接，也不通过堆叠更多入场效果补长度。

### 6.5 设计关键中途与美术协作

入口和结果成立后，找最容易失去主次的时刻：新旧同场、遮挡解除、主体转向、结果开始反馈、文字第一次可读。说明此刻谁是重点、谁仍作参照、谁让位、哪些文字能看清、速度处于哪一阶段。

美术随过程一起调整。主体扩大时文字是否迁移，旧材料退后时明暗如何变化，花字与承托是否同属一个对象，背景怎样承接空间，均在当前场面决定。真实字形和材料参与粗排，不拿字号名称或色板证明画面已经成立。

### 6.6 直接在当前作品中实现连续粗排

粗排先实现主要过程、关键中途和接点，允许次要纹理尚未精修。使用实际材料、准确文字、正式可用字体和当前可靠时钟；尚未取得的材料或时间保持候选身份。

作品实现分清三层：

| 层次 | 应承担的工作 |
|---|---|
| 绘制组件 | 画票据、节点、字组、材料窗口等，并暴露当前作品需要的参数 |
| 场面逻辑 | 决定何时启动、怎样传播、谁跟随、谁反馈、谁退让、观察如何接管 |
| 合成与资源 | 素材绑定、源时钟、字幕独立层、声音事件和最终输出范围 |

绘制组件复用不意味着所有对象使用同一入场。场面可以共用一个语义事件，让主体面积、文字位置和解释区同时响应，同时为局部反馈保留不同延迟与收势。实现变量属于当前作品源码，不因此新增 MCP 字段或平台状态机。

真实视频时间独立求值。技术拆块使用连续场面时间与块内时间的正确换算，后块承接前块状态；组件挂载与配音段边界不能自动清空场面。任意帧重建等技术要求继续沿现有合同执行。

### 6.7 真实声音到达后重新编排

先定位句群和事件，再核对可辨、读清、回应与接管。必要时改变启动、交叠、行程和阅读面积，不只更改段长或统一压缩进度。

时间不足先判断是动作安排不当、文字过密、材料不合适还是讲述需要修改。可修改内容交导演与文案协调；用户锁定项继续保持。声音与字幕依赖真实改动更新，无关范围不连带重做。

## 7. 一个完整示例：传播机制怎样进入本片

以下是方法示范，依据已核读的 `068-m07` 说明设计与实现关系。本节不是本轮新检索结果，不代表该新闻事实重新核验或方案已经渲染采用，也不写入活动技能作为固定题材范本。

### 7.1 内容问题与参考贡献

内容需要观众看到：活动起初发生在受控范围，随后跨越边界并影响外部。参考自身提供：固定弧形网络、独立亮点沿线传播、抵达节点后的反馈、继续传递。边界表达、外部范围显露和后续事故段连接，仍由本片设计补足。

### 7.2 本片候选连续过程

| 阶段 | 观众实际看到什么 | 需要保留的关系 |
|---|---|---|
| 建立 | 受控范围与内部连接已可辨，画内文字说明对象身份 | 边界和网络持续提供参照，不全层同时抢入 |
| 传播 | 独立信号沿既有连接运动，节点在抵达后响应 | 线路显露与信号位移是不同动作，到点反馈有明确先后 |
| 越界 | 信号穿过边界，外部节点开始显露和响应 | 发生变化的位置清楚，保留内部结构供比较 |
| 扩大观察 | 观察范围拉开，旧区域让出面积，外部影响成为重点 | 旧对象身份、相对关系和活动时间延续 |
| 接下段 | 当前结果收稳，事故后果的真实材料取得阅读空间 | 前段留下的边界或结果成为后段接收依据，不突然清屏 |

这个过程还需要在真实材料与连续粗排中判断能否成立。图解不伪装成真实网络拓扑或攻击日志，准确新闻含义由本片核验稿约束；制作解释留在记录，不自动新增画面角标。

### 7.3 源码怎样防止关键动作被压缩

当前作品至少需要能够分别控制：信号沿路径的位置、各节点的抵达反馈、边界变化、观察范围及字组让位。可以复用节点与线条绘制，但不能用一个“线段长度进度”代替全部行为。

共同事件负责协调：观察拉开时，网络父层变换、旧说明退让、外部材料取得空间；局部节点仍保留自身反馈。素材源时钟不随窗口缩放重新开始。具体变量名和技术拆件由作者决定，不要求把本节做成一套通用引擎。

### 7.4 怎样判定此次借鉴有意义

先看当前连续画面是否清楚、有力度、主次成立，再对照参考：能否跟随独立信号，能否辨认抵达与反馈，范围扩大是否真的带来新认识。只有线变长、文字上移，即使引用正确，也要继续修。

实现了参考关系但本片仍平淡，则调整比例、行程、启动、停顿、反馈性格、材料与接点，必要时换演法。创新发生在这些适配和组合中，无须保存整库源码才可执行。

## 8. 当前稿与交接怎样保持设计不丢失

沿用当前声画稿和已有源码，不新建第二套计划数据库。每个复杂连续范围只需把以下信息写清，可用连贯正文，不要求固定表格：

- 观众要理解什么，准确内容和实际材料是什么，哪些条件不能变。
- 从入口到结果怎样发展，关键中途谁主谁次，下一段如何接住。
- 借用哪些真实参考，关键关系是什么，本片补了什么；参考和源码的具体位置。
- 当前实际实现到哪里，已观察什么，仍缺什么；声音或材料改变带来的真实差异。

源码已明确的精确参数不在稿中重复抄写。设计稿保留意图、采用关系和未完成项，源码保留实现，预览证明实际发生的过程。

若粗排暂未实现某个动作，当前稿应保留该目标并标明未实现。不能先把设计描述改成现有简单效果，再以“稿件一致”关闭问题。原设计确需改变时，由原作者说明具体原因和替代过程；涉及主要含义再由导演协调。

继续制作或接任时，携带当前范围及相邻接点、准确内容、素材范围、参考位置、源码、同版实际媒体和未完成问题。无需重发全片历史日志，但也不能只交几个机制编号、版本数字或被长度上限截断的摘要。

## 9. 审片与返修怎样追回缺失过程

### 9.1 两种观察各有作用

先观察实际作品：第一关注是什么、主要过程是否能跟随、字形和材料是否成立、节奏是否单调、接点是否连续。随后对照当前演出与参考关键关系，判断原来打算发生的动作是否真的发生。

头尾静帧可帮助查布局，不能证明传播、惯性、遮挡接管和速度。顺序抽帧、辅助模型分析、原速连续观看和真实听审分别说明覆盖，不互相替代。原参考必要上下文尚未观察时保留缺口。

### 9.2 按根因处理

| 实际问题 | 继续做什么 | 关闭依据 |
|---|---|---|
| 稿件只有形容词，没有完整过程 | 原视觉作者借参考补主变化、关键中途与接点，进入粗排 | 新的具体设计及实际过程 |
| 稿具体，关键动作未实现 | 原视觉作者修场面逻辑、父层、路径、挂载或时钟 | 同版连续结果出现了缺失动作 |
| 过程完整，但仍不好看或不好懂 | 调整构图、字形、材料关系、演法和节奏，必要时换参考 | 实际观看问题改善，不能仅补采用理由 |
| 段落各自成立，整片重复或断裂 | 视觉统筹接点与变化；内容发展由导演协调 | 相邻范围与整片顺序复看 |
| 素材无法承担需要的行为或细节 | 向素材作者提出具体缺口，或与导演调整表达 | 实际可用材料及其合成表现 |
| 已修姓名、裁切，但动效缺口仍在 | 关闭已修局部问题，继续保留并处理其他缺口 | 每项问题对应自己的实际修改证据 |
| 只有静帧或没有听觉输入 | 先修已能确认的问题，补足可用观察，保留未知 | 不填写未执行的动态或声音通过结论 |

反馈使用“实际发生了什么、丢了什么关系、影响哪里、应改什么、需保留什么”的短句，附具体时间／对象、版本和媒体。由现有项目记录承接，无需新增评分表或审批状态机。

局部返修不要求重看全部参考；关闭范围覆盖受影响过程及必要前后接点。导演负责确认整片问题得到处理，视觉作者负责具体修订，审片不是无人接手的报告终点。

## 10. 具体实施顺序

### 第一步：核对实际入口与专业正文

以当前 `.agents/skills/` 为准，核对第 4 节指定的章节、段首和调用位置，保留已有用户修改。旧文档只提供历史依据，不照搬其旧行号、旧数量和旧待办。已有完整有效的方法按本方案的保留范围继续使用。

### 第二步：先改入口、任务路由与按需读取

按第 4.4.1、4.4.3、4.4.6 节处理 K01、K04、K07、K15，以及受影响的 K11、K18 调用。先使新设计能够直达核心方法，局部修改不重新进入全片构思，Scene、空间、时机和技术操作只在对应工作发生时读取。

检索入口分清尚无演法、缺局部关系、指定参考和历史研究，不能要求先设计完整运动再开始搜索。入口中的重复流程改成条件明确的引用，必要的局部约束保留。

### 第三步：补齐参考到演出、演出到实现

按第 4.4.2—4.4.4 节处理 K05、K09、K10。以已有演出知识为主体，接上内容问题、参考关键关系、本片对象、共同状态和真实连续粗排。将实现问题分为选择缺失、过程未完成、源码遗漏；清楚交代分别继续哪项工作。

这一步不批量重写美术、风格、时机、Scene 和空间正文，不批量生成库内动效源码。先把当前作者实际执行的一条主线接通。

### 第四步：合并重复交接与返修流程

按第 4.4.5、4.4.7 节处理 K14、K16、K17：同一当前稿交清完整设计，复杂结构按需使用；专业审片只维护一套五类观察说明，实际结果与设计兑现使用同一根因判断。先合入独有内容，再去掉等价副本。

### 第五步：验证知识、读取路径与实际行为

先核对专业知识是否完整、引用是否有效、核心与分支能否按任务正确进入，再执行第 11 节中受影响的检查和隔离行为验证。实际制作测试检查参考关系是否进入源码与连续结果，不用段落更短或出现了关键词证明优化成功。

### 第六步：按已有流程同步与报告

技能源修改与对应检查完成后，经 `npm run plugin:sync-skills` 生成仓库发行副本，并核对内容一致。正式构建、安装和 Runtime 切换按已授权发布范围执行，不手改缓存。报告实际修改、检查结果、未解决问题与验证边界，不把源文件变化当作生产会话已加载。

后续制作验证使用确认已加载目标技能版本的新会话；旧会话里文件已变不等于指令已经重新加载。正式视频重做、平台修复和本次文档交付分别记录。

## 11. 怎样验证优化确实有效

### 11.1 结构与知识检查

- 入口对新设计、机械修改和返修的分流明确；必要演出核心有直接可达路径。
- 同一决定只有一套完整方法；删除重复后，独有适用条件、错误分流和技术语义仍能找到。
- 按第 4.5 节核对被合并、迁移和改写的知识；保留完整的创作依据、具体关系、适用例子及返修方法，而非只确认标题和关键词存在。
- 核查活动引用、默认提示词和发行副本，不只验证被改的 Markdown。
- 保留现有相关检查，例如 `scripts/check-topic-film-skills.mjs`、`tests/skill-reference-routing.test.ts`、`tests/topic-film-skills.test.ts`、`tests/creative-delegation.test.ts`、`tests/plugin-packaging.test.ts`。按实际影响选择执行，不因本文列举而无差别跑全部测试。
- 需要调整依赖旧位置的测试时，验证新的归属、可达路径与行为，不为通过测试把重复正文加回来，不新增“出现了高级、惯性等词就算合格”的测试。

### 11.2 行为验证任务

| 验证任务 | 应观察到的行为 | 失败表现 |
|---|---|---|
| 新建有真实材料、准确文字和声音的连续解释段 | 读取核心；参考参与构思；关键关系进入同源粗排 | 先固定通用页面，再查几个编号装饰 |
| 同一视频包含传播、比较、证据阅读和段间交接等不同需要 | 参考与自主设计覆盖真实缺口，适配后形成统一美术 | 首轮几个候选被当作整片预算，其余只换字 |
| 已成立作品只改一个字或一个位置 | 直接改当前源码并核对局部及必要接点 | 重做整片风格、全库搜索或加载全部技能 |
| 字组缩小、原件让位或素材跨段后出现漂移／重播 | 进入坐标与时间分支，保留已成立设计 | 为规避技术问题删去主要动作 |
| 新配音时长与停顿发生改变 | 重排语义落点、阅读和动作交叠 | 只统一缩放动画时间 |
| 返修材料中故意提供“线段生长代替独立传播”的版本 | 发现关键关系缺失，修实际过程 | 只修可读性，或重写设计稿为当前结果辩护 |
| 人物专项或纯导出任务 | 进入对应范围；不误读无关解释片或人物制作全集 | 所有任务共享一个全量必读清单 |

行为验证不把本方案写好的具体演出作为全部输入，否则只能证明模型能照抄答案。用原始任务、必要材料、目标技能和实际工具条件，检查它是否自行形成正确路径。验证在隔离目录或项目中进行，不修改正式视频状态。

### 11.3 效果验证与上下文验证分开

效果验证看实际连续画面：主体发展、关键中途、观察作用、花字造型、局部协作、美术统一和声画接续。先验证最有可能暴露问题的连续范围，再检查更长作品中的多样性、重复与跨段关系。局部样片成立不自动证明五分半整片成立。

上下文验证记录实际读取的文件与章节、重复读取、无关分支和核心漏读。若使用 token 指标，说明统计来自哪个公开字段，不把文件字节数、技能目录数量或累计消耗混称为上下文长度。可以比较前后趋势，不承诺未经实测的压缩百分比。

比较时尽量保持模型配置、任务范围和材料条件一致；一次成功只证明该次可行，不宣称已找到全部因果。后续多类任务表现支持后，再报告稳定改善。

### 11.4 完成标准

文档形成、技能源修改、结构检查、实际读取行为、连续作品效果、发行与生产部署分别报告。只有实际作品支撑时才说动效和美术得到改善；工具运行、渲染完成、用户认可仍是不同事实。

## 12. 代价、限制与不做的扩展

合理代价是前期花更多精力做主要连续过程与短范围预览，换取更早发现意图丢失，减少全长渲染后才发现演出不足。不会因为写了新的技能文字就自动得到理想成片，仍需要真实素材、可用工具、持续作者和实际观察。

本次优先在现有文件和流程内完成，不新增加载器、参考覆盖率系统、动效模板平台或自动审美打分。参考数量与动作密度由内容和效果决定，不设置配额。全库源码化既非必要条件，也不在本方案范围。

完整保留专业正文，意味着总字数未必明显下降，必要的核心串联还可能增加少量文字。优化收益首先体现在少读无关分支、少走重复流程、核心方法不漏读，以及设计更完整地落实到作品。知识归属与行为核对需要实际工作，不能通过省略方法来节约。

观察工具能力不足时保留准确的未确认范围；能够确定的设计或实现缺失继续处理。素材不合适、搜索无结果和设计失败先调整策略，只有确认平台自身缺陷阻断操作时才沿既有规则报修。
