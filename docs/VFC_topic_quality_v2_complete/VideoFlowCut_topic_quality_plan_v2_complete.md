## 2. 这次成功，具体多了哪些真正有用的东西

### 2.1 外部指令替团队完成了大量创意决定

`02_attention_new_generation.md` 不是一个普通主题，而是已经包含：完整评论基线、观看发展、材料角色、准确主读、显示字气质、工作坐标、主体与纸条比例、四字动作、语义落点、镜片数学关系和检查位置的创作输入。

普通主题任务必须由项目内部完成这些决定；不能只在 Skill 里写“导演应该自行决定”，然后期待它自然补齐。

| 成功输入已经给出的决定 | 它解决了什么 | 无参考任务中应由谁产生 |
|---|---|---|
| “住在／路过”到节目压力的完整论述 | 不是知识点罗列，有比喻、例子与递进 | 导演与文案，依据研究和实际材料 |
| 两次主读承担不同的语义重音 | 不是每句都提取关键词做大字 | 导演确定内容作用，视觉作者具体表达 |
| 头像、椅子、真实直播、PUBG 身份图各有角色 | 选材不止题材相关，还要能承接演出 | 素材作者提供发现，导演与视觉作者采用 |
| 固定实际字体、字重、字形和工作尺度 | 防止默认回退、名义字号代替实际观感 | 视觉作者在 Runtime 字体目录内选择并渲染检查 |
| 实际语音语义点驱动手机退出与节目组进入 | 讲述和画面不会各自按固定槽位播放 | 导演、声音与视觉作者共同校准 |
| 四字不同阶段侧转，最终仍读成同一词组 | 有可见的中间表演，不是统一平移 | 同一视觉作者写演出并实现 |
| 同一节目组供镜内镜外取样 | 图像、纸面、文字与连线保持共同关系 | 视觉作者负责本片实现 |
| 字幕是连续语音上的短句卡，不是多个停顿音频 | 阅读顺畅，语言不会被字幕布局切碎 | 字幕作者与声音负责人 |
| 从实际预览修椅子和主体 ROI | 发现具体误差后有限修订，不推倒全部重做 | 原视觉作者，导演只统筹主要变化 |

这些内容不是因为字数多而有用，而是因为**主要创作选择已经作出，而且彼此兼容**。[F2]

### 2.2 实际源码确实保留了这些关系

当前作品是 768×1344、30fps、788 帧，视频约 26.27 秒，文件含音轨约 26.33 秒。指令的约 29—33 秒没有被硬补满。

源码使用真实受管字体：

```text
主显示字：maoken-yanbo-song-black
纸条与次级衬线：maoken-yanbo-song-semibold
普通界面字：noto-sans-sc-bold
```

主字在 `LetterAct` 中分别处理“不能冷场”四字，各自具有入场偏移与竖轴角度；`Observer` 复用同帧 `Programme`，按共同坐标采样；阅读轨迹通过连续插值衔接，不是每张纸重新 ease-out 一次。

这些是该作品的实际实现，不是据视觉效果臆测“应该用了某种组件”。但这些函数里属于本片的材料尺寸、位置、词句和事件表不能原封不动升级成通用规则。[F3]

### 2.3 “剧情分段”没有变成“技术页数”

制作记录将三组句群映射到三个 Story Beat，同时用一件完整受管作品持续呈现 A—F 场面。

这很重要：故事存在不同阶段，并不要求每个阶段都清空画面、重建标题、播放一个新效果。保持对象和前后关系的场面可以跨句；真正需要切镜时才切。

不是以后全片必须只有一件作品。**应让场面内容决定连续性，再按真正的资源与编辑边界组织作品，而不是按段落标题分成几张页面。**[F4]

### 2.4 这次并不依赖很多音效或背景音乐

最终生产记录选择旁白主导，未采用 BGM，三个可选音效家族也没有进入最终音轨。原因包括音效语气不合、起音和合成适配尚未确认。它们没有因为“需要高级”就被勉强加入。

因此不能从成功结果推出“多加 whoosh、铺音乐就能变好”。本次先成立的是内容、字形、动作、构图和声音语义的对应。其他题材需要音乐或原声时当然可以使用。[F4]

### 2.5 成功交付包含内部修订，而不是反复让用户做审片员

记录显示，R49 是首次完整合成，v2 修摄影椅轮廓和气杆两侧空隙，v3 修两处游戏裁切；其他主要声音、时间与结构保留。

这里的 R72/R73 是项目版本，不等于渲染了 72 或 73 次。最终可见采用源是 v3。不能拿版本数字夸大迭代量，也不能把最终版冒称第一次结果。

无参考流程应复制的是**依据真实观察定位问题、回到同一作者、限制修改影响范围**，不是要求所有任务固定修两轮，也不是取消内部预排追求“完全一遍生成”。[F4]

### 3.1 不缺“导演”这个名字，也不缺基本方法

`production-director` 已要求完整观看叙述、材料反馈、段落、声画、跨场统筹；`TOPIC_TO_FILM` 已写主题驱动、文案画面共同发展；`SCENE_DESIGN_HANDOFF` 已有主体、美术、路径、文字和出口。

所以不能再把问题说成“项目没有导演层”。真正要查的是：**这些角色在一次主题任务中，是否交出了与成功输入同等完成度的决定，接收者是否拿到了它们，最后实现是否兑现。**[S2–S4]

### 3.2 受管渲染能力有了重要进展

当前 `managed-motion-13` 支持固定 TSX、真实图片/视频绑定、真实字体绑定、源时钟与事件输出。`submit_motion_work` 接收已经写好的源码、Props 和素材绑定，排队隔离渲染；它不是读取一句“做得高级”后自动承担创作的另一个模型。[S5]

当前合同已去掉以前按 30 秒、900 帧或累计像素帧要求作者切件的门槛，改为连续有界取帧与实际磁盘预检。仍有单件视频槽等实际限制，但不能沿用旧限制把每个场面切碎。[S5]

当前字体目录、文件哈希、实际字重、加载与 `props.fonts` 注入已经存在。不能再建议为此从零重建字体管理，也不能回到读系统字体候选栈却不确认实际加载的方式。[S6]

### 3.3 审阅与修复边界应该保留

`AGENTS.md` 已区分素材不合适、选择问题、平台故障；`inspect_asset` 提供可继续查看、换候选和报告故障的恢复类别。`review_motion_work` 不把审美待审当成一切操作的技术禁令。

## 4. 当前最明确的几个缺口

### 4.1 成功输入被存进 docs，不等于主题任务能自动学到

远端已经有 `docs/video22/02_attention_new_generation.md`；它与本次包内输入的 Git blob 一致。

但 `AGENTS.md` 明确运行时 Skills 的唯一源是 `.agents/skills/`。目前读取到的案例索引仍主要指向历史六例与 r92 组，新指令放进 docs 并不会自动成为一个有正确来源、适用范围与调用时机的运行案例。[S1,S7]

**建议：**将这次真实制作整理为一份完整案例入口，保存原输入、实际执行摘要、源码、视频、字体、时序、有限修订及用户反馈。正文按需读，不将 docs 全历史自动注入每个任务。

### 4.2 先看素材的指导仍有局部冲突

当前 Remotion 前置方法已经要求读取实际材料，但“段内创作”部分仍写着：

> 材料不齐可以先设计美术、状态和动作……取得实际候选后验证能否承担原定关系……

这可能被执行成动画先定案，素材回来再找容器适配。这里应明确“可以探索”与“具体采用”不同。

**建议：**本场素材依赖的主体裁切、原话揭示、源动作和具体表演，在相关材料查看后采用。未看材料的构想标作候选方向，不能提前作为正式完整动画提交。其他已具备的场面继续，不等待全片素材齐备。

这是一处真实的文案边界，不是声称本次成功任务又违反了它；本次记录反而说明素材被看过后才写本场采用稿。[S3,F4]

### 4.3 “需要交什么”已经写了，“怎样作出好选择”仍不够具体

现有交接表很完整，但下面这两段都可能被当成“已填写”：

```text
A：采用手机模型，标题进入，之后展示步骤和放大镜。

B：根据实际直播中人物和游戏的位置重排同源取景；
语言转到观看压力时，四字在各自终点附近错时侧转，
手机配合靠近；语义转折开始就下沉，节目身份组交叠接入；
镜片在纸条尚未全部落定时进入，与后续论述一起观察。
```

B 的价值是对一套具体材料作出了一组互相需要的决定。**再增加几个“必须有节奏”“禁止PPT”栏目，不会自动让A变成B。**

**建议：**补一项由现有视觉作者执行的详细写作方法，用真实案例说明如何从内容、素材、主角、构图变化和运动中途得到B，并在采用时检查实际稿，而不是只检查是否有栏目。

本轮在当前 main 未找到此前提案中的 `.agents/skills/motion-brief-writing/SKILL.md`，不能把“曾经交过候选文案”说成项目已经安装。可以新增这一项能力，也可并入 Remotion 的专门 reference；不要两份重复规则同时维护。[S3,S4,S7]

### 4.4 创作输入的完整度，在工具层不受自动保证

`motionSubmissionSchema` 的 `creativeBrief` 目前是最长 6000 字符的文本；`source` 是固定源码。校验器能保证字段和绑定有效，不能知道稿件是否写出了美术、剧情与演出价值。

本次实际 `creativeBrief` 约 2047 字，仍保留了关键几何、语义事件、字体、素材及变化；同时制作报告明确引用了完整外部输入。**本次没有证据表明它因 6000 限制丢了设计。**

建议不是简单把字段改成无限长，而是保证：作者在当前上下文读到完整稿；采用的完整稿有可恢复版本；工具摘要保留关键执行关系；最终源码和预览能对应到这版稿。[S5,F2,F3]

### 4.5 字体加载正确，不等于每次都能选对美术

当前能固定字体，这是执行稳定性的进步。下一步选择应从**本片内容语气＋实际可用目录**出发，而不是先想象一个并未登记的同款，再让用户选替代。

普通主题没有指定字体时，视觉作者应在已发布字款中自主挑选，结合真实字句和版式确认。用户明确要求的字体或品牌标准则继续按约束处理。

当前“理想字体未收录时由用户选择”的合同不能被悄悄取消。若要改变这项交互政策，应作为单独产品决定，同步 AGENTS、协调/视觉 Skills、工具提示及回归；不能只在一份 Skill 写自动采用首选。[S1,S3,S6]

### 4.6 原生字幕仍会依法定排版规则变成两行

`caption-layout.ts` 当前的结果类型允许一行或两行，并按实际字宽自动拆行；字体族固定为 `Inter, Noto Sans SC, sans-serif`。受管作品的 `fontBindings` 不自动控制原生字幕轨。[S8]

本次通过真实时间重新切成 21 张单行卡，避免了这一问题。但是“不要输入换行”不保证以后所有长句仍是一行。

**建议：**先让字幕作者按片内设计与真实语音切卡。若需要工程保底，增加经评审的字幕行数偏好，例如可选 `maxLines: 1 | 2`，默认保留当前两行兼容；超过所选宽度回报应重分卡，不替用户改台词、不自动压扁字。

这是建议新增的合同，不是当前已经存在的字段。词级或句级精度不足时不伪造切口；依据可用粒度选择可兑现的排版与声音调整。

### 4.7 当前测试不能替代无参考创作验证

读取到的 `presenter-creative-agent.eval.ts` 明确只验证 Skill→MCP→报告→预览/质量入口可调用，不声称专业创作或审美通过。这是正确的技术测试边界。[S9]

接下来要另补真实主题任务的结果评估，而不是把现有技术回归全绿当成稳定高质量。也不能把本次手工完整指令放进测试输入，然后将结果命名为“主题冷启动成功”。

```text
用户只给主题
    ↓

    ↓
按当前问题读少量内部案例
    ↓
同一视觉作者：生成本片自己的完整演出稿
    ↔ 旁白/源声制作，返回真实时间校准

    ↓
```

这不是新增一串代理。保留原角色，明确每个阶段**已经作出什么决定、接收者真正取得什么输入、何时能进入下一步**。

无参考时允许读内部案例库。用户“不提供本次参考视频”不等于系统没有任何设计经验。但内部案例只教可迁移方法，不代替本片新的内容、主体和布局。

## 6. 无参考时，内容和审美怎么具体产生

### 6.1 先生成值得看的内容，不从动画菜单开始

导演与文案应交连续声画叙述，包含：

1. 观众此刻关心的一件具体事；
2. 哪份实际材料提供了行动、细节、条件、对比或反应；
3. 观看过程中发生什么变化；
4. 哪句是需要被记住的判断，哪里只应保留源镜头；
5. 下一画面为什么接在这里，最后怎样完成本段。

不是每段必须反转，也不是固定三幕或固定九节点。访谈、物体展示、空间观察和安静反应也可以成立。判断要建立在当前内容上。

当材料只支持一个很短的小观察，就缩短或继续研究，不给它硬分配三十秒。语言讲的是动机与判断，画面讲的是可见过程；有必要的强调可以重复，但不逐项报“人物在这里、现在放大”。

### 6.2 素材同时考虑语义匹配与可编辑性

先确认它是否是正在讲的人、事件、物体或依据；再确认它适合怎样裁切、停留、局部指认或作环境。

原片、录屏、成片、照片、页面都是候选。既不因“成片”而自动拒绝，也不因“能下载”就用无关游戏或采访补位。

素材负责人返回具体发现；导演可以因此改稿，但不能不说明就换掉必要主体和事件关系。普通搜索失败继续调整策略，真正的工具错误才走修复。

不同媒体可以承担不同作用：需要行动就用实际视频；需要读取结构或条款可以用静态材料；纯图形解释需要内容依据；不把“所有时刻都有活动视频”当质量指标。

### 6.3 本片视觉设计必须是一套已选方案，不是形容词

在已有 VisualTreatment 或同一场面正文里，明确：

| 设计项 | 本片需要作出的决定 |
|---|---|
| 字体 | 实际可用ID；主读、普通字幕、物体标签各自用途；不得每场随手换字体 |
| 颜色 | 哪个是底、文字、强调和证据色；颜色承担什么内容作用，而不是列三种喜欢的颜色 |
| 图形形态 | 纸面、平面矢量、产品实物、截图或其他适合题材的载体；边缘和阴影为什么这样处理 |
| 构图 | 当前主角占什么可见范围，文字与它怎样交叠，哪处负空间有用 |
| 运动语气 | 主体有重量还是轻快；哪里跟随真实动作，哪里稳定阅读，哪里需要有力度的转移 |
| 段落差异 | 相邻场面的观看距离、方向、明暗和表现任务如何变化，同时保持同一美术语言 |

存在实质不确定时，内部比较少量完整的候选构图，例如同一素材的两种主次关系；选定后再交一个清楚方案。不是每场强制生成三套美术，也不让用户替作者选每个坐标。

候选预览应使用实际素材、真实字体和将用于作品的代码。不再让图像模型画一张理想化年轻主播、漂亮房间和纸条，再声称工程能够自动达到。

### 6.4 多样性来自内容任务，不来自特效数量

本次有群体关系、真实物体笑点、内容更替、概念重音、节目安排和局部观察。它们任务不同，因此动作自然不同。

新题材不应复制这六件东西。可以出现：

- 已有操作视频里的一次真实错误与修正，主要靠剪辑和局部指认；
- 一张有明确来源的尺寸图，围绕同一尺度展开比较；
- 产品实物的一个部件如何接入整体，靠材质、角度和遮挡表达；
- 一个真实人物的短反应，保留原声和足够空间，不叠满文字。

以上是设计路径示例，不声称已经取得这些材料。具体采用要由本片材料决定。**不规定每分钟有多少转场、多少镜片、多少弹幕。**

### 6.5 从决定写成完整执行稿

采用稿至少把四个层次接成一件事：

```text
内容：为什么此时需要这次变化。
材料：哪份实际内容/对象/原句是依据。
美术：当前主角、字体、比例、明暗与空间怎样构成画面。
运动：从起点经过什么中间状态，谁让位，何时落读，下一步怎样接。
```

不能只写“画面放大，字幕进入，有高级感”。也不需要把所有局部都变成API字段。普通坐标由作者在实际画布中确定，主要关系与时间写清即可。

## 7. 一次具体转场需要写到什么程度

下面用本次成功作品说明“有动作名”与“已作出演出决定”的区别；这是案例解释，不是未来所有视频必须用手机。

### 薄弱交接

> 说到压力，手机退出，随后显示节目安排。用衬线花字和放大镜，保持流畅。

### 当前作品实际明确的关系

- 讲到压力时花字即开始退，手机向下；
- 手机尚未完全出画，身份头像与灰板已经展开；
- 图像紧接着进入灰板下方；
- 到持续有活这层语言，新场面已经成立；
- 讲节目安排时，点线、纸条与镜片交叠建立；
- 镜片观察期间语言继续解释，而不是读完所有条目后静默扫一遍。

实际源码将这些关系落实为同一张事件表：`pressure=505`、`board=512`、`art=517`、`phoneEnd=528`。这些数值仅用于定位本次作品，不进入通用Skill默认。[F3]

### 无参考生产要迁移什么

迁移“把前后动作挂到本片当前语义与观看任务上，共同编排”，不是迁移 `505/512/517/528`。

对每处关键变化，视觉作者应具体写：

> 此时正在看哪个对象；实际源状态是什么；哪项内容触发转移；旧主体沿哪里离开、保留什么；新主体从什么已存在的边缘或空间接入；中间一半时观众还能追踪什么；本句说到哪儿新重点已经可读；需要多久读清；出口由什么接住。

这份正文是同一作者实现和审片的依据。缺主要设计时回该作者补全，不由主任务在参数装配中临时换成模板。



````markdown
# 完整声画演出稿：从具体内容到可以实现的设计

## 1. 使用时机与责任

导演已提出本段内容及在全片中的作用，且影响具体设计的材料已经可查看时，由正在负责该场的视觉作者读取本 Skill。作者可继续读取构图、时机、字幕或案例资料，不为每份资料另建子代理。主要剧情和跨场风格由原导演统筹，正式项目写入、生成与渲染仍由主任务按当前 MCP 合同执行。

本方法要产出的不是“给另一模型的华丽提示词”，而是原作者自己准备实现的完整演出。故事怎样发展、什么值得被看见、用了哪份实际材料，先有依据；然后作出美术和运动决定；最后把它们写在一份当前正文中。下游不应重新猜主角、主要构图和关键转场。

只需机械改字、固定偏移或简单直剪的任务按局部范围完成，不强迫它经过长表单。真实动作、人物原声或稳定对比已经足够时，可以明确采用直接剪辑；不为触发本 Skill 强行增加动画。

## 2. 先确认足以设计的实际输入

阅读导演当前声画稿、前后场面与本次发布配置。实际查看将被使用的源范围、图片、页面、原声和已有文字，理解主体、相机、动作、遮挡、原包装和清晰度。导演看过故事材料，不代表视觉作者已经知道如何裁它；反过来，素材摘要也不能代替导演决定这段值不值得讲。

缺关键输入时，向协调者返回具体请求：要补哪个源范围、哪句上下文、什么动作或字形。其他具备材料的场面继续，不要求全片等齐。没有看清的源内运动不写成已发生；静帧可支持静态构图，却不能支持未经观察的快速反应和精确词级时刻。

已剪成片、原始视频、照片和页面均按实际用途判断。不要因成片身份自动规定 contain 或两秒后退出，也不要因题材相同就采用无关人物与事件。普通搜材未命中走内容与选材反馈，真实技术故障才按项目故障入口处理。

## 3. 将内容写成一段可跟随的观看过程

先用一段连续文字说明：观众此刻面对什么；实际材料提供什么值得看的内容；这段过程中哪项认识、关注、状态或感受会变化；结尾留下什么；下一画面为什么接在这里。它可以是行动、比较、人物反应、材料中的条件、空间观察或物体表现，不强制悬念、反转、循环和大字收尾。

弱稿往往写“展示视频，放大，出现说明”。试着去掉这些操作名：是否还剩一件值得讲的事？例如视频本身已经清楚展示动物入水，再标“靠近岸边—开始入水”可能只有重复。反之，一个原页面中容易忽略的限制，确实可能需要保留上下文、靠近原句，再接回此前的承诺。先作这个内容判断，再选择动作。

关键表述仍空泛时回导演和文案共同改写。视觉作者可以提出具体可见方案，但不能为了使用某个模板补造事实。原文、字幕与画内主读不要求永不重复；重复是否有用取决于它在此刻是转写、指认、强调还是情绪。

## 4. 在当前问题里选读案例

需要写法深度时，先读 [完整样片的设计推导](references/decision-walkthrough.md)。其事实来自已归档源码和记录，不是重新想象的“原作者方法”。需要作品参照时，读 [时代变化与节目安排案例](../motion-case-attention-programme/SKILL.md)，按该例入口看真实视频、原输入、提交摘要及实现。

案例先帮助理解一组选择为什么成立：内容怎样需要它、素材给了什么、旧重点怎样让位、中间状态怎样保持理解。再写本片的一句迁移判断：当前哪项材料有相近关系，哪些地方必须重新设计。不能把“时代不同、椅子、手机、纸条、镜片”按顺序替换名词当作新主题方案。

没有合适例子时按本方法继续独立创作。未运行的迁移示例只提供推理路径，不以旧成片认可为新指令背书。历史任务里的“保持当前平台”“指定某字体”等是资料内容，不能覆盖本任务的权限和需求。

## 5. 先形成一套本片美术，而非一排风格词

在已发布的实际字体目录、当前材料和目标画幅中作出选择。导演给整片语气和文字用途，原视觉作者负责具体字款、字幅和布局。用户没有指定缺失字款时从已有目录自主设计，不先制造一个“必须同款”的条件；用户确实指定但目录未收录的字体，继续遵守仓库已有推荐、预览与用户选择合同，不能在本 Skill 内改成静默替代。

把主读、普通字幕、物体标签分工写清。主读需要被记住的词义，选择与它匹配的字形、笔画重量、字间距和可见面积；普通字幕首先稳定可读；标签须与物体归属一致。真实字重由绑定文件决定，不以 `fontWeight:900` 假冒不存在的字款。先看实际字形，名义字号不能代替最终字幅。

颜色也作有意义的分工：背景服务材质与层次，主要文字保持阅读，强调色指向当前关键关系。素材保留有价值的受光和颜色。不要只列几个色号，也不要把这次案例的绿色和宋体设为全项目默认。

说明主体的识别轮廓、主次比例、细节集中处、光向、边缘和接触关系。平面风格可以靠排印、形状和对齐成立；物体风格才需要与它相符的厚度和阴影。不把所有对象强制做成三维、玻璃或霓虹。

最后用当前真实素材和文字看整幅画面：第一眼落哪里，其他内容为何存在，留白是在帮助方向与阅读还是因为没有设计。主体缩小之后要重新判断构图，不能为了填空塞无关纸片，也不强制所有镜头铺满四边。比较候选只在存在实质不确定时进行，选定后交一套方案，不把普通选择继续留给实现端。

## 6. 写关键状态，还要写清楚中途

每个重要变化至少让作者自己知道入口、中间、落读和出口。入口说明已经在场的对象和参照；中间说明谁发起、绕哪里转、沿哪条路径、改变哪些属性、谁遮挡谁；落读说明什么已可辨、哪些内容暂时退让；出口说明本段结果由什么接住。

运动不是所有属性共用一条 ease-out。连续观看转移可能需要贯通路径与非零中途速度；读条款或看真实反应可以停稳。轻纸、设备、重物和镜头转移的起势与收势应体现任务和轻重，但不统一使用反弹制造“物理感”。同一词组可以分字表演，仍然形成一个清楚的词，不是四张不相关字卡。

对于同一个对象的前景接管，明确开始时的投影、裁切、内容和源时刻；退场的原对象怎样覆盖或保留，防止双影。真实内容引出图形时说明依据是哪句或哪项观察，新文字是引用还是解释。共同构图则写清素材、排印、遮挡与镜头怎样一起转移重心，而不是一块播视频、一块弹标签。

以上关系按本场需要选择，不强制全部出现。图解可以离开实拍，但前面的内容应被后面接住；明确硬切比错误“像素连续”更诚实时，就采用切镜。模板见 [执行稿结构](references/execution-brief-template.md)，不是交给用户填写的问卷。

## 7. 用语言和源事件安排时间

先有当前可讲内容和声音方向，再取得实际旁白、原声及可用对齐。画面设计可以与声音共同深化，但正式动作时机需要落到当前真实句群。首版配音可以因内容修订而重配，不能强行删掉主要演出来服从旧长度。

关键动作分别说明预进入、落读、回应和持续：哪句意思让旧对象离开，哪句开始时新重点应已看清，什么还需要阅读或反应。先用秒描述尺度，之后按当前 fps 换算；记录时间精度，没有词级证据不按字数平均制造精确时间。

讲述句群、字幕卡和视觉场面是不同单位。一段自然语音可有多个短字幕，同一对象也可以跨句发展。采用单行字幕的片子，用实际语音和字宽切成先后短卡，不通过把 TTS 切碎、缩字、非等比压字或隐藏内容来“通过”。需要双行且设计成立的其他影片可以保留。

运动完成后的停留必须有阅读、比较、反应、情绪或源声用途；背景还在漂浮不代表当前内容在发展。反过来，不把所有静态都判为空等。音乐、音效和源声按作用选择，这次无 BGM 的成功不成为新任务的默认静音方案。

## 8. 深化稿、导演采用与实现是同一个版本链

使用执行稿结构交回一份自洽正文，包含实际材料与范围、准确台词、主读、美术、连续演出、当前声音时机、字幕策略、前后接口与待核事项。简单段短写，复杂段写到能直接实现；不以字数、字段个数或效果数量判断完成。

主任务将完整稿回原导演统筹。导演检查本场发展与全片关系；局部坐标和曲线仍由原作者决定，不让每个像素都审批。采用只表示可以据此继续，不表示动态和审美已通过。随后同一作者读取 [Remotion实现](../remotion-production/SKILL.md) 完成源码，不能把已选方案又压缩成一句交给另一个人猜。

完整稿沿已有任务消息、附件与创意决策引用保存，确保实现作者实际取得全文。提交的 `creativeBrief` 使用实时长度合同，摘要可以短，但不能丢掉主要执行关系；没有证据时不把字段上限当成本次失败根因。素材或时间变化后原作者重看影响，更新当前稿和对应实现，而不是只更换 Revision 号。

## 9. 在实际产物上检查，按根因返回

先从当前源码、素材和字体渲染必要关键状态，查看真实字号、裁切、边界和主次；不要用另画的概念图代替实现。对需要动态判断的接点，取得开始前、中间、落读后和下一画面的连续范围，再查看完整声画。

如果内容没有发展，回导演与文案；内容成立但稿只有动作名，继续深化；稿具体但源码漏层、裁错、字体回退或时钟错，修实现；实现忠实仍不好看，回到美术和演出选择。不要统一以加阴影、加字、更多 whoosh 或更长指令处理。

静帧只证明对应画面；声音检测只证明相应技术事项。未听到、未连续看过的范围明确保留，不将记录里“已播放”写成所有听感已通过。用户认可最终作品是独立反馈，不倒改较早的原始审阅记录。

## 10. 返回产物

返回当前完整执行稿与准确参数、素材/字体/声音引用、主要实现位置、实际检查请求和修改影响。继续本次作品直至完整交付，不停在“写好指令”。归档时分开原始任务、实际提交摘要、源码、最终视频、修订记录与后写的教学说明。新主题的新结果必须重新验证，不借用历史样片的认可。
````

````markdown
# 当前作品完整演出稿结构

这是给已获授权的原视觉作者使用的产物结构，不是用户问卷，也不是新增工具 Schema。简单场面可合并栏目。复杂场面中，栏目后必须填当前已经作出的决定，不能抄下标题就提交。

连续说明前文已经建立什么，本场实际展开什么，观看后哪些认识、关注或感受变化，下一场为何接入。确认原剪辑与源声是否已经足够，图形具体增加什么价值。

## 二、实际材料及依据
列已查看的文件、源范围和观察精度；指出将被操作的主体、原句、动作、纹理或空间。真实人物身份来自可靠文字/记录，不从相似面孔推断。关键未知及其影响写清。待找材料不混入“已经取得”列。

## 三、当前完整声音与文字

## 四、本片美术和关键构图
写实际字体ID及用途、颜色角色、主体轮廓与比例、细节与受光、整幅画面内第一关注、前后层级和负空间。以真实字形与素材投影说明，不只写“高级”“有冲击力”。

## 五、连续演出正文
每个内容段用连续叙述写入口、发起原因、路径/轴心、速度与幅度、中间状态、遮挡、落读、交叠和出口。说明谁持续、谁离开、为什么下一项现在出现。普通设计选择在稿内选定，不给执行端一整排可选效果。

例如，不交“先显示设备再出现限制”；而交“当前录屏停留在已核实的价格区域，保持该价格为左侧参照；同页限制从原行靠近，前景主读尚在收势时限制已达到阅读位；旁白解释差别，原页面的单位和条件仍可辨。下一句回到实际操作的结果”。这个例子只说明深度，真实任务仍需取得对应页面和操作，不能假设结果。

## 六、语义时间与源时间
写当前真实语言/源事件的锚点、动作起止和有效阅读用途。先用秒，实际实现再落帧。源时间、作品局部时间、全片时间与预览文件时间分别清楚；短源结束后的接续有明确内容，不隐式冻结或循环。

## 七、实现接口和检查点
说明主要对象/函数如何兑现关键决定，事件和动画是否共用依据；跨作品连续时交最后状态、源时刻、当前文字与声音偏移。列必要的中间帧和连续范围以及具体要看什么，不只给一串时间。

## 八、版本与修订
给原始输入、当前采用稿、实际提交摘要、源码与预览的对应。材料变动造成的焦点、词句、路径、声音或字幕变化由原负责人同步。哪些事项未验证据实记录。
````

````markdown
# 用已认可作品看清“方法—具体设计—实现”的区别

本页根据[时代变化与节目安排案例](../../motion-case-attention-programme/SKILL.md)的原输入、v3固定源码与生产记录编写。文字是本轮教学解释，不是当时模型的原始思考记录，也不证明每条规则有独立因果效果。

## 一、为什么只有栏目不够
“素材出现—花字进入—节目表—放大镜”具有结构，但没有完成主要决定。实际作品多了一条具体内容：观众停留方式变了，熟悉房间容得下暂离，随手划走带来持续节目压力，后面的编排因而有理由出现。

## 二、美术选择怎样从名词变成具体物体
案例的欢迎栏不是抽象“一个UI组件”：灰板400×96工作像素，头像80，凹槽和欢迎字有对应体量；下接图像，上方板面和下方纸条有遮挡。主字与纸条使用真实已登记烟波宋字款，普通字另有黑体。数字只属于这个作品，值得迁移的是“先设计实际字幅、部件比例和共同空间，再实现”，不是所有视频都使用这款字和这组尺寸。

参看[固定源码](../../motion-case-attention-programme/source/Motion.tsx)的 `Programme`、`LetterAct`，以及[实际字体记录](../../motion-case-attention-programme/source/font-bindings.json)。字体文件没有附带；新任务查当前能力目录，不用历史系统字体栈猜测已加载。

## 三、对一个接点写清楚中途
实际事件表：主字在502帧开始退出，压力点505帧触发手机下沉，身份板512帧、图像517帧开始进入，手机528帧退出，564帧前新组已成立。除以30才是本次秒数，不能放到其他帧率任务直接使用。

这不是四项机械顺序：手机尚在退，新组已经建立，声音的同一层意思串住过程。前景词组完成重音后让位，图像无需等前一个物体彻底消失。新作者应该为自己的语义点写出同样清楚的交叠，而不是复制502/505/512。

见[交叠截帧](../../motion-case-attention-programme/assets/keyframes/f0520.jpg)与[事件提取](../../motion-case-attention-programme/source/timing.json)。静帧只证明该状态，动态须看实际视频。

## 四、镜片为什么不是一个独立大字框
`Observer` 内部用同一时刻重新绘制 `Programme`，不包含镜片自己。底层与镜内共享纸面、字体、图像和事件状态；中心变化用连续曲线。这样方法上能保住归属，但是不是好看还要看实际结果。

新内容若不需要局部观察，就不要套镜片；需要时重新算目标字形、倍率和边界。不能把教学里的“216直径、1.42倍率”当作任意文字都能读清的默认值。

## 五、这次提示词没有包办所有正确决定
原输入规定了具体构图与动作，但实际作者仍依据所选图片做椅子轮廓、源坐标裁切与最长纸条的字宽调整。报告记载首个完整预览后修了椅子轮廓，再只改A/B游戏ROI，其余声音和结构保持。

这些实现补充要记录为作者与预览修订，不全部归功于原提示。完整案例能教“怎样根据实际结果修局部”，却不能证明一套全自动无参考主题创作已经稳定。

## 六、迁移到无参考任务的产物
新主题不是写“参照本例”，而是交自己的：内容发展、实际材料、准确台词、美术选择、关键中途、当前声音锚点和前后接口。方法与模板由本 Skill 提供，专业选择仍由同一视觉作者作出并承担检查。
````

### 10.3 字幕代码建议具体落点

已读取并确认相关位置：

- `packages/contracts/src/caption-presentation.ts`：字幕位置与显示范围；
- `packages/remotion-runtime/src/caption-layout.ts`：字宽、显式/自动一至两行及浏览器测量；

````markdown
## 5. 值得迁移的具体设计

### 主体持续，而非页面轮播
`People`、`Opening`、`RealChair`、`Handset` 与 `Programme` 按同一作品时钟存在或退出，前景变化不自动卸载所有参照。是否需要同场持续由新内容决定；明确切镜可以保留，不要求所有东西用遮罩变形。

### 字形与动作一起设计
`LetterAct` 用实际绑定的显示字形，四字固定读序，各自不同时间侧转，最后读成一行。主读语义在原输入中明确，不是从每句摘一个词放大。新稿先确定哪项判断值得强调，再选择字形、尺度和进入方式，不把四字侧转变成所有标题默认。

### 真实视频与局部同源
`LivePage` 把同一直播的游戏和人物裁切接入同一页，两区域依同一根时钟；上划时整页一起更替。源码假设本批视频1280×720并保存具体ROI，迁移时必须用新源实际几何重算，不能把这组坐标称为通用自动跟踪。

### 语义点触发前后交接
本片压力点505帧，新门牌512帧开始、图像517帧开始、手机528帧退出。新旧先交叠，再完成交接，不等一个物体走完再读下一句。这些帧只用于本例查源；迁移时按新声音和任务重排。

### 镜内外来自同一状态
`Observer` 按同一帧复用 `Programme`，镜片取样不递归包含自己。`ReadingPoint` 以连续插值经过本片阅读点。迁移的是归属和时钟方法，不是固定圈径、倍率或五行纸条。

### 有针对性的修订
````

## 12. 如何证明没有参考也能稳定，而不再次自我感觉良好

### 12.1 固定评估环境

每轮记录实际模型/设置中能读到的部分、已安装Skills版本、Runtime releaseId、字体目录、源材料版本、初始输入及最终输出。读取不到的型号或参数保留未知，不补造。

代码main头和实际生产Runtime不是同一个概念。本次视频manifest可以确认 `managed-motion-13`，但小包没有完整生产Runtime releaseId；不能仅凭合并后的main就说成片一定由0.1.70这次构建生成。

### 12.2 三种测试分开

| 测试 | 输入 | 主要回答 |
|---|---|---|
| A 复现能力 | 已有完整指令＋合法可用材料 | 引擎、字体、源时钟与实现是否能兑现设计 |
| B 无外部分镜的设计能力 | 同一个内容问题＋固定材料池，不给目标分镜或参考视频 | 内部团队能否自己写出并实现足够好的演出 |
| C 主题冷启动 | 只给新主题，材料自行搜索 | 研究、选材、文案、美术、动画、声音整条链是否有效 |

A通过不抵扣B，B通过不抵扣C。本次成功主要给了A类证据，且执行任务自己搜索过材料；它仍收到完整外部内容和演出，因此不是严格C类。

### 12.3 先小批筛查，再重复验证

先选三个有不同表达需求的主题，例如实际操作、对象比较、人物/空间过程。每个主题在当前main与候选优化版各跑一次，比较真实成片与执行稿。不要给测试方本应由导演产生的长分镜。

方向正确后，再选若干未参与规则修改的主题，做新窗口重复运行。比较首次用户交付质量、内部实质修订次数、总耗时/调用代价、搜材偏题率、声音/字体/字幕等客观错误，以及用户或独立盲评对内容、美术和节奏的判断。

这是一项分阶段实验计划，不是保证跑几条就能统计证明所有题材稳定。保留未用于调规则的主题，以免只把当前案例换名字。

### 12.4 区分四种失败，才能改到正确地方

| 失败 | 诊断 | 修改方向 |
|---|---|---|
| 文案没有内容发展，素材只题材相关 | 上游创作与选材 | 导演/文案/素材方法，不能靠更多光效修 |
| 内容成立，执行稿只有标签和动作名称 | 具体设计没有完成 | 写法方法、完整案例与采用判断 |
| 演出稿具体且自洽，源码遗漏或错位 | 实现保真 | 原作者、绑定、时钟、字体、局部几何回归 |
| 实现忠实，但看起来仍不好 | 设计本身不成立或跨场组合弱 | 回导演和视觉作者重选构图/动作/节奏，不盲目加字数 |

审美反馈不能全部归成工程缺陷；工程错误也不能都归为提示词不够长。

## 13. 最小实施顺序与本轮建议

### 第一步：固定成功结果和现有能力

保留本次最终输入、源码、视频、实际字体、时间和有限修订记录。将用户新反馈写入案例档案。不要先重跑全部历史案例，也不将最终成片当作参考素材直接进入新作品。

### 第二步：补齐内部创作能力，不重建引擎

局部修共享流程冲突，明确本场实际材料的查看先于具体采用。把完整演出写作作为同一视觉作者的明确职责，配一份有实物依据的完整案例和少量变化示例。

同时在导演和文案里补内容发展，在视觉里补实际美术选择。只补最末端“提示词格式”不足以代替上游的参考文案与剧情。

### 第三步：验证第一次内部生成的执行稿

先检查团队是否真的作出本片的字体、构图、主读、中途动作与交接选择，再生成视频。不要只以“读了新Skill”“返回了JSON”判定完成。

需要关键构图预排时，使用同一源码与实际素材；所有判断在一次生产任务内部完成，用户不用逐镜批准。

### 第四步：补最小代码保真能力

根据测试中的实际缺口决定字幕单行合同、事件选段、完整稿版本恢复和字体协同。每项改动都有对应失败输入与回归，不先开发通用审美平台。

既有 `typecheck`、`test`、Skills同步、插件构建和验证按本机代码执行；本轮只读取其定义，没有执行并声称通过。[S10]

### 第五步：无参考冷启动与保留样本

使用新主题，让系统自主搜材、写稿、作设计与交付；记录成功与失败，区分题材边界。稳定性来自这类重复结果，而不是单个案例的认可或文档篇幅。

## 14. 本轮结论

**要迁移的是“产生具体决定的能力”，而不是这条视频的外壳。**

当前成功样片说明：原项目受管路径与最新能力已经能够承载比普通主题输出复杂得多的声画。问题不能再被简化为“需要换一个渲染引擎”或“再加一种转场”。

优先顺序是：

> 补自主内容发展 → 实际材料参与 → 本片美术与完整演出 → 全文不丢的交接 → 同一作者实现与检查 → 最小工程保真 → 无参考重复验证。

本轮不建议增加一串新代理、重做数据库、给所有影片固定配色、强制每个镜头全幅/有动画，或要求用户补参考与专业分镜。

**这次已认可的样片可以成为第一份完整的、可追溯的训练性案例；它是方法提炼的依据，而不是所有未来题材都应长成它的证明。**
