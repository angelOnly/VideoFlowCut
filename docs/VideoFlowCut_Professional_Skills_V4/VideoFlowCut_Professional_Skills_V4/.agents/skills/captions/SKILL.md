# 字幕、文字层级与强调

> **V4 单文件原则**：本 Skill 已内置完成该任务所需的核心专业知识、案例、失败模式和验证方法。除项目级 `_shared` 合同与 `docs/asr接入.md` 等真正共享资料外，不依赖同目录 `references/`。


## 字幕首先解决可读和理解

字幕的首要职责是让观众可靠知道说了什么，尤其在静音观看、口音、环境噪声和信息密度较高时。它不是逐字复制 ASR 的终端，也不是为了“网感”持续跳动的装饰层。字幕必须基于最终 Script 和 SpeechTiming；上游语义和声音未稳定时，不提前精修。

当前 VideoFlowCut 第一版主要生成稳定 CaptionCard，并只通过 `read_captions` 暴露读取，尚未有完整 `edit_captions` MCP。因此，本 Skill 当前可执行自动生成后的 review，也可以在代码支持的 Application/Web 中调整；不能因为专业计划写得详细，就声称所有 Span、动态样式和逐词强调已经落地。

## Caption Card 是一个阅读单位

字幕分卡不等于标点切分。一个 Card 应让观众一次读懂一个完整短语或思想，同时与自然语音范围大致一致。过短会导致眼睛持续追逐；过长会让观众在人物和文字之间来回寻找。

例如“不是因为我们没有时间，而是因为时间从未真正属于自己”，可以根据语速和画面分成“不是因为我们没有时间”与“而是因为 / 时间从未真正属于自己”。不能把“不是因为”单独留一张，也不能将“时间”与“属于自己”拆开到不同卡，破坏否定和结论。

## 换行承载语义层级

换行应保护短语、数字单位、专名、否定、条件和关系。中文竖屏字幕通常需要较短行，但不能只按字符数硬切。好的换行让眼睛在第二行获得补充或结论；坏的换行把动词和对象、数量和单位、条件和结果分开。

画幅影响排版：竖屏人物居中时，字幕宽度可能较窄；横屏可以更长。不要把横版换行直接复用到竖版。平台底部 UI、安全区和人物手势也会改变字幕位置。

## 强调不是把每个关键词变色

强调应服务信息层级。适合强调的内容包括关键结论、数字、对比词、行动动词和需要记住的专名。强调一个词时要保护完整意义：否定句中只强调“有钱”可能让观众忽略“不是”；数字不能脱离单位；“只有在……时”不能只高亮结果。

动态强调尤其需要时间精度。`segment_exact` 只能可靠支持段级和卡级字幕，不能自动逐词跳动。没有 `word_exact` 时，可选择稳定 Card、手工预览校正的少量词，或完全不做逐词强调。按字符平均时间会产生看似同步、实际错位的假精度。

## 字幕与人物、MG 和证据的竞争

字幕是持续存在的视觉层。人物正在做重要手势、证据需要阅读、全屏图形包含文字时，字幕应减少运动、缩短或在安全时隐藏。不能让大标题、图表标签和字幕同时要求阅读。

人物口播动效丰富时，稳定字幕通常比高动态字幕更专业，因为主视觉变化已经承担注意力。纯人物、画面长期稳定的短段落可以适度增加关键词强调，但也要避免观众只读字幕、不看人物。

## 字幕不应提前泄露

字幕通常跟随声音，而不是提前显示整句。提前展示结论会削弱笑点、转折、悬念和证据揭示。对复杂句可以短暂预读，但要确认它是在帮助阅读，而不是抢先回答当前问题。

## 一个具体案例

人物说：“我后来才发现，真正让我疲惫的，不是工作多，而是每天都不知道自己为什么在做。”这句话的第一张 Card 可以是“我后来才发现”，留给人物表情；第二张“真正让我疲惫的 / 不是工作多”，第三张“而是每天都不知道 / 自己为什么在做”。若在“疲惫”上做大字跳动，会和人物坦白竞争；更好的处理是保持字幕稳定，在最后结论落下时才轻微强调“为什么”。

## 审查方法

有声检查文字是否与实际语音一致；静音检查能否在正常播放速度读完；关闭字幕检查视频是否仍有视觉主线；查看人物、平台 UI、MG 和证据是否碰撞。整片检查字幕卡长度是否过于统一、强调是否重复、是否形成视觉疲劳。

## Caption Card 与语义换行

一个 Caption Card 是观众一次可以完成的阅读任务。分卡要同时考虑语义、语速、画面负载和行长。标点提供候选边界，但转折、否定、数字单位、专名和动宾关系比字符数更重要。

换行的目标不是让两行长度完全相等，而是让阅读顺序清楚。第一行可以建立前提，第二行给结论；也可以让完整名词短语保持在一行。不要把“不是因为”“如果没有”“三十万元”等关系或单位拆散。

卡片持续时间取决于文字量和画面是否还要求观察。证据和复杂视觉段应减少字幕文本；人物稳定段可以承载稍长 Card。若文字无法在合理时间读完，应修改文案或 Scene，而不是无限缩小字体。

## 强调、时间精度和动态字幕

强调应回答“观众此刻最需要记住什么”，而不是把名词、动词和形容词全部换色。每张 Card 一般只需要零到一个主强调，少数对比可有两个。

动态字幕需要真实时间。segment_exact 只证明整段范围，不能自动知道段内某词的落点。没有 word_exact 时，使用稳定 Card、段级进入，或在真实预览中手工校正少量关键事件，并记录这是编辑 Override，不是 ASR 事实。

Kinetic Caption 会与人物嘴型和图形竞争。画面已经高动态时应退让。它适合纯人物、高能短句和明确节奏，不适合证据阅读、个人坦白、复杂解释和全片持续使用。

## 字幕在真实画面中的层级

字幕位置由人物、手势、产品、证据、平台控件和其它文字共同决定。不要只用固定底部安全区思考；某些竖屏平台底部和右侧都有 UI，人物手势也可能进入字幕区域。

文字层级应区分：Caption、章节标题、身份、数据、证据原文、CTA 和 MG 标签。它们不能都使用同一字号、颜色和运动。字幕通常是稳定基础层，重要 MG 临时成为第一注意目标时，字幕应降低对比或减少变化。

多画幅需要重新换行和定位。横版中的两行字幕在竖版可能占据人物身体；竖版大字在横版可能显得空。每个主要规格都要在实际 Composition 中检查。

## 三个字幕案例

### 个人坦白

人物说出自我怀疑，画面和声音是主证据。字幕稳定，少强调，不逐字跳动。停顿处不急于提前显示下一句。

### 软件教程

观众同时看 UI 操作和字幕。字幕缩短为行动要点，避免逐字重复完整旁白；关键按钮名称可强调，但不能遮挡界面。

### 促销口播

数字、产品和 CTA 可以有更强层级。字幕仍负责完整语句，产品名称或数字可由独立 MG 承担，不要在字幕、产品卡和背景数字中重复三次同一信息。

---

## 最终检查

- 字幕来自最终 Script，不来自未经审阅的 ASR 候选。
- Card 是完整阅读单位。
- 换行保护否定、条件、数字单位和专名。
- 时间精度与表现形式相匹配。
- 强调数量克制，有信息理由。
- 不提前泄露关键结论。
- 不与人物、MG、证据和平台 UI 竞争。
- 有声、静音和完整播放均通过。
