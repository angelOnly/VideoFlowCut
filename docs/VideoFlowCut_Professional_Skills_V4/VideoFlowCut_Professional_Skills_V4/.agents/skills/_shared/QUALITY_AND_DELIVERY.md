# 质量、修订和交付

审片至少有四个视角。只听声音时检查语义、停顿、音量、音乐和切口；静音看画面时检查视觉重点、字幕、动效密度和遮挡；完整声画时检查落点与声画关系；首次观众视角检查 Hook、迷失点、承诺和结尾记忆。

问题记录应写可观察证据和观看影响，而不是只写“节奏不好”。例如：“12–17 秒连续三个大字和两次 CameraPunch，同时字幕换卡，观众无法确定先看人物还是结论；建议保留第一次 Punch，后两句稳定人物，验证时静音播放 10–19 秒。”

修订应寻找根因。用户说某处无聊，根因可能是内容重复、问题已经消失、声音没有层级、画面没有变化，或结论没有兑现。机械增加 Effect 只是其中一种候选，通常不是默认答案。

正式导出必须固定 Revision。当前代码尚未把 Editorial Review 作为独立 Delivery Gate 强制执行，因此 `export` Skill 必须主动检查当前 Revision 是否已完成真实审片，避免“文件存在”被描述为“可交付成片”。
