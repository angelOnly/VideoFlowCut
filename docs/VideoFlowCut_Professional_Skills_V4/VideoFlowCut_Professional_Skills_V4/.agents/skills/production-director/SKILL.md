# 整片生产导演

> **V4 单文件原则**：本 Skill 已内置完成该任务所需的核心专业知识、案例、失败模式和验证方法。除项目级 `_shared` 合同与 `docs/asr接入.md` 等真正共享资料外，不依赖同目录 `references/`。


## 这项工作的本质

整片导演的任务不是替每个工种完成细节，而是保证所有工种在同一条片上服务同一个观众体验。项目里可以同时存在转写、声音、人物、Scene、Effect、字幕和导出任务，但只要它们没有共同回答“这条片为什么值得看、观众在结尾获得什么”，系统就只是把多个可运行模块拼在一起。

开始一条片时，先把用户的愿望翻译成可由素材兑现的观众承诺。比如“做得高级一点”不是承诺，“让正在为工作焦虑的人意识到，真正被拖延的不是旅行，而是对时间的所有权”才是。承诺决定哪些句子必须保留，哪些例子只是重复，哪些画面需要人物完成，哪些观点必须用视觉解释，以及结尾怎样回收开头。

导演还要区分事实时间线和观看时间线。原素材中事件发生的顺序、人物当时知道什么、哪个回答属于哪个问题，属于事实时间线；Hook、倒叙、并置和压缩属于观看时间线。观看时间线可以更有力量，但不能制造假因果、假反应或错误归属。

## 先确定主线，再谈包装

不同视频的主线由不同证据驱动。数字人口播和课程主要由完整观点和最终声音驱动；访谈由问题、回答、追问和证据驱动；Vlog 由事件、动作、选择和反应驱动；视觉解释片由旁白中的认知问题和证据关系驱动。选择主线以后，字幕、MG、B-roll、音乐和 SFX 才有可靠锚点。

当前 VideoFlowCut 的正式 Presenter 路径是先明确选择 A-roll，用 `assemble_presenter_track` 建立物理主轨，再由 StoryBeat 和视觉计划通过 `compile_presenter_scenes` 建立叙事 Scene。兼容工具 `create_presenter_timeline` 会按素材数量临时分组，只适合旧客户端和组件测试，不适合正式导演生产。

主线尚未稳定时，不批量生产下游包装。字幕依赖最终 SpeechTiming，MG 和 Cutaway 依赖最终语义位置，音乐依赖成片结构。过早包装会让任何一次内容删改都变成大范围返工，也会诱使 Agent 为了保护已经做好的效果而保留本应删除的内容。

## 如何选择路线

当人物的可信度、表达和情绪本身是主要证据时，使用 Presenter 路线。人物不只是承载台词的背景；脸、目光、呼吸和停顿可能是内容的一部分。此时 `presenter-motion-director` 决定什么时候保持人物，什么时候由 Rear/Front/Actor FX 辅助，什么时候切到 Cutaway 或 Explainer。

当旁白可以独立成立，而观众需要理解分类、比较、流程、数据、文档或系统关系时，使用 Visual Explainer 路线。这里视觉场景承担认知工作，不能把每一句旁白都变成一张标题卡。

当故事隐藏在实拍事件、动作、反应和环境声中时，使用 Vlog 路线。Vlog 不是给一堆生活素材配旁白和模板动效，而是从真实发生的变化中组织经历。

混合视频也必须有主路线。数字人口播中可以插入一个 ExplainerScene，但这不代表人物、解释和 Vlog 三种模式平均分配。模式切换本身是强视觉事件，需要明确进入和返回。

## 导演计划怎样形成

当前代码还没有独立的 DirectorPlanDocument，所以 V3 不会假装有 `manage_director_plan` 工具。实际执行时，导演计划通过 Story、CreativeDecision、quietRanges、effectDecisions 和 ProductionRun 共同表达。计划至少要回答：版本目标、观众承诺、主线、必保内容、可删内容、安静区、视觉与声音意图、不可接受的误读、验收范围和未解决能力。

`start_production_run` 只应登记实际加载的 Skills 和 References。每个高影响决定通过 `record_creative_decision` 保存证据、候选方案、选择理由和验证方法。报告不是为了把所有思考写成长篇日志，而是让用户能看懂为什么这里不加效果、为什么那个素材被拒绝、为什么某个停顿被保留。

## 一个完整例子：哲学口播与促销口播

同样是人物口播，两条片不应得到相同 Effect Plan。

哲学读书口播中，人物说“我以前总觉得，只要再赚多一点钱，我就有资格休息”。若人物低头停顿，观众此刻需要确认的是自我怀疑和真实感。把“钱”做成巨大数字、把“休息”切成海边 B-roll，会把个人反思变成泛化励志。更好的导演计划是保留人物和停顿，让字幕稳定；当下一句从个人经历转入“为什么这种想法永远不会结束”的机制解释时，再切到不断后移的日历或“以后”视觉模型。

促销口播中，人物说“这次送出 70 台平板”。观众任务是理解产品、数量和行动。产品前景、背景数字和 CTA 可以成立，但仍要分阶段：产品在“送出”前预进入，数字在“70 台”落音时稳定，CTA 在行动语句开始时接管。这里高密度是内容价值的表现，不是固定模板。

导演 Skill 的价值就在于让这两条片产生不同方案，而不是证明 11 个 Effect 都能渲染。

## 生产闸门

每个阶段都必须回答自己的问题。转写阶段只证明文字证据可读，不证明 Script 已选好；SpeechAsset 成功只证明语音已生成，不证明表演自然；Timeline 合法只证明结构可播放，不证明画面有效；Preview 成功只证明局部能够合成，不证明整片成立；Export 成功只证明文件生成，不证明可交付。

在主线 Gate，必须只听声音检查语义和结构。在包装 Gate，必须检查注意力、安静区和效果选择。在交付 Gate，必须进行四轮审片，并确认当前 Revision 的 Editorial Review。当前代码没有独立 Delivery 对象，因此 `production-director` 和 `export` 必须主动阻止“未审片但技术成功”的版本被描述成成片完成。

## 修订

用户反馈应绑定他实际看到的 Revision 或导出。时间码只是症状位置，根因可能在更早的 StoryBeat。例如用户说 20 秒无聊，原因可能是 12–18 秒已经重复说完结论，使 20 秒失去问题；在 20 秒加动画不会解决根因。

修订时先保护用户明确满意的内容，再比较保持、最小修复和结构修复。读取 ImpactReport，复核受影响的字幕、Effect、Scene 和声音。若修改改变了节奏或承诺，即使 DirtyRange 很小，也可能需要整片复核。

## 当前执行顺序

执行时通常按以下顺序组织，但不要把顺序当成机械流水线：

1. 定位 Project 和 Revision，创建 ProductionRun。
2. 读取素材、转写、声音、Story、Scene、Timeline 和当前质量证据。
3. 写清观众承诺、主线和必保约束。
4. 路由到相应专业 Skill 完成语义和主线。
5. 主线通过后规划视觉、字幕、Cutaway、声音和 Remotion。
6. 渲染局部 Preview，检查真实合成。
7. 运行四轮审片，修复 blocking 和 major 问题。
8. 固定最终 Revision，导出并验证文件。
9. 完成 ProductionRun，明确仍存在的能力和质量限制。

## 导演计划、故事脊椎与信息账本

导演计划不是待办清单，而是把“为什么这样剪”变成可以持续维护的项目判断。一个好的计划从观众承诺开始，再建立故事脊椎和信息账本。承诺描述观众为什么继续看；故事脊椎描述视频如何检验一个问题、完成一个行动或解释一个机制；信息账本则控制每个节拍何时释放什么信息。

以“金钱与自由”为例，最弱的脊椎是“讲一本书和自由”。更强的脊椎是：“人物一开始相信更多金钱会带来自由，随后发现自己只是把生活不断推迟，最后把自由重新定义为对时间和选择的掌控。”这个脊椎自然产生节拍：原始信念、现实矛盾、反复推迟、认知转折、生活选择和结尾祝愿。

信息账本防止画面提前泄露。若认知转折是“问题不是钱，而是时间不属于自己”，开头不应直接把这句话做成大字，否则中间论证失去问题。开头可以展示“等存够钱、等工作稳定”的不断累积，让观众自己感到推迟；转折时再完成视觉模型。

导演计划还要记录被拒绝方案。拒绝不是为了留痕而留痕，而是防止后续 Agent 重新犯同一错误。例如“海边空镜与自由关键词相关，但会把关于时间控制的论证泛化成旅游情绪，因此只在真正讲到远行体验时使用”。

## 路线选择与混合模式

路线选择看“哪一种证据最有资格支配主时间轴”，而不是看项目里有什么素材。人物视频很多，不一定是 Presenter；旁白很长，不一定是 Explainer；实拍很多，也可能只是 B-roll。

Presenter 路线适合人物的表达、信任和语音结构决定视频。Explainer 适合视觉模型承担理解。Vlog 适合真实事件、动作和反应承担推进。混合模式需要先指定主路线，其他模式只在局部完成主路线做不到的任务。

例如一条数字人口播讲航班退改签，人物负责 Hook、态度和结论；座舱分类与价格关系使用 ExplainerScene；真实机场镜头只用于建立现实经验。这不是三种模式平均混合，而是 Presenter 主线、Explainer 解释、B-roll 具体化。

模式切换应有进入理由和返回理由。全屏解释结束后，人物回来时应带着新的结论或反应，而不是重复刚才的画面内容。若解释场景结束后没有新的语言作用，说明这段可能应继续保持全屏，或原解释场景过长。

## 完整案例：哲学口播与促销口播

### 哲学读书口播

脚本从“如果不用急着成为谁，今天最想怎样度过”开始，随后讲金钱、工作和不断推迟的以后。这条片的承诺是让观众重新理解“快乐为什么总被推迟”。人物的语气、停顿和直视镜头承担信任，因此开头不应每句话切画面。

第一段只使用稳定人物和问题文字。提到书名时可以短暂展示书籍，但书籍不是主角。讲“先有金钱，才有资格谈自由”时，若只做左右两个词，会像演示文稿；更有效的是让工作、存款和日历逐层占据空间，再让“自由”始终后移。讲到“陌生的城市和海”时可以使用现实 B-roll，因为语言已经从论证进入具体体验。结尾回到人物，音乐减弱，给祝愿和停顿留下余韵。

这条片的专业决定包括大量“不加”：不在“钱”上使用计数器，不在“自由”上随便使用海边，不用 CommentCloud，不用 Meme，不全程动态字幕。

### 促销人物口播

人物宣布粉丝里程碑、奖品数量、参与方式和后续作品。观众任务不断变化：先理解里程碑，再识别产品和数量，然后完成行动，最后接受作品预告。

大数字可以在人物后方建立规模；产品可以在前景展开；CTA 箭头在完整行动语句期间保持；历史封面墙在“做了这么多节目”时出现；评论云只在讲评论生态时使用；笑点后短暂 FullScreenMeme；结尾用 DeviceShowcase 和 EndCard。

这里高密度合理，但仍需要恢复段。人物感谢观众时应减少效果，让关系重新成为主证据。若所有效果连续出现，CTA 和作品预告都不会再显得重要。

### 对比结论

两条片使用同一套技术内核，但承诺、主线和观众任务不同。一个专业 Skill 应让最终 Treatment 明显不同；若两条片都机械使用 11 种效果，说明系统只在展示组件，不在导演视频。

## 停止条件

当承诺无法由素材兑现、事实冲突未解决、用户硬约束互斥、关键素材权利未知、当前能力只能做计划、Preview 无法验证，或当前 Revision 与用户反馈基线不一致时，停止受影响流程。说明已经完成什么、缺少什么证据、最小下一步是什么，不用包装掩盖问题。

## 最终检查

- 这条片有一句可兑现的观众承诺。
- 主线由正确类型的证据驱动。
- Story 和声音先于包装稳定。
- 每个强效果都有观众任务，安静区也有理由。
- ProductionRun 记录了实际判断而不是套话。
- 真实画面、真实声音和整片都被检查。
- 当前 Revision 没有 blocking 问题。
- 导出的文件对应被审片的 Revision。
