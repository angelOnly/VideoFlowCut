# 人物前后景与空间合成

> **V4 单文件原则**：本 Skill 已内置完成该任务所需的核心专业知识、案例、失败模式和验证方法。除项目级 `_shared` 合同与 `docs/asr接入.md` 等真正共享资料外，不依赖同目录 `references/`。


## 层级不是轨道顺序，而是意义关系

Rear、Actor 和 Front 不只是三个技术层。后景信息属于人物所处的环境，前景对象像被人物展示或与人物共同存在，全屏画面则暂时接管观众的认知模型。选错层级，即使没有遮挡，也会显得不可信。

背景大数字适合表达人物身后的规模；产品放前景适合展示对象；完整 UI 和证据需要全屏；CameraPunch 直接改变人物关系。不要为了“空间感”把任何文字放人物后面。

## 先保护人物和证据

眼睛、嘴、关键表情、重要手势、产品、证据文字、字幕和平台 UI 是受保护区域。人物正在直视镜头做承诺时，任何穿过脸的对象都会破坏关系；观众正在读法规时，人物和动效都应退让。

空间规划先决定第一注意目标，再安排第二重点和稳定层。多个大对象同时运动，会使每一项都失去层级。

## Mask 决定能否做真正前后景

有稳定 Alpha 时，可以让人物遮挡背景文字和对象；无 Mask 时，所谓 Rear FX 只是普通 Overlay。专业降级应改变视觉方案：把信息移到左右安全区、减少穿插、改成全屏，或不使用。不能只加一条 warning，画面仍继续失败。

Mask 审查要看头发、手指、快速动作、半透明、帧率和时间同步。边缘在静态帧看起来可用，连续播放仍可能闪烁。

## SpatialAnchor 的当前边界

代码支持 top_left、middle_right 等逻辑锚点，但尚未拥有自动姿态和手部锚点。Skill 可以根据真实帧选择安全位置，不能声称产品已经绑定人物双手。未来姿态能力接入后，逻辑锚点应由 MotionLayoutCompiler 转换为实际坐标。

## 多画幅

横版改竖版不是中心裁切。人物尺寸、负空间、字幕、产品和路径都可能需要重排。竖屏常有更少横向空间，前景产品和人物容易竞争；横屏可利用左右关系，但字幕行长和观看距离不同。若当前代码只有一套布局，应明确优先平台，并在另一个画幅生成独立版本计划。

## 完整案例

人物居中讲“70 台平板”，双手位于胸前。若有可靠 Mask，可以把数字放后景、产品在双手下方前景展开，字幕保持底部安全区。若无 Mask，把数字移到人物右上安全区，产品改成短全屏 Cutaway。继续使用后景会让数字穿过身体，技术上渲染成功但空间失败。

## 人物、字幕与证据的保护顺序

保护不是简单留出矩形。人物眼睛和嘴的优先级高于肩膀，关键手势的优先级高于普通手部动作，证据中的限定条件高于装饰。构图应让第一重点拥有尺寸、对比和运动优势，次要层保持稳定。

---

## 前后景语义与 Mask 降级

后景适合环境和规模，前景适合对象和行动，全屏适合阅读和认知接管。无 Mask 时，背景信息不再拥有真实深度，应改成安全区或全屏。降级是重新选择形式，不是只降低透明度。

---

## 横竖画幅重排

9:16 中人物常占据更大比例，左右安全区更小；16:9 可以建立人物与对象并置。字幕行长、平台 UI 和观看距离也不同。每种画幅单独检查稳定帧和运动路径，不能机械缩放。

---

## 完整推演：人物坦白和前景证据为什么不能同时抢中心

人物正在讲自己过去的错误判断，脸和停顿承担信任；同时台词提到一张旧账单。若立刻把账单以大尺寸盖在人物胸前，虽然素材“相关”，却会让观众从确认人物态度转向阅读证据，情绪表达被截断。更合理的处理可能是先让人物完成坦白，在下一句从个人经历转入事实说明时，再把账单作为 Fullscreen Evidence 展示。

如果确实需要人物与账单同屏，账单应进入人物视线和字幕之外的安全区，尺寸只承担“存在这份证据”的任务，而不是要求完整阅读。需要阅读时再切换全屏。前景、后景和全屏不是装饰位置，而是不同的认知承诺。

---

## 最终检查

- 第一注意目标明确。
- 脸、嘴、手、证据和字幕安全。
- 层级与内容关系一致。
- Mask 经过连续播放检查。
- 无 Mask 时视觉方案真正降级。
- 空间锚点没有超出当前能力。
- 目标画幅单独验证。
