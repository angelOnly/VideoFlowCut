# Presenter / Talking-head 动效导演

> **V4 单文件原则**：本 Skill 已内置完成该任务所需的核心专业知识、案例、失败模式和验证方法。除项目级 `_shared` 合同与 `docs/asr接入.md` 等真正共享资料外，不依赖同目录 `references/`。


## 人物不是一块等待被装饰的背景

人物口播的核心优势是关系。观众通过脸、目光、语气、停顿和手势判断这个人是否可信、是否在思考、是否真的相信自己说的话。因此，Presenter 视频的第一个问题不是“多久加一次效果”，而是“此刻人物本身是否已经是最有价值的画面”。

当人物讲个人经历、承认失败、表达犹豫或做重要承诺时，人物通常是主证据。即使台词中出现数字、地点或抽象词，也不应自动切 B-roll 或大字。视觉包装会替观众规定感受，可能削弱真实感。只有当语言从人物态度转入机制解释、事实证明、产品展示或行动指引时，视觉中心才适合离开人物。

## 上游必须稳定

Presenter 动效依赖最终声音和主线。先用 `semantic-continuity` 确认观众听到什么，再确定人物原声还是 OmniVoice Dialogue。当前正式执行先 `assemble_presenter_track`，再根据 StoryBeat 和时间范围 `compile_presenter_scenes`。若 Script 或 SpeechAsset 仍在变化，不批量建立 EffectCue 和 Caption。

ActorPerformance 必须明确 audioMode。人物视频自带最终声音时使用 source audio；使用 OmniVoice 时 Actor 视频应静音并由 Dialogue 播放；纯视觉人物则 muted。双重人声是 blocking 问题。

## AttentionCurve 不是效果数量曲线

AttentionCurve 表示观众感知到的视觉和听觉强度。安静人物、轻处理、中处理和高处理之间应有结构。高强度不是“每三秒一次”，而是内容价值真正上升：里程碑、产品数量、笑点、证据揭示、重大认知转折或 CTA。

哲学口播可以长期保持人物和稳定字幕，在一个认知转折处进入全屏解释；促销口播可以在开场连续使用数字、产品和 CTA，但感谢观众时应降密度。没有恢复段，高强度就失去意义。

## 四种视觉位置的认知差异

Rear FX 让信息处于人物环境中，适合规模、状态、评论和氛围。它依赖可靠 Mask；无 Mask 时不能假装文字真的在人物身后，应降级到安全区 Overlay。

Front FX 是人物面前的对象，适合产品、证据和 CTA。它需要空间支撑关系，不能像随机贴纸；若人物正在做关键手势，产品和手势的先后、方向和遮挡必须协调。

Actor FX 直接改变人物构图，例如短 Punch 或喜剧反应。它会强烈影响信任，应短促、有落点，不长期 Zoom 或震动。

Cutaway/Fullscreen 暂时改变主视觉模型，适合完整阅读、复杂解释、UI、B-roll 和证据。它不是“大一点的卡片”，需要进入理由和返回人物的连接。

## 人物表演和动效联合规划

同一句“这次送出 70 台平板”，如果人物双手展开，产品可以从手势区域出现；若人物双手始终不动，强行让产品从手里飞出会显得假。当前代码还没有自动姿态锚点，所以 Skill 只能通过真实帧选择 top_left 等已有 spatialAnchor，或在 plan 模式记录未来手势需求。不能因数据结构有 spatialAnchor 就假装完成姿态级互动。

规划重要 Beat 时同时写：人物情绪、目光、手势、主视觉、语义锚点、进入、稳定、退出和降级。这样表演与图形不会成为两个互不知情的系统。

## 一个完整案例：个人坦白转入机制解释

人物说：“我以前总觉得，只要再赚多一点钱，我就有资格休息。”画面中人物低头，语速下降，句尾停顿。此时不应该在“钱”上出现计数器，也不应在“休息”上切海边。观众正在确认人物的自我怀疑，脸、声音和停顿是主证据。保持人物，字幕稳定，音乐减弱。

下一句：“但这种想法最可怕的地方，是‘以后’会不断往后退。”观众任务从相信人物转为理解机制。可以让人物仍留在画面前几帧，随后切到全屏 Scene：日历、工作、存款和“以后”不断后移。解释结束后人物回来，说“后来我开始问自己，今天能不能先活一点”，这时人物重新承担结论和关系。

这个切换不是为了防止画面单调，而是因为观众任务发生了变化。

## Effect 选择

MetricBackdrop 适合需要记住规模的数字，不适合任何数字。ProductFan 需要真实产品 Asset 和展示任务。CommentCloud 需要真实评论语境。EvidenceCard 需要真实证据。FullScreenMeme 只在真实笑点后短促使用。DeviceShowcase 需要观众理解 UI 或账号，不是装饰。没有实际 Asset 和叙事目的时，不使用对应 Effect。

## 字幕与声音

人物动效丰富时，字幕应稳定。逐字跳动会与人物嘴型和图形竞争。只有画面长期简单、时间精度可靠、且关键词强调确有阅读价值时，才使用有限动态强调。

声音上，Dialogue 是主 Anchor；SFX 绑定视觉事件，不能每次入场都“叮”；BGM 在重要坦白和证据阅读时退让。Cutaway 可通过 L-cut 保持人物关系。笑点音效在包袱后，而不是提前告诉观众应该笑。

## 真实审片

局部检查每个 Effect 的 Before、Motion、Settled 和 Exit。整片静音看视觉密度，确认不是所有段都在动；只听声音确认视觉没有掩盖结构问题；完整声画检查落点；首次观众检查 Hook 和结尾。

## 人物信任、注意力和安静区

安静区不是缺少设计，而是把注意力还给人物、证据或观众思考。当人物承认自己曾经错误、做价值判断或直接请求行动时，持续动画会稀释关系。人物直视、呼吸和停顿可能比任何 MG 更能建立信任。

高密度段之后需要恢复，不只是为了视觉舒服，也为了让下一次强变化重新具有意义。若开场连续使用数字、产品和 CTA，感谢段可以只保留人物和稳定字幕；若一段复杂 Explainer 刚结束，人物回到画面时先给一个简短反应，不立刻再放图形。

## 人物前后景与 Cutaway 的完整选择

同一信息有多种视觉位置。背景数字适合表达规模，同时保持人物关系；前景产品适合展示对象；全屏页面适合需要阅读；人物自身 Punch 适合强调表情和包袱。

选择位置时问：观众是否仍需要看人物，信息是否需要完整阅读，是否有可靠 Mask，人物是否在做关键手势，字幕是否占据下方，下一拍如何返回。没有可靠 Mask 时，Rear FX 应降级，不把普通 Overlay 称为人物后景。

Cutaway 的长度应覆盖识别、理解和返回，而不是固定两秒。复杂 UI 需要更长；一个简单海边情绪镜头可以短，但仍要有具体作用。

## 两条 Presenter 的完整对照

### 哲学口播

核心是自我反思和认知变化。人物长期保持；字幕稳定；书籍和城市海边只在具体提及时出现；“以后不断后退”使用一个完整 ExplainerScene；不使用产品、评论云和 Meme。音乐低强度，结尾给停顿。

### 促销口播

核心是里程碑、产品、数量、参与和作品预告。开场背景数字建立规模；产品前景展开；数量落音完成；CTA 接管；作品墙和评论云在对应内容中出现；笑点后短 Meme；感谢段恢复人物；结尾 DeviceShowcase 和 EndCard。

差异来自观众任务，不来自“一个要高级、一个要网感”的抽象标签。

## Presenter 真实审片

只听声音时确认语言像一个人连续说出，而不是片段拼接。静音看画面时观察人物是否仍是锚点、效果密度是否有层级、字幕是否疲劳。完整声画时检查每个效果是否在语义落点而不是仅在时间上“差不多”。首次观众视角则检查前三秒是否建立问题、什么时候迷失、结尾记住什么。

模式专项审查还要问：若禁用所有效果，这条片是否仍成立；若不成立，问题是主线还是视觉解释缺失。只有主线成立、包装增加了明确价值，Presenter 才不是组件展台。

## 当前工具与边界

使用 `assemble_presenter_track`、`compile_presenter_scenes`、`manage_actor_performance`、`manage_effect_cues`、`render_preview_range` 和 `inspect_composed_frames`。当前没有自动 Avatar Provider、姿态锚点、完整 B-roll 自动放置和全功能音频混音。缺失能力时输出计划或使用现有安全降级，不报告已经执行。

## 最终检查

- 人物在需要信任和情绪时保持主视觉。
- StoryBeat 与 PresenterScene 有真实关系。
- audioMode 明确且无双声。
- AttentionCurve 有安静区和恢复。
- 强 Effect 只服务重要事件。
- 需要真实素材的 Effect 已绑定真实 Asset。
- 人物、字幕、图形和 Cutaway 不争夺第一注意。
- 四轮审片和当前 Revision Editorial Review 已完成。
