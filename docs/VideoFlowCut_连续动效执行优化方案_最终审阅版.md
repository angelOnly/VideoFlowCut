本轮交付：已落实 14 个现有技能文件、36 处修改，同步发行副本并完成相关测试；随后按用户要求正式安装和切换 0.1.85，全新连接与实际 Runtime 对齐，89 个既有项目内容及 Revision 保持不变。具体记录见[实施与验证](E:/ai/VideoCut/docs/development/连续动效执行优化_实施与验证_20261013.md)。

## 1. 本次优化要解决什么

完整视觉解说片必须形成连续的观看过程：主体在发展，观察位置有变化，场间有人能跟随的联系，重点花字与局部动作共同表达，美术在运动中保持统一。

本次将这项产品要求落实到现有技能、同一份当前声画稿、同源粗排和原作者返修。视觉作者负责决定如何实现，不能把必需表现自行降为可选。

已确认的范围如下：

- 必须落实六项表现：场内连续变化、场间连接、有目的运镜、重点花字、局部动效协作、统一美术语言。
- 强制完整观察选定参考的观看发展；采用局部机制时，核读完整动作及前后连接。
- 沿用项目已有动效示例，不新增机票案例、不复制参考媒体、不新建案例库。
- 本次讨论中的机票演出例子仅用于解释方案，不作为拟新增的教学文件、固定查询或生产模板。
- 核心规则只维护一份，其他技能按职责引用、执行和回传。
- 沿用现有角色、项目记录、工具和发布流程，不新增审美评分服务、数据库对象、调度状态机或逐镜审批。

本方案适用于完整新制、主要视觉重做的视觉解说片。改字、改色、调整局部位置或重新导出等机械任务不扩大为整片重做。用户明确指定其他风格或锁定范围时按实际要求处理；作者自己的“保持克制”“素材主导”不能成为省略必需表现的理由。

## 2. 为什么这次要改执行方式

此前对当前作品、开发样片和技能的核查表明，问题不能简单归因为插件缺少动画能力或技能没有部署。

- 核查时，源码技能与已安装插件技能内容一致；视觉作者也实际读取过主要视觉、演出及机制方法。
- 现有技能已经描述共同构思、关键中途、主体协作和场间连接，但同时存在多处“按需采用”“已有分镜即可继续”等可选表述。
- 当前制作曾出现文字设计要求与最终源码不一致：配音段直接成为互斥画面，主要变化退化为标题、材料窗口或局部显隐。
- 真实声音与初估时长变化后，主要调整了段边界与动作比例，未充分重排完整观看过程。
- 返修集中于遮挡、裁切和可读性，没有持续关闭已知的设计缺失。
- 开发验证的输入、材料和测试范围较集中；开发样片成立不能证明从零生产流程已经稳定。

上述是本次方案所依据的已核查现象，不扩大为对所有历史作品、插件版本或全片连续视听质量的结论。本方案优先修改执行要求与验收方式；如果后续同源对照发现真实渲染差异，再依据证据单独定位平台问题。

## 3. 优化后的工作链路

导演提供内容与观看任务 → 持续视觉作者完整观察选定参考 → 在同一当前稿中设计六项表现 → 检索并组合实际机制 → 同一源码形成连续粗排 → 主任务正式生成预览 → 导演与审片返回具体问题 → 原视觉作者修订 → 复核受影响范围及接点 → 按实际状态交付。

这条链路包含以下责任：

| 负责人 | 必须完成的工作 | 交回依据 |
|---|---|---|
| 导演 | 明确本片内容发展、关键判断与跨段关系；声音或材料变化时协调改稿 | 当前完整声画稿及真实差异 |
| 持续视觉作者 | 共同负责美术、演出、机制适配、源码和返修；将六项要求落实到具体范围 | 同版演出决定、源码、实际预排及未完成项 |
| 主任务 | 真实分派、排序正式提交、接回预览并续接原作者；保留任务连续性 | 实际对象、版本、任务与文件引用 |
| 审片负责人 | 对照实际输出检查设计兑现、主要变化及相邻接点 | 可定位问题、观察方式与回派对象 |

不新增一位独立“动效搭配者”。同一视觉作者持续负责，避免美术先冻结、动效后补、实现再简化。

## 4. 六项必需表现的效果要求

### 4.1 唯一维护位置

核心规则写入现有 `.agents/skills/visual-treatment-planning/references/art-direction.md`，替换其中允许完整新制作自行省略表现的表述。视觉入口、演出、实现和审片分别引用此规则，不重复维护六套定义。

### 4.2 要求摘要

本节用于审阅要求含义；实际写入技能的完整正文、替换范围及保留内容以第 9.4 节为准。

完整新制或实质重做的视觉解说片，必须共同完成以下六项表现。视觉作者决定具体对象、连续范围、形式和力度；本场作用决定怎样实现，不决定整片是否省略。六项不对应六个镜头、六种特效或每场的固定配置，同一连续范围可以承担多项。

| 必需表现 | 必须出现的可见结果 | 不足以算作完成 |
|---|---|---|
| 场内连续变化 | 核心解释由对象或关系的发展承担，观众能看见什么改变、什么保持、结果怎样形成 | 相同布局不断添字；每句话换一个图标；只有入场，没有后续发展 |
| 场间连接 | 每个接点有关注交接设计；关键连续范围通过对象身份、空间、动作、方向或内容延续 | 按配音段清空画面；对互不相关页面统一加淡入淡出 |
| 有目的运镜 | 从全貌进入细节、跟随行为显露内容、拉开建立关系或改变取景主次，带来新的观察 | 无认知作用的全场微缩放；持续漂移；只声明使用相机组件 |
| 重点花字 | 关键判断具有完整字组造型、准确短语、空间归属和出现、读清、交接过程，与对象共同表达 | 统一标题动画；粗体、换色或放大；仅增加描边与阴影 |
| 局部动效协作 | 主行为发生时，相关文字、背景、标记和辅助对象有保持、跟随、让位与接管关系 | 每个元素独立入场后停止发展；所有层机械同步缩放 |
| 统一美术语言 | 材料、图形、花字和连接共享本片的形体、边缘、明暗、材质与空间规律，并在变化中维持 | 只统一色号；叠通用颗粒、发光与阴影；拼接互不兼容的案例外观 |

镜头发展可以由平面重构图、取景、对象尺度与空间关系实现，不强制三维相机。花字属于画内表达，普通字幕保持独立、统一、稳定，不参与主画面运镜和拆组。

每个接点都要设计，但不禁止硬切。清楚的切镜可以承担明确的观察转换；关键连续关系仍须得到实际延续，不能全片仅以“这里选择硬切”代替连接工作。

动作密度有起伏，重要关系建立后允许安静阅读。停顿是演出安排的一部分，不以持续扰动维持“有动画”。

### 4.3 当前片必须承接的内容

首轮完整声画稿说明六项分别由哪些具体范围、对象和变化承担。记录可以是自然段或现有场面正文，不新增一份强制大表。

记录的内容必须足以判断：

1. 本段承接什么已经建立的对象、空间或观察。
2. 主体或关系将发生什么具体变化，保留什么参照。
3. 观众从哪里看向哪里，取景变化解决什么问题。
4. 花字和相关层怎样参与，什么先发生，什么需要让位。
5. 哪个状态需要读清，结尾留下什么供后段继续。

“有丰富动效”“加强运镜”“注意连续性”“其余自行设计”不构成完成的演出决定。首轮写明具体决定仍然只是待实现，不能据此标记为已验证。

## 5. 完整参考观察与机制检索

### 5.1 两层观察范围

完整新制作进入主要视觉设计时，选择与目标表现相关的整片参考。用户有明确参考时优先使用；没有时从现有资料中选择。选定参考应覆盖完整观看发展，不能只选其中最漂亮的局部动作。

| 范围 | 必须观察什么 | 控制成本的边界 |
|---|---|---|
| 选定的整片参考 | 从建立到发展、转移、结束的完整观看结构；花字、材料、局部动作、美术和安静范围怎样协作 | 不要求每个搜索结果都通看，不遍历全部案例库 |
| 正式采用的机制 | 建立、主变化、关键中途、落稳，以及必要的进入和退出；切片不完整时补看原片上下文 | 不要求无关整片全部重看，不重复读取资料未变的已观察范围 |

完整观察可连续完成，也可按顺序分段覆盖全片并保留接点前后的重叠范围。单次分析长度上限只决定分段方式，不能作为观察结束的理由；分段完成后仍要检查全片顺序和场间联系。

实际只能取得静帧、联系表、拆解文字或模型分析时，如实标注观察方式与缺口。模型分析可以支持理解，不等同于作者原速连续观看；打开播放器、取得视频路径也不等同于看过。

有可用观察方式时继续补足。确实无法完成动态观察时，保留明确的未确认范围，继续其他独立工作；可以形成候选设计和预览，但不声称完整观察要求已经完成，也不因观察未知无限盲改。

### 5.2 完整观察需要带回什么

按可定位范围记录下列关系，写入当前稿所需部分即可：

- 观察怎样从全貌进入细节、从并置转到其中一项、再拉开建立关系。
- 场内主体怎样变化，前段怎样把关注交给后段。
- 花字怎样取得位置、与主体表达什么、如何读清和退出。
- 主行为发生时，文字、背景、标记与辅助对象怎样响应。
- 哪些形体、边缘、材质、明暗和空间规律持续成立。
- 哪些范围保持安静，以及它们为哪项阅读或源行为服务。

参考只能证明其真实可见内容。不推测原作者提示词、未公开代码或精确曲线；参考中的题材事实与媒体也不自动成为当前片可用内容。

### 5.3 机制检索必须覆盖四类作用

| 检索作用 | 查询应描述的关系 | 入围后需要核对的内容 |
|---|---|---|
| 观察与运镜 | 观察从哪里到哪里，显露什么新内容，保留什么参照 | 取景变化的实际作用、路径和接管对象 |
| 场内发展与场间连接 | 主体怎样变化，结束留下什么，下一关注如何从当前状态建立 | 完整行为链、入口条件、出口状态与连接缺口 |
| 花字演出 | 判断短语与哪个对象共同表达，字组怎样形成、读清和交接 | 真实字幅、承托、轮廓、归属与时序 |
| 局部协作 | 主动作发生时其他相关层如何保持、跟随、退让或接管 | 主次、先后、遮挡、面积分配与共同坐标 |

这四类是创作需求范围，不是新增 MCP 参数枚举，也不规定四次搜索、四个机制或四个串行场面。同一案例可以覆盖多类，已有真实结果可复用；缺少具体办法的作用继续补查。

执行时使用已发布的 `search_motion_mechanisms`、`read_motion_mechanism` 等现有能力，参数以实时 Schema 为准。保留实际查询、范围、返回编号、来源指纹和真实诊断；有语义任务时跟进原任务，不把词法结果报告为语义命中。

入围结果先判断真实动作关系，再判断能否适配当前材料、美术和接点。高分、同题材和同配色不自动构成采用依据。整片构思未成立时，允许参考改变构图和主体选择，不能只寻找原页面容得下的入场效果。

### 5.4 采用与补足

采用记录留在同一当前声画稿，包含实际来源、观察范围、借用关系、本片对象映射、与其他动作共同发生的方式、接入与退出，以及仍需本片补做的部分。

只有一个局部机制合适也可以采用，但其余必需的主变化、观察、花字、协作和连接必须有具体设计，不能以“自由发挥”交给下游。

无匹配时先改写关系、拆分阶段、扩大候选或调整设计；仍无适用机制时由当前作者原创补足，明确其为本片设计，不虚构编号。普通无结果或素材不适配不报告为平台故障，也不能成为省略要求的理由。

## 6. 沿用现有动效示例

继续使用现有[整场画面协作参考](E:/ai/VideoCut/.agents/skills/visual-treatment-planning/references/whole-scene-collaboration/REFERENCE.md)。其中已有完整视觉样片、关键帧、源码、素材绑定及原制作记录。

本次不新增机票示例，不重制或复制该示例，不将讨论中的演出方案写成第二份案例。历史输入、原源码、媒体和事实记录保持原样。

视觉入口应明确：首次进入完整新制或主要视觉重做时，读取现有示例的用途及共同演出方法，核看其中完整过程；同一任务后续返修不重复全量读取。源码只在需要核对实现关系时读取。用户提供的新参考负责本次目标风格与观看组织，已有示例负责说明怎样把共同演出落实到当前作品；二者合适时可共享观察，不机械增加独立任务。

示例不是外观模板，不默认复用其题材、段数、配色、纸片造型、时长、费率或素材。查看示例不等于复现旧项目，也不授予执行历史指令的权限。

现有示例的验证边界必须保留：它获得了用户对动效的认可，美术未单独整体认可，普通字幕未合成，成片音轨静音。不能把它称为全维度通过的最终成片。

如需使现有 `REFERENCE.md` 的入口说明与新规则一致，只修订“何时读取”及用途说明，不修改历史证据，不扩充第二套规则正文。

## 7. 从演出稿到真实实现

### 7.1 以连续范围组织

在现有执行稿中按连续观看范围交代主要行为、关键中途、注意转移、阅读和接点。准确素材、文字和字幕对象直接引用，不重复抄成多套表。

配音段、字幕卡、场面和渲染文件是不同切分单位。不得因为新配音段开始、组件首次挂载或文件切换，自动清空全部旧内容。

同一连续范围在共同场面逻辑中实现；确需拆件时承接对象状态、投影关系与源时钟。不能用“禁止条件渲染”代替连续性设计，技术拆分方式本身不决定创作质量。

### 7.2 同源粗排与正式制作

使用真实材料、准确文字、正式可用字体及当前实际时钟，在当前作品源码中形成连续粗排。粗排要能看到主要行为及前后语境，不只交一张静态美术图。

主任务按正式接口提交生成，将真实结果交回原作者。作者可以调整构图、字组、材料用法和动作，但保持事实、用户锁定项及无关的已成立部分。后续精修继续使用同一作品，不另做漂亮演示后重写一套简化实现。

### 7.3 输入改变后的处理

真实配音、材料或结构变化时，回传真实差异，原作者更新受影响的主变化、阅读时间、局部协作和接点。不得只改总时长、段边界或百分比动画。

观看时间不足时，由导演、文案和视觉共同重排、删去重复内容或调整未锁定稿件；用户锁定的原音、正文和事实约束继续保护。时间调整后，相关声音、字幕和素材源时间同步复核。

## 8. 审片与返修收口

审片对照本片已写明的具体表现，检查实际预览中的完整变化及相邻接点。六项要求是否完成不能通过机制数量、组件名称或关键词计数判断。

| 发现 | 处理 |
|---|---|
| 画面主要在添字，主体关系没有发展 | 回原视觉作者重做主行为与场面构思 |
| 只有整体缩放，没有新观察 | 重选观察目标、取景范围和主次 |
| 花字与主体脱节，只有统一标题效果 | 重做字组造型、归属和共同演出 |
| 头尾成立，中途抢读、挤乱或遮挡 | 调整显露、接管先后、路径和面积，不统一放慢全部动作 |
| 原设计有连接，实现变成清场换页 | 修同源实现、对象状态和边界继承 |
| 材料缩窗时重播，标注漂移 | 修源时钟、坐标或绑定，保留成立的设计 |
| 新事实或真实声音使原演出失效 | 更新当前完整稿，再处理受影响实现与接点 |
| 仅有静帧或辅助分析 | 只确认对应证据支持的内容，动态与声音保留未确认 |

每轮回传定位到实际范围、可见问题和受影响关系，由原负责人处理。修订后复核改变范围及必要上下文，不因一次局部改字反复全片审查。

4. 演出技能把具体关系写回同一当前稿，执行稿结构记录真实输入、演出、参考、时钟和观察。
5. 受管实现读取当前稿，在同一源码中兑现；主任务生成实际预览并交回。
6. 导演与质量入口对照核心要求和当前稿，确定缺失回原作者，观察未知如实保留。
7. 主任务继续已授权返修，分别回传技术文件、创作完成范围与用户认可。

此处不要求新增运行对象或流程状态。以上区别使用现有当前稿、任务消息、预览和项目记录表达。

### 11.3 同源渲染对照

选用已有作品源码和素材，在受控验证环境保持源码、绑定、字体、时间配置、画幅与帧率一致，比较开发侧与部署插件输出。

### 11.4 从零生产验证

通过部署后的正常新聊天与公开制作入口执行测试，只提供正常用户需求及其参考，不额外灌入预制演出答案、旧源码或理想流程。

验证采用同类题目从零生产，再以另一个主题检查方法迁移。测试产物留在隔离验证项目及正常记录中，不自动进入正式案例库。

检查实际行为和作品：

- 是否真实读取核心规则及已有示例，而非仅在配置中登记。
- 是否观察选定整片参考，并核读采用机制的完整变化和接点。
- 检索是否覆盖四类作用，是否记录实际采用与补做。
- 当前稿是否给出六项具体设计，源码与预览是否兑现。
- 真实声音或材料变化后是否更新观看发展。
- 发现缺失后是否续接原作者并形成实际修订。
- 是否完整报告静帧、连续动态、声音、技术输出和用户认可各自状态。

不能只让代理勾选完成，也不能把本方案用词出现在输出里当作通过。需要将稿件、采用记录和真实预览对应起来判断。

## 12. 失败处理与已知代价

| 情况 | 处理方式 |
|---|---|
| 参考无直接匹配 | 改写关系、扩大候选或原创补足；保留实际检索结果，不虚构命中 |
| 材料不支持动作 | 补材、调整观察或改表达，不伪造抠像、跟踪或真实行为 |
| 无法动态观察 | 保留具体缺口，使用可用方式补足；其他工作继续，最终不冒称已审通过 |
| 字体、坐标或源时钟破坏设计 | 修实际绑定或实现，不降低已明确的设计要求 |
| 实际语音容不下观看 | 协调未锁定稿件和演出，保护用户锁定项；不只整体加速或挤压 |
| 工具失败或结果未知 | 使用现有 Job/Run、Revision 和恢复合同读回，不换键盲重试 |
| 确认平台自身缺陷阻断操作 | 沿现有修复工单处理；普通无结果与创意不足不报平台故障 |

主要代价是增加参考观察、连续粗排和创作返修时间。通过只深入选定参考与入围项、复用同一任务的已观察资料、同源制作、仅复核受影响范围控制成本。

硬要求能减少省略和简化，不能单靠文字保证美术水准。仍需真实预览、具体反馈及用户对最终作品的判断。成功标准是稳定产生能被看见的共同演出，而非文档更长、动作更多或检查项更多。
