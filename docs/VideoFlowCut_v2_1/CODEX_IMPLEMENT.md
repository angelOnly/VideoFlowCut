# Codex 开发执行说明

本文件用于用户批准本方案后的**项目接入开发**，不是让你制作一条测试视频。完整分析与实际修改文字已在本包写好；读取`实施方案_v2_1.md`，不需要从历史聊天重新提炼。它保留V1分析并逐章接入V2载荷，不是单独的文件清单。

## 1. 确认工作范围

读取当前仓库AGENTS.md和开发规则，确认仓库根路径、未提交改动、实际发行方式。修改范围是`skill-edits/edits.json`和`repo-overlay/`列出的文件。保留用户已有修改、原六例和本机后续修复。默认不提交、不推送、不改正式视频项目或运行时数据库。

本次生产模型的正常输入是**一个视频主题**；导演和团队自主完成内容、素材、分镜、美术、声音和时长。勿将案例档案中的历史技术数据改成产品默认。

## 2. 保留分析脉络，应用确切内容

先读`实施方案_v2_1.md`第0—3章明确业务与分析；第4—10章逐链路看原因和对应正文；第11章核对文件表与应用范围；第14章读取案例结构及索引改法。实际修改动作仍以`skill-edits/edits.json`和`repo-overlay/`为准。

本次文档整合没有修改V2实施载荷，已有`topic-film-v2-*`标记保持。已经接入V2时先预演确认无新增业务改动，不制造第二套标记。

先运行以下命令（用真实路径替换尖括号）：

```bash
python <PACKAGE_DIR>/apply_changes.py --repo-root <REPO_ROOT>
```

无冲突且改动范围正确后运行：

```bash
python <PACKAGE_DIR>/apply_changes.py --repo-root <REPO_ROOT> --apply
```

脚本只复制已写好的新增文件，在现有Skill第一个一级标题后加入对应完整角色块，并对案例索引做精确替换。它会先检查全部目标，再保存备份并写入；重复执行不重复插入。

精确锚点不存在时，先读当前同一段落，对照本包的新旧正文作最小合并；不得整文件覆盖回旧版本。将实际合并差异写进开发记录。不能因为一个地方变化就略过整个案例入口。

## 3. 核对生产正文和案例接入

确认：

- 主题入口直接进入导演/文案/研究，不等待用户提供时长、原稿或素材。
- 导演交完整观看过程，视觉作者交美术、文字、动作、时间和接点。
- 素材适配同步需求与实际绑定，静态替代同步重排时间。
- 配音、字幕、音乐音效回到整片流程，教学片静音不成为默认。
- 16个角色Skill及共享交接读得到新方法。
- 旧六例保持，索引能找到新六例；按需选例，而不是每片用六个。
- 每例都能读到完整教学稿、实际观察视频、源码和验证状态。
- 新教学稿没有被登记为已由旁侧历史视频验证。

## 4. 测试和发行

在仓库根目录运行：

```bash
node scripts/check-topic-film-skills.mjs
npm run plugin:sync-skills
node scripts/check-topic-film-skills.mjs --skills-root plugins/videoflowcut/skills
npm run typecheck
npm test
npm run plugin:build
npm run plugin:verify
```

命令来自已核仓库基线；若本机脚本已更新，使用当前等价入口，保留真实输出与差异。不为让测试通过删除现有审阅、素材权利或沙箱校验。

沿现有候选发行/安装方式部署并核对运行版本。仅同步文件不证明当前生产任务已载入；新建生产任务读回实际Skill内容确认。

## 5. 创作行为验收

运行主题冷启动，不给人工专业分镜，不附历史视频和源码。使用完整方案第12.6节的三个主题或用户批准的同类主题；第12.1节的17项回归同时保留为检查依据。现有项目案例库是允许的内部能力，但用户无需主动指定哪个案例。

记录实际素材搜索、采用、稿件与配音、完整场面、生成、合成和检查结果。只有文件/路径/静态合同测试通过，不能宣布创作目标已完成。真实动效与声画验收按当前能取得的媒体证据如实记录。

## 6. 最终回报

交付实际修改文件列表、测试与发行记录、运行版本、主题测试产物、仍有的具体问题。内容保持与本方案一致；只有与本机当前代码真实冲突的局部才需要适配，不自行另起一套架构或重新概括教学指令。
