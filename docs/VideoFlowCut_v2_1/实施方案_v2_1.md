## 0. 这份方案要解决什么

目标是把 r92 已经获得用户认可的制作方向，变成普通生产任务也能稳定执行的过程，而不是把《满格之外》的四段内容做成固定模板。

期望的用户体验是：

> 用户只给一个视频主题 → 导演组织研究、选材、解说稿与完整声画设计 → 团队完成美术、运动、配音、字幕和合成 → 同一次生产任务内检查和必要修订 → 交付完整作品及真实检查结果。

用户不需要承担普通选材、逐镜纠错和反复补充美术指令。内部检查和局部修订仍然存在；“一次交付”不等于“只允许渲染一次”，也不能承诺任何主观审美结果必然一次通过。

本轮落实六个结果：

1. 系统能从内容产生具体、适合当前题材的观看过程，而不是按素材类型轮播。
2. 选不到理想实拍时，自主调整载体，并把变更同步到实际需求与采用对象。
3. 原创主体、画内文字和来源说明在生成前就有明确设计，不把制作备注带入成片。
4. 运动、阅读、源动作和声音各有时间依据，能定位主视觉空等，不靠持续微动掩盖。
5. 局部作品、字幕、源视频和整片合成的坐标、版本及时间关系能够核对。
6. 导出成功、抽帧检查、连续审阅和用户认可分别记录，不相互代替。

### 1.4 保留现有架构，不另建创作平台

继续使用 Project、Script、Story/NarrativeMap、Scene、VisualTreatment、AssetRequirement、Asset、EffectCue、Job、ProductionRun、Revision 和现有审阅证据。

“场面设计单”“文字清单”“时间用途表”首先是现有交接文本的固定栏目，不是三套新数据库，不要求用户在新界面逐项填写。

现有 Skills 已经提到了完整场面、主次、秒级试排、真实素材、动作交叠和连续审阅。改动重点是让这些要求成为具体交付与检查内容，并删除冲突或重复表述，而不是再次堆一篇同义原则。

### 1.5 为什么这次要同时保留“分析”和“改法”

本节在V1事实边界上补充解释，不增加新的观众实验结论。r92是有价值的方向样例，但期间指令、素材和运行版本都发生过变化，不能将提升归为某个参数的单独功劳。

**第一，问题的单位由素材变成了观看过程。** “放实拍、再放网页、最后放图形”描述的是文件顺序；“从多处观察中选中一个对象，再让它让位揭出条件”描述的是观众在一段画面里经历什么。前者即使入场顺滑，仍容易像换页；后者要求构图、遮挡、对象身份和注意位置真正发展。因此导演要改的是具体场面正文，不是给素材清单多加一个转场字段。

**第二，丰富度来自不同任务，而不是动作数量。** 多窗口负责建立范围，前景让位负责揭示，局部观察负责看清，关系展开负责保持参照，物体和大字接管负责表现和记忆。它们是内容需要时的不同方法，并不要求每片依次采用。若只固化这五个名称，新片仍可能退化成另一套模板。

**第三，事实研究和画面主读分工更清楚。** 研究文件保存完整依据；成片按实际观看需要显示原文、出处或概念关系。网页本身是被讨论对象时可以成为主角，只用于支持一句判断时则不必总占满整屏。减少无用资料页并不是减少核实，而是把核实结果转成适合视频的表达。

**第四，载体适配避免把创意冻结在理想素材上。** 没有某个握姿或天线机位，不等于这段无法表达。保留真实活动影像，用其他可核载体或原创结构完成同一个观看任务，同时更新需求和源时钟。这里最容易遗漏的是：替代成静态模型后，原实拍中持续发生的动作已经不存在，时间必须重新安排。

**第五，连贯不能替代美术。** 主体虽然持续出现，如果比例、细节、明暗和文字重心没有设计，仍会显得笨重或像示意面板。美术需要决定“拿什么东西来展示、怎样让它值得看”；运动再决定“这个物体如何与文字、素材交换重点”。第6章和第8章分别保留这两个责任，不能只写一个“更高级”的结果要求。

**第六，工程通过、设计兑现和实际观感仍是三件事。** 事件表完整只说明声明了时序；主体持续移动也不自动证明没有等待；播放器成功播放不等于专业审阅已经发生。因此第7章保留时间用途判断，第9章保留证据与回派方法，第12章保留对应测试，不因V2提供了实施正文就删掉这些判断理由。

这些分析决定后面每一项修改的目的。阅读顺序应是“为什么有问题 → 采用什么方法及取舍 → 负责人怎样执行 → 哪个文件放什么正文 → 怎样验证”，而不是跳过前半部分只读粘贴块。

## 2. 整体链路与负责人

### 2.1 执行顺序

```text
用户只给视频主题
  → 协调者读取现有配置、真实版本与能力
  → 导演形成整片观看叙述和初步场面
  ↔ 素材负责人核实事实、探索材料、提出适配
  → 导演采用实际载体与信息顺序
  → 同一视觉/动效作者完成美术、文字、运动、时间用途
  → 导演内部协调完整深化稿，作者取得统一采用版本
  → 协调者提交作品；作者检查实际渲染并局部修订
  → 合成实际字幕、源声/旁白与前后作品
  → 原作者与独立审片按各自职责检查
  → 协调者导出、对账，交付可播放文件和真实状态
```

这是依赖顺序，不是每一步都必须串行等全片完成。事实调查、材料探索和不依赖未知源片的造型可以并行。主项目写入与会改写版本的异步任务继续由协调者按现有规则串行对账。

### 2.2 分工及每一步必须交回的内容

| 负责人 | 具体负责 | 必须交回 | 遇到问题回哪里 |
|---|---|---|---|
| 协调者 | 读取主题与配置、调度、媒体可达性、正式写入与交付 | 当前输入版本、采用方案引用、真实对象/Job/版本、未解决项 | 创意交原负责人；工具故障走 Repair Ticket |
| 导演 | 整片发展、主要场面、跨段节奏和取舍 | 连续观看叙述、场面设计、本版制作决定、下一依赖 | 缺材料交素材；主要表达冲突由自己决定 |
| 文案负责人（任务需要时） | 正文和讲述结构 | 全文及变化范围，不只给标题摘要 | 主张、顺序或句群修改回导演统筹，返回准确新版全文 |
| 素材负责人 | 搜索、原文核验、源片观察、替代建议 | 实际内容与范围、支持/不支持的主张、适配方案、许可与获取状态 | 未命中先自行换查询/载体；事实缺口回导演 |
| 视觉/动效作者 | 主体、美术、构图、运动、可见文字、作品源码 | 完整场面深化稿、实际绑定、代码、事件与复核结果 | 局部实现自己改；主要表达/跨段时间变化回导演 |
| 字幕/声音负责人（可由现有合适专项兼任） | 字幕阅读、语音时序、原声策略、音效配合 | 实际字幕/声音对象、时间精度、占用区域、事件绑定 | 语义冲突回导演，不单方压缩语言 |
| 独立审片负责人 | 从实际成片判断观看过程、美术、节奏与自然度 | 指定版本、具体区间、观察事实、影响、应修对象及证据方式 | 由协调者回派原作者；跨段问题回导演 |

“负责人”不等于“新增一个代理”。同一视觉作者可执行视觉、动效和时机相关 Skills。沿用已有 director/specialist/reviewer 分派与 followup，不因增加栏目或检查点创建一批新代理。

### 2.3 用户给主题，团队承担普通制作决定

普通选材、字体、美术、稿件、画幅、内容规模、配音表演、动作安排和局部修订由导演组织团队完成，不向用户发约束问卷，也不请求逐项审批。事实需要核实，材料使用条件需要遵守；这些是生产责任，不是让用户先提供全部素材或专业参数的理由。

真正需要外部账户、新增付费额度或恢复运行权限时，协调者只报告具体阻断与最小所需操作，其他不依赖工作继续。对已有工具、素材权利、安全和正式写入边界的要求保持，不能把“导演自主创作”理解为可以绕过这些边界。

用户此刻评审的是链路方案与候选接入文件；方案文件生成不等于已经修改正式项目或安装插件。案例库的具体文件已按后续要求加入本方案，部署与真实生产验证仍待执行。

## 3. 主题驱动入口：导演怎样从零形成完整制作方案

### 3.1 主题进入：导演直接开始创作

协调者读取主题、现有发布配置与真实工具能力，将它们交导演。导演输出内部制作决定：讲述角度、观看承诺、受众推定、画面/声音方向和初步内容规模。配置足够就使用；不足的普通创作选择由导演补齐并记理由，不询问用户要“多少秒、什么镜头、什么动画模板”。

### 3.2 研究、文案、材料是相互作用，不是三段流水线

导演给研究和素材负责人：要核实什么主张、要看见什么过程。文案作者同时发展完整声画稿。实际材料可以改变讲述顺序、结论和表现方式；正文更新后给所有受影响的作者同一份全文。

例如终端实拍没有找到，但人群影像和准确来源已经取得，可以由导演采用原创终端与真实活动影像共同构图，同时让文案去掉依赖未取得实测的表述。不能继续保留“必须有一条长终端实拍”的旧需求，也不能让静态模型沿用实拍的无效长驻留。

### 3.3 场面不是素材清单

每场正文至少明确：入口看谁、段内什么保持/变化、观众因此看见什么、实际材料与文字、声音、出口和大约节奏。既可跨句连续，也可包含明确切镜；技术分块不决定故事段落。

素材轮播转成场面设计的关键不是多加转场，而是让活动窗口能重排、前景能揭示后方内容、真实局部能被观察、关系能在共同参照下展开、主体与文字能共同形成结尾。它们只是可选方法，不是每片都按顺序出现的配额。

### 3.4 美术从第一份执行稿就具体

重要主体的轮廓、比例、细节集中位置、材质光向、实际投影尺寸，与文字排印和运动一起设计。只写“产品感、精致、高级”不能交给实现；要写清物体有哪些可识别部件、哪个细节是焦点、主次面积和前后关系。

绘制时先看实际构图，再连接动态路径；正常尺寸下读得清、轮廓成立、重心完整，是内部制作判断，不要求用户先提供效果截图或逐帧批准。

### 3.5 时长由本片内容和声画共同确定

文案、导演、配音和视觉共同调整讲述密度、动作、观察、阅读与反应。首轮TTS时长不成为固定总长。某个动画任务已完成时，允许改句群、调整表演停顿、提前接续或重排场界；同步更新配音、字幕、事件和旧审阅。

普通生产不再使用“一个模型已经展示完了，仍等到预先分配时长”的做法。保留必要的阅读、比较、人物反应与情绪，不用“每帧有变化”替代有效观看。

### 3.6 完整声音与交付

主题成片按导演决定生成配音，并使用本机已有音源检索、混音和合成路径。音乐和音效是否使用、哪里需要安静由内容决定；教学原片的静音不是正常交付默认。独立动效受管渲染可以无声，回整片合成时必须与当前实际语言和声音一起检查。

### 3.7 这一章替换什么，保留什么

这一章只替换V1已被用户否定的“输入与约束”及样片生产条件。用户无须提交锁定稿件、固定总长、帧数、静音要求或人工分镜。目录中的“设计单”“文字表”“时间用途表”均由团队生成，是具体创作产物，不是新的用户表单。

V1关于导演、素材、美术、时序、合成、审片和验证的分析继续位于第4—13章。将测试条件从正常链路移开，不构成删除这些分析的理由。历史片的实际秒数只用于第1章、第7.3节、附录A和案例记录的证据定位。


### 3.8 主题到成片方法：完整接入正文

新增文件：`.agents/skills/_shared/TOPIC_TO_FILM.md`。以下为V2已写好的完整正文；在分析和执行逻辑之后保留全文，开发者无须重新从聊天归纳。

`````markdown
# 从主题到完整成片

本方法的正常起点是用户只给一个视频主题。导演带领团队完成研究、角度、解说稿、选材、分镜、美术、配音、声音、动画、合成和交付。下列栏目由团队自己生成，不是用户问卷；本文件不增加 API 字段或新项目数据库。

## 1. 导演先作出创作决定

读取主题后，先确定一个足够具体、能被材料支撑的讲述角度，用三句话写清：从什么处境或对象开始；中途让观众看到哪些值得观察的变化；结束时带走什么认识、感受或行动。受众与表达方式由主题和发布环境推定，推定写在内部制作决定里。

并行发出事实研究与画面探索：前者核实主张，后者寻找实际可用的动作、细节、比较和反应。初步方向可以因此变化。一个网页打不开或一个理想机位未命中，不等于主题不能制作。

导演自行决定有无出镜人物、画幅、初始节奏、声音方向、预计内容规模。已经有项目发布配置时读取并使用；配置不足时选择合理方案并记录理由。初始长度服务内容展开，不是必须填满的目标；整体音画可以随制作继续调整。无需先向用户索要解说稿、固定秒数、参考片、素材包或逐镜设计。

## 2. 文案与画面一起发展

文案作者返回完整朗读正文，同时在每个句群旁写主要观看过程。正文放入关系、动机、判断、态度和必要条件；画面承担能被观察的动作、比较和变化。字幕转写本版正文，画内文字承担指认、强调或关系，不把正文复制成每句一张说明卡。

材料改变判断时改稿；画面已经讲明的重复可压缩；关键过程需要更多观看时，重排句群或调整配音停顿。由原作者返回一份自洽的最新全文，不让下游拼接多份修改留言。

## 3. 从连续观看叙述产生场面

先写“观众实际看到怎样的展开”，再映射 Story/NarrativeMap 和 Scene。技术作品数量由资源预算和接点决定，既不等于句子数，也不决定整片时长。

一个场面可以跨句、包含明确切镜，也可以让一个对象保持。不同场面在内容需要时形成尺度、方向、明暗、材质或注意路径的变化。人物表演、实拍过程、稳定比较和安静观察都有价值；不设每场必须多少动作或全片必须多少种转场的配额。

进入具体制作时，导演给每场交出 [场面执行正文](SCENE_DESIGN_HANDOFF.md) 所列内容。视觉作者据此继续深化，不重新猜主要对象与关系。

## 4. 实际选材与美术同步

素材负责人先按主体与动作搜索，再依据真实候选校准裁切、观看范围和接点；返回文件、源区间、实际内容、适配理由、来源与使用状态。每段显示多久由片中实际作用决定，源片只须覆盖它真正连续显示的部分。

理想材料未取得时，优先用可得材料重组同一观看任务。导演内部采用载体变更，协调者同步需求、采用与作品绑定。由实拍换成照片或原创对象时，视觉作者同时重算该场的有效观看内容和时间，不能保留原实拍时长让静态主体空驻留。

事实依据缺失时，继续核实、改成可支持的准确表述或改讲述角度；图形和模拟画面不承担不存在的事实证据。付费、账户和运行权限继续沿现有授权路径处理，普通搜材不匹配不转交用户上传。

## 5. 同一作者落实美术、运动与时序

在当前画幅和真实字体下确定主体轮廓、比例、细节分布、光向、文字主次、有效留白与投影尺度。为关键入口、一次主要变化、一次重要阅读、出口画面形成实际构图；检查时把真实字幕和人物占用也放进去。

写清状态之间怎样变化：哪个层发起、绕哪一处转、沿什么路径、谁被遮挡、谁保持、下一重点何时接手。不同对象按重量和任务分配速度，文字达到可读状态后计阅读时间。作者从设计时就去掉重复建立与无用驻留，而不是先交一版低质量片让用户指出。

## 6. 声音是完整生产的一部分

主题驱动的解释片通常由完整解说、实际配音与字幕共同组织。导演按题材选择语气与说话节奏；音效、音乐和源声按具体内容服务观看，必要时保持干净。配音回来后，以真实句段边界校准动作和阅读，不能把首轮 TTS 时长反过来固定全部创作。

遇到画面任务过早完成，优先删并重复话语、调表演停顿、改动作接续和段落边界；返回相关原作者并同步重配、字幕和音效。整片总长由这次音画共同完成后的实际结果确定，不继承任何教学样片的秒数。

## 7. 一次任务内完成成品检查

原作者先检查自己的关键动作与共同构图，再由独立审片按正常顺序查看实际合成。分别记录文件/引用正确、设计是否实现、实际观看是否成立。按实际可用的播放、抽帧和媒体分析能力记录范围；静帧不能替快速动作或听审背书。

发现问题回原负责人；同类问题合并处理。用户接收本次任务的完整成片和准确状态，不承担找素材、补分镜、逐帧找错这些生产工作。内部有限修订是生产的一部分，不把“首次面向用户的成片质量”理解为取消必要的渲染检查。

## 8. 当前采用稿与正式对象

复用现有宿主完整消息/任务附件和 CreativeDecision 引用保存全文与版本，不新增通用剧情数据库。完整交接集中为：本版主题角度、最新朗读全文、实际材料、场面执行正文、声音方向、采用差异、正式写入参数。

协调者只做版本/引用/权限/确定性装配，不把全文压成“做高级动画”，也不为通过字段上限静默截断。当前工具需要参数时，由原作者给出已核对值。发现接口不能表达当前决定，保留原产物并沿项目修复入口处理。

项目中已有其他任务类型时维持其路由。本方法直接覆盖“只有主题”的普通原创生产，不改写用户真实给定的特殊任务，也不改平台安全、素材权利和版本校验。
`````

## 4. 导演链路：从“列画面”改为可执行的观看过程

### 4.1 导演先交完整观看叙述，再交场面边界

一个合格叙述要回答：观众起初看到什么，随后关注怎样变化，有什么值得观察或发现，最后留下什么认识或感受。

例如 r92 的可迁移方法是“并置中选出主体 → 主体让位揭出条件 → 整体进入局部并拆开关系 → 物体与排印收束”。可迁移的是组织方法，不是要求所有主题都有这四段。

叙述不能只写“开头实拍、中间图解、结尾动效”。实拍、网页和图形是载体，不是内容发展的理由。

### 4.2 每场交接使用同一张设计单

| 栏目 | 作者需要拿到什么 | 用途 |
|---|---|---|
| 本场作用 | 一个清楚的理解、观察、感受、比较或记忆任务 | 防止只写“展示素材” |
| 进入状态 | 整幅构图、已存在对象、当前第一重点 | 让作者接住上场，而不是从空场重新摆 |
| 发展过程 | 什么保持，什么变化，观众因此看见什么 | 给段内动作明确职责 |
| 材料与事实 | 已取得的真实范围、证据身份、概念对象边界 | 不把假想素材当作已取得 |
| 美术方向 | 主体轮廓、比例、色彩主次、空间/光照、字级 | 让造型和运动同时成立 |
| 准确文字 | 每项实际屏幕文案及角色 | 防止生成时把备注临时塞进画面 |
| 时序依据 | 秒级起点、可变区间、语义锚点、阅读/观察用途 | 给节奏调整留正确空间 |
| 出口与下一场 | 采用切镜还是对象接力，交出去的实际状态 | 连续需要可核对；切镜需要有理由 |
| 可调整范围 | 作者可改的局部；需导演决定的主要变化 | 减少无意义审批，又防止静默降级 |

同一场可以覆盖多句，也可以包含清楚的切镜。不是所有场面必须有三次变化，不要求每个边界都变形，不排斥静态比较、人物表演或情绪停留。

### 4.3 全片检查重复的是“观看方式”，不是统计动画数量

导演将相邻场面并排核对：第一重点的形状、大小、亮度、位置和观看任务有没有实际变化。连续重复出现相同容器、相同层级、同一进退方式时，先看内容是否确实需要稳定重复；没有理由才重写该场。

需要保持美术统一，但不强迫每场都用相同主物体。不能把“至少五种转场”“每两秒一个效果”写成通用规则。

### 4.4 内部采用标准

协调者检查完整性，导演负责创意判断。作者收到的应是导演吸收深化后的**同一份完整采用稿**，不是主线程再次总结的几个关键词。

若只缺像素或曲线，由原作者补足；主要对象、观看关系仍不明确，则回导演补完整。这些都是同一生产任务内部的工作，不交用户补专业参数。

`````markdown
## 2. 视觉作者回传的深化内容

在导演正文上补齐，不另起一份与正文断开的“动效清单”：

- **主体设计**：识别轮廓、主次比例、细节集中位置、材质和光源；最终投影中实际多大。
- **关键构图**：主体与文字的相对位置、前后层级、负空间作用、人物和字幕位置。
- **变化路径**：动作发起者、父子层、轴心/曲线、遮挡、速度轻重、收势与交叠。
- **可见文字**：正文字幕、画内主读、对象标签、UI、来源/必要身份、制作备注分别管理。
- **时间用途**：何时能认清、何时已完成当前任务、何时有下一次有效关注。
- **设计兑现位置**：关键过程落在哪个组件/代码区间、应看哪些中间状态。
- **跨场接口**：持续对象的投影、显示内容、源时刻；或明确采用切镜。

主任务将完整深化稿交导演，导演返回吸收结果的当前采用稿；原作者据此完成实现。局部像素和曲线由同一作者决定，主要内容和跨段顺序由导演统一，不逐项询问用户。

## 4. 美术判断的实际操作

先按灰度查看关键构图：第一眼是否落在真正主角；有无互不相干的同等亮块；负空间是否帮助方向、阅读或下一步运动。再恢复色彩，看强调色是否指向正确重点。

看主体轮廓而不是只看渐变：去掉落影仍能辨认对象和层次吗；接触区、槽口、切边是否符合这个具体物体；精细区是否与观看焦点一致。平面风格可依靠轮廓、比例和排印成立，物体风格才需要相应侧边与光照，不能全部强制三维。

把入口、主要变化和出口并排看：视觉重心有没有真正转移；新主体是否带来合适的尺度、方向或明暗差异；统一风格是否误变成同一版面反复替字。没有内容理由的重复在编码前就改。
`````

## 5. 素材链路：自主适配不仅写在提示词里，还要落实到对象

### 5.1 把需求拆成三个层次

**事实底线：**必须真实存在和核实的内容。例如明确称为某次实测的结果，不能用绘制UI代替。

**表达底线：**这场必须让观众看清的动作或关系。例如整体进入可辨认局部，不能改成一个固定小图标。

**拍摄偏好：**自然光、完整握姿、指定背景、特定品牌、单条长镜头等。只有当前事实指认确实需要的条件才进入必须满足的素材要求；其余由导演依据可得材料决定。

素材负责人先按主体和行为检索，再根据实际候选调整机位、裁切与场面。原文核验与视觉选材关联，但分别保留状态。

### 5.2 一次候选返回必须回答的问题

返回实际可读/可解码的文件或明确的获取状态，说明：

- 画面真实有什么，计划使用哪个源区间，哪里能形成主体或接点。
- 能承担什么角色，不能证明什么；是否需要另一个事实来源。
- 裁切后主体还能否辨认，可用的源动作长度与余量。
- 与当前构图的适配方式；必要时提出一项最合适的替代，而不是列一堆让用户挑。
- 来源、授权事实、署名和是否可以分发；未知如实保留。

“下载成功”不等于“已采用”，“未命中”不等于“工具故障”。

### 5.3 失败后的具体路由

| 情况 | 下一步行动 | 是否需要用户 |
|---|---|---|
| 查得到但机位不理想 | 放宽偏好，换查询或同源区间；试适配实际裁切 | 否 |
| 只有短片段 | 核对实际连续可见跨度；在明确接点换源或交给图形 | 否 |
| 视频不适合，照片可用 | 改成资料图片观察；由载体和镜头运动组织局部，不伪称动态实拍 | 否 |
| 现实环境有素材，设备特写缺失 | 保留真实活动影像；采用原创设备承担概念角色 | 否，主要变化由导演内部采用 |
| 指定证据不存在或不支持原句 | 继续核实；导演和原文案作者缩小主张、改准确表述或调整讲述角度 | 否，团队不能用概念图补造证据 |
| 某个Provider不可用 | 换实际可用合法入口；故障留诊断 | 通常否 |
| 必须新增登录、付费或权限 | 说明具体错误、替代已尝试情况与最小所需授权 | 是，限该事项 |
| 所有合法获取/渲染途径确实受阻 | 保存进度与准确状态，其他独立工作继续 | 仅必要操作；不伪造交付 |

搜索预算由任务规模和现有配置决定。首轮查看少量实际候选，发现题材或机位方向不对就改变查询；不能把“再试两组关键词”写成所有项目的硬上限，也不能无休止搜索同一个理想机位。

### 5.4 采用替代后，完成五步同步

1. 素材负责人交替代内容、事实边界及对场面的影响。
2. 导演确认仍完成当前观看任务；视觉作者补足实际新载体的构图和动作。
3. 协调者更新当前 AssetRequirement：主体/动作、媒体类型、连续时长、状态及理由；清空旧时长条件按实时Schema执行。
4. 按新版本绑定实际 Asset 与源范围，更新相关 Scene/VisualTreatment/采用决定；已有作品因依赖变化需要重做的，明确标出。
5. 读回确认：正式需求不再等待已放弃的长实拍，实际绑定没有仍指向旧素材。

当前已有 `manage_asset_requirements` 及采用链路，优先正确使用并测试；只有实时实现无法保存这些选择时再补代码。不新增一套独立“素材适配引擎”。

### 5.5 防止替代后自动退化成普通图标

替代被采用时，同时写出保留的观看过程。例如“真人手机视频改原创手机”仍应完成视窗聚焦、前景让位与揭字；只放一部手机加标题，未完成替代合同。

不同载体的内部运动不同：实拍有自己的真实过程，静态模型没有。替换后必须重新安排有效观察时间和接续动作，不能只替换Asset而保留长素材的停留时序。这正是 r92 需要补进链路的一点。

## 6. 美术与文字：生成前就明确成片里具体长什么样

### 6.1 同一作者同时做造型和运动

视觉/动效作者依据导演完整场面和实际材料，完成对象轮廓、比例、主要细节、空间与材质，再决定该对象能怎样被观察、遮挡或拆开。

制作过程中选择几处高风险构图，例如主物体近景、复杂证据阅读、结论共同构图，使用实际字体、实际文字和真实素材预排。这些是内部工作的输出，不要求用户先提供效果图，也不把它拆成多轮用户审批。

### 6.2 美术交付具体到可检查的决定

每个重要原创对象写清：识别轮廓、比例、关键细节的位置、受光方向、侧边/厚度如何表现、与文字的前后关系、接点时的投影尺寸。

不要只给CSS容器尺寸。SVG viewBox有空边、旋转有投影变化，容器宽570不等于手机实体宽570。验收看最终可见主体和文字，而不只看参数值。

整片风格说明要确定字体、字重、色彩主次、光源方向与明暗变化，但材质依据对象重新设计，不把重阴影、发光和一套渐变强加给全部元素。

### 6.3 每场生成“可见文字清单”

这是现有场面交接中的一张表，不是新的内容管理系统。

| 类型 | 例子 | 成片如何使用 |
|---|---|---|
| 正文字幕 | 当前导演采用的完整朗读句群 | 字幕负责人管理与真实配音对应的换行和时序 |
| 画内强调 | 负载；可能影响速度；信号强≠质量好 | 明确准确文案、字级、进退和阅读任务 |
| 对象标签 | 强度；质量；连接部 | 跟随所指对象，必要时保留独立阅读朝向 |
| 屏幕内UI | 演示真实交互所需按钮、状态 | 只有叙事需要且身份清楚时进入屏幕 |
| 来源/必要限定 | 摘录、来源名、必要条件 | 可读且不改变主张，按用途设计位置 |
| 示意身份 | 画面示意、结构示意 | 根据误读风险给出足够清楚的观众说明 |

### 6.4 r92 的具体处理原则

Phone() 里的“终端示意”承担的是制作身份，而不是手机UI或叙事信息。建议屏幕维持干净的泛化界面；确有识别需要时，在合成角注中设计一次“画面示意”。“同源编辑并置”留在素材记录，不让普通观众阅读生产术语。

必要的虚构/示意身份、来源及事实限定不能为了漂亮自动删除。是否显示、在哪显示由意义和误读风险决定，不能统一缩到看不见的角落。

`````markdown
| 多个场景或对象中关注一个 | 活动窗口重排、近远错位、前景取得面积 | 同一主体身份、源动作进展 |
| 现象背后还有条件 | 主体让位、遮挡揭字、边缘带出依据 | 现象本身或已建立的判断 |
| 有一个细节值得看 | 同源局部靠近、观察窗口、局部与整体对应 | 真实源时刻、可辨认部位 |
| 一个关系含多个部分 | 先建立共同骨架，再展开差异部分 | 比较尺度、上下/内外结构 |
| 一个物体值得展示或记住 | 局部到整体、拆分/离槽、方向变化、文字接管 | 部件归属、受光和空间 |
| 人物的反应或情绪需要时间 | 保持人物、干净切镜、源声延续 | 真实表情、动作和语义 |

真实素材本身有好的过程时，以其为主要内容；动效负责观看位置与重点，不把它替成低信息符号。需要切镜就切镜，只有共同对象或观看关系需要延续时才作形变接管。

## 2. 原创对象的绘制决定

先把当前主体拆为轮廓、主材质、识别细节、可动作部件和投影。每一项要具体到本片对象：例如薄卡的切角、窄切槽、较大接触区，与厚设备壳体的螺丝、散热孔、侧壁不是同一套图形。

主体关键细节集中在第一注意位置。主体需要占据足够投影面积，局部可以出画，身份必要部分保持可辨。次要装饰服务比例和材质，不用随机细节填满背景。

设置共同主光，亮边、暗侧与投影说明空间；接触时影子窄，离开时投影偏移并变软。选择柔和面光时卡面应平整，不能用多段强渐变制造鼓起。2D风格以形状、排印与色块成立，不机械加金属和发光。

## 3. 排印与主体一起构图

先量真实字形和换行，再选位置。主读、标签、字幕、出处按作用形成层级。大字可以在物体前方遮住一部分，物体则保留足够面积在后方构成背景；不把每个元素分配到一个互不关联的角落。

来源是依据时，仅把必要原文和身份带到可读位置；网页本身是讨论对象时才展示页面过程。文字随纸面共享透视，阅读状态清楚；使用替身阅读层时在交接点对齐，避免同时出现两张半透明的同一纸页。

## 4. 关键状态与中间路径

为入口、主要变化、有效阅读/观察和出口构图。然后逐对写出：

1. 哪个对象先发起，旧重点为什么退让。
2. 运动轴心/路径，变化的是投影尺度、姿态还是观看位置。
3. 中途谁遮住谁，文字或细节从哪里变成可见。
4. 有意义的变化何时完成，下一动作在哪一段收势中开始。
5. 实际源动作与声音怎样继续。

前景让位揭字必须让遮挡面积真实变化；同源局部观察必须保持源时刻；从图标进入物体时要匹配起始投影，不能把两个不重合对象交叉淡化就称为同一主体。

## 5. 速度与停留

物体掠入可以利落，细节观察可以舒缓，文字在可读条件下保持。不要把同一缓动函数套到所有对象后等同于运动设计。阅读可以在收势阶段开始；主体已经认清且没有新关系时，开始下一项有效关注。

主对象不动而其他对象承担阅读、表演或比较时可以合理保持；背景粒子与无关光扫持续变化不抵消主体空等。完整规则见 ../../effect-timing/references/pacing-by-completion.md。

## 6. 源码实施与交接

源媒体、作品局部、整片和声音使用独立、可核对的时间映射。跨作品接管时核对投影、姿态、文字、材质、源帧；容器显式拥有所需宽高，子层共享父变换。

尽量用同一份命名时序常量驱动动画与 resolveMotionEvents。事件描述对象和阶段须与实际实现相符；事件值本身不证明美术和阅读通过。

每个关键设计写出实现位置与中途检查：例如“让位揭字—ForegroundWindow / conditionText—检查遮挡解除中点”。若技术资源需要分作品，按正常预算拆分并继承出口，不把技术上限当整片时长。

## 7. 在一次任务内完成检查

以正常观看尺寸检查关键构图，再看连续动作和整片声音。选择实际风险点，不按固定三张图就宣布通过。首次交付前解决已观察到的截边、双影、文字竞争、无用等待和未实现的主要动作。仍无法验证的范围据实记录。

案例资料帮助作设计判断，不是自动拼接模板。先决定当前场面，再按需要学习一例的美术和动作关系，回到当前内容重写完整执行稿。
`````

## 7. 时序链路：解决的是“没有作用的等待”，不是清除所有静止

### 7.1 用四个时钟避免假同步

1. 讲述时钟：旁白/原声的真实时间与精度。
2. 编辑时钟：整片时间线的全局位置。
3. 作品时钟：当前受管作品的局部帧。
4. 源媒体时钟：绑定素材的真实播放位置。

主题整片按本版真实讲述与声音校准；制作中尚无声音的内部试排如实标记，不作为正常成片静音默认。字幕出现过，不证明观众正常速度下读完。实际使用Sequence等带起点的层级时，局部帧会相对父层计算，不能混用全局帧。

### 7.2 每个重点记录“动作结束”和“观看任务结束”

在现有effect-timing交接中追加时间用途栏目：

| 项目 | 含义 |
|---|---|
| 第一重点 | 这段希望观众主要看谁 |
| 动作范围 | 进入、主体变化、交接各在什么秒级范围发生 |
| 可读/可辨起点 | 何时字与对象真的到达有效尺度且未被挡住 |
| 必要持续 | 原动作、阅读、比较、反应或情绪还需要多久，依据是什么 |
| 最早可接出点 | 不破坏当前理解、不提前泄露下一信息的起点 |
| 实际接出点 | 下一项有意义的画面从何时开始接管 |
| 停留理由 | 有效阅读/比较/真实过程/体验/等待外部锚点，或待判断 |

不能把“动作收势结束”再加一整份重复阅读时间。阅读从实际可读时开始，它可能和收势交叠。

### 7.3 对当前 r92 的时间判断

|---|---|---|
| f34—55，约1.42—2.29秒 | 手机已进场且几何状态保持，侧窗仍在错位 | 是中央对象等待候选。若此时需要看三窗关系可保留；若第一重点已是手机，聚焦可与侧窗收势交叠。不能把“全画面有变化”当作足够理由 |

这些是源码区间与编辑判断，不是已经连续观看测得的“每段空等秒数”。

### 7.4 主题生产中，时长由文案、声音和画面共同形成

**先判断当前画面是否完成任务。** 若对象已经被认出，既无新细节、真实过程、阅读或反应，也没有需要继续保留的参照，就安排下一项有效观看，而不是等待最初估计的段尾。

**再判断语言是否也需要调整。** 画面先完成不必然是动画太短，可能是句群重复、表演停顿过长，或画面没有演出正文承诺的过程。导演把问题交对应原作者：重复话语删并，表演由配音调整，遗漏过程由视觉补实；新版本同步字幕与声音。

**段落边界允许共同重排。** 原始估计和首轮TTS长度是当前产物，不是用户要求固定的终长。重要细节需要更多观察就补相应时间，重复建立完成就及时交接，不统一把所有节省的时间加到结尾，也不统一加速全片。

**载体改变时重算时间用途。** 实拍有持续手部操作或空间移动，照片和原创模型没有同样的源过程。替换后重新决定需辨认什么、接下来发生什么、何时让位；不能让模型占满旧实拍时段。

本节取代V1按“固定总长／锁定声音”讨论的样片分支。正常业务仍保留事实准确、真实素材时钟与版本同步，但不从测试参数推导普通生产边界。

### 7.5 调整的顺序

先改变不必要的重复建立和过长动作，再让前后动作在不争抢注意时交叠，并结合当前语言调整场面边界。发现句群重复或表演妨碍观看时，立即交原文案、配音与导演共同修订，不把首轮声音当永久边界。无作用的漂浮、光扫、粒子循环，不用来冲抵空等。

一次时间修改要同时列出受影响的作品、源范围、字幕、声音事件和相邻出口。字幕保持独立，但不能与画面使用两套未对账的句子时钟。

### 7.6 事件与动画使用同一份时间常量

r92已经有 resolveMotionEvents，可以直接利用。建议生成的源码让事件表和实际动画从同一份时间常量导出，减少“文档写13—31，但代码16—34”的漂移；两者描述的对象或阶段不同可以合理不同，必须说明清楚。

示意写法仅说明设计，不是要求新增平台DSL：

```tsx
const timing = {
  terminalEnter: [0.65, 1.35],
  focusTakeover: [1.8, 2.65],
  revealCondition: [2.5, 3.25],
};
// 秒数乘fps后确定帧；动画插值与resolveMotionEvents共用这些值。
// 实际采用时间来自本片，不将上述例子固化成所有视频的节拍。
```

### 7.7 自动提示做到什么程度

第一版先用时间用途表、事件区间和局部实际预览定位，不强行开发自动剪辑器。

需要批量辅助时，再做只读诊断：从事件间隔、已知主要对象区域的变化和阅读记录找“待审片段”。变化很少只产生候选；背景人流、字幕换卡、微光扫也不能自动证明主体内容在推进。最终由实际观看判断。

自动提示输出区间、对象、依据、例外因素和下一检查动作，不自动剪时长，不给出伪精确的“审美通过分数”。

### 7.9 时序方法：完整接入正文

新增文件：`.agents/skills/effect-timing/references/pacing-by-completion.md`。以下为V2已写好的完整正文；在分析和执行逻辑之后保留全文，开发者无须重新从聊天归纳。

`````markdown
# 按观看任务完成度编排时间

## 1. 主题创作的正常时间来源

导演、文案和视觉共同决定这一片需要展开的内容。稿件读起来和画面发生的节奏提供初步秒级范围；生成配音后用真实语言边界校准。画面、稿件、表演停顿与成片时长可以继续一起调整，不按某个先生成的时长反向补空画面。

作品技术分段的时长是实现结果；样例的场数、帧数与语速都不进入新片默认。任何本片已采用的方案仍保留版本，修改同步相关对象。

## 2. 每次主要关注写四个时间

- **开始可辨认**：对象或文字达到有效尺寸、对比和无遮挡条件。
- **当前任务已完成**：所需辨认、阅读、比较、动作或感受已经获得条件。
- **下项关注最早可进入**：不破坏当前理解、不提前泄露重要答案。
- **实际接管**：下一项有效信息或观看行为在当前方案真正开始。

不用把这些变成四个必填API字段。作者在场面稿写清秒级范围和理由即可。

文字开始淡入不是开始阅读；大段阅读也不必等所有背景完全静止。动作收势和阅读能交叠时，不重复增加两份等待。

## 3. 空等的判断与处理

先看第一重点，而不只看全画面像素差：一个模型已经认清、没有新细节或关系、也没有阅读/表演用途，却一直等下一段，这是候选空等。背景人流在动、字幕换卡或光扫出现，都不能自动证明第一重点仍有任务。

稳定比较、人物反应、来源阅读、音乐或情绪释放有明确用途时保留。静止本身不是错误。

处理顺序：

1. 合并重复建立，缩短没有信息的等待或过慢推进。
2. 让下一动作在合适的收势区间进入，保持一个清楚的第一重点。
3. 重新安排段落边界，把时间给真实过程、必要阅读或有表现力的主体展示。
4. 句群仍然重复或与画面冲突时，由原文案作者改写；配音与字幕同步更新。
5. 更新音效/音乐事件、源区间及跨作品接点，再检查实际合成。

“建立都快、阅读都短、结尾都长”不是通用节奏。每处时间由具体内容决定。

## 4. 从视频改为原创主体时重新计时

原视频可能在数秒内发生手部操作或空间移动，替成静态手机后这些过程不存在。此时重新决定：手机需多长时间被认出、是否还需要观察屏幕细节、什么时候让位、能否直接接到下一画面。

例如任务只是先认出终端再揭出条件，终端出现并完成辨认后即可与揭字动作交叠；不能因为原搜材需求写了长镜头，就让模型独占同样的时间。

## 5. 四时钟与修改传播

- 语言时钟：本版配音/原声的真实时间及精度。
- 全局编辑时钟：最终时间线位置。
- 作品局部时钟：当前受管作品从自己的起点计时。
- 源媒体时钟：素材源区间内的实际播放位置。

交接清楚保存局部起点与映射。当前工具帧率/源范围以实时Schema为准，不假定同一对象跨组件后源视频自动续播。

建议作者使用下列思路，数值由本片决定：

```tsx
const schedule = { enter: [enterStart, enterEnd], focus: [focusStart, focusEnd] };
const secondsToFrame = (seconds: number, fps: number) => Math.round(seconds * fps);
// 动画与事件共同读取 schedule；平台仍按既有事件结构校验。
// 全片长度由当前音画编排确定，不能把下面某次示例总长写成默认。
```

发现改稿时，协调者调用既有稿件/语音路径并读回Impact；作者只重做被影响的作品及接口，字幕/声音负责人同步，旧审阅不自动背书新版本。

## 6. 审片如何记录

记录区间、第一重点、这段正在做什么、实际可读起点、为何保留或缩短、对应版本和检查方式。代码时序可以帮助定位；自动低运动提示只给候选，不自动裁时长，不把静帧范围当连续审阅。
`````

## 8. 动效生成：保留创意设计，不在写代码时退化

### 8.1 一份受管作品可以承担完整表达段

编译为A/B/C/D还是其他作品数量由实际资源预算、版本修订和接点需要决定，不按字幕句数拆片。A/B这种同一终端持续变换，可以复用相同的状态计算逻辑并用不同局部窗口提交。

### 8.2 源码前的“兑现表”

作者给当前场面列出少量关键动作，与自己的实现位置对应：

```text
设计：手机让开，露出原本被挡的大字。
实现：同一场景中的前景手机、后景字和真实遮挡关系。
关键检查：中途字是否真被手机遮住；换源时是否重播。

设计：从真实设备进入可辨认局部。
实现：同源源时钟+局部裁切，或清楚切入原创结构并交代身份。
关键检查：局部是否属于正确对象；没有把原创细节伪装成实拍放大。
```

它不要求平台自动判断“高级”。作用是作者和审片能够对照实际过程，防止“出现了手机和文字”就算兑现揭示。

### 8.3 合成层级有明确责任

主视觉负责主体、图内字和资料；字幕层负责完整正文；声音层负责旁白/源声/音乐。主视觉的设计必须预先看到真实字幕与人物占用，但不永久留一个固定大空洞。

像r92那样使用fullscreen主视觉和front字幕可以保留为本次放置方案，不提升为所有视频全局固定顺序。数字人同屏时按人物、手势、图形和字幕的实际关系重新设计。

### 8.4 版本及跨场交接

同一对象跨作品接管时，保存并核对出口与入口的投影位置、大小、方向、可见部分、文字状态、材质状态和源时刻。

实际数据可写在现有完整创作交接里；不必新增Scene数据库。导演改变边界后，协调者按新的Cue范围提交，作者同步局部时钟和源映射，旧审阅证据不自动继承。

### 8.5 实现限制的处理

使用当前部署的受管能力。确定性代码校验、素材路径、许可和资源预算保持；不能为追求质感临时放开任意脚本或网络访问。

某个具体表达确实超出能力，作者给出保持观看任务的可行实现及代价，导演内部决定。需要补平台能力时开独立修复/开发任务，不在剪片过程中偷偷改变通用引擎。

## 9. 审片与交付：检查真实结果，又不把未审变成无限停工

### 9.1 开工时就检查审片输入是否可达

协调者在首个小预览出现时，确认原作者和审片负责人能取得该实际文件/受管地址，不等整片做完才发现浏览器不可用。

记录当前支持：实际连续播放、逐帧读取、原声读取、已接入视频分析，以及各自覆盖的时间和采样限制。播放到末尾只是播放器能力，不自动算专业审阅完成。

### 9.2 复用现有能力

已有 render_preview_range、inspect_composed_frames、analyze_media、read_media_observations 和审阅记录入口，先验证当前运行版本的这些能力。

宿主播放器不可用时，可将原审片者提出的具体问题交给已有媒体分析链辅助查看，再把真实窗口、模型观察和限制交回原审片者。低频抽样可以发现较长等待、内容错误，不能证明快速接点或精确同步已通过。

这轮不引入一个新的审片大模型服务，也不因为播放器故障改成要求用户上传同一份媒体。

### 9.3 三类检查，各有结论

| 检查 | 重点 | 能证明什么 |
|---|---|---|
| 工程检查 | 范围、哈希、依赖、解码、字体就绪、素材时钟、字幕层可见 | 文件和引用是否正确 |
| 设计兑现 | 采用稿里的主要动作、主体、可见文字、中间过程是否实现 | 输出有没有完成所采用的设计 |
| 成片观看 | 阅读、自然度、美术、节奏、重复、声音配合和结束 | 当前范围实际观看是否成立 |

抽帧中无叠字不等于动态节奏通过；“忠实执行”也不等于设计好看。分镜已实现仍平淡，回导演/视觉作者；实现缺了动作，回原作者补代码；纯技术失败回对应平台模块。

### 9.4 审片反馈的最小完整格式

```text
版本：真实Preview/Artifact、Revision、内容哈希
区间：全局秒/帧；涉及作品及局部区间
观察：实际看到了什么，而不是复述分镜意图
影响：读不清/注意力不前进/主体不自然/来源误读等
证据方式：frames / continuous_video / audio / audiovisual及实际覆盖
负责人：原作者、导演、素材、字幕/声音或平台
建议动作：保留、局部改动、改构思、补充证据
复核范围：改动区间及前后接点；是否影响其他版本
```

“手机1.42—2.29秒完成辨认后中心无新观察，侧窗运动不再承担第一重点”是可讨论的具体反馈；“节奏再快一点”不足以交付修正任务。

### 9.5 防止反馈变成无限循环

同类小改回原作者并成一次修订。修后审具体问题及前后接口；没有影响的场面继续使用已有证据。已影响的全片节奏仍需整段回看。

根据任务预算由协调者管理迭代，保留实际消耗；不强制每段多版本对比，也不允许把可选审美建议无限升级为必须重做。达不到目标或证据受阻时准确报告，不降低严重程度凑通过。

### 9.6 保持“可导出”和“已验证”分开

现有质量策略允许尚未完成审美审阅时导出，不应改成主观意见都关闭才能取得文件。本轮保留这一点。

对外交付摘要至少并列展示：

- 文件是否生成并核对到正确版本；
- 工程检查覆盖情况；
- 设计兑现与静帧检查范围；
- 连续视觉/声画审阅的实际范围及未知；
- 用户认可所对应的具体文件与反馈。

这些首先从既有证据记录推导，不新增一个混合所有含义的“完成=true”。r92可以准确写“可导出、抽帧通过部分检查、用户认可方向、连续节奏未审”，而不是自动扩成“全面通过”。

### 12.2 端到端验收：主题冷启动为主，固定说明只做隔离诊断

**主题冷启动是本轮产品验收：**用户只给一个主题，不给正文、素材、长分镜、固定时长或历史效果图。系统自行完成研究、完整声画稿、场面设计、美术、选材、配音、动画、合成及检查。只有这一类结果，才能说明优化真正进入导演和生产链，而不只是执行了一份外部手写提示词。

**固定分镜复现保留为工程／执行诊断：**需要单独定位“同一说明被怎样实现”时，冻结一份当前完整说明并在独立任务中比较。这个方法不成为用户的正常输入要求，也不单独替代主题到成片的产品验收。

至少覆盖本题材、不同题材解释片，以及具有真实声音或人物占用的完整任务。样本用于发现回归，不作为“保证成功率”的统计证明。每次是一项完整任务，内部完成检查与修正。

### 12.3 记录指标，而不是预设虚假的审美分数

记录：用户被要求补材料/逐镜干预的次数；替代后遗留需求数；未声明或身份错误的占位；主要设计动作兑现情况；最终可见文字与采用清单的一致性；空等候选及判断理由；真实动态审阅范围；内部返工原因；最终交付文件。

审美结论保留实际观察和用户对具体文件的反馈。不用“有四段”“有十个效果”“帧哈希每帧不同”作为好看的替代指标。

### 12.4 环境问题另做受控试验

同一文字在两端独立生成的结果不同，可能来自设计、选材、字体选择、代码实现与修订过程。若要定位纯渲染差异，再用同一兼容源码、同一素材、同一字体与参数跨端重渲染；这与本轮从文字生成的实验分开。

### 12.6 主题冷启动验收：输入只有主题

### 12.7 五个针对性行为测试

- 搜不到理想长终端实拍，但有短实拍或人群影像：团队完成载体适配并重排时间，不让用户上传，不遗留旧必需需求。
