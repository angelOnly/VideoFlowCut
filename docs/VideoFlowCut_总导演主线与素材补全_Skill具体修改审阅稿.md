## 1. 本稿修正什么

原方案没有充分写出两项总导演工作：**构思整片从开头到结尾的故事主线，以及根据这条主线主动取得和制作尚不存在的画面。** 只有素材理解、段落标签和分镜字段，仍不足以组织出一条好片。

本稿将流程明确为：用户需求与已有事实 → 总导演构思初步表达方向和关键声画 → 按需要探索事实与外部素材 → 导演根据实际发现完善故事、剧本、分镜与初始声画节奏 → 定向补齐镜头、生成或原创制作 → 实际声画粗剪与修订 → 完整代表段与整片制作 → 导演和专业审片持续反馈。已有材料足够时跳过无必要的探索；这不是要求每次固定搜索两轮。

这条链允许前半程循环。导演先提出值得尝试的表达方向，真实材料帮助发现可看的行动、细节、变化、声音和情绪，再由导演决定取舍；形成的分镜继续指导精确补材。不能等全部素材齐备才开始构思，也不能先把完整脚本锁死再给每句话配图，更不能把未经核实的设想当作事实进入成片。

本轮进一步把制作单位明确为完整声画场面：导演先构思实际发展，决定由什么载体、观看位置和声画关系呈现；专项围绕同一场面细化素材、美术、运动、讲述与不同文字的持续范围。稳定字幕、固定外框和持续实拍都可能成立，不能用取消全部限制或让所有层一起运动代替创作。具体方法进入已有编号，新增 SM1、CA1、ET1 仅补语义、字幕和时机三个缺失入口。

本稿对应[原优化方案](</E:/ai/VideoCut/docs/VideoFlowCut_总导演分镜驱动的整片制作链路优化方案.md>)第 4—7 节和第 9.1 节，补足第一批 Skill 的具体正文。此前四部分、选材补充与当前角色规则保留，本轮局部细化完整场面如何产生、如何由各专项共同做出，以及怎样通过实际媒体修订。素材不足时区分事实、画面和生产阶段；两份 docs 均是待实施资料，不会自动改变运行中的剪辑行为。

### 1.1 总导演具体做什么，怎样验证

导演先选出本片实际开头的画面与声音，试接后面一段，形成可以进入、可以发展的观看过程；再写出从开头到结束的具体经历，安排必要背景、变化前的判断依据、重要结果后的反应或观察，最后细化段落和分镜。不能用“观看价值、引起好奇”作为已经完成构思的证明。

整片初稿随后变成可播放的声画粗剪。承担叙事的动画要演出主要关系与时序，不能用占位标题代替；先看实际哪里迷失、重复、来不及或空等，再改声画安排。视觉与动效专项把导演分镜发展成具体美术和连续动作，原样交付完整指令、源码与参数；主任务提交后把真实媒体交回原负责人。

审片先写实际观察，再对照计划：既可指出源码漏实现，也可指出完全实现的原设计仍然不好看。问题回到负责人的具体修订，并比较新版本同一上下文。F1/F2、P3/P5—P9、M4—M6/M8、Q1—Q3、C1—C3 及本轮 SM1、CA1、ET1 给出拟用正文；下表说明它们在当前链路怎样起作用。

材料不足时，以上构思从可讨论的初步声画方向开始，按第 1.4 节探索关键材料，实际发现回导演后再完善故事、剧本与分镜。探索阶段不要求最后全部镜头都已存在，也不能用空泛主题代替导演想验证的具体表达。

### 1.2 素材不足时怎样规划

| 缺的是什么 | 总导演要做什么 | 得到什么才算解决 |
|---|---|---|
| 必要事实、背景或真实过程的依据 | 在用户题目与创作范围内研究、核实来源，查找原始材料；根据结果校正主张与主线。 | 该事实有可追溯依据，或明确调整了无法支持的判断。 |
| 事实已清楚，但没有适合的画面 | 从分镜提出素材需求，选择网络真实素材、来源页面、MiniMax 表现镜头、原创图形或组合。 | 实际取得的材料完成该镜头作用，能接入前后画面。 |
| 画面存在，但一条源片很短 | 判断还需要辨认、讲解、比较、回看、反应或欣赏什么，设计有效的视觉与声音展开。 | 新增时间有具体观看内容，完整预览中的节奏和接续成立。 |
| 内容本身不足以支撑用户目标 | 研究与主题相关且值得加入的内容，重审表达范围；确实无法满足时说明具体缺口与影响。 | 新增内容推动同一主线，或用户约束内形成了合理的新编排。 |
| 镜头需要的工具或运行能力缺失 | 报告具体平台阻断，由总导演判断现有能力能否保留表达；平台修复另行处理。 | 有已验证的实现路径或明确待解决项，不能用假素材、假成功代替。 |

网络获取、MiniMax 与原创动效都是首版分镜可主动选择的制作方式。是否使用取决于真实性、可控性、美术与动作需要，并非只能在搜索失败后降级使用。生成结果不能冒充真实现场、操作结果或证据；事实内容也可以使用明确的原创示意来解释。

### 1.3 五秒素材怎样参与约十秒内容

五秒真实过程本身只有五秒，但观众辨认结果、理解细节、比较前后状态或听一段有内容的说明，可能还需要时间。总导演可以安排正常播放、在关键状态回看或停留、由图形拆解接管、再回到后续讲述。画面和旁白各承担一部分表达，不是把同一动作拖慢两倍。

设计同时保留三种时间：**源视频的真实范围、镜头在成片中的显示范围、段落的初始节奏范围。** 搜索参数 `min_duration_ms` 和 MiniMax 的 `duration_seconds` 指向需要的源长度，不直接照抄整段长度。如果一段约十秒的内容只需要五秒连续实拍，就不应把最短源素材设为十秒，否则候选硬过滤会排除可用片段。

有目的的定格、回看和慢放是创作手法；源视频结束后采用什么画面、原声怎样退出、何时交给下一镜，都需要写明。当前没有核实到可直接生成正式原分辨率定格的专用 MCP；审阅联系表中的低清帧不能直接当作高质量成片素材。所需派生操作或动态合成不支持时，保留设计意图并反馈具体缺口，由总导演选择可行表达。

初稿的“约十秒”仍是节奏设计。必要表达七八秒已经成立可以提前接续，需要更多阅读则局部延长；明确锁定的声音或总长保留，允许修改的旁白与画面一起调整，已有文件不自动构成锁定。具体规则见 F2、A2、SC2、M7、Q2、VO2。

### 1.4 两个选材入口及其实际交接

| 当前阶段 | 导演交出的任务 | 素材专项完成的工作 | 导演收到结果后必须作出的决定 |
|---|---|---|---|
| 表达方向尚在形成 | 初步开场声画、可能的发展与结束、关键未知、已有材料及约束；没有最终分镜可以明确说明 | 找实际处境、行为、细节、过程、反应、环境和资料，观看关键范围，比较哪些材料具有表达潜力 | 依据实际观察保留或调整表达方向，采用新发现，或缩小到具体缺口继续探索 |
| 已有具体分镜 | 本镜任务、前后声画、必须出现的动作或状态、实际连续源长度、构图和声音要求 | 定向搜索、比较可剪片段与组合，交回源范围、用法建议和限制 | 确定采用材料与分镜版本，交专项细化制作；不匹配时决定换材料还是改表达 |
| 材料已进入粗剪 | 当前采用的故事与分镜、实际连续声画及需复核范围 | 原专项复核自己的选段和用法，审片提供实际观察；不能用搜索排名解释剪辑效果 | 区分素材不合适、使用方式不合适、故事编排不成立，修订相关范围并再次观看 |

探索阶段的返回不是一份主题相关链接清单；定向阶段的返回不是一句“素材已下载”。两者都交可查看的实际范围、观察事实、建议作用、取舍与未知。新发现可以推翻原设想，但整片主线与跨段决定始终由导演负责。

对应改动：P3/P4/P6/P8/P9 安排时机；A1/A5—A8 完成专业选材；C4/C5 保证宿主真实分派与回传；CP1、SC2、M2 接入具体制作；Q1 和第 5 节检验实际观看。探索和定向是同一个选材 Skill 的工作方式，不新增平行导演、固定两轮任务或通用评分系统。

### 2.1 以后应用在哪里，为什么写进 Skill 会影响链路

Skill 是具体负责人执行时读取的工作方法。改正文的目的，是使导演在写对象前先完成声画构思，使专项在写源码前完成设计，使审片在给结论前真正观察。文档或 Skill 本身不会替模型作决定；是否改变行为，要用实际子代理交接、作品和预览验证。

### 5.1.1 从主题到粗剪的一次实际调用顺序

1. 主任务读取项目事实与用户约束，按 `production-coordinator` 启动或续接导演；没有项目时传递真实状态，不先造空分镜。
2. 导演按一种主工作流完成 P3：返回初步开场声画、发展方向、关键未知和需探索的内容；已有材料充分时直接进入分镜细化。
3. 主任务按 C5 交素材专项执行 A1/A5/A6/A7。事实资料、可观察候选与未解决项返回；浏览器阅读与平台获取按现有权限和已发布能力进行。
4. 主任务把真实范围与完整观察交回原导演。导演查看，返回采用、继续搜索或故事修订；同一代理的后续任务续接原上下文，不重新派一个导演猜此前意图。
5. 导演据实际发现完善故事、剧本、分镜和秒级节奏，对剩余镜头发定向需求。素材专项按准确任务补齐，取得原文件后复核源范围；素材充足则不强制重复搜索。
6. 导演采用后，主任务把版本、实际材料与完整分镜交视觉、Cutaway、Scene、动效和声音所需负责人。完整视觉动效段由专项先深化场面、关键构图与连续过程，交完整正文及必要试作请求，不直接跳到正式源码提交。
7. 主任务把完整深化稿与实际关键画面交原导演正常统筹。导演结合前后声画，返回统一采用分镜、具体续接要求及未解决项；主任务把完整稿与差异回原作者继续设计、试作或正式实现。局部参数不逐项审批，主要变化提前反馈不替代这次常规协调。
8. 原作者返回完整指令、源码与执行参数，主任务排序提交、读回实际版本并取得连续声画粗稿，回原专项和导演，并按范围交审片子代理。关键动作未制作、只有占位时记录尚不能验证的部分；图形本身承担叙事时先做可观察的关键试作。
9. 导演根据实际结果修订选材、镜头用法或整片编排，并交回后续可沿用设计、需改段落、下一项制作范围和剩余依赖。主任务续接负责人、提交新版本并复核，继续代表段及其余制作；一个样片不等于整片完成。

这些是任务中的决策与返回顺序，不是新增数据库状态，也不要求用户逐步确认。正式对象、异步 Job、版本变化与未知结果继续按现有合同处理。完整创作正文经真实宿主消息交接并续接原负责人，CreativeDecision 记录采用审计；尚未提交作品的长篇设计恢复仍依赖原任务全文，不把审计报告当成通用分镜文稿存储。边界见总方案第 9.2、14.6 节。

| 多个真实用途视频同屏 | 核对内部源动作、裁切、标签指认顺序和比较参照；窗口稳定也可成立。 | 窗口会动就宣布通过，内部只有截图或从头重播；为了变化遮住有效过程。 |

| 分镜在制作中改变 | 读回新决定，显式检查旧作品、声音与采用依据，重做必要范围并补审。 | 认为追加文本决定会自动更新旧作品或使旧审阅覆盖新设计。 |

验收保留从初步方向、探索请求、真实宿主分派、实际候选范围、原导演修订，到分镜、完整生成指令、源码与 Preview 的对应证据。覆盖只有主题且材料不足、允许声画共同创作、明确锁定声音或总长的条件；条件可组合，不规定固定样片数量。素材不足任务不预先给整片答案，可改稿任务验证是否真正共同修订，锁定任务检查是否在边界内扩展画面。先用当前已支持的图形、图片和外层视频验证；多动态视频按原专项范围另验，不借本稿扩开发范围。

### 5.3 失败怎样回到正确层

故事没有推进，回总导演；分镜无法表达，回总导演与视觉；事实无依据，回核实；画面未取得，回素材专项；指令具体但源码遗漏，回动效实现；动态本身不好看，回美术与运动；合成或声音冲突，由总导演协调相关专项。工具缺失或运行故障通过 `report_editing_blocker` 进入独立修复流程，停止受阻步骤，其余不依赖的工作继续。

同一问题修订后要看新版本实际范围和前后接点。证据不足保持待审；不能为了流程结束删掉未完成的承诺或把旧媒体证明写成新版本通过。

### 5.4 验证方法与需要保留的证据

**文档和路由检查。** 更新现有 Skill 引用与路由测试，检查导演、协调者、素材和具体使用方之间的入口及返回路径，防止“主线稳定后才可找素材”等冲突重新出现。检查目标是实际约束，不仅是出现“探索、分镜”等词语。它们不能证明代理已经搜索、观看或作出好的选择。

**宿主真实交接验证。** 在验证任务中保留导演任务、素材专项的真实调用与返回、实际媒体回传和原导演续接。检查发现的新材料是否进入导演决定，决定变化是否传到制作方；只有自报 delegation、工作单或 SkillExecutionReport 不算完成。测试中模拟的数据仅验证合同，不能写成真实观看结果。

**获取回归与小范围联通验证。** 在现有获取与媒体测试附近补下载错误、结果未知、文件验证失败、成功登记与范围复核的测试。自动化采用固定夹具或模拟下载器以保持可重复；候选环境再用可取得且用途条件明确的单个真实来源验证浏览器发现到平台获取、读回和内容复核。两种证据分别报告，不能用模拟通过宣布 YouTube 联通成功。

**实际声画试剪。** 让独立验证用剪辑任务接收主题和约束，按第 5.1.1 节完成关键段与全片；审片先记录实际观察再对照计划。观察未知保持待审，技术可用与艺术效果分别判断，用户对具体文件决定最终效果。测试不以强行填满秒数、增加效果数量或关闭全部 AI 问题作为通过条件。

失败保留具体输入、范围与结果：是发现不到材料、原文件取不到、源片选错、用法不成立、导演计划需要改变，还是平台阻断。修订后看新版本，而不是只把报告改成“已优化”。

### 6.3 获取、复核与失败怎样闭合

素材专项交完整来源、所需内容、准确程度与获取要求；主任务通过实际发布入口提交并跟踪已有任务。平台返回文件、真实媒体信息、来源关系和 Job 结果，主任务读回当前对象与版本，再交原专项查看原文件的相关范围。源时间以实际下载文件核对，若未来提供截取下载，必须明确原始时间与派生文件时间的对应，不能沿用错误偏移。

文件取得并验证后仍有两个判断：实际内容能否完成导演的任务，以及在具体镜头中怎样使用。由素材专项和导演完成前者，具体使用专项细化后者；主任务执行采用与放置，实际合成回传复核。下载成功不会自动把使用状态、事实判断或艺术效果标为通过。

下载器缺失、访问失败、超时、大小超限、文件损坏或输出不可解码，返回具体诊断并不登记假素材。任务结果未知先读取状态和对账，不换键重试或重复导入；项目引用、版本和异步回写按现有合同排序。工具与 Runtime 阻断走独立 Repair Ticket，剪辑任务不改源码或绕过 MCP；专业未找到合适材料由导演决定继续找或改变表达，不当作平台错误处理。
