## 先看整体

**保留现有技术架构，调整创作工作流与方法的接入。** 文案研究和主题画面准备并行；导演从任务开始就参与，不是等两者完成后才接手。编排、制作和预览都可以返回改稿、补材或重做设计，只处理实际受影响的内容。

通用方案不以某个具体题材组织。普通配图按整片主题广泛准备，精确事实按实际需要定向核实；六种表达方向用于调整讲述和美术，不控制素材类别、动效力度或知识深度。

## 1. 目标、原因与改造范围

### 1.1 四项问题同时解决

| 问题 | 需要实现的变化 | 不能作为替代的做法 |
|---|---|---|
| 文案生硬、难懂，缺少吸引力和必要知识 | 标题提出的疑问得到真实解释；信息易跟随，进入和收束完整；口吻建立在清楚的内容上 | 只加一个热闹开头、只举算式、压缩到听不懂，或用风格代替知识 |
| 主题素材少、下载失败后没有补充、图片反复撑时长 | 首轮广泛发现并分批取得主题画面，导演有足够可剪选择；制作中持续按需补材 | 要求每句话都有高度匹配的专属镜头；搜索只交链接；下载一个文件就结束 |
| 动效主要是显字、停留、整屏硬切 | 主要变化、动作性格、文字表现和前后接点有实际设计，机制的有效关系进入源码和成片 | 记录机制编号、统一淡入、套同一弹簧，或把技术文件边界当作切镜安排 |
| 背景、排版与整片节奏单调 | 美术有配色、布局、字体、材质和层次选择；声画有发展和变化 | 全片固定说明页、只换底色、把所有字幕做得更花 |

普通画面的价值可以是题材氛围、视觉变化、情绪、趣味或节奏，不必逐句解释知识。关键原文、数据、真实操作和明确事件则必须对应依据。这是用途区别，不是新增素材类别或评分制度。

### 1.2 原因分析

**创作信息被当成固定输入。** 把初稿、首批材料或首次构图过早视为定稿，会使导演后续只能装配；发现讲述难懂或画面无聊，也只能在既有框架里微调。

**普通配图承受了过高的语义匹配要求。** 当检索从“找一个能解释这句话的动作”开始，主题相关且好看的镜头会被误排除。研究资料、事实证据与背景画面混用同一标准，又会进一步偏向原文截图。

**方法、方向和案例混在一起。** 文案口吻不等于知识结构，美术气质不等于固定镜头，示范题材不等于产品范围。只有例子而没有规律，或把所有例子直接放在 Skill 入口，都容易诱导照搬。

**设计与执行之间丢失关系。** 机制选择后只保留局部淡入、移动，未保留主从动作、交叠和接续；或者设计已写明，但源码把对象提前卸载、把过冲裁掉，实际效果仍会退化。

**反馈缺少明确去向。** 只说“可以返修”不足以运行。需要明确发现什么问题、回给谁、返回什么实际修改、哪些依赖要更新，然后继续原任务，而不是重开整片或仅解释原因。

这些是本方案要消除的工作风险。是否存在某个具体代码缺陷，仍须读取实际调用和测试，不根据风险描述直接推断所有模块都需要重写。

### 1.3 改造取舍

采用“**通用生产方法＋可回改的交接＋按需参考＋有依据的小范围代码改动**”。仅改职责名称，不能消除逐句取材与一次性交付；重建 Agent、素材库服务或流程引擎，又没有必要。

保留既有偏好入口、`CreativeBrief`、`CreativeDecision`、`AssetRequest`、`Candidate`、`Asset`、`Job`、`Revision`、时间线、受管 Remotion、声音、字幕和复核记录。现有需求字段可以描述主题级取材，搜索入口不要求先提供句子 ID。[R1][R11][R17]

明确的工程改动是解除单作品四个视频选段的总量限制。其余依赖错误、提前关闭任务或案例预加载问题，只在确认实际消费者存在该行为后修改，不先新增状态机。

适用主题可以变化。知识解说需要核实和解释；真实采访、操作教学、事件记录需要保留原意与事实顺序；纯视觉或无旁白任务不强加解说正文。广泛配图只放宽辅助画面的选择，不允许用其他事件替代明确指认的真实事件。

## 2. 工作流：并行开始、分批汇合、编排与预览都可回改

### 2.1 导演全程参与的工作关系

```text
任务主题、受众、用途、已有偏好与本次明确要求
                      │
           导演明确题目与表达目标，全程协调
                      │
       ┌──────────────┴──────────────┐
       │                             │
文案作者：研究、试写、形成当前正文    素材作者：按主题广搜、取得、选段
需要准确依据时提出定向资料需要      不等待完整稿，不预先绑定每句话
       │                             │
       └──────────────┬──────────────┘
                      ↓ 分批交回，不等待全片齐备
             导演＋视觉作者：编排与场面设计
                      │
       ┌──────────────┼─────────────────────┐
       │              │                     │
讲述/声画表达不合适   画面选择不足          构图/演出不合适
       ↓              ↓                     ↓
回文案改相应正文     回素材继续补搜         回视觉改方案、查机制
       │              │                     │
       └──────────────┴───────→ 回到当前编排
                      │
           当前源码、素材、声音与字幕合成预览
                      │
          发现问题 → 按相同去向修改 → 再看相关范围
                      ↓
             完整成片、技术导出与真实状态说明
```

箭头表示工作关系，不是新增软件节点。已具备条件的部分继续制作；需要某份证据、某段改稿或某个模型结果的部分才等待它。试排帮助早点发现问题，不能代替好文案和好设计。

### 2.2 “不默认改稿”指不自动连带返工，不是限制改稿权

**准确但不好讲的文案也可以改，不必等到出现事实错误。** 导演和视觉作者发现文字太密、缺少必要铺垫、语言抢先说完了画面、某段很难形成有效观看，或者出现了更好的表达办法，都可以提出改稿。

普通背景替换没有影响意思时，可以保留文案；同一次换图若顺便暴露讲述问题，也可以基于这个实际问题改稿。不是“画面一变必须改”，也不是“事实没错就不许改”。

| 发现的情况 | 谁继续工作 | 要返回的实际结果 |
|---|---|---|
| 导演觉得主线不吸引人、开头和结尾接不上 | 导演与原文案作者 | 重新组织相关正文或主线，并明确哪些段落继续保留 |
| 视觉作者发现文字太密、说明抢在必要观察之前、同一意思重复 | 视觉提出具体位置，文案修改，跨段取舍由导演协调 | 新的准确台词与声画顺序，不只是“请缩短” |
| 文案正确，但一种更好的画面方案需要调整表达 | 视觉与文案共同提出可行改法，导演采用主要关系 | 文本和画面共同更新；不为了迁就不合适素材而损失核心含义 |
| 首批素材太少、太同质，或制作中需要更多选择 | 素材作者 | 新取得文件、可用范围和简要说明；可以换方向或载体，不死守单个镜头 |
| 精确资料不能支撑当前主张 | 资料核实与文案作者，必要时导演 | 补可靠依据、修正或收窄主张，不能用背景配图冒充证据 |
| 换普通背景，正文含义、指代和声音均不变 | 视觉作者与必要的声音工作 | 更新选段、裁切、字位、绑定和接点；通常保留正文和既有语音 |
| 设计写得清楚，输出却漏了进入、惯性或退出 | 原实现作者 | 修源码与时序，生成对应产物，不重新解释风格 |
| 实现忠实，但实际观看仍不好看 | 原视觉作者，影响主线时交导演 | 改演出或美术，再同步实现，而不是无止境调同一个参数 |

局部改字、表达与演出在已授权范围内由相应作者继续；改变主要意思、跨段顺序或整片长度时由导演协调。只有触及用户明确锁定的内容、真正缺少的授权或预算，才需要向用户确认，不把每次修改都变成逐镜审批。

### 2.3 改稿和补材如何回到项目

一条续接说明用自然语言交清：**实际哪一段有问题、为什么影响观看、准备改变什么、哪些内容保持。** 携带当前稿或片段的真实引用；用已有任务与原负责人续接，不创建“改稿审批对象”或第二套稿件库。

文案作者返回修改后的准确正文，纳入同一份当前声画稿；素材作者返回可访问文件和范围，导演与视觉选择位置；视觉作者返回具体方案、源码或修改。主任务继续负责正式提交与实际版本读回。[R8]

正文变化后，配音、字幕、动作事件和后续位置是否受影响，要按真实工具返回处理。某句话长度变化，可能需要移动后面多个对象；不能承诺永远只改局部，也不无条件重做全片。背景换用若已经封装在受管作品里，仍需以正确的新输入生成作品，不直接替换缓存文件。[R6][R10]

制作中补材是正常工作，不是只允许首轮搜索。需求尚未完成就继续；已关闭而需要新内容时，沿正式接口恢复或建立适用需求，不能直接篡改数据库。已核读的搜索入口拒绝 `closed` 需求，关闭时机必须与实际任务相符。[R11]

### 2.4 职责与共用稿件

| 现有角色 | 持续负责什么 |
|---|---|
| 导演 | 题目、主线、采用和跨段取舍；接回改稿、补材、设计与预览，持续编排 |
| 文案作者 | 研究、清楚有内容的旁白、讲述调整；根据导演和视觉反馈实际改稿 |
| 素材作者 | 主题广搜、取得建议、内容观察、选段与后续补材；准确展示时定向核实 |
| 视觉作者 | 剪辑、美术、动效、源码与局部返修；可向文案提出表达修改，向素材提出补充需要 |
| 主任务及声音作者 | 主任务组织真实分派和正式操作；声音作者完成配音、音乐、音效并接回相关调整 |

角色可兼任，不扩大固定团队。当前声画稿分为纯旁白、依据与素材引用、画面和演出、制作反馈四区。主题素材清单继续使用项目里的现有文件，不在每次交接复制全部资产。

### 2.5 偏好、方法、场面设计分别保存

偏好优先级保持本任务明确要求、已保存且适用的默认、导演当次判断。现有五维字段继续使用，不增加六选一枚举。[R1]

六种方向只帮助调整讲述与审美，不能自动生成素材筛选、动作幅度、背景或音乐配方。导演实际采用的场面当然可以写清颜色、构图、动作和声音；这是本片设计，不是风格名称自动施加的永久限制。

## 3. 文案：通用解释方法在前，表达方向在后

### 3.1 原因：风格不能替代要讲清的内容

稿子难懂可能因为省略了背景、概念进入太快、数字没有归属、因果跳跃，或者结尾没有回答开头。只有语气变化和有趣例子，却没有解释题目，仍然不是完整的解说。

通用方法应先解决“讲什么、为什么成立、普通观众怎样理解”。轻松、温暖或探索只改变与观众交流的方式，不决定能否省略关键原因，不要求所有题材都变成某种生活故事。

### 3.2 从题目到完整正文

先用日常语言回答题目，明确这条片子最终需要讲清的关系。根据主题补充必要事实、原因、条件或相反情形；来源只支持现象时，不把推测动机写成事实。研究材料按核实需要整理，旁白不直接继承资料目录。

组织正文时，让一个普通观众能够认出正在谈什么，再引出值得关心的差异或疑问。每次增加概念，先说明它在这件事中做什么。称呼尽量稳定，参与者、动作与结果明确；必要术语可以使用，但不能让听者替作者翻译一串抽象词。

例子、类比、数字和人物经历都是解释工具。一次例子说明一个关键关系，随后回到本题的原因和结论；不能只做几次计算就结束，也不为了延长内容不断换例子。真实经历与假设分清，假设用自然语言交代，研究备注不混进口播。

吸引力来自真实的认识变化：澄清一个误会、看懂一个反常结果、发现两个看似相同事物的区别、理解一个生活现象。趣味和共鸣可以贯穿解释，但不能只在第一句出现，后半段又变成逐条宣读。

结尾使用正文已经讲清的关系回答题目。没有足够事实支撑的结论，不靠金句补上。没有用户给定时长时，不为压缩到固定长度删掉必要解释；有时长要求时，先删旁支和重复，而不是让配音越来越快。

### 3.3 编排阶段允许改稿，表达阶段也能反过来推动研究

导演和视觉作者可依据实际声画要求改变台词顺序、措辞、字量或解释方式。文案即使准确，若缺少观看前提、反复说明画面已经表达的内容，或不适合当前整体节奏，也应修改。

提出改稿时，说明具体困难和希望保留的意思，不只说“更高级”“更有网感”。文案作者返回改后的准确正文；对主要结论或跨段结构的改变由导演采用。需要新的事实才能完成解释，就返回资料核实；普通配图换用不触发无关研究。

正文、事实依据、画面意图、改写理由在共用稿件里分区。TTS只读取准确旁白及明确支持的表演参数；镜头说明、美术建议、作者分析和示例说明不朗读。[R9][R10]

### 3.4 方向使用方法

先学习下面的通用规律，再按当前需要选择一种讲述倾向或少量组合。主题和核心知识不变时，方向主要调整叙述距离、用词、信息进入方式和收句感受，不增加六条生产流程。

### 六种讲述方向：先理解特点，再选择用法

共同底线是准确、清楚、完整且值得听。同一份知识可以有不同口吻；方向名称不决定字数、段落数、事实深度、素材类别或动画。没有命名方向也可以按实际需求写作。

<a id="narration-light-humor"></a>
#### 轻松有梗

**核心特点：** 与观众站在一起发现一个有点好笑的落差，让复杂内容听起来像一次明白、有意思的交流，而不是把严肃信息改成段子。

**内容组织：** 从可理解的经验、预期或具体观察进入，尽早给解释。可以在原因讲清后用短反应收住，再继续下一层；不规定必须先误导再反转。

**语言特点：** 使用具体动词、贴切比喻、有分寸的夸张和长短句变化。幽默落在事实已支持的反差上，调侃事物或共同困惑，不靠虚构经历和强烈嘲讽制造热闹。

**迁移与修正：** 在任何主题中先找“大家容易怎样想，实际哪里有意思”，再选择是否幽默。正文只剩笑话时补因果；只有开头活泼时重排后半段；笑点不成立可以直说，不强求每段一个梗。知识仍须讲清。

<a id="narration-warm-company"></a>
#### 温暖陪伴

**核心特点：** 理解观众面对的处境，用平等、不责备的方式解释信息，让人获得理解和选择能力，而不是只获得安慰。

**内容组织：** 承认真实困难或感受后，直接进入能提供帮助的知识；原理、区别和选择逐步讲清。没有具体处境的主题也可用温和、耐心的解释，不编造一个悲伤故事。

**语言特点：** 称呼自然、句子完整，必要的专业内容说得明确。少用训诫式提醒和替观众下判断的语气；可以坚定、有观点，不靠大量抚慰词或缓慢语速表现温暖。

**迁移与修正：** 从“观众哪里困惑、需要理解什么”出发。泛泛安慰就补实际信息；替观众决定情绪就改叙述立场；过于软弱冗长就收紧重复，但不删掉解释本身。

<a id="narration-curiosity"></a>
#### 悬念探索

**核心特点：** 让观众愿意追随问题的答案；悬念来自真实的未知和发现，不来自故意藏住理解所需的前提。

**内容组织：** 建立一个清楚的问题，较早给出第一层有用答案，再沿尚未解释的原因、条件或结果深入。需要多少层由内容决定，不把知识目录全部改成问号。

**语言特点：** 关键疑问简洁，解释有喘息。一次说明一个新的关系，称呼与比较条件稳定；不是连续抛多个金额、否定和转折让观众猜谜。

**迁移与修正：** 在主题中寻找真正值得追问的现象或差异。问题太多就先回答；节奏拥挤就拆开复杂条件并减少旁支；已经解释清楚就收束，不追加没有依据的新谜题。

<a id="narration-clear-punchy"></a>
#### 理性爽快

**核心特点：** 结论明确、推理可跟随、解释不拖泥带水。专业来自把关系讲透，不来自术语多或语速快。

**内容组织：** 可以先给关键结论再解释依据，也可以从一个清楚比较得出判断。删掉重复定义和不影响答案的旁支，但保留必要前提和边界。

**语言特点：** 具体称呼、明确动词、直接收句。复杂部分给完整解释，不把几步推导挤成半句；用一次恰当总结帮助观众形成认识，而不是每段重新喊口号。

**迁移与修正：** 检查听者能否复述核心答案。只有结论就补推导；一口气塞太多条件就放开篇幅；只有数字比较就补原因。没有幽默也可以有吸引力，关键是发现和判断有价值。

<a id="narration-playful-objects"></a>
#### 奇趣卡通

**核心特点：** 以容易想象的对象、类比或俏皮口吻降低理解门槛。拟人和对白可以选用，但不是必需条件，也不等于受众一定是幼儿。

**内容组织：** 先让人认识对象和规则，再解释一次变化及结果；借类比时说明对应关系，及时回到真实主题。不能为了角色表演增加一条与知识无关的剧情。

**语言特点：** 主语明确、动作具体，一句话尽量承接一个关注。专业词出现时当场解释，避免给抽象概念换一个可爱名字后继续抽象地讲。幼龄受众需要更基础的铺垫，不只需要更多语气词。

**迁移与修正：** 找一个能降低理解成本的形象即可。类比反而难懂时去掉类比；对白使身份混乱时改回单人旁白；真实机制与比喻冲突时修比喻，不修事实。

<a id="narration-immersive"></a>
#### 沉浸叙事

**核心特点：** 让观众跟随一个过程、观察或选择进入内容，解释属于正在发展的关注，而不是与故事分离的课堂。

**内容组织：** 交代必要的起点，在遇到问题、发现或决定时引入知识，结尾回到原来的关注并给出答案。可以按观察推进，也可以按事件推进，不要求复杂人物或固定故事结构。

**语言特点：** 具体、可感知，叙述视点稳定；细节服务理解和投入，专业解释仍清楚。慢读、少字和长停顿并不自动构成沉浸，必要处可以直接、紧凑。

**迁移与修正：** 优先确认跟随什么以及为何值得跟随。只有氛围就补发展；讲完经历却没回答主题就补解释；真实素材不支持某个动作就改叙述或明确假设，不为匹配旁白无限寻找同款演员。

### 规律与示例的关系

先依据当前主题写作，使用相关方向的规律修正表达。仅在需要看一份完整示范、比较讲法或出现具体写作困难时，再读 `examples/README.md` 的索引并选择一个相关文件。普通任务不默认读全部六篇，不把示例的专名、金额、故事、结尾或段落顺序变成下一主题的模板。

示例学习后，返回当前题目与当前资料，保留可迁移的原则，重新写实际正文。采用方向不同，不要求资料、素材或动效生产另起一套流程。
<!-- VFC:END:NARRATION-PATTERNS -->

### 3.5 文案方法怎样判断是否有效

只听正文时，能否知道在讲什么、为什么会这样、哪些条件影响答案，并获得值得记住的认识。风格是否生动是进一步判断，不替代前面的理解要求。导演可以因整体观感不好再次发起改稿；规律与示例都不是不可修改的标准答案。

## 4. 素材：整片主题广搜，准确展示定向，编排中继续补充

### 4.1 为什么首轮就应放宽

普通解说的画面可以提供题材语境、氛围、变化、情绪、趣味或连接，不必逐句演出知识。以当前句子的动作细节作为主要检索要求，会过早排除大量可以剪的材料。

默认应按整片主题、常见相关场景和关联对象发现材料。旁白提供上下文，不变成每个候选都必须高度匹配的筛选表。宽泛主题词可以直接使用，不必等精确长句全部失败才放宽。

主题相关、画面有表现力、来源和技术条件可处理的候选，可以先推进取得，再由导演决定位置。反应、趣味和类比片段可以来自相邻甚至不同题材，采用与否看实际表达，不以语义相似度自动否决。

### 4.2 两种需要沿同一条工具链处理

| 需要 | 默认做法 | 制作中的调整 |
|---|---|---|
| 普通主题背景、过场、氛围、趣味、视觉变化 | 按整片主题广泛取得，多种材料都可以候选，不绑定逐句位置 | 换选段、换载体、换来源、补画面，不要求换用就改稿 |
| 明确原文、数据、操作、特定事件或直接指认对象 | 根据要核实或展示的事实定向查找，保留上下文 | 证据不符就继续核实或协调修改主张，不能拿普通背景替代证明 |

这不是新增两种 Asset 类型、两个服务或两个代理。相同文件也可能在不同位置承担不同作用；沿既有需求、来源记录和绑定说明清楚即可。

对纪实、真实原话和操作教学，所讲主体与步骤必须准确；普通插入画面仍可灵活。不要让广泛配图暗示未经核实的具体人物、品牌或地点就是事件当事方。

### 4.3 可复用的主题取材任务说明

以下方括号由调用方填入当前实际任务信息，是人读的交接格式，不是新 API，也不是固定搜索词。

> 本片主题是【主题】，面向【受众／用途】。请围绕主题及其常见相关场景、对象、环境广泛准备可剪画面，优先考虑清楚、有表现力且彼此有区别的材料；使用位置由后续编排决定。无需逐句解释旁白，也不要求一条视频表现整段内容。适合当前表达的趣味、反应或类比材料可以提出。具体原文、数据、真实操作或指定事件的查证需要将另行说明。首批实际文件及时返回，制作中仍可继续补材。

生成查询时，从主题名、自然同义词、常见相关场景、关联活动或对象出发。不同方向分别查询，不将多个备选合成一条必须全部满足的长句。结果同质就换来源、场景或构图；结果太少先检查查询入口并减少自加限定；大量无关时再增加区分信息。

美术色板、某种机位、演员连续动作或动画跟踪条件，不自动加入所有查询。个别已采用场面确实需要某项条件时，只对该需要定向查找，不能反向收窄整片普通取材。

### 4.4 取得文件并分批交回

沿已发布工具完成实际工作：[R2][R11]

```text
已有 AssetRequest 描述主题需要
  → list_asset_providers 核对实际服务、媒体类型与查询模式
  → 关键词发现，或网页发现并选定具体来源页面
  → search_media_candidates / inspect_media_candidate
  → acquire_media_asset / track_job
  → 已登记的真实 Asset、源范围和内容观察
  → 导演与视觉作者选择位置并正式绑定
```

选定公开原文、页面快照、直接图片或 PDF 时，按实时能力使用 `acquire_source_material`。来源页面和候选并不等于已取得文件，不能把候选 URL 当成正式绑定。[R2]

| 入口 | 实施时要核对什么 |
|---|---|
| 支持关键词的 Provider | 准确 ID、本轮媒体类型、真实返回完整性；关键词可宽，不假定写了 video 就必然进入视频入口 |
| Pexels 未配置关键词接口时 | 通过可用网页发现单视频页面，再沿当前 Provider 取得；不在仅接受 URL 的入口反复提交关键词 |
| YouTube 的已选页获取 | 先发现单个视频页面，再交候选与下载接口；不把获取工具当全站检索或传入列表页 |
| 精确网页／图片／文档 | 取得真正可读、可绑定的对象，保留事实适用范围；链接本身不是已下载素材 |

实际可用性以当前 Runtime、Schema 和任务返回为准，不依据文档假定某服务已配置。授权、来源许可、路径安全、文件头、媒体流、哈希与范围校验保持；普通缺素材由作者继续处理，新增付费、账号或真实权限问题才请求用户决定。

### 4.5 下载失败与补材不是同一个问题

| 当前情况 | 接下来做什么 |
|---|---|
| 部分结果或详情失败 | 使用有效候选，读 warnings；需要更多结果时使用真实游标，不把首批当完整搜索 |
| 关键词没有结果 | 检查查询模式，换宽词、语言、来源或相邻内容，不一味增加限定 |
| 文件明确下载失败 | 按原因恢复或换候选；普通镜头可以换不同内容，只要仍有画面作用 |
| Job 未知或仍在运行 | 跟踪原任务，其他无依赖候选继续；不换幂等键重放 |
| 已取得但不好看、过短或不适用 | 换范围或其他文件，不因下载成功就强行采用 |
| 精确证据缺失 | 保留查证需要，换可靠来源或协调调整主张，不以普通画面冒充 |
| 文件都成功，但编排时发现画面仍少或同质 | 主动再次发补材任务，扩展主题相关画面或新的表达机会，不等下载出错才补 |

既不规定每类画面都要找齐，也不规定下载几条就完成。导演能进行有效编排就推进；缺少选择时继续补。记录尚未解决的需要和下一步，不无限重试一个无望的镜头，也不以“已经尝试过”结束实际未完成的工作。

### 4.6 返回与补材请求保持轻量

素材作者交回真实文件／Asset、推荐范围、实际内容、重要使用注意即可；推荐位置可以写，但不是取得或其他位置使用的前提。技术时间以真实文件和观察为准，不由文案估算。

导演或视觉作者补材时说清当前少了什么可剪选择，范围仍可宽泛。例如需要更有变化的环境、不同观看距离、另一种质感，或者适合过渡的片段。只有具体事实或已经采用的核心场面确有依赖，才精确到指定内容。

反复出现的文件可用于持续参照、回扣、氛围和节奏，不要求每次新增知识。实际乏味时先改选段、长度、组合或补画面；文案本身有问题时也可改，但不为证明共创而强行重写。

### 4.7 当前对象如何承载

使用既有 `AssetRequest.title/purpose/visualBrief/queryHints` 描述主题取材，具体取值来自本片任务，不带固定行业名。它们是内部字段；正式 MCP 参数要读实际 Schema，不自行发明参数。[R17]

Candidate 保存候选，Asset 保存已取得文件，位置和显示范围在采用时绑定。`ready/acquired/fulfilled` 表示相关取得进展，不自动表示整片画面充分。需求未结束应可继续，关闭和恢复沿正式接口；不另建主题素材池服务、覆盖率表或逐句匹配分数。[R11]

## 5. 美术与动效：审美规律独立，具体演法按场面决定

### 5.1 美术负责外观，不复述文案内容

美术方法要讲清整体气质、配色关系、布局、字体、材质、形状和视觉层次。写“把本段的两个名词做出不同身份”属于某个场面的信息设计，不能替代一套能迁移到不同主题的审美规律。

下面提供六种可尝试的审美方向。**颜色组合和布局是设计起点，不是主题素材的颜色筛选，也不是全部镜头的固定模板。** 用户明确给出的色板、字款或其他要求优先；实际原件与素材仍可使用不同色彩，后续通过构图与表现协调。

将标记内的文字保存为 `visual-treatment-planning/references/art-directions.md`。它不包含题材旁白、特定物件或固定运动程序。

<!-- VFC:BEGIN:ART-DIRECTIONS -->
### 美术方向：从气质到配色、布局与风格

同一方向可以有多种外观；讲述口吻和美术也可以自由组合。先根据任务选择可解释的审美倾向，再放入真实画幅检验字体、颜色和布局。下面的配色只是可选组合，不是必用色号；不从任何名称自动推导素材、运镜、动效强度或配乐。

<a id="art-light-humor"></a>
#### 轻松有梗：机灵、明快、有编辑感

**配色思路：** 可从浅中性色配墨黑、再用明亮的珊瑚橙或清亮蓝作视觉点开始；也可采用更大胆的撞色。重点是明暗和色彩有明确主次，而不是每一块都同样鲜艳。

**布局与排印：** 可尝试不对称排版、大小反差、局部出格但整体有秩序的编排。正文阅读区保持清楚，少量手写或非规则字形增加机灵感，不把所有文字变成同一种夸张标题。

**造型与材质：** 现代编辑海报、拼贴、手绘批注或略不规则边缘都可作为候选。趣味来自视觉性格与对比，不依赖表情包和装饰堆叠。

**适用与调整：** 适合希望亲近、活泼但仍清楚的内容。严肃主题可以降低外观的嬉闹感而保留利落感；失控杂乱时先恢复层级，不通过统一缩小全部内容解决。

<a id="art-warm-company"></a>
#### 温暖陪伴：亲近、舒展、成熟

**配色思路：** 可尝试米白、暖灰、茶棕、陶土或灰绿的协调组合；冷灰蓝与适量暖色也能成立。重点是色彩相互协调、文字边缘清楚，不是全部低对比或全部暖黄。

**布局与排印：** 区块间有适当呼吸，边界关系清楚；字形可舒展、柔和但有骨力。可以使用稳定对齐和较自然的非对称布局，留白服务舒适观看，不把主要画面缩成小装饰。

**造型与材质：** 生活编辑、自然质感、适量纸感或柔和表面都可尝试，也可以完全平整现代。成熟、克制装饰不等于压低清晰度或内容面积。

**适用与调整：** 适合希望降低距离感、陪伴理解的内容。需要强调时可以有强对比和大面积主读，不因温暖就一味变淡；过度柔焦、滤镜或空白使画面发虚时，恢复清楚的轮廓与主次。

<a id="art-curiosity"></a>
#### 悬念探索：层次分明、线索清楚、有发现感

**配色思路：** 可从深蓝灰与暖白、搭配少量琥珀色开始，也可用明亮灰白与清晰冷色强调。共同原则是用色彩和明暗区分重点与环境，不把“探索”固定成黑底或昏暗。

**布局与排印：** 阅读顺序明确，重点与辅助信息之间有可辨差别。可采用调查编辑、研究笔记或清楚的版面分区；字形和小标记有秩序，不让装饰符号成为另一套难懂编码。

**造型与材质：** 精细线条、层叠纸面、干净的几何边界或现代信息编辑风均可作为候选。神秘道具、聚光灯或放大镜不是该方向的必要外观。

**适用与调整：** 适合需要观察、比较、发现的内容。外观神秘但难读时，先恢复文字与背景的明暗分离；版面变成等权资料墙时，重新组织主次。

<a id="art-clear-punchy"></a>
#### 理性爽快：清晰、利落、有分量

**配色思路：** 可用黑白或灰阶建立结构，配钴蓝、朱红等明确强调；也可选高辨识的双色或多色关系。统一的是颜色用途，不是每一场都同底色。

**布局与排印：** 对齐有秩序，字级和面积差异果断，重要信息有足够存在感。可参考现代信息海报和编辑设计；无衬线、衬线或混合排印都要看实际中文字形，不固定一种字体家族。

**造型与材质：** 干净的几何、清楚边界、少而有作用的材质层次。可以大胆、厚重，也可以轻巧、精细，取决于整体视觉判断，不等于白纸黑字或取消装饰。

**适用与调整：** 适合重视解释、比较和清晰判断的内容。压得太密会损害爽快，应删弱信息、放开间距；太空则增加有意义的面积和构成，而不是持续复制标题页。

<a id="art-playful-objects"></a>
#### 奇趣卡通：轮廓鲜明、比例有性格、容易辨认

**配色思路：** 可用清楚分离的大色块、奶白或深色基底、适量高纯度颜色；也可尝试粉彩配深轮廓。色彩服务形状识别，不能因为可爱而让轮廓与背景混在一起。

**布局与排印：** 大小、正负形与形状关系有趣，字形饱满或带手绘性格，准确阅读区仍清楚。布局可以自由而有秩序，不强制居中和等大卡片。

**造型与材质：** 纸片、手绘、平面插画、黏土感或玩具感是不同候选。选择一种有一致性的材质逻辑，不是所有物件都加脸，也不必增加复杂角色和三维模型。

**适用与调整：** 适合形象化、轻趣味或低理解门槛的表达，年龄气质要与受众相符。幼龄受众可以更简洁，大众内容可更成熟；可爱掩盖重点时减少装饰，轮廓相似时调整形状和比例。

<a id="art-immersive"></a>
#### 沉浸叙事：有空间、触感与整体氛围

**配色思路：** 从整体环境的明暗、冷暖和材质关系形成连续气质；可以偏自然中性，也可以偏风格化的冷暖对照。某些场面明亮、某些较暗都允许，不把沉浸限定为暗调和低饱和。

**布局与排印：** 画面空间可以更舒展，文字像整体构图的一部分，不额外盖上一层无关课件。字体、间距和画面边缘之间有呼吸，必要信息保持实在清楚，不以少字或小字作为目标。

**造型与材质：** 摄影感、真实纹理、插画空间、触感纸面或统一的图形环境均可尝试。空间层次来自前后、明暗和面积关系，不是统一模糊背景。

**适用与调整：** 适合希望观众投入一次经历、观察或氛围的内容。画面漂亮但无重点时重新安排注意；过度滤镜导致细节丢失时恢复材质；统一气质不等于所有场面同色、同布局。

### 美术判断与动效判断分开

本页只提供审美方向。实际作品的颜色、布局、字体与材质由美术确定；运动、声音和源素材选用由当前场面设计决定。方向不禁止强烈动作、硬切、原色素材或跨题材趣味画面，也不要求逐一实现某个配色示例。

需要重做配色或布局时，读取相关方向和通用美术方法即可，无需读取六篇旁白案例。文案主语、某组数值或具体镜头内容不是本页的规则。
<!-- VFC:END:ART-DIRECTIONS -->

### 5.2 动效先有完整变化，不等于先画完静态页面

导演和视觉作者根据当前正文、已有画面、前后关系与明确要求设计主要观看过程。普通背景尚未选定时，独立图形、排印和主要动作可以探索；只有确实依赖抠像、跟踪、精确标注或原件内容的部分，才需要先确认相应材料。

构图、文字、背景和主要运动共同形成。入口、中途、主读和出口是同一过程中的状态，不是四张孤立页面。一个场面可跨多句，一句也可跨多镜，字幕换卡不决定镜头边界。

视觉作者发现台词不适合当前表达时，可以按第2章发起改稿；没有适合的画面或视觉变化不够时，可直接提出补材，不等到最终预览才暴露。

### 5.3 机制检索与组合

按本段实际需要检索可迁移的动作关系，而不是按题材或六方向筛选。沿现有工具完成候选召回、完整机制阅读、必要范围的动态观察；有语义检索 Job 时读回真实结果，不能把暂时的词法结果称作全库无匹配。[R3]

采用结果写回当前演出：借了什么关系，本片由谁承担，哪些外观不用，接入和退出还需要补什么。允许局部借鉴，不强制复刻全部案例；但只借一个渐显，不能报告成完整关系复现。

段内可以由前一步结果推动下一步；不同层可以共同变化；对象与文字可以按父子关系跟随；新旧重点可以交叠，也可以有明确、好看的切镜。它们是可选办法，不是每段配齐的动作套餐。

### 5.4 节奏、起势与惯性进入实际时序

在需要力量的主要表现中，明确发起者、准备方式、释放阶段、主要落点以及收势或继续通过。准备可以来自方向、尺度、重心、姿态或观察变化；惯性可以由主体、附属层或镜头关系表现。具体手法由对象与内容决定，不由“温暖、理性”等口吻决定。

`spring()` 和插值函数是工具，不会自动生成完整的准备、发力、主从关系和接续。受管编译器已允许基本动画接口，重点是如何实现当前演出，不是另建播放器。[R12][R14]

| 实际退化 | 优先检查和修改 |
|---|---|
| 全部元素同起同停 | 区分观察层、主体、文字和附属层的控制关系，而非随机错开 |
| 写了过冲，画面却停在落点 | 检查位置、尺度是否共用了裁成 0～1 的透明度进度；分开合法范围 |
| 对象走了，字或影子留在原地 | 修父子归属、局部偏移和投影关系 |
| 两种运动互相覆盖 | 分层变换或统一求值，避免最后一次 `transform` 覆盖前者 |
| 接点突然刹停或跳位 | 对连续通过处核对位置和速度；需要读清时允许稳定 |
| 进入或退出被裁掉 | 检查对象挂载时间、局部窗口和需要的交叠，不能由文件结束强制切掉动作 |
| 动作结束后长时间只换字幕 | 查讲述重复、材料乏味或缺少后续发展，再改稿、换材或改演出 |

时序先用秒与相对关系设计，再按实际声音和材料校准并落帧。没有用户要求固定长度时，不为凑时长冻结、循环或增加空等待。普通字幕以可读为目标，画内文字可以充分参与表现。

### 5.5 源码与声画反馈

同一视觉作者沿采用稿实现和返修。源码漏了设计就修实现；忠实实现仍不好看就改设计；正文妨碍理解或声画关系时就回文案，不把“已经配音”当作永远不可改的理由。

素材和图形可以松耦合：普通背景直接提供主题氛围，图形独立解释；也可以共场或附着，视条件决定。普通素材替换检查裁切、绑定、图层、声音与接点，不因此自动改动无关旁白。

`TimelineVideo` 保持作品根源时钟；嵌套 `Sequence` 的布局时间不能令源片重播。技术拆件按共同时间和源范围换算，采用一件还是多件作品服从当前连续范围，不以数量作为观感判断。命名事件与动画共用时序，内部静音视频需要的原声通过既有声音链明确接入。[R6]

实际动态与听感必须基于对应产物观察。静帧只能支持构图等局部结论，不能证明惯性、速度或声画接点已经成立。试排只负责尽早发现问题，创作方法仍负责给出下一种更好的方案。

## 6. 怎样真正接入项目

### 6.1 接入的含义：改作者会读的方法，再同步为可用插件

这里不是把一段文字交给模型就宣布完成，也不是在 TypeScript 中 `import` 一篇 Markdown。实际接入分为两条链：

```text
开发时：
本实施文档
  → 修改 .agents/skills/ 下的入口和专业方法
  → 新增独立的规律参考与案例文件
  → 按既有脚本同步到 plugins/videoflowcut/skills/
  → 校验、构建、按项目现有方式启用相应发行版本

生产时：
用户提出视频任务
  → 进入已有的协调／导演／专业 Skill
  → 作者读取当前任务相关的方法，形成实际产物与续作请求
  → 主任务通过已有 MCP、Job、Revision 和渲染链完成正式操作
```

Skill 定义工作方法和何时使用工具；MCP、Worker 和渲染器执行正式操作。修改方法不会自动下载素材、自动重生成既有项目或自动部署。Codex 的一般技能机制采用逐步读取：先发现元信息，选用后读取入口，需要时才读取参考；因此这里明确把规律和长案例分开，不把它们全部塞进入口。[W2]

### 6.4 案例的按需读取是文件与入口共同实现的

建议生产读取关系：

```text
写作任务 → narration-writing/SKILL.md
             ├─ 正常写作：writing-methods.md 的相关方法
             ├─ 需要表达定向：expression-patterns.md 的相关规律
             └─ 需要具体示范：examples/README.md → 所选单个案例

美术任务 → visual-treatment-planning/SKILL.md
             ├─ art-direction.md 的当前方法
             └─ 需要审美定向：art-directions.md 的相关规律

素材／动效任务 → 自己的专业入口与当前任务信息
                 不默认经过六篇旁白案例
```

`references` 目录或一个链接，不是程序自动执行的导入。入口必须写清“何时读取”，作者实际用现有读取能力打开所需文件；框架若把整个目录拼进提示词，必须修对应加载行为，而不是仅声称已按需。[W2]

六个案例是普通参考 Markdown，不创建独立 `SKILL.md`、不放到六个新的顶层 Skill 目录、不写入 `AGENTS.md` 或每次系统提示。长案例分文件，可以避免只想看一种口吻却读取全部正文。不同文件进入上下文后，不能声称它会自动被移除；这里控制的是初始和无关读取。

现有同步脚本将 `.agents/skills/` 同步到插件的 `skills/`，并为 `_shared` 生成仅供引用的内部入口。不要让新增参考另起自动工作流，也不要手改发行副本来绕过维护源。[R18]

### 6.5 数据和执行代码保持聚焦

主题取材、补材、改稿和返修继续使用现有任务、消息、`CreativeDecision` 与项目对象。没有必要增加风格服务、通用改稿审批器、主题素材池、逐句覆盖表、自动案例学习器或六方向加载引擎。

先验证实际调用中是否存在：无正文就无法发主题需求、首个下载成功就错误关闭全部取材、普通背景替换自动重配整片、编排后拒绝合理改稿、入口主动读取全部案例。存在才修改具体消费者；没有就不新增功能。不要删除真实的版本、权限、资源与证据校验。[R8][R11][R17]

**明确的容量改动：** 在 `packages/motion-work/src/schema.ts` 删除以下总数判断，而不是将四改成另一个小数字：[R4]

```ts
if (Object.keys(value.videoBindings ?? {}).length > 4) {
  ctx.addIssue({ code: "custom", message: "单个作品最多绑定4路视频" });
}
```

同步 `videoBindings` 描述、实际能力响应和 `remotion-production/references/remotion-component-contract.md`。保留槽位名、哈希、源范围、正常速度与作品时长对应、安全和资源校验。

现有视频 Provider 通过分块、串行解码、内存帧缓存和磁盘回收工作，先复用再测试；单块预算不等于整个浏览器内存预算。内容使用数量由导演决定，后台管理真实负载；超出能力时明确返回诊断，不静默删镜头、降质量或发布半件作品。[R5]

## 7. 验证与交付

### 7.1 分清四种验证

**文件接入验证**检查入口链接、规律与案例的物理拆分、维护源和发行副本一致；**工程验证**检查真实接口、绑定、时钟、资源与副作用；**工作流验证**检查是否实际发生改稿、补材和按需读取；**作品验证**检查文字和声画是否达到目标。四者不能互相代替。

建议新增 `tests/skill-reference-routing.test.ts` 和 `tests/motion-video-bindings-capacity.test.ts`；具体测试需要结合现有测试夹具实现。这些名称是拟新增文件，不表示本轮已运行。

文件测试验证相对链接都指向已存在文件，六个案例不含独立 Skill frontmatter，没有入口要求无条件读完全部案例；比较源目录与同步结果。不能仅通过字符串包含“按需”就证明真实按需读取，也不能通过文件数量证明创作质量。

容量测试使用超过四段的顺序片段、同源多范围与交叠输入；仍测试非法范围、错哈希、越界槽位和源时间。没有变更内容的输入不注入无关默认值，检查作品身份与缓存语义是否保持。未知 Job 不重放，真实资源失败不发布半件结果。

### 7.2 工作流验证用例

下列是隔离评估场景，不是每次生产的必做步骤，不带固定题材和固定素材清单。

| 验证场景 | 应当观察到的行为 |
|---|---|
| 仅给一个新主题，没有完整稿和分镜 | 导演先明确目标，文案与主题取材并行，不索要逐句素材表 |
| 首批文件只有主题语境，不能逐句演出知识 | 保留有观看价值的候选，能够进入编排，不被高语义匹配要求全部淘汰 |
| 一个普通候选失败，其他类型主题画面可用 | 换其他有用画面，继续制作，不死守原镜头或自动改稿 |
| 编排发现正文准确，但解释太密、铺垫不足或缺吸引力 | 视觉／导演发起具体改稿，原文案交回真实新稿，重新回到当前场面；不能以“事实没错”拒绝 |
| 第一批取材已完成，制作中仍感到画面少、同质 | 原素材作者继续补材，真实结果分批进入当前编排，不以“素材阶段结束”拒绝 |
| 视觉发现更好的声画方案需要改动表述 | 文案与视觉共同调整，导演协调主要关系，更新实际受影响依赖 |
| 只换普通背景，内容和指代无变化 | 更新画面、绑定和必要接点，文本与无关配音不被无条件重做 |
| 准确展示与来源不一致 | 核实或修改主张，不因允许广泛配图而放过事实错误 |
| 正常生成一条内容，没有请求示范 | 入口不预加载六篇案例，不复制某个题材的场景、查询或结尾 |
| 要求改进一种具体讲法 | 先使用相关规律；确需示范时只读取所选案例，明确比较才追加 |
| 只要求调整整体配色和布局 | 使用通用美术方法及相关美术规律，不必打开旁白案例 |
| 只进行机械的字体或位置修订 | 处理当前实现与真实依赖，不重启选题、研究、六方向比较或全库检索 |

记录可见的读取、任务、稿件、文件和版本结果。若环境没有可观察的读取证据，按需加载结论保持待验证，不能仅凭作者声明认定。没有可调用自动编排接口的行为，用真实隔离制作任务验证，不伪造一个单元测试来替代作者工作。

### 7.3 效果验证仍对应四个原始目标

文案只听正文，能否理解主题、关键原因与结论；六方向是否保留同等必要知识，而不是一版有解释、另一版只讲情绪。完整脚本被实际修改过，也不能自动说明更吸引人，要读听当前产物。

素材看可剪选择、主题语境、变化与实际使用，不看每句话是否匹配一条专属视频。重复材料、跨题材反应和普通背景都由实际观感判断，不设固定比例。

动效正常速度看进入、变化、惯性、阅读和接续，先核查有没有实现，再判断好不好看。密集帧和慢放可定位问题，不代替正常速度观感；函数名和事件名不是完成证据。

美术看色彩、布局、排印、形态、材质与整体一致性，而不是是否照搬某篇旁白中的物件。声音看自然表达和与动作的配合，不只看响度值。

真实观察不足的部分标明未知，技术可导出继续允许；已发现的创作问题仍交回对应作者。复用现有审阅记录，不新增审美分数门禁。[R7][R15]

### 7.4 实施顺序与完成报告

先建立两份规律参考、短案例索引和独立案例文件，更新相关入口；同时将主题广搜与可回改回路写入共同流程、素材与导演方法。不是先完成六个风格的全片验证，再开始素材优化。

随后用一个主题测试真实首轮取材、编排阶段改稿、制作中补材、普通替换不连带改稿这几种行为。用实际材料实现一个有前后接点的连续范围，检验设计、代码和真实声画是否一致。

容量修改可并行，在隔离环境通过相关回归后用于多素材制作。最后换至少一个不同内容领域检查可迁移性：入口不生成固定行业查询，知识研究适应当前题目，素材和动效仍按实际需要选择。测试题材是评估输入，不写进生产规则。

交付说明包括实际修改文件、关键引用链、工程测试、实际读取的参考、改稿和补材如何回到编排、看过哪些产物、当前发行与安装状态、尚待处理的内容。不得把本文的设计和示范报告为已经渲染或验证的结果。

**完成的标志不是“职责写清了”，而是既能看到作品效果，又能在流程中实际发起并接回合理的修改；通用方法可以换主题使用，案例只在需要时提供帮助。**

### 轻松有梗｜同题旁白参考

**教学主题：** 机票改签为什么可能贵。此处保留一个有明确来源的知识解说样本，不将其当作所有主题的生产模板。数字在旁白中已明示为举例；实际新片须核实当次适用事实。

**先理解通用方法，再读例文：** 保留完整的原因解释，以具体经验进入，用贴合事实的落差和短评论降低距离感。幽默不能替代知识；迁移的是交流位置和措辞方法，不是某个钱包笑话或固定结尾。

**旁白正文**

> 买机票的时候，为了便宜几十块，你能把几个平台来回翻一遍。临时有事，想把出发日期挪一天，改签页面却让你再补几百。
>
> 日期只动了一格，钱包怎么跟着动了一大截？
>
> 先别急着把这几百块，全理解成“客服帮我改一下”的钱。机票改签，可能同时在算两笔账：新航班的票价差额，还有变更手续费。国航公布的国内自愿改期规则，就把这两项分别规定了。
>
> 差价比较好理解。你原来买到的便宜票，不代表换到另一班，还能用同样的价格。哪怕两班都是经济舱，看起来也没换什么金边座椅，适用的票价仍然可能不同。
>

>
> 再看变更费。这笔钱看的是你买的票适用什么条件，以及在什么时间办理，不只是工作人员操作了几分钟。
>

>

>
> 有些票还分提前多久改。越接近起飞，可重新安排销售的时间越少；这一班空着飞走的座位，不能留到明天接着卖。不过，这只能帮助理解时间为什么重要，不能证明收多少都合理。
>
> 还有一个关键区别：上面说的是你自己主动改行程。因为航空公司自身原因让你不得不改，按规定安排的非自愿改期或签转，不应收取客票变更费，不能直接照搬主动改票的账单。
>
> 所以，改签贵，往往不只是一个按钮贵，而是新航班的票价，加上原来那张票的变更条件，一起影响了你要补的钱。先看清差价和手续费各是多少，再核对适用条款。

**旁白正文**

> 机票写着可以免变更手续费，为什么改签时，还是可能要付钱？
>
> 因为免手续费，不一定免票价差额。要理解改签为什么贵，先把这两项分开。
>
> 票价差额，是新航班的适用价格比原票更高时，需要补的那一部分。变更手续费，则按这张票适用的改期条件收取。国航的国内自愿改期规则，分别规定了这两类费用。不是每次都有两项，但不能把补交总额全部当成手续费。
>
> 为什么换过去还会更贵？机票不是同一路线永远同一个价。不同日期、不同航班，以及不同价格的票还能不能使用，都会影响你能得到的票价。
>
> 即使新航班还有经济舱座位，也不能据此判断原来的低价还在。航空公司会管理不同票价的可售数量。空座是乘坐位置，票价是销售条件，这是两件事。
>
> 变更费同样不只是一次操作的成本。不同票种可以有不同的退改条件，有些购买价较低的票，改动限制会更严格；更灵活的票也可能卖得更贵。这是把价格与使用条件组合起来销售的一种方式，并不意味着便宜票一定严格，或者贵票一定能免费改。
>
> 有些条件还按办理时间区分。提前很久改和临近起飞改，适用的费用可能不同。座位的销售机会会随着起飞而结束，航空公司需要管理变化带来的影响；但这不能直接证明某一笔费用等于实际损失，更不能证明收费越高越合理。
>
> 算账只需一个例子。假设新航班比原票贵200元，这张票当前另收100元变更费，本次合计补300元。这里的数字是举例，不是标准费率。
>
> 如果只免了变更费，200元差价仍可能需要补。反过来，新航班没有应补差价，也不代表原票的变更费自动消失。
>
