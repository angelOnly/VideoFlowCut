# VideoFlowCut：物件制作能力迁移与超现实拼贴接入方案

> **目标：让物件凭借自己的形体和部件完成表达，不再把本应发生的动作主要交给花字、标签和通用色块。**
>
> 核对日期：2026-10-16。项目基线：`d47c7d3b0608f84ec4511679b0710005d941f234`，插件 `0.1.92`。参考仓库基线：`chuspeeism/dashi-animationstyle@aa620f3b859aa5d191b783b2eb0fb59263731c76`。[1][2]
>
> 本文交付已确认的实施方案、案例制作要求和可直接写入项目的 Skill 指令；物件源码移植、实际渲染与效果验收由后续开发完成，不把原仓库演示视为本项目已经验证。

## 一、本次需求与解决方向

### 1. 要解决什么

当前需要补强的不是普通入场、转场或花字质量，而是主要表现对象的制造和使用：视觉方案选择了一个物件，最终画面却可能仍是写着该名称的矩形；动画虽然流畅，观众看到的主要还是标签移动，而不是物件执行动作。

本次需要同时补齐两项能力。

**物件制作能力。** 从已有源码中学习轮廓、厚度、材质、部件、轴心和遮挡，制造能够辨认、能够控制、能够参与演出的主体。对象不必是三维模型，但不能只靠名称成立。

**主要画面的选择与兑现。** 视觉作者在整场构思时决定由真实材料、实体物件、关系图形还是文字承担主要表达。采用物件后，让它参与过程并产生结果；不是在原有花字页面旁边再摆一个漂亮图标。

超现实拼贴的配色、纸面、材质对照和排印同时作为可选美术参考接入。**物件能力与风格分开：会画物件不要求全片采用拼贴，采用拼贴也不代表所有镜头都必须造物件。**

### 2. 为什么选择“源码示范＋现有方法增强”

参考项目不是凭“高级、超现实”几个词自动生成主体。它提供具体物件函数、完整演出示例和风格卡；其主 Skill 也明确说明画面由 HTML/Canvas 代码绘制，不使用生图模型。剪刀、放大镜、骨牌和开顶石雕均能在公开源码中定位。[2][3]

VideoFlowCut 已经具备主体关系、关键中途、部件跟随和连续演出的指导，不需要重新建设意图转化流程。[4] 真正需要增加的是可参照的物件制法，以及防止已选主体在实现中被标签代替的具体要求。

只有案例而没有使用方法，作者可能仍然默认做文字；只有“多做实体”的要求而没有画法，结果可能退化成粗糙图标。因此，**本次开发必须同时交付实际绘制案例和本文的使用指令，只追加 Skill 文字不算完成。**

### 3. 保留什么

保留现有视频类型、六种表达方向、偏好入口、导演与持续视觉作者、素材共创、动效机制库、重点花字、普通字幕、配音、声音、真实时钟及渲染合成流程。原有方法不删减，不把“物件化”变成逐句配实体，也不把静态图片、原件或真实视频全部换成原创图形。

本次不迁移外部完整工作流，不新增物件代理、独立渲染器、物件数据库或强制逐镜审批。具体风格只作用于当前稿已采用的全片或连续范围，不覆盖其他任务。

## 二、迁移什么，以及由谁渲染

### 1. 保留现有渲染器，迁移主体画法

```text
参考项目
物件轮廓、材质、部件与动作状态
        ↓ Canvas 绘制
浏览器逐帧截图 → 视频合成

VideoFlowCut 接入后
本片内容与实际材料 → 选择主要表现方式
        ↓
读取物件案例 → 制作 React/SVG 主体 → 组织本片演出
        ↓
现有受管 TSX 编译 → Remotion／Chromium 渲染 → 原视频合成
```

“不迁移渲染器”是继续使用 VideoFlowCut 已有渲染器，不是取消渲染。当前编译器允许受管 React、CSS、SVG、图片和视频，禁止原生 `canvas`、浏览器 `document` 及任意模块导入；不能直接把参考 HTML 放入现有受管源码。[5]

SVG 与 Canvas 可以表达相近的路径、渐变、分层和二维变换，但绘制方式、合成语义与性能并不完全相同。**本次目标是保留这些案例的形体、部件和演出质量，不承诺自动转换、逐像素一致或相同耗时。** 密集颗粒、复杂滤镜和大范围像素处理必须单独验证。[3][5][6]

| 原 Canvas 做法 | 在本项目中的迁移方式 | 必须保留的内容 |
|---|---|---|
| 曲线路径、椭圆、多边形 | SVG `path`、`ellipse`、`polygon` | 识别轮廓、比例和有用细节，而不只是外接矩形 |
| `save/restore` 与坐标变换 | 嵌套 `g`、显式 `transform` | 部件归属、旋转中心、变换顺序 |
| 渐变、侧面和边缘明暗 | SVG 渐变与独立色面 | 材料区别、厚度、明暗转折 |
| 裁剪、开口与前后覆盖 | `clipPath`、适用的遮罩及绘制顺序 | 内部可见范围、前缘遮挡和作用位置 |
| 按时间改变开合、翻面与摆动 | 由当前帧计算状态，再传给绘制组件 | 动作中途、对象响应和连续性 |
| 离屏缓存的复杂纹理 | 适合的固定 SVG 细节，或预先制作并正式绑定的纹理图片 | 质感与放大清晰度；不照搬逐帧大量绘制 |

纹理确需图片时，使用既有素材取得与 `imageBindings → props.assets → Img` 路径。不得直接把本地路径、网络地址或 SVG `image href` 塞进受管源码。图片如何参与遮挡，应以当前能力和实际渲染为准。字体继续使用正式 `fontBindings`，不继承参考项目的 macOS 字体环境。[5][7]

### 2. 源码怎样组织

每个已移植案例的 `source.tsx` 应是可独立提交的受管演示源码，内部包含物件绘制、状态计算和演示场面。正式制作只选取当前需要的部分，整合到本片源码，不提交整套示范剧情。

```text
物件绘制组件
    轮廓、部件、材质、局部轴心；根据输入状态绘制
        ↑
本片场面状态函数
    整体位置、部件动作、接触／显露、受作用对象与后续结果
        ↑
当前作品帧、准确内容、已采用时序与实际材料
        ↓
同一受管作品输出；需要声音绑定时共用实际事件时序
```

开发时落实以下细节，不改变现有 API：

- **时间只计算一次。** 在作品根层取得当前帧，再向主体传递同一场面时间；内部 `Sequence` 的局部帧不能重复减起点。状态不依赖上一帧播放结果，任意跳帧仍得到同一画面。设计用秒，正式时序按真实声音和作品 fps 落帧。[7][8]
- **部件必须能单独动作。** 关节围绕实际轴心旋转，附属物跟随所属部件，容器前壁独立遮挡内容。先满足所需动作，再决定分件；不把所有层烘焙成只能整体移动的图片。
- **转换绘制语义，不只替换函数名。** 核对弧度与角度、局部原点、矩阵顺序、填充规则、透明度和裁剪范围。SVG 渐变、遮罩的 ID 使用稳定的实例前缀，避免多个物件互相引用。
- **保留内容与状态身份。** 切开、翻面或移交之后的对象仍对应原内容；事件点与动画共用状态／时序函数。接触、切开、落定不是同一个时刻，不能把声音全部绑到入场开始。[7]
- **示范不是新运行时库。** 当前不允许任意本地组件导入。作者读取已验证源码，将必要函数、常量和依赖放进本片受管 TSX；不得写一个尚未开放的 `@videoflowcut/objects` 导入。构建时如有拼接，应在提交前形成完整源码。

## 三、物件参考：案例、交付内容与参考指令

### 1. 首批案例怎么选

先迁移原仓库能够核到源码的案例，再用新对象验证画法是否真正可迁移。下表是开发范围，不是每条视频必须使用的物件清单。[3]

| 本地案例目录 | 原始定位或来源 | 本次重点 |
|---|---|---|
| `scissors-cut/` | `scissors`、`drawScissors`、`drawStrip`、相关切割时序 | 刀刃与握柄围绕轴心开合；切口、纸片分离和结果共同发生 |
| `magnifier-scan/` | `magnifier` 及数据区观察场面 | 镜框、握柄、镜片、高光和扫描指认；不把原示例冒称为已实现光学放大 |
| `domino-flip/` | `domino`、`domState`、纸片翻面与落地 | 正面、侧面、顶面、翻面中途和落地响应；不等同于任意视角三维旋转 |
| `cutaway-head/` | `headPath`、`HEADTEX`、`drawInterior`、`drawHead` | 复杂轮廓、石材质感、开口厚度、内部承载和观察尺度；保留制法，不固定后续主题必须用人头 |
| `bowl-receive/` | 本项目新设计，验证迁移能力 | 碗口、内部、前壁与内容物的进入、遮挡、落定 |
| `book-open/` | 本项目新设计，验证迁移能力 | 封面、书脊、页块厚度、独立页片及展开／翻页 |

碗和书籍不是本次已经核实的原仓库对应案例，也不是已完成的移植。它们用于检验作者能否从“开口遮挡”“铰接与翻面”等画法制造新主体，避免接入后只能重复几个现成道具。

原仓库的 `styles/超现实拼贴/示例_Token.html` 是完整演出源码，`模板.html` 保存绘制基础，`风格卡.md` 说明函数与适配方法，`docs/3_超现实拼贴.gif` 和同目录静帧用于对照。模板里的标题与关键词骨架不是新内容的最终场面，必须替换成实际演出。[2][3]

### 2. 每个案例交付什么

案例统一放在现有视觉 Skill 的参考目录，一案例一个完整目录，不另注册为独立代理。

```text
.agents/skills/visual-treatment-planning/references/
├── object-drawing/
│   ├── REFERENCE.md             下面给出的统一参考方法及本地索引
│   ├── LICENSE                 复用代码对应的原许可
│   ├── SOURCES.md               原仓库版本、文件、函数与改编范围
│   └── cases/
│       └── <案例目录>/
│           ├── case.md         用途、造型与动作说明、完整复现指令、检查状态
│           ├── source.tsx      本项目受管环境可执行的完整演示源码
│           ├── demo-props.json 演示固定参数；有绑定时同时写清真实准备方式
│           ├── preview.mp4     从该源码实际生成的动作片段，可为无声
│           └── keyframes/      体现轮廓、部件关系和关键中途的实际帧
└── surreal-collage.md           下文给出的可选美术规则
```

演示必须包含自身动作及必要的受作用对象，不只做物件展示转盘。静帧与视频须对应同版源码；原示例画面只能标作原参考，不能冒充移植结果。案例记录源码、参数、资源与输出的版本／哈希关联；没有完成渲染或连续观察的范围照实说明。

`case.md` 使用以下内容结构。不要只写“高级、丝滑、有体积”，也不要求日常作者每次重新填写：

```markdown
# 案例名称

## 用途与来源
说明解决哪种造型或动作问题。记录原始文件、函数、版本与改编范围；
新设计明确注明，不声称来自原作者。说明哪些情况不适合直接复用。

## 物件怎样造出来
说明辨识轮廓、比例、前后部件、局部轴心、材料与光向。
将关键决定指向 source.tsx 的实际组件或函数，不只描述最终印象。

## 动作怎样发生
说明初始状态、主体自身动作、接触或遮挡的关键中途、另一对象的响应、
结果与后续状态。标明 preview.mp4 中相应范围及真实关键帧。

## 复现与改写指令
写清使用哪些源码、参数与实际资源，怎样提交到现有受管链路。
哪些结构和动作关系需要保留，哪些颜色、形体、节奏或对象身份可以修改。
给出能够重新制作本案例的完整自然语言指令，不只提供源码文件名。

## 验证与边界
记录真实渲染结果、观察方式和覆盖、已知限制、未确认部分。
标明是原作者示例、本项目移植还是新物件设计，不混用认可状态。
```

**剪刀案例的复现指令应达到下面的具体程度：**

> 制作具有双刀刃、双握柄和中央轴心的剪刀，保留金属刀面与握柄的材料区别。两组刀刃和握柄绕同一轴心反向开合，挂在握柄上的标签随该部件运动并有独立的收势。安排纸条与剪刀在同一场面中交互：剪刀到达实际切口并合拢之后，对应纸段才分离；碎片的身份、翻面与落定继续可追踪。用统一时序控制剪刀与纸条，不用两段互不相关的入场动画拼接。将几何、部件状态和演示时序分开，移除原题材关键词依赖。演示长度依完整动作需要确定，不继承原样例的固定次数或总长。

这段是案例自身的制作指令；日常生产仍根据本片内容选择和改写，不要求所有视频使用剪刀或切割过程。

开发期可以用原 HTML 在隔离的本地环境核看参考，但原渲染脚本不进入生产依赖。复用代码保留 MIT 版权与许可；作者口播不随案例打包，字体文件不随包分发。[9]

### 3. `object-drawing/REFERENCE.md` 完整指令

**新建文件：** `.agents/skills/visual-treatment-planning/references/object-drawing/REFERENCE.md`。

以下正文直接采用；案例目录与索引对应上一表。它教作者如何看懂并迁移案例，不是另一条生产流程。

```markdown
# 物件绘制：从案例到本片主体

在当前画面需要可识别、可表演的物件，或已经采用的主体退化成名称色块时，
由当前视觉作者使用本页。先读取当前声画稿、实际材料和已有设计；
原美术、机制参考、完整演出与受管实现继续执行，不另建物件任务流程。

## 按结构与动作选择案例

先确定本片物件要做什么，以及它需要哪些部件才能完成。
不要只按名称检索，也不要为了使用现成案例而改写本片事实或硬套比喻。

需要铰接开合和接触后的变化，读 cases/scissors-cut/case.md；
需要镜框、镜片与扫描指认，读 cases/magnifier-scan/case.md；
需要厚度、翻面和落定，读 cases/domino-flip/case.md；
需要复杂轮廓、材料表面和开口内部，读 cases/cutaway-head/case.md；
需要容器前后遮挡，读 cases/bowl-receive/case.md；
需要书脊连接、封面和页片展开，读 cases/book-open/case.md。
先读解决当前问题的案例，只有缺少另一种结构时再补读，不通读全部源码。

## 先看完整动作，再定位画法

观看案例的相关完整动作和接续，确认物件如何被认出、哪里能动、
谁被遮挡、接触何时发生、另一对象怎样改变、结果如何留下。
关键帧用于辨识结构和中途，不能代替连续动作观察；只有静帧或源码时，
把据此推定的过程与实际看见的内容分开，不写成已经观看通过。

随后对照源码，找到物件轮廓、部件与轴心、材质、遮挡及状态函数。
观察记录应能指向真实函数和画面：不能看完只剩“推进、强调、让位”几个动词。
不要只读取入场和转场代码，忽略物件自身动作与受作用对象。

## 先保留关键结构，再适配本片

在本片需要的观察尺度下保留轮廓比例、重要部件和材料层次。
按实际动作保留关节、开口、前缘、页片或连接部位，不把它们合成一张只能平移的图。
更换身份、配色、比例和构图时，原来承担遮挡、接触和反馈的结构必须有对应做法。
代码复用不是让所有物件长成同一个模板；主体不同就重画识别结构。

把案例映射成本片实际对象及关系。无需继承原题材、台词、道具组合、
固定切割次数、镜头顺序和总时长。新对象可以组合已掌握的结构画法，
但其轮廓与动作必须重新检查，不能仅凭“与案例相似”登记为已验证。

## 让物件参与表达，而不是摆在花字旁边

同时设计物件自身动作、它作用于什么、对方何时响应及留下什么结果。
只有整体飞入、缩放或漂浮，不足以证明已采用的切分、容纳、翻页等行为完成。
原内容不需要交互时，不强造接触；姿态、观察距离、结构展开和材质表现也可承担观看。

在当前“画面与演出”正文说明本次具体采用的主体、结构和过程，
以及文字承担的身份、条件、比较或结论。沿现有完整稿深化，不另写学习心得表。
制作到一半发现换载体更合适时说明表达变化，按原采用边界协调，
不能因为文字更容易画就静默删掉主要主体和动作。

## 使用当前受管源码与时钟

从案例选取必要组件、状态函数及其依赖，整合进本片受管 TSX；
不新增任意本地模块导入，不直接执行原 Canvas HTML。
以真实 Props、资源和当前帧驱动；稳定的实例 ID 避免渐变与遮罩串用。
图片、字体、视频和声音分别沿现有绑定，案例的项目 ID 不能复制到本片。
按实际讲述与观看时间重排动作，不整段压缩或拉长原案例去填满口播。

## 回到实际画面检查

对采用实体的部分，可以在诊断预览中暂时隐藏身份标签，检查物件是否可辨；
这不要求去掉文字后整段知识也能独立成立，更不能把诊断改动保留为正式成片。
再检查关键动作、遮挡、接触与结果是否真的发生，是否与本片美术及前后关系一致。

造型失真修轮廓与材料；关节或遮挡错误修结构；动作不成立修场面状态；
设计明确但漏做修实现；忠实实现仍不适合本片则重选表达。
使用同源预排和原有审阅，只有实际检查过的范围才记录结论。
```

## 四、接入现有创作链路：具体文件与修改正文

### 1. 谁在什么环节使用

导演继续决定内容、表达目标和跨段关系；文案与素材照原流程参与共创。**主体选择发生在视觉作者形成主要场面的阶段，而不是排好花字页面之后再添加物件。**

```text
当前声画稿＋实际材料＋本片方向
                ↓
现有视觉作者选择主要表现方式，并与导演共同采用
                ↓
需要实体 → 读取物件制法案例 → 在本片源码中制造主体
                ↓
现有演出方法组织主体动作、材料、文字、声音和接续

现有受管渲染与合成 → 检查已采用的主体是否真正兑现
```

## 五、`surreal-collage.md`：可直接采用的美术正文

**新建文件：** `.agents/skills/visual-treatment-planning/references/surreal-collage.md`。

以下是项目化正文。色值取自原风格卡，用作明确选择此风格时的起始方案；不迁入其固定页眉、字幕区、逐字上色、全场慢推和转场配额。[3]

```markdown
# 超现实拼贴：纸面、实体与图形共同演出

仅在用户明确选择，或当前稿已采用本风格的全片／连续范围中使用。
沿既有视频类型、表达方向、视觉作者和受管渲染制作；
不覆盖普通字幕，也不要求所有主题沿用同一种比喻、道具或镜头顺序。

## 先建立场面，而不是复制海报版式

以可识别的物件、实际材料和图形关系组成主要场面。
超现实感来自尺度、材料、内外空间或用途的有意义重组，
不是堆放无关奇怪道具。比喻服务理解和感受，不能冒充事实或虚构因果。
主体能够直接表现时不强造比喻；证据与真实材料仍保留必要身份和条件。

重点字、批注、箭头与色面参与场面，但不固定左标题右主体，
不因进入这一风格就增加常驻品牌、页码或整句重复文字。
不同场面保持材料、排印与颜色职责的一致，可以改变构图和观看距离。

## 配色与材料

起始色板：纸底 #e9e5d9；浅纸面 #f6f3ea / #f4f0e5；
主要墨色 #0b1615，次级墨色 #1e2523；
笔刷橙 #ef7e40，物件局部朱橙 #f75e18；
芥末黄 #f2ab11，背景拼贴青 #43a9ad；
需区分重点对象时可用砖红 #a02503 与青蓝 #3aa6c0。

米灰与暖白承接大面积，深色轮廓及实体建立分量，
鲜明颜色优先落在物件、纸片、批注和当前重点上。
这些色值是一套可采用的关系，不要求全部同时出现，也不强制两个核心词永久上色。
明快可以保留，重点在面积与材质有区别，不把所有颜色做成等权平面块。

纸有轻微纤维、颗粒和边缘变化，物件保留与其材料相容的表面。
金属依靠亮暗转折和窄高光，石材依靠斑驳与较粗表面，
纸片依靠薄边、层叠和适当投影。不同材料置于相容的光向和空间中。
纹理用于辨认材料，不遮挡原件阅读，不以统一噪点代替造型。

## 主体、空间与排印

制造主体先确定轮廓、比例、部件与动作能力，再完善质感。
需要开口、厚度、翻面或关节时，保留独立图层与局部控制；
读 object-drawing/REFERENCE.md 获取制法，不把所有对象做成带字纸片。
物件与实拍、原件可以共场，按当前观看决定主次和面积，不固定媒介占比。

重点文字可选粗而有结构的衬线字，辅助标签使用清楚的无衬线字，
手写感批注只在有指认、态度或解释作用时使用。
按真实字体目录选择并绑定，以实际中文字形校准，不假定本机有参考中的字体。
干笔刷、撕边、箭头和纸胶带围绕具体关系安排，不要求每段集齐。
普通字幕继续本片已确认的独立规范，不导入外部字幕纸条或固定字号。

## 动作与接续

物件按结构行动，纸片按薄、轻和附着关系行动，
较重主体通过重心、阻力和收势形成分量。
可以使用拍贴、翻面、纸片遮挡、尺度穿行与空间接管，
但具体过程必须适合当前对象，不给所有东西套同一种弹跳或震屏。

主体行动与受作用对象共同发展，身份标签和批注按归属配合。
背景与辅助层依原演出要求参与进入、响应和接续，阅读时可以稳定，
不把每层持续漂浮、每镜慢推或固定数量转场当作风格成立的证据。

时序以秒设计，再按本片真实语音、源事件和作品帧校准，
不继承原示例时长、切割次数或关键词时间。
声音由原声音作者根据纸、金属、物件动作与当前语气设计，
不复制原作者口播，不给每次出现自动加一声。

## 在当前作品中检查

检查实体是否有辨识结构并承担了表达；颜色是否依附材料和当前重点；
原件是否仍然可读；文字、实体和背景是否有组织地共同变化。
只换成米色底、加大宋体和橙色笔刷，但主要画面仍是关键词页面，不算完成。

用实际同源预排和成片检查构图、关键中途、前后关系及声音。
局部不合适时修具体选择，保持已验证的复杂动作和字幕能力，
不通过减成简单显隐或全片套同一版式解决。
```

## 六、实施顺序、工程边界与验收

### 1. 先制作真实案例，再开放稳定使用

**第一步：固定来源与建立案例。** 保存上述两套代码基线和原许可，核读原样例与函数。先迁移剪刀切割、放大镜、骨牌、开顶石雕；保留造型与完整动作，去掉原题材台词、固定品牌和原声依赖。再完成碗与书的迁移验证案例。此步骤是能力开发，不是每次生产的强制试作。

**第二步：沿当前环境验证。** 查询正式 `read_motion_capabilities`，使用现有受管编译与提交链渲染。静帧核对轮廓、材料和遮挡；连续片段核对自身动作、关键中途和结果。原参考与移植结果按对应姿态比较，允许绘制接口不同，不允许借迁移删掉已采用的主体结构。不能仅凭语法通过就标记“可用案例”。[5][7]

**第三步：写入方法与四处入口。** 保存第三、五节的完整正文，按第四节精确插入。原 Skill 与已接入的气质方法保留；审查 diff，不顺手改写字幕、简化动效或调整无关生产规则。未完成的案例标明状态，不把缺失预览伪装成可查看文件。

**第四步：用真实任务检查选择是否改变。** 在原本需要制作或修订的连续范围中，确认作者在排画面时已经选择实体及其作用，并真正读取相应源码；检查最终是否仍由花字宣布动作、物件只负责装饰。问题按选择、造型、动作、实现分别返修，不要求重做无关段落。

### 2. 关键代码边界

`packages/motion-work/src/compiler.ts`、现有 Schema、Registry、渲染 Worker 和时间线合同本轮保持。变化主要发生在新增案例源码、生产时生成的受管 TSX 及四处 Skill 指令。若实际测试发现具体 SVG 特性被当前链路拒绝，记录该限制，优先以已允许的画法保留效果；不得直接放宽安全限制来执行外部 HTML。[5]

需要动作声音时使用现有 `resolveMotionEvents`，动画和事件共用本版时序；图片、视频、字体使用真实绑定。只补案例说明或审阅文字，不应改变原作品渲染输入；实际改动主体、参数或绑定时，沿现有版本与影响范围重新生成。[7]

本轮不建设可任意导入的通用物件包。以后确有稳定、高频复用需求，再单独评估受信任组件模块；本次文件布局不应假定那项能力已经存在。

### 3. 开发测试与效果验收

可新增 `tests/object-drawing-reference.test.ts`，检查本地索引、文件引用、案例来源和参数完整性，并用现有 `validateMotionSource`、`compileMotion` 检查案例源码。该测试只证明文档接入与源码可编译，不能替代以下渲染和观看检查。

| 检查 | 应取得的结果 |
|---|---|
| 制造质量 | 轮廓、重要部件、材质与必要厚度在实际画幅中成立，不靠身份字才能认出所选物件 |
| 自身动作与交互 | 关节、翻面、开口、遮挡和受作用结果符合采用设计；不是整组平移冒充内部动作 |
| 时间与实例 | 顺序取帧、跳帧后返回同一帧结果一致；多个实例无渐变／遮罩串用；嵌套时间无重复偏移 |
| 从案例到新对象 | 碗和书具有自己的轮廓与结构，不是换名称的剪刀／骨牌；明确新设计的实际验证范围 |
| 创作链路 | 当前稿、作者读取内容、源码和真实输出对应；采用实体的主要行为没有退回花字或卡片 |
| 风格隔离 | 物件可用于未采用拼贴的任务；拼贴只作用于采用范围，不自动启用严肃调查或覆盖六种方向 |
| 既有能力 | 素材共创、重点花字、连续动作、普通字幕、配音、声音和真实绑定不出现规则性退化 |

采用现有技术检查与实际预览，合成时同时检查真实素材、普通字幕和前后接点。不以像素差、物件数量或关键词覆盖作为审美评分；临时隐藏标签只用于诊断。无连续视觉或听觉输入时记录对应未知，不声称整段效果通过，也不因此无限重渲。
