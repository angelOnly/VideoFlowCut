# 第一部分｜当前基础、剩余问题与优化思路

## 1. 结论：需要调整搜索方案，但不重做已经开发的能力

这次开发与素材搜索优化有交集，但并不等同。现在应当保留“机制库里查表现方法”的新能力，继续解决“从外部找到什么内容”的前端工作。旧方案不能原样交给 Codex：它仍把已完成的资格移除列作开发任务，且部分 Skill 的原文定位已经失效。

| 范围 | 当前核对到的状态 | 本次处理 |
|---|---|---|
| 连续制作 | 主题入口、导演、调度和演出方法已经区分内容段落、连续画面与技术文件；开发记录包含整段与拆块一致性测试 | 保留现有方法与验证，不另写一套连续制作流程，不以此宣称生产成片已变好 |

| 素材资格链 | 原采用/关联MCP与HTTP入口已移除；采用服务删除；使用检查已改为实际绑定的技术检查 | 从“待删除任务”改成“保持与回归”，不再次删除播放器、媒体分析或技术绑定检查 |

| 导演与素材作者职责 | 新文档已明确素材作者推荐、导演采用，但导演前半篇仍预先展开搜索，素材入口仍接收搜索起点 | 保留采用职责，进一步把查询构思交给素材作者 |

### 1.1 开发记录能证明什么，不能证明什么

仓库《实施与验收》记录：固定20条开发需求时，原词法、新全文词法、纯向量和混合检索，在“前12项至少包含一个已标注候选”这一指标上，转换查询均为20/20；混合检索用原始意图为15/20。该记录自身也明确没有证明向量比词法更准确。这是有限标注、开发派生样本的命中指标，不是全库召回率、前12条全部相关，更不是素材外网搜索成绩。[T1]

记录还包含288帧连续场面与拆块输出逐帧一致、576项自动测试通过等结果，同时明确没有完成连续视听与完整成片观感验证。本轮读取这些记录而未重跑。**应当认可工程基础已经建立，但不能用该成绩取消对真实查询、指令转换、材料丰富度和实际演出的检验。**

## 2. 本次仍需要修的项目行为

### 2.1 连续稿不等于最终素材规格

新的连续稿已经要求说明入口、发展、持续参照和出口。这有助于组织视频，但交给素材作者时应区分“这段要表达什么”和“作者暂时想到怎样表现”。不能把内部设计中的某个载体、几何位置或运动路径全部变成外部文件必须满足的条件。

当前导演 `asset-briefing.md` 前半篇仍安排导演给搜索起点、倒推具体细节；素材入口又要求接收已经展开的材料角色与搜索起点。开放原则虽在，执行任务仍容易变成按既定找法填空。[S1][S2] 本次改的是搜索构思的职责，不撤掉新建立的连续表达方法。

### 2.2 删除资格审阅，不等于候选不再被拒绝

当前 `adopt_media_fragment`、`bind_media_adoption` 和对应写路由已不在活动工具注册中；`MediaIntelligenceApplication` 已没有原采用/关联服务。`mediaUsageProblem(snapshot, target)` 检查的是实际素材、槽位、就绪与范围；`mediaUsageFindings()`不再读取旧采用状态和覆盖证明。[C3][C4]

但另一条代码仍存在：`manageAssetRequirement()` 的 `searchCriteriaChanged` 因用途、找法或画幅字段的提供而运行，下载中拒绝更新，快照内 `available` 候选写为 `rejected`。[C1] **这是搜索策略与候选生命周期的耦合，不应重新称为“素材审阅未删除”。** 两个问题分别修，避免误删刚完成的能力。

### 2.3 还要修搜索返回与下载完成两端，而不只删一个拒绝分支

已定位四个关键位置：[C1][C2]

- `recordAssetSearch()`：搜索过程中需求版本改变，会拒绝保存返回结果；需求关闭也会使返回失败。
- `acquireAssetCandidate()`：从搜索会话提升候选时，需求版本不同或会话超过24小时，要求重新检索。
- `completeAssetAcquisition()`：文件完成后仍用当前需求再次做候选允许判断，之后无条件写 `fulfilled`。
- `failAssetCandidateAcquisition()`：失败后按在途/候选情况重设需求状态，没有先保护 `closed`。

如果只解除“下载中不准改稿”，后面的当前需求检查仍可能挡住文件登记；如果只删成功时的 `fulfilled`，失败分支仍可能重新打开已经结束的用途。因此本轮须打通“查询发出—结果回来—选择获取—完成登记—需求收口”，不是放宽一句错误提示。

### 2.4 三种搜索各自回答不同问题

| 搜索工作 | 当前主要入口 | 使用对象与边界 |
|---|---|---|
| 外部素材发现 | 宿主网页/搜索能力、`list_asset_providers`、`search_media_candidates` | 找外部候选，查询词直接描述当前内容；不默认附加拍摄或来源身份 |
| 已发现素材的片段查找 | `search_media_fragments`，必要时现有媒体理解 | 对已经进入可读取范围与索引的素材查具体内容；索引为空不等于网络没有素材 |
| 动画机制检索 | `search_motion_mechanisms`、`read_motion_mechanism`，必要时 `analyze_motion_reference` | 在现有运动库找表现方法，发生在动画制作阶段；不把业务主题直接当动作相似度 |

新的机制向量不会自动扩大外部素材来源。素材搜索应保留内容名称与语境，机制检索才提炼可迁移的对象、变化和保持关系。两者共用底层模型运输不等于共用查询或索引。[M1][M2][C3][S5]

### 2.5 语义能力已接通，仍要正确接收异步结果

`search_motion_mechanisms` 首次可先返回全文词法候选和语义Job。没有解析到当前项目时，也可能明确返回纯词法结果；指定项目后才能进入现有Job路径。语义Job完成后，以相同查询输入读取最终结果，核对实际 `diagnostics.mode` 和 `semantic_used`，不能把第一次返回当作向量排序已完成。[M1]

这是日常调用使用方式，不需要重写算法。现有机制Skill已经写了等待Job与相同输入读回，因此本轮主要做真实调用回归与必要澄清，不在每个角色文件中再复制一遍。服务失败可按明确降级使用结果，但不能据降级结果判断“新语义检索没有效果”。

### 2.6 当前工作方法的旧锚点确实不能直接再用

旧方案第7.4节引用的“导演与文案先共同发展”“候选材料及观察交原导演”已不在新版相同位置。第7.5节要替换的“事实核对与生活画面探索在草稿阶段同时进行。”也已从主题入口移除。新版仍在调度文件里保留类似偏向，但不能在找不到原句时直接追加。[S3][S6]

导演文件如果仍按旧范围一直替换到“素材到混合场面”标题之前，会一起删除新加入的“用材料更新同一份稿”和“素材选择与直接使用”。新方案改为只替换前面的取材推导，明确保留这两段。第7节给出全部当前定位。

### 优化思路：保留探索成果，让材料参与创作

以下思路属于实施文档，不复制到每个Skill。它们解释接下来代码和职责调整的目的，而不是增加制作关卡。

#### 思路一：素材丰富度来自表达选择，不来自固定材料类别

取材的起点应该是当前文本、镜头在整片中的作用，以及画面准备提供什么。素材可以直接呈现内容，也可以提供对照、细节、情绪、空间或形式上的趣味。重要的是它怎样帮助这段表达，而不是它属于某一种制作或拍摄身份。

如果系统先规定所有任务都补某类材料，素材作者就会先证明候选属于这个类别，再考虑它是否适合文本。这个顺序反了。即使已经写了“开放搜索”，固定前缀和类别偏好仍可能让实际查询变窄。需要清理的是自动加到所有任务上的偏好，而不是反过来禁止使用这些材料。[S1][S2][S3]

同样，“相关”应该让材料进入比较，不是要求它独自证明整段讲述。一个候选可以只承担当前镜头的一项作用。素材是否值得采用，仍由当前内容、可利用范围和实际画面共同判断，不能靠题材名相同自动选中，也不能靠媒体种类直接排除。

**因此，本方案不设置素材类别配额、统一拍摄要求、每段最低下载数量或固定画幅筛选。要提升的是可用表达的广度和材料的实际作用，而不是文件数量。**

#### 思路二：导演应把表达说清楚，不应替素材作者提前完成找法

“准确”有两个不同层次：内容目标准确，和文件规格精细。前者是必需的工作上下文；后者通常需要在看见候选以后才有依据。把两者混在一起，会让导演为提高指令准确度而不断补充想象中的机位、形式、部件和排列，最后下游只能寻找这份尚未验证的设计所需要的文件。

当前导演方法已经包含详细搜索起点和细节推导，素材入口又接收这些展开结果。文件也允许探索，但职责安排容易使探索成为“找不到原目标后的补救”，而不是素材作者的正常工作。[S1][S2]

改造后，导演负责说明当前句群、段落作用、前后联系和画面需要补充的表达；素材作者负责把这些内容转成不同的寻找方向，生成查询并比较候选。导演仍然可以提出画面建议，但建议不自动获得用户硬要求的地位。用户明确指定的内容，以及已经确定采用的来源和范围，继续直接执行，不要求重新开放选择。

这不是减少导演的专业能力，也不是让素材作者接管整片。导演负责内容与最终主要采用，素材作者负责检索构思与材料推荐，视觉作者负责材料怎样形成画面。**把决定放回合适的位置，才能既有明确方向，又不把搜索空间提前锁住。**

#### 思路三：给素材作者自由，还必须给它可执行的思考方法

只把指令改成“随便搜、找相关素材”仍然不够。素材作者需要读懂当前文字正在推进什么，找出画面可以承担的内容，再提出真正能查询的方向。它不是把名词逐个拿去搜，也不是先规定每段需要人物、环境和细节各一条。

实际思考应该连续发生：先理解文本作用，提出不同的可视内容；再用有辨识度的词寻找；根据候选反过来调整方向。返回太少时，检查是否自己叠加了不必要条件；返回太相似时，改变寻找的内容关系，而不只是替换同义词；大量结果不贴合时，再补充真正能够区分需求的信息。工具失败与有效零结果要分开，不能把一个入口的失败理解为内容不存在。

候选还可以推动创作：某份材料让表达更清楚、更有趣，或者提供了更好的连接机会，就把发现交回导演、文案和视觉更新当前稿。素材作者不自行重写整片，但也不只交链接，等待别人猜它为什么有用。

**第4节和第7节的素材正文因此保留完整的“理解—构思—查询—比较—反馈”方法。删除的是固定找法和资格义务，不是把专业工作缩成一句“开放检索”。**

#### 思路四：为什么修改找法会拒绝候选？现有逻辑混淆了“旧查询”与“坏素材”

本轮当前源码核对表明，`manageAssetRequirement()` 将一组需求／策略字段的提供纳入 `searchCriteriaChanged`，随后可能拒绝相关修改、把候选写为 `rejected`；会话候选进入获取时还会检查需求版本。[C1][C2] **这些是已有代码行为，不是本方案建议保留的处理。**

从逻辑结构看，它把“输入发生变化，应重新计算搜索结果”的思路，扩展成了“旧查询发现的候选已经无效”。这是对现有逻辑的解释，不是推断原作者当时的主观意图。

新查询确实可能让旧排名不再合适，但不能因此推出候选失效：

```text
内容或找法变化
    → 下一轮查询、排序或当前使用选择可能变化
    ≠ 已经找到的来源不存在
    ≠ 下载中的文件需要取消
    ≠ 已有素材不能在当前或其他位置继续使用
```

因此，**修改检索思路不应该自动拒绝任何已有候选，也不应该只把“普通改词”列为例外。即使当前表达有较大调整，也应改变它与本次用途的匹配判断，而不是批量撤销候选本身。**

旧候选当前没用上，可以暂不选择；新查询更合适，可以重排展示。只有明确对某候选作出“不用于本次需求”的创意决定，才记录这个具体决定。真实来源或文件错误属于技术问题，不能和检索思路变化共用一个“素材已拒绝”的理由。

#### 思路五：保留候选不等于沿用旧答案，要把四种信息分开

要防止误用旧信息，正确做法不是清空探索成果，而是明确每种信息回答什么。

| 需要区分的信息 | 它回答的问题 | 查询变化后应怎样处理 |
|---|---|---|
| 来源与文件身份 | 这是哪份内容，是否还是同一来源／文件 | 没有真实来源变化就保持，不因换词作废 |
| 某轮查询与排名 | 当时如何发现它，它与这轮问题有多相关 | 保留当时记录，新查询重新排序，不覆盖旧记录 |
| 当前创意选择 | 这一段准备用什么，哪些暂不采用 | 在当前稿和使用关系里更新，不自动否定素材在别处的价值 |
| 取得与执行状态 | 是否已下载、是否在途、是否出现实际技术错误 | 按真实任务结果更新，不被稿件措辞重置 |

这张表是语义说明，不是要求建立四个新数据库或让作者填写四份表。第5节将它们映射回现有需求、会话、候选和素材对象。

由此得到一个明确原则：**检索策略变更只影响后续找法和排序；候选作为已经发现的资源继续存在。** 沿用候选时判断当前用途，不是要求它必须继续符合第一次搜索时的全部词语。显式拒绝也应有清楚作用范围，不因为某处不用，就全局封禁同一素材。

已经被旧自动逻辑写成 `rejected` 的记录也不能忽略。迁移时要区分“仅因策略变化而被系统拒绝”和“用户／作者明确不用或确有技术问题”；只恢复前者的候选可见性和可操作性。理由混杂、不能可靠区分的，不批量伪改为可用，更不删除历史记录。

#### 思路六：探索可以改变，已提交的下载应按原任务执行

素材探索天然会边找边改。如果一次下载会锁住需求说明，或改一句话会取消下载，就把本可同时推进的工作绑成了串行等待。当前代码里的在途检查和版本检查，需要按它们实际保护的内容重新区分。[C1][C2]

下载任务提交时固化来源、文件身份与获取选项，后续按这份输入取得文件。稿件或查询更新，不偷改这个下载要获取什么，也不阻止新的探索。下载成功后把文件保留下来，再与当前用途组合。用户明确取消某次下载，才按取消动作处理。

需求版本仍有历史意义，项目 Revision 仍可保护真实写入冲突。但版本不同，不应自动使候选失效。发生并发写入冲突时，读取最新项目状态后执行仍有效的操作，而不是要求重新去外网发现同一内容。

来源临时地址过期，也只说明获取地址要刷新。对同一来源重新解析可下载位置，与重新构思、重新搜索全网是不同的工作。如果刷新后发现来源内容确实改变，再按实际身份变化处理。**这既保留必要的执行正确性，也不把技术恢复变成重新选材。**

#### 思路七：一个文件下载成功，为什么不能替整项取材宣布完成

当前获取完成方法直接设置候选为 `acquired`，并将需求设为 `fulfilled`。[C5] 前者是确定的技术结果，后者却可能被读成“这个镜头已经不缺材料”。

一项表达可能由一份材料承担，也可能需要多份互补内容；某份文件已经下载，不代表它的当前用法已经确定，更不代表其他未完成的画面内容自然消失。下载器没有当前整段的创作判断，不应该替导演作出这个结论。

改造后，程序报告文件取得；素材作者继续推荐和说明尚缺什么；导演与视觉在当前稿里确定材料是否已经能承担表达。已有明确采用不再重复确认，普通局部使用由原作者继续，不为每次下载新增审批。

**需求结束来自内容工作确实完成或用途被明确取消，不来自某一条下载成功。** 这也避免相反的浪费：材料已经足够时无需继续找齐某个固定数量。整片丰富度最终取决于材料是否形成不同的有效观看内容，而不是是否下载了很多同类文件。

#### 思路八：资格移除已经实现，为什么素材发现仍需单独优化

素材资格审阅曾是使用链里的独立阻力。当前提交已经移除了核心资格服务与调用义务，使正常材料按技术条件进入剪辑；但这一改变不会自动替导演产生更好的内容目标，也不会替素材作者展开搜索方向，更不会自动改变后续版式。[C3][C4]

因此，不能以资格链移除宣布素材问题全部解决，也不应该重复开发已经删除的服务。两项工作同时成立：**保持直接使用的基础，进一步让前端职责与检索方法开放，让策略版本不再阻断候选与获取。**

播放器、实际内容理解、定位、裁切与正常看片仍然是创作能力。现有向量和多模态能力可以帮助在已发现、可读取的内容中查找范围和比较关系，不应再次生成素材能否使用的资格状态。外部内容尚未发现或进入索引时，向量服务不能代替外部搜索。

素材外部发现和运动机制库语义检索也不能混为一个问题：前者扩大可用内容，后者寻找表现方法。复用已有能力，不意味着让一种索引包办两项工作；本方案保留已有机制检索与连续演出路线，不要求另建模型服务或重新建设案例库。

#### 思路九：材料必须能影响设计，否则搜索再多仍然只是填空

如果所有版式、窗口和动作在取材前就已经定完，素材作者最终只能找能塞进这些位置的内容。即使找到更好的材料，其主体、空间和动作也很难进入设计，搜索自由就只剩表面上的“可以多搜”。

因此，导演与文案、视觉要允许候选改变当前构图、讲法或连接。材料返回后，先判断它提供了什么，再决定怎样取景、文字放在哪里、下一关注怎样接入。不是要求所有材料铺满背景，也不是让任何新素材都推翻主线；主要表达由导演掌握，局部设计留给对应作者。

运动机制随后帮助组织已经选定的材料和内容，不把素材反过来变成已定效果的填充物。材料还没承担预定作用时，生成了一个图形文件也不能自动关闭该任务。这个反馈回到同一份当前稿，不另外建立一套剧情表、画面审核表和复用审批表。

**最终要恢复的是材料参与创作的能力，而不只是让下载目录变大。**

#### 思路十：怎样减少复杂度，而不是再写一层规则

这轮改造不通过新增评分、配额、审批或更多角色来实现。核心是拆开原来错误绑定的决定：表达需求不等于找法，换查询不等于拒绝候选，下载成功不等于内容完成，程序可执行不等于画面好看。

代码负责确定的输入和执行关系；工作方法负责内容理解、检索和设计判断。Skill 不再替程序反复解释版本和错误恢复，程序也不替作者规定材料类别与版式。后面的详细技术修改、正常工作正文和验证，分别放在各自章节。

本轮验证首先确认尚未实现的行为改变：不预写查询也能开始探索；更新找法保留候选；下载进行中可以继续改稿；旧会话候选仍可取得；单文件成功不关闭整项内容需求。随后再看实际候选是否更有差异、是否改变了稿件和画面，以及最终表现是否改善。

这些结果必须分开记录。技术回归通过可以证明流程阻力被移除；不能自动证明导演表达与成片质量已经提升。反过来，某次成片改善也不能替代候选与状态迁移的回归检查。


### 思路与实施位置对照

| 优化目的 | 当前应做的工作 | 落地位置 |
|---|---|---|
| 内容准确而找法开放 | 导演给表达、素材作者提出查询；保留新版导演采用权 | 第3—4节，第7.1—7.6、7.8节 |
| 查询变化保留探索成果 | 更新、迟到返回、会话获取、下载完成分别解耦 | 第6.1—6.3节 |
| 下载成功不替内容收口 | 候选/Asset状态与需求结束分开，保护closed | 第6.3—6.4节 |
| 已有语义能力真正被用到 | 保留混合实现，正确读回Job，不混淆外部发现与机制检索 | 第6.5节，第7.7节 |
| 不破坏本次已完成开发 | 资格移除改为回归；连续稿与共同状态原文保留 | 第6.6节，第8—9节 |
| 文档可直接执行而不会变成技能杂文 | 精确替换范围、完整写入正文、明确保留区 | 第7节 |

# 第二部分｜目标工作方式与当前基线上的实施

## 3. 目标分工：精确交代内容，不提前锁定找法

| 责任主体 | 正常输入与工作 | 不接管的工作 |
|---|---|---|
| 导演与文案 | 当前稿、段落作用、前后联系和要补的表达；决定最终材料采用及主要编排 | 不预写全部查询词，不把初步构图变成来源筛选条件 |
| 素材作者 | 理解内容，构思可寻找的不同表达，生成查询，选择来源，比较并推荐候选及范围 | 不独立改变主要论述和整片顺序 |
| 视觉与动效作者 | 用采用材料形成构图、观看变化、文字和机制组合；普通局部调整直接完成 | 不为适配已画好的页面而自动撤掉素材需求 |
| 主任务 | 传完整上下文，执行获取和正式写入，带回结果，持续推进实际未完成项 | 不代替作者预设搜索关键词、替换创意或用文件成功证明内容完成 |
| 程序 | 提供搜索、媒体、缓存、使用和渲染能力，报告具体运行结果 | 不根据辅助观察资格或普通检索策略变化决定材料不能使用 |

导演无需在每条需求里重新粘贴整篇长稿：原作者首次取得完整稿，后续接收当前相关范围与差异。内容不明确时回导演问具体分歧；仅仅没有选定机位、造型和文件形式，不算需求缺失。

## 4. 素材作者的通用检索方法

### 4.1 先理解文本在当前镜头里的作用

读取准确句群和前后内容，区分文字正在描述的内容、画面可承担的部分，以及语言需要补充的关系。不要只抽名词；也不要给所有段落规定同一类场景。

### 4.2 从内容提出可比较的画面方向

素材作者寻找能够直接呈现、辅助说明、形成对照、建立氛围或带来视觉趣味的内容。这些是思考角度，不是每项任务必须配齐的固定分类，也不要求单条素材承担全部作用。

方向应具有可搜性，但不是成品分镜。与文本和镜头作用契合的不同来源、媒介、取景与表现都可比较。发现更好的材料，可以提出调整当前画面，而不是只寻找一个预设容器的填充物。

### 4.3 由素材作者生成短而有辨识度的查询

查询使用当前要找的内容词；一条查询解决一个可寻找方向。换词、换语言、组合相关内容或切换入口由实际结果决定，不在每条查询中自动叠加制作属性、审美形容词、目标画幅和所有上游要求。

用户明确指定的内容与限制仍保留；作者自行推测的偏好首先用于比较，不自动成为排除条件。主题相关是进入候选的依据，是否值得用还结合本段表现力和前后关系选择，不要求每条素材证明整段论述。

### 4.4 按结果继续，而不是按固定轮数工作

结果过窄，先撤掉自行添加的限制或换一种表现方向；结果同质，改变内容关系而不只重复同义词；结果大量无关，补真正有辨识度的内容；某个获取入口失败，保留其他候选继续。一次接口错误与一次有效的零结果分开处理。

能直接推进当前画面的候选尽早取得；不等全部需求齐备。缺少必要内容时继续对应探索，不以重复取得相同作用的文件凑数量。

### 4.5 返回材料方案，不交资格证明

回传实际文件或候选定位、推荐范围、可利用的内容、与当前句群的关系、可比较的替代，以及值得改稿或改画面的发现。已有明确选用和范围直接承接。

素材作者推荐；导演确定最终采用和主要编排。采用方向内的精确切口与构图由对应作者细化。材料获取前后的状态如实区分，但不再形成“补齐审阅记录才准用”的额外链。

## 5. 四类信息在现有数据里怎样分开

不新建搜索导演、剧情数据库或一套表单。优先沿用现有 `AssetRequest`、`SearchIntent`、搜索会话、候选和作品绑定。

| 现有位置 | 调整后的含义 |
|---|---|
| `AssetRequest.purpose/visualBrief` | 当前内容用途及待探索画面，不要求填成最终镜头规格 |
| `AssetRequest.queryHints` | 可选的历史线索，不是每条实际查询必须包含的词，也不作为候选有效性条件 |
| `SearchIntent.query/provider/mediaType/cursor` | 这一轮实际运行的查询与入口，由素材作者决定；新查询新会话，不覆写旧候选 |
| `targetAspectRatio` | 本片画幅或构图上下文，不自动解释为只接收同画幅原素材；创建需求不再静默填成源筛选条件 |
| Candidate / Asset | 来源身份、文件事实、获取结果；内容推荐与生产采用通过当前稿和实际使用表达 |
| 作品与时间线绑定 | 当前最终使用什么、源范围及处理方式，不需要资格审阅ID |

程序参数可以服务某一轮定向查询，但不能把一次查询参数永久升级成整项需求的边界。候选没被选中只是未采用，不必一律写成拒绝或内容不合格。


## 6. 代码实施：只开发当前还缺的行为

### 6.1 需求更新不改变候选和在途任务的资格

**目标文件：** `packages/edit-application/src/index.ts`。**定位：** `manageAssetRequirement()` 的 `searchCriteriaChanged`、`hasDownloadInFlight` 与候选批量 `rejected` 分支。[C1]

删除内容/查询策略变化触发候选拒绝、需求更新阻塞、候选清空或不可见的处理；不改成`needs_review`或默认关闭的拒绝开关。相同值不制造失效，不同值只更新当前内容及找法。真实项目Revision仍保护并发写入，但版本冲突只需要读新状态并继续有效操作，不要求重新发现素材。

需求字段继续有用：`purpose/visualBrief`记录表达，`queryHints`保留线索，`targetAspectRatio`提供当前画幅语境；这些不是候选身份。显式用户约束或技术选项改变时，分别影响下一轮比较或下一次获取输入，不能据此全局废除已有资源。这里不要求新建四套数据库。

**迁移：**仅因旧“需求已更新、重新搜索复核”自动逻辑被拒绝的候选，恢复可发现和可操作；保留历史原因。来源损坏、显式取消、作者对当前用途明确放弃不能批量恢复。混合原因需在迁移结果中区分，不伪造已通过记录。

### 6.2 查询返回和旧会话获取也必须保留成果

**定位一：**同文件 `recordAssetSearch()` 的 `input.requestVersion !== version` 与搜索会话写入。[C2]

搜索发出时固定当轮输入和对应需求版本，返回时按这份输入保存原会话。若当前稿已更新，旧查询结果照常保留为历史发现，当前排序可重算；不把旧请求的结果伪标为新查询，也不抛错要求全网重搜。不得用当前新需求再对旧返回一律判拒绝。仍检查来源、结果格式及文件身份，不混淆两轮输入。

用途已结束时，已经发出的只读搜索可以保存结果而不重新开启用途、不自动下载。明确取消网络任务按实际取消能力处理；保存已返回的内容不等于替用户继续制作。沿调用方传递的实际请求快照或已有会话关联实现，不凭当前文本猜回旧输入。

**定位二：**同文件 `acquireAssetCandidate()` 从搜索会话提升候选时的需求版本相等与24小时检查。[C2]

移除需求版本相等作为获取资格。会话年龄和临时URL过期只触发同一来源地址刷新，不把候选内容作废。保留准确源ID、取得范围和获取选项；已有同输入Job继续复用。用户要求的当前写入使用最新Revision；同一下载的不同获取参数仍是两个不同操作，不能偷换在途任务。

候选源身份相同可以去重展示，发现路径分别保留。不用标题相同判断同一文件，不让旧`hardFilterPassed`承载的创作条件永久否定资源。

### 6.3 下载完成不重新服从变化后的创意需求

**定位：**`acquireAssetCandidate()` 的入队payload、获取Worker的实际输入读取，以及 `completeAssetAcquisition()` 中 `candidateIsAllowed(candidate, request)` 和资源登记。[C2]

现在入队记录候选与获取选项，而完成阶段仍读取当前需求。解除需求更新限制时，必须同步明确下载使用的来源和选项：提交后执行固定输入；更新文案、查询或目标构图不取消、不阻止、不偷改下载。

成功结果依据本次实际任务、真实媒体和所提交源范围登记为Asset。当前内容已经变化，不作为拒绝登记这份合法文件的理由。文件缺失、不可解码、哈希/来源不符、取得范围错误等继续按真实技术错误处理；不以放开创作策略为由接受错文件。

临时地址更新由同源解析完成，素材结果保留来源与实际本地范围。内容选用由当前稿决定，未选文件可留存，不强行装入已设计画面。Worker输入流及所有取得成功回调需要跟随本次固定输入规则查引用；本轮并未声称读完所有来源Worker。

### 6.4 文件完成与需求关闭分开，成功和失败都保护closed

**定位：**同文件 `completeAssetAcquisition()` 的 `request.status="fulfilled"`，`failAssetCandidateAcquisition()` 的需求状态重设，以及 `manageAssetRequirement(action="close")`。[C1][C2]

文件成功只更新对应候选与Asset，不自动认定整项内容已满足。`closed`需求无论收到成功、失败或迟到结果都保持关闭；成功文件仍登记，失败原因仍保存，但不重新打开用途，不自动放置内容。

未关闭的需求可以沿当前已有枚举表达进度：有相关未结束获取时反映`acquiring`，已有待比较候选时反映`candidates_ready`，否则`open`。具体统计同时覆盖搜索会话与已提升候选，不能因候选尚未进入快照就误报没有候选。不要把这些进度状态当素材质量或内容完成标准。

复用现有`close`和`closeReason`记录明确的完成或取消。导演/原作者在当前工作中确认用途已完成即可执行关闭，不逐文件新增审批。按完成关闭前要有实际选定材料，按取消关闭不要求先下载。历史`fulfilled`解释为旧获取进展；不能自动宣称充分，也不擅自批量重开旧项目或重新联网取材。

### 6.5 三种检索按当前已实现接口衔接

外部发现继续使用宿主和Provider能力。`list_asset_providers`给实际`id/mediaTypes/queryMode`；关键词入口不可用不等于对应内容不存在，选定单页URL获取不等于全站搜索。素材作者根据文本自行生成查询，不自动加拍摄身份、固定审美或来源等级。[S5]

已发现材料需要定位内容时，可使用现有`search_media_fragments(mode="hybrid")`与媒体理解；没有分析笔记仍可按正常文件直接使用。这不是恢复素材资格链。[C3]

进入动画制作再用`search_motion_mechanisms`。保留已实现的全文文本、向量、RRF、缓存和`analyze_motion_reference`，不在本次素材方案中重新开发。普通文本机制查询传已存在的`project_id`或确认当前项目已解析；首次返回语义Job就按返回ID跟进，完成后用相同需求及来源指纹读取结果，查看真实`semantic_used`。独立工作可继续，不能为了等待该Job阻塞所有材料探索。[M1][M2]

`ids/selection`是精确恢复，不必强制走向量；无项目时纯词法是当前合法模式，不因此新建虚假项目。真实服务失败如实降级，依现有恢复方法处理，不通过换键反复提交。机制缓存与初建代价属于已有维护，不新增数据库或要求所有素材先向量化。

## 8. 回归与效果验证：新增测试和既有测试分别保留

### 8.1 本轮新加的是外部素材生命周期测试

| 输入或操作 | 必须得到的结果 |
|---|---|
| 只有文本、用途与前后关系，没有预写查询和最终布局 | 素材作者能正常产生寻找方向；不要求用户或导演先补文件规格 |
| 不指定拍摄身份或风格 | 查询与工具不会由通用方法自动附加固定身份；一次视频类型选择不锁住整项需求 |
| 改`purpose/visualBrief/queryHints/role/targetAspectRatio`或传相同值 | 保存真实变化，不批量拒绝、清空、隐藏已有候选 |
| 搜索已发出，返回前需求更新 | 返回保存在当轮查询及版本下，不冒充新查询，不抛错丢成果 |
| 搜索返回时用途已关闭 | 可保留已返回发现，需求仍关闭，不自动下载或重新开工 |
| 需求版本变化后从旧会话获取候选 | 不重新进行创意搜索；真实写入冲突仍按Revision恢复 |
| 会话超时或临时URL过期 | 同一来源可刷新获取信息，不自动否定内容 |
| 下载中改词、改稿或目标构图 | 内容可更新，下载按固定来源和选项继续 |
| 下载完成时当前需求已经改变 | 合法结果仍登记，创意相关性不覆盖文件技术结果 |
| 成功/失败/迟到回调遇到`closed` | 不打开需求，不删除成功文件，不自动放进画面 |
| 一个文件成功而还有待完成用途或其他候选 | 不自动`fulfilled`；当前进度与内容完成分开 |
| 从旧系统恢复仅因策略变化被拒绝的候选 | 恢复可继续使用并保留历史，不误恢复显式取消或错文件 |

这些是通用参数化回归，不向活动Skill写测试题材、示范画面或固定素材数量。使用隔离项目和现有测试框架，不在用户生产项目中重新抓取文件。

### 8.2 已实现基础作为不回退检查

素材正常绑定不需要审核ID，旧审核状态不影响导出；技术错误仍有明确诊断。保留当前连续整段/拆块一致性测试、源视频时间测试、语义缓存/失败恢复测试和活动工具注册测试，不用旧假审核数据重新“修复”测试。[T1]

机制调用检查从当前正式入口进入：解析真实项目，首次Job、相同输入读回、真实`semantic_used`、候选原文与当前稿的关系都能核对。该测试判断语义路线是否实际用上，不等同于向量比词法更准确。

### 8.3 质量验证不能被开发20条命中率代替

保留既有20条结果作为已知开发基线，不重标成新的提升成绩。新增由未参与索引描述编写的人或实际任务产生的需求，包含正常口语、关系反转、跨段连接与多义表达；测试查询不照抄机制标题。固定库、候选预算和内容，分别比较算法与指令转换；标注集不穷尽全库时只报告有限集合覆盖。

素材搜索另外观察：找到了哪些不同的有效内容，候选有没有推动改稿与构图，最后有没有进入实际连续过程。当前大多数检索测试对象是机制库，不能用这些数字宣称外网素材已经丰富。

候选未召回、候选已入围但选择不佳、选择正确但实现缩水，分别定位；不要每次都同时换文案、素材、配色和算法，最后无法解释改变来自哪里。本轮没有独立运行这些效果测试，正文不承诺提升幅度。

## 9. 实施顺序与最终交付

先在当前分支保留已完成的机制检索、资格移除和连续制作；确认开发Runtime与实际测试版本，避免对旧安装包重复诊断。

接着修“需求更新—查询返回—候选获取—下载完成—需求关闭”的生命周期，将第8.1节的回归与变更一同提交；旧候选迁移明确作用范围。文件、来源、参数、幂等和实际并发校验不被当成创作限制一并删掉。

然后按第7节的当前锚点替换技能，保留每项列明的新工作方法。`.agents/skills/`同步到发行副本，工具描述与真实代码保持一致。不手工维护两套规则，不把整份分析复制进插件。

最后在隔离环境核对三路检索衔接与一次实际的素材驱动连续制作。生产素材的获取、采用及编排继续由原角色完成，不给素材作者新设导演身份；不以一个局部样片代替用户要求的完整交付。

**完成的含义：**前期内容准确而检索开放；变更找法保留既有成果；取得文件不提前结束内容；已选材料正常使用并影响当前画面；后期使用现有语义机制检索和共同状态制作，不重新退回逐页填素材。
