# VideoFlowCut LTX 2.3 真人口播：需求与优化方案

日期：2026-10-19  
需求基线：本轮已确认方案；用户提供的部署版本为 VideoFlowCut 0.1.94。  
文档状态：最终需求与实施方案，供后续开发使用。本文不代表代码已完成、插件已部署或样片已通过。

## 1. 已确定的目标与范围

让用户保存一次人物照片和音色样本，以后通过聊天或工作台重复选用，制作“部分镜头人物口播、部分镜头素材或图形”的视频。

本次只完成两项优化：

1. 将照片驱动的人物口播生成正式接入现有 LTX 2.3 工作流。
2. 在工作台增加可复用的人物照片与音色配置，并支持在项目中独立更换。

已确定的边界：

- 本条人物生成链路使用 LTX 2.3；失败不切换 H3，也不自动改成没有人物的解说片。
- 人物照片与音色分别保存、独立选择，不要求每次聊天重新上传。
- 先按内容规划人物可见范围，再生成所需人物片段，不默认生成一条覆盖全片的超长口播。
- 沿用当前人物导演、声画稿、素材混剪、动画、字幕和声音制作方法；这些创作方法是否调整，等首轮真实样片测试后再决定。
- 不新建通用多模型调度系统、第二份分镜数据库或完整资源管理平台。
- 已有真人实拍视频仍沿原片导入和剪辑路线处理，不强制重新生成人物。

## 2. 当前事实与待补齐能力

以下基于本会话对实时 Bridge、已发布 MCP 和仓库代码的只读核对。实施时仍须重新读取实际接口，不能将这份快照当成永久合同。

| 项目 | 当前事实 | 本次目标 |
| --- | --- | --- |
| LTX 工作流 | Bridge 中已存在且显示可用；仅公开必填图片、音频输入 | 接入正式人物生成 Job 与项目对象链 |
| 人物生成执行器 | 原来对接其他模型，仍强制寻找文字提示词字段 | 按 LTX 的实际输入构造请求 |
| 音色 | 有项目内 VoiceReference，以及服务端内部配置的默认音色 | 用户能在工作台看见、试听、选择和更换保存的音色 |
| 人物配置 | 有项目内人物视频与表演绑定，没有完整的跨项目照片选择功能 | 全局保存照片，项目固定选用的照片与音色 |
| 可见范围规划 | 当前导演规则已支持人物退场、素材接管和人物返回 | 继续使用，不重新设计分镜方法 |
| 生成质量 | 本轮没有实际生成人物样片 | 实测口型、身份、时长和混剪接续 |

### 2.1 LTX 与 H3 没有依赖关系

旧人物生成代码是按 H3 接口编写的，假设提交时要找到“文字提示词”字段。现在的 LTX 工作流只公开图片和音频，直接更换工作流 ID 会先卡在这项旧输入要求上。

因此，本次修改的是 VideoFlowCut 人物生成代码的输入假设。LTX 不需要经过 H3，不使用所谓“H3 提示词”，也不以 H3 作为失败替代方案。

删除范围仅限旧人物生成适配；项目中其他普通素材视频生成功能不属于本次修改范围。

### 2.2 已核对的 LTX 工作流

| 字段 | 本会话核对结果 |
| --- | --- |
| 名称 | LTX2.3数字人文生图生自由切换版 |
| 工作流 ID | `7f5e0c56-93b4-4937-b7f2-efd0f1853e33` |
| 可用状态 | `available=true` |
| 必填输入 | `image`、`audio` |
| 公开参数 | `fields=[]`，没有公开文字提示词、时长或画幅参数 |
| 输出声明 | 一个动态输出，标签为 `Video Combine`；须验证实际返回文件为可用视频 |

“可用”表示 Bridge 能提供该工作流接口，不等于中文口型、单段时长或完整视频质量已验证。

## 3. 用户需要准备的材料

首次配置时准备：

- 一张人物照片：清晰、脸部可辨、无遮挡，构图适合预期口播画面。
- 一个音色来源：可以保存用户提供的声音样本，也可以选用登记后的现有默认音色。

每期制作时提供：

- 本期主题或文稿，以及是否允许改稿。
- 画幅、预计时长、用途等尚未确定的信息。
- 如需指定素材，提供素材或取材要求；否则沿现有取材流程处理。

必须区分：

| 材料 | 用途 | 是否可跨项目复用 |
| --- | --- | --- |
| 人物照片 | 提供人物外观参考 | 可以 |
| 音色样本 | 交给 OmniVoice 生成指定声音的台词 | 可以 |
| 本片台词音频 | 本片真实要说的内容，按所需范围交给 LTX 驱动口型 | 随本片台词和声音版本产生 |

一张照片不能独立完成指定台词的口播。用户不必每次提交录音，但系统仍须先准备本片台词音频。

## 4. 工作台与聊天交互

### 4.1 工作台全局入口：人物与音色

与现有全局设置同级增加“人物与音色”，在尚未创建项目时也可进入。

入口包含两个简洁列表：

| 列表 | 内容 | 操作 |
| --- | --- | --- |
| 人物照片 | 名称、照片预览 | 添加、重命名、更换、移除、选为默认 |
| 音色样本 | 名称、音频样本 | 添加、重命名、试听、更换、移除、选为默认 |

默认组合由“默认人物照片＋默认音色”组成。两者独立保存，同一张照片可以搭配不同音色，同一个音色也可以用于不同照片。

日常界面不要求用户填写工作流 ID、文件路径或模型输入槽位。工作流绑定由系统配置和正式接口负责。

“试听样本”只播放所保存的参考录音，不将它表述为本片配音或 LTX 效果预览。真实配音和人物效果由实际生成结果验证。

### 4.2 项目入口：本片人物与音色

在现有项目“人物”面板顶部增加：

- 本片人物：显示名称和所选照片。
- 本片音色：显示名称并支持试听样本。
- 生成方式：LTX 2.3。
- 分别更换人物照片、音色并应用到本片的操作。

现有生成结果、人物视频和表演信息继续在项目内查看。应用更换时说明受影响的声音、人物镜头或时序，并进入正式修改与生成流程；仅保存全局素材不会自动启动制作。

### 4.3 聊天入口

支持下列日常表达：

- “做一期真人口播，用默认人物和默认音色。”
- “人物用商务照，音色换成沉稳版。”
- “这期只换照片，声音保持。”
- “把这张照片保存为新的默认人物。”

照片和音色分别按以下优先级解析：

1. 用户本次明确指定的选择。
2. 当前项目已经固定的选择。
3. 工作台默认选择。

已有明确选择时直接使用，不重复索要文件。缺少必要输入或名称无法唯一定位时，只补问缺失项；不能自动改用其他人物或音色。

聊天与工作台调用同一组正式业务接口，共享同一份设置和项目事实，不维护两套配置。

## 5. 保存位置与项目输入固定

### 5.1 全局保存

复用现有 `workspace_settings` 存储方式，为人物与音色增加独立设置项。只保存本功能所需的列表元数据、文件身份和默认选择，不把媒体路径塞进创作偏好文字。

照片和音色文件放在工作区受管目录，登记名称、稳定标识及内容哈希。不依赖聊天附件临时地址、外部原文件路径或插件安装缓存。

更换文件产生新的文件身份，不原地覆盖已经被项目采用的内容。

### 5.2 项目固定输入

项目首次选用或显式更换时，通过现有素材导入链复制并登记所选文件：

- 照片成为本项目的图片 Asset。
- 音色样本成为本项目的音频 Asset，并登记为 VoiceReference。
- 项目保存实际选择、来源标识和文件身份，生成 Job 固定本次使用的输入。

修改全局默认、替换全局文件或移除全局条目，不回写已使用它的项目。已有项目继续使用固定的本地输入；移除默认条目时清除对应默认选择，不自动指定其他条目。

这会让每个项目多保存一张照片和一小段音色参考，换来稳定、可追溯的重新生成。

### 5.3 当前默认音色的处理

现有服务端默认音色的实际音频隐藏在 ComfyUI 工作流内部。新功能建立时，将这份真实参考音频登记进音色列表，并设置为默认选择。

本次人物口播路径以后使用项目固定的 VoiceReference，通过现有显式参考的 OmniVoice 路径合成。不能仅保存一个“服务端默认”标签，却在每次重生成时读取已经变化的外部文件。

这是当前已配置样本的一次性登记，不建设通用迁移系统，也不批量改写历史项目。若真实文件不可读取，明确显示该默认音色未就绪，由用户选择或补充有效样本。

## 6. 整体制作调用链

1. 解析本片人物照片和音色，固定项目输入。
2. 沿现有人物导演路线形成声画稿，确定哪些内容需要人物、素材或图形。
3. 将当前准确台词与所选音色交给 OmniVoice，形成真实 SpeechAsset 及时间信息。
4. 根据实际声音和素材校准人物可见范围，再安排生成片段与合理剪辑余量。
5. 从当前 SpeechAsset 精确裁出该生成范围的音频，与照片一起提交 LTX。
6. 跟踪原 Job 和 Bridge Run，下载、检查并登记人物视频及 ActorPerformance。
7. 将人物、素材和图形放回当前声画设计，统一字幕和声音，生成连续预览。
8. 根据真实预览修订并导出，分别记录技术结果、审片结果和用户采用状态。

### 6.1 可见范围规则

- 人物全屏、缩窗、分屏及出入画过渡，只要仍可见，就需要对应声音的人物视频。
- 全屏素材接管且人物完全不可见的范围，可以只保留讲述声音，不生成人物视频。
- 生成段按自然表演、实际工作流能力和剪辑余量组织，不按每张字幕卡机械拆分。
- 相邻露脸区间可因连续表演需要合并，但不默认覆盖全片。
- 缩放、移位和返回时保持人物源时间连续，不重新播放嘴型。

### 6.2 声音规则

本路线以当前 SpeechAsset 承担讲述声音。LTX 输出即使自带音轨，也不与讲述轨重复播放；素材原声按现有声音设计单独安排。

人物口型绑定实际台词音频。音频被替换后，不能继续把旧人物镜头标记为当前版本有效。

## 7. LTX 正式接入的开发要求

### 7.1 输入与输出

- 将人物生成 Provider 及相关合同改为 LTX 2.3，保持现有 Job、Revision、人物对象和时间线写入链。
- 每次实际提交前读取当前 Bridge Schema，绑定唯一明确的图片和音频输入。
- 上传项目固定的照片，以及当前生成范围的实际台词音频；不上传音色样本冒充台词音频。
- 原工作流仅公开图片和音频；正式口播入口公开可选正向提示词。提供 prompt 时必须有唯一明确的公开字段，否则失败；不提供时使用工作流默认。时长、画幅仍不作为虚构参数发送。
- 时长来自实际音频范围和输出校验；输入范围不等于工作流一定完整输出该长度。
- 核验返回视频的可解码性、真实时长、帧率和尺寸，并确保可用源范围覆盖要求。
- 输出短于所需范围时明确失败，不冻结、循环、错误变速或重复配音补齐。
- 保留工作流版本、原 Run、输入文件与生成范围的追踪关系。

### 7.2 删除与保留

| 旧逻辑 | 调整 |
| --- | --- |
| 人物 Provider 只允许旧模型 | 替换为 LTX 人物生成合同，不增加双模型兼容分支 |
| 人物生成强制搜索正向提示词字段 | 删除强制要求；仅在作者提供逐镜 prompt 时绑定明确公开的正向字段 |
| 旧人物接口的默认提示词与字段推测 | 删除；采用 LTX 工作流中性默认与可选逐镜正向提示词 |
| 旧人物请求的时长、画幅字段映射 | 删除不适用于当前 LTX Schema 的映射；保留真实范围与输出校验 |
| 音频裁切、任务追踪、输出下载和人物登记 | 复用并按 LTX 合同验证 |
| 当前导演、素材、动画、字幕和声音方法 | 保留；首轮样片后再决定是否调整 |

移除旧模型提交路径不意味着删除既有生成文件或破坏历史成片读取。既有任务按其真实状态处理，不把未完成的旧任务静默改成 LTX 任务。

### 7.3 失败处理

- 服务未就绪、输入缺失、Schema 不匹配、生成失败和输出不合格分别报告实际原因，不切换生成模型。
- 已取得 Run ID 时继续查询原 Run；结果未知先对账，不更换幂等键盲目重复生成。
- 仅在现有正式恢复合同明确允许时恢复失败任务，不把超时或连接中断等同于确定失败。
- 未知或失败结果不能登记为已就绪人物；不能绕过正式接口修改项目数据库。
- 一次局部生成失败只处理受影响依赖，无依赖的素材、文稿等工作可继续。

## 8. 照片和音色更换的影响

| 更换操作 | 必须处理 | 不应发生 |
| --- | --- | --- |
| 改工作台默认组合 | 保存供未来项目使用的默认选择 | 自动修改已有项目 |
| 换本片照片 | 固定新照片；使相关旧人物生成失效；重生并复核构图、身份和接点 | 无原因重配旁白或改写台词 |
| 换本片音色 | 使受影响配音进入待重生成状态；重新合成；更新真实时间；重生对应口型；重校字幕与受影响画面节奏 | 只换音色 ID，继续复用旧声音和旧口型 |
| 同时换照片和音色 | 合并处理一次输入变更；先获得新台词音频，再用新照片生成人物 | 先按旧声音生成一次，再因新声音生成第二次 |
| 仅重命名全局条目 | 更新显示名称 | 使内容相同的人物或声音无故失效 |
| 替换或移除全局文件 | 更新全局条目与默认状态 | 破坏项目已固定的素材副本 |

换音色可能改变停顿、语速和时长，因此素材剪辑、动画、声音接点和后续段落可能需要重新校准。按真实差异处理，不承诺所有下游时间保持不变，也不因换音色而自动重做无关素材。

## 10. 测试与验收

测试从简，围绕真实核心行为，不以覆盖率为目标。

### 10.1 核心自动验证

| 场景 | 验收结果 |
| --- | --- |
| LTX Schema 只有图片、音频，没有文字字段 | 可正确构造请求，不再因缺提示词拒绝 |
| 生成一个局部人物段 | 提交音频与目标范围一致，输出覆盖所需时长，只有一条有效讲述声音 |
| 全局保存并跨项目选用 | 无需重新上传；项目固定正确文件；改默认或移除全局条目不改变旧项目 |
| 更换本片照片 | 相关人物需重生，原旁白保持，新的结果有正确照片来源 |
| 更换本片音色 | 真实重新配音，旧口型失效，字幕和受影响时序按新声音处理 |
| 外部调用中断或结果未知 | 沿原 Job/Run 恢复或对账，不重复提交，不切模型 |

### 10.2 真实样片验证

使用隔离测试项目和已保存的照片、音色，制作一段包含“人物出镜—素材接管—人物返回”的短样片；具体长度按内容和实际工作流能力安排，不预设为固定剪辑模板。

检查：

- 人物身份、脸部、手部、背景和镜头稳定性。
- 中文口型与实际音频是否同步，句首、句尾是否完整。
- 输入音频与实际输出时长的关系，有无截断、静止或重复。
- 人物退场、素材接管和返回时，声音、字幕、姿态与源时间是否连续。
- 换照片后的局部重生，以及换音色后的声音、口型和时间联动。
- 工作台配置能在新的制作会话中被正式接口读取，不依赖本次聊天记忆。

记录实际文件、输入版本、Job/Run、检查范围和未能观察的事项。任务成功和视频可播放不能代替口型、连续性或审美验收。

### 10.3 开发到业务验收的顺序

1. 完成代码、接口、工作台和必要技能说明的同步修改。
2. 使用隔离项目、目录、端口和队列完成核心验证，不与生产 Runtime 共用工作队列。
3. 构建候选 Release，沿现有正式发布和安装流程部署插件，不手改已安装缓存。
4. 新会话核对实际 MCP、Runtime、启动器版本与 Worker 健康。
5. 通过部署后的正式接口创建独立验收项目，完成真实样片和更换测试。
6. 依据测试结果决定是否需要调整其他导演、分镜或生成设置。

交付时分别说明：文档完成、代码完成、隔离验证、插件部署、实际样片和审片结果，不能用其中一项代替其他项。

## 11. 暂不承诺的能力与已知代价

- 当前工作流的单次稳定生成时长尚未实测，不承诺一次生成任意长度的口播。
- 不新增精确目光、手势、逐帧姿态或透明人物输出的承诺；当前先使用真实可用的人物视频构图。
- 正式入口只新增可选正向提示词；时长与画幅不增加无效控件。原有裁切、帧率等设置保留，首轮真实样片后再决定是否调整。
- 多段人物可能出现姿态、情绪或身份差异，需真实连续审片和局部修订。
- 换照片需要重新生成人物，换音色还需重新生成声音和校准时间，均有计算与等待成本。
- 本文最初为开发前需求方案；后续代码开发与检查范围见第 12 节及开发验证记录，不能将代码完成视为生产部署或真实样片验收。


## 12. 提示词职责与本轮开发落地

### 12.1 已确认的提示词补充

LTX 本身使用提示词。最初 `fields=[]` 只说明 Bridge 没有公开文本输入，不代表图内没有提示词。原图正负文本直接连接 LTXVConditioning；负向文本包含不适合通用口播的“微笑、看镜头、衬衫、帽子、麦克风”等限制。

本次通过 `configure-ltx-avatar.mjs` 从原保存图生成独立正式 API 工作流 `videoflowcut-ltx23-avatar-v1`，保留图片、音频和输出映射，替换中性默认正向文本、清理负向限制并公开可选正向输入。原 `.app.json` 不改写；其他图参数不变。正向提示词描述表演和镜头，不替代本片台词音频。

职责固定为：导演决定意图 → 人物专项编写逐镜提示词 → 主任务按 Schema 提交 → 实际样片验证。用户无需每期自行写提示词。系统不新增独立提示词管理平台或隐藏生成模型。

### 12.2 已实现入口

- 全局工作台：人物与音色，可添加、预览／试听、重命名、更换、移除、设默认。
- 项目人物面板：显示固定副本、独立选择和应用照片／音色；应用只保存选择及失效状态，不自动开始生成。
- 正式 MCP：`read_presenter_library`、`import_presenter_media`、`manage_presenter_library`、`apply_presenter_selection`、`resume_avatar_job`。
- 人物 Provider：`ltx23_audio_to_video`，复用已有 `submit_avatar_job`、Job、Bridge、ActorPerformance、时间线与质量门禁。
- 全局表在 `workspace_settings.presenter_library`，文件在工作区 `presenter-library/`，项目副本在项目目录 `assets/presenter/`。
- 换音色递增 `speechInputVersion`，清空旧段音频缓存并拒绝在途旧音色结果；换照片不触碰配音内容。

### 12.3 部署时配置

完成候选构建后，部署阶段运行配置脚本的 `workflow` 子命令，将独立 API 工作流写入 ComfyUI Bridge 的 `api_workflows` 目录；再用 `voice` 子命令，通过 VideoFlowCut 正式接口登记现有服务端默认音频。后者遇到已有用户默认时保持该选择。具体命令、核验与本轮实际执行范围见 [开发验证记录](development/ltx-presenter-20261019.md)。

移除全局条目只移除列表入口，旧项目副本保留；全局历史内容文件暂不自动清理，因此有少量磁盘占用。真实 LTX 时长、中文口型、身份稳定与混剪接续仍需部署后的独立样片验证。
