## 主要调用链

用户主题 → 主任务分派导演及现有专项 → 内容、素材、文案与视觉共同修订 → 本场目标与实际材料 → `search_motion_mechanisms` → `read_motion_mechanism` → 同稿对象映射与连接 → 原作者生成受管源码 → 主任务正式提交 → 实际 Preview 回原作者 → 导演协调与专业审片 → 既有导出链。

既有视频发现、正式获取、选段、配音、字幕及源时钟合同保留。支持媒体类型筛选的连续行为需求沿现有 `media_type="video"` 查询；YouTube/Pexels 先发现真实单视频页再获取，不把关键词当视频URL。阶段是工作分派约定，不宣称已经实施工具权限隔离。

## 失败处理与已知代价

材料不适合或搜索无结果继续换行为描述、范围或候选；获取结果未知先读原 Job。机制无匹配先拆阶段、改关系或找相似项，仍缺主要动作时交导演与原作者选择调整或补做。连接失败先修状态、重叠、坐标和源时间，不为编号丢失关键材料。工具故障仍受原有原始错误保存、幂等和报修条件约束。

验证期间修正了三处已有校验漂移：静态报告的中文类型名、机制工具注册文件与状态字段分类、字幕获取合同已经搬至参考文件后的测试路径。跨版本测试也在新业务握手后刷新工具目录，避免旧目录触发正常的 Schema 变更拒绝；未削弱生产校验。发行快照测试依赖构建完成后运行，构建过程中临时缺少manifest的竞争结果不作为有效验收。

机制仍是运动描述，适配与连接需要作者实现；新增主要动画会多一次有目的的检索与核读，局部修改沿用原选择。没有新增评分、素材数量或每场机制数量门槛。

本次未接管已有剪辑任务、制作新主题成片或执行完整创意团队实测。方案中“文案更生活化、素材更好看、机制组合更连贯”的实际效果，仍需在下一次正式制作的真实调用记录与连续声画中验收；静态路由、协议测试和技术渲染不能替代该结论。构建保留既有 CommonJS/import.meta 与 Web体积提示，本次发行实测通过，未扩大到无关构建优化。
