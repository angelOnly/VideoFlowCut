## 实现与调用链

| 位置 | 最终行为 |
|---|---|
| `packages/edit-application/src/index.ts` | 更新表达、线索、角色、画幅和时长不拒绝候选、不锁住下载；未指定源画幅时不自动补项目画幅。 |
| `apps/server/src/mcp.ts`、`apps/server/src/sound-tools.ts` | 查询前读取需求，将当轮快照与版本传到结果保存；关闭后不发起新搜索，已在途返回仍可保存。 |
| `packages/media-intelligence/src/store.ts` | 搜索会话保存当轮需求快照、查询、版本和发现路径；新格式版本为 5，旧会话仍可读和获取。 |
| `acquireAssetCandidate()` → `apps/job-worker/src/index.ts` | 用最新项目 Revision 提交，固化候选来源、需求标签与获取参数；不再检查搜索需求版本相等或 24 小时时限。Worker 按固化输入执行，来源 Provider 仍按原始 ID 重新解析下载位置。 |
| `completeAssetAcquisition()` / `failAssetCandidateAcquisition()` | 成功登记真实文件，失败保存原始原因；二者均保护 `closed`，不放置素材、不把需求自动设为 `fulfilled`。回调检查任务、来源身份和范围，迟到失败不覆盖已取得文件。 |
| `readProject()` 与上述写入 | 合并独立搜索会话与快照候选统计进度；同候选以快照里的执行结果为准。有在途获取为 `acquiring`，有可比较或已取得材料为 `candidates_ready`，否则 `open`。历史 `fulfilled` 保留为旧进展，不自动重开。 |
| `apps/job-worker/src/sound-ranking.ts` | 当前声音排序允许同需求的旧查询候选参与；当前排序本身仍校验其提交需求版本，不能把旧排名冒充当前排名。 |
| 视频生成完成分支 | 单份生成文件也只报告材料进展，不自动宣告整个内容需求完成；原生成任务的其他合同保持。 |

关闭继续使用 `action=close` 和 `close_reason`。补充可选 `close_outcome=completed|cancelled`，避免程序通过自由文本猜测“完成”或“取消”：完成需有该需求关联的已就绪取得/生成材料，取消不需下载。省略按取消处理；导演或原作者的关闭操作本身表达内容判断，不增加逐文件审批。

获取仍保留幂等、MIME、文件头、实际媒体流、来源 ID、源范围与时长对应检查。不同参数不能偷换在途任务，同一幂等键不能对应另一来源。错误结果和未知任务不自动重放。

## 历史候选兼容

`packages/media-intelligence/src/candidate-lifecycle.ts` 由快照规范化与独立搜索会话读取共用。

- 只有旧自动理由“素材需求已更新，必须重新搜索并复核候选。”明确且无其他拒绝原因、来源技术字段仍合法时恢复候选。
- `strategyMigration.outcome=restored` 保留原始 `rejectionReason` 与 `filterReasons`，不伪造人工通过记录。
- 混合原因或真实来源错误返回 `retained_mixed`，保持拒绝；纯人工拒绝不进入自动恢复。
- 已有旧时长过滤兼容继续保留；不会误恢复混合策略原因。
- 使用现有读取规范化边界，不改写历史 SQLite 行、不批量产生视频 Revision；后续正常提交自然保存兼容后的快照。

## 代价与验证边界

- 读取项目时会合并现有搜索会话的候选进度；未增加新数据库或索引。保存的历史会话不会因换词被清理。
- 旧任务缺少新来源/需求快照时沿用原候选和已有固定获取选项；不能倒推出旧任务从未记录的完整创意上下文。
- 混合拒绝理由无法可靠归因，因此不自动解除。历史 `fulfilled` 不被重新解释为内容充分，也不自动开启新的联网制作。
- 正式发行可构建和隔离验证，不等于生产已部署。已安装旧插件需要后续正式发布、重连和核验才能使用新版。
- 未开展独立人员盲标、真实外网候选丰富度评估或新主题完整成片的专业视听评估；不把测试夹具、静态 Skills 检查或原有开发命中率包装为质量提升。正常视频制作仍由原导演、素材与视觉作者协作进行。
