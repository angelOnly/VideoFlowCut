# 连续制作与语义检索：开发与验收

日期：2026-10-10。实施依据：`docs/VideoFlowCut_连续制作与语义检索_通用方法与逐文件实施.md`。

## 实施结果

1. 删除活动生产路径中的素材采用资格：MCP/HTTP 的 `adopt_media_source`、`bind_media_adoption`、应用层采用与绑定方法、声音入口的 `adoptionId`、页面采用表单及采用状态导出阻断。历史合同字段只读保留，旧快照不做破坏性迁移，也不再用旧审核状态判断可否制作。
2. 保留实际媒体读取、分析、播放器、抽帧、纠错及诊断。素材可以直接绑定；文件缺失、哈希不符、源范围越界、类型错误、技术未就绪继续拒绝。检查实际合成引用，隐藏轨道不会被算成导出依赖。
3. 744 条机制的派生文本包含完整运动指令、组合与调整，以及身份元数据。原机制正文、编号、分镜及 120 个视频保持原件；索引增加文本版本与哈希。
4. 在既有 Bridge、Job 与 SQLite 上实现全文词法和独立向量召回，按 RRF 融合。显式筛选继续生效；自动推导的类别和公共起止标签不再形成硬排除。精确编号、清单恢复和稳定分页保留。
5. 通过 `analyze_motion_reference` 按库编号、来源指纹及不超过 15 秒的原片范围补充理解。结果进入独立派生缓存，带模型、工作流、原片哈希、时间映射和采样限制；不覆盖案例、不创建素材采用对象、不改变视频 Revision。
6. 第 21 节的方法替换落到唯一 `.agents/skills/` 源，补清声音直接使用、首次观看与专项审阅边界。发行副本通过同步脚本生成。独立作者实际完成正向方法演练、查询标注和返修样例设计，观察范围另记。

## 失败处理

- 首次自然语言查询先返回真实全文词法结果与语义 Job；同一输入在完成后读回混合结果。服务失败、未知提交不自动重放，不换幂等键绕过。
- 未指定项目时明确返回词法结果。无效显式项目仍报错。Job 创建之后的异常按副作用未知报告，不能宣称无副作用。
- 显式 `retry_media_job` 后沿同一请求的重试链读最新尝试；已有外部 Run 沿现有模型运输恢复。模型输出无效保留原始诊断。
- 模型版本、工作流 Schema、指令模板、原文指纹与文本哈希参与缓存身份。索引变化、错误 ID、路径越界或原片范围无效明确拒绝。
- 视频派生输入的帧数与模型真实采样分开记录；本轮模型未回传采样密度，速度和快速交叠的精确判断仍为未知。

## 连续实现与返修验证

- 小型自动测试使用真实视频源，在交叠中拆成两个文件；24 帧整段输出与分块拼回逐帧相同。
- 作者提供 12 秒开发场面，背景使用实际库 014 的同一 0—12 秒，内容、画幅、配色保持一致。前版人为构造文字争抢，后版保留交叠，通过空间退让、主次和次行时序修正。它是开发缺陷样例，不冒称修复了历史成片。
- 首轮整段为 288 帧，在第 132 帧交叠中拆成 132+156 帧，所有帧哈希与整段一致。真实源时间没有重播。
- 局部增加字区暗衬后的 v2 再次完成同样拆块比较，全部 288 帧一致；两版结果见 `连续拆块_v1.json`、`连续拆块_v2.json`。
- 字体使用已登记的 Noto Sans SC：标题 700，正文 400，覆盖所用中文；没有使用系统字体。
- 作者实际查看前后关键 PNG，确认中文同区叠压改善，同时指出背景原片英文的注意力竞争并进行局部修订。实际观察、版本和限制见 `作者验证.md`。
- 作者另实际查看 v2 的 5 张关键帧：背景英文竞争降低，新旧交叠与全部文案保留。暗衬边界仍可见，保留为风格精修项，不把它描述为无痕处理。前后共实际查看 13 张关键帧。
