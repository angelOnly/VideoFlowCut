# AGENTS.md

## 开发原则

不要过度设计。优先选择满足当前需求的最简单、可靠、可维护方案，只实现明确需要的功能，不为假设中的未来需求增加复杂度。

当“简单方案有明确代价、复杂方案更完善但明显更臃肿”时，先简要说明取舍，并在开发前询问我是否接受该代价，不要默认选择复杂方案。

## 文档与产品决策

- - 让我分析、解释、梳理时，只分析，不改文件；让我澄清、对齐或写入刚确认的结论时，只做解决当前问题的修改。
- 分析和设计不以兼容现有实现为前提。旧方案不合理时，应参考业界成熟实践重新设计并删除旧逻辑，避免冗余；提案须说明旧方案、新方案及拟删除的功能或逻辑，确认后实施。
- 仅当项目自身缺陷导致任务无法继续时，才报修复工单。素材不合适、搜索无结果或思路有误，应调整策略继续处理，不得因此报障停工。

## 任务范围与维护方式

本文件只规定工作入口、协作、正式操作与异常恢复。视频业务方法由对应 Skills 维护，具体任务决定保存在当前稿和项目记录中。

先确认用户本轮要求是分析、文档整理、视频制作还是平台开发。分析不修改仓库或项目；文档任务只修改指定交付；视频制作与平台开发分别在已授权范围内执行。旧实现需要替换时说明取舍和删除范围，不增加未经需要的新系统。关键代码注释和交付说明使用中文。

运行时 Skills 的维护源为 `.agents/skills/`，发行副本沿现有脚本同步。`docs/` 保存说明和开发验证，不另行维护活动技能树。功能、接口、技能路由与相关测试一起更新；记录实际基线和变更，不覆盖用户无关改动。

## 工作入口与协作

视频任务先读 `.agents/skills/project-basics/SKILL.md` 和 `.agents/skills/production-coordinator/SKILL.md`。主题任务转入 `.agents/skills/_shared/TOPIC_TO_FILM.md`；已有项目与局部任务按对应业务入口继续。

主任务负责沟通、项目事实、真实分派、正式提交与结果接回。完整制作建立持续负责的导演，并按业务入口的初始依赖同时启动或续接所需作者，不等导演完成全部规划才逐项分派。局部任务交原负责人处理。宿主代理能力可用时使用真实 `spawn_agent`、`followup_task` 与状态读取，不把审计字段当成真实委派。

角色分工是责任划分，不要求一项 Skill 对应一个代理。同一作者可负责相邻工作；兼任时分别保留每项未完成产物和回传时机。子代理不递归分派；新增依赖回主任务调度。名额或工具不足时按协调技能续接、接替或等待对应依赖，不新建重复任务掩盖状态。

同一任务沿当前完整稿、实际对象引用与变更范围交接。输入改变时交真实差异，由原负责人处理受影响产物；不只替换版本数字重发旧输入。配置中登记表示可发现，不表示全文已加载；按业务需要读取相应 Skill 与参考文件。

## 查询、提交与结果恢复

执行前读取实时 MCP Schema 和能力状态，不把文档中的计划字段当成已发布接口。候选发现、资料读取及不修改创作 Revision 的搜索按自身输入和会话执行，可与无依赖工作并行；正式项目修改、下载提交、生成和渲染提交由主任务按当前接口、Revision 与幂等要求协调。排序提交不等于等待所有异步任务完成后才继续独立查询。

正式项目对象、素材绑定、时间线和任务状态通过已发布接口写入。内容发现和读取使用本次已授权的搜索、浏览器及文件能力；作品源码按当前受管制作方式形成并提交。不得用临时脚本直接改生产数据库、伪造任务结果或绕过正式写入。

返回先检查 `isError`，保存原始响应，再解析结构化数据。区分参数拒绝、版本冲突、运行失败和结果未知。参数明确未执行且接口允许纠正时，按实际字段依据修正后提交；写入版本冲突时读回最新对象和真实差异。已建立的下载、生成或渲染任务继续读原 Job 和 Run，未知结果不换幂等键重放。

重试按接口返回和现有恢复能力执行。重复失败先核对原因，不按固定失败次数自动认定平台 Bug。辅助读取只有部分结果时保存原始结果与诊断，仅恢复失败的读取操作，不自动改变素材、用途或其他项目对象。

## 制作与平台修复分开

视频制作不擅自修改平台源码、依赖、启动器、发行物或已安装插件缓存；平台开发与修复不改正式视频 Project、Story、Scene、Timeline、Revision、Job 或 ExportArtifact。开发验证使用隔离项目、目录、端口和队列，不与生产 Runtime 共用工作队列。

服务未启动、临时连接失败、普通无结果或输入错误，不直接等于平台 Bug。先检查状态和原始诊断，并按已有授权恢复。只有确认平台或服务自身问题且阻断当前操作时，使用 `report_editing_blocker`，同一根因续接同一 Repair Ticket；其他无依赖工作继续。

修复任务定位根因、补测试、构建候选 Release 并验证。发行物保存在 `plugins/videoflowcut/runtime/dist/`，Repair Ticket 使用已有独立存储；不写进视频快照，也不手改已安装缓存。正式切换后检查 Runtime/MCP 的实际 `releaseId`、API 与 Worker 健康，由制作会话重新连接并读回项目状态，再沿 `acknowledge_repair_deployment` 确认切换。未验证构建不称为已部署。

## 已授权的 ComfyUI 恢复

相关服务未启动、停止或崩溃时，先检查进程、8188 端口、启动日志和 Bridge 健康状态。已有实例正在启动时等待，不重复启动或擅自杀进程。确认需要启动后，可由制作主任务使用下列已指定环境和参数；后台启动保留日志，不擅自安装或升级依赖。

```powershell
& 'C:\Users\13222\anaconda3\envs\comfy_5090_313\python.exe' `
  'E:\ai\comfyui\ComfyUI-aki-v2\ComfyUI\main.py' `
  --listen 0.0.0.0 `
  --auto-launch `
  --preview-method auto `
  --use-sage-attention `
  --cuda-malloc `
  --disable-smart-memory
```

确认 `http://127.0.0.1:8188/comfyui-bridge/v1/health` 就绪后，通过正式工具读回当前项目、Revision 和原 Job。启动既有服务不表示旧 Job 成功，也不是新版部署；失败任务只按已发布恢复方式处理。启动仍失败时保存日志并定位，不把连接拒绝本身当成 Bug。
