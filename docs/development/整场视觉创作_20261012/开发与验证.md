## 主要调用链

1. 主题入口 → 协调任务路由 → 同一视觉负责人 → 默认整场方法＋当前稿 → 机制正文/分镜/必要视频 → 受管源码 → 正式生成与原作者修订。
2. MCP `place_narration` / HTTP `/api/projects/:projectId/narration` → `placeNarration` → 可播放视觉范围校验 → 原子Revision提交 → Dialogue Item → narration混音 → Remotion合成。
3. MCP `manage_captions` / HTTP `/api/projects/:projectId/captions/import-srt` → `captionSrtImportSchema` / `parseSrt` → 全量范围与冲突校验 → 同一事务保存卡与导入审计 → `CaptionLayer` / 质量测量。
4. `analyze_motion_reference` → 冻结提示的Job → `runMotionReferenceAnalysis` → 缓存身份与原Run检查点 → 同一范围理解 → 必要字段投影。

## 失败处理与代价

- 声音与SRT的已知输入拒绝发生在事务写入前或回滚中，返回无副作用及纠正输入指引。版本冲突先读当前版本；未知结果不能换键重放。
- SRT只接收标准正文，不让服务端读取任意文件路径；最多10000卡、200万字符。原始时间量化单端最多半帧，量化为空拒绝；整卡/整Program替换限制避免破坏已有来源链。
- 原旁白不自动裁短以适应主线；超出范围需明确调整画面或合法源范围。旁白变更不代表已完成听审。
- 真实技术组合测试精确验证60视频帧、原声音持续长度和频率；AAC输出观察到约43毫秒编码偏移、48毫秒容器尾部填充，未声称样本级同步。
- 参考原件总计21,815,802字节，发行副本亦包含这些按需资料。运行时不会自动加载全部案例；原字体文件不在参考包中。
- 旧分析提示仅用于旧Job恢复身份，新分析使用新提示。没有重建或重分析整个机制库。

五项视频均完整解码通过。作者与主任务实际查看了关键帧和联系表；字幕未遮挡声画样本的主要图解，末段将有歧义的不等号修为“费用不一定等于航司损失”。[声画检查](作品验证/声画检查.json)保存三段音频相关系数（均大于0.99994）和一致的42.667毫秒延迟，支持原音未被隐式变速；不是听感审阅。
