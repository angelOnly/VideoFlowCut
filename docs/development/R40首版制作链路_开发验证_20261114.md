## 主要调用链

创意或动效参考经 `analyze_motion_reference` 分析后，由 `record_creative_decision` 保存原片区间和实际观察。视觉方案用研究决定、区间、素材角色和目标范围建立映射；`prepare_motion_handoff` 冻结导演稿、时间和资料清单。导演采用引用清单，`manage_visual_treatment` 绑定采用，`start_motion_authoring` 核验当前场面、补传文件并启动 OD 首版。`wait_motion_authoring` 接回冻结作品、工作台范围及作品根帧；返修沿原委托与作品继续。

阶段交件核对当前发布范围实际使用的视频素材与已采用源段。目标变化时停止启动，文件传输失败可续传缺件；Windows 长路径和 OD 文件名规则已纳入交接。最终文件审阅证据供项目完成评估复用；导演明确要求精确卡点的事件须有实际测量证据。

真实隔离验收发现，创意研究的阶段来源缺项会在持久化前确定拒绝，但旧回执错误地标为副作用未知。现已将该错误标为输入校验拒绝，并通过真实 MCP 回归核对未写入及纠正后的提交；其他未知异常仍保持原有对账规则。旧版返回的未知结果不能自动视为新版的安全重试许可。

真实制作还发现，OD 收到通用 HyperFrames 指南，却没有受管作品阶段清单和视频槽的完整合同，导致首版发布被拒绝。`start_motion_authoring` 现从共享 Schema 和 HTML 合同生成制作端说明，连同导演稿一起发送；其中包含阶段范围、视频绑定及槽名规则。交接回归检查了实际发送内容，避免由手写字段另维护一份合同。

工作台和正式抽帧对同版作品的画面不一致。定位到 HyperFrames 在 iframe 中给作者节点自动添加全片时间属性，并覆盖原有可见性；顶层正式渲染不执行该分支。工作台编译器现保留作者初始时间属性和可见性，只撤销运行库自动添加的标记。另查明预备 iframe 使用 `display:none` 会暂停绘制回调，造成寻帧超时；现以 `visibility:hidden` 隐藏并继续预取。真实浏览器回归覆盖前进、后退、隐藏层预取、跨镜播放、图片、字体、视频与声音时钟。
