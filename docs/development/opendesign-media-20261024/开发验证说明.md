# OpenDesign 创作分工与正式媒体链路：开发验证

日期：2026-10-24。开发基线 `0a83ea3b2f518da4afbb3729c224d253118c79d9`。
原方案 `docs/VideoFlowCut_OpenDesign_MCP_Integration_Plan.md` 保留用户原有修改，本次实施记录单独保存。

## 已实现

- 创作入口改为场景级简报：表达、真实材料、质量目标与必要边界明确即可进入 OpenDesign；具体美术、镜头与动效在制作中深化。已修改核心三个 Skills、共享交接、派发和相关方法，并同步插件副本。
- 受管捕获直接把 PNG Buffer 顺序写入编码器。不透明作品输出 H.264 MP4；透明作品输出 FFV1/BGRA MKV。只保留首、中、尾确定性样本，不保留全量 PNG。源码、资源、事件、每帧哈希和确定性阈值继续保留。
- 完整提交身份与像素键分离。纯名称、说明变更可复用正式媒体；源码、Props、素材范围、字体、画幅、帧率、帧数、依赖、合成用途或编码改变会失效。`renderedAssetId` 验证已有作品身份，错误引用明确拒绝。
- `Asset.managedPath/sourceHash` 指向正式输出；审阅代理使用独立路径和哈希。服务、离线浏览器与 Web 审阅入口已同步消费实际表示。透明文件按需解码，内存 LRU 默认 64 MiB，窗口工作集约 32 MiB，临时帧随读取清理。
- 同一 ProjectSnapshot 生成执行计划：常规媒体、透明动效与稳定字幕走 FFmpeg；特殊效果、Mask、PiP、原生 Explainer 等必要范围走原 Composition。局部段保持全局帧，作为完整视觉消费，字幕不重复叠加，中间音轨被丢弃。
- 声音使用与 Player 共用的增益函数，保留原声策略、真实源范围、循环交叠、淡入淡出、Duck、包络及总增益。删除旧 `audio-mix-gain.ts` 的导出后再编码路径，只在统一混音应用一次总增益。
- 编码器按当前画幅与帧率实际试编码：支持时用 NVENC p7/hq/CQ18，否则软件 x264 medium/CRF18，报告原因。纯媒体不预热浏览器。导出和预览记录实际 renderer、范围、缓存命中、耗时与资源采样。

## 修改位置与调用链

| 职责 | 文件 |
|---|---|
| 创作交接与派发 | `.agents/skills/` 中方案指定入口及 `plugins/videoflowcut/skills/` 发行副本 |
| 输出、提交与像素身份 | `packages/contracts/src/index.ts`、`packages/motion-work/src/{schema,compiler,hyperframes-contract}.ts`、`packages/edit-application/src/index.ts` |
| 捕获与完成登记 | `apps/render-worker/src/{motion-renderer,motion-stream-encoder,motion-job,motion-output-budget}.ts` |
| 合成与声音 | `apps/render-worker/src/{render-plan,ffmpeg-compositor,timeline-audio,visual-range-cache,exporter}.ts`、`packages/remotion-runtime/src/{index.tsx,audio-semantics.ts}` |
| 读取与审阅 | `packages/media-intelligence/src/motion-frames.ts`、服务媒体入口、`motion-review.ts`、`source-review.ts`、两个 Web 审阅面板 |
| 验证 | `tests/motion-media-pipeline.test.ts`、相关原有测试与 `tests/fixtures/motion-output.ts`、`scripts/verify-motion-media-pipeline.ts` |

正式调用链：原视觉作者传场景简报给 OD → 主任务 `submit_motion_work` → `submitManagedMotion` 固定输入与复用选择 → `runMotionJob` 流式生成或验证复用 → `completeManagedMotion` 登记正式媒体 → 原时间线 Cue → `RevisionRenderer` → `buildRenderPlan` → FFmpeg/必要局部浏览器 → 统一混音、最终编码与现有 ExportArtifact 校验登记。

失败处理：捕获、编码、取消、磁盘不足或身份不符不登记作品；管道退出释放等待，临时文件清理，Job 保留诊断。局部缓存缺失、损坏或淘汰只重建该段；2 GiB 有界缓存回收最旧文件，崩溃留下的过期 pending 文件可清理。导出失败返回 `TIMELINE_EXPORT_FAILED`，不交付只有底层视频的文件；未完成候选及报告清理，已有交付不改动。

- 新测试覆盖 24→30 fps、native→browser→native 接点、普通视频在字幕分段后的源采样相位、同一全局音频范围的逐样本一致性、中间音轨丢弃、透明无损往返、缓存淘汰、编码提前退出、取消与不透明声明拒绝。

## 可重复测量

运行：`npx tsx scripts/verify-motion-media-pipeline.ts`。生成固定 320×180、30 fps、60 帧中文、细线、渐变与移动物件夹具；临时项目结束后清理，报告与样例保存到本目录。
原始机器记录见 [validation.json](validation.json)。源码见 [source.html](source.html)，无损基准见 [reference.mkv](reference.mkv)。

| 纯说明变更复用 | 288 ms | 0 |
| 单个作品的局部视觉输入改变 | 7,662 ms | 60 |

| 同版再次导出 | 537 ms；校验 43 ms | 0 |
| 局部修改后导出 | 571 ms；校验 41 ms | 0 |

捕获阶段约 5,987 ms；写管道等待 1 ms；编码收尾 37 ms；代理编码 83 ms。编码与捕获重叠，不能把“收尾”误称为全部编码耗时。正式无损输出 2,063,196 字节，每版仅 3 个 PNG 样本；导出阶段末临时目录最大采样 2,831,404 字节。Worker RSS 最大采样约 354 MB，不含 Chromium/FFmpeg 子进程；不是整机峰值。

| 编码器 | 编码耗时 | 大小 | SSIM All | PSNR average |
|---|---:|---:|---:|---:|
| x264 medium/CRF18 | 76 ms | 11,406 字节 | 0.996923 | 51.306 dB |
| NVENC p7/hq/CQ18 | 301 ms | 16,502 字节 | 0.997620 | 55.278 dB |

比较以同一无损正式媒体转换到 YUV420P 为参照。短片硬编启动成本更大；不据此承诺长片固定提速倍数，也不将客观编码指标等同于美术、连续动态或声画审片。

## 部署边界与代价

- 只完成仓库代码、Skills、隔离验证及候选构建；未切换生产 Runtime、未手改安装缓存、未修改正式视频项目。插件版本仍为 `0.1.100`。
- 候选 Release：`release-9b6f0b455c8af9bd303d0b38fcb1f6028e1d05f2b7b5299570d8ad6ad2bbc9f8`，产物目录 `plugins/videoflowcut/runtime/dist/`。没有把“构建通过”报告为“已部署”。
- 本轮没有发起真实 OD Run；源码交付 profile 是否在当前 daemon 路由生效，仍须在制作会话读取实际路由与产物验证。未新增不存在的 `sourceOnly` 参数或后台 OD 客户端。
- `renderedAssetId` 当前只采用已有同 pixelKey 的正式受管作品。普通导入的 OD MP4 不携带可验证的源码/绑定身份，不能仅凭名字或时长宣称同版复用；默认有效路线仍是 OD 交源码、VFC 生成一次正式媒体。
- 透明 FFV1 仍可能较大；预算包括正式输出、代理和有界工作集。同版说明复用不重新捕获，但为独立版本追溯复制正式媒体和资源，会增加磁盘占用。
- 原生段暂存无损 FFV1 后统一编码；局部浏览器缓存采用 PNG 捕获、x264 CRF1/YUV444P 中间片，最终再编码。临时磁盘可能较大，任务结束清理；并非零解码或零重编码。
- 普通视频先按原源时间轴重采样再裁切，避免字幕或局部预览重置采样相位；远端源位置可能需要从源开头解码，准确性优先，尚未加入索引寻址优化。
- 稳定字幕仍需浏览器栅格化字形，每卡一次；特殊整段确实覆盖全片时，执行计划仍可能全片使用浏览器，并在报告中如实列出原因。
