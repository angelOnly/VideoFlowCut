### 一套普通字幕规范

`TimelineDocument.captionFormat` 是新项目普通字幕的唯一样式来源。默认使用发行库 `noto-sans-sc-bold` 的固定字体身份，并预留双行空间；这是可统一修改的初始值，不是认定用户选择了双行。字幕作者首次设计仍可选单行。

新增 `fontId`、`lineHeight`、`maxLines`、`paddingHorizontal`、`paddingVertical`、`borderRadius`、`boxWidth`。字体文件身份由服务端登记库派生为 `font`，不接受客户端任意路径或伪造身份。单行溢出不缩字，双行短句仍预留双行高度，固定首行基线与底板高度。文字与主画面相机变换独立。

正式写入：

```text
MCP edit_captions(action=set_global_format, format, base_revision_id)
或 HTTP PATCH /api/projects/:projectId/captions/global-format
  → EditingApplication.editCaptions
  → 样式校验与登记字体绑定
  → Repository.commit（版本检查、原子提交、Impact）
  → Timeline.captionFormat
```

统一模式不保存每卡 format/emphasis；生成、重建和纠错后仍继承同一规范。单卡样式及强调操作被拒绝，返回 `CAPTION_GLOBAL_FORMAT_REQUIRED`，调用方应统一修改全片。正文、来源纠错、真实时序与显隐沿用现有合同。

旧项目没有 `captionFormat` 时保留历史逐卡解释。显式调用全片入口后清除当前卡的局部样式，历史 Revision 不改写。工作台把普通字幕正文保存与全片样式保存分开，旧项目有明确的切换入口。

读取合同变化：`read_captions` 现在返回 `{ projectId, revision, presentation, captionFormat, captions }`；原来直接消费数组的调用方需要读取 `.captions`。`presentation` 为 `global` 或 `legacy_per_card`。

渲染与检查链：

```text
Timeline.captionFormat
  → resolveCaptionFormat
  → 登记字体预载与固定哈希文件校验
  → 共享字幕排版（真实字宽、固定行数、画布边界）
  → 最终画布的独立 CaptionTrackLayer
  → Player / 预览 / 导出
```

质量检查加载同一字体原件并共用排版解释。字体缺失、绑定错误或加载失败明确拒绝；超宽、超高或字幕重叠不会被裁字或多层叠加掩盖。全片字体在无字幕时也预载，空档后复用就绪状态。

## 代价与未完成边界

- 旧项目须显式切换统一样式；不会自动重做历史作品。统一双行占位会为短句留空行空间，可由首次全片设计改为单行，但不能以删词、缩字或猜时间处理溢出。
- 字体依赖发行登记原件与固定哈希；文件不匹配时失败，不静默换字体。首次加载有等待，后续复用已加载状态。
- `read_captions` 返回结构改变；机制工具新增业务字段也需要显式维护投影。
- 任意受管源码自行绘制普通字幕无法靠通用文字黑名单可靠识别。本轮通过正式字幕层、作者职责和真实预览约束重复显示；未新增声称可理解任意源码的重复字幕检测器。
- 新主题首次交付是否主动形成完整动态表达、实际美术品质及完整声画审阅，仍需后续视频制作验证。平台开发完成不代表这些创作结果已完成。
