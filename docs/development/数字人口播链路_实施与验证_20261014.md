### 实际代码缺口

| 位置 | 原问题 | 本轮处理 |
|---|---|---|
| `packages/edit-application/src/index.ts`：`submitManagedMotion` | Avatar 输出为 `actor_video`，视频绑定只允许 `video` | 放行真实已就绪人物视频，保留素材身份、哈希、源范围、受管作品不可嵌套等校验 |

## 主要调用链

1. 用户完整输入与当前项目 → 协调者采用 `project.profile` 及范围路线 → 对应主导演与共用作者。
2. 新写数字人口播：`apply_authored_script` → 正式 SpeechAsset／真实时序 → `create_scene(PresenterScene)` → `submit_avatar_job` → Worker 读取 Bridge Schema、下载及校验 → `completeAvatarGeneration` 写入真实 `actor_video` 与 ActorPerformance。
3. `submit_motion_work(videoBindings)` → `submitManagedMotion` 固定源身份／哈希／范围 → Motion Worker、`TimelineVideo` 连续解码和渲染 → ManagedMotion Cue → 项目合成；普通字幕在最终画布层，讲述音轨独立。
4. 改稿／换声音 → 原人物 stale → 当前采用作品的人物源版本检查 → 更新实际受影响的源与作品后再交付。布局与制作备注不调用人物或声音生成。

## 失败处理与已知代价

- 原有范围、哈希、Revision、Schema 歧义及 Provider 输出错误继续明确拒绝；未知任务结果沿原 Job／Run 恢复，不换键重放。
- 新增版本拒绝不留下部分写入；没有人物范围的解释片不增加人物资源前置。
- 完整舞台通过不透明背景明确接管外层人物；没有新增自动隐藏外层人物或自动生成 Mask 的能力。透明作品须先核对实际可表达的外层可见范围。
- 已烘焙作品不能自动把内部旧口型换成新口型。需要重新生成人物或更换声音时，必须显式更新相关绑定并重新渲染作品；未提供跨版本自动重绑定系统。
- 本轮未验证在线数字人 Provider 的中文口型、身份稳定、手势或局部重生自然度；未执行真人审美定稿，也未发布正式视频。
- 代码、Skills、候选构建与隔离技术链路分别报告。当前会话安装插件的 Skills 仍来自旧安装版本，仓库同步不代表会话自动重载。本轮不将这些结果扩大为“新数字人全片创作及实际表演验收全部完成”。
