## 主要调用链与失败处理

- 审阅：MCP/HTTP → 验证实际媒体、文件身份、范围和目标版本 → 仓储事务保存独立观察 → 质量检查读取作品版本/声音依赖匹配记录。媒体检查期间项目改变会拒绝保存；旧证据不标成新版。最新局部混音失败不能被旧整段通过掩盖。
- 校样：正式提交入口 → 固定输入 Job → 原渲染器定位完整作品根帧 → 只生成窗口 PNG 与代理视频 → 原哈希、输出帧数和确定性核验 → 返回 `motion_proof`。不创建 Asset/Revision；确认后省略窗口提交完整版本。编译、源变化或校验失败仍返回原诊断，不降质、不登记半件。
- 配音：正式 Job → 每段提交前保存意图 → 保存 Run → 原 Run 等待 → 下载并校验 → 保存段检查点 → 真实时长装配 → 保存总轨身份 → 核对文稿后原子写入。中断恢复沿原 Run；已完成段核对哈希后复用。明确失败才允许显式重新生成该段；无 Run 的未知提交拒绝重放。总轨已写入后重复完成不新增 Revision。
- 调度：平台只跟踪 Job/Run；主协调使用宿主真实状态核对作者与审阅者。先保存部分成果，确认无法推进后接替剩余范围，不能用心跳或审计字段宣称代理有进展。

## 验证

所有业务回归使用临时独立工作区与本地小媒体；没有使用真实生产队列或调用线上配音生成。

- TypeScript 类型检查、Web 构建通过。
- 真实 Chromium 校样与完整渲染对照：同一输入 8 帧，校样只渲 3～5 帧；对应 PNG 字节一致，保留完整 duration，校样期间项目快照/Revision 不变。
- 三段模拟配音：第二段等待中断；恢复复用第一段音频，继续第二段原 Run，只新提交第三段；重复完成不新增 Revision；未知提交拒绝重放。
- 审阅/局部证据/声音/版本/失败恢复、导出用途、确定性、源校验、MCP 与操作锁、数据库字段目录、技能路由及发行副本回归通过。具体测试见本次新增 `editorial-range.test.ts`、`voice-recovery.test.ts` 与更新后的既有测试。
- Skills 使用既有 `plugin:sync-skills` 同步；源与副本及引用完整性检查通过。
- 四个发行入口使用相同 esbuild 基本选项构建到 `.repair-validation/performance-candidate-UClx5B`；隔离 CommonJS MCP 实际连接确认校样 Schema、统一 outcome、配音恢复与批量查询。它是入口构建验证目录，不是完整已安装 Release。

## 计时与实际代价

Job 的 `result.execution.attempts` 只记录实际领取和观察到的终态；租约到期前进程退出时，旧尝试没有真实结束时间就保留缺失。`lastProgressAt` 来自检查点变化，不来自续租。Motion 额外保留实际阶段区间。并行任务应按时间区间求并集，不能简单相加；宿主创作/审片耗时仍要结合宿主真实事件，平台不会伪造这部分计时。

旧快照里的旧审阅字段不再参与当前通过判定，不新增兼容层或迁移系统；历史快照本体保留。客户端改从独立 reviews 读取记录，ProjectState 的 snapshot 只保留一份。独立审阅集合保留历史，因此需要读写其 JSON；校样仍有启动浏览器和资源校验的固定成本，最终完整作品仍完整生成。局部窗口不会证明整片质量。新增计时带来少量 Job JSON 写入。Web 构建保留已有大包提示，未为此扩大为前端拆包重构。

没有运行固定长稿的多轮生产性能对照，因此不宣称整片提速比例或“性能最优”。未调高并发、降低分辨率、移除真实媒体/确定性检查或创建跨版本帧缓存。已安装插件、生产部署、实际完整视频验收仍是后续独立步骤。
