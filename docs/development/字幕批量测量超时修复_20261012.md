# 字幕批量测量超时修复

## 问题与根因

工单 `repair_ticket_fdabbddb-463f-4fa4-b8fe-1e80fe7a5335`，修复者 `/root/skills`。0.1.80 的正式质量报告在 33 张共用登记中文字体的字幕卡上两次返回 `CAPTION_LAYOUT_MEASUREMENT_UNAVAILABLE`，外层 Runtime 请求 60 秒超时。

`measureCaptionTextInBrowser` 已按字体哈希避免重复读文件，但随后把字体 base64 放进每张卡的浏览器调用参数；直到浏览器内加载 FontFace 才再次去重。8,543,168 字节的 Noto Sans SC Bold 因而随 33 张卡发送 375,899,436 字节的重复 base64。真正需要发送的字体内容只有 11,390,892 字节。

旧代码在隔离真实浏览器中以同样 33 卡规模复现，60 秒测试期限内未完成；停止的仅为本次隔离测试的 Node/Chrome 子进程树，没有停止正式 Runtime 或渲染。

## 最小修改

- `packages/quality-system/src/caption-measurement.ts`：先核验每卡绑定身份，再独立传入按哈希去重的字体文件数组；卡片仅传字号、字体身份与待测文本。
- `tests/caption-measurement-batch.test.ts`：33 张不同长度中文卡一次真实测量，逐行验证字宽及空文本结果。
- `plugins/videoflowcut/.codex-plugin/plugin.json`：补丁版本升为 0.1.81，避免官方安装覆盖正在使用的 0.1.80 缓存目录。
- 沿现有 `plugin:build-runtime` 生成候选发行物，没有手改已安装缓存。

调用链仍为质量报告 → `measureCaptionLayouts` → 同版 Runtime 的 `/api/captions/measure-text` → 登记字体校验 → 独立浏览器真实测量 → 既有布局判断。保留字体哈希、错版、无效结果和实际溢出拒绝，不增加估算放行、重试或新的缓存系统。

## 失败处理与代价

字体校验、真实浏览器或测量失败继续明确阻断；不跳过门禁。候选安装核验失败、队列未空或版本不一致时不切换。每次仍启动并关闭独立浏览器，仍需传输每种实际使用字体的一份原件；本修复只消除随卡数重复的传输，不改变既有浏览器生命周期。
