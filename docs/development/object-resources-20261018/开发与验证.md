## 本轮实现

物件效果标准、案例学习与制造方法接入同一持续视觉作者。导演负责表达和关键效果，视觉负责具体造型、结构、材料、动作及源码，审阅引用同一标准。未新增角色、插件、数据库、全片物件配额或创作审批。

正式新增 `prepare_object_resources` 与 `read_object_resource_capabilities`，接入现有 MCP、能力总览、Application 和媒体 Worker。输入使用真实项目图片 Asset、整数 Revision、幂等键、明确区域与遮罩；输出仍是现有 image Asset，provenance 保留派生来源，配套 JSON 保存部件布局。原图片绑定、八槽限制、源码白名单与渲染合同不放宽。

主要实现文件：

- `packages/media-intelligence/src/object-resources/{schema,prepare,atlas,index}.ts`：操作合同、裁切、同尺寸显式遮罩、透明裁边、确定性图集及依赖哈希。
- `packages/media-intelligence/src/raster-decode.ts`、`apps/render-worker/src/motion-images.ts`：提取并复用原生 EXIF/ICC、原尺寸 sRGB 解码；既有 JPEG 固定解码及关闭诊断保留。
- `packages/edit-application/src/object-resources.ts`、`index.ts`：输入验证、Job 幂等、固定源身份、整套资源原子登记及恢复。

- `apps/server/src/object-resource-tools.ts`、`mcp.ts`、`motion-tools.ts`、`app.ts`；`packages/contracts/src/index.ts`、`packages/project-overview/src/index.ts`：工具、能力、Job 类型及来源关系接入。

## 调用链与失败处理

`import_media → media_analysis → prepare_object_resources → object_resource_preparation → 图片与 layout.json 齐套发布 → 一个 Revision 原子登记全部 image Asset → submit_motion_work(imageBindings) → motion_generation`。

遮罩先作用于规范化源像素，裁切和透明裁边保留原 `sourceSize/localRect` 与 `trimOffset`。图集按高、宽、部件 ID 排列，不旋转、不缩小，每部件扩展两像素边缘。作者仍可独立显示和驱动各部件。

明确失败包括缺源、越界、遮罩模式遗漏或尺寸不同、全透明、源字节变更、页面预算不足、版本冲突、取消及产物损坏。超页数返回 `requiredPages/largestParts`。同一幂等键回读原 Job；不同输入占用同一键时拒绝。文件齐套但登记中断时读取原发布目录；登记已成功但回执中断时依据固定 Asset ID 恢复，不重复推进 Revision。失败不覆盖旧的有效资源。

加工登记严格核对提交时的 Revision；执行期间有其他正式写入会失败，需要读取真实差异后处理。失败的新目录可能保留以便恢复，不自动清理旧有效资源。PNG/JPEG/WebP 支持静态图；APNG 与动态 WebP 须先明确取得静帧，避免非确定性烘焙。

当前每任务上限：32 个源、128 个部件、4096 像素页边长、8 页；单源 64 MiB、总源 128 MiB；单源 16,777,216 像素、总源 33,554,432 像素；已知工作像素预算 512 MiB。该预算不包含浏览器进程自身开销，不是全片素材配额。受管源和遮罩必须位于当前项目内；不接受路径或 URL 代替 Asset ID。

## 当前样例稿与实际输出

两个主体都由本轮新制，未修改 R138、六个历史案例或 Token 原片。借鉴依据是现有案例源码中的共同支点、局部坐标、静态表面与运动状态分离；未宣称本轮重新连续观看原作。几何与材料由本轮按新主体设计，非原组件换名称。

**罗盘／资源组合。** 表达“偏转后仍能辨认稳定方向”。黄铜环、内侧暗边、纸面刻度与红蓝针形成材料区别；从正面看，固定表盘保持参照，指针绕共同轴心衰减摆动。原创 SVG 只用于开发素材制备，取得实际 PNG 后正式导入；工具将表盘和指针裁成同页，保留负局部坐标与独立活动能力。作品通过真实图片绑定显示，未将 SVG 程序或开发 imageData 注入生产渲染。

**雨伞／代码绘制。** 表达“滑套推动骨架，布面随之展开并形成遮雨空间”。采用浅底平面插画，布面分成四色瓣，伞骨、支撑杆、轴杆与弯柄分别绘制。展开角驱动半径与高度，固定杆长反算滑套位置；对初稿支撑连接进行了修订。代码路径不依赖图集，也不照搬罗盘材质与版式。

当前有效输出集中在 [validated](validated/)：

- [罗盘视频](validated/罗盘_资源组合.mp4)：960×540、30fps、120 帧、4 秒，100,088 字节。
- [雨伞视频](validated/雨伞_代码绘制.mp4)：960×540、30fps、120 帧、4 秒，88,699 字节。
- 同目录保存两份 TSX、原创部件 SVG/PNG、真实 `compass-layout.json`、`mcp-audit.json`、`result.json`、`release.json` 与关键帧。早期试运行记录仍保留在上层目录，不作为当前有效样例。

两份 MP4 均通过完整解码检查；直接检查了当前第 0、90 帧，确认主体、独立指针、展开骨架和文字布局。静帧检查不证明连续速度、力感和完整观看体验。这是无声开发样例，不是含真实旁白、普通字幕和相邻镜头的交付片，也不是用户对美术的认可。未登记虚构审阅或 ExportArtifact。
