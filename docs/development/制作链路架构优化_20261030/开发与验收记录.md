## 已落地的主调用链

### 作者交件

作者维护一份 HTML 和一份创作清单。Local Codex 的 prepareAuthoredWorkSubmission 计算配对摘要，正式 freeze_project_work 核对 Run 与真实文件版本后原子冻结；read_frozen_work 读取固定的完整字节，不读取后来修改的工作件。

运行中的原作者可以通过现有 Run 令牌调用 od motion-work stage。该操作配对明确的 readyRanges、保存源版本、冻结并发出 frozen_work 事件；作者可继续编辑同一作品。没有令牌不能由外层猜测当前文件已交件。

主任务用机器转发把完整字节包交给 VFC import_motion_bundle。VFC 核对长度、两份摘要和包身份，原子发布到项目 inputs/motion。正式 submit_motion_work 接受 work/frozen_work 二选一，归一后仍只调用 submitManagedMotion；输入来源固定到 Job.inputBundle。真实图片、字体和视频继续沿原绑定解析，不由源码包伪造 Asset。

### 生成、采用、声音与预览

submit_motion_work(on_success) → 固定原 motion_generation 输入及目标依赖 → 既有渲染 Worker → 真实媒体和事件验证 → commitMotionResult 短事务：

1. 核对原任务、当前目标和相关依赖；
2. 登记唯一正式 Asset；
3. 采用整件或正式局部范围；
4. 对真实不变事件先重绑声音，再统一 reconcile；
5. 写准确的新 Revision；
6. 为该版本和范围插入 Preview Job；
7. 在父任务保存同一采用结果。

任一步失败共同回滚。文件生成、哈希、媒体探测和模型调用不放进数据库写锁。相关变化保留已生成素材，返回 needs_reconfirmation，原画面与音轨保持；不把生成成功当作采用或预览成功。

重新确认时 manage_effect_cues(action=adopt_work_and_preview) 创建 motion_adoption 短任务。它由现有 RENDER_JOB_KINDS/处理器领取，核验已有素材字节、提交时候选身份和当前目标后调用同一采用事务，不重新生成画面。未核验的候选即使在事务前恢复成旧身份也不能自动采用。

同键不同基准、来源、作品或采用指令拒绝；重领已保存结果的任务返回原 Asset/Revision/Preview。通用 Worker 终态合并保留事务保存的采用检查点，并发交错完成也从持久结果回收原素材引用。

## 失败处理与代价

外部结果未知先对账原Run，不换键重新生成；参数明确未执行可按诊断纠正。采用冲突保留生成素材与具体原因，预览失败只恢复该预览。字幕冲突保留原识别证据，不覆盖人工字幕；旧活跃Job缺新固定输入身份时明确拒绝，部署前需核对旧队列，不新增兼容执行。

源码与清单的配对、受管副本和识别原文增加磁盘占用，base64消息有约三分之一体积开销。真实素材/工具二进制身份核验、短任务和短事务也有成本，已保持在现有模块内；未新增数据库、常驻服务、DAG调度器或渲染器。

声音复核保留原Preview的hash、版本、方法和范围。系统字体身份无法证明时，含字幕或浏览器文字的声画范围不跨版复用；未知环境不伪造适用结论，旧文件真实观察仍保留。只有实际目标文件哈希匹配才可引用到该文件，工程Revision相同不代表新Artifact已经听审。

本轮没有复测约83秒正式解释片的完整制作，因此尚不能声称“一小时以内”已达成，也不把18帧隔离样片的耗时外推到整条创作链。完整文案/取材/作者返修、连续动态和声音效果需要另做同类制作对照。

后续已按用户明确要求重新部署VideoFlowCut正式插件及Runtime，见[部署说明](E:/ai/VideoCut/docs/development/制作链路架构优化_20261030/重新部署/部署说明.md)。新注册连接和正式服务同版，原项目及任务记录摘要未变。当前聊天的外层启动器仍待宿主重新连接；Local Codex独立服务本轮未重部署。正式片重做和整条制作的一小时目标仍未验证。
