## 调用链

`manage_visual_treatment.presenter_uses → prepare_avatar_sources → submit_avatar_job(contract_version:2) → Worker裁真实Dialogue采样 → Bridge/LTX → actor_video + avatarSourceReceipt → adopt_avatar_source → Timeline/ActorPerformance → 原Remotion/质量链`。

准备接口只读，不创建第二份计划。准备后的分镜改变会使预检摘要失效；提交重新计算当前范围。正式采用不自动重写 TSX，画面编排仍由原视觉作者实现。

`presenterUses` 未设置不推断全文生成，空数组撤回该部分人物。动态头像、分屏、纸片和容器只改变合成；源条件仍满足时不重新配音或生成。多个不连续缺口分别提交；明确重新抽样用 `attempt` 保留独立尝试。段内 `aligned` 必须有真实段/词边界，否则先做局部音频核验，不按字数估时。

## 删除与失败处理

删除旧新任务提交路径中的全文/完整SpeechSegment限制、`supportsPartialRegeneration` 强制全文分支，以及生成完成自动采用旧placement的路径。旧Job完成与恢复仍按旧合同处理，未批量迁移历史项目。

- 声音、照片、表演要求与实际采样决定有效性，无关Revision及兄弟任务回写不会导致重复生成。
- 已运行任务即使需求撤回仍可回收源；未提交Provider且无人需要的任务停止执行。
- 未知提交、丢失Run且无已核验文件时明确报结果未知；原Run可查时继续查询、下载、登记，不重调LTX。
- 时长不足、编码不支持、声音映射不连续、旧预检和错误当前采用分别明确拒绝。没有循环、冻结或变速补嘴型。
- 延长需求时保留已经有效的部分；局部换源仅替换对应范围并保留前后片段。新源未完成不会先删除旧源文件。
