## 流程与职责

```mermaid
flowchart LR
  A[主题和已有内容] --> B[导演协调主线与事实]
  B --> C[素材 文案 创意 视觉并行探索]
  C --> D[视觉作者完成整幅画面与同源预排]
  D --> E[导演检查主要采用]
  E --> F[主任务准备并核验交付]
  F --> G[制作作者沿同一作品深化]
  G --> H[原视觉作者 创意作者 导演检查]
  H --> I[按问题返修或继续正式合成]
```

导演负责准确内容、主要采用和跨段关系；素材作者取得、核实并描述真实材料；创意作者观察完整参考并提出可迁移方法；视觉作者持续负责整幅构图、美术、运动、预排、交接和视觉返修；制作作者深化既定画面与源码；主任务负责资源、项目、版本、阶段交件和正式提交。

## 交付契约与失败处理

`prepare_motion_handoff` → `prepareReferencePackage` → 交付并核验文件 → `verifyReferenceDelivery` → `start_motion_authoring` → 现有阶段冻结、登记与采用。`process`、`visualRoles`、`preserve`、`adapt` 继续保存完整过程及保持／深化边界，不复制为另一份场面正文。

可选 `visualPlan` 保存 `draft`／`previewed`／`pending` 状态、主要角色、可选参考映射与图形主导理由。`previewed` 使用现有项目 `MotionWork` 的 `workId` 和作品根帧范围，项目快照提供真实定义哈希及可用时的制作项目、Run 和冻结版本。交付包同时携带该作品固定定义中的源码、绑定及根时钟。角色、实际采用参考、素材身份与范围、预排作品范围及哈希不一致时返回场面诊断；显式 `draft` 或 `pending` 不作为已完成预排。正式启动前重新核对当前素材、固定源码及制作端文件；预排源于其他制作项目时拒绝继续。无 `visualPlan` 的既有合法输入仍可准备，但启动文字明确资料就绪不代表完成视觉预排。

这些检查只验证身份、结构和资源一致性，不判断画面审美，也不证明真实观看。Run 进行中沿原 Run 接回阶段交件；原 Run 已结束时使用现有续接入口。资料不足、实现遗漏、设计问题和内容变化分别交原负责角色处理。
