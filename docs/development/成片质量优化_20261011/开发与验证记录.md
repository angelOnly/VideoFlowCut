## 实际消费者核查

- `manageAssetRequirement` 可通过现有主题、用途、画面说明创建需求，不要求 Script、Scene 或句子 ID。
- `refreshAssetRequestProgress` 不把首个成功文件自动当作关闭；搜索与获取拒绝的是 `closed`。当前更新接口不支持重开 `closed`，所以方法明确指向新建适用需求，不承诺不存在的恢复接口。
- `startProductionRun` 的 `loadedSkills/loadedReferences` 是调用方记录，代码未将整个参考目录加载为提示词；没有为案例新增自动加载服务。仅凭这些字段不能证明宿主实际读取。
- 配音仍由明确的声音提交执行，本轮没有增加背景替换自动重配的消费者。素材、声音及其他对象的版本与失效规则保留。

## 主要调用与引用链

写作：`narration-writing/SKILL.md → writing-methods.md → 按需 expression-patterns.md → 确需示范时 examples/README.md → 所选单篇`。

美术：`visual-treatment-planning/SKILL.md → art-direction.md → 按需 art-directions.md`。素材与动效从各自专业入口进入，不经过六篇旁白。

返修：编排或预览问题 → 原文案／素材／视觉／实现作者 → 实际新稿、文件、设计或源码 → 合并当前稿 → 主任务正式提交与影响读回 → 相关声音、字幕、绑定、时序及接点复看。

视频：`submit_motion_work → motionSubmissionSchema → submitManagedMotion 固定绑定与哈希 → runMotionJob → planMotionVideos → createMotionVideoProvider → renderManagedMotion → 源复核与完整产物发布`。

## 失败处理、代价与后续边界

正式写入的版本冲突、参数拒绝、失败 Job 和结果未知合同保持不变；未知任务继续读原 Job/Run，不换键重放。普通无结果或不合适素材由原作者换方向和补材，不报平台故障。

不设选段总数上限不等于无限资源。并发画面、源清晰度和作品长度仍可能触发实际资源诊断；不会静默少放镜头或降质。参考文件接入与提示方法也不能保证每个作者每次产生好作品。

待生产阶段完成：启用匹配的插件与 Runtime、确认新会话实际 Skill 路径；真实主题广搜与文件取得、补材回编排、连续演出与声音观看、不同题材最终效果检查。开发交付与这些生产结果分别记录。

原始构建、测试与候选日志保存在 `E:/ai/VideoCut/.cache/quality-optimization/`；本目录 `验证摘要.json` 固定本轮结果和候选能力。用户原有未跟踪方案、素材、交付及其他目录保持原状。
