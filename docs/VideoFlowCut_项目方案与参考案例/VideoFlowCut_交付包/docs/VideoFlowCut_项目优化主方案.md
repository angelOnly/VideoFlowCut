# VideoFlowCut 整场视觉创作与制作链路实施方案

## 1. 目标、范围与实施原则

让用户只提供主题、可选的已有材料，以及本次已明确的要求，系统就能主动完成整片内容组织、素材准备、美术、动效、声音与字幕，交付画面有表现力、动作与构图相互配合的视频。用户不需要逐次提醒“不要只动局部”“加花字”“重做背景”，也不需要提供外部参考成片、机制编号或逐镜答案。

**创作的基本单位是一段随时间发展的完整画面，不是静态页面上的几个效果。** 美术负责的造型、颜色、字形、主次和空间，与动效负责的变化、配合、节奏和连接，在同一项设计中决定。完整画面里可以有稳定部分、局部动作和自然切镜；不要求全屏所有东西一直动。

**完整美术与动效设计是产品默认工作，不以用户填写风格、花字、材质或转场要求为启用条件。** 用户只给主题时，系统也要主动完成文字造型、材料处理、空间层次、画面发展和动作配合；默认的是这些设计工作与作品完成度，不是某一种固定外观。

本方案调整正常任务入口、创作上下文、视觉职责、参考使用、实现交接、声音字幕接入和作品验证。保留现有导演、作者和正式受管渲染体系，不新建动画引擎、组合数据库、审美打分服务或一批审核代理。

代码核对基线：`angelOnly/VideoFlowCut`，提交 `7ab8d1c70468fa5c7cfe18383cc444ffe790778f`。实施时先读取工作区 `AGENTS.md`、实际相关代码和运行工具合同；仓库基线与本机已部署 Release 分别核实。本文件是实施要求，不表示已修改仓库或完成部署。

### 1.1 完成标准

| 方面 | 应达到的结果 |
|---|---|
| 内容与整片 | 画面、语言和声音共同表达，场面根据内容发展，不按句号或字幕卡机械清屏 |
| 美术与动效 | 主体变化时，文字、辅助内容和可用空间有相应安排；不同内容不被固定页头与中央窗口限制 |
| 默认美术与审美方向 | 无风格要求时也主动完成有表现力的文字、材料、构图与动作设计；有明确要求时准确承接，不擅自扩为固定风格 |
| 参考使用 | 自主使用内置机制正文、分镜与视频，按实际素材适配；既不机械复制，也不只取一句原则 |
| 实现 | 按本片已经作出的具体设计生成源码，保留对象关系、源时间和准确内容 |
| 字幕与声音 | 原声音和可靠字幕时间能通过正式接口接入；普通字幕独立、固定样式、背景按实际行数计算 |
| 验证 | 用户对具体作品的认可、技术测试、审阅范围分别记录，不用其中一项替代其他项 |

正常制作允许内部设计、正式生成、查看与修订。不增加“先做独立样片、先交图片证明、逐镜等待用户批准”的必经流程。

## 2. 架构判断：创作任务需要对齐，渲染体系不需要重建

### 2.1 模型与程序的职责

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| 主任务与导演 | 表达目标、内容取舍、前后关系、真实分派、正式提交与结果接回 | 不把每个镜头提前锁成固定模板，不替视觉作者猜坐标和曲线 |
| 视觉创作 | 同一连续范围的美术、素材表现形式、动作、文字和实现；根据正式结果修订 | 不把事实材料直接当版式答案，不只向固定页面追加效果 |
| 检索与素材工具 | 返回真实文件、候选、完整说明、分镜、视频入口、身份和运行状态 | 不自动完成本片分镜，不把搜索分数当审美评分 |
| 项目与渲染程序 | 校验输入、固定绑定、计算源时间、执行源码、合成声画、保存产物 | 不把“有质感”这类描述自动转换成更好的视觉设计 |
| 审阅 | 看实际作品，区分内容、美术、动作和实现问题，向原负责人反馈 | 不只证明工具成功，不把作者意图当作已经发生的观众感受 |

现有 `motionSubmissionSchema` 接收源码、参数与素材绑定；`runMotionJob` 负责固定输入和渲染。渲染器不会重新决定主体、文字或背景的位置。已有正式环境已经生成用户认可动效的作品，实施不以新增渲染能力为创作改进前提。[S1][S8]

### 2.2 局部化为什么容易发生

当任务先完成一个静态布局，再把它作为“已选美术”传给动作设计，最容易实现的就是保留背景和文字位置，只改变中间对象。即使是同一位作者，先后完成两份不能互改的设计，仍然会发生这种问题。

完整机制进入这个任务后，也可能只剩一项局部作用：原机制同时安排窗口变化、文字退让和新内容建立，当前任务却只需要一个高亮或入场，于是其他关系被省去。问题不一定是资料缺失或模型看不懂，也可能是交给它的实际工作已被缩小。

当前主线、任务路由与场面交接中，既有“美术与动作共同形成”的要求，也存在“先可运行粗排，再深化美术与曲线”“前期独立形成美术，随后追加机制”的具体次序。应统一这些口径，而不是继续增加相同的职责形容词。[S2]

这些是由实际依赖关系支持的风险判断，不是声称已通过单变量实验确定每次失败的唯一原因。

### 2.3 整体设计不等于取消局部动作

一个主体放大时，辅助内容退让，相关标签重新定位，后续信息进入腾出的空间，即使背景保持稳定，也属于整场设计。只把整个根容器一起缩放，内部关系始终不变，不足以说明已经共同设计。

局部高亮、单个花字和稳定阅读可以保留。判断重点是：这些局部是否完成当前任务，整段中其他必需的变化是否也被解决。不能按运动面积、机制数量、布局数量或背景切换频率判定好坏。

## 3. 正常生产流程

```text
主题、可选材料（无需花字、材质或风格术语）
                     │
        正常入口携带默认制作要求，并承接可选的明确要求
                     │
        ┌────────────┴────────────┐
        │                         │
   文案研究与试写             主题素材探索与取得
        │                         │
        └──────────分批汇合─────────┘
                     │
        导演协调表达重点、准确讲述和前后关系
                     │
        同一视觉作者设计当前完整连续范围
        ├─ 看真实材料及可操作条件
        ├─ 共用内置参考，判断外观与动作
        ├─ 同时设计开始、中途、结果和下一步
        └─ 需要时向原作者提出具体改稿或补材
                     │
          同一份当前设计 → 源码与真实绑定
                     │
        正式生成 → 作者查看实际输出并修订
                     │
        正式声音、普通字幕与全片画面共同合成
                     │
             独立终检 → 完整交付
```

默认制作要求来自运行时业务方法，已确认的个人默认仅作为可选补充；两者不混写。主任务沿现有路由安排负责人，不以偏好是否为空决定是否启动视觉创作。图示表示产物依赖，不是全串行排队。文案、取材、声音准备和无依赖的设计可以并行；实际文件分批交回，具备条件的范围先做。正式声音已存在时提前作为时钟使用，不必等视觉制作结束才读取。

没有锁定的草稿可以在材料和视觉发现后调整。用户明确锁定原音或正文时，在其边界内重做画面，不能擅自变速、删条件或通过静止等待补时长。

技术 Scene、一个句群和一个源码文件不是同一个单位。内容需要连续就连续，需要转题就切镜；输出拆件不能反过来决定内容边界。

## 4. 默认完成专业视觉设计，偏好只用于定向调整

### 4.1 默认的是设计工作和完成度，不是固定外观

用户只说“做一个关于某主题的视频”，就应得到经过完整美术与动效设计的作品。花字、材料处理、图形造型、空间层次、镜头组织和动作配合属于作者的正常工作，不是用户点名后才增加的选项。不能先交基础说明页，等用户逐次说“加描边”“加材质”“让背景也参与”，再逐项补齐。

本产品的默认方向是有表现力的解说与视觉表达：素材能成为主角，重要信息有清楚且经过设计的呈现，画面随内容发展，文字、素材和图形相互配合。具体作品可以活泼、理性、克制或有戏剧性，但都需要达到相应的设计完成度。

| 默认必须处理的工作 | 作者主动作出的决定 | 不固定的具体答案 |
|---|---|---|
| 画内重点文字 | 选择哪些词需要强调，并把字形、轮廓或承托、大小、位置及动作一起设计；花字与动态排印可正常采用 | 不要求所有字描边，不指定同一种贴纸或固定标题区 |
| 材料与质感 | 处理真实素材、原件和原创图形的边缘、明暗、色彩、遮挡与空间关系，使主次和材料感在实际画面中成立 | 不要求全部加纸纹、玻璃、金属、颗粒或阴影 |
| 整幅画面的发展 | 内容推进时共同安排主体、辅助信息、背景关系与观察范围，让重要变化带动构图 | 不要求每句换镜、全屏一直运动或每段一种背景 |
| 视觉一致性与变化 | 为本片选择协调的字形、色彩用途、图形语言与节奏，同时允许不同材料有不同呈现 | 不把一次成功案例的配色、胶带、纸片和布局变成全项目模板 |

**必做的是设计，不是把所有装饰全部用上。** 不用某项手法可以是合理的表达选择，但不能以“用户没要求”为理由跳过其所承担的设计工作。真实光影已经有质感时保留并组织它，不必叠加人工纹理；文字以尺度和遮挡就能形成重点时，不必再加多重描边。判断依据是实际画面，不是效果数量。

“不预设拼贴风”不等于“默认极简”，更不等于只剩裸文字和纯色底。系统可以自主使用拼贴、花字、空间图解、实拍合成等不同手法，也可以在一部片中配合使用，具体取舍由内容与素材决定。

### 4.2 偏好字段是可选调整，不是美术和动效的开关

`ExplicitCreativePreferences` 的 `visual`、`motion`、`background` 等可选维度，以及 `initializeCreativeBrief`、`mergeCreativePreferences`，继续用于承接和合并有明确来源的用户设置。[S3] **偏好为空只表示用户没有额外指定，不表示没有视觉目标，也不表示花字、材质或整场动画被关闭。**

三类信息分开保存和使用：

| 信息 | 来源与位置 | 无用户偏好时如何处理 |
|---|---|---|
| 产品默认制作要求 | 正常任务入口及相关运行时 Skills，核心要求为本章与第6—9章 | 始终执行，不向用户索要美术术语，不回退到低完成度模式 |
| 用户明确要求及已确认的个人默认 | 当前真实输入与已有偏好字段 | 未提供就不补造；有输入时按实际范围调整默认创作 |
| 本片具体设计 | 导演与视觉作者的当前场面稿和源码 | 由模型主动形成，不能因为偏好字段空着就让设计也空着 |

不得为使流程启动而伪填“用户喜欢某种风格”，也不得写出“只有 `visual` 非空才设计花字与材质”的条件。实现时核查正常路由与交接；若存在把明确偏好当成视觉创作开关的逻辑，应移除这一条件，保留用户真实的限定与覆盖关系。此处是开发要求，不假定当前代码已经存在某个具体开关。

当前明确要求优先于已确认的个人默认，未指定部分仍执行完整的默认制作。用户要求克制或简洁，应改变表现方式和强调力度，而不是减少设计工作。用户只要求机械改字、保留原片或只导出时，则按真实任务范围处理，不借默认美术扩成未经要求的重做。

用户只认可某段动效，就记录对应作品与范围，不反推新的全片风格；用户明确提出长期偏好时，才按现有正式设置流程保存。作者自主选择的字体、色板、造型和媒介保存为本片决定，不写成用户原话。本文件不执行偏好写入，也不清除已有真实设置。

### 4.3 没有风格要求时，模型也必须作出具体设计

同一视觉作者先理解当前要表达的关系，查看真实素材能提供什么，再使用已有库内候选、分镜与必要的视频范围形成画面。研究事实不必机械调用机制；进入视觉创作后，不能因为用户没有说“参考美术”就只看动作摘要。

设计需要具体到：什么是这一刻的主体，文字是主角、标签还是辅助条件，素材怎样处理和占据空间，颜色与明暗如何分配，重要变化发生时其他内容如何配合。花字、材质和背景不是源码完成后的附加修饰，应与这些决定一起形成。

这些工作写进现有当前稿并落实到源码，不新增风格问卷、必填评分或逐镜确认。无需给本片先命名一种风格，也无需每段列出所有未采用手法的理由；但实现者必须能据此做出具体画面，不能只拿到“自主发挥、做得高级”的描述。

同一部作品可以让实景、资料、空间关系、图形或文字在不同段落成为主角，并保持本片的设计联系。换主题和材料时可以重新选择视觉语言；统一的是默认完成度与协作方式，不是所有项目的外观。

### 4.4 把默认要求接入正常流程，不塞入个人偏好

主任务启动视觉创作时直接承接第4.1节的默认任务，叠加用户确实提出的调整；不能只转发一个空偏好对象，就让下游自行猜产品目标。详细方法集中在视觉与动效的中心参考中维护，入口短写并引用，不在每次任务中重复堆叠长提示。

导演、视觉作者与审阅者接收同一份默认制作要求、当前明确调整和本片设计。审阅必须检查默认完成度，不能只检查是否违背了用户偏好。用户没说“花字”，不能用来解释所有重点文字都未设计；用户没说“质感”，不能用来解释原件、背景与图形没有层次。

正式实现仍沿现有场面稿、任务交接与工具执行，不新建风格系统、默认参数数据库或更多代理。原声音、字幕、事实准确性和操作权限继续按各自合同执行。

## 5. 内容输入与创作上下文分开

### 5.1 从零创作

交给作者的内容是准确正文、可靠声音和字幕时间、真实素材、已核对字段与必要限制。它们不包含一套必须沿用的构图、现成作品源码或同题旧画面。

若内容来自历史交付包，主任务只整理当前需要的事实与源文件；原表白底、素材尺寸和原视频已有标题，不自动成为本片设计要求。技术身份和来源信息可读，未经要求的历史方案不作为默认答案。

新任务使用新建项目及本次真实资产身份，不能直接重放其他任务的 Asset ID、Job、Revision 或 `previousAssetId`。

### 5.2 局部修改

用户明确要求修改已有作品时，必须读取当前作品、源码、采用方案和问题范围。保留被认可的部分，修改实际受到影响的部分，不借“干净输入”之名把必要上下文全部删除。

从零创作和局部修订是两种任务范围，不新增两套生产架构；由现有路由在派发前说清楚。

### 5.3 隔离测试与普通生产不同

隔离测试可以限定内容目录、禁止读取同题历史成片，用来检查自主设计。普通主题生产仍允许按授权搜索、下载和补材，不能继承某次测试的“禁止联网和补材”。

已保存的用户偏好应继续使用；禁止测试读取旧作品，不等于清除用户偏好。宿主自动注入历史摘要时，记录可知的注入情况，不宣称测试完全没有历史影响。需要严格实验时，由宿主提供真正的干净任务上下文，不能只依靠自然语言禁令证明隔离。

## 6. 统一视觉创作责任，而不新增角色

### 6.1 负责人

同一连续范围由一位视觉负责人持续完成构图、美术、素材表现、动作与源码。现有宿主已经分配了相关作者时续接原人，不按 Skill 数量再创建人员。

确需不同作者协作时，共享同一份当前设计，允许美术与动作互相修改；不存在“静态美术已完成，所以动画不能改构图”的前提。主要内容、事实含义或跨段关系改变回导演协调；正常视觉重排由原视觉负责人完成。

### 6.2 任务的产物

不是一份色号表加一份机制清单，而是**本片这段画面实际怎样发展**。简单场面短写；复杂场面把必要过程展开，不新增固定评分表。

作者在同一份当前稿中说明：

| 要作的决定 | 要让实现者明白什么 |
|---|---|
| 开始 | 看见哪些真实内容，首先看谁，为什么从这里进入 |
| 变化中途 | 谁改变位置、面积、形状或可见范围；其他内容怎样配合、保留或退让 |
| 读清结果 | 重点在哪里，哪些文字此时可读，辅助层为什么留下 |
| 后续 | 下一段从什么关系进入，哪些对象与源时刻继续，哪些可以退出 |
| 视觉性格 | 字形、颜色、边缘、材质怎样支持以上过程，而不是事后随机装饰 |

不要求每个镜头都人为拆成四个固定时长；这些是共同设计时要解决的问题。时间使用秒表达，按实际声音和素材调整，提交时才换算成帧。

### 6.3 模型必须做的判断

无论是否提供风格偏好，模型都要决定当前表达需要哪些对象、实际材料能支持哪些操作、哪些参考合适、需要什么改造、文字和材料怎样设计、哪种美术协调，以及何时应改变整幅构图。检索和计算不能代替这些选择；缺少个人偏好也不能成为省略这些工作的理由。

事实身份、准确数值、必要条件与用户锁定项保持；初稿的位置、背景、标题、造型和机制选择可以修改。保持同一个对象的含义，不等于永远保持同一个坐标。

## 7. 美术和动作如何共同设计

### 7.1 先确定要发生的画面变化，再安排关键状态

主体要扩大时，先决定辅助内容怎样让出实际空间；需要进入细节时，先决定全貌与局部怎样共同存在；一个费用被取消时，先决定剩余结构如何重排。

随后在这些状态中同时安排造型、文字、明暗、颜色和边缘。不能只让结束帧好看，而在动作中途让多个大字、亮块和图片互相遮挡。

这项工作可以直接在当前稿和源码设计中完成，不要求正式生成前另渲染一段练习或等待用户批准。

### 7.2 把文字当成当前画面中的对象

画内重点文字默认按视觉对象设计，而不是统一调用普通标签函数后只改字号与透明度。作者主动选择需要强调的词，结合字形、轮廓、大小、承托形、空间和动作形成可辨认的重点；花字与动态排印无需用户点名即可采用。进入、收稳和退出回应正在发生的内容，并与其他对象的空间变化配合。

对象标签与所属素材或图形一起安排，不默认钉在上方。费用名称、时间条件和数值要清楚，但不必全部采用强烈花字。原件内容和普通字幕不因重点字的设计而被重画成另一份信息。

具体字形和造型由本片设计主动选择；用户提供偏好时再按其范围调整。描边、承托形与偏移影是可用手法，不是所有文字必须叠加的清单。花字与材质设计不受偏好字段是否为空控制。使用登记的真实字体，检查中文字宽和笔画；不要用随机描边补错误字款，也不要分发字体文件。

### 7.3 统一视觉语言，不统一整张页面

可统一字形观感、强调色用途、图形边缘与材料处理。背景、主体面积、标题存在与否、窗口位置可以随内容变化。

纯色、浅色、卡片、左对齐文字和稳定构图都不是自动失败项。问题在于它们是否长期成为不受内容影响的固定包装。禁止把“整场设计”实现成一套全项目通用页头、底纹、中心卡片和固定入场。

也不把所有场面的颜色数量、元素数量或切换频率设成配额。颜色与文字的丰富度由主次组织，而不是把所有重点平均涂亮。

### 7.4 实景、原件与原创图形共同表达

材料处理是默认设计工作。实际摄影已有的纹理、光线与体积可以直接成为质感基础；原件和原创图形则需要通过面积、边缘、明暗、遮挡和恰当细节形成层次。不能把一张素材放上纯色底就视为美术完成，也不能以叠加颗粒或阴影的数量替代材料与构图判断。

实景可以成为整个场景，也可以在解释展开时改变显示范围；源视频本身继续正常播放。没有新视觉信息的持续镜头不能只用于等待下一段动画，但有真实观察、情绪或阅读作用的稳定镜头可以保留。

原件可以整体展示、进入局部或转为核实数据的编辑图形。原图身份与重新排印的内容明确区分，不伪造官网页面，不把解释图形冒称真实物理变化。

单张照片不能自动拆出内部部件。需要独立层、背面、目标跟踪或更清楚细节时，先确认实际条件；缺失就改造方法或按授权补材，不以虚构素材条件换取效果。

## 8. 机制库服务整场设计，不代替设计

### 8.1 共享一次工作的参考

先读取本场已有候选和实际采用记录；缺正文读正文，缺分镜打开对应图，缺运动信息看相关视频。这些是继续读取，不是重新检索。

当前候选不能解决真实缺口时再补查。语义 Job 完成后的同请求回读也不算重复创作。不要要求搜索总调用数必须为一，也不要让美术和动作按职责重新搜索相同需求。

### 8.2 看完整过程，也看实际美术

入围后读取完整机制，查看图像及必要的原片范围，理解建立、内部变化、完成反馈和下一内容如何发生，同时观察颜色、字形、主体比例、边界与遮挡。美术观察属于这次参考工作的正常内容，无需等待用户提出材质或花字要求；相关判断来自实际可见资料，不凭摘要猜测。

检索分数帮助发现候选，不表示审美质量或能直接拼接。原片本身好看，也不证明它适合当前素材。已有工具返回正文、分镜、片段和原片入口，优先使用，不新建平行美术检索系统。[S4]

### 8.3 局部借鉴是允许的，缺失的工作要由本片解决

一项参考只用于局部关系时，按局部用途记录即可；作者可以自行设计其余部分。没有必要为了“完整采用”复制参考的所有装饰、阶段和旧题材。

关键是：本片需要的完整变化有没有具体做法。例如参考只帮助解决“保留一项”，其余对象如何退出、空间怎样重排、文字如何进入，仍由当前作者负责。不能用多个局部采用编号冒充这些设计已经完成。

**参考完整度不是逐项照抄率；实现完整度是本片已经决定采用的过程是否真正发生。** 允许在设计阶段改变方法；不允许为了方便编码，在实现中无说明省掉重要关系。

### 8.4 按实际素材适配

沿 `mechanism-retrieval.md` 处理对象对应、需要保留的关系和前后连接，沿 `material-space-and-time.md` 处理源坐标、裁切、窗口与源时间。[S5]

参考里的主体可以对应本片素材窗口、原件局部、准确编辑图形或画内文字，依据它承担的工作判断，不因两者都是矩形就直接替换。位置、形状、数量、角度、幅度和时间按本片重做。

查询可以抽象地描述对象关系；实现输入必须回到本片实际对象和具体动作。不要多次改写同一机制，把真实过程逐步缩成“突出重点、增加层次”。

## 9. 源码实现：共享设计基础，不共享固定页面

### 9.1 共同时间与对象关系

同一对象跨阶段需要延续时，保持对应身份与状态；一个动作的结果成为后续动作的起点。相关文字、边缘和影子跟随所属对象，取景层与对象内部运动有明确归属。

素材显示窗口改变时，源视频继续使用正确源时间。同源全貌与局部在同一时刻显示同一源帧；不因 `Sequence`、拆件或改窗口而从头播放。

可以使用共同进度驱动相互依赖的变化，再为不同对象安排合理延迟与收势。无需强制所有对象使用同一曲线；也无需把整个连续片段写成一个不可维护的巨大函数。

### 9.2 可复用与不应自动复用的内容

| 可以复用 | 不应成为无条件默认 |
|---|---|
| 花字的描边和偏移影、标签、纸面边缘等绘制方法 | 所有场面必须在同一位置画标题和内容框 |
| 轨迹、缓动、源坐标、窗口裁切等可靠计算 | 全部对象使用同一种弹入、同一静态目标布局 |
| 语义明确的颜色、字形和间距约定 | 每条视频复制同一组色号、胶带和卡片 |
| 已认可案例中适用的对象协作方法 | 复制案例的金额、机制组合、画幅、秒数与旧项目身份 |

作品内部可按当前设计使用 `Sticker`、`Tag` 这类辅助函数，也可选择完全不同的绘制方法；函数存在不表示每段都要出现贴纸或标签。不因一次案例可复用就立即升级为平台默认组件。先让方法正确服务当前设计，确有重复业务需要时再讨论抽取。

### 9.3 正式提交与创作正文的分工

完整场面稿随同一任务与源码交接。`creativeBrief` 用于提交时保存简明创作说明，不承担唯一完整设计输入；不能为满足字段长度而把复杂设计删成标签，然后让下游重新猜。

主任务只补真实 Asset、Job、Revision、字体和时间等无歧义执行参数，不在装配时重新简化创意。源码、Props、绑定、事件与输出身份一致；重放其他任务的身份不属于复用。[S8]

## 10. 返修：完成当前作品，而不是再次压缩成小修任务

同一作者先查看正式输出，再根据实际问题修订。检查包含第4.1节的默认制作标准，不仅是“有没有违反用户提出的条款”；不能以用户未点名某个效果，为薄弱美术和局部化设计辩护。把问题分到正确层：

| 实际问题 | 修改位置 |
|---|---|
| 当前画面本来就没有发展、风格不符或主体不成立 | 修改相关场面的设计，保留无关的正确内容 |
| 已设计的主体运动、文字配合或取景没有实现 | 修源码和参数，不撤销原设计替输出辩护 |
| 原件、源坐标、字体、时钟或素材绑定错误 | 修对应实现与绑定，继续同一任务 |
| 只是记录不完整 | 补记录，不因此重新渲染 |
| 用户只要求改一个确定参数 | 完成局部修改，不扩大成整片重做 |

语义和美术修改可以很小，却仍需检查其相关范围。例如修一个否定词，要同时核对图形是否仍然表达相同限定；手续费卡展开压扁文字，应修显露或布局，不只是把字变细。

最终合成后的声音、普通字幕和原素材会改变阅读条件，应连同画面检查。静帧能确认的配色、裁切和重复结构要处理；速度、交叠和听感按实际媒体覆盖记录。不能把播放器启动、模型收到文件或事件表存在当作完整审看。[S6]

不新增逐镜审批。作品已经可用但部分审美未知时如实说明；技术问题、用户认可和专业观察是不同状态。

## 11. 正式声画接入需要同时补齐

视觉作品可以单独验证动效，但产品目标是完整声画。应把原声音放置、原SRT导入及字幕背景计算作为明确工程工作，而不是让每次制作临时寻找旁路。

### 11.1 已有旁白音轨的正式放置

当前应用层 `manageAudio` 中的主线范围来自非 AudioCue 的 `snapshot.timeline.items`。范围为空会触发 `AUDIO_PROGRAM_NOT_READY`。独立 ManagedMotion 已通过 EffectCue 产生可播放画面，但音频入口可能仍看不到相应主线；这与已观察到的执行阻断吻合，开发须用最小项目正式复现。[S7]

实施要求：

1. 核查并复用现有可播放范围的公共计算。需要补齐时，让声音放置和渲染使用一致的范围依据，纳入实际已放置、可渲染的 ManagedMotion，而不是仅凭空 Scene 的结束时间判断。
2. 保持声音不能无意拉长主线的限制。未放置的作品、缺失资产、失效 Cue 或空场景不能单独构成有效主线。
3. 已登记旁白音轨按真实源范围与目标起点使用，复用现有音频编排和 `narration` 语义；明确已有声音与重新合成语音两条合法输入。不要通过伪造人物轨或重复生成语音绕过问题。
4. 将当前正式接口中 SFX 事件参数与 BGM 范围参数的差异写清楚。参数预校验错误与真正的主线范围阻断分别处理，不能一次请求失败就统一认定平台故障。
5. 已知未执行、结果未知、版本冲突使用不同恢复规则。输入纠正后是否允许重试由真实合同决定，不用新幂等键重复提交未知操作。

不必立即增加新的音频服务。优先修正式范围判断和现有接口的正确用法；确实缺少已有旁白的明确入口时，在现有声音模块补最小能力并测试，再加入生产指令。

### 11.2 按用户原SRT导入普通字幕

若实时接口仍没有创建原SRT字幕卡的能力，沿现有 Caption 管线增加批量导入，而不是重新ASR、伪造词级时间或把字幕写进动画源码。

建议最小合同接受：项目与基准 Revision、字幕原文或受管文件引用、可选的明确时间偏移、目标范围和写入策略。字段名以实际发布合同为准；这些是开发要求，不是声称已有工具参数。

处理要求：解析与全量校验先完成，再原子写入；正文与原毫秒时间保留；本片局部时间默认不二次平移。换算使用项目统一帧率工具，半开范围与现有字幕规则一致；量化误差有明确上限，不靠ASR重新决定时间。

来源应记录为用户提供的字幕及其真实身份，不冒称语音识别或词级对齐结果。重复请求沿现有幂等能力避免重复卡；无效或冲突输入不得写入一半。

### 11.3 字幕背景随实际行数，不随最大行数占位

普通字幕的字体、字号、字重、字色、圆角、背景、内边距、行距、宽度规则与底部位置首次确定，之后只换内容和时间。

`maxLines=2` 表示最多两行。当前一行只绘制一行背景；当前两行向上增加高度，底部不动；无字幕不留空底板。换卡直接使用新尺寸，不增加缩放、弹性或逐词强调。

`CaptionLayer` 的 `fixedLineCount` 同时影响高度与强调，不能简单置为 `false`。拆开样式统一、强调禁用与实际行数。布局成功后采用同一排版结果计算绘制和边界检查：[S9]

```ts
// 算法含义，不是整段替换补丁；仅在正式布局已成功后计算。
const actualLineCount = layout.lines.length;
const contentHeight =
  format.fontSize * resolved.lineHeight * actualLineCount
  + resolved.paddingVertical * 2;
```

保留字体加载、真实字宽、DOM复核、错误处理和来源检查。同步 `caption-layout.ts` 与质量测量调用方，不出现一边画一行、一边按两行判越界。其他用途的显式顶部定位不能被静默改义。

### 11.4 文字归属保持清楚

纯旁白供声音使用；普通字幕呈现准确讲述；画内文字承担重点、标签或必要条件；来源、机制编号、内部对象名和制作步骤留在记录中。

不自动上屏“数学示意”“来自网络”“接收区”等制作性内容。不能只禁某个词再换同义词；也不能删除真正影响理解的假设、否定和适用条件。必要真实署名按素材使用要求处理。

### 14.2 作品验证：先验无偏好的正常入口

**默认能力验证。** 首先只给主题与可选材料，不提供风格名称、花字、材质、描边、色板、外部参考视频或逐镜答案，偏好字段保持省略或为空。让正常入口按授权取材、查看内置参考并完成制作。检查重点文字、材料层次、整幅构图与动作是否被实际设计，不能只凭路由调用或报告通过。

**固定内容与明确调整验证。** 在固定材料、声音与模型条件下先测试空偏好的默认输出，再分别加入有真实来源的简洁、字款或品牌限制等调整，核对具体表现改变而设计工作没有被关闭。这些是开发测试条件，不是替用户写入真实偏好。记录实际Release、读取入口、参考、源码与结果；必要时多次独立运行，不只选最好的一次作为结论。

**跨内容验证。** 使用至少覆盖真实行动、原件阅读和抽象关系的不同主题，允许系统按授权自行取材。具体主题不是固定生产模板；检查是否能产生适合各自内容的画面，而不是替换案例中的文字和图片。

**完整声画验证。** 补齐正式声音与普通字幕后，复看整体阅读和动作。画面静音时成立，不代表加入字幕、旁白和音效后仍然没有竞争与时点问题。

以上是开发评价，不是每条视频新增的审批步骤。正常用户只给主题即可；素材与偏好都是可选输入。验收不规定花字、纹理或机制数量，评价这些设计工作是否使实际表达成立。

### 14.3 按实际断点评价

| 看到的结果 | 下一步处理 |
|---|---|
| 用户没给偏好，系统就退回基础说明页或不做文字、材料设计 | 修默认制作要求的实际触发与设计工作，不要求用户补专业术语 |
| 用户已经提出具体要求却未传到作者，或把新创作当旧页面补效果 | 修入口与上下文传递 |
| 参考完整，但当前设计已经很薄弱 | 修整场创作与素材表现方法，不先怪渲染器 |
| 设计具体，源码省略主要关系 | 修交接与实现 |
| 设计和实现一致，仍不符合用户审美 | 回设计选择；保留有依据的偏好和已认可部分 |
| 动效获认可，但声画无法合成 | 修对应正式能力，不推倒成功视觉设计 |

成功案例能支持实施方向，不能单独证明某一条提示或某一个角色安排具有因果保证。若需要定位单项因素，开发测试固定内容、模型和预算，只改变相应输入或方法；普通制作不做消融实验。

## 15. 实施顺序与交付

**优先实施：** 让无偏好的正常入口也执行完整默认视觉设计，再对齐真实可选要求、从零创作与局部修订的上下文，以及整场视觉工作的统一方法；同时复现并修复旁白放置、原SRT导入和实际行数字幕背景。保留已有效的素材绑定、源时钟、正式渲染与返回投影。

**随后验证：** 在当前真实Worker里先用只给主题、不填风格的普通入口制作，区分默认工作是否启动、设计选择、源码兑现和实际观感；完成带声音字幕的合成。基准动效作为适用范围的对照，不作为所有输入的模板。

**按需接入：** 按明确认可范围整理案例；完善同次参考理解的必要信息。性能、组件化与更大范围的架构改造，仅根据真实阻碍继续评估。

开发结束交付：实际修改位置、主要调用链、测试结果、运行Release、作品入口、已完成与仍缺能力。说明以真实产物为准，不拿代码编译、文档长度或单个局部认可代替整片完成。
