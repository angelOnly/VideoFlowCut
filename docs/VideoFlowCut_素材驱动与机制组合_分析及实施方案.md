# VideoFlowCut：内容与素材共创、动效机制组合——分析思路与实施方案

## 如何阅读这份文档

本文将内容规划与机制组合、素材搜索与观感选择、生活化文案、基于实际材料的动画设计，组织成一份从判断依据到实施的完整方案。

**第一部分讲清为什么这样调整。** 从测试中“文案硬、资料图多、素材少且不好看”的现象出发，分析问题之间的关系、不同选择的代价，以及为什么机制组合必须承接实际材料。

**第二部分写清如何执行。** 包含完整流程、导演取材和演出要求、查询与获取方法、素材和文案共同修订、机制检索与连接、具体Skills工作正文、异常续接和验证。

两部分使用同一条路线，不需要另找历史方案拼接。本文中的机票试写、搜索词和材料用法属于本次方案讨论；机制组合示范是已有条目的适配分析，都不是新增成功案例，不应直接收录为通用业务范本。

**资料与状态：** 仓库现状沿用此前核读的固定提交，具体依据见第二部分第一章和文末资料目录。本次完成文档合并与分析展开，没有修改仓库、部署插件、检索或下载生产素材、调用本机机制MCP或生成新视频。

## 核心结论

**内容与实际素材共同决定文案和分镜；动画从这些材料的形状、行为、空间与声音中设计出来，再选择机制适配组合。**

导演、文案和视觉在研究、取材、写稿与分镜阶段，不再主动检索项目中的历史案例或120条动效参考。它们仍然使用各自的通用专业方法，产出有发展、有真实材料、有明确美术与演出目标的声画稿。

进入某个场面的动效制作后，由负责该场的作者从120个视频拆出的运动机制中选择、适配和组合，再写成当前作品源码。**机制选择发生在本场主要动画源码编写之前，不是在渲染时选择，也不是完整动画写完后补几个参考编号。**

保留现有项目、分镜、素材获取、配音、受管实现和导出链路；不新增导演、案例代理、第二套数据库或动画编译器。本次需要同时落实：前期不默认查内置案例、内容研究与生活画面探索并行、素材选得贴合且有观感、材料参与改稿、源上美术与演出设计，以及后期机制适配和连接。只完成机制检索，不能补救取材与讲法的空缺。

## 第一部分｜分析思路：为什么必须把内容、素材与机制放在同一条链路里

这一部分回答“为什么这样调整、不同选择有什么代价、怎样避免把方向做反”。后面的实施部分回答“现有角色具体怎样工作、哪些 Skills 要改、怎样验证”。这里的分析与建议不是新增的项目字段、审批步骤或要求每位作者全文预读的教程。

### 一、先分清三个问题：讲得硬、素材弱、动画脱离材料，并不是同一件事

用户反馈的现象很具体：机票改签主题的文案偏解释，画面集中在规则和资料图片，视频少，缺乏有生活感的行动、机场空间与有趣的表达；动画即使增加了变化，也没有真正从视频和图片的内容中形成。

不能把这几个现象统称为“动画不好”，然后只换一种动画生成方式。文案决定正在展开什么问题；素材提供实际可观看的内容；美术决定观众怎样面对这些内容；运动机制则帮助已经建立的画面发生变化。某一层欠缺，下一层可以补充表现，却不能无条件替代它。

一个需要警惕的循环是：

```text
题目被理解成一组需要解释的规则
    ↓
文案先写成知识说明，导演据此提出条款和订单需求
    ↓
素材返回更多规则页，生活行为与环境没有同步取得
    ↓
视觉围绕文字与票据排版，素材只能当背景或小窗口
    ↓
动画让文字板进入、退出、缩放
    ↓
成片依然缺少观看体验，再继续增加动效
```

这个循环说明：**只改最后的动效生成，可能得到更会动的说明页，而不是更好看的视频。** 因此素材和讲法的优化不是机制组合之外的附加任务，它们决定机制最终服务的内容。

上述循环是根据用户反馈及已核读方法作出的机制分析，不是已经从这次完整运行日志确认的唯一原因。现有方法其实已经允许情境、幽默、细节与欣赏；需要改变的是这些方法怎样变成真实的取材、采用和改稿，而不是再写一句“允许多样素材”。[R18](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/references/source-review.md)[R20](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/narration-writing/references/writing-methods.md)[R21](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/production-director/references/story-and-shot-design.md)

**由此得到的方案选择：先修正前期在寻找什么、怎样使用结果，再让后期机制组合承接这份具体的内容。**

### 二、为什么不能让“寻找证据”代替“寻找值得看的画面”

“为什么改签贵”可以被做成规则讲解，也可以从人的处境展开：原本准备出发，计划发生变化，接着需要重新理解价格、时间和选择。两种讲法不必互相排斥；问题是整条视频是否只剩下第一种。

事实研究回答的是：具体主张是否成立、哪些条件不能省略。画面探索回答的是：观众从哪里进入、能看见什么行动和细节、哪里有反应与声音、为什么值得继续观看。**这是两种需要同时思考的问题，不是两套固定素材分类。** 一份体验视频既可能提供生活过程，也可能出现值得核对的真实操作；一张页面既能承载事实，也能成为当前观察的对象。

因此，一段机场行进镜头不需要证明某家航空公司的费率，才能用于这条视频。它可以只负责建立“已经准备出发”的环境与期待。反过来，规则原件已经拿到，也不能自动证明出行处境、行为和声音都已经得到表现。[R18](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/references/source-review.md)

机场空镜可以提供空间、光线、旅行预期和节奏变化，不必每一秒都新增事实。不过，机械地在规则卡之间插入两秒飞机，也不会自动改变整片的讲法。如果旁白仍在连续下定义，空镜很可能只是装饰。

**由此得到的方案选择：事实核对与生活画面探索在同一草稿阶段开展；导演接到实际材料后，决定它怎样改变讲述，而不是把它简单插到一份已锁死的说明稿里。**

### 三、为什么取材需求必须由导演写准，而搜索范围必须保持开放

主题词与画面不是一一对应的。“机票改签”可以帮助发现规则和经历，却未必能找到收拾行李、走进航站楼、候机或机窗外滑行。这些内容可能出现在旅行记录中，标题从来没有提到改签。

所以，搜索不能停在“抽出旁白名词—搜索同名内容”。导演首先需要说明这段在建立什么处境、发生什么变化、希望看见什么；素材作者再寻找可能拍到这些内容的来源。完整关系是：

```text
当前内容与观看目的
    → 可辨认的主体、行为、环境、细节或反应
    → 可能记录这些内容的材料
    → 实际候选提供的过程与新发现
    → 取回、选段、修改讲法与分镜
```

**准确的是材料要承担的作用，开放的是来源、媒介和取得路径。** 导演只说“找机场素材”太泛；要求同一条素材满足所有尚未决定的机位、服装、色调与动作，又会把空间限制过死。好的请求能让作者知道什么值得找，同时知道哪些相近内容也有机会完成同一段表达。

现有六步取材方法仍有价值：读完整意思、转成可见内容、从用法倒推细节、成组提出材料关系、给出相近方向、提供搜索起点。它应该保留，不能在调整链路时又缩成“负责搜索相关素材”。[R16](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/production-director/references/asset-briefing.md)

**由此得到的方案选择：导演交具体的内容目标与材料关系；素材作者按实际结果调整查询，发现更好的内容就回到当前稿，而不是自行追加一套来源和类型限制。**

### 四、为什么“相关、可下载、技术清晰”仍不足以代表好素材

素材是否贴合、是否有观感、是否能剪接，是相互关联但不相同的判断。标题命中主题只能说明值得看；分辨率和时长只能提供技术信息；文件取得说明获取成功。真正的选择还需要面对实际画面。

同样是机场内容，有的镜头能让人进入空间，有的只是一个远处看不清的牌子；有的能看到行动的起承与落点，有的刚发生动作就被原片切走；有的有可用的环境声，有的声音完全被原配乐盖住。它们能否接到当前句群，不能只靠文件标签判断。

因此，素材作者应该实际判断：主体怎样出现，光线与空间有没有表现力，人和相机怎样运动，哪里能进入和退出，声音有什么价值，以及哪个边缘、空位、动作或细节能支持下一步设计。[R17](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/SKILL.md)[R18](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/references/source-review.md)

这并不意味着给每条素材新增审美评分，也不意味着必须电影级、4K、无包装。同样能承担内容时，选择观感更好的；真实内容独有且重要时，不因为摄影普通就丢弃。

“丰富”同样不能化成下载数量。一条长视频可能提供多个互补范围；多条视频也可能都在重复同一个起飞镜头。真正需要看的是当前稿还有哪种观看内容没被承接，而不是文件数够不够。

**由此得到的方案选择：素材返回不只包含名称、时长和状态，还要用简短的实际判断说明“哪段值得用、怎样接台词、哪些声音或空间可以继续设计”。**

### 五、为什么“有视频需求”不等于已经执行了视频搜索

这次症状还可能包含执行断点，而不全是创作判断。导演需要连续行为，下游却只搜索了页面；找到视频页面却未获取；已经选过范围，本地化后又把原选择丢掉。这些情况需要分别核对，不能统一归因于“搜索模型不够聪明”。

已核读的获取说明明确区分：支持媒体类型筛选的查询要保留视频意图；查询词中有 video，不等于工具收到 `media_type="video"`。现有 YouTube、Pexels 单视频获取路径还需要先发现具体页面，再取得相应文件。当前已有范围获取、画质选择和媒体探测方法，不应重新套用旧的统一720高度或只能整片下载的描述。[R19](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/references/acquisition-operations.md)

没有本次调用日志，不能认定上述哪一个断点已经发生，但可以明确要核对的过程：

```text
需要什么连续行为
    → 实际进行了什么视频发现
    → 找到了哪个具体候选
    → 是否真正提交并完成获取
    → 返回了哪些已观察范围
    → 是否进入当前场面
```

规则页先到手，不应让尚未执行的生活视频需求被悄悄取消。一个文件正在下载，也不意味着另一个候选的只读发现和比较必须停止；结果写入仍按现有项目的真实顺序进行。

**由此得到的方案选择：改清楚从获取决定到实际文件的续接，保留已有看片与选段，不新增素材准入门槛，也不把全部问题推给新建下载系统。**

### 六、为什么文案生活化不能只靠短句、问号和网络梗

把一段规则说明切短、改成反问、加入感叹词，会改变表面语气，却不一定改变内容发展。观众如果始终只是在听定义、条件和结论，稿件仍然偏硬。

需要改变的是规则进入视频的方式：先让观众理解正在面对的处境、行为或选择，再让必要的规则回答此刻关心的问题。专业任务需要直接答案时当然可以直接深入；生活化不是所有视频必须先编一个故事。[R20](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/narration-writing/references/writing-methods.md)

机票主题中，“箱子都收好了，计划却变了”之所以与“介绍改签费用影响因素”不同，是前者先建立一种能被理解的处境。但它仍只是试写方向。实际取得的是候机看手机，而不是收拾行李，就应围绕真正可见的内容改写，不能为了保住一句好听的话反向强迫素材符合它。

幽默可以来自期待与结果的差异、一句与画面配合的评论、动作后的反应和声音停顿。它不一定需要表情包，也不需要对被拍人物的内心作未经支持的判断。重点是语言与画面共同完成一个意思，而不是在说明书开头加一个笑话，后面仍然逐项读条款。

材料返回后，文案需要真实修改准确正文、句群顺序和声画分工。画面已经清楚呈现的动作，不必再念同义说明；语言可以补必要条件、判断和态度。有价值的源声可以接管一部分表达，而不是被默认全部静音。

**由此得到的方案选择：文案与导演、视觉共同写作，材料和试排直接推动当前全文修订；第一稿和第一版配音不自动成为最终长度与顺序。**

### 七、为什么“动画从素材长出来”是依赖关系，而不是一种视觉口号

依赖真实素材的构图，需要知道主体在哪里、往哪边动、哪一块可读、有什么遮挡和原声。没有实际材料，可以提出方向，却不能假定源内细节、抠像条件和精确路径都已经成立。

如果导演先决定一个完整卡片翻转，素材作者随后找图填满卡片，再把这种方式称为“素材融合”，方向仍然没有改变。真正从素材出发，需要让实际内容影响观察距离、字位、主次、裁切、动作和接点。[R7](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-treatment-planning/references/art-direction.md)[R16](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/production-director/references/asset-briefing.md)

拿到的是横向行进，设计可以顺着行进与可读空间发展；拿到的是稳定候机宽景，空间与环境声可能更有价值；拿到的是机窗外连续运动，就不应先为了放标题把它缩成一个小框；拿到的是规则原件，则从真实区域、字幅和上下文安排观察。具体做法在实施部分展开，不将这些可能性固定为每个题材的模板。

这也解释了为什么换背景颜色不一定解决PPT感。反复出现的可能不仅是米白，而是同一观看结构：整块底色、常驻标题、中部小窗口、内容逐组替换。图片与视频没有取得主画面的表达空间，换成黑底仍可能像另一页说明。

对确实依赖源内容设计的段落，更换构图和动作不同的素材，通常应影响字位、路径、裁切或节拍。这个判断帮助辨认是否只是换了一张背景；它不用于否定普通B-roll、可复用组件或不需要变形的好画面。

提供的历史直播任务也明确要求：相关材料在正式动画开工前确定，再决定裁切和字位。这里保留的是这项依赖关系，不恢复为新流程前期的默认案例教学，不继承其题材、色板、秒数和一次性制作条件。[R22](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/motion-case-library/references/cases/motion-case-attention-programme/references/original-input.md)

**由此得到的方案选择：内容与材料反复共同发展；依赖素材的具体动画在实际范围可见后落实；材料尚缺的场面继续补，已有材料的场面继续制作。**

### 八、为什么把机制检索放到后面，却不能先把全部动作锁死

用户希望前期创作不再受到历史案例和120条库外观的牵引，这与素材驱动并不矛盾。前期仍然研究内容、寻找生产材料、设计主角和观看发展；推迟的是内置机制的选型，不是推迟视觉作者参与。

需要区分三个层次：

**内容与观看决定**：这一段讲什么，实际看见什么，为什么在这里变化，前后怎样接。

**具体演法**：选择怎样的进入、让位、显露、并置和接管，哪些变化交叠，怎样安排关键中途。

**实现细节**：具体坐标、曲线、绑定、源时钟及作品代码。

导演不能只交“做高级动画”，否则库检索仍无从判断；也不应在查机制之前把每个角度、曲线和全部像素锁死，否则机制库只剩下寻找近似配方的作用。前期美术是一套具体但可发展的选择，材料与机制试排仍可以推动局部调整。

因此，新流程不是单向流水线。导演给有材料依据的演出目标，动效作者在此范围内选型和适配；主要事实、关键素材或跨段表达改变，回导演协商；已采用方向内的路径、字位和切口由原作者继续。

**由此得到的方案选择：前期独立规划，后期机制制作；两者通过同一份当前声画稿连接，而不是通过一份越来越长的参数审批单连接。**

### 九、为什么“120条案例库组合”实际是在复用运动关系，而不是拼接成片

按既有核读记录，库的检索单位是从120条视频中拆出的744条独立运动机制，提供指令、起止状态、保持关系和源帧分镜；它没有被确认拥有744份可直接调用的原作者代码。机制资料还刻意不负责题材、美术和配色。[R1](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/references/motion-cases/skillry/README.md)[R14](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/references/motion-cases/skillry/mechanism-index.json)

因此，这套库的作用不是让模型交出几个编号，渲染器就自动生成好视频；也不是下载几段参考动画首尾拼接。正常产物应该是：采用具体机制关系，将其映射到本片实际对象，设计前后连接，再编写本片源码。

这让动效作者不必仅凭“丝滑、专业”等抽象目标临时发明全部运动，也让它有机会核对一个动作到底怎样发起、怎样保持旧状态、怎样接到下一步。但机制换了材料、字幅、画幅、速度和邻接关系，就仍然需要适配与实际预览。

美术因此不能被省略。颜色、字形、材质、主体比例和观察距离来自本片视觉选择；原机制里的附属横条、底板和字组没有本片用途，就不应被自动带入。否则即使换了多个机制，也可能只是复制另一套卡片外壳。

**由此得到的方案选择：保留现有检索与实现，不先把全部机制重做为组件；把“读机制、理解关系、适配对象、组合实现”作为主要动画的正常工作。**

### 十、为什么组合最难的地方是连接，而不是候选数量

检索命中一条机制，说明找到了值得研究的运动关系，不说明它能直接接到当前画面。前一段结尾是两块并置，后一段开头却要求单个完整活动层，即使都属于“平面”，也不代表无须设计就能连接。

每次组合首先需要回答：**上一段留下什么，下一段需要什么，中间差的状态怎样建立？** 这比单纯比较标题、标签和主色更重要。对象身份、位置、尺度、朝向、源时间和第一关注都可能影响连接。

组合也不一定串行。新内容可以在旧内容仍然可辨时建立；底层视频可以持续，图形在前景变化；一个动作减速时，另一个动作开始显露。要求每条机制先完整退出、下一条再完整进入，很容易制造空等、重置和机械分段。

反过来，没有共同对象需要延续时，清楚切镜同样可以成立。不能为了证明“组合”而把每个边界都变成形变，也不能为了保留某个编号把原视频缩小到不可辨。

同一场面的共同对象宜在统一状态、坐标和源时间中实现。当前资料不是即插即用组件，局部连接和代码需要作者补做；这些补做不应假称来自原片。普通局部修改沿已选组合继续，不重新检索全部资料。[R2](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/motion-case-library/references/mechanism-retrieval.md)[R11](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/remotion-production/SKILL.md)

**由此得到的方案选择：用真实机制支撑主要动作，作者负责具体连接与整体实现；验证关注连续画面，而不是每场用了几个机制。**

### 十一、为什么不再新增角色、资料库和强制检查表

素材少、文案硬和连接差，已经能够对应到现有角色和产物。导演、文案、素材、视觉、动效、主任务及审片都有各自应承担的判断。当前缺的是这些判断真正进入同一份稿，以及候选到文件、文件到设计的续接，不是缺一个新的角色名称。

因此，素材返回的内容应被导演和文案使用，视觉在实际材料上继续，动效承接当前对象与声音。一个视觉作者可以连续使用美术、演出和实现方法，不因多读一份Skill就新增代理，也不为每条机制创建独立任务。[R9](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/production-coordinator/references/task-routing.md)

本报告详细，是为了讲清设计理由和修改依据，不代表这些分析全文都要复制进每个Skill。主流程保留一处共同约定；具体取材、写作、机制组合和实现知识各有主要位置；其他入口只写何时读取。

同理，说明要看哪些内容，不等于规定每条候选必须填完一份长表。明确的普通取材和局部修订继续执行，不新增逐镜用户审批、下载配额、机制数量或统一美学评分门槛。

**由此得到的方案选择：保留已经整理好的目录和运行链，只调整相互冲突的入口及必要专业方法；用更清楚的工作替换重复要求，而不是在末尾继续叠加限制。**

### 十二、为什么验证必须分别看素材、讲法、设计和实现

将全部问题归到某一角色，容易让返修永远停在错误的位置。材料本身不贴合，应继续选材；材料好却被裁错或缩小，应修改用法；忠实实现却仍然像说明书，应回到导演与文案；运动顺但美术弱，应修改构图、字形与质感；连接跳位和源重播，则是实现与时钟问题。

因此，新方案不能只以“没读前期案例”“调用了机制搜索”“得到导出文件”来证明成功。它需要在实际作品中看见：内容有发展，材料真正取得且有表达作用，文案因材料而改变，关键动作从这些材料出发，并通过机制适配形成连续过程。

判断资料是否足够，要对应当前尚未完成的观看内容；判断机制是否采用，要看到它如何进入对象映射和源码；判断效果是否改善，要看同一段实际声画，而不是引用历史案例好评。

本次合并没有读取新的运行日志、搜索或下载测试素材、重新观看全库或生成新片。因此，下文保留“已核读资料支持的现状”“基于反馈的原因分析”“拟议工作方法”“待执行的验证”之间的区别，不能把方案写得具体当成已完成验证。

**最终方向不是多堆一些视频或多叠几个动作，而是：内容与材料共同形成值得看的过程，视觉把它组织成画面，机制帮助这个画面按当前讲述继续发展。**

#### 1. 组合的是运动关系，不是原片碎片

本方案的产物链是：

```text
当前实际素材、准确讲述与本场演出目标
    → 据此寻找库内机制指令与分镜
    → 沿当前素材、文字、美术完成对象适配
    → 连续组合设计
    → 本片受管源码
    → 当前场面及整片声画预览
```

不是“下载几段参考动画后剪在一起”，也不是把原片颜色、主体和时长当模板。库里真实视频用于理解机制；本片画面来自本次生产素材、已采用视觉设计和生成的实现。

#### 2. 这条路线的好处与边界

好处是让前期创作不受某个案例外观牵引，同时减少动效作者凭几句抽象要求重新发明所有运动的负担。744条机制提供具体的运动关系，可帮助作者把中途、保持和接管做得更明确。

边界是：已观察到的机制不是已验证的通用组件。它换了材料、字幅、画幅、速度和连接方式以后，仍需要实际实现与观看。**选对机制会提供更具体的依据，但不自动保证美术、组合和整片节奏。**

### 二、整体链路：保留前期共创，改变动效制作入口

```text
用户剪辑要求
    ↓
主任务定位当前任务与已有作品
    ↓
导演＋文案＋视觉：选择具体处境与内容角度，试写开头
    ↕ 同轮开展，不等文案全部锁定
事实研究＋生活画面探索：查依据，也找行为、环境、细节与原声
    ↕
素材作者：实际取得、比较观感、选段，返回可剪组合与设计机会
    ↕
导演＋文案＋视觉：围绕实际材料改台词、试接镜头、形成源上美术
    ↓
当前场面明确：讲什么、实际材料里发生什么、怎样观看与接续
    ↓  在这里开始使用120条库的机制
动效作者：分阶段检索 → 读入围机制 → 对象适配 → 连接设计
    ↓
同一作者完成本片源码，主任务沿现有链提交与取得预览
    ↓
场面运动、真实素材、配音、字幕和声音一起复看
    ↓
局部问题由原作者修；主要内容或跨段改变回导演
    ↓
整片合成与交付
```

这里有两个并不冲突的要求：

**前期不参考案例，并不等于前期不设计动画。** 导演和视觉仍要写出完整的可见过程，只是不预先指定库内编号、原片外观或具体实现配方。

**后期使用机制，并不等于素材和文案一旦写过就永远不能改。** 实际材料与试排可以推动修改；但不能仅因某机制方便，就默默删除重要镜头、换掉真实素材或重写故事。

按场面逐步推进。某场材料与演出目标已足够明确，即可开始该场机制制作，不必等待整片每份材料全部取得。暂时缺关键原件的场面仍可以探索，但依赖真实裁切和源动作的部分不能冒称已经定好。

#### 前期四项专业工作：改变参考时机，不削弱创作方法

##### 1. 导演：先组织值得看的发展

导演与文案根据研究和实际材料组织开头、变化、发现、反应与结尾。每段解决一个具体内容问题，并与前后段接上；不要把知识章节直接变成动画清单。

导演不仅说“这一段讲什么”，还决定观众实际经历什么：先认出哪个对象，什么变化值得看，哪里缩短重复，哪里展开关键过程，何处让语言、现场声或画面先行。这些属于导演专业方法，不依赖内置参考库。

##### 2. 文案：把画面发现写进讲述

文案不是先独立锁死一篇稿再交画面配图。它在同一草稿阶段与导演、视觉工作；材料返回后，根据实际动作、细节和可用原声调整准确句群与顺序。

已经由画面清楚呈现的动作，不必机械复述；语言可以补充比较、条件、判断、评论或预期。是否反问、停顿、反转，取决于内容，不增加固定结构配额。现有写作方法继续保留，只移除通用入口中早期案例检索的要求。[R6](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/narration-writing/SKILL.md)

##### 3. 素材：按镜头用途寻找，不由机制库反推搜索范围

导演和视觉交下游的仍是具体请求：本段准确句群、要看见的主体与动作、与其他材料的关系、准备如何使用、可以采用的相近方向。保持开放搜索，实际选择可以是视频、图片、录屏、页面、模型或其他契合材料，不给每种题材固定媒介。

丰富来自有用内容与可剪范围：环境让人进入处境，行动和细节推动观看，反应与原声提供节奏，相关范围支持比较和接续。它们按实际需要寻找，不要求每段配齐一套景别，也不以文件条数代替丰富度。

找到有希望的候选后继续取得与选段；已有观察随文件传递。下载或审阅某来源受阻时，继续其他候选和仍有缺口的镜头。**机制检索只能解决“这些材料怎样演”，不能把未取得生产素材的问题包装成“采用图形表达”。** 现有协调方法已经要求从获取决定推进到实际文件，这部分应保留。[R9](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/production-coordinator/references/task-routing.md)

##### 4. 视觉：没有案例配色，也要交出具体画面

视觉作者使用本片真实材料和准确文字，决定主角、观察距离、背景、尺度、字形、明暗和材料关系，再给动效作者入口、重要变化与落读状态。

当前机制资料刻意不讲配色和美术，因此“用了机制库”不会自动治好米白底或PPT感。视觉需要把选择落在当前画面：素材是否承担足够的主画面，主体是否有分量，文字是否靠真实字幅形成层级，背景是否服务观察，而不是默认所有内容同一底色、中间小框、常驻标题。[R1](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/references/motion-cases/skillry/README.md) [R7](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-treatment-planning/references/art-direction.md)

可以复用本片已成立的视觉语言，但不能把同一版面反复替字。机制作者沿这套美术实现，不从候选分镜的原片颜色重新选整片风格。

### 三、素材、文案与分镜怎样共同变好

#### 1. 先找准这次问题：不是资料不够，而是资料代替了观看

用户描述的测试结果是：规则页面、票据和资料图片占据主要画面，视频少，材料不够漂亮，文案偏说明书。本次未读取这条测试的完整任务日志、全部候选与成片，不能将症状直接认定为某个模型、Provider或过滤函数的故障。

当前导演方法已经允许情境、幽默、细节与欣赏；素材观察方法也明确说情境材料不必承担未承诺的证据作用；文案方法要求从具体处境写作。问题不是完全缺少这些原则，而是正常任务里没有把它们落实为足够具体的寻找和采用。[R18](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/references/source-review.md) [R20](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/narration-writing/references/writing-methods.md) [R21](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/production-director/references/story-and-shot-design.md)

需要警惕的执行倾向是：围绕“为什么收费”组织整片，然后把取材理解为“取得能证明每条解释的原文”。这样容易找到很多规则页，却找不到旅行准备、行进、等待、临时变化和人的反应。文案越像知识说明，取材越集中于条款；只有条款返回，画面又越容易成为文字板。这是基于现状的机制推测，不冒充已查明的运行因果。

**事实研究解决“讲得对不对”；画面探索解决“观众正在经历什么、为什么值得看”。** 同一材料可以兼有两种作用，来源与媒介都开放，不为这两种问题新增团队、数据库或固定材料分类。

#### 2. 导演先提出具体处境，让体验探索与事实研究同时开始

研究退改规则可以继续，但导演同时要回答：这件事对人意味着什么？人原来准备做什么，什么被打断，需要作什么选择？这不是强制每条视频编一个人物故事，而是把抽象主题接到当前观众能够理解的生活处境。

对“机票改签贵”这个选题，可探索的观看内容包括出发前的准备、进入机场、等待与查看行程、计划变化后的犹豫，以及账单或规则中的实际差异。它们是这条测试的开放方向，不是各片必须配齐的清单，也不代表已经取得对应视频。

导演不先定死全部分镜再找材料。首次交付包含可继续写作的内容角度、开头试写和待发现的可见内容；素材作者尽早返回有表现力的候选，导演和文案再确定更具体的讲法。源内精确动作、取景、遮挡和节拍，等实际材料可看后才决定。

只找到规则时，下一项需要补的是出行情境或人物行为，就继续这个缺口，而不是再找第五张相似规则截图。反过来，有漂亮机场镜头却没有论述依据，也要补事实。是否充分由当前稿需要完成的观看内容判断，不按图片或视频总条数判断。

#### 3. 搜索要从主题走到行为，再走到可能拍到它的内容

导演交“这一段想让人看见什么、为什么”，素材作者负责把它变成能找到候选的查询。正常搜索可以沿以下过程展开，结果已足够时不必走完每一步：

```text
当前内容与观众处境
    → 可见行为、环境、物件或反应
    → 可能记录这些内容的视频与图像
    → 看实际候选，发现更好的范围与来源
    → 获取、选段，并把发现带回改稿
```

本片的查询示意如下。它们是待执行的搜索起点，不是已发现素材，不包含任何“必须在同一条候选里全部满足”的意思。

| 正在补什么观看内容 | 可以尝试的查询起点 | 为什么不只搜“机票改签” |
|---|---|---|
| 人已经为旅行作准备 | `出发前 收拾行李 vlog`、`packing suitcase travel vlog` | 好的动作可能拍在家里，并未在标题中提到改签 |
| 进入机场的真实过程 | `机场 出发 登机 vlog`、`airport travel day walking luggage` | 旅行记录可能同时提供行进、候机、细节与环境声 |
| 计划变化或查看行程 | `机票改签 经历`、`行程变更 旅行 vlog`、`flight change travel vlog` | 寻找叙述或反应，不预设每条视频必然存在所需动作 |
| 有空间与摄影质感的机场画面 | `机场 航站楼 空镜`、`airport terminal cinematic b roll`、`airport window aircraft taxiing` | 这类画面可承担环境、节奏和旅行预期，不必证明费率 |
| 接近个人视角的细节 | `机场 第一视角 行李`、`boarding plane POV`、`suitcase wheels airport` | 物件与视角有机会与当前台词、声音、图形相接 |
| 实际费用和规则依据 | 对应航空公司或平台的准确退改条款、真实操作或解释材料 | 这部分负责核对具体主张，不替代整片生活画面 |

影视或二创中的相关表达、体验分享、报道、评测、图库和个人记录都可参与比较；不按网站身份提前决定内容是否有用。只保留当前主张与表现真正需要的区别，避免把他人的遭遇表述成当前某位旅客的真实经历。

**关键词相关只是入口，候选在这条视频中的作用才是采用理由。** 搜不到时，从缺少的行为、反应或空间改查询，而不是每次都附加退改费关键词。漂亮的整段旅行视频可能比一张精确命中主题的规则图提供更多可剪内容；具体仍要看片判断。

#### 4. 想找动态画面，就真的进入视频发现与获取

现行操作说明写明：`search_media_candidates` 查动态材料时应显式使用 `media_type="video"`；查询词中出现 video 并不自动限定媒体类型。Pexels无Key路径与YouTube路径需要先在浏览器中发现合适的单视频页面，再进入正式取得。[R19](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/references/acquisition-operations.md)

因此，这次应检查实际调用链是否完成了：视频需求 → 视频候选发现 → 单条页面／真实候选 → 下载 → 可播放文件与选段。没有本轮调用记录，不能直接断言哪一步漏了。

具体执行建议：

- 导演希望看到连续行为时，主任务在支持类型筛选的查询中保留 video 意图，不用图片查询结果冒充已完成该需求。需要照片、原件或图像时照常取，不给全片设媒介配额。
- 原文页获取与视频发现并行推进。不能因为网页截图容易取得，就把其他未执行的视频需求改成“已被资料覆盖”。
- 一条候选足够有希望便继续取得。其余还没覆盖的画面可以同时发现，结果写入仍沿现有项目顺序。
- 某页或某次获取失败，只处理这一候选；继续其他有效候选、同源范围和其他入口。未知写入先查询原任务，避免重复下载。
- 已在线选好的范围随文件回传；下载后程序补媒体信息，只有质量、裁切、上下文或时间对应改变时补看，不重新从头审一轮。

现行文档已支持YouTube的范围获取与画质选择，不能沿用旧的720封顶或必须整片下载的描述。这里只核对本机是否走对已提供的入口，不要求再造下载系统。[R19](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/visual-asset-sourcing/references/acquisition-operations.md)

#### 5. 从“可用”继续选到“好看、贴合、能剪”

当前素材返回强调范围、精度和支持什么判断，这些要保留，但不能成为全部选材依据。素材作者应在真实片段中作专业选择：画面把人带到哪里，主体是否清楚，光线和空间有什么价值，运动是否有节奏，切入切出与声音是否值得保留。

| 观察角度 | 选材时具体看什么 | 怎样影响选择 |
|---|---|---|
| 与台词和处境的关系 | 当前句子是在准备、等待、选择、感受还是核对，候选实际发生什么 | 排除只命中名词、却接不上本段意思的材料 |
| 画面的第一印象 | 主体大小、可辨轮廓、光线、色彩、前后空间，原包装有没有挤压重点 | 在同样能承担内容的候选中选更有表现力的一条 |
| 运动与剪接 | 人物和相机怎样动，动作哪里有起承落点，进入退出是否自然 | 找到值得剪的过程，不只挑一张漂亮帧 |
| 声音与生活感 | 环境声、动作声、短语或反应怎样与讲述形成关系 | 声音可承担转场、停顿或幽默，不默认全部静音 |
| 进一步设计的机会 | 哪个边缘、空位、动作或物件能接文字与下一镜 | 给视觉作者具体机会，而不是只给Asset ID |

这是看片角度，不增加评分字段、固定阈值或每条候选的长报告。真实且有价值的片段即使摄影不完美也可采用；“好看”不等于所有材料必须电影感、4K或没有已有包装。

两条都相关时，不只交清晰度与时长。应说清哪条更适合当前场面：例如哪一条能完整看见行动，哪一条主要是静止等候；哪一条提供了可利用的侧向空间，哪一条人物与文字会挤在同一区域。未看片时不能写这种结论。

#### 6. 文案不只是换口语，而要换进入问题的角度

“改签费受多种条件影响”可以准确，却未必让观众产生观看兴趣。文案应先让观众知道自己正在面对什么，再带出值得理解的规则。术语只在当前问题需要它时进入，不先铺完定义再配图。

以下仅是本次讨论的写法对照，没有核实具体票规、金额或费率，也不写入通用Skills成为新的业务范文：

| 偏说明书的进入 | 更贴近本片处境的试写 |
|---|---|
| 本视频介绍机票改签费用及其影响因素 | “箱子都收好了，计划却变了。你想改的是出发时间，先得重算的却是预算。” |
| 接下来分析追加费用的构成 | “先别被那个总数劝退。把这笔追加的钱拆开，看看它到底在算什么。” |
| 应关注退改条件与适用规则 | “问题不只是改一次要花多少，而是你买票时，到底把哪些选择一起买进去了。” |

这不是规定所有视频都这样开场。使用“箱子都收好了”需要该稿的假设身份或实际材料配合；拿到的如果是临近出发查看手机、而非收拾行李，就围绕那个真实可见动作重新写，不硬套这句。

幽默可以来自期望与结果的不对称、贴合场面的评论、动作后的反应以及声音停顿。它不等于每几秒插表情包或夸大收费，也不要求凭表情推断被拍人物真实心理。关键是画面、语言和声音一起完成一个有趣的意思。

改稿要改到正文：让规则成为对当前处境的回答，删掉资料中与本段无关的铺陈，保留决定含义的条件。不是在整篇说明书前面加一句梗，后面仍然逐条朗读条款。实际原声有价值时让它承担一部分表达；语气与自然度仍需听最终声音。

#### 7. 先把材料接成可看的段落，再精修动画

拿到材料以后，用已有时间线／预览把实际选段、当前台词和必要原声试接。目的不是新加一个必须审批的中间产物，而是先发现：一段话是否一直要求读字，几条镜头是否在重复同一作用，好的行动有没有被无谓截掉，原声能否形成节奏。

已有粗剪可直接继续，不重新制作。依赖机制才能看懂的主要变化，在粗稿中用将采用的机制做出关键过程；不必等全部装饰完成，也不能把静态卡写上“这里有动画”就当已验证。

材料合适且时间能接上后，视觉作者在这些实际文件上确定更细的构图；动效阶段再选择合适机制。取材还缺关键动作的场面继续寻找，已经有足够材料的场面照常推进，不形成“整片全部齐备才能动”的总门槛。

#### 8. 动画怎样从材料中长出来

素材返回后，视觉作者不只继承名称，而是继承实际内容、选段和可设计机会。依次看：哪个对象值得成为主角，真实动作怎样发展，相机与主体走向是什么，哪里有可阅读空间，哪些细节可以靠近，原声何时提供接点。

然后写本场变化，再向机制库查询。查询来自“这份实际材料怎样继续发展”，不是来自“想用一个看起来高级的机制”。

| 实际材料不同 | 本场设计应随之改变 | 机制承担什么 |
|---|---|---|
| 人物持续横向行进 | 保留可见行进，文字安排在能看清的空间；出口接顺运动方向或声音 | 适配内容进入、让位或画面接管，不强加卡片容器 |
| 候机的稳定宽景 | 用实际空间和环境声建立等待；下一项可从空位进入或清楚切镜 | 支持重点变化，不给静止人物硬造动作 |
| 机窗外的连续运动 | 保留源内速度与观察，不为塞标题一律缩成小窗 | 在真实过程上编排必要文字与下一镜接口 |
| 静态票面或规则原件 | 选择值得读的真实区域、实际字幅与上下文 | 帮助观察与比较，不重新画一堆同义条款 |

上表是当前主题下的设计可能，不表示已经取得相应镜头。没有可靠抠像或跟踪也能做出丰富画面：改变整幅观察、并置、字幕安排、声音先行或清楚切镜都可以，不必为选中的机制勉强分离人物。

纯图片区段也能成为好动画，前提是图像的形状、内容、字幅和材质实际参与构图与过程。图像若只是任何同题照片都能替换的小背景，不能据此声称完成了紧密的素材融合；但普通环境B-roll本身无需变形也可以有价值。

**对需要源上设计的段落，换掉实际材料，裁切、主次、路径或节拍通常会受到影响。** 这是一项判断是否真正根据材料设计的自查，不是否定可复用组件或要求每镜完全独创。

#### 9. 延迟的是机制选型，不是素材参与；开始的是适配，不是套模板

前期不加载内置案例库的约定继续成立。导演、文案、视觉依据内容与实际生产材料共创；机制阶段使用120库支持当前材料的运动。前期的美术是可发展的方案，材料和机制试排回来后，允许修改局部字位、取景和动作，不宣称一开始已经定好所有像素。

当前提供的直播原任务之所以能支撑混合表达，是先写材料用途、再要求实际材料确定后决定裁切和字位。本次只用它解释材料与设计的依赖，不重新设为前期作者必读资料，也不继承那次的题材、配色或固定参数。[R22](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/motion-case-library/references/cases/motion-case-attention-programme/references/original-input.md)

最终希望做到：**规则负责讲清，生活材料负责让人进入处境，语言负责形成发现与态度，机制负责把当前材料的观看关系做出来。** 同一份材料可以同时承担多种作用，具体用法由作品决定。

### 四、导演要给多具体的动画指令

**导演交由实际材料支持的观看过程；视觉作者在这些材料上确定美术与变化；动效作者选择机制，适配并实现这次观看。**

素材未取得时，导演交探索方向，不假定源内动作、抠像条件或精确坐标；材料回来后，再把它写成下面的可实施演出目标。

导演不能只说“增加科技感、找高级动画、把资料展示出来”。但也不必在未查机制前规定每个对象的角度、曲线和全部像素，使后续只能勉强找相似条目。

#### 1. 本场演出目标的写法

以下内容写进现有场面正文，不是新增Schema或必填长表：

| 导演需要明确的内容 | 应具体到什么程度 |
|---|---|
| 当前讲述与本场作用 | 对应准确句群；这一段让观众理解或感受到什么 |
| 当前画面与实际材料 | 谁已在场、哪些源范围准备使用、哪些文字准确出现 |
| 可见变化 | 谁保持，谁出现或让位，注意怎样从前一项转到下一项 |
| 重要辨认与声音接点 | 讲到哪层意思时，需要看见哪一状态；初排用秒，随后按实际声音校准 |
| 结尾与下一镜 | 末态留下什么，下一镜从哪个对象、方向、声音或信息接走 |
| 表现空间 | 已确定的内容与美术是什么；路径、显露、交叠和局部构图哪些可由动效作者选择 |

“具体”是为了让下游能够作选择，不是把每个镜头写成参数审查表。短直剪可以一段话说完；需要连续机制组合的场面，才把过程展开。

#### 2. 仅用于说明交接尺度的一段请求

> 保留已经在场的真实过程A，使其继续播放；在讲到另一种情况时，让实际材料B进入并置位置，观众能看清两者的共同参照。随后把注意引向B中的实际细节，原有比较关系仍能被辨认，不把B重新从头播放。标签跟随自己的对象，普通字幕继续。结尾保留本段判断需要的画面，由下一句接走。沿本片已确定的字体、材质和色彩处理；具体进入路径、减速和局部显露由动效作者依据机制库安排。

这是交接结构示意，不代表项目已经有A、B这两个素材，不是新增业务案例，也不应作为全片通用版式写入案例库。实际使用时必须替换为已取得的具体内容、文字、用途与源范围。

#### 3. 动效角色不重新决定整片故事

它可以选择不同进入方向、幅度、速度与连接方法，并据材料调整局部布局；需要改变主要事实、关键素材、讲述顺序或跨段表达时回导演。普通路径与曲线无需逐项审批。

导演和视觉的前期工作因此不会被库替代；动效作者也不是机械翻译员。它的专业工作从“全凭空设计”转为“理解目标、挑选演法、适配当前对象、补齐连接并实现”。

### 五、动画制作怎样从机制库开始

#### 1. 先把本场目标拆成运动问题，不拆成零碎属性

检索首先依据本场实际选段、图片内容、当前构图和声画目标；输入是准备采用的材料，而不是“尚无素材的几个盒子”。检索问题应保留一段有意义的行为。例如“保持旧画面，新内容进入并置，再转向局部观察”，可以分成建立并置、局部观察两个阶段。不要只剩“位移、缩放、透明度”，也不要把本场所有词放入一次严格交集。

本片对象用于作者理解，查询重点是动作关系。题材、材料或颜色不同，不自动排除可迁移机制；但实际要依附某个部位或精确延续源动作时，必须确认本片材料支持这件事。

#### 2. 直接复用现有五种查询能力

| 当前制作问题 | 现有入口与用法 |
|---|---|
| 本场有几个动作阶段 | `search_motion_mechanisms`的`stages`按阶段召回 |
| 某个画面已经存在，只需从这里变化 | 以`query`描述变化，必要时用`entry`、`holds`、`exit`说明真实状态 |
| 当前候选方向对，但不适合本片 | `similar_to`寻找关系相似而表现不同的候选 |
| 需要接在某机制之前或之后 | `before`或`after`辅助寻找，并读取连接缺口 |
| 已经有选中的编号或网页清单 | `ids`或`selection`恢复，不重新扫描全库 |

这些选择模式当前每次只能使用一种；多个阶段的初选与某项的前后续接应分次调用，不拼成一个未被支持的混合请求。工具当前主要以词表、同义词和文本描述召回，最终语义判断由作者完成；前后状态粗匹配也不是连贯性证明。[R2](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/motion-case-library/references/mechanism-retrieval.md)

本方案不重建这套检索，不再要求每次读完120份总览。字段、允许值和分页按实际返回使用，不将本文件的示意当作实时工具Schema。

#### 3. 读入围原文，才决定采用

`search_motion_mechanisms`用于发现；入围后使用`read_motion_mechanism`核读指令和分镜。依据当前问题确认它真正做了什么：主体整体移动还是局部复制、原框先入场还是一直保持、内容被替换还是同源连续。

涉及速度、遮挡瞬间或复杂交接，而已有分镜不足时，再看相应原片范围。不是每次先看全部原片，也不把分镜图片称为已连续观看。[R2](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/motion-case-library/references/mechanism-retrieval.md)

#### 4. 在同一份稿中完成对象映射

每项采用机制只补充当前制作真正需要的说明：

- 对应的本片动作和真实机制ID；
- 原机制哪些角色映射到本片的哪个对象、素材、文字或共同父层；
- 保留哪段动作关系，哪些附属元素不采用；
- 接入前是什么状态，结束后留下什么，以及连接由谁实现。

字体、颜色、整体美术继续来自本片视觉稿。原机制中的附属横条、角落字组没有本片用途，就不额外添加；保留的是主要行为关系，不是原片里所有物体。

这段内容附在现有场面执行稿中。编号、来源指纹和网页清单也随稿保留，不建一份与导演稿脱节的“动效清单数据库”。

### 六、组合能否好看，重点在连接而不在选了几个机制

#### 1. 组合不是机械串行

一个场面中可能同时存在以下几种关系，按实际内容使用：

| 关系 | 当前作者真正要决定什么 |
|---|---|
| 顺序发展 | 前一变化完成哪项观察后，后一变化开始 |
| 有重叠的接管 | 旧主体尚未完全退场时，新主体何时建立、何时取得主次 |
| 同一场面分层发生 | 哪个是主要动作，其他层怎样支持而不争抢注意 |
| 保持底层、内部变化 | 哪些层不重新创建，内部素材与文字怎样接着发展 |
| 切镜连接 | 没有共同对象需要延续时，怎样用内容、方向或声音清楚接入下一镜 |

不规定每场至少用几个机制，也不追求让所有边界变形。一个机制足以完成，就深入做好它；需要组合时，把实际连接做好。

#### 2. 每一个相邻接点都要回答同一组问题

**上一段结束时是什么画面？下一段开始需要什么画面？两者不同的部分怎样建立？**

进一步只核对相关问题：

| 接点 | 需要解决的具体内容 |
|---|---|
| 对象 | 延续原对象、复制同源局部，还是明确替换另一个对象 |
| 空间 | 位置、大小、方向、父层坐标和可用空位是否能接上 |
| 注意与阅读 | 哪个先被看见，旧参照何时让位，新字何时达到可读面积 |
| 源素材 | 源范围和源时钟是否延续；局部观察是否取自同一状态 |
| 运动 | 前段的出口速度与后段的启动是否需要连续，还是有意停稳 |
| 声音 | 建立和落读是否赶上当前句意，源声与音乐是否仍按本段安排继续 |

这不是每镜必填表，而是选中机制后真实需要解决的连接问题。不能只核对`end_state`和`start_state`都写“平面”就宣布可拼。

#### 3. 库没有直接提供的连接，由作者补设计

允许作者设计必要的移动、让位、遮罩与过渡，也可以换更合适的机制。连接设计不要求额外登记为库内新机制，更不声称来自原片。

如果两个机制需要互相矛盾的状态，优先换相似机制或重新安排当前局部；不能为了复用编号把实拍缩得看不清，不能删除导演需要保留的比较参照。

**机制优先不是绝对禁止任何新代码。** 当前库本来就是运动描述，适配、连接和本片源码必须由作者写。关键是已有主要运动应当真正由采用机制支撑，不再泛泛搜几条以后完全忽略它们。

#### 4. 统一到一份当前场面实现

机制不是默认一个机制一个独立视频。对同一场面的共同对象，优先在同一受管作品中安排状态、图层与时序，避免多个片段各自从空场开始。

同一属性在重叠区由谁控制要明确：父层改变整体位置，子层执行自己的局部显露，不能两份机制代码同时重置同一个位置或裁切。当前项目需要技术拆件时，沿已有方法传递出口状态和源时间，不新增调度系统。

窗口运动不能让真实视频重播；不同机制共用一个源时，应沿现有媒体绑定和根时钟合同实现。[R11](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/.agents/skills/remotion-production/SKILL.md) 这些实现知识继续保留，机制组合不取代它们。

### 七、用库内两个真实条目说明适配，而不是另造成功案例

#### 1. `002-m07`真正提供了什么

该机制名为“侧面图块快速靠近，减速后与旧块并置”。原文描述左侧旧块保持，右侧新块进入并减速，底部横条在减速期间上移；随后其他附属形状建立。它允许调整来路、间距与减速位置。[R12](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/references/motion-cases/skillry/cases/tomandrieu96707-875264-original/mechanisms/m07.md)

应用到本片真实材料比较时，可将两块映射为当前A、B两份材料，保留旧内容持续与新内容减速进入的关系。底部横条只有本片确有对应信息时才使用；不因为原机制里出现过，就给本片增加工具栏或卡片装饰。

#### 2. `001-m07`真正提供了什么

该机制名为“原活动层继续，角落另开局部放大窗”。原文强调原层与同源局部并存、两处继续活动，并非把原局部挖走；窗口位置和局部来源可调整。[R13](https://github.com/angelOnly/VideoFlowCut/blob/72cb314dceae8a5c129f5c55ae222a963489f54f/references/motion-cases/skillry/cases/sab8a-475686-original/mechanisms/m07.md)

因此，它不能被简单实现成整幅画面放大，更不能把局部换成一张无关图。映射到本片时，要明确放大哪个已存在源、观察哪个真实区域，以及放大以后还需保留什么整体参照。

#### 3. 两个条目排列在一起，不表示已经组成了合格动画

第一项结束时是两块并置；第二项原入口描述的是一个完整活动层。因此，不能直接串接两个默认版本，否则会出现第三个窗口挤占画面、原比较重置或源身份不清。

作者需要先决定如何接：保留当前并置组作为全局参照，从其中一份真实源取局部；视觉布局必须有足够观察空间，所有相关区域取正确源状态。若当前构图放不下，就调整局部布局、寻找另一种同槽观察机制，或交导演判断观看方式是否要变。不能让候选的默认布局替代本片分镜。

**这只是基于两份现有机制正文的适配分析，没有运行此组合，也没有证明该组合好看。** 它不写入案例库，不增加未经认可的教学作品。

#### 2. 可写入主流程的完整段落

> **内容先行，动效阶段组合机制。** 用户输入剪辑要求后，导演、文案、素材与视觉作者使用通用专业方法，根据研究、实际材料和当前反馈形成完整声画稿。前期不主动读取项目内的历史案例、整片参考卡或运动机制目录，不为了匹配库内形式预先决定题材、分镜、材质或版式。
>
> 事实核对与生活画面探索在草稿阶段同时进行。材料回来后共同改写文案、试接镜头；导演与视觉写清本场实际看什么、选段里有什么变化、使用哪些材料、关键句意到来时应看见什么、出口怎样接下一镜。进入该场动画制作后，由当前作者使用120条库的运动机制完成选型、对象适配和组合，再落实受管源码。材料足够的场面先推进，不以全片资料齐备为前置。
>
> 机制改变局部路径、速度与显露时由作者继续；影响主要内容、关键素材或跨段关系时回导演。真实素材不足仍继续补材或修改具体镜头，不能因机制容易实现就取消素材任务。当前方案允许反馈改稿，但不让库内现成外观重写上游主题与美术。

这段主规则只维护一处，其他角色只引用与本角色有关的一句，不把三段文字复制进所有Skills。

#### 3. 导演入口中的参考段，改为以下职责

> 前期围绕当前内容、研究和实际材料独立构思，不检索内置案例库来决定故事与分镜。与文案、视觉共同形成准确句群、取材需求、主画面与本场演出目标；明确实际对象、需要保持的参照、可见变化、关键声音接点和出口。具体机制选择、路径与连接由进入制作的动效作者完成。作者提出会影响内容或跨段表达的适配建议时，回到同一份稿作选择。

此段替换原来的早期案例调用安排，不覆盖主线、取材和返修方法全文。六步取材方法不是案例目录，应完整保留。

#### 4. 动效入口的核心工作段

> 新建或实质重构动画时，先读本场准确讲述、实际素材、已选美术和导演演出目标。把可见变化分成有完整意义的运动阶段，使用机制库检索候选，再读取入围的运动指令与分镜。保持原机制的主要动作关系，映射到当前真实对象与源范围；删除没有本片用途的附属表现，不继承原题材、配色或秒数。
>
> 将采用项组织成同一场面的连续发展。明确上一项留下什么，下一项需要什么，以及位置、面积、层级、源时间和注意怎样接上；需要重叠时共同安排，不把所有机制首尾串行。前后不能直接连接时，换候选或设计必要的连接，并区别库内依据与本片补做。
>
> 用当前声音与可读状态确定动作时机，沿专业中途方法检查最危险的过渡。交回同一份完整演出稿中的采用机制、当前对象映射、连接与声音安排，继续实现当前作品。只改既定文字、颜色、位置或曲线且原机制仍适用时，沿原选择修订，不重新检索全库。

#### 5. 机制库入口的范围说明

> 默认用于当前视频的动画制作：依据已明确的场面目标，查找可适配的运动机制，读取候选，比较连接，形成当前作品的组合设计。不在普通研究、写稿、取材或初步分镜阶段主动提供整片讲法与美术模板。
>
> 正常生产使用120个视频的机制资料；用户明确要求研究某个历史作品、复现旧源码或分析整片参考时，才进入对应历史分支。13例与其他历史材料继续保存，不作为本流程缺少源码时的自动回退。需要本片代码时，由当前作者根据采用机制实现。

保留现有五种查询及其真实边界，不再额外写一套查询DSL。清理旧引用时查`description`、入口、参考方法和默认分派文字；仅改一段而留着上游多个早期入口，会让链路继续走旧路线。

#### 6. 实现与主任务只补必要的续接

实现入口在正常流程中补充：

> 接收的是已经适配到本片材料与美术的机制组合稿，不是几个编号。落实当前对象、共同坐标、源时钟和命名事件，优先保持同一场面连续实现。预览出现问题时修具体连接与表达；不把参考指令直接贴进Props，也不把找到机制当作源码已经存在。

主任务分派时补充：

> 前期作者使用内容与材料工作方法；本场进入动画制作后，将完整演出目标、实际文件和源范围、材料中已观察的动作与空间、视觉决定及当前声音交给原作者，并启用机制选型与组合。已有采用项和未改变的资料继续传递，不为每个机制创建代理，不把相同场面拆成多个互相不知道状态的生成任务。

阶段可以写在现有任务范围中，不必新增Project字段。若宿主已有按任务分配工具的能力，可用它进一步限定发现范围；本方案不假定这种隔离已经存在。不支持时采用明确分派并核对实际读取记录，不能把一句“不要读”宣称为技术权限隔离。

#### 7. 素材共创的具体工作正文

以下文字按所列现有章节合并整理，替换重复的同义说明；不要整份覆盖Skills，也不要把本片搜索示例写入通用方法。详细方法在所属位置维护，其他入口只保留触发说明。

##### 导演取材方法：用观看内容提出任务

位置：`production-director/references/asset-briefing.md`，合入六步取材开始部分及材料反馈段。

> 从本片的人与内容出发，先明确观众面对什么、准备做什么、哪里发生变化，再提出可观察的材料方向。事实研究核对具体主张；画面探索同时寻找能建立处境、呈现行为、形成反应、提供空间和声音的内容。两者可以来自同一来源，但规则原文已取得，不代表整片画面已经充分。
>
> 初次请求给正在展开的内容与可见方向，允许实际候选改变讲法；定向补材再给准确句群、需要的内容、前后关系与可比较方向。不要把尚未看到的动作、机位和原件形式先定成全部候选的硬条件。材料的来源和媒介由实际内容与用法决定。
>
> 返回材料后，在同一稿里明确用了哪段内容、为什么值得看、相邻镜头怎样接，以及台词和美术随之改变什么。缺口仍是生活处境或实际行为时，继续相应寻找，不以再取得同类规则页面完成该需求。

##### 素材作者：取得有观感、能剪接的内容

位置：`visual-asset-sourcing/references/source-review.md`，合并“比较候选”与“反馈”；入口保留读取条件，不复制整段。

> 根据导演的内容目标展开主体、行为、环境和可能记录它的内容形式。主题词只作起点；在旅行记录、体验、报道、二创、图库和其他实际来源中寻找契合范围，根据结果改变查询。需要视频时实际执行视频发现与取得，不让已有图片清单替代尚未满足的连续行为。
>
> 在相关候选里比较整段观看：主体与光线怎样呈现，空间和运动是否有表现力，哪里可切入切出，原声有没有价值。真实重要内容不因摄影普通就排除，漂亮但接不上当前意思也不直接采用。已有合适选择继续取得，不为比较数量重复搜索。
>
> 交回实际文件与源范围，并用短段说明“片段发生什么、哪一处值得用、怎样接当前台词、还有什么材料互补”。需要源上动画时，指出可利用的动作、方向、细节和空间。技术信息继续由现有媒体结果携带，不为同一素材新建多份评分或证明表。
>
> 当前一类画面已有可用内容时推进仍空缺的类目；取得失败继续其他候选，未知提交先查原任务。没有找到有说服力的画面时交具体缺口和已尝试方向，不把候选列表、截图或计划下载说成素材准备完成。

##### 取材操作：明确视频意图，不扩大为全片限制

位置：`visual-asset-sourcing/references/acquisition-operations.md`，合并现有媒体类型、页面发现和获取说明。

> 当前需求需要真实连续行为时，在支持类型的候选工具中使用视频类型。YouTube与Pexels等单视频获取入口，先由实际浏览能力发现页面，再交正式获取；不能把关键词直接当成单视频URL。其他媒介照实际用途取得，不把视频意图扩展成整片必须全视频。
>
> 已选候选立即续接正式获取与结果回传；下载过程中可以准备其他无依赖候选。已有观察和选段沿同一来源继续使用，程序补齐媒体信息，质量与时间对应变化时才补查。这里不新增时长、画质、来源或数量门槛。

##### 文案方法：从处境展开，用材料完成评论

位置：`narration-writing/references/writing-methods.md`，合并“从主题找到关注”和“材料改稿”。

> 为大众观看写作时，先让观众理解自己面对的处境、动作或选择，再把规则和术语放在解释当前问题的位置。专业读者需要直接结论时可直接深入，不把生活化变成固定开场模板。
>
> 幽默与节奏可以来自期望、结果和实际反应的不对称，以及语言与画面的分工；不只是加感叹词、网络梗或固定反转。让当前材料提供具体动词、细节和声音，连续几句都在解释时，判断哪里应当改为观察、行动或评论。
>
> 材料回来改准确正文与观看顺序：实际没有的行为不要硬写，有更好动作或原声就重新组织对应句群；关键规则和限定仍讲清。将变化落进同一份全文，不只在说明书前加一个热闹开头。

##### 视觉与场面交接：从实际材料决定动画起点

位置：`visual-treatment-planning/references/art-direction.md`的材料共场段，以及`_shared/SCENE_DESIGN_HANDOFF.md`的材料使用段。

> 在实际文件和已选范围上决定主角、观察距离、文字位置与前后接点。先看源内动作、相机方向、主体轮廓、可读区域及原声，再设计画面怎样变化；素材本身可以承担主画面，不先给它一个固定小窗。
>
> 给动效作者的同一稿带实际材料、已观察的过程、当前构图和准备继续发生的变化。尚未取得的关键材料只给方向，不虚构源内细节。更换构图不同的材料后，复核受影响的字位、裁切、路径与时机。

##### 动效：机制适配实际材料，而不是材料适配默认机制

位置：`motion-brief-writing`与`mechanism-retrieval.md`中现有对象映射、连接段。

> 根据本场实际材料与已采用声画目标，把变化写成运动关系再检索机制。把机制中的主体、载体和附属层映射到当前真实对象，沿本片的空间、美术与源时钟实现。原分镜的额外卡片、横条或包装没有本片用途就不采用。
>
> 候选需要本片不具备的开口、分离或运动条件时，选择别的机制、改变局部观察或用清楚切镜；不为保留机制编号伪造素材能力。关键材料仍未取得的部分继续补材，其他有条件的场面继续制作。

##### 主任务与导演粗剪：用实际结果推进

位置：`production-coordinator/references/task-routing.md`和`production-director/references/rough-cut-review.md`。

> 从当前稿查看仍缺哪段观看内容。已取得事实原件不能自动关闭情境、行为与声音需求；动画产物也不算外部视频补齐。原作者选定候选后继续正式取得与回传，已有可用片段及时试接，不在计划里反复写“稍后下载”。
>
> 试排先观察讲述、实际材料与主要动作是否共同成立。规则画面过密就检查对应场面是否缺行为和体验；材料好却被缩小、裁错或听不见，回使用方修改；素材不合适继续选材；讲法始终像说明书，回导演与文案。返修定位问题，不增加统一评分门禁。

这些是拟议方法正文，不表示已写入项目。上线前应根据当前实际正文合并同义段落，而不是把所有段落再追加到文件末尾。

### 九、材料、机制或表现不成立，怎样继续

**材料缺少生活感或实际行为：** 继续当前画面探索，换行为描述、记录形式、同源范围或入口；规则原文能用但不承担这个缺口，不能再堆同类原文作为补齐。

**材料贴合但不好看：** 优先换同用途的更好取景、光线、完整动作与声音，或从同源寻找更有效范围。若内容独有且重要，则由视觉调整实际用法，不机械要求电影级摄影。

**机制检索没有命中：** 先检查是否把多段动作塞成一个查询、是否附加了不必要的软筛选；改写关系、分类浏览、找相似项或扩大候选。保留真实结果，不虚构编号。

**命中但本片材料不适合：** 换同阶段机制，或修改局部映射。只有主要观看方式确需改变，才回导演；不能为保留某编号任意缩小实拍或隐藏关键内容。

**机制能实现但接不上：** 先修前后状态与重叠，或用已有`before`、`after`继续查找；小段连接由作者补做。必要且有理由的切镜不是失败。

**确实缺少承担某个主要动作的机制：** 说明库内已找到哪部分、缺哪部分、尝试过哪些替代，由导演与作者选择可接受调整或补充实现。本方案允许必要补做，但不能静默退回“整场自由生成”并把它报告成库机制组合。

**运动顺但美术差：** 回当前构图、材质与排印，不继续堆机制。机制库本来没有承担配色设计。

**场面漂亮但整片仍平：** 回导演与文案检查发展、取材和声画顺序，不用更多转场补内容空缺。

这些是常规工作分支，不增加逐条用户确认。检索、组合、实现与审美分别报告实际进展，避免“已命中”被当作“已完成”。

### 十、实施顺序与验证

#### 1. 先改相互冲突的入口，不重写所有技能

先确认当前工作副本与本文基线的差异。先落实事实研究与生活画面探索、视频意图到真实获取、材料反馈改稿，再收拢前期库引用，调整共享主线和主任务分派；保留现有内容创作、开放取材与美术方法。然后将动效制作从“参考可有可无”改成“默认先选机制并适配组合”。

详细组合方法集中在现有`mechanism-retrieval.md`，中途与速度知识仍在`performance-design.md`，接口与时钟仍在实现参考。不要把同一套流程重复写在三个文件里。

正常沿当前源码生成、提交和导出执行；不为本次流程另建运行时动作引擎，不预先把744个描述全部重做成组件。

#### 2. 用现有任务验证，而不是新增永久教学案例

| 验证范围 | 应看到什么 |
|---|---|
| 前期不受库牵引 | 新任务研究、写稿、取材和初步分镜不主动调用机制查询，不预读历史CASE；通用方法与网络研究正常使用 |
| 前期不是空壳 | 分镜有准确句群、具体画面与取材用途；事实核对与生活画面发现同步，视觉有主体、构图和美术 |
| 视频意图没有丢失 | 需要连续行为的任务实际走video查询或单视频发现与获取，不只返回规则截图；核对真实调用而非口头承诺 |
| 文案不再只是规则目录 | 内容从能理解的处境、观察或选择展开，术语回答当前问题；幽默与评论进入正文，而非只加开场一句梗 |
| 素材参与实际设计 | 返回的动作、空间、字幅或原声改变了取景、台词、路径或接点，不是只替换Asset ID |
| 选材有观感判断 | 候选选择能说明哪段过程、取景或声音值得使用，不只记录时长与文件状态 |
| 生产素材得到推进 | 具体候选实际获取并选段；未满足用途继续补齐，不以参考库视频替代 |
| 动效正常使用机制 | 新的主要动画先有真实机制候选、原文读取与适配决定，不只在交付时补编号 |
| 组合不是拼片 | 重要对象、源时间、注意与声音能跨机制继续，接点没有无意空场、重播或重置 |
| 本片美术保持 | 不随机制来源换一套背景和字形；已定视觉不退回通用卡片 |
| 局部修订足够局部 | 改一个字或参数复用原组合，不重读整个库，不重跑整片 |
| 如实说明限制 | 无匹配、连接补做、未连续看过的范围均明确；静态测试不冒称效果达标 |

可以在现有任务日志记录阶段、实际查询、采用机制及修改原因，用来比较执行是否符合设计。不设置必须下载多少条、每场必须几个机制或规定字数的指标。

#### 3. 成功标准

**导演仍然主导内容，真实素材仍然充分服务画面，视觉仍然形成自己的美术，动效则能够把库内具体运动关系适配为本片的连续演出。**

当前检索能力已经为这条路线提供了基础。下一步要验证的是角色执行与组合质量，而不是再次扩大案例数量或增加大量新规则。
