# 数字人物与人物表演

## 执行角色与代理交接

当前授权作者完成专业判断，主任务统一正式提交；输入、完整产物、依赖变化与原作者续接沿 [角色交接](../_shared/PROJECT_REVISION_AND_HANDOFF.md)。

## 人物不是一个普通视频文件

人物视频同时承担身份、信任、情绪、口型、空间和视觉锚点。一个 MP4 能播放，不代表 ActorPerformance 成立。人物声音可能来自源视频、OmniVoice Dialogue 或静音；Mask 可能内嵌、独立或不存在；段落之间可能口型、姿态和情绪不连续；Provider 可能不支持精确手势。

本 Skill 在 `presenter-motion-director` 中作为专项负责人，判断人物版本是否适合当前 Script 和视觉计划。当前代码可以登记 imported/generated、MaskMode、AudioMode、MaskAsset 和 SpeechAsset，但自动 Avatar Provider、姿态和局部重生仍未完整实现。对未实现能力只能规划和审查。

## 角色关系决定表演

先根据当前讲述者与观众的实际关系决定态度和表演距离。角色不是标签装饰，它决定观众与人物的距离、直视镜头比例、语速、表情强度、景别和视觉包装容忍度。

在生成或选择人物前，先写清：人物是谁、代表谁、与观众是什么关系、应该显得权威还是亲近、是否允许夸张、哪些情绪变化需要出现。风格不能只写“自然、专业”。

## 目光、表情和手势

交给动效专项的是实际构图、可用动作范围、Mask 状态和返回人物的姿态风险；无法观察到的指向、抓握或前后遮挡不可承诺。人物专项提供素材事实，主流程决定是否交出主画面。

直视镜头让观众感到被直接对话，适合承诺、坦白、结论和 CTA；看向侧面可以引导即将出现的对象，但如果对象没有按时出现，会像眼神漂移；低头或避开镜头需要内容动机，例如思考、犹豫或情绪，不应作为随机生成动作。

手势应有准备、主相位和结果。数字、对比、列表、产品和行动可以配合手势，但不能每句挥手。复杂解释时人物应稳定，让注意力转向图形。当前没有真实姿态数据时，不承诺产品“从双手之间展开”，可使用 safe_left/safe_right 或 Fullscreen 降级。

## 段间连续性

分段生成的人物常在每段开始重置为中性微笑、姿态变化或眼神跳回中心。相邻段应检查情绪、目光、身体、景别、背景、光线和音色。若上一段是严肃结论，下一段突然笑着开场，即使单段都“自然”也会破坏整片。

修复优先顺序通常是：Script/SpeechSegment 是否切错；声音表演是否不连续；人物生成指令是否重置；能否局部重生；是否需要 Scene/Cutaway 交接；最后才考虑通过视觉效果掩盖。

## Uncanny Valley 的常见来源

眼神无目标、长期固定微笑、表情与语气冲突、手势重复、嘴型延迟、段间姿态重置、皮肤过度平滑、身体高能但声音平静、图形假装与手互动，都会让人物显得不真实。问题应被具体描述，而不是笼统说“AI 感重”。

## 局部修复优先级

1. 确认问题是否来自 Script/Voice；
2. 确认人物源和 SpeechAsset版本；
3. 检查口型偏移是否整体或局部；
4. 检查是否可以局部重生；
5. 判断 Cutaway 是否是合理视觉选择而非遮丑；
6. 最后才用轻微速度/剪辑调整，避免明显变形。

## 人物安全与隐私

VoiceReference、人物图片、视频和生成结果记录实际来源与用途。外部 Provider 的数据保留方式在接入文档中记录；素材链路不做权利审核。

## 审片细节

在正常速度、静音和只听声音三种方式检查。静音可发现眼神、表情和动作僵硬；只听声音可发现人物画面掩盖的 TTS 问题；声画一起看口型和情绪。近景比中景更容易暴露异常，质量门槛应更高。

## 交接合同

连续作品交接还带入口/出口约束、真实可用范围与局部事件；素材、时序或作品版本变化后相关 Cue/声音需要复核。验证必须对应当前版本实际合成。

输入是稳定 SpeechAsset、人物素材或 Provider 能力、角色和视觉计划。输出是 ActorPerformance、AudioMode、Mask 状态、版本关系、表演问题和降级。它会使空间效果和 Preview 需要重建。验证包括口型、边缘、完整动作、段间连续和声音所有权。
