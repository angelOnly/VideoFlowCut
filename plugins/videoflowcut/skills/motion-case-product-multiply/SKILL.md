# 产品增殖：让数量由同一件产品长出来

先看[独立动效视频](assets/product-multiply.mp4)，再对照[完整源码](assets/motion.tsx)与[参数、语义拍及审阅帧](assets/fixture.json)。视频是已认可的无声案例；本 Skill 解释其设计选择和改写边界。

样例为 720×1280、30 fps、420 帧，共 14 秒。默认展示 70 台无品牌自绘平板，源组件 `transparent=true`；配套审阅视频的底色不代表源组件不透明，也不代表它已经与某个真实人物合成通过。

## 观众最后应理解什么

观众先认出一台具体形状的平板，再看到它与同伴形成组合，继而理解数量扩大到 70 台，最后把注意收回到一台与“查看配置清单”。核心理解是“同一种设备形成可清点的团队规模，接下来可以统一规划”。

单件识别、数量理解和下一步阅读需要不同尺度。开场让产品足够大，规模阶段让轮廓足够多且规整，结尾恢复一个可识别的主产品。只把“70”放大不能完成数量关系，只把设备铺满画面也不能自然导向行动。

## 为什么选平板，以及怎样安排视觉

平板有稳定外轮廓、屏幕、边框与摄像头，放大时有可辨细节，缩小时仍保留同类身份。它适合示范设备数量增长，屏幕中的工作计划界面又与“个人工作空间—团队协作—配置计划”的内容语气一致。

产品由一个 `Tablet` SVG 组件绘制，主产品保留界面细节，新增小件使用 `tiny` 版本简化屏幕内容。小尺寸阶段的任务是辨认轮廓和核对数量，强行保留所有微字只会增加视觉噪声；真实产品宣传则需要另行绑定并使用已审阅的真实产品素材。

默认蓝色 `#4979F5` 贯穿屏幕、阶段点、数量计划标记与结尾行动区，深蓝灰正文承接信息。金属边缘的浅暗变化提供厚度，屏幕高光帮助识别材质；低强度光晕和投影只负责将物体与背景分离，不承担“数量变多”的语义。

画面内容主要安排在下半部，上方约 600 px 是为人物留出的构图假设。小型眉题从 y=621 附近开始，主要标题基线约 y=708；产品在下方获得完整展示区域。该位置适合某些人物镜头，但必须和真实手势、服装及字幕一起检查。

三个产品展开时中心分别到 x=360、180、540，主件稍大、两侧略小并各转约 10°，先建立主次，再表达同类组合。数量阵列固定十列，中心间距为 56×47 px；70 台形成七行，规整共同坐标比随机散落更容易核对规模。

单件阶段主标题约 52 px，数量阶段主数字为 116 px、单位为 27 px，结尾行动文案为 31 px，按钮内短句为 23 px 或 20 px。每阶段只有一个第一阅读目标；切换时淡出旧标题，使产品运动不被多组大字同时包围。

## 从结论到代码的生成顺序

先确定内容真的要表达同类数量扩大，并写下最后的行动：观众应记住什么产品、多少件、接下来做什么。接着设计单台、三台、70 台阵列和主产品加行动区四个稳定关键帧，先检查轮廓、单位、阵列可数性与人物留白。

然后建立对象身份：第 0 台贯穿所有阶段，第 1、2 台从它后方展开并进入阵列首行，其余第 3–69 台补齐规模。结尾保留第 0 台重新放大，其他对象沿路径收拢后淡出；“同一件”由持续的索引、位置和尺度函数保证。

再写状态和帧函数：`entrance` 控制首件落位，`spread` 控制三件展开，`grid` 把三件转换到共同阵列坐标，`appearances` 决定新增件的到达，`collect` 将注意收回主件，`cta` 建立最后的行动阅读区。

所有状态来自局部 `useCurrentFrame()`。位置用 `blend(a,b,t)` 连续混合，透明度、旋转与尺度使用相同阶段进度；先验证几何路径与数量，再补金属边、屏幕界面、阴影和字距。美术细节不能用来掩盖首件跳位或数量不一致。

## 实际帧段怎样建立连续

入场、展开和小件到达使用 `Easing.bezier(0.22,1,0.36,1)`；阵列重排和主件回收使用 `Easing.bezier(0.65,0,0.35,1)`，让大规模位置变化从静止启动并收住。所有插值 clamp，阶段外保持终态，不依赖 CSS 计时动画或随机数。

| 帧段 | 实际函数与变化 | 下一拍留下什么 |
|---|---|---|
| 0–74 | 首件 `entrance` 在 0–42 帧完成；产品落位并供识别 | 第 0 台的屏幕、轮廓与主件身份 |
| 75–177 | `spread` 在 75–130 帧展开；第 1、2 台分别在 82–124、88–130 帧出现 | 同一三台产品及主次关系 |
| 178–283 | `grid` 在 178–240 帧重排；新增件按行列错开到达 | 前三台成为阵列首行，新增件补齐总量 |
| 284–323 | 十列七行与 70 台读数稳定保留 | 可同时核对的数量与产品轮廓 |
| 324–385 | 主件 `collect` 在 324–378 帧回收；其他对象逐行归并 | 第 0 台成为结尾主产品，规模结论留在标题 |
| 386–419 | `cta` 已在 357–386 帧完成；主产品与行动区停稳 | 可读的下一步和 70 台规划结论 |

前三台的扇形坐标由 `firstXs`、`firstYs`、`firstScales`、`firstAngles` 定义。每台从中心展开，再混合到阵列第 0、1、2 个坐标，最后混合到 x=190、y=979；没有在阶段边界把大产品换成另一张阵列截图。

主件从初始约 0.96 倍变为三件阶段的 0.86 倍，进入阵列时缩至 0.125 倍，结尾长回 0.66 倍并转至 −7°。另外两台收拢时缩至 0.055 倍并淡出，主件持续可见，观众才有路径把“一台”和“70 台”连起来。

新增件的到达起点为 `190 + floor(index/10)×6 + (index%10)×2.1`，结束点比起点晚 25 帧。横向错开避免整排突然出现，行间错开使补齐方向可读；第 69 台约在 269.9 帧完成，随后进入完整阵列停留。

计数不是独立从 1 滚到 70，而是累加 `appearances` 中进度大于 0.6 的对象。前三台在这个数组中固定记为已存在，数量标题直到 191–214 帧才显露，因此它服务的是阵列建立阶段，不宣称开场已经看见三台。

新增件回收使用按行错开的 324–370 帧基础窗口，每行再延后 1.5 帧；它们沿自身阵列位置向 x=190、y=979 缩小并淡出。第 0 台同时放大，使回收表达焦点汇聚，而不是用硬切抹掉数量阶段。

标题淡入淡出与产品运动交叠：首台标题在 70–91 帧退去，三台标题在 95–116 帧建立，数量标题在 191–214 帧建立，结尾标题在 346–369 帧建立。CTA 在回收后段进入，到 386 帧完全停稳，避免产品结束时才临时补上一张结尾卡。

## 源码已处理的问题与仍需修正的情况

“数字是 70，画面却没有 70 个对象”会削弱数量表达。本例根据同一个 `count` 创建对象与最终标签，并让中间计数跟随到达进度，解决数字与阵列脱节的问题。改变数量后仍需核对实际轮廓、读数和末行排列，不能只改结尾标题。

首件在规模转场中消失，会让各阶段像四段拼接。本例始终保留前三件并连续变换，第 0 台最后回到大尺寸；新增件先绘制，前三台后绘制，转场时主件也有清楚的遮挡层级。

70 台缩小时若沿用大物体阴影，会让阵列发糊。源码在 `grid>0.96 && collect<0.04` 时移除前三台阴影，新添小件也不带该滤镜；回收时恢复主件材质。改写后优先保证间距与轮廓，不用更亮光晕替代可数性。

`quantity` 目前四舍五入并限制为 3–70，超出范围会被夹到边界，不会如实表达原输入。少于三件应重做组合阶段，多于 70 件应设计分组或新的规模编码；同时更新源码、fixture 与文案，并明确每个图形对应几件。

当前阵列始终按十列排布，非整十数量的最后一行靠左，不自动居中；标题中的“十列展开”也固定存在。迁移到少量或异形对象时，应重新安排列数、间距和标签，而不是把数量参数当作任何布局都已支持的保证。

平板是自绘示意，`productName` 只改变名称，不会替换外观或功能界面。真实产品任务应让组件实际消费已绑定的真实素材，并核对比例、裁切与权利；只增加素材绑定而继续绘制 `Tablet`，不能算完成产品替换。

## 可以怎样迁移，哪些迁移不成立

适合迁移到同款设备配置、同类库存、赠品数量或作品规模：先让观众认出单位对象，再建立少量组，最后用共同坐标表达总量。结尾依据真实任务决定是回到代表单件、展开明细还是进入分配，而不是固定附送一个 CTA。

例如改为 40 套培训资料，应先确认每个对象代表“一套”，把平板改成可识别的资料包，阵列改成四行并重审节奏；结尾若任务是领取，行动区应说明领取路径。保留索引连续与数量一致的机制，重新生成物体、单位和行为关系。

不同型号、不同价格或不同能力的产品不宜直接复制成完全相同的轮廓，观众会误以为它们同质。人口、金额或抽样数据若使用一个图标代表多单位，要明确比例；把 70 个形状直接标为“七万人”而没有编码说明并不成立。

随机飞满全屏会传递热闹，却很难核对数目；每组对象从无关位置突然进入会丢失从单件到规模的因果感；结尾主产品与行动区同时退场则剥夺阅读时间。是否保留复制机制，应由内容关系决定，不能只换标题来套用。

## 与数字人、真人或解说怎样配合

先把源组件叠到实际人物镜头上，再判断上方约 600 px 留白是否成立。脸部可能在上方，手势、躯干和字幕仍可能进入下半区；深色文字在某些背景上也会失去对比。应调整人物构图、动效版式或局部承托，不把透明画布当作遮挡安全证明。

解说可按“一个人的工作空间—同伴展开—70 台团队计划—配置清单”推进。规模数字应在对象逐步可见时被说出，完整阵列留出识别窗口，再回到下一步；真人或数字人若有展开手势，可以对齐三件展开，但没有真实表演证据时不编造互动。

本例不绘制假人物，也未实现人物前后穿插。需要这类效果时由正式生产核对已就绪的 Mask 与合成关系；不适合持续同屏的镜头可以改为全屏产品解释，再在结尾接回人物。

“查看配置清单”是视频中的行动提示，不是可点击网页控件。若有真实链接或二维码，应在项目层明确承接方式与阅读时间；配套 MP4 无声，不能用它证明旁白、字幕、音乐和声效已经合成通过。

## 交接合同

输入是单位对象与数量口径、真实产品或示意身份、观众最后的行动、画幅、解说节奏和人物字幕占用。案例学习不要求用户每次给参考；正式生产所需的素材、参考和权利事实由调用方按当前能力主动补齐。

输出交回 [remotion-production](../remotion-production/SKILL.md)：说明数量模型、保留的对象身份、真实素材使用方式、Props、局部动作帧、阵列布局、人物字幕关系及验证证据。需要选择其他内容机制时回到[总案例 Skill](../motion-case-library/SKILL.md)。

验证对照 fixture 的 24、62、140、213、283、316、350、402 帧，核对首件可追踪性、数量与单位、阵列间距和 CTA 停稳，再正常速度连续播放。若没有观看动态或真实人物合成，应明确证据边界，不能把源码与审阅帧列表写成已完成验收。

数量、产品素材、字体、画幅、解说时序或人物构图改变，会使相关布局、数量和合成证据失效，需复核受影响范围。正式受管版本、Cue、Impact 与当前 Revision 的成片验收由生产 Skill 承接；这份案例不执行正式 Project 总流程，也不声明额外 MCP 能力。
