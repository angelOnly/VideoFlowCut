# 解释设计与信息释放

## 从主题与实际材料形成解释场面

本主题路线由导演、文案、素材、视觉首轮共同进入。材料提供真实观察、语境和事实依据，由视觉负责人整体选择材料、文字和图形如何形成可见过程，不预先分配主角与辅助的固定地位。先找初步问题与可取得内容，再由实际发现形成当前声画稿。

素材作者无需等待NarrativeMap或完整台词即可探索；导演不提前把主题映射成封闭的Scene类型和图形容器。文案使用本地已提炼写法，材料带回主语、行为、差异与新问题；视觉据实际材料选择取景、空间和主要动作，导演决定整体采用。

材料和文本可分范围共同发展。看到主要素材后，导演、文案和视觉确认它能支撑什么讲述，视觉作者将过程写进导演稿。可朗读正文确定后即可按授权制作配音，用实测声音校准正式时序。OD 制作第一版连续画面。

抽象关系可由准确编辑图形承担主要表达，材料可阶段性成为主角、共同呈现或完成作用后退为参照。原文、单位、条件与源时间保持准确，面积、位置和观察范围按本片选择；不可辨数据不猜，单图不假装可拆层，编辑图形不冒充官方页面。用户明确保留原片或实拍主导时按范围执行。材料不足继续探索或重构，不取消未完成取材，也不用无关素材凑数。视觉与动画共同设计时沿[机制方法](../../motion-case-library/references/mechanism-retrieval.md)使用参考，允许其改变初始构思。

## 解释片的核心是材料、讲述与可见变化共同解释

解释片是观看任务，不是默认使用图标和卡片。观众通过实际采用的材料认出对象、观察过程、比较差异，语言解释其中的条件、原因或意义，图形帮助指认和理解材料难以直接呈现的关系。旁白、材料和动画不必串行占用三段时间。

当前素材主导任务继续使用Explainer业务入口，不必切换成Vlog；NarrativeMap保存本版关注和理解关系，不把它当作必须回到同一模型的指令。实际素材、连续场面和必要图形在同一稿中形成，正式接口只承接已经作出的决定。

## 适用范围

适合分类、机制、流程、数据、对比、政策、产品结构、UI 操作、历史演变、证据论证和知识解释。人物可以开场、过渡或提供信任，但若主要理解仍依赖视觉模型，主工作流是 Explainer。

不适合以人物坦白、访谈关系或实拍事件为主的视频；这些应由 Presenter 或 Vlog 统领，并在局部调用 ExplainerScene。

## Gate A：NarrativeMap 和主声音

### 从问题开始

需要原创解说或授权改写时，导演把初步方向、当前证据与研究问题交 narration-writing。文案专项发展准确台词与逐段声画初稿，明确每段让观众看见什么、语言补充什么、依据在哪里、为什么接下一段。导演依据全文和实际材料采用主线，再组织 NarrativeMap 与分镜；不能将一份知识点提纲当作完成讲稿。

从用户要讲清的内容与目标观众出发，先提出整片初步观看方向。总导演试写先让观众看见什么，接着理解哪些关系，哪些材料可能负责验证、比较或改变判断，最后获得什么；关键材料探索后再明确各段作用和进入下一段的关系。问题、机制、证据、例子、反例和结论是可用内容，不是所有影片必须依次填满的结构。

主线初稿中的事实判断可标为待核实，所需页面、实拍、图形或动画可标为待补全。事实须取得依据才正式采用；表达画面可搜索、生成或原创。暂时没有现成画面不妨碍构思解释过程，NarrativeMap 初稿也不等于来源已经通过审阅。

从主题起步时，先试写开场声画与可能的发展，再找足以影响这个方向的真实过程、页面、操作和细节。事实调研用来核实判断，视觉探索用来发现怎样呈现；两者结果都回导演调整。不能把主题相关的画面直接当作主张证据，也不等完整 NarrativeMap 锁定才允许前期探索。

### 信息账本

记录每个 Beat 前观众已知、当前关注、即将新增、必要前提、暂缓信息和可能误读。先反向检查理解结论需要什么依据，再正向检查下一内容为什么值得此时出现。结果先行有助理解时可以先给结果；需要经历比较或条件变化时保留发现顺序。不为悬念隐去必要背景，也不提前展示需要逐步发现的全部关系。

### 主声音

先核对当前材料与文本的事实和讲述配合，可用实际读稿或试音调整语感。已确定范围即可生成或修订正式配音，其余材料和视觉编排并行。用 `manage_sound_plans` 保存声音意图，正式语音回来后按实测边界更新时序，再交 OD 实现。

材料、旁白与图形可以共同表达。新增材料优先在现有语音时段承担、替代或共场，不先要求额外插播时长；仍需改稿且用户未锁定时，原文案与导演修订受影响句群，声音和字幕相应更新。用户锁定的录音或总长在其边界内重新编排，不擅自裁声、变速或增加空尾。

需要配音沿 `voice-production`，原声文字沿 `transcription`／`semantic-continuity`，声音素材沿 `sound-asset-sourcing`，混合沿 `audio-finishing`。原声有表达价值时随选段和导演稿交接，OD 首版返回后在实际合成中试听。

## Scene Grammar：选择视觉机制

以下方法用于完善结合实际素材和参考形成的场面。根据当前内容选择适用的方法，处理比较依据、信息出现顺序和必要解释。具体素材、主要构图和运动过程由创意与视觉共同确定，再映射为平台场景；这些方法可组合、变形或另建适合当前关系的表达。

### HeroReveal

用于开场极端结果、关键数字或核心对象。先建立最少坐标，再给冲击，不让视觉夸大后文无法证明的承诺。

### ProgressiveClassification

用于分类、分层和用户群。先建立共同坐标，再逐项出现，最后显示差异或重点。不要每类一张新卡片。

### ComparisonScene

用于 A/B、前后、价格、方案和正确/错误。先建立比较维度，再出现双方，最后给差值或判断。不同尺度的数据不能用相同视觉长度误导。

### RouteAndFlow

用于流程、因果、路径、迁移和系统。对象和关系持续存在，随旁白推进；复杂流程分阶段揭示，不一次跑完。

### LayerStack

用于产品组成、成本、技术栈和结构层级。层的位置和顺序要有含义，不能只是叠卡片。

### EvidenceDocument

用于法规、论文、投诉、报告和合同。来源尚未明确时建立页面身份，再进入重点；已有上下文时可直接看局部。保留条件、否定、单位和必要上下文。

### UIWalkthrough

用于 App、网页和操作。让观众看见真实界面状态变化、点击目标和结果；人物/旁白只解释必要内容。

### DataConclusion

用于趋势、比例和结论。数据来源、坐标、基线、样本和不确定性必须可读，动画不能改变比例事实。

### RealityBroll

用于现实经验、地点、行为和情绪。它可提供现实体验，也可通过真实操作和同条件比较解释关系，采用范围以实际观察为准。

### QuotePortrait / HistoryTimeline / EndCard

分别用于人物观点、历史演变和收束，但引语、日期和来源需要真实证据。

具体变体按本页当前观看任务的方法选择，不另加载业务范本。

## 大 Scene 内部渐进

一个连续场面可以跨越多个句群。根据已经采用的材料决定观察范围、主读和下一变化；通过取景、材料自身变化、解释层与声音安排发展，不因一句说完或一个机制结束就清空重建。不同内容可以用同一材料继续展开，确需换材料时设计完整接管。

## 解释、证据和素材的分工

材料的事实依据、情绪、观察和审美价值按实际内容使用，不把媒介预分成“只能情境”“只能证明”“只能动画解释”。素材、花字和准确图形谁取得主要面积、何时让出注意，由当前观看过程决定；真实性不自动要求原件一直占主画面。

素材作者带回实际内容与范围，导演和文案共同确定讲述，视觉在材料上组织观察、文字及动作。当前需要的单位、条件和原文关系保持，来源信息留在项目记录，必要说明自然进入讲述，不自动铺成画面脚注。此处不提供业务场景范文，具体素材与对象写在当前作品稿中。

## 工具与当前落地

当前 MCP 已实现 `manage_story` 保存 Beat、`manage_narrative_map` 写入 NarrativeMap、`read_narrative_map` 读回当前 Revision 的问题/知识/递进与证据交接、`manage_visual_treatment` 保存主视觉决定、`create_scene` 创建基础 ExplainerScene 或 CutawayScene、`manage_cutaways` 将已就绪本地视频放入 Fullscreen/PiP、`submit_motion_work` 生成原创固定版本，`review_motion_work` 审阅，`manage_effect_cues` 放置，以及通过工作台固定版本的范围播放检查实际合成。文件交接、离线检查或渲染差异诊断使用 `render_preview_range`，具体静态问题使用 `inspect_composed_frames` 定位。当前 Scene Schema 没有独立 DocumentScene；文档、网页和证据只能作为已登记 Asset 进入已有 Scene。

这些对象和命令已有确定性 MCP/项目图测试，但不等于 Evidence Provider、完整 Scene Registry、复杂数据/文档组件或审美效果已经完成真实验证。每次写入 NarrativeMap 后读回对象、Revision、Impact 和 Preview；缺失组件不能用错误的通用卡片替代后声称完成。

不能为了“代码已支持 create_scene”就用一个空 Scene 声称 Explainer 成立；也不能把 Presenter Effect Registry 里的 ProductFan 强行当通用解释组件。

## 多 Scene 的整片结构

按已取得材料和内容关系组织观察的发展，不预设“模型解释—证据页—素材插播—回到模型”的循环。材料、图形和文字可以相互接管，完成作用的内容可以退出或退为参照，不必返回原模型、原表或人物。

连续性来自仍需追踪的问题、对象、比较、方向或声音。需要持续的源时间和几何状态保持，已经无用的卡片和背景可以离开。观察转向与必要切镜都由内容设计，文件边界不决定画面边界，也不将每句旁白做成一件独立作品。

同一段时间内，材料、图形与文字按已选观看过程共同表达，语言补充必要意义与条件；原有时段放不下时先取消重复表达、重分主次和取景。真实的阅读或声音冲突再调整局部内容，不以实现方便取消材料用途。不同来源并列或类比不伪装同一事件。

## 复杂信息的减法

当一张 Scene 有超过观众能同时比较的对象时，应分阶段、分组或拆 Scene。不要用更小字体、更多箭头和更快动画解决。旁白可以省略视觉已经表达的内容，视觉也不必显示所有旁白词语。

## 根据实际素材和参考确定解释场面

创意与视觉查看本片实际素材和参考视频后，共同决定具体场面。导演检查这些场面怎样支撑整片内容，并协调主要采用。

选定参考中的一段以后，将共同形成效果的素材组织、构图、文字、背景、镜头和运动作为一个完整过程研究，并结合本片材料照着完成。

先看清参考从什么画面开始，素材和文字怎样变化，变化后形成什么构图，最后怎样结束。再确定本片分别使用哪些素材、准确文字和图形完成这些过程。

本片题材、中文和画幅带来的调整，由创意与视觉共同完成。需要保留的主要表现写入制作简报，具体取景、比例、排版、路径、曲线和内部时序交制作作者完成。

参考不适用时，依据已经看见的问题调整查询，继续寻找能够支持当前内容和材料的场面。需要原创补充的部分，写清它承担的内容、具体过程及与前后场面的连接，由创意与视觉共同设计。

涉及数据、身份、事件与因果的表达，依据本片准确内容和实际来源确定。参考提供的画面表现与这些事实条件共同进入本片编排。

作品返回后，对照选中的参考范围查看素材组织、构图变化、文字作用和运动节奏。缺少主要表现时，交回原作者调整场面或实现。

## Gate B：具体生产

具体编排为每段给出大约的秒级初始节奏，同时说明机制怎样推进、动作如何交叠和文字何时可读，按 [初始节奏与预览修订](../../effect-timing/SKILL.md#初始节奏与预览修订) 实现首版后再调整各段起止。明确锁定的讲稿、声音与总长按约束保留；可修改讲述由导演结合完整场面共同修订。必要或受约束的后续讲述由实际画面接续，不能补空尾。

导演与首轮文案、素材、视觉共同确定主要对象、要让观众看到的变化、声音方向和前后关系。由同一视觉负责人共同设计真实选材、关键构图、美术与连续动作，再映射 Scene 范围、内部状态和接口；不把视觉交付冻结成等待动画接续的静态页面。不能让 Scene 类型或组件默认行为重新决定整片故事。

若关系变化本身承担解释，在导演稿中写清主要动作、可读时刻和与声画的承接，让 OD 在首版优先实现该范围。视觉作者看实际画面修订，影响内容、讲述顺序或跨段含义时交主导演。

交出的分镜以完整场面描述解释怎样发生：表层参照如何留下、内层怎样出现，局部如何获得整体归属，真实过程如何验证判断。普通字幕、画内数值和问题各有持续范围，稳定构图可承接多句；不是一旁白句对应一件作品。

采用 OD 的原创主视觉由 OD 制作受管 HyperFrames 源码，通过现有 ExplainerScene 与 ManagedMotion 放置。需要真实证据时由 `evidence-visualization` 提供可追溯素材。普通视频插播走 Timeline/Cutaway。同一活动视频参与重排、裁切和图形解释时使用[受管视频合同](../../opendesign-video-production/references/hyperframes-contract.md#受管动态视频)，核对素材身份和源时钟，原声随声音链处理。

作品替换现有 Program 时，明确谁承担主视觉，再对旧 Program 局部停用。不能用新的不透明背景把旧内容遮住后就宣称替换完成。结构上覆盖完整 Scene，只证明有可用主视觉；内部是否真的解释了内容，仍由真实连续观看验证。

## 字幕和声音

普通字幕是否全程显示由交付目标与本片构图决定，需要完整字幕时保留准确语言。画内文字与字幕分别承担作用时可以共存；证据、UI 与文字的实际阅读顺序和遮挡在合成中复核，不因题材自动删减。音乐提供章节和能量，按当前听觉主次安排；SFX 绑定有作用的对象、状态或叙事事件，不给每个元素入场都加声音。

## 常见失败

- 旁白一句一页卡片；
- 全部信息一开始同时出现；
- 图形只是文字容器，没有关系或状态；
- 证据缩小到看不清；
- 生成截图冒充真实页面；
- 数据动画改变比例或缺基线；
- 同一模板重复整片；
- 素材与当前主题和场面缺少联系，或没有实际完成已经安排的主体、语境、情绪、趣味或节奏作用；
- 每个对象都动，观众不知道先看哪里。

## 已选材料进入解释场面

材料从首轮参与，实际文件和源范围直接进入现有时间线或作品绑定，不以分析等级、overview、range或满覆盖记录建立采用资格。未知范围在正常播放器、代理或可选理解中继续定位；辅助读取不足不自动改变材料身份。必要证据按当前主张核实，不给普通配图追加整套事实证明。

外层Timeline/Cutaway和受管视频槽位按实际使用选择，前者不是唯一“允许素材”的位置。源内容需要与图形、文字、取景共同变化时，在同一场面实现；原声按当前声音设计接入。使用实际受管文件、源身份和合法时间范围，不以预览地址冒充项目素材。

原件与编辑解释的含义通过准确讲述和清楚画面关系区分；制作来源、用途备注和辅助分析留在记录，不默认生成“示意、示例、非当事”等角标。当前NarrativeMap、试音和临时布局继续随材料修订，不以纯图形的完成关闭材料主导任务。
