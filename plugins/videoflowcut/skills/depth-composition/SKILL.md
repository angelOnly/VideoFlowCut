# 人物前后景、遮挡与空间构图

## 空间合成不是把对象塞进空角落

一个画面中的人物、字幕、产品、证据、背景数字和 UI 都在争夺面积和注意力。`depth-composition` 不只是检查“有没有挡脸”，还要判断谁是主视觉、对象为什么位于该层、运动路径是否穿过关键内容、前后景是否形成可信空间，以及横竖屏是否需要重新构图。

默认层级可以是 Background → Rear FX → Actor → Actor FX → Front FX → Fullscreen/Cutaway → Caption，但语义优先于轨道名称。Fullscreen 有意接管主视觉；Caption 虽在上层，也不应永远比证据或人物更显眼。

## 先标记受保护区域

人物的眼睛、嘴、关键表情、手势、产品和视线方向通常需要保护；证据文字、UI 操作区、画内原文字和平台控件也不能被覆盖。字幕区不是固定安全带：近景人物、手持物和横竖屏会改变可用空间。

在布局前先检查目标帧，不要用固定 `bottom_right` 作为默认。对象进入和退出路径也要保护，静止时不挡脸不代表飞入过程不穿过脸。

先比较源画幅与输出画幅的主体占比，区分源素材本就近景与 cover 裁切造成的大近景。头顶、肩部、手势和负空间共同决定文字是否能与人物建立关系。不要先固定大脸铺满再把所有对象缩进剩余角落；可用能力允许时重新构图，否则选上下层级或全屏。不能将有限缩放写成已实现自动跟踪或缺失画面恢复。

## Rear FX

后景适合规模、状态、氛围、章节和评论环境，因为它可以让人物保持前景关系。它要求 Mask 或透明通道稳定；关键信息不能被人物完全遮住；背景数字和滚动评论的对比与运动不能压过脸。

无可靠 Mask 时，不能只把层标为 rear 就声称后景成立。降级到人物两侧、普通背景、轻 Overlay、Fullscreen 或不使用。

## Front FX

产品、证据、CTA、封面和对象可以位于前景，但必须有空间支撑关系。对象从人物手中展开需要真实手势和位置；没有姿态数据时使用标准安全区。前景不能随机贴在脸旁，也不能迫使字幕缩得不可读。

## Actor FX

CameraPunch、轻构图变化和表情反应用于短落点。长期推近、抖动或变形会让口型和信任受损。焦点应指向人物的有效表情，而不是固定画面中心。

## Fullscreen 与返回

共同设计入口、关键状态与出口的主体尺度和可见范围，记录人物离开/返回时的位置、姿态与字幕预算。遮盖中的底层作品仍运行，关键关系必须在实际可见时展示。

复杂文档、UI、解释、B-roll 和强笑点需要全屏。进入前应有语言或声音交接，退出时观众要重新定位到人物的新姿态、情绪和句子。全屏不是把一个前景卡片放大；它拥有自己的 Scene 任务和阅读时间。

## 视觉重量和第一重点

尺寸、对比、运动、位置、清晰度和声音共同决定视觉重量。一个大但静止的背景数字可能仍比人物弱；一个小但高速闪烁对象可能抢走全部注意。每个范围明确第一重点、第二重点和保持稳定层。

同时检查最低有效显著性：承担核心判断的对象，应在目标观看尺寸、真实人物背景和正常速度下自然进入注意，而非只在放大截图中读得出。语义重点的体量、对比和位置可短暂强于人物；保护脸部与语言阅读不等于禁止主次交换。对比布局使用共同对齐线、接近性与一致色彩语义建立关系，空白用于分组和呼吸，不用于隔开本应一起比较的对象。

动机性 Cut-in 应产生明确的新景别，保持眼线、主体重心与源时间连续；连续 Push-in 应有起势、目标和稳定落点。幅度过小的反复缩放可能像抖动，源人物已经过近时更不应持续追加 Punch。先选择可成立的构图，再让运动建立它。

## Mask 质量

检查头发、耳朵、手指、快速动作、半透明、边缘抖动、背景泄露、分辨率和时间同步。Mask 在静止帧通过后，还要播放动作。边缘问题严重时，减少高对比后景和穿插，不用 Glow 掩盖。

## 多画幅

16:9 允许左右关系，9:16 更依赖上下层级和安全区。横屏组件不能只中心裁成竖屏；人物大小、负空间、产品、证据和字幕都需要重新布局。当前 Runtime 对 SpatialAnchor 的响应有限时，应明确优先画幅并为另一画幅给出降级，而不是承诺自动响应式完成。

## 多对象构图

当同一 Scene 有人物、产品、数字、字幕和评论时，先确定第一和第二重点，再决定哪些对象只作为背景。可以通过尺寸、透明度、清晰度和运动降低次要层，不需要全部删除。对象数量超过可理解范围时，拆阶段而不是继续缩小。

## 视线和动作方向

人物看向右侧会让观众期待右侧出现对象；对象从相反方向进入可能造成错觉。手势、身体朝向和镜头运动共同建立方向。没有真实证据时不要让布局依赖精确视线。

## 文本和证据保护

Evidence 和 UI 的可读区域优先级可能高于人物持续可见。若 PiP 导致原文不可读，应切 Fullscreen。字幕与证据都需要文字时，考虑短暂隐藏字幕、重新排版或让旁白承担内容，不在一个小区域叠两层文字。

## 颜色与背景

Mask 边缘、人物肤色和产品颜色会受背景影响。高对比动态图形放在头发后容易暴露抠像；低对比但可读的后景更稳定。颜色语义和可访问性也要检查，不只追求品牌色。

## 安全区不是固定坐标

平台 UI、字幕、人物动作和不同画幅会改变安全区。建议从目标 Frame计算可用区域，并在整段运动中更新；静态 safe_left 只能作为初始降级。

## 当前工具

ManagedMotion 内部图形的位置由源码固定，外层 Cue 不能任意拖动内部对象或重排人物。改变内部构图要新作品版本；没有真实 Mask 时按可实现同屏与全屏设计。

EffectCue 支持 top_left、top_right、middle_left、middle_right、bottom_left、bottom_right、center、full_frame。架构中的 actor_head、actor_hands、behind_actor 等逻辑锚点尚未完整进入当前 Tool Schema。Skill 可以规划这些语义位置，但执行时必须使用当前可用 Anchor 或 Browser Inspector 微调，并记录能力差异。

## 案例：人物手势与产品

人物说“这里有三种方案”，右手向画面左侧展开。若产品卡从右侧进入，会和视线/手势方向矛盾；若字幕也位于左下，产品会压字幕。合理方案可能是让三项在人物左侧上方逐步出现，字幕保持下方中央，人物手势结束后对象稳定。没有手势证据时，不要写“从手中展开”，改为安全区出现。

## 交接合同

连续作品交接还带入口/出口约束、真实可用范围与局部事件；素材、时序或作品版本变化后相关 Cue/声音需要复核。验证必须对应当前版本实际合成。

输入是人物/主体、Mask、字幕、画幅、Scene 和 Effect。输出是空间布局、安全区、层级、运动路径和降级。它会影响 EffectCue 与 Scene Layout。验证是静止构图、完整运动、Mask 边缘、字幕和多画幅。结果返回 `remotion-production` 或主工作流。
