# 语义连续性与 A-roll 内容编辑

## 这不是“按标点删废话”

语言剪辑最危险的错觉是：文本删完仍然语法通顺，就认为意义没有变化。真实口语依赖前提、语气、连接词、停顿和上下文；一个结论离开铺垫后可能从个人经验变成绝对判断，一个回答离开原问题后可能改变对象，一次重复可能不是口误而是强调。

`semantic-continuity` 的任务是决定观众最终听到哪些完整思想，以及这些思想怎样自然连接。它是声音、字幕、B-roll、MG 和音乐的上游。若主线尚未成立，下游包装只会把断裂隐藏得更深。

## 先判断这次属于哪种任务

### Cleanup

目标是保留原内容和原顺序，只移除错误重启、无意义口癖、技术等待和确实重复的部分。好的 Cleanup 让说话者听起来像状态更好的一次自然表达，而不是像机器把所有呼吸都抽走。

### Highlight

从长素材中选择最有价值的完整观点、故事或反应。这里允许大量不使用，但每个选中范围必须有完整上下文，不能只因为出现关键词就截半句。

### Restructure

重排完整语义单位，使问题、论证、步骤或故事更清楚。重排必须保护事实时间线、人物知情、问题与回答和引语条件，不能从不同 Take 的残句拼出说话者从未完整说过的新句子。

### Hook / Short Version

为短视频或开头建立问题、结果、反差或高价值承诺。Hook 必须由后文兑现，不能只把最激烈的一句话提前后失去语境，也不能通过字幕或 B-roll 夸大原内容。

### Target Script

用户已经给定要保留的准确文稿、范围或目标表达。此时应尽量与目标对齐，但仍要保护自然音频边界和完整语法。若源素材无法真实组成目标 Script，应明确缺口，不拼造。

不同任务使用不同标准。Cleanup 不应偷偷重写观点；Highlight 不要求保存全部结构；Target Script 不允许 Agent 自行保留“觉得更好”的额外内容。

## 建立完整内容地图

第一次阅读 TranscriptText 时不要立即删。先标出：问题、回答、主张、前提、原因、结果、转折、对比、例子、列表、设置、包袱、结论、重录、错误重启、有意重复、口癖、呼吸和情绪停顿。

TranscriptSentenceCandidate 只提供阅读分块。一个完整思想可能跨多个候选句，例如“我不是说钱不重要，我是说如果把所有生活都推迟到以后……”；如果只保留后半句，观众会误以为人物否定钱的价值。反过来，一个长句可能同时含问题和结论，需要拆成两个 SemanticUnit。

当前代码要求通过 `apply_semantic_units` 将 candidate_ids 组合为 SemanticUnit，并可以记录 kind、dependencies、上下文、retakeGroup、confidence 和 pauseBefore。这里的结构不是为了让 Agent 填满字段，而是把影响后续编译的专业判断保存到 Project。

原创新稿不属于转写清理。用户提供或委托新写、尚未录音的旁白，经完整思想与事实审阅后用 `apply_authored_script(base_revision_id, source_note, units)` 整体写入当前 Script；每段给出 text、kind 和必要的上下文、停顿判断。`source_note` 说明真实文稿来源，不填写 candidate_ids，也不把音色样本当作台词来源。该入口直接建立 authored SemanticUnit 与待合成 SpeechSegment，不制造 Transcript、媒体 Asset 或时间戳。VoiceReference 只在后续配音时提供音色。写后读回 Script、Revision 和 Impact，再交回主工作流生成真实旁白；之后的选段重排仍可用 `apply_script`。新稿入口是整稿替换而非追加，修改已有主线会使旧旁白、字幕和包装失效，必须复核后续链路。若任务是在剪真实原声，仍走转写候选入口，不能用原创新稿改写人物实际说过的话。

## 完整思想怎样判断

一个范围至少要让观众知道谁或什么在做判断、判断对象是什么、条件和否定是否完整，以及它与前后句的关系。高风险信号包括：

- “但是、所以、其实、不过、也就是说”开头却没有前项；
- “这、那、它、他们、这样的事情”没有明确指向；
- 回答存在但原问题被删；
- “第一、第二”只留下其中一项；
- 数字没有单位、对象或比较基线；
- 情绪反应被保留，却看不到触发原因；
- 结论有力，却失去说话者限定条件。

判断不是看字数，而是看观众能否在当前顺序中合理复述含义。

## 重录、错误重启与有意重复

### 错误重启

人物说到一半停下、改口并重新完整表达，通常选择完整版本。但早期片段可能包含后一次没有重复的必要前提、人物反应或更自然的动作。不能默认删除整个第一次 Take。

### 两次完整重录

比较准确性、完整性、自然性、情绪、声音、画面、前后衔接和可用余量。最后一次不一定最好；第一遍可能情绪真，第二遍更流畅。若无法同时保留，依据视频承诺决定优先级，而不是固定选择后一次。

### 有意重复

重复可能用于强调、节奏、笑点、情绪升级或结构回环。例如“我一直在等，等一个更好的时候”中的重复建立主题，删除后会削弱人物状态。判断它是否让观众状态变化，而不是仅仅词相同。

### 跨 Take 拼句

不能把两个不完整残句拼成一条说话者从未完整说过的句子，尤其在访谈、证据和真实人物内容中。允许在完整表达之间重排，但要保留事实与语气。

## 口癖、连接词和停顿

“嗯、然后、就是、你知道”可能是无意义填充，也可能标记人物思考、转折或口语身份。删掉后若句子变得过于书面、情绪突然或呼吸不自然，说明它承担了功能。

停顿也需要分类。技术等待和找词卡顿可以缩短；呼吸、犹豫、情绪、包袱后的释放、结论前准备和章节转场可能保留。正确做法是比较保留、缩短和删除三个版本，而不是所有停顿统一 180ms 或全部压到零。

例如人物说：“我以前总觉得……只要再赚多一点，就有资格休息。”中间停顿可能是在承认一个长期信念。如果删除，句子更快，却失去自我反思；如果过长，又像忘词。需要结合表情、语气和整段节奏确定。

## Hook 和短版怎样不误导

一个有效 Hook 让观众产生可被后文公平回答的问题。可用的材料包括具体结果、真实冲突、反差、强问题和有证据的结论。仅仅声音大、数字大或快速切镜头不构成 Hook。

前置一句话后要检查：原身份、时间和对象是否仍清楚；这句话是否本来是对特定问题的回答；后文什么时候兑现；是否把人物的有限经验改成普遍结论。若需要补一句坐标才能公平理解，就应补，而不是为了前三秒强刺激删掉。

## 特殊场景与边界

### 问题与回答

访谈中回答常省略主语和对象，因为问题已经提供语境。把回答单独前置为 Hook 时，可能需要保留或补足问题坐标。不能让受访者看似主动做一个原本没有做的绝对声明。

### 列表和步骤

删除某一项后，序号、承接和结论可能需要重写或保留解释。只留下“第三”而没有前两项会让观众迷失。若 Highlight 只选一项，应去掉序号或给出新的上下文，但不能修改原声事实。

### 数字、时间和范围

“增长了 30%”需要知道相对谁、什么时期和什么指标。内容选择不能留下孤立数字让 MG 夸大。高风险内容应绑定证据。

### 观点与事实

人物说“我觉得”“在我的经验里”的限定不能随意删除。删掉后主观判断会变成事实陈述。反过来，过多限定若只是口头重复可以精简，但保留必要边界。

### 情绪和反应

一句“我没想到”只有前面有触发事件才成立；一个笑声只有包袱或情境存在才有意义。反应可以作为 Highlight，但需要最低语境。

### 跨语言和专名

中文夹英文、品牌名和术语要听声音并参考可靠来源。为了字幕统一可以规范大小写，不可改变词义。TTS 需要读法调整时，区分最终显示文本和朗读文本，避免 Script 状态混乱。

## 删除的反事实测试

每个高影响删除问：删除后观众会不会误解人物更确定、更冷漠、更绝对或更快得出结论？前提、对象、问题、情绪和反应是否仍存在？如果保留的唯一理由只是“原片有”，可能可删；如果删除改变人物意图，即使句子更短也不应删。

## 重排的关系测试

相邻 SemanticUnit 必须有可描述关系：因果、问题/回答、主张/证据、行动/反应、对比、递进、坐标/展开。若只能说“这两段都挺好”，说明重排还没有结构。

## 与字幕和视觉的边界

不要为了让字幕短而改变 Script，也不要为了某个 Effect落在句首把自然语言硬拆得不自然。可以调整 SpeechSegment，但 SemanticUnit 仍保持完整；视觉应服务语言，而不是让语言适配模板。

## 写入当前项目

标准流程是：

```text
read_script
→ 读取 TranscriptSentenceCandidate、现有 SemanticUnit、Script、SpeechSegment
→ 必要时回听源音频
→ apply_semantic_units
→ 读回 SemanticUnit 与新 Revision
→ apply_script
→ read_impact_report
→ 读回最终 Script / SpeechSegment
```

Script 修改会使 SpeechAsset、Caption、EffectCue、Cutaway 和 ActorPerformance 的部分结果失效或需要复核。不要在本 Skill 内假装这些下游已经更新；把 Impact 和新 Script 交回主要工作流。

## 只听声音的验证

文字看起来正确不代表听感正确。完整播放主声音，检查：

- 是否有半个音节、辅音尾或突然切断；
- 前后背景噪声和 Room Tone 是否跳变；
- 情绪是否在切点无原因改变；
- 每句话是否都像独立 TTS 片段；
- 观众是否能复述核心和相邻段关系；
- 有没有正确但多余、重复消耗注意力的内容；
- 停顿是否有层级，而不是全片同一种间隔。

若当前工具不能精确裁源音频，仍应输出语义计划和风险，不声称 A-roll 已经完成。

## 完整案例：反思型口播

原始表达：

> 我以前总觉得，嗯，只要再赚多一点钱，我就有资格休息。然后我后来读到这本书的时候，我突然发现，不是钱不重要，是我一直把生活推到以后。

错误 Cleanup 会删成：

> 只要再赚多一点钱，我就有资格休息。不是钱不重要，是我一直把生活推到以后。

文字更紧，但“我以前总觉得”和“读书后发现”的认知变化消失，后半句像直接说教。更合理的处理是删掉无功能的“嗯”和部分“然后”，保留旧信念、触发事件和新认识，并保留“不是……是……”的完整对比。若人物在“我突然发现”前有表情变化，停顿也应保留或只轻微压缩。

## 反例：关键词 Highlight

在一小时访谈中搜索“人工智能、未来、工作”，截取所有命中片段并串联，往往得到多个没有原问题、对象和结论的残句。Highlight 应先确定选段承担哪一个观点或故事，再取完整问答和必要铺垫，而不是把搜索命中当最终 Selects。

## 交接合同

进入事实：Transcript/候选句、当前 Script、源声音、任务模式、目标时长和用户必保内容。输出：经审查 SemanticUnit、最终 Script、删留/重排理由、停顿策略和新 Revision。失效：SpeechAsset、Caption、EffectCue、Cutaway、ActorPerformance。验证：读回、Impact、只听声音和事实/语义复核。

完成后将结果交回 `presenter-motion-director`、`visual-explainer-director` 或 `vlog-director`。本 Skill 不负责继续做包装或宣布整片完成。

## 文字之外的源素材证据

当任务只涉及明显错字、低歧义口癖或已有可靠范围的文本重排时，可以先从 Transcript 和现有 SemanticUnit 工作；但以下判断不能只看文字：两次完整重录的选择；停顿究竟是卡壳、呼吸、犹豫还是情绪落点；回答脱离原问题后是否变义；跨 Take 拼接是否造成表演、口型或环境声断裂；人物反应是否真正属于当前事件；句首句尾是否存在半个音节或未完成口型；连接词删除后语气是否变得更绝对。

遇到这些情况，先读取对应 Asset 的 `range`；边界依赖短暂动作、微表情或发音时，再读取最小 `dense` 窗口。选择 SemanticUnit 时同时保护文字意义、声音自然、人物表演和真实上下文。一个文本更短、语法仍通顺的版本，可能已经让人物显得更确定、更冷漠或更绝对。

本 Skill 仍负责语言和内容连续性，不替主工作流决定视觉形式。完成后交付最终 SemanticUnit、Script、SpeechSegment、停顿策略、删留/重排理由、源范围证据和下游失效范围；Presenter、Explainer 或 Vlog 主工作流再决定人物、B-roll、字幕、声音和 Scene。
