# 任务范围、真实分派与原负责人续接

本页只解决交给谁、交什么、何时接回。项目定位沿[项目基础](../../project-basics/SKILL.md)，正式操作沿[项目写入](project-writes.md)；角色身份、版本和完整交接字段以[共同交接约定](../../_shared/PROJECT_REVISION_AND_HANDOFF.md#代理角色与交接)为唯一依据。

## 按用户实际范围分派

每次剪辑建立或续接实际范围的 ProductionRun，完整解说新片（`full_creation`、`visual_explainer`）真实分派两位独立作者代理，分别承接 `creative_research` 和 `motion_research`、`visual_design`；其他类型按相应路由执行。登记实际 agent、输入版本和使用的方法。局部编辑分别判断表达、动作接点和画面影响，以 `record_creative_decision` 记录三项决定、依据和对象；视觉决定用 `input_decision_ids` 引用本次创意与机制判断。沿用旧决定时填写 `reused_decision_refs` 并写明本次核对依据；多个来源合计覆盖本次判断范围，部分沿用与新增判断按范围分别记录。没有历史决定时查看当前作品后形成判断。

制作前用 `read_production_status` 检查 `preparation`，按缺项续接原视觉作者。正式画面委托必须传 `production_run_id`。工作台局部修改在同一 Run 的准备检查后使用现有控件，保存后读回 Revision。作品返回时分别填写三项 `responsibility_reviews`，引用实际分派与本次判断，说明实际观察和结论；问题引用原 Finding 沿原作品返修，复查确认后关闭。普通字幕单帧只核对静态文字，运动沿用须有本次影响判断。

分派采用 [唯一视频类型路由](video-type-routing.md) 的当前结论；人物专属参考只随 `presenter_motion` 或 `hybrid` 中已确认的人物子范围发给导演／视觉／人物专项。其他类型继续使用原有专业方法。单个图表、实拍或人物窗口变化不是重新路由的依据；收到不匹配的委派时，返回主任务核对，不自行补造路线和对象。

完整视频建立持续负责的[总导演](../../production-director/SKILL.md)；新制或主要重构按[主题工作流](../../_shared/TOPIC_TO_FILM.md)并行启动并按[共同交接](../../_shared/PROJECT_REVISION_AND_HANDOFF.md)保留各项职责与接回条件。局部任务交原负责人。

完整解说默认完成整幅画面与连续观看的设计。导演交清准确内容、真实材料、表达重点与前后关系；视觉作者决定主体、背景、文字和动作怎样共同成立，花字、基础排印、实拍、图形、静止或切镜按本场用途选择。普通字幕独立，出处、原件页码和研究备注不作为新增说明上屏；主任务传同一画面文字规则，不只交“解释这个表”。没有偏好时仍从[整场视觉入口](../../visual-treatment-planning/SKILL.md)直接制作，传递本任务明确要求、用户主动保存的默认及当前设计，完整解说新片的画面编排由视觉作者决定，按[素材主导与图形规则](../../visual-explainer-director/references/explanation-design.md#素材主导与图形规则)执行。普通制作使用已整理的本地方法，不派发博主研究，不将本片选择写成用户永久偏好。

完整人物混合解释从首轮交付整场视觉责任，不派成“人物段加花字、无人段做动画”。
交当前完整句群、主要观看任务、实际材料、前后关系、目标画幅和真实锁定项；
人物作为带源时钟与表演限制的视频材料进入同一设计，不预分配不可改变的主画面。
人物源返回后续接原视觉作者；生成视频只完成人物素材。

沿当前口播和分镜派发人物源缺口，不遍历全文语音段生成人物。范围已明确的部分
可以先做，后续增加或改分镜仍走原流程。调用实际发布的 v2 源生成和使用合同，
读回真实素材及当前引用；不重新组织整片主线，也不把旧 Job 的位置覆盖回新画面。
接回真实画面与完整发展、资源和源码、已观察范围及未完成用途。
只有布局名称、颜色、机制编号或人物文件时，继续原任务，不报整场完成。
正文锁定只限制文字与相应声音修改，不减少已委托的取材和整场视觉责任。
人物成为某种窗口后，主要材料的观察、关系发展和交接仍须有实际制作产物；
缺少哪项作用就续接对应作者，不能把完整工作单改写成少量装饰任务。

尚无 Project/Revision 时，把用户需求和真实建项状态交导演形成建项建议；主任务依明确参数创建后读回版本，再交导演确认。探索没有最终 Scene、Beat 或精确时长也可继续，不为交接字段编造对象。

按实际工作需要读取上表对应方法。首次视觉派发交当前准确内容、实际材料、参考、前后关系、用户锁定项和视觉入口。

首次接回按当前阶段进行。主题阶段先接回文案骨架及画面需求，代表素材返回后启动对应场次的参考检索。制作前按下方路由接回创意原文，再接回视觉作者确认的复摆、完整简报、实际资料和完整请求，按视觉作者确认的版本办理导演采用。主任务正式启动 OD 后，接回同版连续作品与源码，交原视觉作者复核与修订，主导演核对文案、制作范围与规格。

首次视觉派发交准确台词、已取得素材及可用的视频源段或静图区域、观看目的、目标画幅和前后接口。视觉作者按[视觉设计](../../visual-treatment-planning/SKILL.md)交导演稿、素材映射、主要美术和运动。不得把只有色号和形容词的摘要标为可制作。普通字幕沿统一规范，机械修改直接定位现有作品。

按当前可用名额真实分派，分别回传文案、素材和视觉作者的三项职责决定。首轮作者并行，有用的发现即时交相关作者。子代理不递归分派。原视觉作者贯穿设计、OD 交接和实际作品返修，OD 编写及修改作品源码。

创意与视觉开始构思关键动作时，就指定持续负责的声音作者，可由职责相邻的现有作者兼任。交当前声音意图、实际动作与旁白约束；有生成需求时接回完整指令，由主任务提交 `submit_sfx_generation`，再把真实候选交回同一作者检查、选段和混音。不因暂无最终动画帧推迟全部选声，也不在提示词或 Job 成功时结束这项责任。粗剪与交付前接回每项意图的采用、留白或未完成结论。

从零创作只交当前准确内容、真实材料、声音字幕与限制，不附同题旧作品布局、源码或历史项目身份。局部修订则必须交当前作品、源码、已认可部分和实际问题范围。隔离试验的禁止联网等限制不继承到普通生产；已知宿主历史注入如实记录，不宣称自然语言禁令实现了严格隔离。

## 完整新制的并行路由

完整新制或主要表达重构，建立一个持续负责的主导演。主导演负责讲述主线、文案、制作范围与成片规格。完整解说新片的整片画面编排、节奏、场间接续与观感由视觉作者负责。

### 首轮分派

主任务接回导演给出的内容范围、成片规格和必要语境。只有主题时先安排文案、取材及画面需求梳理。用户已给完整文案时，沿用原文，由素材作者取得本片画面后分场交给创意作者；创意库入口随内部派工传递。主任务将主导演确认的整片视觉导演基准原样发给创意与视觉作者，附完整文案和可打开的全片素材入口。整片研究形成后，按本场代表素材和待解问题分批续接逐场检索。用户指定的原话、事实或画面要求随适用范围传递。

- 主导演使用 `production-director`。首轮把当前文案、代表素材、全片素材入口和用户要求随实际消息送达。交给主导演的话是“这支完整解说新片以素材为主体，动效、花字、运镜围绕素材展开。请先实际观看代表素材，交付整片视觉导演基准。说明各场的主要素材、希望观众看见的变化、前后场接点和仍待研究的问题。等创意和视觉作者用实料试过后，再对着同版导演稿逐场判断是否成立，并指明整片实际采用的创意与机制分别落在哪里。”
- 文案作者：必须加载现有 `narration-writing`，按[文案状态](../../narration-writing/SKILL.md#按用户提供的文案状态工作)起稿、补稿或接续完整原文。
- 真正分派后，在现有 `update_production_run` 中如实登记文案职责 `narration`、`skill_ids` 中的 `narration-writing`；素材作者使用 `asset_sourcing`。分派记录是来源声明，不代替宿主执行或实际加载技能。
- 素材作者：visual-asset-sourcing，围绕主题广搜并交实际可剪素材，按创意及视觉的具体角色补搜。
#### 给创意作者

本次为普通完整解说新片，正式主创意模式为 full_reference。

请读取完整文案、主导演整片视觉导演基准和全片真实素材。

先完成 R40 案例研究，再从整片视觉组织出发开展创意检索。

不要从单句旁白或局部动作直接开始正式检索。

研究整片视觉语言、主要场面的完整组织和需要补充的局部运动。

使用 creative-case-library 检索并亲自观看候选原片。

自主选择完整参考，完成原片完整视觉表现分析及本片迁移。

创意参考与动效机制可以组合，但局部机制不得代替完整主参考。

交付整片视觉研究、完整参考迁移稿、真实素材映射、必须保留的视觉表现和场间接续。

完整参考须实际改变素材组织和画面发展，局部动作仅作为辅助。


#### 给视觉作者

首轮阅读整片文案、主导演视觉基准和全片真实素材。

先研究整片组织，再完成场间和场内编排。

首次研究必须完成 R40 和《机票退改》教学；涉及真实素材与机制组合时，必须对照 0.1.92 案例。

收到创意作者同版完整迁移稿后，亲自观看相同参考原片及本片对应源段。

完成同状态对照和连续过程对照。

在同一份视觉导演稿中落实整幅构图、美术、素材主次、花字、背景、镜头、运动和节奏。

保留创意作者已经确认的关键视觉表现，不得静默删减。

将必须兑现的关系、可深化参数和须回提的改动写入 OD 完整请求。

正式首版使用真实旁白。


### 选片后按场续接与交稿

#### 完整参考迁移与局部机制续接

普通完整新片的正式创意交件统一使用 full_reference。

主任务将创意作者冻结的完整迁移稿、原片定位、实际素材和研究决定交给同一位视觉作者。

局部机制作为同一完整创意单元的辅助研究记录和视觉映射，不得将单元主模式改为 local_mechanism。

只有独立动效机制专项任务才使用 local_mechanism 作为独立任务模式。

缺少完整参考或完整迁移稿时，退回原创意作者继续研究，不得进入正式视觉采用。

全片正式采用前核对真实声音时钟和制作范围。写入、组包、修订与恢复按 [写入与恢复](project-writes.md) 办理。


#### 逐场接件与指令交付

按本次时间计划中的预定场面和主要视觉单元，逐个读回 `read_production_status` 的 `unitHandoffs`。核对每个单元当前固定稿和视觉接收回执、可打开的原帧标注和同版对照、以及视觉作者 OD 正文中的对应制作步骤和覆盖范围。缺项按上文续接原负责人。用户要求停在 OD 指令时，在以上交件齐备后交付，停在 `prepare_motion_handoff` 和 OD 委托之前。继续整片制作时，完成以下正式制作准备与导演采用。

### 持续接回与交叉传递

任意作者返回当前成果或新发现时，主任务及时接回真实文件、决策 ID、来源、版本和未完成项，并传给需要使用的原负责人。

- 素材作者交本场代表素材及其实际观察，同时给创意、视觉和导演。视频附源段，静图附取景。补创意素材缺口时先交原创意作者补稿，并向视觉作者同步。
- 视觉作者的原片、采用范围、完整研究和正式研究决策交给主导演。
- 视觉作者的素材观察、画面机会和补材缺口交给素材作者和主导演。
- 文案作者把段落骨架、当前正文、锁定项和声画说明交主导演；根据内容影响同步素材、创意和视觉作者，确保各方使用同一当前稿版本。
- 新稿或授权改稿由主任务沿现有 `apply_authored_script` 写入完整正文，随后用 `read_script` 和 `read_impact_report` 读回新 Revision、当前稿和受影响范围；原声语义剪辑仍沿现有文稿操作。用户锁定正文时只核查并交回建议，不擅自改写。
- 主任务用现有 `record_creative_decision` 记录文案作者的稿件状态、声画说明和修改影响；新增内容有研究依据时一并记录，填写文案作者的 `assignment_id`、实际 `input_revision` 和 `evidence`；这些记录属于当前项目的制作报告并指向对应 Revision，不是假装另建文案数据库。通过 `read_skill_execution_report` 读回后，连同当前稿和版本交给导演及受影响的素材、创意、视觉作者。
- 文案变化交主导演及受影响的素材、创意和视觉作者；文案作者负责合并并交回当前完整正文。

专项补查作者与视觉作者直接双向协作；素材作者与视觉作者直接双向协作。主导演持续接收各职责结果并协调整片方向。主任务负责真实分派、结果接回和正式操作，不代替专业作者进行创作判断。

### 共同编排

创意作者借原片核对采用的完整画面单元和必要上下文。记录所选关系的依据和未核细节。需要精确复现连续运动、节奏或声音时，按该问题补看相应原片。

本场研究分批回到同一导演稿。按[共用交接](../../_shared/SCENE_DESIGN_HANDOFF.md#正式创意交接)补实料、关键中途和跨场接点。用 read_production_status 读回逐单元交件、范围及负责人，已齐场面可冻结，整片齐备后用 whole_film 派发同一首版。

### 主导演持续协调与采用

主任务按[早期叙事记录与正式画面采用](../../production-director/SKILL.md#早期叙事记录与正式画面采用)登记，使用同一份视觉作者确认的交件。

视觉作者完成当前目标的导演稿后，主任务先准备交付清单，再登记引用该清单的 `visual_design` 候选。修订说明画面变化和前后接续。主导演对着同版导演稿核看实料怎样承担各场主要画面，并确认各单元的完整参考和实际采用的辅助机制落在哪个场段，随后确认文案、制作范围与成片规格。主任务将 `adoption` 关联该设计与同一清单，再一次写入相关计划，成功后切换制作依据。

主导演不代替视觉作者决定构图、美术、排印和运动参数。

### 视觉派发与制作准备

视觉作者交回导演稿、时间计划、真实素材与源段、采用的研究决定和参考映射、OD 可深化范围、待补问题。新片在首版交件后取得首个真实作品 ID。已有作品的重构或续修另传原 Work、冻结版和目标根帧。

主任务接回当前视觉稿和版本，调用现有 prepare_motion_handoff 完成正式资料核验，再交主导演采用并关联清单。

当前目标范围必须通过现有制作协作准入检查。未就绪场面可以继续探索；已就绪且不依赖缺口的范围可以继续推进。

### OD 派发

视觉作者负责解释方案。主任务交付核验过的文件，按当前 ProductionRun、目标范围和稳定幂等键正式提交 OD。OD 制作首版，代表性连续范围可先阶段交件。所有场面沿同一作品总时钟。登记真实 Work 后，后续交件、跨场续作和返修接回同一作品。已运行委托先读回原请求。

### OD 返回后重新进入同一协作循环（与首轮创作共用）

OD 每次返回当前作品后，主任务将同版工作台入口、Revision、Work、Run、Frozen Version 和实际范围交给原视觉作者，并同步主导演、文案作者及受影响的素材作者。文案作者检查当前正文与实际声画表现是否仍匹配；只有发现文案问题且处于用户授权范围内时才修订，不为配合画面而擅自改变锁定原文。首轮创作与后续返修使用相同的职责、结果接回和问题回流方式。

- 视觉作者作为 OD 的主要专业对接人，检查素材组织、构图、美术、排版、镜头和运动，判断视觉方案本身是否成立；需要 OD 修改实现时，整理具体范围、当前表现、目标表现和必须保持的关系，并向 OD 提出反馈。
- 视觉作者对照原始参考检查创意迁移，发现偏差时记录原片过程、当前作品差异及应保留的核心关系，确定修改。
- 素材作者在发现素材不足、身份错误或源范围不合适时，按视觉作者提出的缺口继续搜索、核实和补充。
- 文案作者在内容、事实或讲述需要变化时，按主导演协调的范围修订当前稿。
- 主导演核对文案、制作范围和成片规格，原视觉作者复核全片画面与场间接续。
- 主任务负责正式反馈投递、Job/Run/Revision/Frozen Version 对账和结果接回。
- OD 根据视觉作者确认的制作反馈，沿原委托和同一 MotionWork 修复实现问题，并返回新的可检查版本。

设计偏弱时，视觉与相关作者共同调整当前稿，涉及文案或制作范围时交主导演协调。正式采用的关系、资料或时序有实质变化时，重备受影响范围并更新 adoption。

如果视觉方案本身成立，只是 OD 没有准确实现，视觉作者直接提出实现反馈，主任务投递给原 OD 委托，OD 沿原作品返修，视觉作者复核。此类实现返修不重复执行完整创意研究和导演 adoption。

互不依赖的问题允许并行处理。所有修改沿原负责人、当前作品、现有 Run/Work/Frozen Version/Revision 续接，不创建平行工程。

### 视觉派发与接回的完成口径

完整视觉制作输入必须包含：

- 准确文案及用户要求。
- 选定参考及实际原片范围。
- 参考完整画面表现和实际观察方式。
- 本片真实素材和 Asset ID。
- 素材映射与使用目的。
- 从入口到出口的连续画面编排、本片目标区间，以及首版后要检验的关键关系。
- 已确定的主要关系、OD 可深化范围和未完成设计。
- 声音和时间资料。
- 当前前后场面关系。
- 未解决问题及锁定项。

视觉作者负责完整简报和制作请求。主任务负责实际文件交付、项目身份、版本、目标和正式提交。

OD 返回同版作品、源码、资源与实际范围后，交回原视觉作者分别检查创意、机制与美术视觉并反馈，主导演核对文案、制作范围与成片规格。采用的制作输入包含完整编排、实际素材和参考原段。

## 让材料与预览回到当前完整稿

完整解释按[主题工作流](../../_shared/TOPIC_TO_FILM.md)使用真实材料并推进连续范围；人物和 Vlog 保持各自业务路线。素材无需逐句表，首批真实文件及时接回当前稿，不把例文阅读作为取材前置。

有价值候选在授权内及时取得，主任务提交获取与正式写入并返回真实结果。查询与只读发现按自身会话并行，不进入无关的创作Revision写入队列；代执行查询时完整传回原素材作者，不替它改词或截掉其他方向。正式写入继续按当前合同协调，未知下载或生成结果读原Job。

已有采用与范围直接承接，文件就绪后沿现有绑定使用，不建立资格审阅。改稿、换词不清空候选，不取消独立在途下载。一份文件成功不代表主要画面已充分；停用一份候选与取消整项材料路线分开，未完成用途继续续接。原负责人返回材料推荐，导演决定主要采用与编排。

按导演确定的范围续接原视觉负责人，沿[整场视觉入口](../../visual-treatment-planning/SKILL.md)交导演稿和资源映射。普通字幕由统一层处理。主次、空间或布局的实际效果在 OD 首次交件后检查。若设计本身偏弱，视觉作者可重选构图与运动，主任务按实际变化更新受影响的依据。

事实研究与普通取材无需查机制。完整新制或主要视觉重做时，原视觉作者必须主动按[机制检索与组合](../../motion-case-library/references/mechanism-retrieval.md)检索并观察整片、连续镜头和多个适用机制，完成对象适配；已有有效观察可共享。传供学习及已采用的材料和真实工具状态，不为每个机制创建代理，不把几组候选视为已经完成组合。

首版与后续固定版的观察沿[共同交接](../../_shared/PROJECT_REVISION_AND_HANDOFF.md)和[专业返修方法](../../quality-verification/references/professional-review.md#根因而不是症状)执行。锁定内容随稿传递，构图和动作可据真实成片修订，跨段影响由导演协调。

## 名额不足时续接与接替

分派前用 `list_agents` 核对实际列表和上限是否包含主任务。`completed` 不证明名额释放；`interrupt_agent` 不用来清理名额。宿主没有关闭能力时，不编造调用或调整全局上限。

原负责人仍在列表且空闲时用 `followup_task` 续接；正在工作时等待该项依赖，不再创建重复负责人。原负责人不存在时，有空位才尝试恢复。列表未满仍被拒绝，保留调用前后列表、上限说明和原始错误，不自行推断计数泄漏或反复重试。

名额已满时优先由现有、职责合适且已结束当前工作的代理接替；合适作者都忙就只等待这一项依赖。按[接替与结果接收](#负责人接替与结果接收)确认新负责人、版本与完整材料后接续；旧负责人迟到结果不直接提交。恢复失败先诊断，不能回退为主任务创作。完整解说新片保留创意与视觉两个独立代理身份，名额不足时按现有接替流程续接其他已经空闲且合适的作者，等待中的范围保持待补。

## 工具或观察材料不足

首次分派和续接后，作者检查本轮实际工具表，区分工具不可见、Schema不匹配、调用失败和材料不足。主任务记录实际工具缺口，必要时用自身可用的正式只读 MCP 补事实；专业判断仍由原代理或确认接任者完成。主任务转交 Schema 不等于子代理工具可调用，主任务成功交接、子代理直接 MCP 访问恢复是两个结论。

需要观看的预览、帧或音频必须由接收者实际打开。请求应说明对象、版本、范围和缺失项；输入变化带差异回传，不能只更换版本数字。缺连续画面或声音只保留相应待审范围，不把静帧当连续观看，也不因辅助审片未完成阻止其它制作或技术条件满足的导出。素材审阅分流查[审阅诊断](../../visual-asset-sourcing/references/acquisition-operations.md#审阅与诊断分流)，故障与未知结果查[写入恢复](project-writes.md#失败与不确定结果)。

## 负责人接替与结果接收

每个工作范围在主任务交接记录中只保留一个当前负责人，复用现有 assignmentId、agentId、inputRevision，不新增项目调度对象或视频 Revision。接替时记录旧分派与接替原因，为接任者分配新的 assignmentId 并使用宿主返回的真实 agentId；将用户约束、原稿/源码/参数、已提交对象与版本、最新预览及范围、未完成事项一起传递。接任者先确认输入版本与范围，明确接受或列出缺失请求；交接未确认不算该范围已经恢复。

建项后按实际范围启动 ProductionRun。每次真实分派后用 `update_production_run` 登记职责及可续接的 agentId；assignmentId 由协调者为该次实际派发生成。同一作者兼任时写明全部承担的职责。创意和机制研究分别接回结论，视觉结果引用实际接收的研究决定，导演采用引用视觉结果与交付清单。记录不代替实际宿主调用和作者观察。

接回任一阶段结果后读取 `read_production_status`，将当前范围的缺项、实际资料和版本交原负责人续接；尚无场面或资料时继续并行探索。旧输入的结果先核对影响，采用决定始终引用当前视觉方案。作品返回后，逐条参考的实际观察填写 `reference_reviews` 及各自结论；必修问题按返回的 Finding ID 和负责人续办，未观察部分按实际范围保持待处理。

接任后，主任务核对回复中的 assignmentId、实际发送代理、inputRevision 与当前负责人记录。旧负责人迟到回复不自动成为待提交命令，保留为历史材料；仍有用的内容交当前负责人重新判断。当前负责人基于旧输入返回的结果也须对照真实变化确认后才能提交。尚未取得宿主真实返回标识或尚无 Project 时，仅对应的缺失字段保持未建立，不能为了记录而编造。

## 事实交接与能力核验

本节只在工具或输入缺口、接任与版本变化时使用，按当前范围补足，不让普通局部任务携带全量项目状态。核对工具不可见、Schema 不匹配、调用失败、结果已返回但材料不足这几种情况；主任务提供读取工具、读取时的 Project/Revision 及原始结果引用，不能只说自行读取项目。

缺版本时补对象与源/成片范围；缺执行事实时补原方案、完整源码/Props/参数及 Job 状态；缺媒体时给实际可访问路径、版本与范围；缺接口时提供相关实时 MCP Schema。输入不存在就明确未知，不补造。

子代理按委派范围使用实际可用能力。视觉作者编写制作请求并组织返修，OD 编写源码，工作台操作者在授权控件中保存调整与实际观察。主任务排序正式提交、对账和接回。工具缺口按原合同处理，实际调用与专业判断的归属按真实记录填写。主任务可用正式 MCP 补事实，但这不证明子代理工具已恢复；专业判断与实际观察仍由原作者或确认接任者完成。新读取发现版本变化，交实际差异并由接收者确认，不只替换包内版本号。主任务也缺能力时保留该项待处理，继续无依赖工作。

## 等待与无进展恢复

平台 Job 用 `track_jobs` 快速批量读取状态、执行尝试和实际进展；不要靠频繁逐项轮询或长调用占住 MCP 操作锁。续租/连接心跳只证明连接活动，不证明新增产物。宿主作者与审阅者用宿主真实状态核对，平台审计字段不代表代理存活。

每完成一个可交接范围就保存实际观察、问题和版本，不等整轮结束。长时间没有新增结果时，主任务核对原 Job/Run 是否仍运行、宿主是否正在工具调用或连接异常，并请求当前部分产物与剩余范围。确认原执行无法推进才按现有接替流程续接剩余部分；真实工作仍在进行则等待该依赖并继续独立工作，不按固定超时盲目重跑。

## 按本次范围收口

根据本次用户要求明确 `completion_scope`，整片使用 project，指定内容使用 beats，局部对象使用 objects，明确的时间区间使用 frames（`start_frame` 包含、`end_frame` 不包含）。独立工作台审阅自动按实际观察区间建立 review_only 任务。

主任务调用 `read_production_status`，传入本次 `run_id` 和 `completion_scope`，读取实际评估版本、结构缺项、待观察范围及未解决问题。缺计划交导演，缺材料交素材作者，缺实现交原视觉或制作作者，待观察范围由对应负责人进入工作台检查。

修改结果进入新版后，负责人在工作台复查实际影响范围及必要接点，并保存结果。已有观察的可用范围依据状态接口返回的依赖判断继续承接。

完整制作需要最终文件验收时，开始 Run 时设置 `delivery_review_required=true`。导出后使用 `update_production_run` 的 `select_delivery_artifact` 选择当前交付文件，返修后选择新文件。

主任务调用 `complete_production_run`，明确本次 Run、范围及 `final_revision`。返回 incomplete 时读取 `evaluation.nextActions`，将具体文件、范围、问题和关闭条件交给对应原负责人，实际续派并接回证据或修订后，使用新操作编号重新完成同一 Run。提交结果未知时先沿原操作编号重试。参考迁移由原创意或机制作者与视觉作者复核，声音和视觉问题交原负责人。返回 completed 后读回同一 Run 的完成版本、范围、指定交付文件及当前评估，再据此交付。用户仅要求导出现有版本时，按导出任务范围执行。

原视觉作者的 OpenDesign 制作权限及正式写入责任以[共同交接](../../_shared/PROJECT_REVISION_AND_HANDOFF.md)为准。
