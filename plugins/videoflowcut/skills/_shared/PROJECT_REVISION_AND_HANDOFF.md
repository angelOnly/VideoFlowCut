# 项目、版本与角色交接

本页维护共用边界。正常任务只传当前范围所需的完整稿、材料与事实；负责人接任、工具缺失和项目恢复发生时，再进入末尾对应操作。这里的交接不是新增 Project 对象或用户表单。

## 代理角色与交接

主任务先读 project-basics 与 production-coordinator，负责沟通、项目事实、真实分派、正式提交和交付。

导演负责组织文案、素材和参考共同形成视频，判断材料是否支撑主要画面，确定整片采用与前后关系，并组织实际作品中的补材和重新编排。首次主要编排、主要场面重选及影响整片表达的返修，沿主导演技能接回采用决定。

创意负责人负责观看目标、参考选择和实际创意效果。视觉负责人亲自查看参考与素材，与创意负责人共同编排，汇总制作简报和完整请求，并持续检查作品与组织返修。

视觉作者交导演稿、实际素材映射和时间计划，负责向 OD 解释设计和检查返回的画面。OD 根据这些资料制作第一版可播放作品，负责源码、绑定、根时钟和同作品返修。

其他专项负责各自范围，审片作者检查可验证问题。

主任务用宿主 spawn_agent 真实分派，以 followup_task 续接原负责人；已授权子代理按需读取相关 Skills 并直接创作，不递归分派，不为案例资料新增代理。主任务统一安排正式操作的范围和顺序。受委派负责人可以通过工作台已有持久化控件完成明确范围的修改，并保存自己实际执行的观察、问题和复查结果。素材登记、生成或渲染 Job、制作采用和生产收口由主任务提交。

每次委派写清专业职责、Skill、范围和交回对象；主任务使用宿主返回的 agentId，自行生成此次真实派发的 assignmentId，并保存实际 inputRevision。建项前探索的版本可为空；建项后交付真实项目版本。相同代理可在一项分派中兼任多个职责。接回时核对实际发送者和当前负责人，审计字段只保存来源声明。

一次交接围绕这次要完成的工作：

- 进入时给范围与验收目的、用户约束、当前完整稿/实现、相关材料和前后接口；涉及正式对象时带真实 Project、inputRevision、对象与源/成片范围。

每次分派、续接、接替和恢复均需传递：整片主类型、当前负责范围及其有效子路线、人物／声音来源、用户锁定项、正文改写权限、当前准确稿和真实 Project／Revision／对象引用。只有人物范围才携带人物可见、口型和 Mask 相关要求；其他路线不填虚构人物信息。上下游冲突交协调者核对，不由子代理重新分类或自行更换说话人。
- 返回可直接继续的完整产物和准确参数，说明实际观察、未知、修改影响及需补的素材或 Preview。简单局部任务不复制全量 Story、Timeline、所有 Job 或无关质量报告。
- 已有 assignmentId、agentId 与版本引用用于追溯，不另建第二套项目状态；尚无 Project 或对象时明确未建立，不填虚构 ID。

主任务保存真实分派、核对实际版本、登记正式对象。缺参考依据找原研究负责人，缺场面设计找视觉作者，缺制作实现找 OD，缺素材或事实找对应作者。主任务把具体问题、受影响范围和下一步交回负责人，接回实际结果。

## 一份当前稿，按影响协调

导演、文案、素材、创意和视觉共同发展同一份当前稿。按[主题到成片](TOPIC_TO_FILM.md)并行交叉传递发现，复杂场面用[场面正文](SCENE_DESIGN_HANDOFF.md)组织交接。

视觉作者交导演稿、时间计划、实际素材、采用参考及其关系。主任务准备清单，主导演确定本次采用，主任务登记并正式提交 OD。首版前没有作品 ID 或实际效果结论。

收到真实阶段回执后，创意与机制原负责人对照采用的关系，视觉作者检查真实素材和设计兑现，导演检查内容与跨场发展。实际观察绑定本次采用、来源及目标区间。专业反馈经主任务投递给原 OD。

### 写清锁定依据和当前创作选择

交接中的用户锁定项应能对应到用户明确要求，事实条件应能对应到准确内容与来源，技术条件应说明适用范围。

团队自行提出的场景、形象、布局、镜头顺序和运动安排写入当前编排，继续依据实际素材、参考和作品调整。定向返修需要保护已经成立的部分时，明确对应范围及保护理由；反馈表明该部分也需要调整时，由原负责人重新判断并更新当前稿。

取景、排版、路径、曲线和局部时机由视觉与制作作者继续完成。主要内容、场面采用或跨段关系变化时，交导演协调。

具体美术和动作细节随同一作品继续完善。作者交回源码、绑定和参数后，主任务沿正式链路取得实际结果，交原作者查看、修订并接回。主要内容、事实含义、讲述顺序或跨段关系改变时由导演协调，用户明确锁定项继续有效。

当前全文保存在已有消息、附件和 CreativeDecision 引用，正文版本、Project Revision、固定作品和 Preview 身份分清。creativeBrief 按当前合同保存提交说明，全文不静默截断；接口表达不了时保留产物和具体缺口，不擅造字段。

## 一个项目事实源与修改反馈

正式 Project Revision 是视频工程事实源。对话、loadedSkills、SkillExecutionReport、浏览器选中状态、临时 JSON 或 ProductionRun 报告不能替代真实 Story、Scene、Timeline 和已完成操作。完整创作正文解释设计，但不另造一份可编辑时间线。

主任务排序正式写入并明确委托执行范围。阶段画面使用 `start_motion_authoring` 绑定目标，由连接器接收同一 Run 的冻结版、核对依赖并采用已完成范围，工作台读取回执中的固定 Revision；同目标采用排序，其他无冲突工作继续。反馈关联 Run、冻结版本、范围和反馈 ID；接收、作者处理与实际复查分别记录。结果未知先读原 Job／Run，不能只换 base_revision_id 重发旧产物；回执不代替实际观察。其他已发布的确定性接续沿原合同执行。

同一范围的问题由主任务合并同版同问题的观察后交一位当前负责人；事实、主线和跨段取舍交导演，画面实现交原视觉作者，声音交声音作者。各方可共用同版预览和截图，但仍要实际独立观察需要自己判断的内容。简单局部任务只传相关权威文件、真实对象及版本、影响范围和锁定项，不复制无关全文或重复制作资料。

实际对象与可访问的 Preview 回原作者。技术核验归主任务，表达、节奏、自然度与审美归子代理；跨段分歧交导演，最终专业审片交审片作者。播放器已启动、文件存在或文字报告都不证明连续观看和听审。

## 工作台预览、修改与复查

完整新制使用一部连续作品。导演稿采用后交 OD 制作首版。第一段可查画面进入当前项目后，主任务将工作台入口、Project、Revision、Work、Cue、成片范围，以及对应的 OD Run、冻结版本和根帧交回原负责人。续作从该作品继续，局部修改直接定位已有目标。

负责人打开对应版本，按可用范围播放，结合已合成的字幕、声音和前后接点复核。静音画面只作视觉观察，已取得同期声音的范围才能作声画判断。其他无依赖工作可并行。

日常观察使用工作台的范围播放和循环播放。文件交接、离线检查或渲染差异诊断需要预览文件时，按具体用途生成。抽帧用于定位对应时刻的静态问题。

同版同范围的问题合并交给当前负责人。已有控件支持的调整在工作台保存，作品内部构图和动画交原视觉及制作作者沿同一作品修订。新版接回后，在工作台复查修改范围及必要接点，实际确认后关闭对应问题。

当前操作者将观察方式、实际范围、发现的问题和复查结果保存到本次制作记录，并交回主任务。已有观察对新版的适用范围以应用层返回的依赖核验结果为准。操作方法读取 `web-editor-operator`，异常处理沿现有项目写入与恢复规则。

## OD 首版、续作与返修的版本连续性

视觉作者持续负责同一范围的设计、交接与复查。第一次制作使用真实目标、当前导演采用及清单创建 OD 委托。第一次登记时记录真实 Work、Run、冻结版和根时钟。之后每次续作沿既有作品。反馈指向所看固定版及受影响的根帧，关闭问题须有修订版的实际观察。

OD 阶段交付后，原视觉作者继续检查同版实际作品。实现遗漏由原制作作者修复；设计本身偏弱由视觉作者重新设计；内容、事实或跨段关系变化由导演协调。

不得因阶段交付、负责人续接或返修而创建平行的视觉版本事实源。所有正式项目写入和采用继续由主任务按现有合同排序。

## 技术检查、辅助审阅与人工定稿

技术检查验证文件、引用、版本、范围和渲染，失败只阻挡相关操作。AI 审阅记录疑似错字、遮挡、节奏、声音与表达问题；未审、failed、inconclusive 和待复核结论保留真实范围与严重度，不伪造 passed，也不单独成为所有制作和导出的前置条件。没有感知能力只暂停相应审阅，其他已授权制作继续。

试听、观看、候选比较与专业采用均为 Codex 内部职责，不是用户参与的审批步骤。原生感知不可用时，先按[证据状态](../quality-verification/references/evidence-status.md)使用当前可用的媒体分析能力；仍无法判断的范围如实保留未知，由导演依据已有证据决定可执行的后续工作，不要求用户代听、代看或确认识别结果。转写与实际声音有疑似差异时继续核对原稿、音频和辅助观察，不仅凭识别结果改写台词或重配。

专业判断由实际负责该范围的导演和专项作者完成。ProductionRun completed 表示本次制作范围的结构、必要工作台观察、必修问题处理及结果版复查已经完成。Export Job succeeded 表示文件生成并通过技术校验。draft 与 delivery 表示文件用途，用户对具体文件的认可依据其明确意见记录。制作收口由主任务按 `production-coordinator` 的本次范围收口步骤执行。

人工定稿只在用户主动明确认可指定文件时记录，以 approve_export_artifact 关联 Artifact、file_hash 与 confirmed_by_user=true；不是制作或交付的必经步骤，不主动索要确认，也不等待用户反馈才结束已完成的制作。沉默、全权剪辑授权、技术成功和 AI 结论不是用户对具体文件的认可；用户反馈或改版后，旧结论不自动覆盖新文件。

## 遇到特殊情况再读取

| 当前情况 | 进入位置 |
|---|---|
| 新会话恢复、Revision 冲突、Job 失败或结果未知 | [项目写入与恢复](../production-coordinator/references/project-writes.md)，按当前状态补读相关项目事实 |
| 原负责人不可续接、名额不足或接任 | [负责人接替](../production-coordinator/references/task-routing.md#负责人接替与结果接收)，交全文、实际版本、媒体和剩余事项 |
| 子代理工具不可见或观察材料不足 | [能力与事实交接](../production-coordinator/references/task-routing.md#事实交接与能力核验)，区分补事实与能力恢复 |
| 浏览器跨回合续看、标签或入口失效 | [浏览器交接](../web-editor-operator/SKILL.md#浏览器审阅跨回合交接)，按本轮宿主能力重新绑定 |
| 原素材只返回部分证据 | [审阅诊断](../visual-asset-sourcing/references/acquisition-operations.md#审阅与诊断分流)，区分有效证据、缺口与故障 |

主任务先诊断并执行已授权恢复，只有确认平台或服务自身 Bug 阻断任务才进入 Repair Ticket；不把缺素材、暂时未就绪或原因未知自动报成 Bug，不静默退回主线程创作。短版、多画幅等是交付版本，不能靠覆盖长版或回退 Revision 冒充；需要时核对真实已发布的版本能力。

视觉负责人汇总创意与素材发现，交同一份导演稿、时间计划、可直接发送的完整请求和资源用途。主任务按当前正式权限创建或复用目标 OD 项目、送交实际文件、登记导演采用并接回结果。导演与视觉需要调整时续接原作者。

主任务用 `prepare_motion_handoff` 固定本次共同简报、时间、资料及选中场面；将实际文件交付制作端，导演判断后以 `record_creative_decision.delivery_ref` 记录清单路径、哈希和场面。用 `manage_visual_treatment.adopted_decision_ref` 关联当前采用，再以 `start_motion_authoring.visual_treatment_ids`、完整请求、真实目标和版本提交。连接器核验制作端实际文件并接回同版阶段作品。资料或采用变化时更新受影响范围并沿原负责人续修。

导演持续判断实际作品的材料组织与整片发展。视觉负责人与创意负责人对照参考检查，并组织同一制作作者返修。主任务接回修订版本，交原作者复看对应范围。

VFC 正式操作的执行权限与排序遵循本文件“代理角色与交接”的约定。主任务接回工作台修改和实际观察结果，继续负责制作采用、任务续接及生产收口。实际工具不可见时，由主任务处理能力缺口。
