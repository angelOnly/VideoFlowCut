# 按当前内容检索 Skillry 案例

从当前项目根目录读取 `references/motion-cases/skillry/case-catalogue.json`，不要相对本Skill或插件安装位置推算。所有索引内文件路径相对索引目录解析，不依赖服务是否启动。索引含分类、用途、推荐秒段、文件入口与媒体来源；完整拆解、来源说明及公开输入都在各例analysis.md中。每例仅有video.mp4和analysis.md。当前项目未包含此库时说明资料缺失，不从其他项目猜测路径。

## 先找材料和观看任务

在项目根目录运行共用检索入口；网页执行同一个 search.mjs，不维护第二套筛选规则：

```powershell
node references/motion-cases/skillry/tools/search-cases.mjs --query "手机 照片" --materials "手机界面" --limit 5
node references/motion-cases/skillry/tools/search-cases.mjs --video_types "新闻解读" --scenes "多来源对照" --limit 5
node references/motion-cases/skillry/tools/search-cases.mjs --query "071" --limit 1
```

支持 `--original_form`、`--video_types`、`--scenes`、`--materials`、`--methods`、`--art`。前四类精确匹配，方法与美术按短词包含匹配（如“遮挡”“纸”）；多个条件同时满足；query 用空格组合关键词并展开小型同义词表。若需多种可选材料，分别查询后比较，不把互斥材料全部强加在同一检索条件中。先用少量关键名词和动作，再读结果做语义判断；它是透明的关键词检索，没有自然语言推理或向量召回。

例如商品详情从手机页面抽出，可找043的14–19秒；文章观点接入关系图可找051的7–12秒，但不能声称它含新闻人物现场素材；宏观与微观解释可查071。返回是否合适仍以实际索引、原片和拆解为准。

## 阅读入围资料再推荐

先读入围结果的 `analysis`，其中包含拆解、观看范围、后写实现建议与作者公开输入，再按 `media` 查看参考视频。研究过程附件已经归档，不作为日常检索依赖。查看视频时遵守当前视频工作流的实际审阅能力；缺少原速或声音证据不能靠报告补成已通过。

每个候选说明：适合本段解决什么问题；借鉴的原片秒段和过程；用户的材料如何对应；需要补齐什么素材/图层；有哪些阅读量、空间、视角或时长方面的迁移代价。预览可给命令结果的 preview_url 加 `#t=起始秒`，服务未运行时给实际本地路径并参考库内使用说明启动。

通常返回3–5例。没有直接匹配时，先报告当前筛选缺口，再明确放宽哪一项，单列可迁移候选。新闻解读用途、摄影外观、照片、三维角色与真实新闻现场是不同概念。材料要求和迁移代价不参与原片实见分类。

## 采用之后

用户已认可的整片共同参考持续参与构思；局部参考只解决对应段落的问题。把采用编号、源秒段与理由写进当前设计交接，结合本片内容重新写执行稿。来源研究与实际制作分别记录：本库未确认120条原片的固定对应源码，后写复现输入也未渲染验证。

索引缺失或媒体缺失时如实说明并检查仓库是否完整拉取；不得生成虚假的媒体路径和已看结论。视频与合并拆解均随Git传递，采样图片、观察日志及研究暂存稿不在正式参考库中。第001条保存兼容播放版，其余为原片，索引的media_sha256记录实际交付视频哈希，source_sha256记录原片哈希。
