# 连续动效源码案例

本 Skill 提供可运行的 Remotion 案例及设计推理。主要工作流仍由 `production-director` 选择，作品生产仍由 `remotion-production` 负责。不要每次制作都加载全部案例，也不要用案例名代替对当前内容的判断。

需要借鉴构图、对象延续、局部时序或改写方法时，读 [案例方法](references/case-methods.md)，再只打开与当前观众任务相关的一份 `assets/cases/*.tsx` 和同名 `*.fixture.json`。需要核对本轮真实原片观察与可迁移机制时，读 [已观察机制](references/observed-mechanisms.md)；需要了解“浏览四站 → 观察 → 设计 → 源码 → 复检与集成”怎样写进 Skill 时，读 [四站教学示范](references/four-source-worked-example.md)。配套 MP4 用于观看源码实际运动；文档和漂亮单帧都不能代替连续预览。

先确定画面要让观众理解什么，再找贯穿几个语义拍的稳定对象与共同坐标。设计可读的停稳构图，随后用进入、状态改变和退出建立它；阅读和思考时可以完全静止。中文的主次、分行、条件、单位与留白必须在目标显示尺寸成立。案例中的揭示、复制、换算、流量只是候选机制，不能推广成固定镜头顺序、统一卡片模板或每句一次转场。

案例使用竖版画布，分别示范全屏解释与为人物留出空间的构图。用于数字人或真人同屏时，先检查真实脸部、手势和字幕占用，再重新排版；全屏讲解接管画布时安排人物离开和返回。没有已就绪、已验证的 Mask 就不承诺人物前后穿插，案例也没有补充这项平台能力。时长、字体或画幅变化后重新审阅，不能把样例的帧数和边距当通用安全区。

本地源码和 fixture 是设计学习材料，不是合法在线参考凭据。当前 `submit_motion_work` 仍要求四站范围内的 `reference.url`、五类真实观察和权利依据。投产时由代理主动选择并实际查看相关参考，无须要求用户每次提供样片；不得把本地路径、虚构网址、只浏览过的目录或未看懂的预览填写为已观察参考。当前没有免在线参考的“本地原创”提交通道，解除这一约束属于后续平台改造，本 Skill 不实现它。

## 交接合同

改写结果交回 `remotion-production`，附上内容与机制取舍、Props 和局部动作帧、拟放置范围、人物/字幕处理、素材与权利、已看过的预览证据及剩余问题。它继续负责受管版本、Cue、Impact 与合成审片；本地渲染成功不表示已进入正式项目。美感需要在连续播放中判断构图、语义匹配、运动节奏、稳定停留、边界交接与整片重复，并在目标 Revision 的成片 QA 中确认。
