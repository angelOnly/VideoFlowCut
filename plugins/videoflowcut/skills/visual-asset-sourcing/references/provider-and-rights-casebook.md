# 素材搜索、证据、权利与降级案例库

## 案例一：抽象“自由”

旁白讨论的是“时间是否属于自己”。如果直接搜索 freedom、ocean、road，候选很漂亮，却把具体社会和时间机制变成泛化励志。正确 AssetRequest 先说明当前需要的是机制解释还是情绪呼吸。机制优先 Remotion：日历和“以后”不断后移；只有在高密度解释后需要现实恢复时，才搜索下班后散步、抬头看天空等具体动作。

拒绝理由也应记录：海边候选不是质量差，而是叙事功能不匹配。

## 案例二：官方规则证据

旁白说“平台会收取 30%”。不能搜索一张写有“30%”的图片，也不能生成假网页。AssetRequest 指定证据型：官方帮助页或条款，保存页面标题、URL、机构、抓取时间和目标段落。Candidate 必须包含完整页面环境，Acquire 后成为 evidence Asset，由 `evidence-visualization` 决定建立—聚焦—高亮。

若官方页无法访问，标记缺口并请求用户资料或替代原始来源，不以二手文章自动代替。

## 案例三：促销产品

产品图应来自用户项目库、官方素材或明确授权。Pexels 的相似平板不能冒充用户实际产品。若用户只需要“平板电脑作为品类示意”，可以使用 Stock，但必须让文案和画面不暗示具体品牌。

## 案例四：Vlog 补地点镜头

用户的旅行素材缺少城市建立镜头。可以搜索公开授权城市空镜，但必须明确这是概括性地点画面，不是用户当时拍摄。若精确城市、季节和时间无法匹配，宁可用地图/标题或用户素材中的广角，而不是插入错误地标。

## 案例五：搜索无结果

“安静黄昏，一个下班后疲惫的人停下来抬头，竖屏上方留白”没有合适 Stock。若它只是情绪与生活经验，可用 MiniMax 生成并标记 generated；若它被用于证明用户真实经历，就不能生成，应保持人物或使用已有真实素材。

## 案例六：许可要求署名

Candidate 标记 attribution_required 后，Acquire 保存作者和许可文本。进入 Delivery 前 AttributionManifest 必须包含该素材。若成片发布渠道没有适合署名位置，主工作流需要换素材或得到用户明确策略，不能把署名要求丢在 Asset Inspector 中。

## 候选比较示例

三个候选都展示“人在城市里走”：

- A：人物大特写、商业摆拍、无天空留白；
- B：中远景、慢速、上方有天空、轻疲惫；
- C：漂亮夜景、人群密集、快速移动。

当前需求是安静恢复并允许字幕，B 最合适。A 的表演感过强，C 的能量和构图错误。这里的选择不是单纯的相似度排序。

## 权利状态处理

- cleared / auto_allowed：按用途可进入；
- attribution_required：需要署名；
- requires_user_confirmation：停止并问明确问题；
- reference_only：只作风格或研究；
- unknown / restricted / blocked：不进入 Delivery。

不同 Provider 的字段可以归一化，但不能因为 API 返回下载链接就自动推断权利。
