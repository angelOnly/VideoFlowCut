# 研究与真实画面的交接示例

> 任务：给普通观众介绍一个网页内的复古桌面。文案作者想知道，外观相似之外，哪些操作能实际完成；导演希望主要使用真实界面，并用图形帮助观察。
>
> 首先查看用户原片和现有观察。如果原片已经包含主题切换与应用输入，就直接核对这两段的前后范围，外部只补作者说明和缺失操作。不要为了“做了素材检索”而重复下载同类画面。
>
> 如需外部发现，事实查询可以从“[实际产品名] 官方 功能 说明”或限定已确认的作者站点开始。打开实际说明正文，辨认明确支持范围、版本及没有解释的部分；搜索摘要里的“完整复刻”暂时不能作为确定台词。
>
> 画面查询从“[实际产品名] 主题切换 完整录屏”或“[实际产品名] theme change walkthrough”开始。如果候选只是宣传剪辑，只有几个漂亮窗口而没有点击到变化的过程，记录具体缺口，改找“[实际产品名] full demo screen recording”。有合适作者时继续查看其同源完整版本，避免用不同版本界面拼成一次操作。
>
> 若得到的是可下载的 YouTube 单条来源，主任务沿现有单 URL Provider 取得候选。其他站点的链接只有在平台发布了相应取得能力时才可沿该能力获取；不能把“搜索到链接”标为“视频已到手”。取得原片后查看实际操作范围。视频只显示计算器窗口打开时，继续找输入和结果；找不到就把拟写的“计算器可以使用”收窄成“可以打开这个窗口”。
>
> 作者说明足以支持具体结论时，读取相关段落的前后文。需要把原文放入成片，再由主任务取得实际页面快照，并登记来源、摘录和范围；只有正文提取文本时，不能画一个自制页面冒充官方截图。
>
> 给作者和导演的回传应包含：“主题切换有连续操作，可以展开这一段；应用只看到窗口，尚不能宣称输入有效；作者说明只承诺部分内置功能，没有承诺完整兼容。建议先跟随主题变化，再核对一个真正有输入响应的应用，最后按说明限定体验范围。”这是一项会改变稿件的发现，不只是一张素材表。
>
> 如果第一轮已经找到足够材料，可以直接采用和细化。候选缺过程时继续沿缺口找，不要求固定三轮搜索。对同一图库查询需要看更多结果时，使用返回的 nextCursor；换产品、动作词或 Provider 后重新开始查询，不沿用上一个查询的游标。
>
> 最终用于剪辑的范围应保留观众认出界面、看到关键动作和确认结果所需内容。设计先让真实界面成为观看主体，再靠近发生变化的区域；指认图形跟随真实对象，必要解释完成后回到原界面结果。不要将每一条材料都缩进相同大小的窗口，也不要裁掉证明操作确实发生的上下文。
