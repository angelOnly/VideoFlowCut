# 弹幕穿行 → 聚合 → 一个重点

[观看选定视频](assets/preview.mp4) · [固定版本源码](assets/motion.tsx) · [参数](assets/fixture.json)

960×540、30 fps、300 帧，10 秒无声案例。props.mode=`comments` 选择 Comments。画面中的“原来如此”“这下看懂了”等为示意弹幕，不是真实用户评价；不能拿这种视觉氛围证明普遍赞同或某种统计结果。

## 先让观众感到讨论，再交给一句重点

前半段有多行声音在共同方向穿过，后半段把这些分散对象向中心区域汇聚，最后由一个红色气泡获得注意。适合“许多人有类似疑惑—我们集中回答这一点”的场景。滚动区负责形成氛围，不负责让观众逐字阅读全部内容；真正要读的句子只在前景中明确出现。

奶油底 `#eee9de` 与深灰文字先保持低刺激，红橙 `#ed482d` 留到重点气泡才使用。前期没有另加标题框，文字本身就是运动对象；后期才用唯一气泡表示归纳。视觉强度由密度、位置与对比变化产生，而不需要每个字各自弹跳。

## 对象与路径怎样生成

24 个文字对象分为六行，文字从八条示意句中取值。row=i%6、col=floor(i/6)，初始横坐标为 `240+col×310+row×27`，随后按 `f×(4+row×0.5)` 向左移动。行速度略有不同，使队形有层次；偏移和字号按索引确定，随机访问一帧仍得到相同文字与位置。

汇聚目标不是一个像素点，而是四列六行的中心区域：x=`100+(i%4)×225`，y=`135+floor(i/4)×51`。当前位置到目标的 mix 由 gather 控制，所以观众能看到散开的文字向一个讨论中心收束。途中存在短暂交叉，不应把聚合中段当作逐字阅读时段。

## 实际时序与注意交接

| 局部帧（30 fps） | 变化 | 观看任务 |
|---|---|---|
| 0–119 | 多行向左穿行，首帧已有文字在画幅内 | 立刻建立讨论氛围，不空等几秒才看到第一条。 |
| 119–210 | gather 收束到中心布局 | 原来的文字对象持续存在，位置变化而非直接替换整页。 |
| 164–220 | 重点气泡显现 | 汇聚还未结束，主重点已经预进入。 |
| 175–229 | 其它文字退淡 | 背景与主重点交棒，避免两层都要求强阅读。 |
| 218–295 | 气泡整体尺度 0.75→1.12 | 前景基本建立后继续短距离聚焦，内部文字不逐字晃动。 |
| 295–299 | 最终落稳 | 保留一句重点，结束时不再增加新消息。 |

重点气泡是独立前景对象，不是每个字从弹幕中逐字变形过来的。背景集体退让与前景共用内容让观众感到“归纳”，但不能称为严格的对象 morph。若需要突出某条真实评论，应保持该条文字与来源身份，而非用统一“这下看懂了”替代原意。

## 如何避免重新做成“出现—停住—下一页”

早期探测的初始 x 在 1080 以外，开头文字尚未进入屏幕。选定版把第一批初始位置移入可见区域；这是开场信息密度修订，不是编码丢帧修复。接着让 gather、气泡进入与背景退出区间交叠，消除“所有弹幕排好后才开下一张卡”的等待感。

关键是接力有方向、背景按时退让，而非全片越动越好。最后的慢聚焦只是这个无声案例的节奏选择，不是所有结论的强制动作；长旁白需要更多阅读时，允许气泡停稳。精确引用应优先保证可读，不能为了显得热闹加速滚动。

本例没有独立的“卡顿版→修复版”全长视频对照，不能把产品或合集的修订数字写成本例历史。可迁移的共同诊断与有证据的前后对照在[停顿与顺滑经验](../motion-case-library/references/timing-continuity.md)。

## 换内容时必须一起改什么

words、重点句、对象数量、行列间距和速度目前写在源码里，Props 只有 mode。改成较长中文时，先减少同屏条数、重排路径与字号，不把长句挤进原字宽；重点气泡的宽度、行数与缩放也需重算。若真实评论需要标识作者或来源，阅读设计应与身份信息共同成立。

适用的是讨论氛围、疑问归纳与回应，不适合用作逐条证据阅读或伪造群众反应。当前没有人像层、Mask 或前后景穿插，只能证明独立包装效果；与数字人合成时要依据实际脸部和字幕占用重排。不是简单把黑字放在人物后面就完成深度关系。

本例没有验证音效。需要声音时，可在重点气泡开始获得注意的主动作附近选一个合适的起音，不必每条弹幕一声提示；如果音效在第二个视觉动作才出现，应同时检查音源前置静音、真正 attack 以及绑定事件，而非只移动音频片段头。
