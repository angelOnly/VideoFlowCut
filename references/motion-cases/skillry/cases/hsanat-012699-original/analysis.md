# 10. 手机录音与人物视频窗口：动效与美术拆解

[原作](../../cases/hsanat-012699-original/media/original.mp4) · [来源](https://skillry.dev/ai-videos/opus-5-5/hsanat-012699) · [作者公开输入](../../cases/hsanat-012699-original/sources/published-prompt.md)

一条招聘流程解释广告，先用70人与3人的差距提出筛选问题，再沿设置问题、发链接、手机录制、查看评分和分享结果前进。手机录制阶段实际显示图形人物，不应把该部分叫真实人物录屏；后面的回答窗口才有人像画面。

直接观察的重点区间为 30.000—35.000 秒。30—33.333秒左侧短标题、中央手机和右侧转录卡形成三栏。右卡文字更换，但手机与左标题不动，观众看的是同一步录制的不同输出。33.4秒三栏一起退模糊，33.6秒评分标题在原上方区域建立；33.867—34.267秒宽白卡从下方显出，左为人物回答、右为空评分。34.467秒第一个粉色评分条出现，34.667—35秒后续条依次填入。这是步骤换场，人物窗与评分关联通过并列和顺序建立。

美术的设计解释：浅粉底把白界面与深色标题分开，饱和洋红用于步骤号、重点条与最后品牌整底。手机中的暖橙肤色和蓝色上衣提供与粉底的差异；回答卡里照片恢复细节，评分条仍沿用品牌色。阴影、圆角和统一对齐让不同来源界面形成一致层级。

迁移思考：适用于用户操作到审核结果的说明，不限招聘。迁移要判断人物窗口代表实见材料还是示意图，评分条也要绑定真实规则。文字多且界面小，手机端不能只靠压缩整屏；应局部放大，保证当前步骤一个重点。模糊转场会损失短暂读时，不要在信息未读完时启动。

资料身份与实现边界：公开输入是一般SaaS发布片要求，没有当前招聘素材、完整分镜或源码。本轮公开仓库、详情页与输入核查中，未找到直接对应当前原作的固定源码；不能把Remake技术标签或需求中提及的工具当原作实现证据。本报告只解释可见关系，具体遮罩、曲线、图层及渲染方案若实施，属于新制作选择。核查范围见[来源核查记录](../../cases/hsanat-012699-original/sources/source-check.json)。

本报告实际查看整片约每秒一帧概览，以及关键区间的密集真实源帧；时间来自源PTS。基于带源时间图片序列，未核验原速观感，未试听，因此不认证整体流畅度、音乐拍点、对白连续或声音同步。概览不足以证明其他快速接续；300像素证据单帧中的小字、边缘精度仍需全尺寸核验。
